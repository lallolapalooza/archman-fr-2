MKDIR(1P) Manuel du programmeur POSIX MKDIR(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

mkdir — créer des répertoires

SYNTAXE

mkdir [-p] [-m mode] dir...

DESCRIPTION

L'utilitaire mkdir crée les répertoires spécifiés par les opérandes, dans l'ordre spécifié.

Pour chaque opérande dir, l'utilitaire mkdir effectue des actions équivalentes à la fonction mkdir() définie dans le volume Interfaces système de POSIX.1‐2017, appelée avec les arguments suivants :

1.
L'opérande dir est utilisé comme argument path.
2.
La valeur de l'OU inclusif-exclusif des bits S_IRWXU, S_IRWXG et S_IRWXO est utilisée comme argument mode. (Si l'option -m est spécifiée, la valeur de l'argument mode de mkdir() n'est pas spécifiée, mais le répertoire n'aura à aucun moment des permissions moins restrictives que l'argument mode de l'option -m.)

OPTIONS

L'utilitaire mkdir est conforme aux Définitions de base du volume de POSIX.1‐2017, Section 12.2, Conventions de syntaxe des utilitaires.

Les options suivantes sont prises en charge :

-m mode
Définit les bits de permission de fichier du répertoire nouvellement créé sur la valeur mode spécifiée. L'argument d'option mode est le même que l'opérande mode défini pour l'utilitaire chmod. Dans les chaînes mode_symbolique, les caractères d'opération '+' et '-' sont interprétés par rapport à un mode initial présumé de a=rwx ; '+' ajoute des permissions au mode par défaut, '-' supprime des permissions du mode par défaut.
-p
Crée tous les composants d'chemin intermédiaires manquants.

Pour chaque opérande dir qui ne nomme pas un répertoire existant, avant d'effectuer les actions décrites dans la section DESCRIPTION, l'utilitaire mkdir crée les composants d'chemin du préfixe de chemin de dir qui ne nomment pas un répertoire existant en effectuant des actions équivalentes à l'appel préalable de la fonction mkdir() avec les arguments suivants :

1.
Un chemin nommant le composant d'chemin manquant, se terminant par un caractère <barre oblique> (slash), comme argument path
2.
La valeur zéro comme argument mode

puis en appelant la fonction chmod() avec les arguments suivants :

1.
Le même argument path que dans l'appel mkdir()
2.
La valeur (S_IWUSR|S_IXUSR|~filemask)&0777 comme argument mode, où filemask est le masque de création de mode de fichier du processus (voir le volume Interfaces système de POSIX.1‐2017, umask())

Chaque opérande dir nommant un répertoire existant est ignoré sans erreur.

OPÉRANDES

L'opérande suivant est pris en charge :

dir
Un chemin d'un répertoire à créer.

Non utilisé.

FICHIERS D'ENTRÉE

Aucun.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affectent l'exécution de mkdir :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la priorité des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si définie à une chaîne de caractères non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles comme caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments).
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

STATUT DE SORTIE

Les valeurs de sortie suivantes sont renvoyées :

 0
Tous les répertoires spécifiés ont été créés avec succès, ou l'option -p a été spécifiée et tous les répertoires spécifiés existaient déjà ou ont été créés avec succès.
>0
Une erreur s'est produite.

CONSÉQUENCES DES ERREURS

Par défaut.

Les sections suivantes sont informatives.

USAGE PAR L'APPLICATION

Le mode de fichier par défaut pour les répertoires est a=rwx (777 sur la plupart des systèmes) avec certaines permissions supprimées conformément au masque de création de mode de fichier. Pour les composants d'chemin intermédiaires créés par mkdir, le mode est le mode par défaut modifié par u+wx afin que les sous-répertoires puissent toujours être créés quel que soit le masque de création de mode de fichier ; si des permissions ultimes différentes sont souhaitées pour les répertoires intermédiaires, elles peuvent être modifiées par la suite avec chmod.

Notez que certains des répertoires demandés peuvent avoir été créés même si une erreur se produit.

EXEMPLES

RATIONNEMENT

L'option -m de System V a été incluse pour contrôler le mode de fichier.

L'option -p de System V a été incluse pour créer les répertoires intermédiaires nécessaires et pour compléter la fonctionnalité fournie par rmdir pour supprimer les répertoires dans le préfixe du chemin lorsqu'ils deviennent vides. Comme aucune erreur n'est produite si un composant du chemin existe déjà, l'option -p est également utile pour s'assurer qu'un répertoire particulier existe.

La fonctionnalité de mkdir est décrite substantiellement par référence à la fonction mkdir() dans le volume Interfaces système de POSIX.1‐2017. mkdir(1p) — man pages

RATIONALE

L'existence de cette page de manuel, bien qu'elle décrive la même commande que la page de manuel mkdir(1), est due à des raisons de compatibilité POSIX. La forme mkdir() est un appel système et une fonction de bibliothèque standard C, tandis que mkdir est une commande utilitaire. Cette page de manuel est conçue pour couvrir les spécifications POSIX pour la commande mkdir.

Dans certains systèmes, les options peuvent être interprétées de différentes manières. Par exemple, la commande mkdir de certains systèmes peut ne pas supporter les options -p et -m simultanément. Cette page de manuel spécifie que de tels comportements sont une déviation de la norme.

Pour les versions futures de la norme, on pourrait envisager d'écrire une seule page de manuel couvrant la commande mkdir et l'appel système mkdir(). Les détails de la création de répertoires sont des informations communes aux deux interfaces. En ayant une seule page de manuel, moins d'efforts seront nécessaires pour décrire les détails de la création de répertoires.
