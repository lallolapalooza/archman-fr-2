mkosi Journal des modifications

v25

•
Au lieu d'utiliser bubblewrap, le sandboxing est maintenant effectué avec un nouvel outil mkosi-sandbox. Cet outil a une API publique et peut être utilisé indépendamment de mkosi.
•
La construction des images se fait maintenant dans un espace utilisateur avec un seul utilisateur lors de l'exécution sans privilèges, au lieu d'utiliser newuidmap/newgidmap. Lors de l'exécution sans privilèges, tous les fichiers et répertoires de l'image appartiendront à l'utilisateur appelant (et à root dans toutes les archives produites). Toute tentative de changer le propriétaire des fichiers à d'autres utilisateurs dans les scripts échouera, sauf si la nouvelle variable d'environnement $MKOSI_CHROOT_SUPPRESS_CHOWN est définie sur une valeur vraie.
•
mkosi ne descend plus les privilèges à l'utilisateur appelant lorsqu'il s'exécute en tant que root pour diverses étapes.
•
Un nouveau verbe cat-config affichera tous les fichiers de configuration qui ont été inclus pour chaque image configurée.
•
Ajout du support pour Azure Linux
•
Ajout du support pour Kali Linux
•
Si mkosi.version est exécutable, nous l'exécutons maintenant et lisons la version depuis la sortie standard.
•
Ajout de --wipe-build-dir pour effacer le répertoire de construction avant de reconstruire l'image.
•
Introduction de RepositoryKeyFetch= pour contrôler si les clés GPG de distribution doivent être récupérées à distance. Ce paramètre est désactivé par défaut pour des raisons de sécurité, sauf lors de la construction d'images basées sur rpm ou Arch Linux sur Ubuntu.
•
Nous gérons maintenant SIGHUP gracieusement
•
Les paramètres universels qui prennent une collection de valeurs ne peuvent plus être ajoutés dans les sous-images. L'utilisation des arbres de gestionnaires de paquets dans les sous-images devra être déplacée vers l'image de niveau supérieur. De même, les dépôts devront être activés dans l'image de niveau supérieur.
•
Les métadonnées des dépôts ne sont plus copiées dans les images.
•
Les métadonnées des dépôts des arbres de base ne sont plus utilisées.
•
Les arbres de gestionnaires de paquets sont maintenant nommés arbres sandbox.
•
Les arbres de gestionnaires de paquets (arbres sandbox) n'utilisent plus les arbres squelettes comme valeurs par défaut s'ils ne sont pas définis.
•
Remarque pour les empaqueteurs : Les pages du manuel ont été déplacées vers resources/man et incluent maintenant les pages du manuel pour mkosi-initrd et mkosi-sandbox.

InitrdInclude= a été supprimé. Si vous utilisez InitrdInclude=, veuillez construire votre initrd via une sous-image dans mkosi.images contenant Include=mkosi-initrd et toutes les personnalisations que vous souhaitez ajouter, et utiliser le paramètre Initrds= pour l'utiliser comme initrd pour l'image principale au lieu de l'initrd par défaut.

Ajout de History= pour que mkosi enregistre la configuration utilisée pour construire l'image et la réutilise lorsque des verbes tels que qemu, boot, ... sont invoqués sans -f.

Ajout de RuntimeHome= pour monter le répertoire personnel actuel à /root lors de l'exécution d'une commande qui démarre l'image
•
Plus de répertoires en dehors de /etc et /usr sont maintenant pris en compte à partir des arbres sandbox (anciennement appelés arbres de gestionnaires de paquets).
•
La configuration des profils de mkosi.profiles est maintenant analysée après mkosi.conf.d au lieu de avant. Pour définir des valeurs par défaut à utiliser dans mkosi.conf.d basées sur le profil configuré, utilisez plutôt un drop-in précoce dans mkosi.conf.d qui correspond au profil configuré.

Profile= est renommé en Profiles= et prend maintenant une liste de profils séparés par des virgules. Les scripts reçoivent maintenant $PROFILES avec une liste de profils séparés par des espaces au lieu de $PROFILE. Le spécificateur %p pour les profils est supprimé.

Plusieurs scripts sync, prepare, build, postinst, finalize, postoutput et clean sont maintenant pris en compte à partir de mkosi.$SCRIPT.d.

Les identifiants agetty.autologin et login.noauth ne sont plus définis inconditionnellement.
•
L'accès au répertoire de sortie dans les scripts de construction a été supprimé. BuildDirectory= n'est plus disponible dans PrepareScripts=. Si vous avez besoin d'acquérir des fichiers pour le processus de construction, placez-les quelque part de manière appropriée dans $BUILDROOT afin qu'ils puissent être mis en cache lors de la construction incrémentielle.

Lors de l'utilisation d'un arbre d'outils et qu'un sandbox relâché est utilisé pour exécuter une commande (qemu, nspawn, ...), nous conservons maintenant toutes les entrées de $PATH en dehors de /usr intactes. Notez que cela peut causer des problèmes si une entrée $PATH contient des binaires liés à des bibliothèques dans /usr de l'hôte.

Introduction d'un nouveau spécificateur %I qui se résout au nom de la sous-image actuelle lorsqu'il est utilisé dans une configuration sous mkosi.images/. Cela diffère de %o car c'est toujours le nom du fichier de configuration sans extension (ou le nom du répertoire).

Les fournisseurs OpenSSL sont maintenant supportés comme sources de clés pour les différents paramètres de clés si une version suffisamment récente de systemd (257 ou plus) est utilisée.

Ajout du support pour charger des certificats X.509 à partir de fournisseurs OpenSSL si une version suffisamment récente de systemd (257 ou plus) est utilisée.

La définition d'un paramètre basé sur une collection sur une chaîne vide via la ligne de commande, puis l'ajout à ce même paramètre, remplacera maintenant les paramètres provenant des fichiers de configuration, alors qu'auparavant les valeurs de la ligne de commande étaient ajoutées aux valeurs des fichiers de configuration.

Suppression de --skip-final-phase car nous n'avons plus qu'une seule phase.

Seuls les fichiers de configuration correspondant à *.conf sont analysés dans les répertoires dropin maintenant.

Suppression de --netdev. Peut être remplacé par l'installation manuelle de systemd-networkd, le placement d'un fichier réseau dans l'image et l'activation de systemd-networkd.

En pratique, cela signifie que systemd et d'autres outils de base doivent être installés explicitement à partir de maintenant.

Suppression de --base-packages car il n'est plus nécessaire puisque nous n'installons plus de paquets par défaut, à l'exception du paquet de disposition de système de fichiers de base.

--base-image est divisé en --base-tree et --overlay.

Suppression de --cache-initrd, utilisez plutôt un initrd pré-construit avec Initrds= pour éviter de reconstruire l'initrd à chaque fois.

•
Suppression de l'option --install-directory=. Elle avait été initialement ajoutée pour mettre en cache les résultats d'installation, mais cela ne fonctionne pas correctement car cela peut laisser des fichiers dans le répertoire d'installation d'une installation précédente. Nous devons donc vider le répertoire avant de le réutiliser, invalidant la mise en cache. L'option a donc été supprimée.
•
Les scripts de construction sont maintenant exécutés sur l'hôte. Voir la section SCRIPTS du manuel pour plus d'informations. Les scripts existants devront être mis à jour pour s'assurer qu'ils continuent de fonctionner. Plus précisément, la plupart des chemins dans les scripts devront être préfixés par $BUILDROOT pour qu'ils opèrent sur l'image au lieu du système hôte. Pour s'assurer que le système hôte ne peut pas être modifié lors de l'exécution d'un script, la plupart des répertoires hôtes sont montés en lecture seule lors de l'exécution d'un script pour garantir qu'un script ne peut en aucun cas modifier l'hôte. Alternativement, au lieu de faire exécuter le script sur l'hôte, le script peut toujours être exécuté dans l'image elle-même en plaçant l'extrait suivant en haut du script :
if [ "$container" != "mkosi" ]; then

fi

Suppression de l'option --tar-strip-selinux-context=. Nous étiquetons maintenant tous les fichiers correctement si selinux est activé et si les utilisateurs ne veulent pas les étiquettes, ils peuvent simplement les exclure lors de l'extraction de l'archive.

Gentoo est maintenant marqué comme expérimental et non pris en charge, et il n'y a aucune garantie du tout qu'il fonctionnera. Les problèmes liés à gentoo ne recevront généralement pas l'attention des mainteneurs principaux. Tous les hacks spécifiques à gentoo en dehors du module d'implémentation gentoo ont été supprimés.

Un verbe documentation a été ajouté. Appeler mkosi avec ce verbe affichera la documentation. Ceci est utile lorsque l'on exécute mkosi pendant le développement pour avoir toujours la documentation dans la bonne version disponible. Par défaut, il essaiera plusieurs méthodes pour afficher la documentation, mais une option spécifique peut être choisie avec l'option --doc-format. Les emballeurs de distribution sont encouragés à ajouter un fichier mkosi.1 dans le répertoire mkosi/resources du paquet Python, s'il manque, ainsi qu'à l'installer dans le chemin de recherche approprié pour les pages man. La page man peut être générée à partir du fichier markdown mkosi/resources/mkosi.md par exemple via pandoc -t man -s -o mkosi.1 mkosi.md.
•
BuildSources= prend maintenant des paires source:cible qui spécifient le répertoire source et où le monter par rapport au répertoire source de niveau supérieur lors de l'exécution de scripts. (par exemple, BuildSources=../my-project:my-project)
