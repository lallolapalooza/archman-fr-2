NOM

mvrefind - Déplacer une installation rEFInd d'un emplacement à un autre

SYNTAXE

mvrefind SOURCE DEST

DESCRIPTION

Déplace une installation rEFInd de SOURCE vers DEST, où SOURCE et DEST sont tous deux des répertoires sur la partition système EFI (ESP), SOURCE contenant une installation fonctionnelle de rEFInd. Cette opération entraîne plusieurs actions :

*
Renommer le répertoire SOURCE en DEST.
*
Renommer le binaire rEFInd avec un nom approprié en fonction de la nouvelle destination. Par exemple, si DEST est EFI/BOOT sur la partition système EFI (ESP), le binaire rEFInd devrait être bootx64.efi (ou quelque chose de similaire mais avec un code d'architecture différent).
*
Modifier les entrées NVRAM de l'ordinateur pour qu'elles pointent vers rEFInd à son nouvel emplacement.
*
Si Shim est détecté, les opérations de renommage et les pointeurs d'entrée NVRAM sont ajustés en conséquence.
*
Si DEST existe, son contenu est préservé.

En général, mvrefind comprend trois types d'emplacements pour SOURCE et DEST, relatifs à la racine de l'ESP :

*
EFI/BOOT -- Le nom de fichier bootx64.efi (ou similaire pour d'autres architectures) dans cet emplacement est le "nom de fichier de secours", utilisé par les supports de démarrage amovibles et comme chargeur de démarrage de dernier recours sur les disques durs. Certains EFI ne peuvent pas mémoriser leurs entrées de démarrage normales, et sur ceux-ci, rEFInd doit être installé ici (ou comme chargeur de démarrage Windows). Lorsque ce répertoire est la DESTINATION et qu'il existe déjà, l'existant EFI/BOOT est sauvegardé sous EFI/BOOT-rEFIndBackup ; et si la SOURCE est EFI/BOOT et que EFI/BOOT-rEFIndBackup existe, il est renommé en EFI/BOOT après que rEFInd a été déplacé vers sa destination.
*
EFI/Microsoft/boot -- Le fichier bootmgfw.efi dans cet emplacement contient normalement le chargeur de démarrage Windows. Les machines avec des EFI défectueux peuvent refuser d'accepter ou de mémoriser les bonnes entrées de démarrage et préféreront démarrer cette entrée avant toutes les autres. Dans de tels cas, utiliser rEFInd nécessite de déplacer le chargeur de démarrage Microsoft ailleurs et de le remplacer par rEFInd. Lorsque ce répertoire est la DESTINATION, mvrefind déplace le fichier bootmgfw.efi original un niveau plus bas (vers EFI/Microsoft) et y stocke refind_x64.efi (ou Shim). Lors du déplacement depuis EFI/Microsoft/boot, ce processus est inversé.
*
Autre -- Tout autre emplacement SOURCE ou DEST est traité comme une installation rEFInd régulière, avec une entrée NVRAM correcte créée par efibootmgr.

mvrefind tente d'identifier l'ESP et refuse de déplacer entre l'ESP et toute autre partition. Lorsqu'il déplace des fichiers, il déplace le binaire rEFInd principal, le fichier refind.conf, tout binaire Shim identifié, ainsi que les sous-répertoires icons, icons-backup, drivers_* et keys. Si d'autres fichiers ou répertoires rEFInd sont présents dans SOURCE (comme un répertoire de thèmes/icônes personnalisé), ils ne seront pas déplacés. Si SOURCE est vide après le déplacement des fichiers et sous-répertoires spécifiés, SOURCE sera supprimé.
