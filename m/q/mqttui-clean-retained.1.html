NOM

mqttui-clean-retained - Nettoie les messages conservés du courtier

SYNTAXE

mqttui clean-retained [--timeout] [--dry-run] [-b|--broker] [-u|--username] [--password] [-i|--client-id] [--client-cert] [--client-key] [--insecure] [-h|--help] <TOPIC>

DESCRIPTION

Nettoie les messages conservés du courtier.

Cela fonctionne en s'abonnant au sujet et en attendant les messages avec le drapeau conservé. Ensuite, un message avec une charge utile vide est publié, conservé, ce qui efface le sujet sur le courtier. Se termine au premier message non conservé ou lorsque le délai d'attente est atteint.

OPTIONS

--timeout=SECONDES [par défaut : 5]
Lorsqu'aucun message n'est reçu pendant le temps imparti, l'opération est considérée comme terminée.
--dry-run
Ne nettoie pas les sujets, se contente de les enregistrer.
-h, --help
Imprime l'aide (voir un résumé avec '-h').
<TOPIC>
Sujet qui est nettoyé.

Prend en charge les filtres comme 'foo/bar/#'.

CONNEXION MQTT

-b, --broker=URL [par défaut : mqtt://localhost]
URL qui représente la manière de se connecter au courtier MQTT.

Exemples : `mqtt://localhost` `mqtt://localhost:1883` `mqtts://localhost` `mqtts://localhost:8883` `ws://localhost/path` `ws://localhost:9001/path` `wss://localhost/path` `wss://localhost:9001/path`

Peut également être spécifié avec la variable d'environnement MQTTUI_BROKER.
-u, --username=CHAÎNE
Nom d'utilisateur pour accéder au courtier mqtt.

Accès anonyme lorsqu'il n'est pas fourni.

Peut également être spécifié avec la variable d'environnement MQTTUI_USERNAME.
--password=CHAÎNE
Mot de passe pour accéder au courtier mqtt.

Envisagez d'utiliser une connexion avec TLS au courtier. Sinon, le mot de passe sera transporté en clair.

Passer le mot de passe via la ligne de commande est dangereux car le mot de passe peut être lu dans l'historique ! Vous devriez le passer via une variable d'environnement.

Peut également être spécifié avec la variable d'environnement MQTTUI_PASSWORD.
-i, --client-id=CHAÎNE
Spécifie l'identifiant client pour la connexion.
Peut également être spécifié avec la variable d'environnement MQTTUI_CLIENTID.
--client-cert=CHEMIN_FICHIER
Chemin vers le fichier de certificat client TLS.

Utilisé conjointement avec --client-key pour activer l'authentification client TLS. Le fichier doit être un certificat X.509 codé en DER sérialisé en PEM.

Peut également être spécifié avec la variable d'environnement MQTTUI_CLIENT_CERTIFICATE.
--client-key=CHEMIN_FICHIER
Chemin vers la clé privée client TLS.

Utilisé conjointement avec --client-cert pour activer l'authentification client TLS. Le fichier doit être un fichier ASN.1 codé en DER sous forme PKCS#8 sérialisé en PEM.

Peut également être spécifié avec la variable d'environnement MQTTUI_CLIENT_PRIVATE_KEY.
--insecure
Autorise les connexions TLS non sécurisées.
