MQ_OPEN(3P) Manuel du programmeur POSIX MQ_OPEN(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

mq_open — ouvrir une file de messages (TEMPS RÉEL)

SYNTAXE

#include <mqueue.h>
mqd_t mq_open(const char *name, int oflag, ...);

DESCRIPTION

La fonction mq_open() établit la connexion entre un processus et une file de messages à l'aide d'un descripteur de file de messages. Elle crée une description de file de messages ouverte qui référence la file de messages, et un descripteur de file de messages qui référence cette description de file de messages ouverte. Le descripteur de file de messages est utilisé par d'autres fonctions pour référencer cette file de messages. L'argument name pointe vers une chaîne de caractères nommant une file de messages. Il n'est pas spécifié si le nom apparaît dans le système de fichiers et est visible par d'autres fonctions qui prennent des noms de chemin comme arguments. L'argument name est conforme aux règles de construction d'un nom de chemin, à l'exception du fait que l'interprétation des caractères <slash> autres que le caractère <slash> initial dans name est définie par l'implémentation, et que les limites de longueur pour l'argument name sont définies par l'implémentation et n'ont pas besoin d'être les mêmes que les limites de nom de chemin {PATH_MAX} et {NAME_MAX}. Si name commence par le caractère <slash>, alors les processus appelant mq_open() avec la même valeur de name référenceront le même objet file de messages, tant que ce nom n'a pas été supprimé. Si name ne commence pas par le caractère <slash>, l'effet est défini par l'implémentation. Si l'argument name n'est pas le nom d'une file de messages existante et que la création n'est pas demandée, mq_open() échouera et retournera une erreur.

Un descripteur de file de messages peut être implémenté à l'aide d'un descripteur de fichier, auquel cas les applications peuvent ouvrir au moins {OPEN_MAX} files et files de messages.

L'argument oflag demande l'accès désiré en réception et/ou en envoi à la file de messages. L'autorisation d'accès demandée pour recevoir des messages ou envoyer des messages sera accordée si le processus appelant obtiendrait un accès en lecture ou en écriture, respectivement, à un fichier protégé de manière équivalente.

La valeur de oflag est le OU inclusif par bits des valeurs de la liste suivante. Les applications doivent spécifier exactement l'un des trois premiers modes d'accès ci-dessous dans la valeur de oflag:

O_RDONLY
Ouvre la file de messages pour recevoir des messages. Le processus peut utiliser le descripteur de file de messages retourné avec mq_receive(), mais pas mq_send(). Une file de messages peut être ouverte plusieurs fois dans le même processus ou dans des processus différents pour recevoir des messages.
O_WRONLY
Ouvre la file pour envoyer des messages. Le processus peut utiliser le descripteur de file de messages retourné avec mq_send() mais pas mq_receive(). Une file de messages peut être ouverte plusieurs fois dans le même processus ou dans des processus différents pour envoyer des messages.
O_RDWR
Ouvre la file pour recevoir et envoyer des messages. Le processus peut utiliser toutes les fonctions autorisées pour O_RDONLY et O_WRONLY. Une file de messages peut être ouverte plusieurs fois dans le même processus ou dans des processus différents pour envoyer des messages.

Toute combinaison des drapeaux restants peut être spécifiée dans la valeur de oflag:

O_CREAT
Crée une file de messages. Elle nécessite deux arguments supplémentaires : mode, qui doit être de type mode_t, et attr, qui doit être un pointeur vers une structure mq_attr. Si le nom de chemin name a déjà été utilisé pour créer une file de messages qui existe encore, alors ce drapeau n'aura aucun effet, sauf mention contraire sous O_EXCL. Sinon, une file de messages sera créée sans aucun message. L'identifiant utilisateur de la file de messages sera défini à l'identifiant utilisateur effectif du processus. L'identifiant de groupe de la file de messages sera défini à l'identifiant de groupe effectif du processus ; cependant, si l'argument name est visible dans le système de fichiers, l'identifiant de groupe peut être défini à l'identifiant de groupe du répertoire contenant. Lorsque des bits dans mode autres que les bits de permission de fichier sont spécifiés, l'effet n'est pas spécifié. Si attr est NULL, la file de messages sera créée avec des attributs de file de messages par défaut définis par l'implémentation. Si attr n'est pas NULL et que le processus appelant dispose des privilèges appropriés sur name, les attributs mq_maxmsg et mq_msgsize de la file de messages seront définis aux valeurs des membres correspondants dans la structure mq_attr référencée par attr. Les valeurs des membres mq_flags et mq_curmsgs de la structure mq_attr seront ignorées. Si attr n'est pas NULL, mais que le processus appelant ne dispose pas des privilèges appropriés sur name, la fonction mq_open() échouera et retournera une erreur sans créer la file de messages.
O_EXCL
Si O_EXCL et O_CREAT sont définis, mq_open() échouera si la file de messages name existe. La vérification de l'existence de la file de messages et la création de la file de messages si elle n'existe pas seront atomiques par rapport aux autres threads exécutant mq_open() nommant le même name avec O_EXCL et O_CREAT définis. Si O_EXCL est défini et O_CREAT n'est pas défini, le résultat est indéfini.
O_NONBLOCK
Détermine si une opération mq_send() ou mq_receive() attend des ressources ou des messages qui ne sont pas actuellement disponibles, ou échoue avec errno défini à [EAGAIN]; voir mq_send() et mq_receive() pour les détails.

La fonction mq_open() n'ajoute ni ne retire de messages de la file.

VALEUR DE RETOUR

En cas de succès, la fonction retournera un descripteur de file de messages ; sinon, la fonction retournera (mqd_t)-1 et définira errno pour indiquer l'erreur.

ERREURS

La fonction mq_open() échouera si :

EACCES
La file de messages existe et les permissions spécifiées par oflag sont refusées, ou la file de messages n'existe pas et la permission de créer la file de messages est refusée.
EEXIST
O_CREAT et O_EXCL sont définis et la file de messages nommée existe déjà.
EINTR
La fonction mq_open() a été interrompue par un signal.
EINVAL
La fonction mq_open() n'est pas prise en charge pour le nom donné.
EINVAL
O_CREAT a été spécifié dans oflag, la valeur de attr n'est pas NULL, et soit mq_maxmsg, soit mq_msgsize était inférieur ou égal à zéro.
EMFILE
Trop de descripteurs de files de messages ou de descripteurs de fichiers sont actuellement utilisés par ce processus.
ENFILE
Trop de files de messages sont actuellement ouvertes dans le système.
ENOENT
O_CREAT n'est pas défini et la file de messages nommée n'existe pas.
ENOSPC
Il n'y a pas assez d'espace pour la création de la nouvelle file de messages.

Si l'une des conditions suivantes se produit, la fonction mq_open() peut retourner (mqd_t)-1 et définir errno à la valeur correspondante.

ENAMETOOLONG

La longueur de l'argument name dépasse {_POSIX_PATH_MAX} sur les systèmes qui ne prennent pas en charge l'option XSI ou dépasse {_XOPEN_PATH_MAX} sur les systèmes XSI, ou a un composant de nom de chemin plus long que {_POSIX_NAME_MAX} sur les systèmes qui ne prennent pas en charge le XSI

mq_open(3p) — man pages

PROLOG

This page is a manual page for the Linux utility mq_open. It is a specification of the POSIX Message Queue interface.

NAME

mq_open, mq_close, mq_unlink - message queue open, close, and unlink

SYNOPSIS

#include <mqueue.h>

mqd_t mq_open(const char *name, int oflag, ...);
int mq_close(mqd_t mqdes);
int mq_unlink(const char *name);

DESCRIPTION

The message queue interface provides a facility for processes to exchange messages.

The mq_open() function shall establish the name of a new or existing message queue and return a message queue descriptor associated with that message queue.

The name argument is a pointer to a character string which is the name of the message queue. The name is a POSIX object name. It is a null-terminated string. The interpretation of name is implementation-defined. On Linux, message queue names are like filenames, starting with a slash. However, unlike filenames, the name is a system-wide name.

The oflag argument specifies the desired message queue creation and access modes. It is the bitwise OR of zero or more of the following flags:

  • O_RDONLY Open the message queue for message reading only.
  • O_WRONLY Open the message queue for message writing only.
  • O_RDWR Open the message queue for both message reading and writing.

Exactly one of O_RDONLY, O_WRONLY, or O_RDWR must be specified.

  • O_CREAT Create the message queue if it does not exist.
  • O_EXCL If O_CREAT is specified, and the message queue already exists, then mq_open() shall fail.
  • O_NONBLOCK Open the message queue without regard to its state (e.g., whether it has been opened by other processes). If O_NONBLOCK is set, and O_RDONLY or O_WRONLY is not set, then mq_open() shall fail.
  • O_APPEND This flag is not supported for message queues.

If oflag includes O_CREAT, then the following arguments are used:

  • mode A protection mode for the message queue.
  • attr A pointer to a structure defining the message queue attributes.

If oflag does not include O_CREAT, the mode and attr arguments are ignored. If oflag includes O_CREAT, then either mode or attr (or both) must be specified. If both mode and attr are specified, the attr pointer is ignored. If only attr is specified, the mode is taken from attr->mq_mode. If only mode is specified, the attr pointer is ignored. If neither mode nor attr are specified, this is an error.

The mode argument specifies the permissions for the new message queue. It is a bitwise OR of protection bits.

The attr argument points to a structure of type mq_attr, which specifies the message queue attributes. The structure has the following members:

mq_flags
Flags associated with the message queue. Currently, the only supported flag is O_NONBLOCK. If this is set, the message queue is opened in non-blocking mode. Otherwise, it is opened in blocking mode.
mq_maxmsg
The maximum number of messages that may be placed in the queue. This value must be greater than 0.
mq_msgsize
The maximum length (in bytes) of a single message. This value must be greater than 0.
mq_curmsgs
The number of messages currently in the queue. This value is set by the system and cannot be set by the user.

The mq_close() function shall close the message queue descriptor specified by mqdes. This means that no further messages can be sent to or received from the queue using this descriptor. The descriptor is invalidated.

The mq_unlink() function shall remove the message queue named by name. When a message queue is unlinked, any remaining messages in the queue are discarded. Any further attempts to open the queue will fail until a new queue with the same name is created. If other processes have the queue open, the queue will be removed once all processes have closed it.

The name specified by name must be the same name used by mq_open().

RETURN VALUE

On success, mq_open() shall return a message queue descriptor. On failure, it shall return (mqd_t)−1 and set errno to indicate the error.

On success, mq_close() and mq_unlink() shall return 0. On failure, they shall return −1 and set errno to indicate the error.

ERRORS

EACCES
The message queue is created, but the calling process does not have permission to access it.
EEXIST
O_CREAT and O_EXCL were specified in oflag, and the message queue already exists.
EINTR
A signal was caught during the mq_open() or mq_close() operation.
EINVAL
Invalid value for oflag, or invalid attributes specified in attr.
EMFILE
The maximum number of message queue descriptors has been exceeded by the calling process.
ENAMETOOLONG
The length of the name argument exceeds PATH_MAX, or a component of the name exceeds NAME_MAX.
ENFILE
The system-wide limit on the total number of open message queues has been exceeded.
ENOENT
O_CREAT was not specified in oflag, and the message queue does not exist.
ENOSPC
The message queue is to be created, but there is not enough space on the file system.
ENOSYS
The mq_open(), mq_close(), or mq_unlink() function is not implemented.
ENOTDIR
A component of the name argument is not a directory.
ENXIO
A component of the name argument does not exist.
EOVERFLOW
The name specified is longer than allowed by the implementation.

In addition, mq_open() may fail if the specified message queue name is longer than {_XOPEN_NAME_MAX} on XSI systems.
