MQ_RECEIVE(3P) Manuel du programmeur POSIX MQ_RECEIVE(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

mq_receive, mq_timedreceive — recevoir un message d'une file d'attente de messages (TEMPS RÉEL)

SYNTAXE

#include <mqueue.h>
ssize_t mq_receive(mqd_t mqdes, char *msg_ptr, size_t msg_len,
    unsigned *msg_prio);
#include <mqueue.h>
#include <time.h>
ssize_t mq_timedreceive(mqd_t mqdes, char *restrict msg_ptr,
    size_t msg_len, unsigned *restrict msg_prio,
    const struct timespec *restrict abstime);

DESCRIPTION

La fonction mq_receive() reçoit le plus ancien des messages de plus haute priorité de la file d'attente de messages spécifiée par mqdes. Si la taille du tampon en octets, spécifiée par l'argument msg_len, est inférieure à l'attribut mq_msgsize de la file d'attente de messages, la fonction échoue et renvoie une erreur. Sinon, le message sélectionné est retiré de la file d'attente et copié dans le tampon pointé par l'argument msg_ptr.

Si la valeur de msg_len est supérieure à {SSIZE_MAX}, le résultat est défini par l'implémentation.

Si l'argument msg_prio n'est pas NULL, la priorité du message sélectionné est stockée à l'emplacement référencé par msg_prio.

Si la file d'attente de messages spécifiée est vide et que O_NONBLOCK n'est pas défini dans la description de la file d'attente de messages associée à mqdes, mq_receive() se bloque jusqu'à ce qu'un message soit mis en file d'attente ou jusqu'à ce que mq_receive() soit interrompu par un signal. Si plusieurs threads attendent de recevoir un message lorsqu'un message arrive dans une file d'attente vide et que l'option de planification par priorité est prise en charge, alors le thread de plus haute priorité qui attend depuis le plus longtemps est sélectionné pour recevoir le message. Sinon, il n'est pas spécifié quel thread en attente reçoit le message. Si la file d'attente de messages spécifiée est vide et que O_NONBLOCK est défini dans la description de la file d'attente de messages associée à mqdes, aucun message n'est retiré de la file d'attente, et mq_receive() renvoie une erreur.

La fonction mq_timedreceive() reçoit les messages de plus haute priorité les plus anciens de la file d'attente de messages spécifiée par mqdes, comme décrit pour la fonction mq_receive(). Cependant, si O_NONBLOCK n'a pas été spécifié lors de l'ouverture de la file d'attente de messages via la fonction mq_open(), et qu'aucun message n'existe dans la file d'attente pour satisfaire la réception, l'attente d'un tel message est terminée lorsque le délai spécifié expire. Si O_NONBLOCK est défini, cette fonction est équivalente à mq_receive().

Le délai expire lorsque l'heure absolue spécifiée par abstime est passée, telle que mesurée par l'horloge sur laquelle les délais sont basés (c'est-à-dire lorsque la valeur de cette horloge atteint ou dépasse abstime), ou si l'heure absolue spécifiée par abstime est déjà passée au moment de l'appel.

Le délai est basé sur l'horloge CLOCK_REALTIME. La résolution du délai est la résolution de l'horloge sur laquelle il est basé. L'argument timespec est défini dans l'en-tête <time.h>.

En aucun cas l'opération ne doit échouer avec un délai si un message peut être retiré de la file d'attente de messages immédiatement. La validité du paramètre abstime n'a pas besoin d'être vérifiée si un message peut être retiré de la file d'attente de messages immédiatement.

VALEUR DE RETOUR

En cas de succès, les fonctions mq_receive() et mq_timedreceive() renvoient la longueur du message sélectionné en octets et le message est retiré de la file d'attente. Sinon, aucun message n'est retiré de la file d'attente, les fonctions renvoient une valeur de -1 et définissent errno pour indiquer l'erreur.

ERREURS

Ces fonctions échouent si :

EAGAIN
O_NONBLOCK était défini dans la description du message associée à mqdes, et la file d'attente de messages spécifiée est vide.
EBADF
L'argument mqdes n'est pas un descripteur de file d'attente de messages valide ouvert en lecture.
EMSGSIZE
La taille du tampon de message spécifié, msg_len, est inférieure à la taille du message de l'attribut de la file d'attente de messages.
EINTR
L'opération mq_receive() ou mq_timedreceive() a été interrompue par un signal.
EINVAL
Le processus ou le thread aurait bloqué, et le paramètre abstime spécifiait une valeur de champ de nanosecondes inférieure à zéro ou supérieure ou égale à 1000 millions.
ETIMEDOUT
Le drapeau O_NONBLOCK n'était pas défini lors de l'ouverture de la file d'attente de messages, mais aucun message n'est arrivé dans la file d'attente avant l'expiration du délai spécifié.

Ces fonctions peuvent échouer si :

EBADMSG
L'implémentation a détecté un problème de corruption de données avec le message.
