mq_open(3) Manuel des fonctions de bibliothèque mq_open(3)

NOM

mq_open - ouvrir une file de messages

BIBLIOTHÈQUE

Bibliothèque temps réel (librt, -lrt)

SYNTAXE

#include <fcntl.h>           /* Pour les constantes O_* */
#include <sys/stat.h>        /* Pour les constantes de mode */
#include <mqueue.h>
mqd_t mq_open(const char *name, int oflag);
mqd_t mq_open(const char *name, int oflag, mode_t mode,
              struct mq_attr *attr);

DESCRIPTION

mq_open() crée une nouvelle file de messages POSIX ou ouvre une file existante. La file est identifiée par name. Pour les détails de la construction de name, voir mq_overview(7).

L'argument oflag spécifie les drapeaux qui contrôlent le fonctionnement de l'appel. (Les définitions des valeurs des drapeaux peuvent être obtenues en incluant <fcntl.h>.) Exactement un des éléments suivants doit être spécifié dans oflag :

O_RDONLY
Ouvre la file pour recevoir uniquement des messages.
O_WRONLY
Ouvre la file pour envoyer uniquement des messages.
O_RDWR
Ouvre la file pour envoyer et recevoir des messages.

Zéro ou plusieurs des drapeaux suivants peuvent être additionnellement combinés par un OU bit à bit dans oflag :

O_CLOEXEC (depuis Linux 2.6.26)
Définit le drapeau close-on-exec pour le descripteur de la file de messages. Voir open(2) pour une discussion sur l'utilité de ce drapeau.
O_CREAT
Crée la file de messages si elle n'existe pas. Le propriétaire (ID d'utilisateur) de la file de messages est défini à l'ID d'utilisateur effectif du processus appelant. La propriété de groupe (ID de groupe) est définie à l'ID de groupe effectif du processus appelant.
O_EXCL
Si O_CREAT a été spécifié dans oflag, et qu'une file avec le name donné existe déjà, alors échoue avec l'erreur EEXIST.
O_NONBLOCK
Ouvre la file en mode non bloquant. Dans les circonstances où mq_receive(3) et mq_send(3) bloqueraient normalement, ces fonctions échouent au lieu de cela avec l'erreur EAGAIN.

Si O_CREAT est spécifié dans oflag, alors deux arguments supplémentaires doivent être fournis. L'argument mode spécifie les permissions à appliquer à la nouvelle file, comme pour open(2). (Les définitions symboliques pour les bits de permissions peuvent être obtenues en incluant <sys/stat.h>.) Les paramètres de permissions sont masqués par rapport à l'umask du processus.

Les champs de la structure struct mq_attr pointée par attr spécifient le nombre maximum de messages et la taille maximale des messages que la file autorisera. Cette structure est définie comme suit :


struct mq_attr {
    long mq_flags;       /* Drapeaux (ignoré pour mq_open()) */
    long mq_maxmsg;      /* Nb. max. de messages dans la file */
    long mq_msgsize;     /* Taille max. d'un message (octets) */
    long mq_curmsgs;     /* Nb. de messages actuellement dans la file
                            (ignoré pour mq_open()) */
};

Seuls les champs mq_maxmsg et mq_msgsize sont utilisés lors de l'appel à mq_open(); les valeurs dans les champs restants sont ignorées.

Si attr est NULL, alors la file est créée avec des attributs par défaut définis par l'implémentation. Depuis Linux 3.5, deux fichiers /proc peuvent être utilisés pour contrôler ces valeurs par défaut ; voir mq_overview(7) pour les détails.

VALEUR RENVOYÉE

En cas de succès, mq_open() renvoie un descripteur de file de messages à utiliser par d'autres fonctions de file de messages. En cas d'erreur, mq_open() renvoie (mqd_t) -1, et errno est défini pour indiquer l'erreur.

ERREURS

EACCES
La file existe, mais l'appelant n'a pas la permission de l'ouvrir dans le mode spécifié.
EACCES
name contenait plus d'un slash.
EEXIST
Les deux drapeaux O_CREAT et O_EXCL ont été spécifiés dans oflag, mais une file avec ce name existe déjà.
EINVAL
name ne suit pas le format décrit dans mq_overview(7).
EINVAL
O_CREAT a été spécifié dans oflag, et attr n'était pas NULL, mais attr->mq_maxmsg ou attr->mq_msqsize était invalide. Ces deux champs doivent être supérieurs à zéro. Dans un processus non privilégié (n'ayant pas la capacité CAP_SYS_RESOURCE), attr->mq_maxmsg doit être inférieur ou égal à la limite msg_max, et attr->mq_msgsize doit être inférieur ou égal à la limite msgsize_max. De plus, même dans un processus privilégié, attr->mq_maxmsg ne peut pas dépasser la limite HARD_MAX. (Voir mq_overview(7) pour les détails de ces limites.)
EMFILE
La limite par processus sur le nombre de descripteurs de fichiers et de files de messages ouverts a été atteinte (voir la description de RLIMIT_NOFILE dans getrlimit(2)).
ENAMETOOLONG
name était trop long.
ENFILE
La limite globale du système sur le nombre total de fichiers et de files de messages ouverts a été atteinte.
ENOENT
Le drapeau O_CREAT n'a pas été spécifié dans oflag, et aucune file avec ce name n'existe.
ENOENT
name était juste "/" suivi d'aucun autre caractère.
ENOMEM
Mémoire insuffisante.
ENOSPC
Espace insuffisant pour la création d'une nouvelle file de messages. Cela s'est probablement produit parce que la limite queues_max a été atteinte ; voir mq_overview(7).

VERSIONS

Différences bibliothèque C/noyau

La fonction de bibliothèque mq_open() est implémentée au-dessus d'un appel système du même nom. La fonction de bibliothèque effectue la vérification que name commence par une barre oblique (/), retournant l'erreur EINVAL si ce n'est pas le cas. L'appel système du noyau attend que name ne contienne pas de barre oblique précédente, de sorte que la fonction C de la bibliothèque transmet name sans la barre oblique précédente (c'est-à-dire name+1) à l'appel système.

mq_close(3) — Arch Linux

mq_close(3)

fermer une file d'attente de messages POSIX

LIBRARY

Message queues - part of the POSIX threads library, libpthread.

SYNOPSIS

#include <mqueue.h>



int mq_close(mqd_t mqdes);

DESCRIPTION

The mq_close() function closes the message queue described by the message queue descriptor mqdes. The descriptor is no longer valid after a call to mq_close(). If this was the last open message queue descriptor for the process, the process's message queue descriptor table entry is deallocated. The underlying message queue object is not destroyed. If other processes have the message queue descriptor open, they are unaffected.

A process can close a message queue descriptor that it obtained from a previous call to mq_open(3).

If the calling process has registered a notification request with mq_notify(3) for this message queue, the registration is cancelled, and any pending notification for the calling process is discarded. See mq_notify(3) for more information.

RETURN VALUE

On success, mq_close() returns 0. On error, it returns -1, and errno is set to indicate the error.

ERRORS

EBADF
The argument mqdes is not a valid message queue descriptor.
EINVAL
mqdes refers to a message queue descriptor that has already been closed.

VERSIONS

The POSIX message queues API was introduced in Linux kernel 2.6.6.

STANDARDS

This function is specified in the POSIX.1-2001 and POSIX.1-2008 standards.

HISTORY

The mq_close() function first appeared in Linux kernel 2.6.6. It was also introduced in HP-UX 11i. This functionality was added to glibc in version 2.3.4.

BUGS

The original POSIX specification allowed mq_close() to be called on a descriptor that had already been closed, and it was specified that EINVAL should be returned in that case. However, on Linux and some other systems, calling mq_close() on an already closed descriptor results in undefined behavior.
