NOM

mqttui-read-one - Attend le premier message sur le(s) sujet(s) donné(s) et renvoie sa charge utile vers la sortie standard

SYNTAXE

mqttui read-one [-r|--ignore-retained] [-p|--pretty] [-b|--broker] [-u|--username] [--password] [-i|--client-id] [--client-cert] [--client-key] [--insecure] [-h|--help] [SUJET]

DESCRIPTION

Attend le premier message sur le(s) sujet(s) donné(s) et renvoie sa charge utile vers la sortie standard.

Renvoie exactement une charge utile du premier message reçu sur le(s) sujet(s) donné(s). Le sujet du message reçu est imprimé sur la sortie d'erreur. Cela signifie que vous pouvez gérer la sortie standard et la sortie d'erreur séparément.

Cela peut être utile pour les scripts afin d'obtenir la lecture de température actuelle et de la rediriger ailleurs :

`echo "La température est $(mqttui read-one room/temp)"`

La sortie est la charge utile exacte sous forme binaire. Cela peut être un ASCII / Unicode valide mais aussi quelque chose qui n'est pas destiné à être affiché sur un terminal. Pour un format lisible par l'homme, utilisez `--pretty` ou `mqttui log`.

OPTIONS

-r, --ignore-retained
Ne pas répondre à un message conservé lors de la connexion, attendre qu'un autre message arrive
-p, --pretty
Analyser la charge utile et l'imprimer dans un format lisible par l'homme.

Cela peut ne pas être utile pour rediriger les données.

-h, --help
Imprimer l'aide (voir un résumé avec '-h')
[SUJET] [défaut : #]
Sujets à surveiller
Peut également être spécifié avec la variable d'environnement MQTTUI_TOPIC.

CONNEXION MQTT

-b, --broker=URL [défaut : mqtt://localhost]
URL représentant la manière de se connecter au broker MQTT.

Exemples : `mqtt://localhost` `mqtt://localhost:1883` `mqtts://localhost` `mqtts://localhost:8883` `ws://localhost/path` `ws://localhost:9001/path` `wss://localhost/path` `wss://localhost:9001/path`

Peut également être spécifié avec la variable d'environnement MQTTUI_BROKER.
-u, --username=CHAINE
Nom d'utilisateur pour accéder au broker mqtt.

Accès anonyme lorsqu'il n'est pas fourni.

Peut également être spécifié avec la variable d'environnement MQTTUI_USERNAME.
--password=CHAINE
Mot de passe pour accéder au broker mqtt.

Envisagez d'utiliser une connexion avec TLS au broker. Sinon, le mot de passe sera transporté en texte clair.

Passer le mot de passe via la ligne de commande est dangereux car le mot de passe peut être lu dans l'historique ! Vous devriez le passer via une variable d'environnement.

Peut également être spécifié avec la variable d'environnement MQTTUI_PASSWORD.
-i, --client-id=CHAINE
Spécifier l'ID client avec lequel se connecter
Peut également être spécifié avec la variable d'environnement MQTTUI_CLIENTID.
--client-cert=CHEMIN
Chemin vers le fichier de certificat client TLS.

Utilisé avec --client-key pour activer l'authentification du client TLS. Le fichier doit être un certificat X.509 encodé en DER sérialisé en PEM.

Peut également être spécifié avec la variable d'environnement MQTTUI_CLIENT_CERTIFICATE.
--client-key=CHEMIN
Chemin vers la clé privée client TLS.

Utilisé avec --client-cert pour activer l'authentification du client TLS. Le fichier doit être un fichier ASN.1 encodé en DER au format PKCS#8 sérialisé en PEM.

Peut également être spécifié avec la variable d'environnement MQTTUI_CLIENT_PRIVATE_KEY.
--insecure
Autoriser les connexions TLS non sécurisées
