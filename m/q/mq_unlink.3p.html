MQ_UNLINK(3P) Manuel du programmeur POSIX MQ_UNLINK(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

mq_unlink — supprimer une file d'attente de messages (TEMPS RÉEL)

SYNTAXE

#include <mqueue.h>
int mq_unlink(const char *name);

DESCRIPTION

La fonction mq_unlink() supprime la file d'attente de messages nommée par la chaîne name. Si un ou plusieurs processus ont la file d'attente de messages ouverte lorsque mq_unlink() est appelée, la destruction de la file d'attente de messages sera reportée jusqu'à ce que toutes les références à la file d'attente de messages aient été fermées. Cependant, l'appel à mq_unlink() n'a pas besoin de bloquer jusqu'à ce que toutes les références soient fermées ; il peut retourner immédiatement.

Après un appel réussi à mq_unlink(), la réutilisation du nom entraînera ultérieurement le comportement de mq_open() comme si aucune file d'attente de messages de ce nom n'existait (c'est-à-dire que mq_open() échouera si O_CREAT n'est pas défini, ou créera une nouvelle file d'attente de messages si O_CREAT est défini).

VALEUR DE RETOUR

En cas de succès, la fonction retourne la valeur zéro. Sinon, la file d'attente de messages nommée ne sera pas modifiée par cet appel de fonction, et la fonction retournera la valeur -1 et définira errno pour indiquer l'erreur.

ERREURS

La fonction mq_unlink() échouera si :

EACCES
La permission est refusée pour supprimer la file d'attente de messages nommée.
EINTR
L'appel à mq_unlink() a bloqué en attendant que toutes les références à la file d'attente de messages nommée soient fermées et qu'un signal interrompe l'appel.
ENOENT
La file d'attente de messages nommée n'existe pas.

La fonction mq_unlink() peut échouer si :

ENAMETOOLONG

La longueur de l'argument name dépasse {_POSIX_PATH_MAX} sur les systèmes qui ne prennent pas en charge l'option XSI ou dépasse {_XOPEN_PATH_MAX} sur les systèmes XSI, ou a un composant de nom de chemin plus long que {_POSIX_NAME_MAX} sur les systèmes qui ne prennent pas en charge l'option XSI ou plus long que {_XOPEN_NAME_MAX} sur les systèmes XSI. Un appel à mq_unlink() avec un argument name qui contient le même nom de file d'attente de messages que celui précédemment utilisé dans un appel réussi à mq_open() ne générera pas d'erreur [ENAMETOOLONG].
