NOM

mq_overview - aperçu des files de messages POSIX

DESCRIPTION

Les files de messages POSIX permettent aux processus d'échanger des données sous forme de messages. Cette API est distincte de celle fournie par les files de messages System V (msgget(2), msgsnd(2), msgrcv(2), etc.), mais fournit une fonctionnalité similaire.

Les files de messages sont créées et ouvertes en utilisant mq_open(3) ; cette fonction retourne un descripteur de file de messages (mqd_t), qui est utilisé pour faire référence à la file de messages ouverte dans les appels ultérieurs. Chaque file de messages est identifiée par un nom de la forme /somename ; c'est-à-dire, une chaîne terminée par un caractère nul de NAME_MAX (soit 255) caractères maximum, composée d'une barre oblique initiale, suivie d'un ou plusieurs caractères, aucun desquels n'étant une barre oblique. Deux processus peuvent opérer sur la même file en passant le même nom à mq_open(3).

Les messages sont transférés vers et depuis une file en utilisant mq_send(3) et mq_receive(3). Lorsqu'un processus a terminé d'utiliser la file, il la ferme en utilisant mq_close(3), et lorsqu'elle n'est plus nécessaire, elle peut être supprimée en utilisant mq_unlink(3). Les attributs de la file peuvent être récupérés et (dans certains cas) modifiés en utilisant mq_getattr(3) et mq_setattr(3). Un processus peut demander une notification asynchrone de l'arrivée d'un message sur une file précédemment vide en utilisant mq_notify(3).

Un descripteur de file de messages est une référence à une description ouverte de file de messages (voir open(2)). Après un fork(2), un enfant hérite de copies des descripteurs de files de messages de son parent, et ces descripteurs font référence aux mêmes descriptions ouvertes de files de messages que les descripteurs correspondants dans le parent. Les descripteurs de files de messages correspondants dans les deux processus partagent les drapeaux (mq_flags) qui sont associés à la description ouverte de la file de messages.

Chaque message a une priorité associée, et les messages sont toujours livrés au processus récepteur par ordre de priorité la plus élevée. Les priorités des messages vont de 0 (basse) à sysconf(_SC_MQ_PRIO_MAX) - 1 (haute). Sous Linux, sysconf(_SC_MQ_PRIO_MAX) retourne 32768, mais POSIX.1 exige seulement qu'une implémentation supporte au moins des priorités dans la plage 0 à 31 ; certaines implémentations ne fournissent que cette plage.

Le reste de cette section décrit certains détails spécifiques de l'implémentation Linux des files de messages POSIX.

Interfaces bibliothèque et appels système

Dans la plupart des cas, les interfaces de bibliothèque mq_*() listées ci-dessus sont implémentées par-dessus des appels système sous-jacents du même nom. Les déviations de ce schéma sont indiquées dans le tableau suivant :

Interface bibliothèque Appel système
mq_close(3) close(2)
mq_getattr(3) mq_getsetattr(2)
mq_notify(3) mq_notify(2)
mq_open(3) mq_open(2)

Versions

Les files de messages POSIX sont prises en charge depuis Linux 2.6.6. Le support de glibc est disponible depuis glibc 2.3.4.

Configuration du noyau

Le support des files de messages POSIX est configurable via l'option de configuration du noyau CONFIG_POSIX_MQUEUE. Cette option est activée par défaut.

Persistance

Les files de messages POSIX ont une persistance au niveau du noyau : si elles ne sont pas supprimées par mq_unlink(3), une file de messages existera jusqu'à l'arrêt du système.

Liaison

Les programmes utilisant l'API des files de messages POSIX doivent être compilés avec cc -lrt pour se lier à la bibliothèque temps réel, librt.

Interfaces /proc

Les interfaces suivantes peuvent être utilisées pour limiter la quantité de mémoire du noyau consommée par les files de messages POSIX et pour définir les attributs par défaut pour les nouvelles files de messages :

/proc/sys/fs/mqueue/msg_default (depuis Linux 3.5)
Ce fichier définit la valeur utilisée pour le paramètre mq_maxmsg d'une nouvelle file lorsque la file est créée avec un appel à mq_open(3) où attr est spécifié comme NULL. La valeur par défaut pour ce fichier est 10. Les valeurs minimale et maximale sont les mêmes que pour /proc/sys/fs/mqueue/msg_max. Le nombre maximal de messages par défaut d'une nouvelle file sera le plus petit entre msg_default et msg_max. Avant Linux 2.6.28, le mq_maxmsg par défaut était 10 ; de Linux 2.6.28 à Linux 3.4, la valeur par défaut était celle définie pour la limite msg_max.
/proc/sys/fs/mqueue/msg_max
Ce fichier peut être utilisé pour afficher et modifier la valeur plafond pour le nombre maximum de messages dans une file. Cette valeur agit comme une limite pour l'argument attr->mq_maxmsg passé à mq_open(3). La valeur par défaut pour msg_max est 10. La valeur minimale est 1 (10 avant Linux 2.6.28). La limite supérieure est HARD_MSGMAX. La limite msg_max est ignorée pour les processus privilégiés (CAP_SYS_RESOURCE), mais la limite plafond HARD_MSGMAX est néanmoins imposée.
La définition de HARD_MSGMAX a changé au fil des versions du noyau :
•
Jusqu'à Linux 2.6.32 : 131072 / sizeof(void *)
•
Linux 2.6.33 à Linux 3.4 : (32768 * sizeof(void *) / 4)
•
Depuis Linux 3.5 : 65 536
/proc/sys/fs/mqueue/msgsize_default (depuis Linux 3.5)
Ce fichier définit la valeur utilisée pour le paramètre mq_msgsize d'une nouvelle file lorsque la file est créée avec un appel à mq_open(3) où attr est spécifié comme NULL. La valeur par défaut pour ce fichier est 8192 (octets). Les valeurs minimale et maximale sont les mêmes que pour /proc/sys/fs/mqueue/msgsize_max. Si msgsize_default dépasse msgsize_max, la valeur par défaut mq_msgsize d'une nouvelle file est plafonnée à la limite msgsize_max. Avant Linux 2.6.28, le mq_msgsize par défaut était 8192 ; de Linux 2.6.28 à Linux 3.4, la valeur par défaut était celle définie pour la limite msgsize_max.
/proc/sys/fs/mqueue/msgsize_max
Ce fichier peut être utilisé pour afficher et modifier la limite plafond sur la taille maximale des messages. Cette valeur agit comme une limite plafond pour l'argument attr->mq_msgsize passé à mq_open(3). La valeur par défaut pour msgsize_max est 8192 octets. La valeur minimale est 128 (8192 avant Linux 2.6.28). La limite supérieure pour msgsize_max a varié au fil des versions du noyau :
•
Avant Linux 2.6.28, la limite supérieure est INT_MAX.
•
De Linux 2.6.28 à Linux 3.4, la limite est de 1 048 576.
•
Depuis Linux 3.5, la limite est de 16 777 216 (HARD_MSGSIZEMAX).
La limite msgsize_max est ignorée pour les processus privilégiés (CAP_SYS_RESOURCE), mais, depuis Linux 3.5, la limite plafond HARD_MSGSIZEMAX est appliquée aux processus privilégiés.

mq_overview - aperçu des files d'attente de messages POSIX

DESCRIPTION

Les files d'attente de messages POSIX sont un moyen pour les processus d'échanger des messages de manière fiable et asynchrone. Elles sont définies par la norme POSIX.1 et sont distinctes des files d'attente de messages System V plus anciennes (msgget(2), msgsnd(2), msgrcv(2)).

Les files d'attente de messages POSIX offrent une interface plus riche et plus facile à utiliser que les files d'attente de messages System V. Elles prennent en charge les notifications asynchrones, la gestion des priorités des messages et la possibilité de travailler avec des descripteurs de fichiers.

Limite au niveau du système

Le fichier /proc/sys/fs/mqueue/queues_max contrôle la limite au niveau du système sur le nombre de files d'attente de messages pouvant être créées. La valeur par défaut pour queues_max est 256. Aucune limite supérieure n'est imposée à la limite queues_max ; les processus privilégiés (CAP_SYS_RESOURCE) peuvent dépasser la limite (mais voir la section BUGS).

Limite de ressources

La limite de ressources RLIMIT_MSGQUEUE, qui impose une limite à l'espace pouvant être consommé par toutes les files d'attente de messages appartenant à l'ID utilisateur réel d'un processus, est décrite dans getrlimit(2).

Montage du système de fichiers des files d'attente de messages

Sous Linux, les files d'attente de messages sont créées dans un système de fichiers virtuel. (D'autres implémentations peuvent également offrir une telle fonctionnalité, mais les détails sont susceptibles de différer.) Ce système de fichiers peut être monté (par le superutilisateur) à l'aide des commandes suivantes :


# mkdir /dev/mqueue
# mount -t mqueue none /dev/mqueue

Le bit collant est automatiquement activé sur le répertoire de montage.

Une fois le système de fichiers monté, les files d'attente de messages du système peuvent être visualisées et manipulées à l'aide des commandes habituellement utilisées pour les fichiers (par exemple, ls(1) et rm(1)).

Le contenu de chaque fichier dans le répertoire se compose d'une seule ligne contenant des informations sur la file d'attente :


$ cat /dev/mqueue/mymq
QSIZE:129     NOTIFY:2    SIGNO:0    NOTIFY_PID:8260

Ces champs sont les suivants :

QSIZE
Nombre d'octets de données dans tous les messages de la file d'attente (mais voir BUGS).
NOTIFY_PID
S'il est différent de zéro, le processus ayant cet ID PID a utilisé mq_notify(3) pour s'enregistrer pour une notification de message asynchrone, et les champs restants décrivent comment la notification se produit.
NOTIFY
Méthode de notification : 0 est SIGEV_SIGNAL ; 1 est SIGEV_NONE ; et 2 est SIGEV_THREAD.
SIGNO
Numéro de signal à utiliser pour SIGEV_SIGNAL.

Implémentation Linux des descripteurs de files d'attente de messages

Sous Linux, un descripteur de file d'attente de messages est en fait un descripteur de fichier. (POSIX n'exige pas une telle implémentation.) Cela signifie qu'un descripteur de file d'attente de messages peut être surveillé à l'aide de select(2), poll(2) ou epoll(7). Ceci n'est pas portable.

Le drapeau close-on-exec (voir open(2)) est automatiquement défini sur le descripteur de fichier retourné par mq_open(2).

Espaces de noms IPC

Pour une discussion sur l'interaction des objets de files d'attente de messages POSIX et des espaces de noms IPC, voir ipc_namespaces(7).

NOTES

Les files d'attente de messages System V (msgget(2), msgsnd(2), msgrcv(2), etc.) sont une ancienne API pour l'échange de messages entre processus. Les files d'attente de messages POSIX fournissent une interface mieux conçue que les files d'attente de messages System V ; d'un autre côté, les files d'attente de messages POSIX sont moins largement disponibles (surtout sur les anciens systèmes) que les files d'attente de messages System V.

Linux ne prend pas actuellement en charge (Linux 2.6.26) l'utilisation de listes de contrôle d'accès (ACL) pour les files d'attente de messages POSIX.

BOGUES

De Linux 3.5 à Linux 3.14, le noyau imposait une limite supérieure de 1024 (HARD_QUEUESMAX) à la valeur à laquelle la limite queues_max pouvait être augmentée, et cette limite était appliquée même aux processus privilégiés. Cette limite supérieure a été supprimée dans Linux 3.14, et les correctifs pour les versions stables de Linux 3.5.x à 3.13.x ont également supprimé la limite supérieure.

Comme initialement implémenté (et documenté), le champ QSIZE affichait le nombre total d'octets (fournis par l'utilisateur) dans tous les messages de la file d'attente de messages. Certains changements dans Linux 3.5 ont involontairement modifié le comportement, de sorte que ce champ incluait également un compte des octets de surcharge du noyau utilisés pour stocker les messages dans la file d'attente. Cette régression comportementale a été corrigée dans Linux 4.2 (et les séries de noyaux stables antérieures), de sorte que le compte n'inclut plus que les octets de données utilisateur dans les messages de la file d'attente.

EXEMPLES

Un exemple d'utilisation de diverses fonctions de file d'attente de messages est présenté dans mq_notify(3).
