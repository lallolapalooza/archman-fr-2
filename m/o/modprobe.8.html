NOM

modprobe - Ajouter et supprimer des modules du noyau Linux

SYNTAXE

modprobe [-v] [-V] [-C fichier-config] [-n] [-i] [-q] [-b] [nom-module]
[paramètres-module...]

modprobe [-r] [-v] [-n] [-i] [nom-module...]

modprobe [-c]

modprobe [--dump-modversions] [nom-fichier]

DESCRIPTION

modprobe ajoute ou supprime intelligemment un module du noyau Linux : notez que pour plus de commodité, il n'y a pas de différence entre _ et - dans les noms de modules (une conversion automatique des underscores est effectuée). modprobe recherche dans le répertoire des modules /usr/lib/`uname -r` tous les modules et autres fichiers, à l'exception des fichiers de configuration optionnels (voir modprobe.d(5)). modprobe utilisera également les options de module spécifiées sur la ligne de commande du noyau sous la forme <module>.<option> et les listes noires sous la forme modprobe.blacklist=<module>.

Notez que contrairement aux noyaux Linux de la série 2.4 (qui ne sont pas pris en charge par cet outil), cette version de modprobe ne fait rien au module lui-même : le travail de résolution des symboles et de compréhension des paramètres est effectué à l'intérieur du noyau. Ainsi, un échec de module est parfois accompagné d'un message du noyau : voir dmesg(8).

modprobe attend un fichier modules.dep.bin à jour tel que généré par l'utilitaire depmod correspondant fourni avec modprobe (voir depmod(8)). Ce fichier liste les autres modules dont chaque module a besoin (le cas échéant), et modprobe l'utilise pour ajouter ou supprimer automatiquement ces dépendances.

Si des arguments sont donnés après le nom-module, ils sont transmis au noyau (en plus des options listées dans le fichier de configuration).

Lors du chargement des modules, le nom-module peut aussi être un chemin vers le module. Si le chemin est relatif, il doit commencer explicitement par "./". Notez que cela peut échouer lors de l'utilisation d'un chemin vers un module avec des dépendances ne correspondant pas à la base de données depmod installée.

OPTIONS

-a, --all

Insère tous les noms de modules sur la ligne de commande.

-b, --use-blacklist

Cette option fait en sorte que modprobe applique également les commandes blacklist des fichiers de configuration (le cas échéant) aux noms de modules. Elle est généralement utilisée par udev(7).

-C répertoire, --config=répertoire

Cette option surcharge le répertoire de configuration par défaut. Voir modprobe.d(5).

Cette option est transmise aux commandes install ou remove à d'autres commandes modprobe dans la variable d'environnement MODPROBE_OPTIONS.

-c, --showconfig

Affiche la configuration effective du répertoire de configuration et quitte.

--dump-modversions

Affiche une liste des informations de versionnement de modules requises par un module. Cette option est couramment utilisée par les distributions pour empaqueter un module de noyau Linux en utilisant les dépendances de versionnement de modules.

-d, --dirname

Répertoire racine pour les modules, / par défaut.

--first-time

Normalement, modprobe réussira (et ne fera rien) si on lui demande d'insérer un module déjà présent ou de supprimer un module absent. C'est idéal pour les scripts simples ; cependant, les scripts plus complexes veulent souvent savoir si modprobe a réellement fait quelque chose : cette option fait échouer modprobe dans le cas où il n'a rien fait.

--force-vermagic

Chaque module contient une petite chaîne contenant des informations importantes, telles que les versions du noyau et du compilateur. Si un module ne parvient pas à se charger et que le noyau se plaint que la "version magique" ne correspond pas, vous pouvez utiliser cette option pour la supprimer. Naturellement, cette vérification est là pour vous protéger, donc l'utilisation de cette option est dangereuse à moins que vous ne sachiez ce que vous faites.

Cela s'applique à tous les modules insérés : le module (ou alias) sur la ligne de commande et tous les modules dont il dépend.

--force-modversion

Lorsque les modules sont compilés avec CONFIG_MODVERSIONS activé, une section détaillant les versions de chaque interface utilisée par (ou fournie par) le module est créée. Si un module ne parvient pas à se charger et que le noyau se plaint que le module est en désaccord sur une version d'une interface, vous pouvez utiliser --force-modversion pour supprimer complètement les informations de version. Naturellement, cette vérification est là pour vous protéger, donc l'utilisation de cette option est dangereuse à moins que vous ne sachiez ce que vous faites.

Cela s'applique à tous les modules insérés : le module (ou alias) sur la ligne de commande et tous les modules dont il dépend.

-f, --force

Essaye de supprimer toute information de versionnement du module qui pourrait autrement l'empêcher de se charger : c'est la même chose que d'utiliser à la fois --force-vermagic et --force-modversion. Naturellement, ces vérifications sont là pour vous protéger, donc l'utilisation de cette option est dangereuse à moins que vous ne sachiez ce que vous faites.

Cela s'applique à tous les modules insérés : le module (ou alias) sur la ligne de commande et tous les modules dont il dépend.

-i, --ignore-install, --ignore-remove

Cette option fait en sorte que modprobe ignore les commandes install et remove dans le fichier de configuration (le cas échéant) pour le module spécifié sur la ligne de commande (tous les modules dépendants sont toujours soumis aux commandes qui leur sont appliquées dans le fichier de configuration). Les deux commandes install et remove seront actuellement ignorées lorsque cette option est utilisée, qu'importe si la demande a été plus spécifiquement faite avec une seule ou l'autre (et pas les deux) de --ignore-install ou --ignore-remove. Voir modprobe.d(5).

-n, --dry-run, --show

Cette option fait tout sauf insérer ou supprimer réellement les modules (ou exécuter les commandes d'installation ou de suppression). Combinée avec -v, elle est utile pour le débogage des problèmes. Pour des raisons historiques, --dry-run et --show signifient en fait la même chose et sont interchangeables.

-q, --quiet

Avec ce drapeau, modprobe n'imprimera pas de message d'erreur si vous essayez de supprimer ou d'insérer un module qu'il ne trouve pas (et qui n'est pas un alias ou une commande install/remove). Cependant, il retournera toujours un code de sortie non nul. Le noyau utilise ceci pour sonder de manière opportuniste les modules qui pourraient exister en utilisant request_module.

-R, --resolve-alias

Affiche tous les noms de modules correspondant à un alias. Ceci peut être utile pour le débogage des problèmes d'alias de module.

-r, --remove

Cette option fait en sorte que modprobe supprime plutôt qu'il n'insère un module. Si les modules dont il dépend sont également inutilisés, modprobe tentera de les supprimer également. Contrairement à l'insertion, plusieurs modules peuvent être spécifiés sur la ligne de commande (il n'est pas logique de spécifier des paramètres de module lors de la suppression de modules).

Il n'y a généralement aucune raison de supprimer des modules, mais certains modules bogués l'exigent. Votre noyau de distribution peut ne pas avoir été compilé pour prendre en charge la suppression de modules.

-w TIMEOUT_MSEC, --wait=TIMEOUT_MSEC

Cette option fait en sorte que modprobe -r continue d'essayer de supprimer un module s'il échoue en raison du module utilisé, c'est-à-dire si son compteur de références (refcount) n'est pas 0 au moment où l'appel est fait. Modprobe tente de supprimer le module avec un temps de pause incrémental entre chaque tentative jusqu'au temps d'attente maximum en millisecondes passé dans cette option.

-S version, --set-version=version

Définit la version du noyau, plutôt que d'utiliser uname(2) pour décider de la version du noyau (qui détermine où trouver les modules).

--show-depends

Liste les dépendances d'un module (ou alias), y compris le module lui-même. Cela produit un ensemble (éventuellement vide) de noms de fichiers de modules,

-V, --version

Affiche la version du programme et quitte.

-v, --verbose

Affiche des messages sur ce que fait le programme. Habituellement, modprobe n'affiche des messages que si quelque chose ne va pas.

Cette option est transmise aux commandes install ou remove vers d'autres commandes modprobe dans la variable d'environnement MODPROBE_OPTIONS.

ENVIRONNEMENT

La variable d'environnement MODPROBE_OPTIONS peut également être utilisée pour passer des arguments de ligne de commande à modprobe. Le format est intentionnellement laissé non documenté, car son utilisation par des outils et des scripts tiers est découragée.

La variable d'environnement provient de l'implémentation des règles d'installation.
