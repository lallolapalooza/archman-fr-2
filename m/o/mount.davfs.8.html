NOM

@PROGRAM_NAME@ - Monter un système de fichiers WebDAV en tant que système de fichiers @PACKAGE@

SYNTAXE

@PROGRAM_NAME@ [-h | --help] [-V | --version]
mount {répertoire | serveurwebdav}

SYNTAXE (root uniquement)

mount -t davfs [-o option[,...]] serveurwebdav répertoire
@PROGRAM_NAME@ [-o option[,...]] serveurwebdav répertoire

DESCRIPTION

@PROGRAM_NAME@ permet de monter la ressource WebDAV identifiée par serveurwebdav dans le système de fichiers local au niveau de répertoire. WebDAV est une extension de HTTP qui permet l'édition collaborative à distance de ressources Web, définie dans la RFC 4918. @PROGRAM_NAME@ fait partie de @PACKAGE@.

@PACKAGE@ permet d'éditer des documents sur un serveur Web distant à l'aide d'applications standard. Par exemple, un site Web distant pourrait être mis à jour sur place en utilisant les mêmes outils de développement qui ont initialement créé le site. Ou vous pouvez utiliser une ressource WebDAV pour les documents que vous souhaitez accéder et modifier depuis différents endroits.

@PACKAGE@ supporte TLS/SSL (si la bibliothèque neon le supporte) et les proxys. @PROGRAM_NAME@ s'exécute comme un démon dans l'espace utilisateur. Il s'intègre dans le système de fichiers virtuel grâce au système de fichiers noyau FUSE. Actuellement, FUSE_KERNEL_VERSION 7 est supporté.

@PROGRAM_NAME@ est généralement invoqué par la commande mount(8) lors de l'utilisation de l'option -t davfs. Après le montage, il s'exécute comme un démon. Pour démonter, la commande umount(8) est utilisée.

serveurwebdav est l'URL du serveur. Elle doit au moins contenir le nom d'hôte. Elle peut éventuellement contenir le schéma, le port et le chemin. Les composants manquants sont remplacés par des valeurs par défaut raisonnables. Le composant chemin ne doit pas être encodé en pour cent (%), mais lors de la saisie de l'URL sur la ligne de commande ou dans /etc/fstab, les règles d'échappement du shell ou de fstab doivent être respectées.

répertoire est le point de montage où la ressource WebDAV est montée. Il peut s'agir d'un chemin absolu ou relatif.

fstab peut être utilisé pour définir les montages et les options de montage comme d'habitude. À la place du périphérique, l'URL du serveur WebDAV doit être fournie. Il ne doit pas y avoir plus d'une entrée dans fstab pour chaque point de montage.

OPTIONS

-V --version
Affiche la version.
-h --help
Affiche un message d'aide.
-o
Une liste séparée par des virgules définit les options de montage à utiliser. Les options disponibles sont :
[no]auto
Peut (ne peut pas) être monté avec mount -a.
Par défaut : auto.
comment=un commentaire
Cette option est ignorée par @PROGRAM_NAME@, mais d'autres programmes peuvent exiger sa présence dans fstab.
conf=chemin absolu
Un fichier de configuration utilisateur alternatif. Cette option est destinée aux cas où le fichier de configuration utilisateur par défaut dans le répertoire personnel de l'utilisateur ne peut pas être utilisé.
Par défaut : ~/.@PACKAGE@/@CONFIGFILE@
[no]dev
(N')interprète pas les périphériques spéciaux de caractères ou de blocs sur le système de fichiers. Cette option n'est incluse que pour la compatibilité avec le programme mount(8). Elle sera toujours définie sur nodev.
dir_mode=mode
Les bits de mode par défaut pour les répertoires dans le système de fichiers monté. Valeur donnée en octal. Les bits s (setuid, setgid, sticky) pour l'utilisateur et le groupe sont toujours ignorés silencieusement.
Par défaut : calculé à partir de l'umask de l'utilisateur qui monte ; un bit x est associé à chaque bit r dans u-g-o.
[no]exec
(Ne pas) autoriser l'exécution de binaires sur le système de fichiers monté.
Par défaut : exec. (Lors du montage en tant qu'utilisateur ordinaire, le programme mount(8) définira la valeur par défaut sur noexec.)
file_mode=mode
Les bits de mode par défaut pour les fichiers dans le système de fichiers monté. Valeur donnée en octal. Les bits s pour l'utilisateur et le groupe sont toujours ignorés silencieusement.
Par défaut : calculé à partir de l'umask de l'utilisateur qui monte ; aucun bit x n'est défini pour les fichiers.
gid=groupe
Le groupe auquel appartient le système de fichiers monté. Il peut s'agir d'un ID numérique ou d'un nom de groupe. L'utilisateur qui monte, s'il n'est pas root, doit faire partie de ce groupe.
Par défaut : le groupe principal de l'utilisateur qui monte.
[no]grpid
Lorsque cette option est définie, un fichier nouvellement créé prendra l'ID de groupe du répertoire dans lequel il est créé. Cela s'appliquera également à tous les fichiers qui sont sur le serveur et qui ne sont pas dans le cache local. (C'est parce que l'ID de groupe n'est pas stocké sur le serveur.)
Si l'ID de groupe du répertoire est root, cette option est ignorée.
Par défaut : nogrpid.
[no]_netdev
Le système de fichiers nécessite (ou pas) une connexion réseau pour fonctionner. Cette information permet au système d'exploitation de gérer correctement le système de fichiers au démarrage du système et lorsque le réseau est arrêté.
Par défaut : _netdev
ro
Monter le système de fichiers en lecture seule.
Par défaut : rw.
rw
Monter le système de fichiers en lecture-écriture.
Par défaut : rw.
[no]suid
(Ne pas) autoriser les bits set-user-ID ou set-group-ID à prendre effet. Cette option n'est incluse que pour la compatibilité avec le programme mount. Elle sera toujours définie sur nosuid.
[no]user
(Ne pas) autoriser un utilisateur ordinaire à monter le système de fichiers. Le nom de l'utilisateur qui monte est écrit dans mtab afin qu'il puisse démonter le système de fichiers à nouveau. L'option user implique les options noexec, nosuid et nodev (sauf si elles sont remplacées par des options ultérieures). Cette option n'a de sens que lorsqu'elle est définie dans fstab.
Par défaut : les utilisateurs ordinaires ne sont pas autorisés à monter.
users
Comme user, mais n'importe quel utilisateur est autorisé à démonter le système de fichiers, pas seulement l'utilisateur qui l'a monté. Ce n'est généralement pas recommandé. Si l'option user permet à un utilisateur non privilégié de monter, mais que le démontage par l'utilisateur qui a monté échoue, users peut être une solution de contournement.
Par défaut : seul l'utilisateur qui monte est autorisé à démonter le système de fichiers.
uid=utilisateur
Le propriétaire du système de fichiers monté. Il peut s'agir d'un ID numérique ou d'un nom d'utilisateur. Ce n'est que lorsqu'il est monté par root que cela peut être différent de l'utilisateur qui monte.
Par défaut : ID de l'utilisateur qui monte.
username=utilisateur_WebDAV
Utiliser ce nom pour s'authentifier auprès du serveur WebDAV. Cette option est destinée à être utilisée uniquement avec pam_mount. Lorsque cette option est définie, les identifiants dans les fichiers secrets seront ignorés. Le mot de passe sera toujours lu depuis stdin, même lorsque l'option askauth est définie sur 0. Ne l'utilisez pas dans fstab. Le nom d'utilisateur sera visible par tout le monde dans la sortie de ps.
Par défaut : pas de nom d'utilisateur.

POLITIQUE DE SÉCURITÉ

@PROGRAM_NAME@ nécessite les privilèges root pour le montage. Mais exécuter un démon connecté à Internet avec des privilèges root constitue un risque de sécurité. Ainsi, @PROGRAM_NAME@ changera son uid et gid lorsqu'il entrera en mode démon.

Lorsqu'il est invoqué par root, @PROGRAM_NAME@ s'exécutera en tant qu'utilisateur @USER@ et groupe @GROUP@. Cela peut être modifié dans @SYS_CONF_DIR@/@CONFIGFILE@.

Lorsqu'il est invoqué par un utilisateur ordinaire, il s'exécutera avec l'ID de cet utilisateur et le groupe @GROUP@.

Vous ne devriez faire cela que si vous pouviez aussi bien donner ces informations à l'utilisateur directement.

URLS ET POINTS DE MONTAGE AVEC DES ESPACES

Les caractères spéciaux comme les espaces dans les noms de chemin sont compliqués. Ils sont interprétés différemment par différents programmes et protocoles, et il existe différentes règles d'échappement.

Dans fstab, les espaces doivent être remplacés par une séquence d'échappement octale à trois chiffres. Écrivez http://foo.bar/path\040with\040spaces au lieu de http://foo.bar/path avec des espaces.

Pour les fichiers @CONFIGFILE@ et @SECRETSFILE@, veuillez consulter les règles d'échappement et de citation décrites dans la page de manuel @CONFIGFILE@(5).

Sur la ligne de commande, vous devez respecter les règles d'échappement du shell.

MISE EN CACHE

@PROGRAM_NAME@ essaie de réduire le trafic HTTP en mettant en cache et en réutilisant les données. Les informations sur les répertoires et les fichiers sont conservées en mémoire, tandis que les fichiers téléchargés sont mis en cache sur disque.

@PROGRAM_NAME@ doit conserver une copie locale de tous les fichiers ouverts dans le répertoire de cache. Veuillez vous assurer qu'il y a suffisamment d'espace disque local disponible.

@PROGRAM_NAME@ considérera les informations mises en cache sur les répertoires et les attributs de fichiers comme valides pendant une durée configurable et ne vérifiera ces informations sur le serveur qu'après l'expiration de cette durée (ou s'il y a d'autres preuves que ces informations sont obsolètes). Ainsi, si quelqu'un d'autre crée ou supprime des fichiers sur le serveur, il faudra un certain temps avant que le système de fichiers local ne reflète cela.

Cela n'affectera pas le contenu des fichiers et les listes de répertoires. Chaque fois qu'un fichier est ouvert, le serveur est consulté pour une version plus récente du fichier. Veuillez consulter le manuel @CONFIGFILE@(5) pour savoir comment configurer cela selon vos besoins.

VERROUS, PROBLÈME DE MISE À JOUR PERDUE ET FICHIERS DE SAUVEGARDE

WebDAV a introduit les verrous et @PROGRAM_NAME@ les utilise par défaut. Cela empêchera dans la plupart des cas deux personnes de modifier le même fichier en parallèle. Mais pas toujours :

Vous pourriez avoir désactivé les verrous dans @SYS_CONF_DIR@/@CONFIGFILE@ ou ~/.@PACKAGE@/@CONFIGFILE@.

Le serveur pourrait ne pas prendre en charge les verrous (ils ne sont pas obligatoires).

Une mauvaise connexion pourrait empêcher @PROGRAM_NAME@ de rafraîchir le verrou à temps.

Un autre client WebDAV pourrait utiliser votre verrou (ce qui n'est pas trop difficile et peut même arriver sans intention).

@PROGRAM_NAME@ vérifiera donc si le fichier a été modifié sur le serveur avant de télécharger une nouvelle version. S'il trouve impossible de télécharger le fichier modifié localement, il le stockera dans le répertoire de sauvegarde local lost+found. Vous devriez vérifier ce répertoire de temps en temps et décider quoi faire de ces fichiers.

Parfois, les verrous détenus par un client sur le serveur ne seront pas libérés. Le client peut planter ou la connexion réseau peut échouer. Lorsque @PROGRAM_NAME@ trouve un fichier verrouillé sur le serveur, il vérifie si le verrou est détenu par @PROGRAM_NAME@ et l'utilisateur actuel, et si c'est le cas, il essaie de le réutiliser et de le libérer. Mais cela ne réussira pas toujours. Les serveurs devraient donc libérer automatiquement les verrous après un certain temps, lorsqu'ils ne sont pas rafraîchis par le client.

WebDAV permet de verrouiller des fichiers qui n'existent pas (pour protéger le nom lorsqu'un client a l'intention de créer un nouveau fichier). Ces verrous seront affichés comme des fichiers de taille 0 et dont la date de dernière modification est 1970-01-01. Si ces verrous ne sont pas libérés correctement, @PROGRAM_NAME@ pourrait ne pas être en mesure d'accéder à ces fichiers. Vous pouvez utiliser cadaver(1) http://www.webdav.org/cadaver/ pour supprimer ces verrous.

PROPRIÉTAIRE ET PERMISSIONS DES FICHIERS

@PACKAGE@ implémente les permissions Unix pour le contrôle d'accès. Mais la modification du propriétaire et des permissions d'un fichier n'est que locale. Elle est destinée à être un moyen pour le propriétaire du système de fichiers de contrôler si d'autres utilisateurs locaux peuvent accéder à ce système de fichiers.

Le serveur ne le sait pas. Du point de vue du serveur, il n'y a qu'un seul utilisateur (identifié par les informations d'identification) connecté. Un autre client WebDAV, connecté au même serveur, n'est pas affecté par ces modifications locales.

Il y a une exception : le bit d'exécution sur les fichiers est stocké comme une propriété sur le serveur. Vous pouvez considérer cette propriété comme une information sur le type de fichier plutôt qu'une permission. L'exécutabilité du fichier sur le système local est toujours contrôlée par les options de montage et les permissions locales.

Lorsque le système de fichiers est démonté, les attributs des fichiers mis en cache (y compris le propriétaire et les permissions) sont stockés dans le cache, ainsi que les attributs des répertoires dans lesquels ils se trouvent. Mais aucune information n'est stockée sur les répertoires qui ne contiennent pas de fichiers mis en cache.

NOM

mount.davfs

monter un système de fichiers WebDAV

SYNTAXE

mount.davfs [-V] [-h] [-v] [-V] [-f] [-N] [-o options] [mountpoint] [mountpoint]

mount.davfs [-V] [-h] [-v] [-V] [-f] [-N] [-o options] device[:special] mountpoint

SYNTAXE (root uniquement)

mount.davfs [-V] [-h] [-v] [-V] [-f] [-N] [-o options] device[:special] mountpoint

DESCRIPTION

Davfs2 est un pilote de système de fichiers qui permet de monter des ressources WebDAV sur le système de fichiers Linux. Davfs2 est implémenté en espace utilisateur et utilise des appels système pour communiquer avec le noyau.

Davfs2 supporte la mise en cache et le verrouillage pour améliorer les performances.

L'utilitaire mount.davfs est utilisé pour monter et démonter des systèmes de fichiers WebDAV.

OPTIONS

Les options suivantes sont disponibles :

auto_cache
Active la mise en cache automatique. Lorsque cette option est activée, davfs2 tente de mettre en cache les fichiers et les répertoires pour améliorer les performances. La mise en cache est désactivée par défaut.
bufcache
Définit la taille du cache tampon en Ko. La valeur par défaut est 1024.
grpid
Active le support des GID (group IDs). Permet aux utilisateurs de monter des systèmes de fichiers WebDAV avec des permissions de groupe spécifiques.
iid
Active le support des identifiants de groupe (group IDs). Permet aux utilisateurs de monter des systèmes de fichiers WebDAV avec des permissions de groupe spécifiques.
keylogin
Active la connexion par clé. Permet aux utilisateurs de se connecter à un serveur WebDAV à l'aide d'une paire de clés publique/privée.
list_xattr
Affiche les attributs étendus des fichiers. Les attributs étendus sont des métadonnées supplémentaires qui peuvent être associées aux fichiers.
lock
Active le support du verrouillage. Permet aux utilisateurs de verrouiller des fichiers pour éviter qu'ils ne soient modifiés par d'autres utilisateurs.
no_cache
Désactive la mise en cache. Les fichiers et les répertoires ne seront pas mis en cache, ce qui peut améliorer les performances dans certains cas.
no_lock
Désactive le support du verrouillage. Les fichiers ne pourront pas être verrouillés, ce qui peut entraîner des conflits d'édition.
no_xattr
Désactive le support des attributs étendus. Les métadonnées supplémentaires ne seront pas stockées ou affichées.
no_xdev
Désactive le montage des systèmes de fichiers cross-device.
offset
Définit le décalage de début du système de fichiers.
persistant_cache
Active la mise en cache persistante. Les données mises en cache sont conservées même après le démontage du système de fichiers.
ro
Monte le système de fichiers en lecture seule.
rw
Monte le système de fichiers en lecture/écriture.
secret
Spécifie le fichier contenant les informations d'identification pour se connecter au serveur WebDAV.
uid
Définit l'UID (User ID) propriétaire des fichiers sur le système de fichiers monté.

POLITIQUE DE SÉCURITÉ

Le montage de systèmes de fichiers WebDAV est potentiellement dangereux. Il est donc fortement recommandé de ne monter que des systèmes de fichiers WebDAV provenant de sources fiables.

Le fichier @SYS_CONF_DIR@/@CONFIGFILE@ contient les informations de configuration du proxy. Il peut être utilisé pour définir les paramètres du proxy pour les montages effectués par l'utilisateur root.

Le fichier ~/.davfs2/secrets contient les informations d'identification pour se connecter aux serveurs WebDAV. Ce fichier doit être protégé en lecture/écriture par l'utilisateur qui l'a créé.

Le proxy http : peut être spécifié dans le fichier @SYS_CONF_DIR@/@CONFIGFILE@ ou dans la variable d'environnement http_proxy. Il peut être spécifié avec ou sans schéma et avec ou sans port.

    http_proxy=[http://]foo.bar[:3218]

Utilisé uniquement lorsque l'utilisateur de montage est root.

URLS ET POINTS DE MONTAGE AVEC ESPACES

Les URL et les points de montage contenant des espaces doivent être encapsulés entre guillemets.

    mount -t davfs -o uid=otto,gid=users,"foo bar" /media/"foo bar"

MISE EN CACHE

Davfs2 prend en charge la mise en cache des données pour améliorer les performances. La mise en cache est activée par défaut. Elle peut être désactivée à l'aide de l'option no_cache.

La taille du cache tampon peut être configurée à l'aide de l'option bufcache.

VERROUS, PROBLÈME DE MISE À JOUR PERDU ET FICHIERS DE SAUVEGARDE

Davfs2 prend en charge le verrouillage des fichiers pour éviter les conflits d'édition. Le verrouillage est activé par défaut. Il peut être désactivé à l'aide de l'option no_lock.

Lorsque le verrouillage est activé, davfs2 crée des fichiers de sauvegarde avec l'extension .backup pour les fichiers modifiés. Ces fichiers peuvent être utilisés pour restaurer les versions précédentes des fichiers.

PROPRIÉTAIRE ET AUTORISATIONS DES FICHIERS

Les options uid et gid peuvent être utilisées pour spécifier le propriétaire et le groupe des fichiers sur le système de fichiers monté.

L'option mode peut être utilisée pour spécifier les autorisations des fichiers.

EXEMPLES

Utilisateur non root (par ex. filomena) :

Pour permettre à un utilisateur ordinaire de monter, il doit y avoir une entrée dans fstab

http://webdav.org/dav /media/dav davfs noauto,user 0 0

Si un proxy doit être utilisé, il doit être configuré dans @SYS_CONF_DIR@/@CONFIGFILE@

proxy proxy.mycompany.com:8080

Les informations d'identification sont stockées dans /home/filomena/.@PACKAGE@/@SECRETSFILE@

proxy.mycompany.com filomena "mon secret"
/media/dav nom-utilisateur-webdav mot-de-passe

Si vous avez activé l'authentification à deux facteurs et si vous pouvez fournir le jeton avec le mot de passe sous la forme mot-de-passe:jeton, ajoutez la chaîne '2FA' comme quatrième paramètre et vous serez invité à entrer le jeton lors du montage.

/media/dav nom-utilisateur "m0t-d3-p@ss\$e" 2FA

Maintenant, la ressource WebDAV peut être montée par l'utilisateur filomena en invoquant

mount /media/dav

et démontée par l'utilisateur filomena en invoquant

umount /media/dav

Utilisateur root uniquement :

Monte la ressource https://asciigirl.com/webdav au point de montage /mount/site, en chiffrant tout le trafic avec SSL. Les informations d'identification pour http://webdav.org/dav seront recherchées dans @SYS_CONF_DIR@/@SECRETSFILE@, sinon l'utilisateur sera invité.

mount -t davfs -o uid=otto,gid=users,mode=775 https://asciigirl.com/webdav /mount/site

Monte la ressource http://linux.org.ar/repos à /dav.

mount.davfs -o uid=otto,gid=users,mode=775 http://linux.org.ar/repos/ /dav
