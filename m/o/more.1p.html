NAME

more — display files on a page-by-page basis

SYNOPSIS

more [-ceisu] [-n number] [-p command] [-t tagstring] [file...]

DESCRIPTION

The more utility shall read files and either write them to the terminal on a page-by-page basis or filter them to standard output. If standard output is not a terminal device, all input files shall be copied to standard output in their entirety, without modification, except as specified for the -s option. If standard output is a terminal device, the files shall be written a number of lines (one screenful) at a time under the control of user commands. See the EXTENDED DESCRIPTION section.

Certain block-mode terminals do not have all the capabilities necessary to support the complete more definition; they are incapable of accepting commands that are not terminated with a <newline>. Implementations that support such terminals shall provide an operating mode to more in which all commands can be terminated with a <newline> on those terminals. This mode:

*
Shall be documented in the system documentation
*
Shall, at invocation, inform the user of the terminal deficiency that requires the <newline> usage and provide instructions on how this warning can be suppressed in future invocations
*
Shall not be required for implementations supporting only fully capable terminals
*
Shall not affect commands already requiring <newline> characters
*
Shall not affect users on the capable terminals from using more as described in this volume of POSIX.1‐2017

OPTIONS

The more utility shall conform to the Base Definitions volume of POSIX.1‐2017, Section 12.2, Utility Syntax Guidelines, except that '+' may be recognized as an option delimiter as well as '-'.

The following options shall be supported:

-c
If a screen is to be written that has no lines in common with the current screen, or more is writing its first screen, more shall not scroll the screen, but instead shall redraw each line of the screen in turn, from the top of the screen to the bottom. In addition, if more is writing its first screen, the screen shall be cleared. This option may be silently ignored on devices with insufficient terminal capabilities.
-e
Exit immediately after writing the last line of the last file in the argument list; see the EXTENDED DESCRIPTION section.
-i
Perform pattern matching in searches without regard to case; see the Base Definitions volume of POSIX.1‐2017, Section 9.2, Regular Expression General Requirements.
-n number
Specify the number of lines per screenful. The number argument is a positive decimal integer. The -n option shall override any values obtained from any other source.
-p command
Each time a screen from a new file is displayed or redisplayed (including as a result of more commands; for example, :p), execute the more command(s) in the command arguments in the order specified, as if entered by the user after the first screen has been displayed. No intermediate results shall be displayed (that is, if the command is a movement to a screen different from the normal first screen, only the screen resulting from the command shall be displayed.) If any of the commands fail for any reason, an informational message to this effect shall be written, and no further commands specified using the -p option shall be executed for this file.
-s
Behave as if consecutive empty lines were a single empty line.
-t tagstring
Write the screenful of the file containing the tag named by the tagstring argument. See the ctags utility. The tags feature represented by -t tagstring and the :t command is optional. It shall be provided on any system that also provides a conforming implementation of ctags; otherwise, the use of -t produces undefined results.

The filename resulting from the -t option shall be logically added as a prefix to the list of command line files, as if specified by the user. If the tag named by the tagstring argument is not found, it shall be an error, and more shall take no further action.

If the tag specifies a line number, the first line of the display shall contain the beginning of that line. If the tag specifies a pattern, the first line of the display shall contain the beginning of the matching text from the first line of the file that contains that pattern. If the line does not exist in the file or matching text is not found, an informational message to this effect shall be displayed, and more shall display the default screen as if -t had not been specified.

If both the -t tagstring and -p command options are given, the -t tagstring shall be processed first; that is, the file and starting line for the display shall be as specified by -t, and then the -p more command shall be executed. If the line (matching text) specified by the -t command does not exist (is not found), no -p more command shall be executed for this file at any time.

-u
Treat a <backspace> as a printable control character, displayed as an implementation-defined character sequence (see the EXTENDED DESCRIPTION section), suppressing backspacing and the special handling that produces underlined or standout mode text on some terminal types. Also, do not ignore a <carriage-return> at the end of a line.

OPERANDS

The following operand shall be supported:

file
A pathname of an input file. If no file operands are specified, the standard input shall be used. If a file is '-', the standard input shall be read at that point in the sequence.

STDIN

The standard input shall be used only if no file operands are specified, or if a file operand is '-'.

INPUT FILES

The input files being examined shall be text files. If standard output is a terminal, standard error shall be used to read commands from the user. If standard output is a terminal, standard error is not readable, and command input is needed, more may attempt to obtain user commands from the controlling terminal (for example, /dev/tty); otherwise, more shall terminate with an error indicating that it was unable to read user commands. If standard output is not a terminal, no error shall result if standard error cannot be opened for reading.

ENVIRONMENT VARIABLES

The following environment variables shall affect the execution of more:

COLUMNS
Override the system-selected horizontal display line size. See the Base Definitions volume of POSIX.1‐2017, Chapter 8, Environment Variables for valid values and results when it is unset or null.

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

more — affiche les fichiers page par page

SYNTAXE

more [-ceisu] [-n nombre] [-p commande] [-t chaîne_étiquette] [fichier...]

DESCRIPTION

L'utilitaire more lit des fichiers et soit les écrit sur le terminal page par page, soit les filtre vers la sortie standard. Si la sortie standard n'est pas un terminal, tous les fichiers d'entrée sont copiés sur la sortie standard dans leur intégralité, sans modification, sauf indication contraire pour l'option -s. Si la sortie standard est un terminal, les fichiers sont écrits ligne par ligne (un écran à la fois) sous le contrôle de commandes utilisateur. Voir la section DESCRIPTION ÉTENDUE.

Certains terminaux en mode bloc n'ont pas toutes les capacités nécessaires pour supporter la définition complète de more ; ils sont incapables d'accepter des commandes qui ne sont pas terminées par une <nouvelle ligne>. Les implémentations qui supportent de tels terminaux doivent fournir un mode de fonctionnement à more dans lequel toutes les commandes peuvent être terminées par une <nouvelle ligne> sur ces terminaux. Ce mode :

*
Doit être documenté dans la documentation système
*
Doit, lors de l'invocation, informer l'utilisateur de la déficience du terminal qui requiert l'utilisation de la <nouvelle ligne> et fournir des instructions sur la manière dont cet avertissement peut être supprimé lors des invocations futures
*
Ne sera pas requis pour les implémentations supportant uniquement des terminaux entièrement capables
*
N'affectera pas les commandes nécessitant déjà des caractères de <nouvelle ligne>
*
N'affectera pas les utilisateurs sur les terminaux capables d'utiliser more comme décrit dans ce volume de POSIX.1-2017

OPTIONS

L'utilitaire more est conforme aux Définitions de base du volume POSIX.1-2017, Section 12.2, Directives de syntaxe des utilitaires, à l'exception près que '+' peut être reconnu comme délimiteur d'option ainsi que '-'.

Les options suivantes doivent être supportées :

-c
Si un écran doit être écrit sans lignes communes avec l'écran actuel, ou si more écrit son premier écran, more ne fera pas défiler l'écran, mais redessinera chaque ligne de l'écran tour à tour, du haut vers le bas. De plus, si more écrit son premier écran, l'écran sera effacé. Cette option peut être ignorée silencieusement sur les appareils aux capacités terminales insuffisantes.
-e
Quitte immédiatement après avoir écrit la dernière ligne du dernier fichier dans la liste des arguments ; voir la section DESCRIPTION ÉTENDUE.
-i
Effectue la recherche de motifs sans tenir compte de la casse ; voir le volume Définitions de base de POSIX.1-2017, Section 9.2, Exigences générales des expressions régulières.
-n nombre
Spécifie le nombre de lignes par écran. L'argument nombre est un entier décimal positif. L'option -n remplacera toute valeur obtenue d'une autre source.
-p commande
Chaque fois qu'un écran d'un nouveau fichier est affiché ou réaffiché (y compris suite à des commandes more ; par exemple, :p), exécute les commandes more spécifiées dans les arguments de commande dans l'ordre, comme si elles étaient entrées par l'utilisateur après l'affichage du premier écran. Aucun résultat intermédiaire ne sera affiché (c'est-à-dire, si la commande est un déplacement vers un écran différent du premier écran normal, seul l'écran résultant de la commande sera affiché). Si l'une des commandes échoue pour quelque raison que ce soit, un message informatif à cet effet sera écrit, et aucune commande supplémentaire spécifiée via l'option -p ne sera exécutée pour ce fichier.
-s
Se comporte comme si les lignes vides consécutives étaient une seule ligne vide.
-t chaîne_étiquette
Affiche l'écran du fichier contenant l'étiquette nommée par l'argument chaîne_étiquette. Voir l'utilitaire ctags. La fonctionnalité d'étiquettes représentée par -t chaîne_étiquette et la commande :t est facultative. Elle doit être fournie sur tout système qui fournit également une implémentation conforme de ctags ; sinon, l'utilisation de -t produit des résultats indéfinis.

Le nom de fichier résultant de l'option -t sera logiquement ajouté en préfixe à la liste des fichiers de la ligne de commande, comme s'il avait été spécifié par l'utilisateur. Si l'étiquette nommée par l'argument chaîne_étiquette n'est pas trouvée, ce sera une erreur, et more ne prendra aucune autre mesure.

Si l'étiquette spécifie un numéro de ligne, la première ligne affichée contiendra le début de cette ligne. Si l'étiquette spécifie un motif, la première ligne affichée contiendra le début du texte correspondant de la première ligne du fichier qui contient ce motif. Si la ligne n'existe pas dans le fichier ou si le texte correspondant n'est pas trouvé, un message informatif à cet effet sera affiché, et more affichera l'écran par défaut comme si -t n'avait pas été spécifié.

Si les deux options -t chaîne_étiquette et -p commande sont données, l'option -t chaîne_étiquette sera traitée en premier ; c'est-à-dire, le fichier et la ligne de départ de l'affichage seront tels que spécifiés par -t, puis la commande more -p sera exécutée. Si la ligne (texte correspondant) spécifiée par la commande -t n'existe pas (n'est pas trouvée), aucune commande more -p ne sera exécutée pour ce fichier, à aucun moment.

-u
Traite un <retour arrière> comme un caractère de contrôle imprimable, affiché sous forme d'une séquence de caractères définie par l'implémentation (voir la section DESCRIPTION ÉTENDUE), supprimant le retour arrière et le traitement spécial qui produit du texte souligné ou en mode sélection sur certains types de terminaux. De plus, n'ignore pas un <retour chariot> à la fin d'une ligne.

OPÉRANDES

L'opérande suivant doit être supporté :

fichier
Un chemin d'accès à un fichier d'entrée. Si aucun opérande fichier n'est spécifié, l'entrée standard sera utilisée. Si un fichier est '-', l'entrée standard sera lue à ce point de la séquence.

ENTRÉE STANDARD

L'entrée standard sera utilisée uniquement si aucun opérande fichier n'est spécifié, ou si un opérande fichier est '-'.

FICHIERS D'ENTRÉE

Les fichiers d'entrée examinés doivent être des fichiers texte. Si la sortie standard est un terminal, la sortie d'erreur standard sera utilisée pour lire les commandes de l'utilisateur. Si la sortie standard est un terminal, la sortie d'erreur standard n'est pas lisible, et des commandes d'entrée sont nécessaires, more peut tenter d'obtenir les commandes utilisateur depuis le terminal de contrôle (par exemple, /dev/tty) ; sinon, more se terminera avec une erreur indiquant qu'il n'a pas pu lire les commandes utilisateur. Si la sortie standard n'est pas un terminal, aucune erreur ne résultera si la sortie d'erreur standard ne peut pas être ouverte en lecture.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de more :

COLUMNS
Remplace la taille de ligne d'affichage horizontale sélectionnée par le système. Voir le volume Définitions de base de POSIX.1-2017, Chapitre 8, Variables d'environnement pour les valeurs valides et les résultats lorsqu'elle est non définie ou vide.
EDITOR
U
sed par la commande v pour sélectionner un éditeur. Voir la section DESCRIPTION ÉTENDUE.
LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou nulles. (Voir le volume Base Definitions de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si défini sur une chaîne de caractères non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_COLLATE

Détermine la locale pour le comportement des plages, des classes d'équivalence et des éléments de collation multi-caractères dans les expressions régulières.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition à multi-octets dans les arguments et les fichiers d'entrée) et le comportement des classes de caractères dans les expressions régulières.
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard et des messages informatifs écrits sur la sortie standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.
LINES
Remplace la taille verticale de l'écran sélectionnée par le système, utilisée comme nombre de lignes dans un écran complet. Voir le volume Base Definitions de POSIX.1‐2017, Chapitre 8, Variables d'environnement pour les valeurs valides et les résultats lorsqu'elle est non définie ou nulle. L'option -n a la priorité sur la variable LINES pour déterminer le nombre de lignes dans un écran complet.
MORE
Détermine une chaîne contenant les options décrites dans la section OPTIONS précédées de caractères <trait d'union> et séparées par des <espaces> comme sur la ligne de commande. Toutes les options de ligne de commande seront traitées après celles de la variable MORE, comme si la ligne de commande était :
more $MORE options opérandes

La variable MORE a la priorité sur les variables TERM et LINES pour déterminer le nombre de lignes dans un écran complet.

TERM
Détermine le nom du type de terminal. Si cette variable est non définie ou nulle, un type de terminal par défaut non spécifié est utilisé.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

SORTIE STANDARD

La sortie standard sera utilisée pour écrire le contenu des fichiers d'entrée.

SORTIE D'ERREUR STANDARD

La sortie d'erreur standard sera utilisée pour les messages de diagnostic et les commandes utilisateur (voir la section FICHIERS D'ENTRÉE), et, si la sortie standard est un périphérique terminal, pour écrire une chaîne d'invite. La chaîne d'invite apparaîtra sur la ligne de l'écran en dessous de la dernière ligne du fichier affiché dans l'écran actuel. L'invite contiendra le nom du fichier actuellement examiné et contiendra une indication de fin de fichier et le nom du fichier suivant, le cas échéant, lors de l'invite à la fin du fichier. Si un message d'erreur ou d'information est affiché, il n'est pas spécifié s'il est contenu dans l'invite. S'il n'est pas contenu dans l'invite, il sera affiché, puis l'utilisateur sera invité à entrer un caractère de continuation, auquel cas un autre message ou l'invite utilisateur peut être affiché. L'invite est sinon non spécifiée. Il n'est pas spécifié si des messages informatifs sont écrits pour d'autres commandes utilisateur.

FICHIERS DE SORTIE

Aucun.

DESCRIPTION ÉTENDUE

La section suivante décrit le comportement de more lorsque la sortie standard est un périphérique terminal. Si la sortie standard n'est pas un périphérique terminal, aucune option autre que -s n'aura d'effet, et tous les fichiers d'entrée seront copiés sur la sortie standard sans modification, après quoi more se terminera sans autre action.

Le nombre de lignes disponibles par écran sera déterminé par l'option -n, si elle est présente, ou en examinant les valeurs dans l'environnement (voir la section VARIABLES D'ENVIRONNEMENT). Si aucune méthode ne donne un nombre, un nombre non spécifié de lignes sera utilisé.

Le nombre maximum de lignes écrites sera inférieur d'une unité à ce nombre, car la ligne d'écran après la dernière ligne écrite sera utilisée pour écrire une invite utilisateur et une entrée utilisateur. Si le nombre de lignes de l'écran est inférieur à deux, les résultats sont indéfinis. Il n'est pas spécifié si l'entrée utilisateur peut être plus longue que le reste de la seule ligne où l'invite a été écrite.

Le nombre de colonnes disponibles par ligne sera déterminé en examinant les valeurs dans l'environnement (voir la section VARIABLES D'ENVIRONNEMENT), avec une valeur par défaut telle que décrite dans le volume Base Definitions de POSIX.1‐2017, Chapitre 8, Variables d'environnement.

Les lignes plus longues que l'affichage seront repliées ; la longueur à laquelle le repliement se produit n'est pas spécifiée, mais devrait être appropriée pour le périphérique de sortie. Le repliement peut se produire entre des glyphes de caractères uniques qui occupent plusieurs colonnes d'affichage.

Lorsque la sortie standard est un terminal et que -u n'est pas spécifié, more traitera les caractères <backspace> et <retour chariot> spécialement :

*
Un caractère, suivi d'abord d'une séquence de n caractères <backspace> (où n est le même que le nombre de positions de colonne occupées par le caractère), puis de n caractères <souligné> ('_'), entraînera l'écriture de ce caractère en texte souligné, si le type de terminal le supporte. La séquence de n caractères <souligné>, suivie d'abord de n<backspace> caractères, puis de tout caractère occupant n positions de colonne, entraînera également l'écriture de ce caractère en texte souligné, si le type de terminal le supporte.
*
Une séquence de n caractères <backspace> (où n est le même que le nombre de positions de colonne occupées par le caractère précédent) qui apparaît entre deux caractères imprimables identiques entraînera l'écriture du premier de ces deux caractères en texte gras (c'est-à-dire, plus lumineux visuellement, mode standout ou mode vidéo inverse), si le type de terminal le supporte, et le second sera ignoré. Les occurrences immédiatement suivantes de paires <backspace>/caractère pour le même caractère seront également ignorées. (Par exemple, la séquence "a\ba\ba\ba" est interprétée comme un seul 'a' en gras.)
*
L'utilitaire more ignorera logiquement tous les autres caractères <backspace> de la ligne ainsi que le caractère qui les précède, le cas échéant.
*
Un <retour chariot> à la fin d'une ligne sera ignoré, plutôt que d'être écrit comme un caractère non imprimable, comme décrit dans le paragraphe suivant.

Il est défini par l'implémentation comment les autres caractères non imprimables sont écrits. Les implémentations devraient utiliser le même format qu'elles utilisent pour la commande print de ex ; voir la section OPTIONS dans l'utilitaire ed. Il n'est pas spécifié si un caractère multi-colonnes sera séparé s'il traverse une limite de ligne d'affichage ; il ne sera pas ignoré. Le comportement n'est pas spécifié si le nombre de colonnes de l'affichage est inférieur au nombre de colonnes que chaque caractère de la ligne affichée occuperait.

Lors de l'affichage (ou du réaffichage) de chaque nouveau fichier, more écrira le premier écran du fichier. Une fois le premier écran écrit, more demandera une commande utilisateur. Si l'exécution de la commande utilisateur aboutit à un écran ayant des lignes en commun avec l'écran actuel, et que le périphérique dispose de capacités terminales suffisantes, more fera défiler l'écran ; sinon, il n'est pas spécifié si l'écran est défilé ou redessiné.

Pour tous les fichiers sauf le dernier (y compris l'entrée standard si aucun fichier n'a été spécifié, et pour le dernier fichier également, si l'option -e n'a pas été spécifiée), lorsque more a écrit la dernière ligne du fichier, more demandera une commande utilisateur. Cette invite contiendra le nom du fichier suivant ainsi qu'une indication que more a atteint la fin du fichier. Si la commande utilisateur est f, <control>‐F, <espace>, j, <nouvelle ligne>, d, <control>‐D, ou s, more affichera le fichier suivant. Sinon, si le dernier fichier est affiché, more se terminera. Sinon, more exécutera la commande utilisateur spécifiée.

Plusieurs des commandes décrites dans cette section affichent un écran précédent du flux d'entrée. Dans le cas où le texte provient d'un flux non rembobinable, tel qu'un tube, il est défini par l'implémentation quelle est la quantité de mouvement arrière supportée. Si une commande ne peut pas être exécutée en raison d'une limitation du mouvement arrière, un message d'erreur à cet effet sera affiché, l'écran actuel ne changera pas, et l'utilisateur sera invité à entrer une autre commande.

Si une commande ne peut pas être exécutée car il n'y a pas assez de lignes à afficher, more alertera le terminal. Si une commande ne peut pas être exécutée car il n'y a pas assez de lignes à afficher ou qu'une commande / échoue : si l'entrée est l'entrée standard, le dernier écran du fichier peut être affiché ; sinon, le fichier et l'écran actuels ne changeront pas, et l'utilisateur sera invité à entrer une autre commande.

Les commandes interactives des sections suivantes seront supportées. Certaines commandes peuvent être précédées d'un entier décimal, appelé compteur dans les descriptions suivantes. Si le compteur n'est pas spécifié avec la commande, sa valeur par défaut sera 1. Dans les descriptions suivantes, modèle est une expression régulière de base, telle que décrite dans le volume Base Definitions de POSIX.1‐2017, Section 9.3, Expressions régulières de base. Le terme « examiner » est un usage historique signifiant « ouvrir le fichier pour visualisation » ; par exemple, more foo ouvrirait

exprimé comme l'examen du fichier foo.

Dans les descriptions suivantes, sauf indication contraire, ligne est une ligne dans l'affichage more, pas une ligne du fichier examiné.

Dans les descriptions suivantes, la position actuelle fait référence à deux choses :

1.
La position de la ligne actuelle à l'écran
2.
Le numéro de ligne (dans le fichier) de la ligne actuelle à l'écran

Habituellement, la ligne à l'écran correspondant à la position actuelle est la troisième ligne de l'écran. Si ce n'est pas possible (il y a moins de trois lignes à afficher, ou c'est la première page du fichier, ou c'est la dernière page du fichier), alors la position actuelle est soit la première soit la dernière ligne de l'écran, comme décrit plus loin.

Aide

Synopsis :
h

Écrit un résumé de ces commandes et d'autres commandes définies par l'implémentation. Le comportement sera comme si l'utilitaire more était exécuté avec l'option -e sur un fichier contenant les informations récapitulatives. L'utilisateur sera invité comme décrit précédemment dans cette section lorsque la fin du fichier est atteinte. Si la commande utilisateur est l'une de celles spécifiées pour continuer vers le fichier suivant, more retournera au fichier et à l'état de l'écran depuis lesquels la commande h a été exécutée.

Faire défiler un écran vers l'avant

Synopsis :
[nombre]f
[nombre]<contrôle>-F

Fait défiler nombre lignes vers l'avant, avec une valeur défaut d'un écran. Si nombre est supérieur à la taille de l'écran, seul le dernier écran sera écrit.

Faire défiler un écran vers l'arrière

Synopsis :
[nombre]b
[nombre]<contrôle>-B

Fait défiler nombre lignes vers l'arrière, avec une valeur défaut d'un écran (voir l'option -n). Si nombre est supérieur à la taille de l'écran, seul le dernier écran sera écrit.

Faire défiler une ligne vers l'avant

Synopsis :
[nombre]<espace>
[nombre]j
[nombre]<nouvelle ligne>

Fait défiler nombre lignes vers l'avant. Le nombre défaut pour <espace> sera d'un écran ; pour j et <nouvelle ligne>, une ligne. Les nombre lignes entières seront écrites, même si nombre est supérieur à la taille de l'écran.

Faire défiler une ligne vers l'arrière

Synopsis :
[nombre]k

Fait défiler nombre lignes vers l'arrière. Les nombre lignes entières seront écrites, même si nombre est supérieur à la taille de l'écran.

Examiner un nouveau fichier

Synopsis:

Examine un nouveau fichier. Si l'argument nomdefichier n'est pas spécifié, le fichier courant (voir les commandes :n et :p ci-dessous) sera réexaminé. Le nomdefichier sera soumis au processus d'expansions de mots du shell (voir la Section 2.6, Expansions de mots); si plusieurs noms de chemin résultent, les effets ne sont pas spécifiés. Si nomdefichier est un <signe nombre> ('#'), le fichier précédemment examiné sera réexaminé. Si nomdefichier n'est pas accessible pour une raison quelconque (y compris s'il s'agit d'un fichier non positionnable), un message d'erreur à cet effet sera affiché et le fichier courant ainsi que l'écran ne changeront pas.

Lancer l'éditeur

Synopsis:

Lance un éditeur pour éditer le fichier courant en cours d'examen. Si l'entrée standard est examinée, les résultats ne sont pas spécifiés. Si le dernier composant de chemin dans EDITOR est vi ou ex, l'éditeur sera lancé avec un argument de ligne de commande -c numéro_de_ligne, où numéro_de_ligne est le numéro de ligne du fichier contenant la ligne affichée actuellement comme première ligne de l'écran. Il est défini par l'implémentation si les options de définition de ligne sont passées aux éditeurs autres que vi et ex.

Lorsque l'éditeur se termine, more reprendra avec le même fichier et le même écran qu'au moment où l'éditeur a été lancé.

Si more lit depuis l'entrée standard, ou si le fichier est plus court qu'un seul écran, le numéro de ligne, le numéro d'octet, le nombre total d'octets et le pourcentage ne doivent pas être écrits.

STATUT DE SORTIE

Les valeurs de sortie suivantes seront retournées :

 0
Achèvement réussi.
>0
Une erreur s'est produite.

CONSÉQUENCES DES ERREURS

Si une erreur est rencontrée lors de l'accès à un fichier lors de l'utilisation de la commande :n, more tentera d'examiner le fichier suivant dans la liste d'arguments, mais le statut de sortie final sera affecté. Si une erreur est rencontrée lors de l'accès à un fichier via la commande :p, more tentera d'examiner le fichier précédent dans la liste d'arguments, mais le statut de sortie final sera affecté. Si une erreur est rencontrée lors de l'accès à un fichier via la commande :e, more restera dans le fichier courant et le statut de sortie final ne sera pas affecté.

Les sections suivantes sont informatives.

USAGE DE L'APPLICATION

Lorsque la sortie standard n'est pas un terminal, seule l'option de modification de filtre -s est efficace. Ceci est basé sur la pratique historique. Par exemple, une implémentation typique de man canalise sa sortie via more -s pour condenser les espaces blancs excessifs pour les utilisateurs de terminaux. Lorsque man est canalisé vers lp, cependant, il est indésirable que ce condensé se produise.

EXEMPLES

L'option -p permet d'exécuter des commandes arbitraires au début de chaque fichier. Exemples :

more -p G fichier1 fichier2

Examine chaque fichier en commençant par son dernier écran.
more -p 100 fichier1 fichier2

Examine chaque fichier en commençant par la ligne 100 à la position courante (généralement la troisième ligne, donc la ligne 98 serait la première ligne écrite).
more -p /100 fichier1 fichier2

Examine chaque fichier en commençant par la première ligne contenant la chaîne "100" à la position courante

JUSTIFICATION

L'utilitaire more, disponible sur les systèmes BSD et dérivés de BSD, a été choisi comme prototype pour le programme d'affichage de fichiers POSIX car il est plus largement disponible que le programme du domaine public less ou que pg, un paginateur fourni dans System V. Le more de 4.4 BSD est le modèle pour les fonctionnalités sélectionnées ; il est presque entièrement compatible ascendante avec la version 4.3 BSD largement utilisée et est devenu plus accessible aux utilisateurs de vi. Plusieurs fonctionnalités initialement dérivées de divers éditeurs de fichiers, trouvées dans less et pg, ont été ajoutées à ce volume de POSIX.1‐2017 car elles se sont avérées extrêmement populaires auprès des utilisateurs.

Il existe des incohérences entre more et vi qui résultent de la pratique historique. Par exemple, les commandes à caractère unique h, f, b et <espace> sont des déplaceurs d'écran dans more, mais des déplaceurs de curseur dans vi. Ces incohérences ont été maintenues car les mouvements de curseur ne sont pas applicables à more et la fonctionnalité puissante obtenue sans l'utilisation de la touche de contrôle justifie les différences.

L'interface d'étiquettes a été incluse dans un programme qui n'est pas un éditeur de texte car elle favorise un autre degré de fonctionnement cohérent avec vi. Il est concevable que l'environnement de pagination de more soit supérieur pour parcourir les fichiers source dans certaines circonstances.

Le mode de fonctionnement référencé pour le terminal en mode bloc

s ajoute efficacement un <newline> à chaque ligne de Synopsis qui n'en a pas actuellement. Ainsi, par exemple, d<newline> afficherait une page entière. Le mode pourrait être déclenché par une option de ligne de commande, une variable d'environnement ou une autre méthode. Les détails ne sont pas imposés par ce volume de POSIX.1‐2017 car il existe si peu de systèmes connus pour prendre en charge de tels terminaux. Néanmoins, il a été considéré que tous les systèmes devraient pouvoir prendre en charge plus étant donné l'exception citée pour cette petite communauté de terminaux car, par rapport à vi, les mouvements du curseur sont peu nombreux et l'ensemble des commandes relativement amenable aux caractères <newline> optionnels.

Certaines versions de more fournissent un mécanisme d'échappement de shell similaire à la commande ! de ex. Les développeurs standard n'ont pas considéré que cela était nécessaire dans un paginateur, particulièrement compte tenu de la large acceptation des terminaux multi-fenêtres et des fonctionnalités de contrôle de jobs. (Ils ont choisi de conserver de telles fonctionnalités dans les éditeurs et mailx car l'interaction avec le shell donne également l'occasion de modifier le tampon d'édition, ce qui n'est pas applicable à more.)

L'option -p (position) remplace la commande + en raison des directives de syntaxe des utilitaires. L'option +commande n'est plus spécifiée par POSIX.1‐2008 mais peut être présente dans certaines implémentations. Dans les premières propositions, elle prenait un argument pattern, mais le less historique fournissait la facilité plus générale de more d'une commande. Il aurait été souhaitable d'utiliser le même -c que ex et vi, mais la lettre était déjà utilisée.

Le texte indiquant « from a non-rewindable stream ... implementations may limit the amount of backwards motion supported » permettrait une implémentation qui autorise aucun mouvement arrière au-delà du texte déjà affiché à l'écran. Il n'a pas été possible d'exiger un montant minimum de mouvement arrière qui serait efficace pour tous les types de périphériques concevables. L'implémentation devrait permettre à l'utilisateur de remonter aussi loin que possible, dans les contraintes de périphériques et d'allocation mémoire raisonnable.

Historiquement, les caractères non imprimables étaient affichés à l'aide des mappages standard ARPA, qui sont les suivants:

1.
Les caractères imprimables sont laissés tels quels.
2.
Les caractères de contrôle inférieurs à \177 sont représentés suivis du décalage du caractère par rapport au caractère '@' dans la carte ASCII ; par exemple, \007 est représenté par 'G'.
3.
\177 est représenté suivi de '?'.

L'affichage des caractères ayant leur huitième bit défini était moins standard. Les implémentations existantes utilisent l'hexadécimal (0x00), l'octal (\000) et un affichage par bit méta. (Ce dernier affichait les caractères dont le huitième bit était défini comme les deux caractères "M-", suivis de l'affichage sur sept bits tel que décrit précédemment.) Ce dernier a probablement la meilleure revendication de pratique historique car il était utilisé avec l'option -v des versions 4 BSD et dérivées de la version 4 BSD de l'utilitaire cat depuis 1980.

Aucun format d'affichage spécifique n'est requis par POSIX.1‐2008. Les implémentations sont encouragées à se conformer à la pratique historique en l'absence de toute raison impérieuse de diverger.
