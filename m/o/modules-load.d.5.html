NOM

modules-load.d - Configurer les modules du noyau à charger au démarrage

SYNTAXE

/etc/modules-load.d/*.conf
/run/modules-load.d/*.conf
/usr/local/lib/modules-load.d/*.conf
/usr/lib/modules-load.d/*.conf

DESCRIPTION

systemd-modules-load.service(8) lit les fichiers des répertoires ci-dessus qui contiennent les modules du noyau à charger lors du démarrage dans une liste statique. Chaque fichier de configuration est nommé selon le modèle /etc/modules-load.d/programme.conf. Il est généralement préférable de s'appuyer sur le chargement automatique des modules par identifiants PCI, identifiants USB, identifiants DMI ou déclencheurs similaires encodés dans les modules du noyau eux-mêmes plutôt que sur une configuration statique comme celle-ci. En effet, la plupart des modules du noyau modernes sont déjà préparés pour le chargement automatique.

FORMAT DE CONFIGURATION

Les fichiers de configuration doivent simplement contenir une liste de noms de modules du noyau à charger, séparés par des sauts de ligne. Les lignes vides et les lignes dont le premier caractère non-blanc est # ou ; sont ignorées.

RÉPERTOIRES DE CONFIGURATION ET PRÉCÉDENCE

Les fichiers de configuration sont lus à partir des répertoires /etc/, /run/, /usr/local/lib/, et /usr/lib/, dans l'ordre de priorité, tel que listé dans la section SYNTAXE ci-dessus. Les fichiers doivent avoir l'extension ".conf". Les fichiers dans /etc/ remplacent les fichiers portant le même nom dans /run/, /usr/local/lib/, et /usr/lib/. Les fichiers dans /run/ remplacent les fichiers portant le même nom sous /usr/.

Tous les fichiers de configuration sont triés par leur nom de fichier dans l'ordre lexicographique, quel que soit le répertoire dans lequel ils résident. Si plusieurs fichiers spécifient la même option, l'entrée du fichier avec le nom lexicographiquement le plus récent prendra le dessus. Ainsi, la configuration d'un fichier donné peut être soit complètement remplacée (en plaçant un fichier portant le même nom dans un répertoire de priorité plus élevée), soit des paramètres individuels peuvent être modifiés (en spécifiant des paramètres supplémentaires dans un fichier portant un nom différent et dont l'ordre est postérieur).

Les paquets doivent installer leurs fichiers de configuration dans /usr/lib/ (paquets de distribution) ou /usr/local/lib/ (installations locales) [1]. Les fichiers dans /etc/ sont réservés à l'administrateur local, qui peut utiliser cette logique pour remplacer les fichiers de configuration installés par les paquets du vendeur.

Il est recommandé de préfixer tous les noms de fichiers par un nombre à deux chiffres et un trait d'union pour simplifier l'ordre. Il est recommandé d'utiliser la plage 10-40 pour les fichiers de configuration dans /usr/ et la plage 60-90 pour les fichiers de configuration dans /etc/ et /run/, afin de s'assurer que la configuration locale et transitoire aura toujours la priorité sur les fichiers de configuration fournis par le vendeur du système d'exploitation.

Si l'administrateur souhaite désactiver un fichier de configuration fourni par le vendeur, la méthode recommandée est de placer un lien symbolique vers /dev/null dans le répertoire de configuration de /etc/, avec le même nom de fichier que le fichier de configuration du vendeur. Si le fichier de configuration du vendeur est inclus dans l'image initrd, l'image doit être régénérée.

EXEMPLE

Exemple 1. Exemple de fichier /etc/modules-load.d/virtio-net.conf :

# Charger virtio-net.ko au démarrage
virtio-net

VOIR AUSSI

systemd(1), systemd-modules-load.service(8), systemd-delta(1), modprobe(8)

NOTES

1.
💣💥🧨💥💥💣 Veuillez noter que ces fichiers de configuration doivent être disponibles à tout moment. Si /usr/local/ est une partition séparée, il se peut qu'elle ne soit pas disponible au début du démarrage, et ne doit pas être utilisée pour la configuration.
