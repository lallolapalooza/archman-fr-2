NOM

mosquitto_rr - un client MQTT version 5/3.1.1 pour la messagerie requête/réponse

SYNOPSIS

mosquitto_rr -e topic-de-réponse {[-h nom-hôte] [--unix chemin-socket] [-p numéro-port] [-u nom-utilisateur] [-P mot-de-passe] -t topic-message... | -L URL [-t topic-message...] } {-f fichier | -m message | -n | -s} [-A adresse-liaison] [-c] [-d] [-D commande identifiant valeur] [-i id-client] [-I prefixe-id-client] [-k temps-keepalive] [-N] [--nodelay] [--pretty] [-q QoS-message] [-R] [-S] [-v] [-V version-protocole] [-W timeout-traitement-message] [-x intervalle-expiration-session] [--proxy url-socks] [--quiet] [--will-topic topic [--will-payload payload] [--will-qos qos] [--will-retain]] [[{--cafile fichier | --capath répertoire} [--cert fichier] [--key fichier] [--ciphers chiffrements] [--tls-version version] [--tls-alpn protocole] [--tls-engine moteur] [--keyform {pem | moteur}] [--tls-engine-kpass-sha1 kpass-sha1] [--tls-use-os-certs] [--insecure]] | [--psk clé-hex --psk-identity identité [--ciphers chiffrements] [--tls-version version]]]

mosquitto_rr [--help]

DESCRIPTION

mosquitto_rr est un client MQTT version 5/3.1.1 qui peut être utilisé pour publier un message de requête et attendre une réponse. Lors de l'utilisation de MQTT v5, ce qui est le défaut, mosquitto_rr utilisera la fonctionnalité Requête-Réponse.

Les options importantes sont -t, -e, et l'une des options -f, -m, -n, et -s.

Exemple : mosquitto_rr -t topic-requete -e topic-reponse -m message

CONNEXIONS CHIFFRÉES

mosquitto_rr prend en charge les connexions chiffrées TLS. Il est fortement recommandé d'utiliser une connexion chiffrée pour tout ce qui dépasse une configuration très basique.

Pour activer les connexions TLS lors de l'utilisation de certificats x509, l'une des options --cafile ou --capath peut être fournie.

Alternativement, si l'option -p 8883 est utilisée, les certificats fournis par le système d'exploitation seront chargés et ni --cafile ni --capath ne seront nécessaires.

Pour activer les connexions TLS lors de l'utilisation de TLS-PSK, vous devez utiliser les options --psk et --psk-identity.

OPTIONS

Les options ci-dessous peuvent être données en ligne de commande, mais peuvent également être placées dans un fichier de configuration situé à $XDG_CONFIG_HOME/mosquitto_rr ou $HOME/.config/mosquitto_rr avec une paire -option valeur par ligne. Les valeurs dans le fichier de configuration seront utilisées par défaut et pourront être écrasées en utilisant la ligne de commande. Les exceptions sont -t, qui, s'il est donné dans le fichier de configuration, ne sera pas écrasé. Notez également que certaines options ne peuvent actuellement pas être niées, par exemple -S. Les lignes de fichier de configuration qui ont un caractère # comme premier caractère sont traitées comme des commentaires et ne sont pas traitées davantage.

-A

Lie la connexion sortante à une adresse IP/nom d'hôte local. Utilisez cet argument si vous avez besoin de restreindre la communication réseau à une interface particulière.

-c, --disable-clean-session

Désactive la session "clean" / active le mode client persistant. Lorsque cet argument est utilisé, le broker sera instruit de ne pas nettoyer les sessions existantes pour le même identifiant client lorsque le client se connecte, et les sessions n'expireront jamais lorsque le client se déconnecte. Les clients MQTT v5 peuvent modifier leur intervalle d'expiration de session avec l'argument -x.

Lorsqu'une session est persistante sur le broker, les abonnements du client seront maintenus après sa déconnexion, ainsi que les messages QoS 1 et QoS 2 ultérieurs qui arrivent. Lorsque le client se reconnecte et ne nettoie pas la session, il recevra tous les messages mis en file d'attente.

Si vous utilisez cette option, l'identifiant client doit être défini manuellement avec --id

--cafile

Définit le chemin vers un fichier contenant les certificats CA encodés en PEM qui sont approuvés. Utilisé pour activer la communication SSL.

Voir aussi --capath

--capath

Définit le chemin vers un répertoire contenant les certificats CA encodés en PEM qui sont approuvés. Utilisé pour activer la communication SSL.

Pour que --capath fonctionne correctement, les fichiers de certificat doivent avoir l'extension ".crt" et vous devez exécuter "openssl rehash <chemin vers capath>" chaque fois que vous ajoutez/supprimez un certificat.

Voir aussi --cafile

--cert

Définit le chemin vers un fichier contenant un certificat encodé en PEM pour ce client, si requis par le serveur.

Voir aussi --key et la section Connexions Chiffrées.

--ciphers

Une liste de chiffrements TLS compatibles openssl à prendre en charge dans le client. Voir ciphers(1) pour plus d'informations.

-d, --debug

Active les messages de débogage.

-D, --property

Utilise une propriété MQTT v5 avec cette publication. Si vous utilisez cette option, le client sera défini comme un client MQTT v5. Cette option a deux formes :

-D commande identifiant valeur

-D commande identifiant nom valeur

commande est l'identifiant de la commande/du paquet MQTT et peut être CONNECT, PUBACK, PUBREC, PUBCOMP, SUBSCRIBE, UNSUBSCRIBE, DISCONNECT, AUTH ou WILL. Les propriétés disponibles pour chaque commande sont listées dans la section Propriétés.

identifiant est le nom de la propriété à ajouter. Il est décrit dans la spécification, mais avec '-' comme séparateur de mots. Par exemple : payload-format-indicator. Plus de détails se trouvent dans la section Propriétés.

valeur est la valeur de la propriété à ajouter, avec un type de données spécifique à la propriété.

nom est utilisé uniquement pour la propriété user-property comme premier des deux chaînes de la paire de chaînes. Dans ce cas, valeur est le second des chaînes de la paire.

-e

Topic de réponse. Le client s'abonnera à ce topic pour attendre une réponse.

-f, --file

Envoie le contenu d'un fichier comme message de requête.

-F

Spécifie le format d'affichage de la sortie. Cette option vous permet de choisir quelles informations de chaque message sont affichées à l'écran. Voir la section Format de Sortie ci-dessous pour tous les détails.

Cette option écrase l'option -v, mais n'écrase pas l'option -N.

--help

Affiche les informations d'utilisation.

-h, --host

Spécifie l'hôte auquel se connecter. Par défaut : localhost.

-i, --id

L'identifiant à utiliser pour ce client. S'il n'est pas donné, un identifiant client sera généré en fonction de la version MQTT utilisée. Pour v3.1.1/v3.1, le client génère un identifiant client au format mosq-XXXXXXXXXXXXXXXXXX, où les X sont remplacés par des caractères alphanumériques aléatoires. Pour v5.0, le client envoie un identifiant client de longueur nulle, et le serveur générera un identifiant client pour le client.

Cette option ne peut pas être utilisée en même temps que l'argument --id-prefix.

-I, --id-prefix

Fournit un préfixe à partir duquel l'identifiant client sera construit en ajoutant l'identifiant de processus du client. Ceci est utile lorsque le broker utilise l'option clientid_prefixes. Ne peut pas être utilisé en même temps que l'argument --id.

--insecure

Lors de l'utilisation du chiffrement basé sur des certificats, cette option désactive la vérification du nom d'hôte du serveur dans le certificat du serveur. Ceci peut être utile lors des tests de configuration initiale du serveur, mais permet à un tiers malveillant d'usurper l'identité de votre serveur par le biais d'un spoofing DNS, par exemple. Utilisez cette option *uniquement* pour les tests. Si vous devez recourir à cette option dans un environnement de production, votre configuration est défaillante et il est inutile d'utiliser le chiffrement.

-k, --keepalive

Le nombre de secondes entre l'envoi des commandes PING au broker afin de lui indiquer que nous sommes toujours connectés et fonctionnels. La valeur par défaut est de 60 secondes.

--key

Définir le chemin d'accès à un fichier contenant une clé privée codée en PEM pour ce client, si requis par le serveur.

Voir aussi --cert et la section Connexions Chiffrées.

--keyform

Spécifie le type de clé privée utilisé lors des connexions TLS. Il peut s'agir de "pem" ou "engine". Ce paramètre est utile lorsqu'un module TPM est utilisé et que la clé privée a été créée avec celui-ci. La valeur par défaut est "pem", ce qui signifie que des fichiers de clé privée normaux sont utilisés.

Voir aussi --tls-engine.

-L, --url

Spécifier l'utilisateur, le mot de passe, le nom d'hôte, le port et le sujet en une seule fois sous forme d'URL. L'URL doit être sous la forme : mqtt(s)://[username[:password]@]host[:port]/topic

Si le schéma est mqtt://, le port est 1883 par défaut. Si le schéma est mqtts://, le port est 8883 par défaut.

-m, --message

Envoyer un seul message de requête depuis la ligne de commande.

-N

Ne pas ajouter de caractère de fin de ligne à la charge utile lors de l'affichage. Cela permet de diffuser des données de charge utile provenant de plusieurs messages directement vers une autre application sans modification. N'a vraiment de sens que si -v n'est pas utilisé.

-n, --null-message

Envoyer un message de requête nul (de longueur zéro).

--nodelay

Désactive l'algorithme de Nagle pour le socket. Cela signifie que la latence des messages envoyés est réduite, ce qui est particulièrement perceptible pour les messages petits et relativement peu fréquents. L'utilisation de cette option peut entraîner l'envoi d'un plus grand nombre de paquets que nécessaire normalement.

-p, --port

Se connecter au port spécifié. S'il n'est pas indiqué, le port par défaut de 1883 pour le MQTT simple ou 8883 pour le MQTT sur TLS sera utilisé.

-P, --pw

Fournir un mot de passe à utiliser pour l'authentification auprès du broker. L'utilisation de cet argument sans spécifier également un nom d'utilisateur est invalide lors de l'utilisation de MQTT v3.1 ou v3.1.1. Voir aussi l'option --username.

--pretty

Lors de l'utilisation du format de sortie JSON %j ou %J, la valeur par défaut est d'afficher de manière non formatée. Spécifier --pretty affiche les messages dans un format plus agréable et plus lisible par l'homme.

--proxy

Spécifier un proxy SOCKS5 pour se connecter. Les types d'authentification "None" et "username" sont pris en charge. L'URL socks-url doit être de la forme socks5h://[username[:password]@]host[:port]. Le préfixe de protocole socks5h signifie que les noms d'hôte sont résolus par le proxy. Les symboles %25, %3A et %40 sont décodés en URL en %, : et @ respectivement, s'ils sont présents dans le nom d'utilisateur ou le mot de passe.

Si le nom d'utilisateur n'est pas indiqué, aucune authentification n'est tentée. Si le port n'est pas indiqué, le port par défaut de 1080 est utilisé.

D'autres versions de SOCKS pourraient être disponibles à l'avenir, en fonction de la demande, et utiliseront différents préfixes de protocole, comme décrit dans curl(1).

--psk

Fournir la clé pré-partagée hexadécimale (sans le préfixe 0x) correspondant à celle utilisée sur le broker pour utiliser le support du chiffrement TLS-PSK. --psk-identity doit également être fourni pour activer TLS-PSK.

--psk-identity

L'identité du client à utiliser avec le support TLS-PSK. Elle peut être utilisée à la place d'un nom d'utilisateur si le broker est configuré pour cela.

-q, --qos

Spécifier la qualité de service souhaitée pour les messages entrants, de 0, 1 et 2. La valeur par défaut est 0. Voir mqtt(7) pour plus d'informations sur le QoS.

Le QoS est identique pour tous les sujets auxquels on s'abonne dans une seule instance de mosquitto_rr.

--quiet

Si cet argument est donné, aucune erreur d'exécution ne sera affichée. Ceci exclut les messages d'erreur donnés en cas d'entrée utilisateur invalide (par exemple, l'utilisation de --port sans port).

-R

Si cet argument est donné, les messages reçus qui ont le bit retain défini ne seront pas affichés. Les messages avec retain sont "obsolètes", car on ne sait pas quand ils ont été initialement publiés. Lors de l'abonnement à un sujet générique, il peut y avoir un grand nombre de messages conservés. Cet argument supprime leur affichage.

-S

Utiliser les recherches SRV pour déterminer l'hôte auquel se connecter. Effectue des recherches sur _mqtt._tcp.<hôte> lorsqu'il est utilisé conjointement avec -h, sinon utilise _mqtt._tcp.<domaine dns local>.

-s, --stdin-file

Envoyer un message de requête lu depuis stdin, en envoyant tout le contenu comme un seul message.

-t, --topic

Le sujet MQTT vers lequel le message de requête sera envoyé.

--tls-alpn

Fournir un protocole à utiliser lors de la connexion à un broker qui dispose de plusieurs protocoles disponibles sur un seul port, par exemple MQTT et WebSockets.

--tls-engine

Un identifiant de moteur openssl valide. Ceux-ci peuvent être listés avec la commande openssl engine.

Voir aussi --keyform.

--tls-engine-kpass-sha1

SHA1 du mot de passe de la clé privée lors de l'utilisation d'un moteur TLS. Certains moteurs TLS, comme le moteur TPM, peuvent nécessiter l'utilisation d'un mot de passe pour y accéder. Cette option permet de fournir directement un hachage SHA1 hexadécimal du mot de passe au moteur, au lieu que l'utilisateur soit invité à saisir le mot de passe.

Voir aussi --tls-engine.

--tls-use-os-certs

Si utilisé, cela chargera et approuvera les certificats CA fournis par le système d'exploitation. Cela peut être utilisé conjointement avec --cafile et --capath et peut être utilisé seul pour activer le mode TLS. Ce sera activé par défaut si -L mqtts://... est utilisé, ou si le port est 8883 et qu'aucune autre option de certificat n'est utilisée.

--tls-version

Choisir la version du protocole TLS à utiliser lors de la communication avec le broker. Les options valides sont tlsv1.3, tlsv1.2 et tlsv1.1. La valeur par défaut est tlsv1.2. Doit correspondre à la version du protocole utilisée par le broker.

-u, --username

Fournir un nom d'utilisateur à utiliser pour l'authentification auprès du broker. Voir aussi l'argument --pw.

--unix

Se connecter à un broker via un socket de domaine Unix local au lieu d'un socket TCP. Ceci remplace -h et -L. Par exemple : mosquitto_pub --unix /tmp/mosquitto.sock ...

Voir l'option socket_domain dans mosquitto.conf(5) pour configurer Mosquitto pour écouter sur un socket Unix.

-v, --verbose

Afficher les messages reçus de manière verbeuse. Avec cet argument, les messages seront affichés sous la forme "topic payload". Lorsque cet argument n'est pas donné, les messages sont affichés sous la forme "payload".

-V, --protocol-version

Spécifier quelle version du protocole MQTT doit être utilisée lors de la connexion au broker distant. Peut être 5, 311, 31, ou les versions plus verbeuses mqttv5, mqttv311, ou mqttv31. La valeur par défaut est 5.

-W

Fournir un délai d'attente sous forme d'un nombre entier de secondes. mosquitto_sub cessera de traiter les messages et se déconnectera après que ce nombre de secondes se soit écoulé. Le délai commence juste après que le client se soit connecté au broker.

--will-payload

Spécifier un message qui sera stocké par le broker et envoyé si ce client se déconnecte de manière inattendue. Ceci doit être utilisé conjointement avec --will-topic.

--will-qos

Le QoS à utiliser pour le Will. La valeur par défaut est 0. Ceci doit être utilisé conjointement avec --will-topic.

--will-retain

Si donné, si le client se déconnecte de manière inattendue, le message envoyé sera traité comme un message conservé. Ceci doit être utilisé conjointement avec --will-topic.

--will-topic

Le sujet sur lequel envoyer un Will, dans le cas où le client se déconnecte de manière inattendue.

-x

Définir la propriété session-expiry-interval sur le paquet CONNECT. S'applique uniquement aux clients MQTT v5. Définir à 0-4294967294 pour spécifier que la session expirera dans ce nombre de secondes après la déconnexion du client, ou utiliser -1, 4294967295, ou ∞ pour une session qui n'expire jamais. La valeur par défaut est -1 si -c est également donné, ou 0 si -c n'est pas donné.

Si la session est définie pour ne jamais expirer, soit avec -x soit avec -c, alors un identifiant de client doit être fourni.

FORMAT DE SORTIE

Il existe trois façons de formater la sortie de mosquitto_rr. Dans tous les cas, un caractère de nouvelle ligne est ajouté pour chaque message reçu, sauf si l'argument -N est passé à mosquitto_rr.

Le mode "Payload-only" est le format de sortie par défaut et affichera la charge utile exactement telle qu'elle est reçue.

Le mode verbeux est activé avec -v et affiche le sujet du message et la charge utile, séparés par un espace.

La dernière option est la sortie formatée, qui permet à l'utilisateur de définir un format de sortie personnalisé. Le comportement est contrôlé par l'option -F format-string. La chaîne de format est une chaîne de texte libre où les séquences interprétées sont remplacées par différents paramètres. Les séquences interprétées disponibles sont décrites ci-dessous.

Trois caractères sont utilisés pour commencer une séquence interprétée : %, @ et \. Les séquences commençant par % sont soit des paramètres relatifs au message MQTT en cours d'affichage, soit des séquences d'aide pour éviter d'avoir à taper de longues chaînes de format de date, par exemple. Les séquences commençant par @ sont passées à la fonction strftime(3) (avec le @ remplacé par un % - notez que seul le caractère immédiatement après le @ est passé à st

rftime). Ceci permet la construction d'une grande variété de sorties temporelles. Les options de sortie pour strftime varient d'une plateforme à l'autre, veuillez donc vérifier ce qui est disponible pour votre plateforme. mosquitto_rr fournit une extension à strftime qui est @N, qui peut être utilisée pour obtenir le nombre de nanosecondes écoulées dans la seconde courante. La résolution de cette option varie en fonction de la plateforme. Le dernier caractère de séquence est \, qui est utilisé pour saisir certains caractères qui seraient autrement difficiles à entrer.

Paramètres liés à MQTT

•%% un signe % littéral.
•%A la propriété alias de sujet MQTT v5, si présente.
•%C la propriété type de contenu MQTT v5, si présente.
•%D la propriété données de corrélation MQTT v5, si présente. Notez que cette propriété est spécifiée comme des données binaires, elle peut donc produire des caractères non imprimables.
•%E la propriété intervalle d'expiration du message MQTT v5, si présente.
•%F la propriété indicateur de format de charge utile MQTT v5, si présente.
•%l la longueur de la charge utile en octets.
•%m l'identifiant du message (uniquement pertinent pour les messages avec QoS>0).
•%P la propriété propriété utilisateur MQTT v5, si présente. Elle sera affichée sous la forme clé:valeur. Il est possible qu'un nombre quelconque de propriétés utilisateur soit attaché à un message, et qu'il y ait des clés dupliquées.
•%p les octets bruts de la charge utile (peut produire des caractères non imprimables en fonction de la charge utile).
•%q le QoS du message.
•%R la propriété sujet de réponse MQTT v5, si présente.
•%r le drapeau de rétention du message.
•%S la propriété identifiant de souscription MQTT v5, si présente.
•%t le sujet du message.
•%x la charge utile avec chaque octet comme un nombre hexadécimal (en minuscules).
•%X la charge utile avec chaque octet comme un nombre hexadécimal (en majuscules).

Aides

•%I date et heure au format ISO-8601, par ex. 2016-08-10T09:47:38+0100
•%j sortie JSON des paramètres du message et de l'horodatage, avec une charge utile citée et échappée. Par exemple {"tst":"2020-05-06T22:12:00.000000+0100","topic":"greeting","qos":0,"retain":0,"payload":"hello world"}
•%J sortie JSON des paramètres du message et de l'horodatage, avec une charge utile non citée et non échappée - cela signifie que la charge utile doit être elle-même un JSON valide. Par exemple : {"tst":"2020-05-06T22:12:00.000000+0100","topic":"foo","qos":0,"retain":0,"payload":{"temperature":27.0,"humidity":57}}.

Si la charge utile n'est pas un JSON valide, alors le message d'erreur "Erreur : la charge utile du message n'est pas un JSON valide sur le sujet <sujet>" sera affiché sur stderr.

•%I date et heure au format ISO-8601, par ex. 2016-08-10T09:47:38+0100
•%U horodatage Unix avec nanosecondes, par ex. 1470818943.786368637

Paramètres liés au temps

•@@ un signe @ littéral.
•@X passe le caractère représenté par X à la fonction strftime sous la forme %X. Les options prises en charge dépendent de la plateforme.
•@N le nombre de nanosecondes écoulées dans la seconde courante, avec une résolution temporelle variable selon la plateforme.

Caractères d'échappement

•\\ un caractère \ littéral.
•\0 un caractère nul. Peut être utilisé pour séparer différents paramètres qui peuvent contenir des espaces (par ex. sujet, charge utile) afin que le traitement avec des outils tels que xargs(1) soit plus facile.
•\a alerte/sonnerie.
•\e la séquence d'échappement, qui peut être utilisée avec des codes couleur ANSI pour fournir une sortie colorée, par exemple.
•\n fin de ligne.
•\r retour chariot.
•\t tabulation horizontale.
•\v tabulation verticale.

WILLS

mosquitto_rr peut enregistrer un message auprès du broker qui sera envoyé s'il se déconnecte de manière inattendue. Voir mqtt(7) pour plus d'informations.

L'exigence minimale pour cela est d'utiliser --will-topic pour spécifier le sujet sur lequel le will doit être envoyé. Cela se traduira par un message non conservé, de longueur nulle et avec QoS 0.

Utilisez les arguments --will-retain, --will-payload et --will-qos pour modifier les autres paramètres du will.
