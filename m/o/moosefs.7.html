NOM

MooseFS - système de fichiers distribué tolérant aux pannes, hautement fiable, quasi infiniment évolutif et rapide en espace utilisateur

DESCRIPTION

MooseFS est un système de fichiers distribué tolérant aux pannes. Il répartit les données sur plusieurs emplacements physiques (serveurs), qui sont visibles pour l'utilisateur comme une seule ressource. Pour les opérations de fichiers standard, MooseFS se comporte comme tout autre système de fichiers de type Unix :

-
structure hiérarchique (arborescence de répertoires)
-
stocke les attributs de fichiers POSIX (permissions, derniers temps d'accès et de modification)
-
prend en charge les fichiers spéciaux (périphériques par blocs et caractères, tubes et sockets)
-
prend en charge les liens symboliques (noms de fichiers pointant vers des fichiers cibles, pas nécessairement sur MooseFS) et les liens physiques (noms de fichiers différents qui font référence aux mêmes données sur MooseFS)
-
prend en charge les ACL
-
prend en charge les verrous de fichiers entre tous les processus clients connectés
-
l'accès au système de fichiers peut être limité en fonction de l'adresse IP et/ou du mot de passe

Les caractéristiques distinctives de MooseFS sont :

-
haute fiabilité (plusieurs copies des données peuvent être stockées sur des machines physiques distinctes)
-
la capacité est extensible dynamiquement en ajoutant de nouveaux ordinateurs/disques
-
les fichiers supprimés sont conservés pendant une période configurable (une « corbeille » au niveau du système de fichiers)
-
instantanés cohérents des fichiers, même pendant que le fichier est en cours d'écriture/d'accès

MooseFS se compose de 4 composants clés :

Serveurs Maîtres
dans MooseFS CE une machine, dans MooseFS Pro n'importe quel nombre de machines exécutant le binaire mfsmaster, qui gère l'ensemble du système de fichiers, stockant les métadonnées de chaque fichier (informations sur la taille, les attributs et les emplacements du fichier, y compris toutes les informations sur les fichiers non réguliers, c'est-à-dire les répertoires, les sockets, les tubes et les périphériques)
Serveurs de Chunks
n'importe quel nombre de serveurs standards exécutant le binaire mfschunkserver, qui stocke les données des fichiers et les synchronise entre eux (si un fichier donné est censé exister en plusieurs exemplaires).
Serveurs de Métalogger
n'importe quel nombre de serveurs exécutant le binaire mfsmetalogger, qui stockent tous les journaux de modification des métadonnées et téléchargent périodiquement le fichier principal des métadonnées
Processus Clients
machines exécutant les processus mfsmount, qui accèdent aux fichiers stockés sur le système de fichiers MooseFS et les exposent via un point de montage régulier dans l'arborescence de répertoires locale d'une machine cliente

De plus, un certain nombre d'outils peuvent être installés pour aider à l'utilisation du système :

Interface Graphique
un outil de statistiques et de diagnostic basé sur le web (mfsgui, qui agit comme un simple serveur HTTP)
Interface en Ligne de Commande
outil de statistiques et de diagnostic en ligne de commande mfscli
Périphérique par blocs
processus client spécial uniquement pour Linux mfsbdev qui mappe des fichiers MooseFS uniques en périphériques par blocs
OUTILS
divers outils administratifs en ligne de commande

ARCHITECTURE

Du point de vue de l'utilisateur, MooseFS se comporte comme un système de fichiers ordinaire, conforme à POSIX, avec une capacité presque infiniment extensible. Pour y parvenir, le système a été conçu comme un système de fichiers réseau distribué, où différents processus s'exécutent sur différentes machines, effectuent des tâches spécifiques pour assurer les bonnes performances de l'ensemble du système de fichiers. Le serveur Maître stocke les informations de métadonnées sur les fichiers et gère l'ensemble du système de fichiers. Dans le cas d'une installation MooseFS Pro, avec plusieurs serveurs Maîtres, un seul d'entre eux (dans le rôle de Leader) gère le système à tout moment, les autres (Followers) le suivent, prêts à prendre le rôle de Leader à tout moment. Le serveur Maître en cours de gestion a les tâches suivantes : il stocke toutes les métadonnées du système de fichiers (informations sur les fichiers et répertoires), il répond aux requêtes des processus clients (montage) lorsqu'ils veulent effectuer une opération sur le système de fichiers, il surveille l'état des serveurs de Chunks et des données stockées, envoyant des requêtes de réplication ou de suppression aux serveurs de Chunks si nécessaire.

Les métadonnées sont stockées dans la mémoire du serveur Maître et simultanément sauvegardées sur un disque local (sous forme de fichier binaire mis à jour périodiquement et de journaux incrémentiels mis à jour immédiatement). Le fichier binaire principal ainsi que les journaux sont synchronisés avec les Métaloggers (s'ils sont présents) et avec les serveurs Maîtres de secours dans la version MooseFS Pro. Les serveurs de Chunks stockent les données réelles des fichiers. Toutes les données du système de fichiers sont divisées en chunks (d'où le nom des serveurs qui les conservent) d'une taille maximale de 64 Mio. Les chunks sont conservés en plusieurs copies sur différents serveurs selon des politiques appropriées pour assurer la sécurité des données. Les serveurs de Chunks communiquent avec les processus clients (à la demande du client, comme dirigé par le maître) pour écrire ou lire les données des fichiers. Les chunks eux-mêmes sont stockés sous forme de fichiers réguliers sur le ou les disques durs locaux.

Toutes les opérations sur les fichiers sur un ordinateur client qui a monté une instance MooseFS sont exactement les mêmes que celles effectuées avec n'importe quel autre système de fichiers. Le noyau du système d'exploitation transfère toutes les opérations de fichiers au module FUSE, qui communique avec le processus mfsmount. Le processus mfsmount communique ensuite via le réseau avec le serveur de gestion et les serveurs de données. L'ensemble de ce processus est entièrement transparent pour l'utilisateur.

À tout moment, de nouveaux serveurs de Chunks peuvent être ajoutés au système pour étendre l'espace total disponible. De plus, de nouveaux disques durs peuvent être ajoutés aux serveurs de Chunks existants. Le serveur Maître ajoutera automatiquement l'espace « nouveau » au système de fichiers. Ainsi, la capacité de données du système peut être étendue presque indéfiniment, tant que le serveur Maître est capable de stocker toutes les informations de métadonnées pertinentes. Le serveur Maître veillera à ce que tout l'espace disque physique disponible soit utilisé de la manière la plus équilibrée possible.

Dans un système aussi vaste, des défaillances matérielles se produiront. MooseFS réagira automatiquement en cas de défaillance d'un disque dur ou d'un serveur de Chunks entier. La sécurité des données est assurée en la stockant en plusieurs copies, conformément aux politiques de stockage définies. Après une défaillance, le serveur Maître commencera la réplication des copies existantes conformément à la politique de stockage du fichier concerné, afin de rétablir son niveau de redondance de sécurité requis dès que possible.

Les défaillances d'une machine cliente (qui exécute le processus mfsmount) n'auront aucune influence sur la cohérence du système de fichiers ou sur les opérations des autres clients. Dans le pire des cas, les données qui n'ont pas encore été envoyées de l'ordinateur client défaillant au serveur Maître et/ou aux serveurs de Chunks pourraient être perdues.

PLATEFORMES PRISES EN CHARGE

mfsmount est basé sur le mécanisme FUSE (Filesystem in USErspace), donc le client MooseFS est disponible sur tous les systèmes d'exploitation dotés d'une implémentation FUSE fonctionnelle.

Les serveurs Maître, Métalogger et Chunks peuvent être exécutés sur n'importe quel système d'exploitation conforme à POSIX sur la plupart des principaux types et architectures de processeurs. Les processeurs 32 bits fonctionneront également, mais attention aux limitations de RAM et à leurs conséquences. L'utilisation de versions 64 bits des systèmes d'exploitation est fortement recommandée.

NAME

moosefs — MooseFS distributed file system

DESCRIPTION

This manual page describes the MooseFS distributed file system.

MooseFS is a fault-tolerant, highly available, scalable network distributed file system.

It offers:

  • High availability and fault tolerance: no single point of failure.
  • Scalability: can grow up to exabytes.
  • Data replication: data can be stored on multiple servers.
  • Thin provisioning: metadata is stored separately from the data.
  • Data access from multiple clients simultaneously.
  • Snapshots: point-in-time copies of the file system.
  • Extended attributes (xattrs).
  • Resource management: define storage classes, set quotas.
  • Disaster recovery: geographically distributed data storage.
