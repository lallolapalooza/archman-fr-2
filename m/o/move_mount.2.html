move_mount(2) Manuel des appels système move_mount(2)

NOM

move_mount - déplacer ou attacher un objet de montage au système de fichiers

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <fcntl.h>          /* Définition des constantes AT_* */
#include <sys/mount.h>
int move_mount(int from_dirfd, const char *from_path,
               int to_dirfd, const char *to_path,
               unsigned int flags);

DESCRIPTION

L'appel système move_mount() fait partie de la suite des installations de montage basées sur des descripteurs de fichiers sous Linux.

move_mount() déplace l'objet de montage indiqué par from_dirfd et from_path vers le chemin indiqué par to_dirfd et to_path. L'objet de montage déplacé peut être un point de montage existant dans l'espace de noms de montage actuel, ou un objet de montage détaché créé par fsmount(2) ou open_tree(2) avec OPEN_TREE_CLONE.

Pour accéder à l'objet de montage source ou au point de montage de destination, aucune permission n'est requise sur l'objet lui-même, mais si l'un des chemins est fourni, une permission d'exécution (recherche) est requise sur tous les répertoires spécifiés dans from_path ou to_path.

Le processus appelant doit posséder la capacité CAP_SYS_ADMIN pour déplacer ou attacher un objet de montage.

Comme avec les appels système "*at()", move_mount() utilise les arguments from_dirfd et to_dirfd en conjonction avec les arguments from_path et to_path pour déterminer les objets source et destination sur lesquels opérer (respectivement), comme suit :

•
Si le chemin donné dans *_path est absolu, alors le *_dirfd correspondant est ignoré.
•
Si le chemin donné dans *_path est relatif et que le *_dirfd correspondant est la valeur spéciale AT_FDCWD, alors *_path est interprété par rapport au répertoire de travail actuel du processus appelant (comme open(2)).
•
Si le chemin donné dans *_path est relatif, alors il est interprété par rapport au répertoire référencé par le descripteur de fichier *_dirfd correspondant (plutôt que par rapport au répertoire de travail actuel du processus appelant, comme c'est le cas avec open(2) pour un chemin relatif). Dans ce cas, le *_dirfd correspondant doit être un répertoire ouvert en lecture (O_RDONLY) ou utilisant le drapeau O_PATH.
•
Si *_path est une chaîne vide, et que flags contient le drapeau MOVE_MOUNT_*_EMPTY_PATH approprié, alors le descripteur de fichier *_dirfd correspondant est opéré directement. Dans ce cas, le *_dirfd correspondant peut faire référence à tout type de fichier, pas seulement un répertoire.

Voir openat(2) pour une explication sur l'utilité des arguments *_dirfd.

flags peut être utilisé pour contrôler les aspects de la recherche de chemin pour les objets source et destination, ainsi que d'autres propriétés de l'opération de montage. Une valeur pour flags est construite en combinant par OU binaire zéro ou plusieurs des constantes suivantes :

MOVE_MOUNT_F_EMPTY_PATH
Si from_path est une chaîne vide, opérer sur le fichier référencé par from_dirfd (qui peut avoir été obtenu depuis open(2), fsmount(2), ou open_tree(2)). Dans ce cas, from_dirfd peut faire référence à tout type de fichier, pas seulement un répertoire. Si from_dirfd est AT_FDCWD, move_mount() opérera sur le répertoire de travail actuel du processus appelant.
C'est le mécanisme le plus courant utilisé pour attacher les objets de montage détachés produits par fsmount(2) et open_tree(2) à un point de montage.
MOVE_MOUNT_T_EMPTY_PATH
Comme avec MOVE_MOUNT_F_EMPTY_PATH, sauf opération sur to_dirfd et to_path.
MOVE_MOUNT_F_SYMLINKS
Si from_path fait référence à un lien symbolique, alors le déréférencer. Le comportement par défaut pour move_mount() est de ne pas suivre les liens symboliques.
MOVE_MOUNT_T_SYMLINKS
Comme avec MOVE_MOUNT_F_SYMLINKS, sauf opération sur to_dirfd et to_path.
MOVE_MOUNT_F_NO_AUTOMOUNT
Ne pas automounter le composant terminal ("basename") de from_path s'il s'agit d'un répertoire qui est un point d'automontage. Cela permet de déplacer un objet de montage qui a un point d'automontage à sa racine et évite le déclenchement involontaire d'un point d'automontage. Ce drapeau n'a aucun effet si le point d'automontage a déjà été monté par-dessus.
MOVE_MOUNT_T_NO_AUTOMOUNT
Comme avec MOVE_MOUNT_F_NO_AUTOMOUNT, sauf opération sur to_dirfd et to_path. Cela permet de monter manuellement par-dessus un point d'automontage.
MOVE_MOUNT_SET_GROUP (depuis Linux 5.15)
Ajouter l'objet de montage attaché à propagation privée indiqué par to_dirfd et to_path dans le groupe "pair" de propagation de montage de l'objet de montage attaché non-privé indiqué par from_dirfd et from_path.
Contrairement aux autres opérations move_mount(), cette opération ne déplace ni n'attache d'objets de montage. Elle met seulement à jour les métadonnées des objets de montage attachés. (Notez également l'ordre des arguments : l'objet de montage modifié par cette opération est celui spécifié par to_dirfd et to_path.)
Cela permet de créer d'abord une arborescence de montage ne contenant que des montages privés, puis de configurer la disposition de propagation souhaitée ensuite. (Voir la section "ARBORESCENCES PARTAGÉES" de mount_namespaces(7) pour plus d'informations sur la propagation de montage et les groupes pairs.)
MOVE_MOUNT_BENEATH (depuis Linux 6.5)
Si le chemin indiqué par to_dirfd et to_path est un objet de montage existant, au lieu d'attacher ou de déplacer l'objet de montage indiqué par from_dirfd et from_path par-dessus la pile de montages, l'attacher ou le déplacer sous le montage supérieur actuel de la pile.
Après utilisation de MOVE_MOUNT_BENEATH, il est possible de faire un umount(2) du montage supérieur afin de révéler l'objet de montage qui a été attaché en dessous précédemment. Cela permet le remplacement transparent (et atomique) d'arborescences de montage complexes, qui peuvent ensuite être utilisées pour "mettre à niveau" une arborescence de montage avec une version plus récente.
Cette opération a plusieurs restrictions :
•
Les objets de montage ne peuvent pas être attachés sous la racine du système de fichiers, y compris les cas où la racine du système de fichiers a été configurée par chroot(2) ou pivot_root(2). Pour monter sous la racine du système de fichiers, pivot_root(2) doit être utilisé.
•
Le chemin cible indiqué par to_dirfd et to_path ne doit pas être un objet de montage détaché, tel que ceux produits par open_tree(2) avec OPEN_TREE_CLONE ou fsmount(2).
•
Le montage actuel en haut de la pile de montages du chemin cible et son montage parent doivent se trouver dans l'espace de noms de montage du processus appelant.
•
L'appelant doit disposer des privilèges suffisants pour démonter le montage supérieur de la pile de montages du chemin cible, afin de prouver qu'il a les privilèges nécessaires pour révéler le montage sous-jacent.

VALEUR RETOUR

En cas de succès, move_mount() renvoie 0. En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

Les erreurs courantes pour move_mount() incluent :

EACCES
Permission refusée. Une des conditions suivantes est vraie :
•
Aucun des chemins from_path ou to_path n'est absolu, et l'un des descripteurs de fichier from_dirfd ou to_dirfd n'est pas un répertoire.
•
L'un des chemins from_path ou to_path est un chemin relatif, et l'un des répertoires dans from_path ou to_path (respectivement) ne possède pas la permission d'exécution.
•
Le chemin cible to_path (ou from_path si flags contient MOVE_MOUNT_F_EMPTY_PATH) est un fichier non-répertoire auquel on essaie d'attacher un montage, et le processus appelant n'a pas la permission d'écrire sur ce fichier.
EBUSY
L'un des chemins est déjà monté, ou le point de montage de destination est déjà occupé.
EINVAL
Le drapeau flags contient une valeur invalide, ou l'un des arguments n'est pas valide (par exemple, des descripteurs de fichiers invalides). Si from_path est NULL et MOVE_MOUNT_F_EMPTY_PATH n'est pas spécifié, cela produit aussi EINVAL.
EMLINK
La destination pointe vers un lien symbolique, mais MOVE_MOUNT_T_SYMLINKS n'a pas été spécifié.
ENOENT
Le chemin source ou de destination n'existe pas.
ENOTDIR
L'un des composants d'un chemin donné est un fichier qui n'est pas un répertoire (et qui n'est pas le composant final d'un chemin qui n'est pas un répertoire).
ENOTEMPTY
Le répertoire de destination n'est pas vide, et aucune opération pour l'écraser n'a été spécifiée.
ENOMEM
Pas assez de mémoire pour effectuer l'opération.
EPERM
Le processus appelant n'a pas la capacité CAP_SYS_ADMIN.
EROFS
Un composant du chemin cible est sur un système de fichiers en lecture seule.
ESRCH
Le processus spécifié par from_dirfd ou to_dirfd n'existe pas.
EXDEV
Le chemin source et le chemin de destination se trouvent sur des systèmes de fichiers différents.

Pour une liste complète des erreurs possibles, voir mount(2).

CONFORMITÉ

Cet appel système est spécifique à Linux. Il a été introduit dans le noyau Linux 5.10.

VOIR AUSSI

mount(2), mount_namespaces(7), open(2), openat(2), pivot_root(2), fsmount(2), open_tree(2)

NOM

move_mount - déplacer un objet de montage

BIBLIOTHÈQUE

Bibliothèque C standard (libc, sans autre dépendance).

SYNTAXE

Dans glibc depuis la version 2.36 :

#define _GNU_SOURCE
#include <sys/syscall.h>
#include <fcntl.h>

long move_mount(int from_dirfd, const char *from_path,
                int to_dirfd, const char *to_path,
                unsigned int flags);

DESCRIPTION

L'appel système move_mount() déplace un objet de montage d'un emplacement source vers un emplacement cible. L'opération est similaire à l'utilisation de mount(2) avec le drapeau MS_MOVE, mais move_mount() offre une flexibilité et un contrôle accrus, en particulier pour la gestion des espaces de montage et des objets de montage détachés.

Les arguments from_dirfd et from_path spécifient le point de montage source. Les arguments to_dirfd et to_path spécifient le point de montage cible.

Pour l'un ou l'autre chemin, s'il est absolu, le descripteur de fichier associé dirfd doit être AT_FDCWD.

Si l'un des chemins est relatif, dirfd est un descripteur de fichier qui spécifie le répertoire à partir duquel le chemin relatif est résolu. Si dirfd est AT_FDCWD, le chemin est résolu par rapport au répertoire de travail courant.

Les chemins peuvent également désigner des objets de montage créés par open_tree(2) ou fsopen(2). Dans ce cas, le chemin peut être une chaîne vide (""), auquel cas il se réfère à l'objet pointé par le descripteur de fichier dirfd.

Les flags sont un masque de bits qui peuvent contenir des valeurs parmi les suivantes :

MOVE_MOUNT_F_EMPTY_PATH
Le chemin cible (to_path) doit être vide. Si le chemin existe, l'appel échoue avec ENOTEMPTY. Sinon, il est créé comme point de montage, et le montage est déplacé vers ce nouveau point.
MOVE_MOUNT_BENEATH
Déplacez le montage source sous le montage cible. Le montage source devient un enfant du montage cible. Le montage cible doit être un répertoire existant où le montage source sera déplacé. Le chemin cible sera alors un des sous-montages du montage cible. Cette opération ne peut pas être combinée avec MOVE_MOUNT_F_EMPTY_PATH.

Les restrictions suivantes s'appliquent lorsque move_mount() est utilisé avec des objets de montage pour déplacer des montages existants vers de nouvelles destinations :

•
Les événements de propagation de montage déclenchés par cette opération move_mount() (tels que décrits dans mount_namespaces(7)) sont calculés en fonction du montage parent du montage supérieur actuel de la pile de montages du chemin cible.
•
Le montage du chemin cible ne peut pas être un ancêtre dans l'arbre de montage de l'objet de montage source.
•
L'objet de montage source ne doit avoir aucun sur-montage, sinon il serait possible de créer des "montages fantômes" (c'est-à-dire deux montages montés sur le même montage parent au même point de montage).
•
Il n'est pas possible de déplacer un montage sous un montage supérieur si le montage parent du montage supérieur actuel se propage vers le montage supérieur lui-même. Sinon, MOVE_MOUNT_BENEATH provoquerait la propagation de l'objet de montage vers le montage supérieur à partir du montage parent, annulant l'objectif d'utiliser MOVE_MOUNT_BENEATH.
•
Il n'est pas possible de déplacer un montage sous un montage supérieur si le montage parent du montage supérieur actuel se propage vers l'objet de montage étant monté en dessous. Sinon, cela provoquerait un problème de propagation similaire au point précédent, annulant également l'objectif d'utiliser MOVE_MOUNT_BENEATH.

Si from_dirfd est un descripteur de fichier d'objet de montage et que move_mount() opère directement dessus, from_dirfd restera associé à l'objet de montage après que move_mount() ait réussi, vous pouvez donc utiliser from_dirfd de manière répétée avec move_mount(2) et/ou les appels système " du type *at() " autant de fois que nécessaire.

VALEUR RETOURNÉE

En cas de succès, move_mount() retourne 0. En cas d'erreur, -1 est retourné, et errno est défini pour indiquer l'erreur.

ERREURS

EACCES
Le droit de recherche est refusé pour l'un des répertoires du préfixe du chemin de from_path ou to_path. (Voir aussi path_resolution(7).)
EBADF
L'un des descripteurs de fichiers from_dirfd ou to_dirfd n'est pas valide.
EFAULT
L'un des chemins from_path ou to_path est NULL ou pointe vers un emplacement en dehors de l'espace d'adressage accessible du processus appelant.
EINVAL
Drapeau invalide spécifié dans flags.
EINVAL
Le chemin indiqué par from_dirfd et from_path n'est pas un objet de montage.
EINVAL
Les types d'objets de montage de l'objet de montage source et de l'inode cible ne sont pas compatibles (c'est-à-dire que la source est un fichier mais la cible est un répertoire, ou vice versa).
EINVAL
L'objet de montage source ou le chemin cible ne se trouvent pas dans l'espace de montage du processus appelant (ou dans un espace de montage anonyme du processus appelant).
EINVAL
Le montage parent de l'objet de montage source a une propagation de montage partagée, et ne peut donc pas être déplacé (comme décrit dans mount_namespaces(7)).
EINVAL
Le montage source a des sous-montages MS_UNBINDABLE mais le chemin cible réside sur un arbre de montage avec une propagation de montage partagée, ce qui provoquerait autrement la propagation des montages non dissociables (comme décrit dans mount_namespaces(7)).
EINVAL
MOVE_MOUNT_BENEATH a été tenté, mais l'une des restrictions listées a été violée.
ELOOP
Trop de liens symboliques rencontrés lors de la résolution de from_path ou to_path.
ENAMETOOLONG
L'un des chemins from_path ou to_path est plus long que PATH_MAX.
ENOENT
Un composant de from_path ou to_path n'existe pas.
ENOENT
L'un des chemins from_path ou to_path est une chaîne vide, mais le drapeau MOVE_MOUNT_*_EMPTY_PATH correspondant n'est pas spécifié dans flags.
ENOTDIR
Un composant du préfixe du chemin de from_path ou to_path n'est pas un répertoire, ou l'un des chemins from_path ou to_path est relatif et le from_dirfd ou to_dirfd correspondant est un descripteur de fichier se référant à un fichier autre qu'un répertoire.
ENOMEM
Le noyau n'a pas pu allouer suffisamment de mémoire pour compléter l'opération.
EPERM
Le processus appelant ne possède pas la capacité requise CAP_SYS_ADMIN.

NORMES

Linux.

HISTORIQUE

Linux 5.2. glibc 2.36.

EXEMPLES

move_mount() peut être utilisé pour déplacer des montages attachés comme suit :


move_mount(AT_FDCWD, "/a", AT_FDCWD, "/b", 0);

Ceci déplacerait l'objet de montage monté sur /a vers /b. La procédure ci-dessus est fonctionnellement équivalente à l'opération de montage suivante utilisant mount(2) :


mount("/a", "/b", NULL, MS_MOVE, NULL);

move_mount() peut également être utilisé en conjonction avec des descripteurs de fichiers retournés par open_tree(2) ou open(2) :


int fd = open_tree(AT_FDCWD, "/mnt", 0); /* open("/mnt", O_PATH); */
move_mount(fd, "", AT_FDCWD, "/mnt2", MOVE_MOUNT_F_EMPTY_PATH);
move_mount(fd, "", AT_FDCWD, "/mnt3", MOVE_MOUNT_F_EMPTY_PATH);
move_mount(fd, "", AT_FDCWD, "/mnt4", MOVE_MOUNT_F_EMPTY_PATH);

Ceci déplacerait l'objet de montage monté sur /mnt vers /mnt2, puis /mnt3, puis /mnt4.

Si l'objet de montage source indiqué par from_dirfd et from_path est un objet de montage détaché, move_mount() peut être utilisé pour le rattacher à un point de montage :


int fsfd, mntfd;
fsfd = fsopen("ext4", FSOPEN_CLOEXEC);
fsconfig(fsfd, FSCONFIG_SET_STRING, "source", "/dev/sda1", 0);
fsconfig(fsfd, FSCONFIG_SET_FLAG, "user_xattr", NULL, 0);
fsconfig(fsfd, FSCONFIG_CMD_CREATE, NULL, NULL, 0);
mntfd = fsmount(fsfd, FSMOUNT_CLOEXEC, MOUNT_ATTR_NODEV);
move_mount(mntfd, "", AT_FDCWD, "/home", MOVE_MOUNT_F_EMPTY_PATH);

Ceci créerait un nouveau contexte de configuration de système de fichiers pour ext4, le configurerait, créerait un objet de montage détaché, puis le rattacherait à /home. La procédure ci-dessus est fonctionnellement équivalente à l'opération de montage suivante utilisant mount(2) :


mount("/dev/sda1", "/home", "ext4", MS_NODEV, "user_xattr");

La même opération fonctionne également avec des montages de liaison détachés créés avec open_tree(2) et OPEN_TREE_CLONE :


int mntfd = open_tree("/home/cyphar", OPEN_TREE_CLONE);
move_mount(mntfd, "", AT_FDCWD, "/root", MOVE_MOUNT_F_EMPTY_PATH);

Ceci créerait un nouveau montage de liaison de /home/cyphar en tant qu'objet de montage détaché, puis le rattacherait à /root. La procédure ci-dessus est fonctionnellement équivalente à l'opération de montage suivante utilisant mount(2) :


mount("/home/cyphar", "/root", NULL, MS_BIND, NULL);

NOM

move_mount - déplace un point de montage vers un autre emplacement

SYNTHÈSE

#include <sys/mount.h>

int move_mount(const char *source, const char *target, unsigned long flags);

DESCRIPTION

La fonction move_mount déplace le montage pointé par source vers l'emplacement target.

Le point de montage source doit être une entrée valide dans le système de fichiers. Le chemin target doit être un répertoire existant.

L'argument flags est utilisé pour spécifier des options supplémentaires pour le déplacement. Les valeurs possibles pour flags sont :

  • MS_MOVE : Déplace le montage de source vers target. Si target est un répertoire existant, le montage est déplacé à l'intérieur de ce répertoire. Si target n'est pas un répertoire existant, source sera renommé en target.

VALEUR DE RETOUR

En cas de succès, move_mount renvoie 0. En cas d'erreur, -1 est renvoyé et errno est définie pour indiquer l'erreur.

ERREURS

Les erreurs suivantes peuvent être définies pour errno :

  • EBUSY : Le point de montage source est occupé.
  • ENOENT : Le chemin source ou target n'existe pas.
  • ENOTDIR : Le chemin target n'est pas un répertoire.
  • EPERM : L'utilisateur n'a pas les privilèges nécessaires pour déplacer le montage.

CONFORME À

Cette fonction n'est pas standard POSIX. Elle est spécifique au noyau Linux.

NOTES

Utilisez cette fonction avec précaution, car elle peut avoir des effets imprévus si elle est mal utilisée.

BOGUES

Aucun bogue connu.

VOIR AUSSI

mount(2), umount(2)
