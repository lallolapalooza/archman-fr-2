MODESETTING(4) Manuel des pilotes de périphériques MODESETTING(4)

NOM

modesetting - pilote vidéo pour périphérique de framebuffer

SYNTAXE

Section "Device"
  Identifier "nom_périph"
  Driver "modesetting"
  BusID  "pci:bus:dev:func"
  ...
EndSection

DESCRIPTION

modesetting est un pilote Xorg pour les périphériques KMS. Ce pilote prend en charge les affichages TrueColor dans les profondeurs de framebuffer de 15, 16, 24 et 30 bits. RandR 1.2 est pris en charge pour les configurations multi-écrans. L'accélération est disponible via glamor pour les périphériques prenant en charge au moins OpenGL ES 2.0 ou OpenGL 2.1. Si glamor n'est pas activé, un framebuffer fantôme est configuré en fonction des préférences des pilotes KMS (sauf si le framebuffer a 24 bits par pixel, auquel cas le framebuffer fantôme est toujours utilisé).

MATÉRIEL SUPPORTÉ

Le pilote modesetting prend en charge tout le matériel pour lequel un pilote KMS est disponible. modesetting utilise les ioctls DRM KMS de Linux et la création/mappage d'objets "dumb".

DÉTAILS DE CONFIGURATION

Veuillez vous référer à xorg.conf(5) pour les détails de configuration généraux. Cette section couvre uniquement les détails de configuration spécifiques à ce pilote.

Pour ce pilote, il n'est pas nécessaire de spécifier les modes dans la section screen du fichier de configuration. Le pilote modesetting peut récupérer le mode vidéo actuellement utilisé auprès du pilote du noyau et l'utilisera s'il n'y a pas de modes vidéo configurés.

Pour les cartes PCI, vous devrez peut-être ajouter une ligne BusID à la section Device. Voir ci-dessus pour un exemple de ligne.

Les Options de pilote suivantes sont prises en charge :

Option "SWcursor" "booléen"
Sélectionne le curseur logiciel. La valeur par défaut est off.
Option "kmsdev" "chaîne"
Le périphérique de framebuffer à utiliser. Par défaut : /dev/dri/card0.
Option "ShadowFB" "booléen"
Active ou désactive l'utilisation de la couche de framebuffer fantôme. Par défaut : on.
Option "DoubleShadow" "booléen"
Double mise en mémoire tampon des mises à jour fantômes. Lorsque cette option est activée, le pilote conserve deux copies du framebuffer fantôme. Lorsque le framebuffer fantôme est vidé, les anciennes et nouvelles versions du fantôme sont comparées, et seules les tuiles qui ont réellement changé sont téléchargées sur le périphérique. C'est une optimisation pour les GPU de classe serveur avec une fonction d'affichage à distance (typiquement VNC), où les mises à jour à distance sont déclenchées par toute écriture dans le framebuffer, il est donc crucial de minimiser la quantité de données téléchargées. Cette option est activée par défaut pour les périphériques ASPEED et Matrox G200, et désactivée sinon.
Option "AccelMethod" "chaîne"
L'un des choix : "glamor" ou "none". Par défaut : glamor.
Option "PageFlip" "booléen"
Active le basculement de page DRI3. La valeur par défaut est on.
Option "VariableRefresh" "booléen"
Active la prise en charge de l'actualisation variable sur les CRTC de l'écran lorsqu'une application appropriée bascule via l'extension Present.
La valeur par défaut est off.
Option "AsyncFlipSecondaries" "booléen"
Utilise les basculements asynchrones pour les sorties vidéo secondaires dans les configurations multi-écrans. Si un écran a plusieurs périphériques connectés et que le basculement de page DRI3 est utilisé, un seul des périphériques aura son basculement de page synchronisé avec le vblank pour une présentation sans déchirement. C'est le périphérique utilisé pour la synchronisation de la présentation et le marquage temporel, généralement celui qui couvre la plus grande zone de pixels de l'écran. Tous les autres périphériques ("Secondaries") ne synchroniseront pas leurs basculements. Cela peut entraîner des déchirements sur ces périphériques, mais cela évite un ralentissement permanent ou périodique ou un jugement irritant des animations si toutes les sorties vidéo ne sont pas synchronisées les unes avec les autres et avec le même taux de rafraîchissement. Il n'existe pas de solution parfaite en dehors de périphériques parfaitement synchronisés, mais cette option peut donner des résultats préférables si les périphériques d'une configuration multi-écrans se reflètent ou se clonent mutuellement. La valeur par défaut est off.
Option "ZaphodHeads" "chaîne"
Spécifie la ou les sorties RandR à utiliser avec le mode zaphod pour une instance de pilote donnée. Si vous utilisez cette option, vous devez l'utiliser pour toutes les instances du pilote.
Par exemple : Option "ZaphodHeads" "LVDS,VGA-0" attribuera les sorties xrandr LVDS et VGA-0 à cette instance du pilote.
Option "UseGammaLUT" "booléen"
Active ou désactive l'utilisation de la propriété GAMMA_LUT, lorsqu'elle est disponible. Lorsqu'elle est activée, cette option permet au pilote d'utiliser des rampes gamma avec plus d'entrées, si le noyau le prend en charge. Par défaut, GAMMA_LUT sera utilisé pour les pilotes KMS dont l'utilisation de GAMMA_LUT est jugée sûre.
