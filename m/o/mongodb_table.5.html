NOM

mongodb_table - Configuration du client MongoDB pour Postfix

SYNTAXE

postmap -q "chaine" mongodb:/etc/postfix/nom_fichier
postmap -q - mongodb:/etc/postfix/nom_fichier <fichier_entree

DESCRIPTION


Le système de messagerie Postfix utilise des tables optionnelles pour la réécriture d'adresses ou le routage de courrier. Ces tables sont généralement au format dbm ou db.

Alternativement, les tables de recherche peuvent être spécifiées comme des bases de données MongoDB. Afin d'utiliser les recherches MongoDB, définissez une source MongoDB comme table de recherche dans main.cf, par exemple :

    alias_maps = mongodb:/etc/postfix/mongodb-aliases.cf

Dans cet exemple, le fichier /etc/postfix/mongodb-aliases.cf a le même format que le fichier main.cf de Postfix, et peut spécifier les paramètres décrits ci-dessous. Il est également possible d'avoir la configuration dans main.cf ; voir "PARAMÈTRES OBSOLÈTES DE MAIN.CF" ci-dessous.

Il est fortement recommandé d'utiliser proxy:mongodb, afin de réduire le nombre de connexions à la base de données. Par exemple :

    alias_maps = proxy:mongodb:/etc/postfix/mongodb-aliases.cf

Note : lors de l'utilisation de proxy:mongodb:/fichier, le fichier doit être lisible par l'utilisateur postfix non privilégié (spécifié avec le paramètre de configuration Postfix mail_owner).

PARAMÈTRES MONGODB

uri
L'URI du serveur/cluster mongo auquel Postfix tentera de se connecter et de requêter. Veuillez consulter https://www.mongodb.com/docs/manual/reference/connection-string/

Exemple :

    uri = mongodb+srv://utilisateur:motdepasse@loclhost:27017/mail
dbname
Nom de la base de données à partir de laquelle les informations seront lues. Exemple : 
    dbname = mail
collection
Nom de la collection (table) à partir de laquelle les informations seront lues. Exemple : 
    collection = mailbox
query_filter
Le modèle de requête MongoDB utilisé pour rechercher dans la base de données, où %s est un substitut pour l'adresse e-mail que Postfix tente de résoudre. Veuillez consulter : https://www.mongodb.com/docs/manual/tutorial/query-documents/

Exemple :

    query_filter = {"$or": [{"username": "%s"}, {"alias.address": "%s"}], "active": 1}

Ce paramètre prend en charge les expansions '%' suivantes :

%%
Ceci est remplacé par un caractère '%' littéral.
%s
Ceci est remplacé par la clé d'entrée. Le %s doit apparaître entre guillemets, car toutes les requêtes Postfix sont des chaînes contenant (des parties d'un) domaine ou une adresse e-mail. Postfix n'effectue pas de requêtes numériques.
%u
Lorsque la clé d'entrée est une adresse de la forme utilisateur@domaine, %u est remplacé par la partie locale de l'adresse. Sinon, %u est remplacé par la chaîne de recherche entière.
%d
Lorsque la clé d'entrée est une adresse de la forme utilisateur@domaine, %d est remplacé par la partie domaine de l'adresse.
%[1-9]
Les motifs %1, %2, ... %9 sont remplacés par le composant le plus significatif correspondant du domaine de la clé d'entrée. Si la clé d'entrée est utilisateur@mail.exemple.com, alors %1 est com, %2 est exemple et %3 est mail.
Dans les substitutions ci-dessus, les caractères seront mis entre guillemets selon les exigences de la RFC 4627. Par exemple, chaque guillemet ou caractère backslash sera échappé avec un caractère backslash.
projection
Projections de requêtes MongoDB avancées. Veuillez consulter : https://www.mongodb.com/docs/manual/tutorial/project-fields-from-query-results/
  • Si projection n'est pas vide, alors result_attribute doit être vide.
  • Cette implémentation ne peut extraire des informations que des champs de résultat de type chaîne (UTF8), entier (int32, int64) et tableau. Les autres champs de résultat seront ignorés avec un avertissement. Veuillez consulter : https://mongoc.org/libbson/current/bson_type_t.html
  • Comme avec result_attribute, le champ _id de niveau supérieur (type OID) est automatiquement supprimé des résultats de projection.
result_attribute
Liste séparée par des virgules ou des espaces blancs avec les noms des champs à retourner dans un résultat de recherche.
  • Si result_attribute n'est pas vide, alors projection doit être vide.
  • Comme avec projection, le champ _id de niveau supérieur (type OID) est automatiquement supprimé des résultats de recherche.
result_format (par défaut: %s)
Modèle de format appliqué au résultat de projection ou result_attribute. Le plus souvent utilisé pour ajouter (ou préfixer) du texte au résultat. Ce paramètre prend en charge les expansions '%' suivantes :
%%
Ceci est remplacé par un caractère '%' littéral.
%s
Ceci est remplacé par la valeur de l'attribut de résultat. Lorsque le résultat est vide, il est ignoré.
%u
Lorsque la valeur de l'attribut de résultat est une adresse de la forme utilisateur@domaine, %u est remplacé par la partie locale de l'adresse. Lorsque le résultat a une partie locale vide, il est ignoré.
%d
Lorsque la valeur d'un attribut de résultat est une adresse de la forme utilisateur@domaine, %d est remplacé par la partie domaine de la valeur de l'attribut. Lorsque le résultat n'est pas qualifié, il est ignoré.
%[SUD1-9]
Les expansions en majuscules et en chiffres décimaux interpolent les parties de la clé d'entrée plutôt que le résultat. Leur comportement est identique à celui décrit avec query_filter, et en fait, comme la clé d'entrée est connue à l'avance, les recherches dont la clé ne contient pas toutes les informations spécifiées dans le modèle de résultat sont supprimées et ne retournent aucun résultat.
Par exemple, l'utilisation de "result_format = smtp:[%s]" permet d'utiliser un attribut mailHost comme base d'une table transport(5). Après application du format de résultat, plusieurs valeurs sont concaténées sous forme de chaînes séparées par des virgules. Le paramètre expansion_limit expliqué ci-dessous permet de limiter le nombre de valeurs dans le résultat, ce qui est particulièrement utile pour les maps qui doivent retourner une valeur unique.

La valeur par défaut %s spécifie que chaque valeur d'attribut doit être utilisée telle quelle.

NOTE : NE mettez PAS de guillemets autour du format de résultat ! Le résultat n'est pas une chaîne JSON.

domain (par défaut: pas de liste de domaines)
Il s'agit d'une liste de noms de domaines, de chemins vers des fichiers ou de bases de données "type:table". Lorsqu'il est spécifié, seules les clés de recherche entièrement qualifiées avec une partie locale *non vide* et un domaine correspondant sont éligibles pour la recherche : les recherches 'utilisateur', les recherches de domaine nu et les recherches "@domaine" ne sont pas effectuées. Cela peut réduire considérablement la charge de requête sur la base de données backend. Exemple : 
    domain = postfix.org, hash:/etc/postfix/searchdomains
expansion_limit (par défaut: 0)
Une limite sur le nombre total d'éléments de résultat retournés (sous forme de liste séparée par des virgules) par une recherche contre la map. Un réglage de zéro désactive la limite. Les recherches échouent avec une erreur temporaire si la limite est dépassée. Définir la limite à 1 garantit que les recherches ne retournent pas plusieurs valeurs.

PARAMÈTRES OBSOLÈTES DE MAIN.CF

Les paramètres MongoDB peuvent également être définis dans main.cf. Spécifiez comme source MongoDB un nom qui ne commence pas par une barre oblique ou un point. Les paramètres MongoDB seront alors accessibles

MONGODB PARAMETERS

The following Postfix configuration parameters are available for mongodb tables.

mongodb_maps
The lookup tables that are specified with the mongodb: transport.
mongodb_map_lookup_timeout
The time limit for the mongodb client library to complete a lookup operation. Defaults to 60 seconds.
mongodb_connection_timeout
The time limit for the mongodb client library to establish a connection to the MongoDB server. Defaults to 5 seconds.
mongodb_host
Specifies the MongoDB host and port. Defaults to localhost:27017.
mongodb_user
Specifies the MongoDB username.
mongodb_password
Specifies the MongoDB password.
mongodb_database
Specifies the MongoDB database name.
mongodb_collection
Specifies the MongoDB collection name.
mongodb_filter
Specifies a filter to apply to the MongoDB query. Defaults to {}.
mongodb_index
Specifies the index to use for the MongoDB query. Defaults to _id.

OBSOLETE MAIN.CF PARAMETERS

The following parameters are obsolete and will be removed in future versions:

mongodb_host_lookup_timeout
This parameter is obsolete. Use mongodb_map_lookup_timeout instead.
mongodb_connection_lookup_timeout
This parameter is obsolete. Use mongodb_connection_timeout instead.

When using the mongodb: transport, parameters can be specified directly in the main.cf file. The parameter name is formed by concatenating the source name, an underscore, and the parameter name. For example, if a map is specified as "mongodb:mongodb_source", the "uri" parameter would be defined in main.cf as "mongodb_source_uri".

Note: with this form, passwords are written in main.cf, which is normally world-readable, and '$' in a mongodb parameter setting needs to be written as '$$'.
