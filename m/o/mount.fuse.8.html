NOM

fuse - format et options pour les systèmes de fichiers fuse

DESCRIPTION

FUSE (Filesystem in Userspace) est une interface simple pour que les programmes en espace utilisateur puissent exporter un système de fichiers virtuel dans le noyau Linux. FUSE vise également à fournir une méthode sécurisée pour que les utilisateurs non privilégiés puissent créer et monter leurs propres implémentations de systèmes de fichiers.

CONFIGURATION

Certaines options concernant la politique de montage peuvent être définies dans le fichier /etc/fuse.conf. Actuellement, ces options sont :

mount_max = NNN
Définit le nombre maximum de montages FUSE autorisés pour les utilisateurs non root. La valeur par défaut est 1000.
user_allow_other
Permet aux utilisateurs non root de spécifier les options de montage allow_other ou allow_root (voir ci-dessous).

OPTIONS

La plupart des options de montage génériques décrites dans mount sont supportées (ro, rw, suid, nosuid, dev, nodev, exec, noexec, atime, noatime, sync, async, dirsync). Les systèmes de fichiers sont montés avec nodev,nosuid par défaut, ce qui ne peut être outrepassé que par un utilisateur privilégié.

Options de montage générales :

Ce sont des options de montage FUSE spécifiques qui peuvent être spécifiées pour tous les systèmes de fichiers :

default_permissions
Par défaut, FUSE ne vérifie pas les permissions d'accès aux fichiers, le système de fichiers est libre d'implémenter sa politique d'accès ou de la laisser au mécanisme d'accès sous-jacent (par exemple, dans le cas de systèmes de fichiers réseau). Cette option active la vérification des permissions, restreignant l'accès en fonction du mode de fichier. Cette option est généralement utile conjointement avec l'option de montage allow_other.
allow_other
Cette option outrepasse la mesure de sécurité restreignant l'accès aux fichiers à l'utilisateur qui monte le système de fichiers. Ainsi, tous les utilisateurs (y compris root) peuvent accéder aux fichiers. Cette option n'est autorisée que pour root par défaut, mais cette restriction peut être supprimée avec une option de configuration décrite dans la section précédente.
allow_root
Cette option est similaire à allow_other mais l'accès aux fichiers est limité à l'utilisateur qui monte le système de fichiers et à root. Cette option et allow_other sont mutuellement exclusives.
kernel_cache
Cette option désactive la purge du cache du contenu des fichiers à chaque appel de open(2). Elle ne doit être activée que sur les systèmes de fichiers où les données des fichiers ne sont jamais modifiées en externe (pas via le système de fichiers FUSE monté). Elle n'est donc pas adaptée aux systèmes de fichiers réseau et autres systèmes de fichiers intermédiaires.

NOTE : si cette option n'est pas spécifiée (et ni direct_io), les données sont toujours mises en cache après l'appel à open(2), ainsi un appel système read(2) n'initiera pas toujours une opération de lecture.

auto_cache
Cette option active la purge automatique du cache de données lors de l'appel à open(2). Le cache ne sera purgé que si l'heure de modification ou la taille du fichier ont changé.
large_read
Émet des requêtes de lecture volumineuses. Cela peut améliorer les performances pour certains systèmes de fichiers, mais peut aussi les dégrader. Cette option n'est utile que sur les noyaux 2.4.X, car sur les noyaux 2.6, la taille des requêtes est déterminée automatiquement pour des performances optimales.
direct_io
Cette option désactive l'utilisation du cache de pages (cache de contenu de fichier) dans le noyau pour ce système de fichiers. Cela a plusieurs effets :
1.
Chaque appel système read(2) ou write(2) initiera une ou plusieurs opérations de lecture ou d'écriture, les données ne seront pas mises en cache dans le noyau.
2.
La valeur de retour des appels système read() et write() correspondra aux valeurs de retour des opérations de lecture et d'écriture. Ceci est utile, par exemple, si la taille du fichier n'est pas connue à l'avance (avant de le lire).
max_read=N
Avec cette option, la taille maximale des opérations de lecture peut être définie. La valeur par défaut est infinie. Notez que la taille des requêtes de lecture est de toute façon limitée à 32 pages (soit 128 Ko sur i386).
max_readahead=N
Définit le nombre maximum d'octets pour la lecture anticipée (read-ahead). La valeur par défaut est déterminée par le noyau. Sur Linux 2.6.22 ou antérieur, elle est de 131072 (128 Ko).
max_write=N
Définit le nombre maximum d'octets dans une seule opération d'écriture. La valeur par défaut est de 128 Ko. Notez que, en raison de diverses limitations, la taille des requêtes d'écriture peut être beaucoup plus petite (4 Ko). Cette limitation sera supprimée à l'avenir.
async_read
Effectue les lectures de manière asynchrone. C'est le comportement par défaut.
sync_read
Effectue toutes les lectures (même la lecture anticipée) de manière synchrone.
hard_remove
Le comportement par défaut est que si un fichier ouvert est supprimé, il est renommé en un fichier caché (.fuse_hiddenXXX), et n'est supprimé que lorsque le fichier est finalement libéré. Cela évite à l'implémentation du système de fichiers de devoir gérer ce problème. Cette option désactive ce comportement de masquage, et les fichiers sont immédiatement supprimés lors d'une opération d'unlink (ou lors d'une opération de renommage qui écrase un fichier existant).

Il est recommandé de ne pas utiliser l'option hard_remove. Lorsque hard_remove est défini, les fonctions libc suivantes échouent sur les fichiers non liés (renvoyant errno ENOENT) : read(2), write(2), fsync(2), close(2), f*xattr(2), ftruncate(2), fstat(2), fchmod(2), fchown(2)

debug
Active l'affichage des informations de débogage par la bibliothèque.
fsname=NAME
Définit la source du système de fichiers (premier champ dans /etc/mtab). La valeur par défaut est le nom du programme de montage.
subtype=TYPE
Définit le type du système de fichiers (troisième champ dans /etc/mtab). La valeur par défaut est le nom du programme de montage. Si le noyau le supporte, /etc/mtab et /proc/mounts afficheront le type de système de fichiers comme fuse.TYPE.

Si le noyau ne supporte pas les sous-types, le champ source sera TYPE#NAME, ou si l'option fsname n'est pas spécifiée, simplement TYPE.

use_ino
Respecte le champ st_ino dans les fonctions du noyau getattr() et fill_dir(). Cette valeur est utilisée pour remplir le champ st_ino dans les fonctions stat(2), lstat(2), fstat(2) et le champ d_ino dans la fonction readdir(2). Le système de fichiers n'a pas à garantir l'unicité, cependant certaines applications dépendent de cette valeur pour être unique sur l'ensemble du système de fichiers.
readdir_ino
Si l'option use_ino n'est pas donnée, essaie quand même de remplir le champ d_ino dans readdir(2). Si le nom a déjà été cherché et est toujours dans le cache, le numéro d'inode trouvé sera utilisé. Sinon, il sera défini à -1. Si l'option use_ino est donnée, cette option est ignorée.
nonempty

OPTIONS

These are the options recognized by the mount.fuse program. Some options may be specific to certain filesystem implementations. Consult the documentation for the specific filesystem for details.

allow_other
Allow other users besides the user who mounted the filesystem to access it. By default, only the user who mounted the filesystem can access it.
allow_root
Allow the root user to access the filesystem. This option is the default when allow_other is not specified.
default_permissions
Enable permission checking by the kernel. If this option is enabled, the filesystem must correctly set the st_mode and st_uid/st_gid fields in the struct stat. If this option is disabled, all permission bits in st_mode are ignored, and all attempts to access files and directories will succeed (as long as the file/directory exists). The default is to enable permission checking.
use_ino
Keep inode numbers as specified by the filesystem. By default, FUSE assigns its own inode numbers, which can lead to issues with tools that rely on persistent inode numbers.
auto_cache
Enable automatic cache invalidation. This means that FUSE will attempt to keep file data consistent between the cache and the underlying filesystem. However, this can lead to performance degradation.
kernel_cache
Enable caching by the kernel. This allows the kernel to cache file data, which can improve performance but may also lead to stale data if the underlying filesystem changes.
fsname=NAME
Set the filesystem name to NAME. This is used in the output of commands like mount and df.
ro
Mount the filesystem in read-only mode. This option is often specified as -o ro.
rw
Mount the filesystem in read-write mode. This is the default.
suid
Allow setuid and setgid bits to take effect. This option is often specified as -o suid.
nosuid
Do not allow setuid and setgid bits to take effect. This is the default.
dev
Allow interpretation of block special devices. This option is often specified as -o dev.
nodev
Do not allow interpretation of block special devices. This is the default.
exec
Allow execution of binaries. This option is often specified as -o exec.
noexec
Do not allow execution of binaries. This is the default.
atime
Update access times. This option is often specified as -o atime.
noatime
Do not update access times. This is the default.
diratime
Update directory access times. This option is often specified as -o diratime.
nodiratime
Do not update directory access times. This is the default.
relatime
Update access times relative to modification times. This is a compromise between atime and noatime.
strictatime
Update all access times immediately. This can significantly impact performance.
intr
Allow requests to be interrupted. Turning on this option may result in unexpected behavior, if the filesystem does not support request interruption.
silent
Suppress some error messages. This option is often specified as -o silent.
nouid32
Do not support uid32. This is the default on 32-bit systems.
uid32
Support for 32-bit UIDs. This is the default on 64-bit systems.
fscontext=LABEL
Set the SELinux context for the filesystem.
defcontext
Set the default SELinux context for the filesystem.
rootcontext=LABEL
Set the SELinux context for the root directory of the filesystem.
umask=M
Override the permission bits in st_mode set by the filesystem. The resulting permission bits are the ones missing from the given umask value. The value is given in octal representation.
umask=0000
Do not mask any of the permission bits.
umask=0022
Mask the group and other write bits. This is the default.
uid=N
Override the st_uid field set by the filesystem (N is numeric).
gid=N
Override the st_gid field set by the filesystem (N is numeric).
blkdev
Mount a filesystem backed by a block device. This is a privileged option. The device must be specified with the fsname=NAME option.
entry_timeout=T
The timeout in seconds for which name lookups will be cached. The default is 1.0 second. For all the timeout options, it is possible to give fractions of a second as well (e.g. entry_timeout=2.8)
negative_timeout=T
The timeout in seconds for which a negative lookup will be cached. This means, that if file did not exist (lookup retuned ENOENT), the lookup will only be redone after the timeout, and the file/directory will be assumed to not exist until then. The default is 0.0 second, meaning that caching negative lookups are disabled.
attr_timeout=T
The timeout in seconds for which file/directory attributes are cached. The default is 1.0 second.
ac_attr_timeout=T
The timeout in seconds for which file attributes are cached for the purpose of checking if auto_cache should flush the file data on open. The default is the value of attr_timeout
intr_signal=NUM
Specify which signal number to send to the filesystem when a request is interrupted. The default is hardcoded to USR1.
modules=M1[:M2...]
Add modules to the filesystem stack. Modules are pushed in the order they are specified, with the original filesystem being on the bottom of the stack.

MODULES FUSE (EMPILEMENTATION)

Les modules sont le support d'implémentation de systèmes de fichiers en pile vers l'API de haut niveau. Les modules de système de fichiers peuvent être intégrés à libfuse ou chargés à partir d'une bibliothèque partagée

iconv

Effectuer la conversion du jeu de caractères des noms de fichiers. Les options sont :

from_code=CHARSET
Jeu de caractères à convertir depuis (voir iconv -l pour une liste de valeurs possibles). Le défaut est UTF-8.
to_code=CHARSET
Jeu de caractères à convertir vers. Le défaut est déterminé par la locale actuelle.

subdir

Précéder chaque chemin d'un répertoire donné. Les options sont :

subdir=DIR
Répertoire à précéder à tous les chemins. Cette option est obligatoire.
rellinks
Transformer les liens symboliques absolus en relatifs
norellinks
Ne pas transformer les liens symboliques absolus en relatifs. C'est le défaut.

SÉCURITÉ

Le programme fusermount est installé avec le groupe-utilisateur défini à fuse. Ceci est fait pour permettre aux utilisateurs du groupe fuse de monter leurs propres implémentations de systèmes de fichiers. Il doit cependant y avoir quelques limitations, afin d'empêcher les mauvais utilisateurs de faire des choses nuisibles. Actuellement, ces limitations sont :

1.
L'utilisateur ne peut monter que sur un point de montage pour lequel il a la permission d'écriture
2.
Le point de montage n'est pas un répertoire "sticky" qui n'appartient pas à l'utilisateur (comme /tmp l'est habituellement)
3.
Aucun autre utilisateur (y compris root) ne peut accéder au contenu du système de fichiers monté.

NOTE

Les systèmes de fichiers FUSE sont démontés en utilisant la commande fusermount(1) (fusermount -u point_de_montage).
