MOUNT.NILFS2(8) Manuel de l'administrateur système MOUNT.NILFS2(8)

NOM

mount.nilfs2 - monter un système de fichiers NILFS2

SYNTAXE

mount -t nilfs2 [-finrvw] [-o options [,...]] périphérique point_de_montage
mount -t nilfs2 [-finrvw] [-o options [,...]] périphérique | point_de_montage

mount.nilfs2 [-fnrvw] [-o options [,...]] périphérique point_de_montage

mount.nilfs2 [-V]

DESCRIPTION

mount.nilfs2 sert à attacher un système de fichiers NILFS2 sur le répertoire spécifié point_de_montage. Il est destiné à être exécuté depuis mount(8), et invoquera le collecteur de recyclage nilfs_cleanerd(8) après qu'un appel système de montage réel ait réussi. Inversement, umount.nilfs2(8) arrêtera le collecteur de recyclage avant de détacher le système de fichiers.

L'interface de ligne de commande standard est la première forme :


mount -t nilfs2 [options] périphérique point_de_montage
Ceci indique au noyau d'attacher le système de fichiers NILFS2 sur le périphérique au répertoire point_de_montage. Avec la seconde forme, le programme mount tente de trouver un argument périphérique ou point_de_montage manquant à partir de la table /etc/fstab.

La troisième forme, qui invoque directement mount.nilfs2, est également utilisable car mount.nilfs2 maintient lui-même l'état de montage du système, comme la liste des systèmes de fichiers montés décrite dans /etc/mtab. Cependant, la première ou la seconde forme est généralement recommandée car certaines options étendues ne sont pas supportées par la troisième forme.

OPTIONS

L'ensemble complet des options utilisées par une invocation de mount(8) est déterminé en extrayant les options de la table fstab, puis en appliquant toutes les options spécifiées par l'argument -o, et enfin en appliquant une option -r ou -w, lorsqu'elle est présente.

Voir mount(8) pour l'ensemble complet des options. Les options couramment utilisées sont les suivantes :

-V
Affiche la version.
-f
Simule le montage du système de fichiers, ce qui signifie que l'appel système réel sera ignoré. Cette option est utilisée pour ajouter des entrées pour des périphériques qui ont été montés précédemment avec l'option -n. Elle peut également être utilisée pour invoquer nilfs_cleanerd(8) ignoré précédemment.
-i
N'appelle pas mount.nilfs2. Ceci désactive la collecte de recyclage et la gestion des options de montage pseudo.
-n
Monte sans écrire dans /etc/mtab. Ceci est nécessaire par exemple quand /etc est sur un système de fichiers en lecture seule.
-r
Monte le système de fichiers en lecture seule. Un synonyme est "-o ro".
-v
Mode verbeux.
-w
Monte le système de fichiers en lecture/écriture. C'est le mode par défaut. Un synonyme est "-o rw".
-o
Les options sont spécifiées avec un drapeau -o suivi d'une chaîne d'options séparées par des virgules. Certaines de ces options ne sont utiles que lorsqu'elles apparaissent dans le fichier /etc/fstab. Pour les options de système de fichiers standard, voir mount(8).

OPTIONS DE MONTAGE SPÉCIFIQUES À NILFS2

Les options suivantes s'appliquent uniquement au système de fichiers NILFS2. Elles suivent toutes le drapeau -o.

barrier / nobarrier
Ces options activent/désactivent (activé par défaut) les écritures barrières pour les entrées/sorties de blocs vers un périphérique inférieur. L'écriture barrière joue un rôle important pour assurer la cohérence des systèmes de fichiers après un crash système ou une panne de courant. NILFS2 utilise cette fonctionnalité par défaut pour garantir la fiabilité. Pour les périphériques ne supportant pas l'écriture barrière, elle sera désactivée automatiquement et un avertissement sera enregistré.
cp=numéro-point-de-contrôle
Spécifie le numéro-point-de-contrôle du snapshot à monter. Les points de contrôle et les snapshots sont listés par lscp(1). Seuls les points de contrôle marqués comme snapshot sont montables avec cette option. Notez que l'option de montage en lecture seule doit être spécifiée ensemble.
errors=continue / errors=remount-ro / errors=panic
Définit le comportement en cas d'erreur. (Soit ignorer les erreurs et marquer simplement le système de fichiers comme erroné et continuer, soit remonter le système de fichiers en lecture seule, soit paniquer et arrêter le système.) Le comportement par défaut est remount-ro. Dans les noyaux antérieurs à Linux 2.6.35, continue était le comportement par défaut.
pp=période-de-protection
Spécifie la période-de-protection pour le démon de nettoyage (en secondes). nilfs_cleanerd ne supprime jamais les points de contrôle récents dont le temps écoulé depuis leur création est inférieur à période-de-protection.
nogc
Désactive la collecte de recyclage. Le démon de nettoyage ne sera pas démarré. Il peut être démarré manuellement, mais dans ce cas, il doit également être arrêté manuellement avant le démontage.
order=relaxed / order=strict
Spécifie la sémantique d'ordre pour les données de fichiers. Les métadonnées sont toujours écrites pour suivre la sémantique POSIX concernant l'ordre des opérations du système de fichiers.
relaxed
Applique une sémantique d'ordre détendue qui permet aux blocs de données modifiés d'être écrits sur disque sans créer de point de contrôle si aucune mise à jour de métadonnées n'est en cours. Ce mode est équivalent au mode de données ordonné du système de fichiers ext3, sauf que les mises à jour des blocs de données conservent toujours l'atomicité. Cela améliorera les performances des écritures synchrones pour les écrasements. C'est le mode par défaut.
strict
Applique une sémantique d'ordre strict qui préserve la séquence de toutes les opérations de fichiers, y compris les écrasements de blocs de données. Cela signifie qu'il est garanti qu'aucun dépassement d'événements ne se produit dans le système de fichiers récupéré après un crash. Contrairement aux systèmes de fichiers journalisés, NILFS2 n'écrit pas un même bloc deux fois sur disque. Il n'y a donc pas de dégradation significative des performances par rapport au mode détendu, sauf pour les écrasements de fichiers.
norecovery
Désactive la récupération du système de fichiers lors du montage. Cela désactive toute écriture sur le périphérique pour les montages en lecture seule ou les snapshots. Cette option échouera pour les montages r/w sur un volume non propre.
discard / nodiscard
Ces options activent/désactivent (désactivé par défaut) l'utilisation des commandes discard/TRIM. Les commandes discard/TRIM sont envoyées au périphérique de bloc sous-jacent lorsque des blocs sont libérés. Ceci est utile pour les périphériques SSD et les LUN sparse/thinly-provisioned. (depuis 2.6.34).

CODES DE RETOUR

Les codes de retour de mount.nilfs2 sont conformes à ceux de mount(8) ; les codes suivants peuvent être retournés (les bits peuvent être combinés par OR) :

0
succès
1
invocation incorrecte ou permissions
2
erreur système (mémoire insuffisante, échec de fork, plus de périphériques loop)
4
bug interne
8
interruption utilisateur
16
problèmes d'écriture ou de verrouillage de /etc/mtab
32
échec du montage
64
certains montages ont réussi
