NOM

mount_afp — monter un système de fichiers afp (AppleShare) en utilisant FUSE

SYNTAXE

mount_afp [-o options] url_afp nœud

DESCRIPTION

La commande mount_afp monte le volume AFP désigné par l'URL afp afp://[utilisateur[;AUTH=nom_uam][:mot_de_passe]@]hôte[:port]/nom_volume au point de montage indiqué par nœud.

Il s'agit normalement d'un lien symbolique vers l'exécutable afp_client(1), qui est une implémentation complète pour monter des volumes AFP en utilisant l'infrastructure FUSE. Il communique avec afpfsd, un démon qui gère les sessions AFP. Les arguments et options sont les suivants :

-o
Les options passées à mount(2) sont spécifiées avec l'option -o suivie d'une chaîne d'options séparées par des virgules. Voir la page de manuel pour les options possibles et leur signification. Les options supplémentaires prises en charge par le client AFP sont les suivantes :
volpass=<mot_de_passe>
La seule option disponible est « -o volpassword=XXX » pour définir le mot de passe du volume (puisqu'il n'y a pas de mécanisme pour cela dans une URL AFP).
rw
Monter le volume en mode lecture-écriture. C'est le comportement par défaut, donc cela n'a aucun effet.
ro
Monter le volume en lecture seule.
group=<nom_groupe>
Monter le volume sous le nom de groupe.
user=<nom_utilisateur>
Monter le volume sous le nom d'utilisateur.
url_afp
Il existe deux formes d'URL afp, une pour TCP/IP et une pour AppleTalk :

afp://[utilisateur[;AUTH=nom_uam][:mot_de_passe]@]hôte[:port]/volume

afp:/at/[utilisateur[;AUTH=nom_uam][:mot_de_passe]@]nom_serveur[:nom_zone]/volume

Désigne le serveur afp et le point de partage à monter. Il peut également contenir le nom d'utilisateur et le mot de passe requis pour se connecter au serveur. nom_uam est le nom du protocole de la méthode d'authentification. Si le port n'est pas spécifié, le port 548 est utilisé.

nœud
Chemin vers le point de montage, qui doit être un répertoire pour lequel l'utilisateur a des permissions d'écriture.

EXEMPLES

L'exemple suivant illustre comment monter le volume afp serveur.entreprise.com/nom_volume/ au point de montage /Volumes/mntpnt :

mkdir /Volumes/mntpnt
mount_afp afp://nom_utilisateur:mot_de_passe_utilisateur@serveur.entreprise.com/nom_volume/ /Volumes/mntpnt
Cet exemple montre l'URL correcte à utiliser pour monter le volume guestVolume du serveur afp myserver en tant qu'invité : 
mkdir /Volumes/invité
mount_afp "afp://;AUTH=No%20User%20Authent@myserver/guestVolume" /Volumes/invité

L'exemple suivant montre comment utiliser un nom d'utilisateur « user:name » et un mot de passe « p@ssword » :
serveur.entreprise.com/nom_volume/ au point de montage /Volumes/mntpnt :
mkdir /Volumes/mntpnt mount_afp afp://user::name:p@@ssword@serveur.entreprise.com/nom_volume/ /Volumes/mntpnt
Cet exemple montre l'URL correcte à utiliser pour monter le volume myVolume du serveur afp myserver en utilisant l'authentification Kerberos : 
mkdir /Volumes/myVolume
mount_afp "afp://;AUTH=Client%20Krb%20v2@myserver/myVolume" /Volumes/myVolume

VOIR AUSSI

afp_client(1) (pour plus de commandes AFP), afpcmd(1) (pour un client AFP en ligne de commande sans FUSE),

HISTORIQUE

La commande mount_afp est apparue pour la première fois dans Mac OS X version 10.0. L'authentification Kerberos a été ajoutée dans Mac OS X version 10.2. Cette syntaxe (et la page de manuel) a été utilisée pour l'implémentation FUSE de afpfs-ng.

VALEURS DE RETOUR

0
mount_afp a monté avec succès le répertoire du volume.
-1
Le volume du serveur n'a pas pu être monté.

VOIR AUSSI

afp_client(1), afpfsd(1)
