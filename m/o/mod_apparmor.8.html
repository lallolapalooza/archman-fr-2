NOM

mod_apparmor - confinement fin d'AppArmor pour Apache

DESCRIPTION

Un profil AppArmor s'applique à un programme exécutable ; si une partie du programme a besoin d'autorisations d'accès différentes de celles d'autres parties, le programme peut « changer de casquette » via aa_change_hat(2) vers un rôle différent, également connu sous le nom de sous-profil. Le module Apache mod_apparmor utilise le mécanisme de aa_change_hat(2) pour offrir un confinement plus fin des éléments dynamiques au sein d'Apache tels que les scripts php et perl individuels, tout en conservant les avantages de performance de l'utilisation de mod_php et mod_perl.

Pour utiliser mod_apparmor avec Apache, assurez-vous que mod_apparmor est configuré pour être chargé dans Apache, soit via a2enmod, yast ou une édition manuelle des fichiers de configuration de apache2(8)/httpd(8), et redémarrez Apache. Assurez-vous qu'AppArmor fonctionne également.

Une fois que mod_apparmor est chargé dans Apache, toutes les requêtes adressées à Apache amèneront mod_apparmor à tenter de changer de casquette pour correspondre au ServerName du serveur/vhost. Si aucune casquette de ce type n'est trouvée, il se rabattra d'abord en tentant de changer de casquette composée du ServerName-URI (par exemple, "www.example.com-/app/some.cgi"). Si cette casquette n'est pas trouvée, il se rabattra sur la casquette nommée par l'URI (par exemple, "/app/some.cgi"). Si cette casquette n'est pas trouvée, il se rabattra sur l'utilisation de la casquette DEFAULT_URI ; si celle-ci n'existe pas non plus, il se rabattra sur l'utilisation du profil Apache global. La plupart des pages web statiques peuvent simplement utiliser la casquette DEFAULT_URI.

De plus, avant que des requêtes n'arrivent à Apache, mod_apparmor tentera de changer de casquette pour la casquette HANDLING_UNTRUSTED_INPUT. mod_apparmor tentera d'utiliser cette casquette pendant qu'Apache effectue l'analyse initiale d'une requête http donnée, avant qu'elle ne soit transmise à un gestionnaire spécifique (comme mod_php) pour traitement.

Comme la définition de casquettes pour chaque URI/URL devient souvent fastidieuse, mod_apparmor fournit les options de configuration Apache AAHatName et AADefaultHatName.

AAHatName
AAHatName vous permet de spécifier une casquette à utiliser pour une directive Apache <Directory>, <DirectoryMatch>, <Location> ou <LocationMatch> donnée (voir la documentation Apache pour plus de détails). Notez que le comportement de mod_apparmor peut être confus si les directives <Directory*> et <Location*> sont entremêlées et il est recommandé d'utiliser un seul type de directive. Si la casquette spécifiée par AAHatName n'existe pas dans le profil Apache, alors il se rabat sur le comportement décrit ci-dessus.
AADefaultHatName
AADefaultHatName vous permet de spécifier une casquette par défaut à utiliser pour les hôtes virtuels et autres directives Apache, afin que vous puissiez avoir des valeurs par défaut différentes pour différents hôtes virtuels. Ceci peut être remplacé par la directive AAHatName et n'est vérifié que s'il n'y a pas de AAHatName correspondant. La valeur par défaut de AADefaultHatName est le ServerName pour la configuration du serveur/vhost. Si la casquette AADefaultHatName n'existe pas, alors elle se rabat sur le comportement décrit ci-dessus.

RESUME DES REQUÊTES URI

Lors du profilage avec mod_apparmor, il est utile de garder à l'esprit l'ordre des opérations suivant :

Pour chaque requête URI, mod_apparmor tentera d'abord aa_change_hat(2) vers ^HANDLING_UNTRUSTED_INPUT, si elle existe.

Ensuite, après avoir effectué l'analyse initiale de la requête, mod_apparmor :

1.
essaiera de faire un aa_change_hat(2) vers une casquette AAHatName correspondante si elle existe et s'applique, sinon il
2.
essaiera de faire un aa_change_hat(2) vers une casquette AADefaultHatName, soit le ServerName (par défaut), soit la valeur de configuration spécifiée par la directive AADefaultHatName, pour le serveur/vhost, sinon il
3.
essaiera de faire un aa_change_hat(2) vers le ServerName-URI, sinon il
4.
essaiera de faire un aa_change_hat(2) vers l'URI elle-même, sinon il
5.
essaiera de faire un aa_change_hat(2) vers la casquette DEFAULT_URI, si elle existe, sinon il
6.
se rabattra sur la politique Apache globale

BOGUES

mod_apparmor() ne prend actuellement en charge qu'apache2, et n'a été testé qu'avec la configuration MPM prefork -- les configurations threadées d'Apache peuvent ne pas fonctionner correctement. Pour les utilisateurs d'Apache 2.4, vous devriez activer le module mpm_prefork.

Il y a probablement d'autres bogues qui se cachent ; si vous en trouvez, veuillez les signaler sur https://gitlab.com/apparmor/apparmor/-/issues.

VOIR AUSSI
