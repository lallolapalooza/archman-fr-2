NOM

mosh-server — programme d'assistance côté serveur pour mosh

SYNTAXE

mosh-server new [-s] [-v] [-i IP] [-p PORT[:PORT2]] [-c COULEURS] [-- commande...]

DESCRIPTION

mosh-server est un programme d'assistance pour l'application de terminal distant mosh(1).

mosh-server se lie à un port UDP élevé et choisit une clé de chiffrement pour protéger la session. Il affiche les deux sur la sortie standard, se détache du terminal et attend que le mosh-client établisse une connexion. Il se terminera si aucun client ne l'a contacté dans les 60 secondes.

Par défaut, mosh-server se lie à un port compris entre 60000 et 61000 et exécute le shell de connexion de l'utilisateur.

Sur les plateformes avec utempter, mosh-server maintient une entrée dans le fichier utmp(5) pour indiquer son ID de processus, si la session est connectée et l'adresse IP actuelle du client.

mosh-server se termine lorsque le client termine la connexion.

OPTIONS

L'argument « new » doit être le premier sur la ligne de commande pour utiliser les options en ligne de commande.

-s
se lier à l'interface locale utilisée pour une connexion SSH entrante, donnée dans la variable d'environnement SSH_CONNECTION (pour les hôtes multihébergés)
-v
Afficher des informations de débogage même après le détachement. Plus d'instances de ce drapeau entraîneront plus d'informations de débogage.
-i IP
Adresse IP de l'interface locale à lier (pour les hôtes multihébergés)
-p PORT[:PORT2]
Numéro de port UDP ou plage de ports à lier. -p 0 laissera le système d'exploitation choisir un port UDP disponible.
-c COULEURS
Nombre de couleurs à annoncer aux applications via TERM (par exemple, 8, 256)
-l NOM=VALEUR
Variable d'environnement liée à la localisation à essayer dans le cadre d'un environnement de secours, si l'environnement de démarrage ne spécifie pas de jeu de caractères UTF-8.

VARIABLES ENVIRONNEMENT

Ces variables permettent la configuration côté serveur du comportement de Mosh. Elles peuvent être définies par les administrateurs dans les fichiers de connexion/rc système, /etc/login.conf, ou des mécanismes similaires, ou par les utilisateurs dans leurs fichiers de connexion/rc de shell. mosh-server transmet ces variables à la session de connexion et au shell qu'il démarre, mais leur modification à ce niveau n'aura aucun effet.

MOSH_SERVER_NETWORK_TMOUT
Si cette variable est définie sur un entier positif, elle spécifie combien de temps (en secondes) mosh-server attendra de recevoir une mise à jour du client avant de se terminer. Comme mosh est très utile pour les clients mobiles avec une opération et une connectivité intermittentes, nous suggérons de définir cette variable à une valeur élevée, telle que 604800 (une semaine) ou 2592000 (30 jours). Sinon, mosh-server attendra indéfiniment qu'un client réapparaisse. Cette variable est quelque peu similaire à la variable TMOUT que l'on trouve dans de nombreux shells Bourne. Cependant, il ne s'agit pas d'un délai d'inactivité de la session de connexion ; elle ne s'applique qu'à la connectivité réseau.
MOSH_SERVER_SIGNAL_TMOUT
Si cette variable est définie sur un entier positif, elle spécifie combien de temps (en secondes) mosh-server ignorera SIGUSR1 en attendant de recevoir une mise à jour du client. Sinon, SIGUSR1 terminera toujours mosh-server. Les utilisateurs et les administrateurs peuvent mettre en œuvre des scripts pour nettoyer les sessions Mosh déconnectées. Avec cette variable définie, un utilisateur ou un administrateur peut émettre 
$ pkill -SIGUSR1 mosh-server

pour tuer les sessions déconnectées sans tuer les sessions de connexion actives.

EXEMPLE

$ mosh-server
MOSH CONNECT 60001 UAkFedSsVJs2LfMeKyQB5g
mosh-server (mosh 1.1)
[...] (avis de copyright omis)
[mosh-server détaché, pid = 20443]
