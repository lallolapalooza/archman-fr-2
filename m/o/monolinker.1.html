Paquet: mono

CIL(Linker) CIL(Linker)

NOM

Mono CIL Linker

SYNTAXE

monolinker [-o repertoire_sortie][-l ensamblages_i18n][-c ignorer | copier | lier] -x descripteur | -a assemblage | -i fichier_info ...

DESCRIPTION

monolinker est un Linker CIL. Le linker est un outil que l'on peut utiliser pour ne distribuer que l'ensemble minimal possible de fonctions nécessaires à un ensemble de programmes pour s'exécuter, par opposition aux bibliothèques complètes.

Le linker analyse le code intermédiaire (CIL) produit par chaque compilateur ciblant la plateforme Mono comme mcs, gmcs, vbnc, booc ou d'autres. Il parcourra tout le code qui lui est fourni et supprimera toutes les méthodes et classes inutilisées. Ceci est réalisé à l'aide d'une opération de marquage et de balayage sur tout le code référencé.

La sortie générée par le monolinker peut être traitée ultérieurement par l'outil mkbundle pour générer de petits exécutables natifs autonomes.

Ne pas confondre avec l'Assembly Linker (al) qui crée des assemblages à partir de manifestes, modules et fichiers de ressources.

OPTIONS

-d repertoire_recherche
Spécifie un répertoire au linker où chercher les assemblages.
-o repertoire_sortie
Spécifie le répertoire de sortie, par défaut 'output'.

Si vous spécifiez le répertoire '.', assurez-vous de ne pas écraser des assemblages importants.

-b vrai | faux
Spécifie s'il faut générer ou non des symboles de débogage, par défaut faux.
-g vrai | faux
Spécifie s'il faut générer un nouveau guid pour chaque module lié ou réutiliser celui existant, par défaut vrai.
-l ensamblages_i18n
Spécifie quoi faire des assemblages spécifiques à la région.

Mono a quelques assemblages qui contiennent tout ce qui est spécifique à une région :

I18N.CJK.dll
I18N.MidEast.dll
I18N.Other.dll
I18N.Rare.dll
I18N.West.dll

Par défaut, ils seront tous copiés dans le répertoire de sortie, mais vous pouvez spécifier ceux que vous voulez en utilisant cette commande. Le choix peut être : none, all, cjk, mideast, other, rare ou west. Vous pouvez combiner les valeurs avec une virgule.

-c action
Spécifie l'action à appliquer aux assemblages principaux.

Les assemblages principaux sont les assemblages qui appartiennent à la bibliothèque de classes de base, comme mscorlib.dll, System.dll ou System.Windows.Forms.dll.

Le linker prend en charge trois opérations sur ces assemblages, vous pouvez spécifier l'une des actions suivantes :

ignorer
Ceci demande au linker de les ignorer et de ne rien faire avec.
copier
Ceci demande au linker de les copier dans le répertoire de sortie.
lier
Ceci demande au linker d'appliquer le processus de liaison et de réduire leur taille.
-p action assemblage
Spécifie par assemblage quelle action appliquer.
-x descripteur
Utilise un descripteur XML comme source pour le linker.

Voici un exemple qui montre toutes les possibilités de ce format :

<linker>
	<assembly fullname="Library">
		<type fullname="Foo" />
		<type fullname="Bar" preserve="nothing" required="false" />
		<type fullname="Baz" preserve="fields" required="false" />
		<type fullname="Gazonk">
			<method signature="System.Void .ctor(System.String)" />
			<field signature="System.String _blah" />
			<field name="someFieldName" />
		</type>
	</assembly>
</linker>

Dans cet exemple, le linker liera les types Foo, Bar, Baz et Gazonk.

L'attribut preserve garantit que tous les champs du type Baz seront toujours liés, qu'ils soient utilisés ou non, mais que ni les champs ni les méthodes de Bar ne seront liés s'ils ne sont pas utilisés. Ne pas spécifier d'attribut preserve implique que nous préservons tout dans le type spécifié.

L'attribut required spécifie que si le type n'est pas marqué lors de l'opération de marquage, il ne sera pas lié.

Le type Gazonk sera lié, ainsi que son constructeur prenant une chaîne en paramètre, et son champ _blah.

Vous pouvez avoir plusieurs nœuds d'assemblage.

-a assemblages
Utilise un assemblage comme source pour le linker.

Le linker parcourra toutes les méthodes de l'assemblage pour ne générer que ce qui est nécessaire à l'exécution de cet assemblage.

-i fichier_info
Utilise un fichier .info xml comme source pour le linker.

Un fichier info est un fichier produit par l'outil mono-api-info. Le linker l'utilisera pour générer un assemblage qui ne contiendra que ce dont l'API publique définie dans le fichier info a besoin.

-s [StepBefore:]NomCompletEtape,AssemblageEtape[:StepAfter]

Vous pouvez demander au linker d'exécuter des étapes personnalisées en utilisant le commutateur -s. Cette commande prend le format standard NomCompletEtape,Assemblage pour localiser l'étape. Vous pouvez personnaliser sa position dans le pipeline en l'ajoutant avant une étape ou après.

Exemple :

using System;
using Mono.Linker;
using Mono.Linker.Steps;
namespace Foo {
	public class FooStep : IStep {
		public void Process (LinkContext context)
		{
			foreach (IStep step in context.Pipeline.GetSteps ()) {
				Console.WriteLine (step.GetType ().Name);
			}
		}
	}
}

Si vous compilez ceci contre monolinker en un assemblage Foo.dll, vous pouvez utiliser le commutateur -s comme suit. Pour ajouter FooStep à la fin du pipeline :

monolinker -s Foo.FooStep,Foo -a program.exe

Cette commande ajoutera FooStep après le MarkStep :

monolinker -s MarkStep:Foo.FooStep,Foo -a program.exe

Cette commande ajoutera FooStep avant le MarkStep :

monolinker -s Foo.FooStep,Foo:MarkStep -a program.exe

Cette commande ajoutera FooStep avant le MarkStep

-m ParametrePersonnalise ValeurParametre
Spécifie un paramètre pour une étape personnalisée.
