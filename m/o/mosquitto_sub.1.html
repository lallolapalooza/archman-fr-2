NOM

mosquitto_sub - un client MQTT version 5/3.1.1/3.1 pour s'abonner à des topics

SYNOPSIS

mosquitto_sub {[-h nom-hôte] [--unix chemin-socket] [-p numéro-port] [-u nom-utilisateur] [-P mot-de-passe] -t topic-message... | -L URL [-t topic-message...] } [-A adresse-liaison] [-c] [-C nombre-messages] [-d] [-D commande identifiant valeur] [-E] [-i id-client] [-I préfixe-id-client] [-k temps-keepalive] [-N] [--nodelay] [--pretty] [-q qos-message] [--random-filter chance] [--remove-retained] [-R | --retained-only] [--retain-as-published] [-S] [-T filtrer-out...] [-U topic-de-désabonnement...] [-v] [-V version-protocole] [-W délai-traitement-message] [-x intervalle-expiration-session] [--proxy url-socks] [--quiet] [--will-topic topic [--will-payload payload] [--will-qos qos] [--will-retain]] [[{--cafile fichier | --capath répertoire} [--cert fichier] [--key fichier] [--tls-version version] [--tls-alpn protocole] [--tls-engine moteur] [--keyform {pem | moteur}] [--tls-engine-kpass-sha1 kpass-sha1] [--tls-use-os-certs] [--insecure]] | [--psk clé-hex --psk-identity identité [--tls-version version]]]

mosquitto_sub [--help]

DESCRIPTION

mosquitto_sub est un client MQTT version 5/3.1.1 simple qui s'abonnera à des topics et affichera les messages qu'il reçoit.

En plus de s'abonner à des topics, mosquitto_sub peut filtrer les messages reçus afin qu'ils ne soient pas affichés (voir l'option -T) ou se désabonner de topics (voir l'option -U). Le désabonnement de topics est utile pour les clients se connectant avec une session propre définie à faux.

CONNEXIONS CHIFFRÉES

mosquitto_sub prend en charge les connexions chiffrées TLS. Il est fortement recommandé d'utiliser une connexion chiffrée pour tout ce qui dépasse une configuration très basique.

Pour activer les connexions TLS lors de l'utilisation de certificats x509, l'une des options --cafile ou --capath peut être fournie.

Alternativement, si l'option -p 8883 est utilisée, les certificats fournis par l'OS seront chargés et ni --cafile ni --capath ne seront nécessaires.

Pour activer les connexions TLS lors de l'utilisation de TLS-PSK, vous devez utiliser les options --psk et --psk-identity.

OPTIONS

Les options ci-dessous peuvent être données en ligne de commande, mais peuvent également être placées dans un fichier de configuration situé à $XDG_CONFIG_HOME/mosquitto_sub ou $HOME/.config/mosquitto_sub avec une paire -option valeur par ligne. Les valeurs dans le fichier de configuration seront utilisées par défaut et pourront être remplacées en utilisant la ligne de commande. Les exceptions sont -t et -T, qui si elles sont données dans le fichier de configuration ne seront pas remplacées. Notez également que certaines options ne peuvent actuellement pas être annulées, par exemple -S. Les lignes du fichier de configuration dont le premier caractère est # sont traitées comme des commentaires et ne sont pas traitées davantage.

-A

Lier la connexion sortante à une adresse IP/nom d'hôte local. Utilisez cet argument si vous avez besoin de restreindre la communication réseau à une interface particulière.

-c, --disable-clean-session

Désactiver la 'session propre' / activer le mode client persistant. Lorsque cet argument est utilisé, le broker sera invité à ne pas nettoyer les sessions existantes pour le même id client lors de la connexion du client, et les sessions n'expireront jamais lorsque le client se déconnecte. Les clients MQTT v5 peuvent changer leur intervalle d'expiration de session avec l'argument -x.

Lorsqu'une session est conservée sur le broker, les abonnements du client seront maintenus après sa déconnexion, ainsi que les messages ultérieurs de QoS 1 et QoS 2 qui arrivent. Lorsque le client se reconnecte et ne nettoie pas la session, il recevra tous les messages mis en file d'attente.

Si vous utilisez cette option, l'id client doit être défini manuellement avec --id

--cafile

Définir le chemin vers un fichier contenant des certificats CA encodés en PEM qui sont approuvés. Utilisé pour activer la communication SSL.

Voir aussi --capath

--capath

Définir le chemin vers un répertoire contenant des certificats CA encodés en PEM qui sont approuvés. Utilisé pour activer la communication SSL.

Pour que --capath fonctionne correctement, les fichiers de certificat doivent avoir ".crt" comme extension de fichier et vous devez exécuter "openssl rehash <chemin vers capath>" chaque fois que vous ajoutez/supprimez un certificat.

Voir aussi --cafile

--cert

Définir le chemin vers un fichier contenant un certificat encodé en PEM pour ce client, si requis par le serveur.

Voir aussi --key et la section Connexions Chiffrées.

--ciphers

Une liste de chiffrements TLS compatibles avec openssl à prendre en charge par le client. Voir ciphers(1) pour plus d'informations.

-C

Déconnecter et quitter le programme immédiatement après que le nombre de messages donné a été reçu. Ceci peut être utile dans les scripts shell où une seule valeur d'état est requise, par exemple.

Combiner avec -R pour afficher uniquement le premier ensemble de messages frais (c'est-à-dire qui n'ont pas l'indicateur conservé défini), ou avec -T pour filtrer les topics qui sont traités.

-d, --debug

Activer les messages de débogage.

-D, --property

Utiliser une propriété MQTT v5 avec cette publication. Si vous utilisez cette option, le client sera configuré pour être un client MQTT v5. Cette option a deux formes:

-D commande identifiant valeur

-D commande identifiant nom valeur

commande est l'identifiant de la commande/paquet MQTT et peut être l'un de CONNECT, PUBACK, PUBREC, PUBCOMP, SUBSCRIBE, UNSUBSCRIBE, DISCONNECT, AUTH, ou WILL. Les propriétés disponibles pour chaque commande sont listées dans la section Propriétés.

identifiant est le nom de la propriété à ajouter. Ceci est tel que décrit dans la spécification, mais avec '-' comme séparateur de mot. Par exemple : payload-format-indicator. Plus de détails se trouvent dans la section Propriétés.

valeur est la valeur de la propriété à ajouter, avec un type de données spécifique à la propriété.

nom n'est utilisé que pour la propriété user-property comme première des deux chaînes de la paire de chaînes. Dans ce cas, valeur est la seconde des chaînes de la paire.

-E

Si cette option est donnée, mosquitto_sub quittera immédiatement une fois que tous ses abonnements auront été confirmés par le broker. En conjonction avec -c, cela permet d'initialiser une session client durable sur le broker pour une utilisation future sans nécessiter la réception de messages.

-F

Spécifier le format d'affichage de la sortie. Cette option vous permet de choisir quelles informations de chaque message sont affichées à l'écran. Voir la section Format de Sortie ci-dessous pour tous les détails.

Cette option remplace l'option -v, mais ne remplace pas l'option -N.

--help

Afficher les informations d'utilisation.

-h, --host

Spécifier l'hôte auquel se connecter. Par défaut : localhost.

-i, --id

L'identifiant à utiliser pour ce client. S'il n'est pas fourni, un identifiant client sera généré en fonction de la version MQTT utilisée. Pour les versions v3.1.1/v3.1, le client génère un identifiant client sous la forme mosq-XXXXXX.
XXXXXXXXXXXX, où les X sont remplacés par des caractères alphanumériques aléatoires. Pour la v5.0, le client envoie un ID client de longueur zéro, et le serveur générera un ID client pour le client.

Cette option ne peut pas être utilisée en même temps que l'argument --id-prefix.

-I, --id-prefix

Fournit un préfixe à partir duquel l'ID client sera construit en ajoutant l'ID de processus du client. Ceci est utile lorsque le broker utilise l'option clientid_prefixes. Ne peut pas être utilisé en même temps que l'argument --id.

--insecure

Lors de l'utilisation du chiffrement basé sur certificat, cette option désactive la vérification du nom d'hôte du serveur dans le certificat du serveur. Cela peut être utile lors des tests de configurations initiales du serveur, mais permet à un tiers malveillant d'usurper l'identité de votre serveur par le biais de l'usurpation DNS, par exemple. Utilisez cette option *uniquement* pour les tests. Si vous devez recourir à cette option dans un environnement de production, votre configuration est défaillante et il est inutile d'utiliser le chiffrement.

-k, --keepalive

Le nombre de secondes entre l'envoi de commandes PING au broker afin de lui signaler que nous sommes toujours connectés et fonctionnels. Par défaut, 60 secondes.

--key

Définit le chemin d'un fichier contenant une clé privée codée en PEM pour ce client, si requis par le serveur.

Voir aussi --cert et la section Connexions chiffrées.

--keyform

Spécifie le type de clé privée utilisée lors des connexions TLS. Cela peut être "pem" ou "engine". Ce paramètre est utile lorsqu'un module TPM est utilisé et que la clé privée a été créée avec lui. Par défaut, "pem", ce qui signifie que des fichiers de clés privées normaux sont utilisés.

Voir aussi --tls-engine.

-L, --url

Spécifie l'utilisateur, le mot de passe, le nom d'hôte, le port et le sujet en une seule fois sous forme d'URL. L'URL doit être de la forme : mqtt(s)://[nom_utilisateur[:mot_de_passe]@]hote[:port]/sujet

Si le schéma est mqtt://, le port est par défaut 1883. Si le schéma est mqtts://, le port est par défaut 8883.

-N

Ne pas ajouter de caractère de fin de ligne à la charge utile lors de l'impression. Ceci permet le streaming des données de charge utile de plusieurs messages directement vers une autre application sans modification. N'a de sens que lorsque -v n'est pas utilisé.

--nodelay

Désactive l'algorithme de Nagle pour le socket. Cela signifie que la latence des messages envoyés est réduite, ce qui est particulièrement perceptible pour les messages petits et relativement peu fréquents. L'utilisation de cette option peut entraîner l'envoi de plus de paquets que nécessaire normalement.

-p, --port

Se connecter au port spécifié. Si non spécifié, le port par défaut de 1883 pour MQTT simple ou 8883 pour MQTT sur TLS sera utilisé.

-P, --pw

Fournit un mot de passe à utiliser pour l'authentification auprès du broker. L'utilisation de cet argument sans spécifier également un nom d'utilisateur est invalide lors de l'utilisation de MQTT v3.1 ou v3.1.1. Voir aussi l'option --username.

--pretty

Lors de l'utilisation du format de sortie JSON %j ou %J, le comportement par défaut est d'imprimer de manière non formatée. Spécifier --pretty imprime les messages dans un format plus joli et plus lisible par l'homme.

--proxy

Spécifie un proxy SOCKS5 pour se connecter. Les types d'authentification "None" et "username" sont pris en charge. L'URL socks-url doit être de la forme socks5h://[nom_utilisateur[:mot_de_passe]@]hote[:port]. Le préfixe de protocole socks5h signifie que les noms d'hôte sont résolus par le proxy. Les symboles %25, %3A et %40 sont décodés en URL en %, : et @ respectivement, s'ils sont présents dans le nom d'utilisateur ou le mot de passe.

Si le nom d'utilisateur n'est pas donné, aucune authentification n'est tentée. Si le port n'est pas donné, le port par défaut 1080 est utilisé.

D'autres versions de SOCKS pourraient être disponibles à l'avenir, en fonction de la demande, et utiliseront différents préfixes de protocole comme décrit dans curl(1).

--psk

Fournit la clé pré-partagée (hexadécimale, sans le préfixe 0x) correspondant à celle utilisée sur le broker pour activer le support du chiffrement TLS-PSK. --psk-identity doit également être fourni pour activer TLS-PSK.

--psk-identity

L'identité du client à utiliser avec le support TLS-PSK. Ceci peut être utilisé à la place d'un nom d'utilisateur si le broker est configuré pour cela.

-q, --qos

Spécifie la qualité de service souhaitée pour les messages entrants, de 0, 1 et 2. Par défaut, 0. Voir mqtt(7) pour plus d'informations sur le QoS.

Le QoS est identique pour tous les sujets auxquels on s'abonne dans une seule instance de mosquitto_sub.

--quiet

Si cet argument est donné, aucune erreur d'exécution ne sera imprimée. Ceci exclut les messages d'erreur donnés en cas d'entrée utilisateur invalide (par exemple, utiliser --port sans port).

-R

Si cet argument est donné, les messages reçus qui ont le bit retain défini ne seront pas imprimés. Les messages avec retain défini sont "obsolètes", dans le sens où l'on ne sait pas quand ils ont été publiés à l'origine. Lors de l'abonnement à un sujet wildcard, il peut y avoir un grand nombre de messages conservés. Cet argument supprime leur affichage.

--random-filter

Cette option peut être utilisée pour réduire la proportion de messages que mosquitto_sub imprime. Le comportement par défaut est d'imprimer tous les messages entrants. Définir la *chance* à une valeur flottante entre 0.1 et 100.0 garantira qu'en moyenne, ce pourcentage de messages sera imprimé.

--remove-retained

Si cet argument est donné, lorsque mosquitto_sub reçoit un message avec le bit retained défini, il enverra un message au broker pour supprimer ce message conservé. Ceci s'applique à tous les messages reçus, sauf ceux qui sont filtrés par l'option -T. Cette option prend toujours effet même si -R est utilisé. Voir aussi les options --retain-as-published et --retained-only.

Exemple 1. Supprimer tous les messages conservés sur le serveur, en supposant que nous avons les droits pour le faire, puis quitter :

mosquitto_sub -t '#' --remove-retained --retained-only

Exemple 2. Supprimer un arbre entier, à l'exception d'un seul sujet :

mosquitto_sub -t 'bbc/#' -T bbc/bbc1 --remove-retained

--retained-only

Si cet argument est donné, seuls les messages reçus qui ont le bit retain défini seront imprimés. Les messages avec retain défini sont "obsolètes", dans le sens où l'on ne sait pas quand ils ont été publiés à l'origine. Avec cet argument utilisé, la réception du premier message non obsolète entraînera la sortie du client. Voir aussi l'option --retain-as-published.

--retain-as-published

Si cet argument est donné, les abonnements auront l'option "retain as published" définie. Cela signifie que le drapeau retain sur un message entrant sera exactement tel que défini par le client qui publie, plutôt que d'indiquer si le message est récent/obsolète.

Cette option n'est pas valide pour les clients MQTT v3.1/v3.1.1.

-S

Utilise les recherches SRV pour déterminer quel hôte contacter. Effectue des recherches pour _mqtt._tcp.<hôte> lorsqu'il est utilisé conjointement avec -h, sinon utilise _mqtt._tcp.<domaine dns local>.

-t, --topic

Le sujet MQTT auquel s'abonner. Voir mqtt(7) pour plus d'informations sur les sujets MQTT.

Cette option peut être répétée pour s'abonner à plusieurs sujets.

-T, --filter-out

Supprime l'impression des sujets qui correspondent au filtre. Cela permet de s'abonner à un sujet wildcard et de n'imprimer qu'un sous-ensemble de la hiérarchie wildcard.

Par exemple, s'abonner à l'arbre BBC, mais supprimer la sortie de Radio 3 :

•mosquitto_sub -t bbc/# -T bbc/radio3

Cette option peut être répétée pour filtrer plusieurs sujets ou arbres de sujets.

--tls-alpn

Fournit un protocole à utiliser lors de la connexion à un broker qui a plusieurs protocoles disponibles sur un seul port, par exemple MQTT et WebSockets.

--tls-engine

Un identifiant d'un moteur openssl valide. Ceux-ci peuvent être listés avec la commande openssl engine.

Voir aussi --keyform.

--tls-engine-kpass-sha1

SHA1 du mot de passe de la clé privée lors de l'utilisation d'un moteur TLS. Certains moteurs TLS, comme le moteur TPM, peuvent nécessiter l'utilisation d'un mot de passe pour y accéder. Cette option permet de fournir directement un hachage SHA1 codé en hexadécimal du mot de passe au moteur, au lieu que l'utilisateur soit invité à entrer le mot de passe.

Voir aussi --tls-engine.

--tls-use-os-certs

Si utilisé, cela chargera et fera confiance aux certificats CA fournis par le système d'exploitation. Ceci peut être utilisé en conjonction avec --cafile et --capath et peut être utilisé seul pour activer le mode TLS. Ceci sera défini par défaut si -L mqtts://... est utilisé, ou si le port est 8883 et qu'aucune autre option de certificat n'est utilisée.

--tls-version

Choisit quelle version du protocole TLS utiliser lors de la communication avec le broker. Les options valides sont tlsv1.3, tlsv1.2 et tlsv1.1. La valeur par défaut est tlsv1.2. Doit correspondre à la version du protocole utilisée par le broker.

-u, --username

Fournit un nom d'utilisateur à utiliser pour l'authentification auprès du broker. Voir aussi l'argument --pw.

--unix

Se connecte à un broker via un socket de domaine Unix local au lieu d'un socket TCP. Ceci remplace -h et -L. Par exemple : mosquitto_pub --unix /tmp/mosquitto.sock ...

Voir l'option socket_domain dans mosquitto.conf(5) pour configurer Mosquitto pour qu'il écoute sur un socket Unix.

-U, --unsubscribe

Un sujet auquel on se désabonnera. Ceci peut être utilisé seul ou en conjonction avec l'option --topic et n'a de sens que lorsqu'il est utilisé en conjonction avec --clean-session.

Si utilisé avec --topic, les abonnements seront traités avant les désabonnements.

Notez qu'il n'est possible de se désabonner que des abonnements qui ont été précédemment effectués. Il n'est pas possible de faire des "trous" dans les abonnements wildcard. Par exemple, s'abonner à sensors/# puis se désabonner de sensors/+/temperature

/b> comme illustré ci-dessous donnera toujours lieu à la remise des messages correspondant à sensors/+/temperature au client.

•mosquitto_sub -t sensors/# -U sensors/+/temperature -v

Notez également que, étant donné que les messages conservés sont publiés par le courtier à la réception d'une commande SUBSCRIBE, l'abonnement et le désabonnement du même topic peuvent entraîner la réception de messages par le client.

Cette option peut être répétée pour se désabonner de plusieurs topics.

-v, --verbose

Imprime les messages reçus en mode verbeux. Avec cet argument, les messages seront imprimés sous la forme "topic payload". Lorsque cet argument n'est pas donné, les messages sont imprimés sous la forme "payload".

-V, --protocol-version

Spécifie la version du protocole MQTT à utiliser lors de la connexion au courtier distant. Peut être 5, 311, 31, ou les versions plus verbeuses mqttv5, mqttv311, ou mqttv31. La valeur par défaut est 311.

-W

Fournit un délai d'attente sous forme d'un nombre entier de secondes. mosquitto_sub cessera de traiter les messages et se déconnectera après que ce nombre de secondes se soit écoulé. Le délai d'attente commence juste après que le client s'est connecté au courtier.

--will-payload

Spécifie un message qui sera stocké par le courtier et envoyé si ce client se déconnecte de manière inattendue. Ceci doit être utilisé conjointement avec --will-topic.

--will-qos

Le niveau de QoS à utiliser pour le Will. Par défaut à 0. Ceci doit être utilisé conjointement avec --will-topic.

--will-retain

Si spécifié, si le client se déconnecte de manière inattendue, le message envoyé sera traité comme un message conservé. Ceci doit être utilisé conjointement avec --will-topic.

--will-topic

Le topic sur lequel envoyer un Will, dans le cas où le client se déconnecte de manière inattendue.

-x

Définit la propriété session-expiry-interval sur le paquet CONNECT. S'applique uniquement aux clients MQTT v5. Défini sur 0-4294967294 pour spécifier que la session expirera dans ce nombre de secondes après que le client se soit déconnecté, ou utilisez -1, 4294967295, ou ∞ pour une session qui n'expire pas. Par défaut à -1 si -c est également donné, ou 0 si -c n'est pas donné.

Si la session est configurée pour ne jamais expirer, que ce soit avec -x ou -c, alors un identifiant client doit être fourni.

FORMAT DE SORTIE

Il existe trois façons de formater la sortie de mosquitto_sub. Dans tous les cas, un caractère de nouvelle ligne est ajouté pour chaque message reçu, sauf si l'argument -N est passé à mosquitto_sub.

La sortie de type "payload seul" est le format de sortie par défaut et imprimera la charge utile telle qu'elle est reçue.

Le mode verbeux est activé avec -v et imprime le topic du message et la charge utile, séparés par un espace.

La dernière option est la sortie formatée, qui permet à l'utilisateur de définir un format de sortie personnalisé. Le comportement est contrôlé par l'option -F format-string. La chaîne de format est une chaîne de texte libre où les séquences interprétées sont remplacées par différents paramètres. Les séquences interprétées disponibles sont décrites ci-dessous.

Trois caractères sont utilisés pour commencer une séquence interprétée : %, @ et \. Les séquences commençant par % sont soit des paramètres liés au message MQTT imprimé, soit des séquences d'aide pour éviter d'avoir à taper de longues chaînes de format de date, par exemple. Les séquences commençant par @ sont passées à la fonction strftime(3) (avec le @ remplacé par un % - notez que seul le caractère immédiatement après le @ est passé à strftime). Cela permet la construction d'une grande variété de sorties basées sur le temps. Les options de sortie pour strftime varient d'une plateforme à l'autre, veuillez donc vérifier ce qui est disponible pour votre plateforme. mosquitto_sub fournit une extension à strftime qui est @N, qui peut être utilisée pour obtenir le nombre de nanosecondes écoulées dans la seconde courante. La résolution de cette option varie en fonction de la plateforme. Le dernier caractère de séquence est \, qui est utilisé pour saisir certains caractères qui seraient autrement difficiles à saisir.

Caractères de drapeau

Les paramètres %A, %C, %E, %F, %I, %l, %m, %p, %R, %S, %t, %x, et %X peuvent avoir des drapeaux optionnels immédiatement après le caractère %.

0

La valeur doit être complétée par des zéros. Ceci s'applique aux paramètres %A, %E, %F, %l, %m, %S, %X, et %x. Il sera ignoré pour les autres paramètres. S'il est utilisé avec le drapeau -, le drapeau 0 sera ignoré.

-

La valeur sera alignée à gauche sur la largeur du champ, complétée par des blancs. Par défaut, l'alignement est à droite, avec un remplissage par 0 ou par des blancs.

Largeur du champ

Certains des paramètres liés à MQTT peuvent être formatés avec une option pour définir leur largeur de champ, de manière similaire aux formats d'impression réguliers (printf), c'est-à-dire que cela définit la largeur minimale lors de l'impression de ce paramètre. Ceci s'applique aux options %A, %C, %E, %F, %I, %l, %m, %p, %R, %S, %t, %x, %X.

Par exemple, %10t définirait la largeur minimale du champ de topic à 10 caractères.

Largeur maximale

Certains des paramètres liés à MQTT peuvent être formatés avec une option pour définir une largeur de champ maximale, de manière similaire aux formats d'impression réguliers (printf). Ceci s'applique aux options %C, %I, %R, %t.

Par exemple, %10.10t définirait la largeur minimale du champ de topic à 10 caractères, et la largeur maximale du topic à 10 caractères, c'est-à-dire que le champ sera toujours exactement long de 10 caractères.

Paramètres liés à MQTT

•%% un signe %.
•%A l'alias de topic MQTT v5, s'il est présent.
•%C la propriété content-type MQTT v5, si elle est présente.
•%D la propriété correlation-data MQTT v5, si elle est présente. Notez que cette propriété est spécifiée comme des données binaires, elle peut donc produire des caractères non imprimables.
•%E la propriété message-expiry-interval MQTT v5, si elle est présente.
•%F l'indicateur de format de charge utile MQTT v5, si il est présent.
•%l la longueur de la charge utile en octets.
•%m l'identifiant du message (uniquement pertinent pour les messages avec QoS>0).
•%P la propriété user-property MQTT v5, si elle est présente. Elle sera imprimée sous la forme clé:valeur. Il est possible qu'un nombre quelconque de propriétés utilisateur soit attaché à un message, et qu'il y ait des clés dupliquées.
•%p les octets bruts de la charge utile (peut produire des caractères non imprimables selon la charge utile).
•%q le niveau de QoS du message.
•%R la propriété response-topic MQTT v5, si elle est présente.
•%r le drapeau retained (conservé) pour le message.
•%S la propriété subscription-identifier MQTT v5, si elle est présente.
•%t le topic du message.
•%x la charge utile avec chaque octet sous forme hexadécimale (minuscules).
•%X la charge utile avec chaque octet sous forme hexadécimale (majuscules).

Aides

•%I date et heure au format ISO-8601, par exemple 2016-08-10T09:47:38+0100
•%j sortie JSON des paramètres du message et de l'horodatage, avec une charge utile entre guillemets et échappée. Par exemple {"tst":"2020-05-06T22:12:00.000000+0100","topic":"greeting","qos":0,"retain":0,"payload":"hello world"}
•%J sortie JSON des paramètres du message et de l'horodatage, avec une charge utile non mise entre guillemets et non échappée - cela signifie que la charge utile doit elle-même être du JSON valide. Par exemple : {"tst":"2020-05-06T22:12:00.000000+0100","topic":"foo","qos":0,"retain":0,"payload":{"temperature":27.0,"humidity":57}}.

Si la charge utile n'est pas du JSON valide, alors le message d'erreur "Error: Message payload is not valid JSON on topic <topic>" sera imprimé sur stderr.

•%U horodatage Unix avec nanosecondes, par exemple 1470818943.786368637

Paramètres liés au temps

•@@ un symbole @ littéral.
•@X passe le caractère représenté par X à la fonction strftime sous la forme %X. Les options prises en charge dépendent de la plateforme.
•@N le nombre de nanosecondes écoulées dans la seconde courante, avec une résolution temporelle variable selon la plateforme.

Caractères d'échappement

•\\ un caractère \ littéral.
•\0 un caractère nul. Peut être utilisé pour séparer différents paramètres qui peuvent contenir des espaces (par exemple, topic, payload) afin que le traitement avec des outils tels que xargs(1) soit plus facile.
•\a alerte/sonnerie.
•\e la séquence d'échappement, qui peut être utilisée avec des codes de couleur ANSI pour fournir une sortie colorée, par exemple.
•\n fin de ligne.
•\r retour chariot.
•\t tabulation horizontale.
•\v tabulation verticale.

WILLS

mosquitto_sub peut enregistrer un message auprès du courtier qui sera envoyé s'il se déconnecte de manière inattendue. Voir mqtt(7) pour plus d'informations.

Le minimum requis pour cela est d'utiliser --will-topic pour spécifier le topic sur lequel le will doit être envoyé. Cela entraînera un message sans conservation, de longueur nulle et avec QoS 0.

Utilisez --will-retain, --will-payload et --will-qos arguments pour modifier les autres paramètres de will.

STATUT DE SORTIE

mosquitto_sub retourne zéro en cas de succès, ou une valeur non nulle en cas d'erreur. Si la connexion est refusée par le broker au niveau MQTT, alors le code de sortie est le code de raison CONNACK. Si une autre erreur se produit, le code de sortie est une valeur de retour de libmosquitto.

Codes CONNACK MQTT v3.1.1 :

•0 Succès
•1 Connexion refusée : mauvaise version de protocole
•2 Connexion refusée : identifiant rejeté
•3 Connexion refusée : serveur indisponible
•4 Connexion refusée : mauvais nom d'utilisateur/mot de passe
•5 Connexion refusée : non autorisé

•0 Succès
•128 Erreur non spécifiée
•129 Paquet malformé
•130 Erreur de protocole
•131 Erreur spécifique à l'implémentation
•132 Version de protocole non prise en charge
•133 ID client invalide
•134 Nom d'utilisateur ou mot de passe invalide
•135 Non autorisé
•136 Serveur indisponible
•137 Serveur occupé
•138 Bannière
•139 Arrêt du serveur
•140 Mauvaise méthode d'authentification
•141 Dépassement du délai de garde

EXEMPLES

Notez qu'il s'agit bien d'exemples - les souscriptions fonctionneront si vous les exécutez telles quelles, mais il doit y avoir quelque chose qui publie des messages sur ces sujets pour que vous receviez quoi que ce soit.

S'abonner aux informations de température sur localhost avec QoS 1 :

•mosquitto_sub -t sensors/temperature -q 1

S'abonner aux mises à jour de température des disques durs sur plusieurs machines/disques durs. Ceci suppose que chaque machine publie la température de son disque dur sur sensors/machines/HOSTNAME/temperature/HD_NAME.

•mosquitto_sub -t sensors/machines/+/temperature/+

S'abonner à tous les messages d'état du broker :

•mosquitto_sub -v -t \$SYS/#

Spécifier le format de sortie comme "date ISO-8601 : sujet : charge utile en hexadécimal"

•mosquitto_sub -F '@Y-@m-@dT@H:@M:@S@z : %t : %x' -t '#'

Spécifier le format de sortie comme "secondes depuis l'époque.nanosecondes : indicateur de rétention : qos : mid : longueur de la charge utile"

•mosquitto_sub -F '%@s.@N : %r : %q : %m : %l' -q 2 -t '#'

Sortie du sujet et de la charge utile, mais avec couleur lorsque cela est pris en charge.

•mosquitto_sub -F '\e[92m%t \e[96m%p\e[0m' -q 2 -t '#'
