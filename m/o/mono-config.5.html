NOM

mono-config - Configuration des fichiers du runtime Mono

DESCRIPTION

Le runtime Mono chargera les données de configuration à partir du fichier d'installation /etc/mono/config, de ~/.mono/config ou du fichier pointé par la variable d'environnement MONO_CONFIG.

Pour chaque assembly chargé, un fichier de configuration nommé : /chemin/vers/l'assembly.exe.config sera également chargé, ainsi que le fichier ~/.mono/assemblies/ASSEMBLY/ASSEMBLY.EXT.config.

Ce fichier contrôle le comportement du runtime.

Ce fichier contient un fichier de type XML avec diverses sections, toutes contenues à l'intérieur d'une section (Il utilise en fait GMarkup pour analyser le fichier).

Cette page décrit les extensions spécifiques à Unix et à Mono du fichier de configuration ; pour plus de détails, consultez la page web http://www.mono-project.com/Config.

DIRECTIVE <dllmap>

Vous utilisez la directive dllmap pour mapper des bibliothèques partagées référencées par P/Invoke dans vos assemblys à une autre bibliothèque partagée.

Ceci est typiquement utilisé pour mapper des bibliothèques Windows à des noms de bibliothèques Unix. L'élément dllmap prend deux attributs :

dll
Ceci doit être la même chaîne que celle utilisée dans l'attribut DllImport, facultativement préfixée par "i:" pour indiquer que la chaîne doit être comparée sans tenir compte de la casse.
target
Ceci doit être le nom de la bibliothèque où la fonction peut être trouvée : ce nom doit être utilisable avec les routines de chargement de bibliothèques natives de la plateforme (dlopen, etc.), vous pourriez donc vouloir consulter également les pages de manuel correspondantes.

DIRECTIVE <dllentry>

Cette directive peut être utilisée pour mapper une paire dll/fonction spécifique à une autre bibliothèque et également à un autre nom de fonction. Elle doit apparaître à l'intérieur d'un élément dllmap avec uniquement l'attribut dll spécifié.

L'élément dllentry prend 3 attributs :

dll
C'est la bibliothèque cible, où la fonction peut être trouvée.
name
C'est le nom de la fonction tel qu'il apparaît dans les métadonnées : c'est le nom de la méthode P/Invoke.
target
C'est le nom de la fonction à rechercher au lieu du nom spécifié dans la méthode P/Invoke.

Mappage basé sur le système d'exploitation et le CPU

Les éléments dllmap et dllentry autorisent les deux attributs suivants, ce qui facilite l'utilisation d'un seul fichier de configuration et la prise en charge de plusieurs systèmes d'exploitation et architectures avec des exigences de mappage différentes :

os
C'est le nom du système d'exploitation pour lequel le mappage doit être appliqué. Les valeurs autorisées sont : linux, osx, solaris, freebsd, openbsd, netbsd, windows, aix, hpux.
cpu
C'est le nom de l'architecture pour laquelle le mappage doit être appliqué. Les valeurs autorisées sont : x86, x86-64, sparc, ppc, s390, s390x, arm, mips, alpha, hppa, ia64.
wordsize
C'est la taille des registres sur l'architecture cible, elle peut être soit 32 soit 64.

La valeur de l'attribut pour les deux attributs peut être une liste séparée par des virgules des valeurs autorisées. De plus, le premier caractère peut être un '!' pour inverser le sens. Une valeur d'attribut telle que "!windows,osx", par exemple, signifierait que l'entrée est prise en compte sur tous les systèmes d'exploitation, à l'exception de Windows et OS X. Aucun espace n'est autorisé dans aucune partie de la valeur.

Notez que les entrées ultérieures remplaceront les entrées définies précédemment dans le fichier.

EXEMPLES

L'exemple suivant mappe les références à la bibliothèque partagée `cygwin1.dll' au fichier `libc.so.6'.

<configuration>
	<dllmap dll="i:cygwin1.dll" target="libc.so.6"/>
</configuration>

Le nom de la bibliothèque dans l'attribut DllImport est autorisé à être dans n'importe quelle variante de casse, comme les exemples suivants :

	[DllImport ("cygwin1.dll")]
	[DllImport ("Cygwin1.dll")]
	[DllImport ("cygwiN1.Dll")]

Ceci mappe la méthode C# suivante :

[DllImport ("libc")]
static extern void somefunction ();

à differentfunction dans libdifferent.so, mais à la même fonction dans la bibliothèque libanother.so lors de l'exécution sous les systèmes d'exploitation Solaris et FreeBSD.

<configuration>
	<dllmap dll="libc">
		<dllentry dll="libdifferent.so" name="somefunction" target="differentfunction" />
		<dllentry os="solaris,freebsd" dll="libanother.so" name="somefunction" target="differentfunction" />
	</dllmap>
</configuration>
