move_pages(2) Manuel des appels système move_pages(2)

NOM

move_pages - déplacer des pages individuelles d'un processus vers un autre nœud

BIBLIOTHÉQUE

Bibliothèque de politiques NUMA (Non-Uniform Memory Access) (libnuma, -lnuma)

SYNOPIS

#include <numaif.h>
long move_pages(int pid, unsigned long count, void *pages[count],
                const int nodes[count], int status[count],
                int flags);

DESCRIPTION

move_pages() déplace les pages spécifiées du processus pid vers les nœuds mémoire spécifiés par nodes. Le résultat du déplacement est reflété dans status. Les flags indiquent les contraintes sur les pages à déplacer.

pid est l'identifiant du processus dont les pages doivent être déplacées. Si pid est 0, alors move_pages() déplace les pages du processus appelant.

Pour déplacer des pages dans un autre processus, les privilèges suivants sont requis :

•
Jusqu'à Linux 4.12 inclus : l'appelant doit être privilégié (CAP_SYS_NICE) ou l'ID utilisateur réel ou effectif du processus appelant doit correspondre à l'ID utilisateur réel ou de jeu sauvegardé du processus cible.
•
Les anciennes règles permettaient à l'appelant de découvrir divers choix d'adresses virtuelles faits par le noyau, ce qui pouvait conduire à la défaite de la randomisation de la disposition de l'espace d'adressage pour un processus appartenant au même UID que l'appelant. Les règles ont été modifiées à partir de Linux 4.13. Depuis Linux 4.13, la permission est régie par une vérification du mode d'accès ptrace PTRACE_MODE_READ_REALCREDS par rapport au processus cible ; voir ptrace(2).

count est le nombre de pages à déplacer. Il définit la taille des trois tableaux pages, nodes et status.

pages est un tableau de pointeurs vers les pages qui doivent être déplacées. Ce sont des pointeurs qui doivent être alignés sur les frontières de page. Les adresses sont spécifiées telles que vues par le processus spécifié par pid.

nodes est un tableau d'entiers qui spécifient l'emplacement souhaité pour chaque page. Chaque élément du tableau est un numéro de nœud. nodes peut également être NULL, auquel cas move_pages() ne déplace aucune page mais renverra plutôt le nœud où réside actuellement chaque page, dans le tableau status. L'obtention du statut de chaque page peut être nécessaire pour identifier les pages qui doivent être déplacées.

status est un tableau d'entiers qui renvoie le statut de chaque page. Le tableau ne contient des valeurs valides que si move_pages() n'a pas renvoyé d'erreur. La pré-initialisation du tableau à une valeur qui ne peut pas représenter un nœud numa réel ou une erreur valide du tableau status pourrait aider à identifier les pages qui ont été migrées.

flags spécifie quels types de pages déplacer. MPOL_MF_MOVE signifie que seules les pages utilisées exclusivement par le processus doivent être déplacées. MPOL_MF_MOVE_ALL signifie que les pages partagées entre plusieurs processus peuvent également être déplacées. Le processus doit être privilégié (CAP_SYS_NICE) pour utiliser MPOL_MF_MOVE_ALL.

États de page dans le tableau status

Les valeurs suivantes peuvent être renvoyées dans chaque élément du tableau status.

0..MAX_NUMNODES
Identifie le nœud sur lequel la page réside.
-EACCES
La page est mappée par plusieurs processus et ne peut être déplacée que si MPOL_MF_MOVE_ALL est spécifié.
-EBUSY
La page est actuellement occupée et ne peut pas être déplacée. Réessayez plus tard. Cela se produit si une page subit des E/S ou si un autre sous-système du noyau détient une référence à la page.
-EFAULT
Ceci est une page zéro ou la zone mémoire n'est pas mappée par le processus.
-EIO
Impossible d'écrire une page. La page doit être écrite pour être déplacée car la page est sale et le système de fichiers ne fournit pas de fonction de migration qui permettrait le déplacement des pages sales.
-EINVAL
Une page sale ne peut pas être déplacée. Le système de fichiers ne fournit pas de fonction de migration et n'a aucune capacité d'écrire des pages.
-ENOENT
La page n'est pas présente.
-ENOMEM
Impossible d'allouer de la mémoire sur le nœud cible.

VALEUR RENVOYÉE

En cas de succès, move_pages() renvoie zéro. En cas d'erreur, elle renvoie -1 et définit errno pour indiquer l'erreur. Si une valeur positive est renvoyée, il s'agit du nombre de pages non migrées.

ERREURS

Valeur positive
Le nombre de pages non migrées si elles résultaient de raisons non fatales (depuis Linux 4.17).
E2BIG
Trop de pages à déplacer. Depuis Linux 2.6.29, le noyau ne génère plus cette erreur.
EACCES
Un des nœuds cibles n'est pas autorisé par le cpuset actuel.
EFAULT
Le tableau de paramètres n'a pas pu être accédé.
EINVAL
Des flags autres que MPOL_MF_MOVE et MPOL_MF_MOVE_ALL ont été spécifiés ou une tentative a été faite pour migrer des pages d'un thread du noyau.
ENODEV
Un des nœuds cibles n'est pas en ligne.
EPERM
L'appelant a spécifié MPOL_MF_MOVE_ALL sans privilèges suffisants (CAP_SYS_NICE). Ou, l'appelant a tenté de déplacer des pages d'un processus appartenant à un autre utilisateur mais n'avait pas les privilèges pour le faire (CAP_SYS_NICE).
ESRCH
Le processus n'existe pas.

NORMES

Linux.

HISTORIQUE

Linux 2.6.18.

NOTES

Pour des informations sur le support de la bibliothèque, voir numa(7).

Utilisez get_mempolicy(2) avec le flag MPOL_F_MEMS_ALLOWED pour obtenir l'ensemble des nœuds autorisés par le cpuset actuel. Notez que cette information est susceptible de changer à tout moment par reconfiguration manuelle ou automatique du cpuset.

L'utilisation de cette fonction peut entraîner des pages dont l'emplacement (nœud) viole la politique mémoire établie pour les adresses spécifiées (Voir mbind(2)) et/ou le processus spécifié (Voir set_mempolicy(2)). Autrement dit, la politique mémoire ne contraint pas les nœuds de destination utilisés par move_pages().

L'en-tête <numaif.h> n'est pas inclus avec glibc, mais nécessite l'installation de libnuma-devel ou d'un paquet similaire.
