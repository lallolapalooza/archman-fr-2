MOSQUITTO.CONF(5) Formats de fichiers et conventions MOSQUITTO.CONF(5)

NOM

mosquitto.conf - fichier de configuration de mosquitto

SYNTAXE

mosquitto.conf

DESCRIPTION

mosquitto.conf est le fichier de configuration de mosquitto. Ce fichier peut se trouver n'importe où tant que mosquitto peut le lire. Par défaut, mosquitto n'a pas besoin de fichier de configuration et utilisera les valeurs par défaut listées ci-dessous. Voir mosquitto(8) pour des informations sur la façon de charger un fichier de configuration.

Mosquitto peut être instruit de recharger le fichier de configuration en envoyant un signal SIGHUP, comme décrit dans la section Signaux de mosquitto(8). Toutes les options de configuration ne peuvent pas être rechargées, comme détaillé dans les options ci-dessous.

FORMAT DU FICHIER

Toutes les lignes commençant par un # comme tout premier caractère sont considérées comme un commentaire.

Les lignes de configuration commencent par un nom de variable. La valeur de la variable est séparée du nom par un seul espace.

AUTHENTIFICATION

Les options d'authentification décrites ci-dessous permettent un large éventail de possibilités en conjonction avec les options d'écoute (listener). Cette section vise à clarifier les possibilités. Un aperçu est également disponible à l'adresse https://mosquitto.org/documentation/authentication-methods/

L'option la plus simple est de n'avoir aucune authentification. C'est le défaut si aucune autre option n'est donnée. Le support du chiffrement non authentifié est assuré par l'utilisation des options basées sur les certificats SSL/TLS certfile et keyfile.

MQTT fournit une authentification par nom d'utilisateur/mot de passe dans le cadre du protocole. Utilisez l'option password_file pour définir les noms d'utilisateur et les mots de passe valides. Assurez-vous d'utiliser le chiffrement réseau si vous utilisez cette option, sinon le nom d'utilisateur et le mot de passe seront vulnérables à l'interception. Utilisez per_listener_settings pour contrôler si les mots de passe sont requis globalement ou par écouteur.

Mosquitto fournit le plugin Dynamic Security, qui gère l'authentification par nom d'utilisateur/mot de passe et le contrôle d'accès de manière beaucoup plus flexible qu'un fichier de mots de passe. Voir https://mosquitto.org/documentation/dynamic-security/

Lors de l'utilisation du chiffrement basé sur des certificats, trois options affectent l'authentification. La première est require_certificate, qui peut être définie sur vrai ou faux. Si faux, le composant SSL/TLS du client vérifiera le serveur, mais il n'y a aucune exigence pour que le client fournisse quoi que ce soit pour le serveur : l'authentification se limite au nom d'utilisateur/mot de passe intégré à MQTT. Si require_certificate est vrai, le client doit fournir un certificat valide pour se connecter avec succès. Dans ce cas, la deuxième et la troisième options, use_identity_as_username et use_subject_as_username, deviennent pertinentes. Si définie sur vrai, use_identity_as_username fait que le Common Name (CN) du certificat client est utilisé à la place du nom d'utilisateur MQTT pour le contrôle d'accès. Le mot de passe n'est pas utilisé car on suppose que seuls les clients authentifiés ont des certificats valides. Cela signifie que tous les certificats d'autorité de certification que vous incluez dans cafile ou capath pourront émettre des certificats clients valides pour se connecter à votre broker. Si use_identity_as_username est faux, le client doit s'authentifier normalement (si requis par password_file) via les options MQTT. Le même principe s'applique à l'option use_subject_as_username, mais tout le sujet du certificat est utilisé comme nom d'utilisateur au lieu du seul CN.

Lors de l'utilisation du chiffrement basé sur une clé pré-partagée (PSK) via les options psk_hint et psk_file, le client doit fournir une identité et une clé valides pour se connecter au broker avant toute communication MQTT. Si use_identity_as_username est vrai, l'identité PSK est utilisée à la place du nom d'utilisateur MQTT pour le contrôle d'accès. Si use_identity_as_username est faux, le client peut toujours s'authentifier en utilisant le nom d'utilisateur/mot de passe MQTT s'il utilise l'option password_file.

Le chiffrement basé sur des certificats et sur PSK est configuré par écouteur.

Des plugins d'authentification peuvent être créés pour compléter les options password_file, acl_file et psk_file avec, par exemple, des recherches basées sur SQL.

Il est possible de prendre en charge plusieurs schémas d'authentification simultanément. Une configuration pourrait être créée avec une écoute pour toutes les différentes options de chiffrement décrites ci-dessus et donc un grand nombre de méthodes d'authentification.

OPTIONS GÉNÉRALES

acl_file chemin du fichier

Définit le chemin vers un fichier de liste de contrôle d'accès. S'il est défini, le contenu du fichier est utilisé pour contrôler l'accès des clients aux sujets sur le broker.

Si ce paramètre est défini, seuls les sujets listés auront accès. L'accès aux sujets est ajouté avec des lignes du format :

topic [read|write|readwrite|deny] <sujet>

Le type d'accès est contrôlé en utilisant "read", "write", "readwrite" ou "deny". Ce paramètre est facultatif (sauf si <sujet> inclut un espace) - s'il n'est pas donné, l'accès est lecture/écriture. <sujet> peut contenir les jokers + ou # comme dans les souscriptions. L'option "deny" peut être utilisée pour refuser explicitement l'accès à un sujet qui serait autrement accordé par une déclaration plus large de lecture/écriture/lecture-écriture. Tous les sujets "deny" sont gérés avant les sujets qui accordent un accès en lecture/écriture.

Le premier ensemble de sujets est appliqué aux clients anonymes, en supposant que allow_anonymous est vrai. Les ACL de sujets spécifiques à un utilisateur sont ajoutées après une ligne d'utilisateur comme suit :

user <nom d'utilisateur>

Le nom d'utilisateur auquel il est fait référence ici est le même que dans password_file. Ce n'est pas l'ID client.

Il est également possible de définir des ACL basées sur la substitution de motifs dans le sujet. La forme est la même que pour le mot-clé topic, mais en utilisant pattern comme mot-clé.

pattern [read|write|readwrite|deny] <sujet>

Les motifs disponibles pour la substitution sont :

•%c pour correspondre à l'ID client
•%u pour correspondre au nom d'utilisateur du client

Le motif de substitution doit être le seul texte pour ce niveau de hiérarchie. Les ACL de motifs s'appliquent à tous les utilisateurs, même si le mot-clé "user" a été donné précédemment.

Exemple :

pattern write sensor/%u/data

Autoriser l'accès aux messages de connexion du pont :

pattern write $SYS/broker/connection/%c/state

Si le premier caractère d'une ligne du fichier ACL est un #, il est traité comme un commentaire.

Si per_listener_settings est vrai, cette option s'applique uniquement à l'écouteur en cours de configuration. Si per_listener_settings est faux, cette option s'applique à tous les écouteurs.

Rechargé lors du signal de rechargement. Les ACL actuellement chargées seront libérées et rechargées. Les abonnements existants seront affectés après le rechargement.

Voir aussi https://mosquitto.org/documentation/dynamic-security/

allow_anonymous [ vrai | faux ]

Valeur booléenne qui détermine si les clients qui se connectent sans fournir de nom d'utilisateur sont autorisés à se connecter. Si défini sur faux, un autre moyen de connexion doit être créé pour contrôler l'accès des clients authentifiés.

Par défaut faux, sauf si aucun écouteur n'est défini dans le fichier de configuration, auquel cas il est défini sur vrai, mais les connexions ne sont autorisées qu'à partir de la machine locale.

Si per_listener_settings est vrai, cette option s'applique uniquement à l'écouteur en cours de configuration. Si per_listener_settings est faux, cette option s'applique à tous les écouteurs.


Important
Dans les versions 1.6.x et antérieures, cette option était par défaut vrai, sauf si une autre option de sécurité était définie.
Rechargé lors du signal de rechargement.

allow_duplicate_messages [ vrai | faux ]

Cette option est obsolète et sera supprimée dans une future version. Le comportement sera par défaut à vrai.

Si un client est abonné à plusieurs abonnements qui se chevauchent, par exemple foo/# et foo/+/baz, alors MQTT s'attend à ce que lorsque le broker reçoit un message sur un sujet qui correspond aux deux abonnements, comme foo/bar/baz, le client ne reçoive le message qu'une seule fois.

Si cette option est définie sur faux, le client recevra le message pour chaque abonnement correspondant. Cela peut entraîner une augmentation significative du trafic réseau et des problèmes pour les applications qui ne sont pas conçues pour gérer des messages dupliqués.

Le comportement par défaut est vrai, car c'est le comportement attendu selon la norme MQTT.

Rechargé lors du signal de rechargement.

background [ true | false ]

Exécute le broker en arrière-plan. Cette option ne peut pas être rechargée et doit être définie au démarrage du broker.

La valeur par défaut est false.

bind_address adresse IP

L'adresse IP sur laquelle le broker écoutera les connexions entrantes. Cela peut être une adresse IPv4 ou IPv6.

Si cette option n'est pas définie, le broker écoutera sur toutes les interfaces réseau disponibles.

Si per_listener_settings est true, cette option s'applique à l'écouteur en cours de configuration seulement. Si per_listener_settings est false, cette option s'applique à tous les écouteurs.

Cette option ne peut pas être rechargée et doit être définie au démarrage du broker.

bridge_cafile chemin du fichier

Chemin vers le fichier du certificat de l'autorité de certification (CA) à utiliser pour vérifier le certificat du broker distant lors de la connexion d'un pont à un autre broker.

Ceci doit être utilisé avec bridge_certfile et bridge_keyfile.

Option non rechargeable.

bridge_capath chemin du répertoire

Chemin vers le répertoire contenant des fichiers de certificats d'autorité de certification (CA) hachés à utiliser pour vérifier le certificat du broker distant lors de la connexion d'un pont à un autre broker.

Ceci doit être utilisé avec bridge_certfile et bridge_keyfile.

Option non rechargeable.

bridge_certfile chemin du fichier

Chemin vers le fichier du certificat client à utiliser lors de la connexion d'un pont à un autre broker.

Ceci doit être utilisé avec bridge_keyfile.

Option non rechargeable.

bridge_insecure_pass [ true | false ]

Si cette option est définie sur true, le mot de passe du pont sera envoyé en clair. Utilisez ceci uniquement dans des environnements de test ou lorsque la sécurité du réseau est garantie.

Par défaut false.

Option non rechargeable.

bridge_keyfile chemin du fichier

Chemin vers le fichier de la clé privée client à utiliser lors de la connexion d'un pont à un autre broker.

Ceci doit être utilisé avec bridge_certfile.

Option non rechargeable.

bridge_password mot de passe

Le mot de passe à utiliser lors de la connexion d'un pont à un autre broker.

Option non rechargeable.

bridge_retry_interval secondes

Le temps en secondes à attendre avant de tenter de rétablir une connexion de pont perdue.

La valeur par défaut est de 60 secondes.

Rechargé lors du signal de rechargement.

bridge_strftime [ true | false ]

Si définie sur vrai, la chaîne de formatage des sujets de pont sera traitée en utilisant strftime. Ceci est utilisé pour créer des sujets de pont dynamiques basés sur l'heure.

La valeur par défaut est false.

Rechargé lors du signal de rechargement.

bridge_topic_inits sujet1[:sujet2]...

Spécifie les sujets que les ponts doivent écouter. Lorsqu'un message est publié sur un de ces sujets, il est envoyé au broker distant.

Les sujets peuvent être spécifiés avec des jokers comme dans les abonnements MQTT.

Par exemple :

bridge_topic_inits sensor/data/#

Rechargé lors du signal de rechargement.

bridge_user nom d'utilisateur

Le nom d'utilisateur à utiliser lors de la connexion d'un pont à un autre broker.

Option non rechargeable.

bridge_vhost vhost

Le vhost à utiliser lors de la connexion d'un pont à un broker distant utilisant des vhosts. (par exemple, pour mosquitto sur un système IBM MQ).

Option non rechargeable.

cafile chemin du fichier

Chemin vers le fichier du certificat de l'autorité de certification (CA) à utiliser pour vérifier les certificats clients.

Ceci est utilisé avec require_certificate.

Option non rechargeable.

capath chemin du répertoire

Chemin vers le répertoire contenant des fichiers de certificats d'autorité de certification (CA) hachés à utiliser pour vérifier les certificats clients.

Ceci est utilisé avec require_certificate.

Option non rechargeable.

certfile chemin du fichier

Chemin vers le fichier du certificat serveur à utiliser pour le chiffrement TLS.

Ceci est utilisé avec keyfile.

Option non rechargeable.

ciphers liste des chiffrements

Spécifie les chiffrements TLS autorisés. La chaîne de caractères doit être au format accepté par OpenSSL. Par exemple :

ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256

Option non rechargeable.

clientid_prefix préfixe

Un préfixe qui sera ajouté à l'ID client pour tous les clients qui se connectent. Ceci est utile pour distinguer les clients provenant de différents brokers, par exemple.

Si cette option est définie, et que le client ne fournit pas d'ID client, un ID client sera généré en ajoutant un caractère unique (par défaut, une séquence de 6 caractères hexadécimaux) au préfixe.

Si cette option est définie, et que le client fournit un ID client, l'ID client fourni sera préfixé avec cette valeur.

Rechargé lors du signal de rechargement.

connection_messages [ true | false ]

Si définie sur vrai, le broker publiera des messages sur le sujet $SYS/broker/connection/{clientid}/state lorsqu'un client se connecte ou se déconnecte.

La valeur par défaut est false.

Rechargé lors du signal de rechargement.

default_interval secondes

Temps en secondes pour les messages de dernière volonté. Définit le temps d'intervalle pour le message de dernière volonté.

Rechargé lors du signal de rechargement.

disable_hook_dirs [ true | false ]

Désactive la recherche de hooks dans les sous-répertoires des répertoires spécifiés par load_plugins. Si cette option est définie sur vrai, seuls les hooks situés directement dans les répertoires spécifiés par load_plugins seront chargés.

La valeur par défaut est false.

Option non rechargeable.

dynamic_security_plugin [ true | false ]

Active le plugin de sécurité dynamique. Ce plugin permet de gérer l'authentification et les autorisations de manière dynamique, par exemple en interrogeant une base de données.

La valeur par défaut est false.

Option non rechargeable.

Voir https://mosquitto.org/documentation/dynamic-security/ pour plus d'informations.

fast_fail [ true | false ]

Si défini sur vrai, mosquitto tentera de se fermer rapidement en cas d'erreur lors du chargement d'un plugin.

La valeur par défaut est false.

Option non rechargeable.

idle_timeout secondes

Définit le temps d'inactivité maximal autorisé pour une connexion client. Si un client ne publie ou ne s'abonne à rien pendant cette période, il sera déconnecté.

La valeur par défaut est de 0, ce qui signifie qu'il n'y a pas de délai d'attente.

Rechargé lors du signal de rechargement.

keyfile chemin du fichier

Chemin vers le fichier de la clé privée serveur à utiliser pour le chiffrement TLS.

Ceci est utilisé avec certfile.

Option non rechargeable.

listeners port[:port]...

Définit les ports sur lesquels le broker écoutera les connexions entrantes. Plusieurs ports peuvent être spécifiés, séparés par des deux-points.

Par exemple :

listeners 1883 8883

Si vous utilisez TLS, vous pouvez spécifier le port TLS comme suit :

listeners 1883 8883

Et utiliser les options tls_version, cafile, certfile, keyfile, etc. pour configurer TLS pour le port 8883.

Si cette option n'est pas définie, le broker écoutera sur le port 1883 par défaut.

Si per_listener_settings est true, cette option s'applique à l'écouteur en cours de configuration seulement. Si per_listener_settings est false, cette option s'applique à tous les écouteurs.

Cette option ne peut pas être rechargée et doit être définie au démarrage du broker.

load_plugins répertoire1[:répertoire2]...

Spécifie les répertoires où chercher les plugins à charger. Les plugins doivent être des bibliothèques partagées (.so).

Option non rechargeable.

log_dest destination

Spécifie la destination pour les messages de journalisation. Les destinations possibles sont :

• stdout : Écrit sur la sortie standard.

• stderr : Écrit sur la sortie d'erreur standard.

• syslog : Écrit dans le journal système (via syslog).

• file : Écrit dans un fichier. Le nom du fichier est spécifié par l'option log_file.

Plusieurs destinations peuvent être spécifiées, séparées par des virgules. Par exemple : log_dest stderr mosquitto.log

La valeur par défaut est stderr.

Rechargé lors du signal de rechargement.

log_file chemin du fichier

Chemin vers le fichier dans lequel écrire les messages de journalisation lorsque log_dest est défini sur file.

Rechargé lors du signal de rechargement.

log_type type1[,type2]...

Spécifie les types de messages de journalisation à enregistrer. Les types possibles sont :

• debug : Messages de débogage détaillés.

• error : Messages d'erreur critiques.

• forward : Messages des ponts.

• subscribe : Messages d'abonnement client.

• unsubscribe : Messages de désabonnement client.

• publish : Messages de publication client.

• "$SYS" : Messages de statistiques du broker.

• mqtt : Messages du protocole MQTT.

• websockets : Messages liés aux connexions WebSocket.

• control : Messages de contrôle du broker (par exemple, rechargement de configuration).

• auth : Messages liés à l'authentification.

La valeur par défaut est error, warning, notice.

Rechargé lors du signal de rechargement.

max_connections nombre

Définit le nombre maximal de connexions simultanées autorisées sur le broker. Si cette limite est atteinte, de nouvelles connexions seront refusées.

La valeur par défaut est de 1024.

Rechargé lors du signal de rechargement.

mem_limit octets

Limite la quantité de mémoire que mosquitto peut utiliser. Si cette limite est atteinte, mosquitto arrêtera d'accepter de nouvelles connexions.

La valeur est spécifiée en octets. Des suffixes comme k, m, g peuvent être utilisés pour kilo, méga, giga octets.

La valeur par défaut est de 0 (pas de limite).

Rechargé lors du signal de rechargement.

password_file chemin du fichier

Chemin vers un fichier contenant les noms d'utilisateur et les mots de passe autorisés. Le format du fichier est le suivant :

nom_utilisateur mot_de_passe

Les mots de passe doivent être hachés à l'aide de la commande mosquitto_passwd.

Si per_listener_settings est true, cette option s'applique à l'écouteur en cours de configuration seulement. Si per_listener_settings est false, cette option s'applique à tous les écouteurs.

Rechargé lors du signal de rechargement. Le fichier sera relu.

per_listener_settings [ true | false ]

Si défini sur vrai, les options de configuration telles que allow_anonymous, password_file, acl_file, listeners, etc. s'appliqueront individuellement à chaque écouteur défini. Si faux, elles s'appliqueront globalement à tous les écouteurs.

La valeur par défaut est false.

Option non rechargeable.

pid_file chemin du fichier

Chemin vers un fichier dans lequel écrire l'ID du processus (PID) de mosquitto.

Option non rechargeable.

psk_file chemin du fichier

Chemin vers un fichier contenant les identités et les clés pré-partagées (PSK) à utiliser pour l'authentification PSK. Le format du fichier est le suivant :

identifiant_psk clé_pré_partagée

Si per_listener_settings est true, cette option s'applique à l'écouteur en cours de configuration seulement. Si per_listener_settings est false, cette option s'applique à tous les écouteurs.

Rechargé lors du signal de rechargement.

psk_hint hint

Une chaîne d'indice optionnelle à envoyer au client lors de la négociation TLS PSK. Cela peut aider le client à sélectionner la clé pré-partagée correcte.

Si per_listener_settings est true, cette option s'applique à l'écouteur en cours de configuration seulement. Si per_listener_settings est false, cette option s'applique à tous les écouteurs.

Option non rechargeable.

require_certificate [ true | false ]

Si défini sur vrai, le broker exigera que les clients fournissent un certificat client valide lors de la connexion TLS.

La valeur par défaut est false.

Option non rechargeable.

retained_messages [ true | false ]

Si défini sur vrai, mosquitto stockera les messages conservés.

La valeur par défaut est true.

Rechargé lors du signal de rechargement.

save_interval secondes

Intervalle en secondes entre les sauvegardes périodiques des messages conservés. Si retained_messages est défini sur true, les messages conservés seront sauvegardés dans un fichier (par défaut, mosquitto.db) à cet intervalle. La valeur 0 désactive la sauvegarde automatique.

La valeur par défaut est de 0.

Rechargé lors du signal de rechargement.

sub_qos [ true | false ]

Si défini sur vrai, le broker n'autorisera que les abonnements avec un QoS de 0.

La valeur par défaut est false.

Rechargé lors du signal de rechargement.

sys_interval secondes

Intervalle en secondes pour la publication des statistiques du broker sur le sujet $SYS/.

La valeur par défaut est de 10 secondes.

Rechargé lors du signal de rechargement.

sys_prefix préfixe

Préfixe pour les sujets de statistiques du broker. La valeur par défaut est "$SYS".

Rechargé lors du signal de rechargement.

tls_alpn protocoles

Spécifie les protocoles ALPN (Application-Layer Protocol Negotiation) à prendre en charge lors de l'établissement d'une connexion TLS. Ceci est principalement utilisé pour MQTT sur WebSockets.

Exemple : tls_alpn mqtt

Option non rechargeable.

tls_disable_authentication [ true | false ]

Désactive la vérification du certificat du client lors de l'utilisation de TLS. Utilisez ceci avec prudence car cela désactive une partie de la sécurité de TLS.

La valeur par défaut est false.

Option non rechargeable.

tls_expiry_limit jours

Définit le nombre de jours avant l'expiration du certificat TLS pour que mosquitto émette un avertissement.

La valeur par défaut est de 30 jours.

Option non rechargeable.

tls_ignore_validation [ true | false ]

Si défini sur vrai, mosquitto ignorera la validation du certificat du client et du serveur. Utilisez ceci avec une extrême prudence, car cela désactive complètement la vérification de l'identité.

La valeur par défaut est false.

Option non rechargeable.

tls_ocsp_chain chemin du fichier

Chemin vers le fichier contenant la chaîne OCSP (Online Certificate Status Protocol) à utiliser lors de la vérification de la révocation des certificats clients.

Option non rechargeable.

tls_password mot de passe

Le mot de passe de la clé privée du serveur TLS.

Option non rechargeable.

tls_psk_identity identifiant

Identifiant PSK à utiliser pour l'authentification TLS PSK.

Si per_listener_settings est true, cette option s'applique à l'écouteur en cours de configuration seulement. Si per_listener_settings est false, cette option s'applique à tous les écouteurs.

Option non rechargeable.

tls_version version

Version minimale de TLS à utiliser pour les connexions. Les valeurs possibles sont tlsv1.0, tlsv1.1, tlsv1.2, tlsv1.3.

La valeur par défaut est tlsv1.2.

Option non rechargeable.

use_identity_as_username [ true | false ]

Lors de l'utilisation de l'authentification par certificat ou PSK, si cette option est définie sur vrai, l'identité du client (Common Name du certificat ou identifiant PSK) sera utilisée comme nom d'utilisateur pour le contrôle d'accès.

La valeur par défaut est false.

Option non rechargeable.

use_subject_as_username [ true | false ]

Lors de l'utilisation de l'authentification par certificat, si cette option est définie sur vrai, le sujet complet du certificat client sera utilisé comme nom d'utilisateur pour le contrôle d'accès. Ceci remplace use_identity_as_username.

La valeur par défaut est false.

Option non rechargeable.

utf8 [ true | false ]

Si défini sur vrai, mosquitto validera que les sujets et les messages de publication sont codés en UTF-8.

La valeur par défaut est true.

Rechargé lors du signal de rechargement.

websocket_ping_interval secondes

Intervalle en secondes entre l'envoi des messages PING par le serveur aux clients WebSocket. Cela permet de s'assurer que la connexion est toujours active.

La valeur par défaut est de 60 secondes.

Rechargé lors du signal de rechargement.

websocket_ping_timeout secondes

Temps en secondes à attendre une réponse PONG après l'envoi d'un message PING par le serveur. Si le délai expire, la connexion WebSocket sera fermée.

La valeur par défaut est de 5 secondes.

Rechargé lors du signal de rechargement.

websocket_timeout secondes

Temps en secondes avant que la connexion WebSocket ne soit fermée en raison de l'inactivité.

La valeur par défaut est de 10 secondes.

Rechargé lors du signal de rechargement.

CONFIGURATIONS DE BROKER

Les options suivantes sont utilisées pour configurer les ponts de brokers. Les configurations de ponts sont définies dans des sections de configuration séparées, en utilisant le mot-clé bridge suivi du nom du pont.

Exemple :

bridge_addr adresse

Adresse du broker distant auquel se connecter. Peut être un nom d'hôte ou une adresse IP.

Option non rechargeable.

bridge_clientid clientid

ID client à utiliser lors de la connexion au broker distant. Si non spécifié, un ID client sera généré aléatoirement.

Option non rechargeable.

bridge_host hôte

Hôte du broker distant auquel se connecter.

Option non rechargeable.

Envoyer les messages du journal à une destination particulière. Les destinations possibles sont : stdout, stderr, syslog, topic, file, dlt.

stdout et stderr journalisent sur la console sur la sortie nommée.

La destination file nécessite un paramètre supplémentaire qui est le fichier dans lequel journaliser, par exemple "log_dest file /var/log/mosquitto.log". Le fichier sera fermé et rouvert lorsque le broker recevra un signal HUP. Une seule destination de fichier peut être configurée.

La destination dlt est pour l'outil automobile `Diagnostic Log and Trace`. Cela nécessite que Mosquitto ait été compilé avec le support DLT.

Utilisez "log_dest none" si vous souhaitez désactiver la journalisation. Par défaut : stderr. Cette option peut être spécifiée plusieurs fois.

NAME

mosquitto-config - Mosquitto configuration file syntax

DESCRIPTION

The mosquitto broker reads its configuration from a text file on startup. The default configuration file is /etc/mosquitto/mosquitto.conf. If this file does not exist, then no configuration is loaded. An alternative configuration file may be specified on the command line using the -c option.

Configuration is organised into sections, with options applying globally or to specific listeners.

Comments may be made on a line by preceding the text with a # character. Blank lines are ignored.

All options are case sensitive.

General Options

These options apply globally to the broker.

allow_anonymous [ true | false ]

If set to true (the default), clients are allowed to connect without providing a username or password. If set to false, clients must authenticate.

Reloaded on reload signal.

allow_zero_byte_retain [ true | false ]

If set to true (the default), clients are allowed to publish messages with the retain flag set and a zero byte payload. This is used to clear retained messages. If set to false, clients will be disconnected if they attempt to publish a zero byte retain message.

Reloaded on reload signal.

auto_id_prefix prefix

If set, when using dynamic security, this prefix is added to the client ID when it is not set by the client. This helps to prevent conflicts if multiple brokers are using the same dynamic security plugin. Defaults to "auto_".

Si un pont a des topics avec une direction "out", le comportement par défaut est d'envoyer une requête de désabonnement au broker distant sur ce topic. Cela signifie que changer la direction d'un topic de "in" à "out" ne permettra pas de continuer à recevoir des messages entrants. L'envoi de ces requêtes de désabonnement n'est pas toujours souhaitable, la définition de bridge_attempt_unsubscribe à false désactivera l'envoi de la requête de désabonnement. Par défaut à true.

bridge_bind_address adresse ip

Si vous avez besoin que le pont se connecte via une interface réseau particulière, utilisez bridge_bind_address pour indiquer au pont à quelle adresse IP locale le socket doit être lié, par exemple bridge_bind_address 192.168.1.10.

bridge_max_packet_size valeur

Si vous souhaitez restreindre la taille des messages envoyés à un pont distant, utilisez cette option. Cela définit le nombre maximum d'octets pour le message total, y compris les en-têtes et la charge utile. Notez que les brokers MQTT v5 peuvent fournir leur propre propriété maximum-packet-size. Dans ce cas, la plus petite des deux limites sera utilisée. Défini à 0 pour "illimité".

bridge_outgoing_retain [ true | false ]

Certains brokers MQTT n'autorisent pas les messages conservés. MQTT v5 fournit un mécanisme permettant aux brokers d'indiquer aux clients qu'ils ne prennent pas en charge les messages conservés, mais ce n'est pas possible pour MQTT v3.1.1 ou v3.1. Si vous devez établir un pont vers un broker v3.1.1 ou v3.1 qui ne prend pas en charge les messages conservés, définissez l'option bridge_outgoing_retain à false. Cela supprimera le bit de conservation sur tous les messages sortants vers ce pont, quelle que soit l'autre configuration. Par défaut à true.

bridge_protocol_version version

Définissez la version du protocole MQTT à utiliser pour ce pont. Peut être l'une des valeurs mqttv50, mqttv311 ou mqttv31. Par défaut à mqttv311.

cleansession [ true | false ]

Définissez l'option de session propre pour ce pont. La définition à false (par défaut) signifie que tous les abonnements sur le broker distant sont conservés en cas de perte de connexion réseau. Si défini à true, tous les abonnements et messages sur le broker distant seront nettoyés si la connexion est perdue. Notez que la définition à true peut entraîner l'envoi d'une grande quantité de messages conservés à chaque reconnexion du pont.

Si vous utilisez des ponts avec cleansession défini à false (par défaut), vous pourriez obtenir un comportement inattendu des topics entrants si vous modifiez les topics auxquels vous vous abonnez. En effet, le broker distant conserve l'abonnement pour l'ancien topic. Si vous rencontrez ce problème, connectez votre pont avec cleansession défini à true, puis reconnectez avec cleansession défini à false comme d'habitude.

local_cleansession [ true | false]

Le cleansession régulier couvre à la fois les abonnements locaux et les abonnements distants. local_cleansession permet de séparer cela. La définition à false signifiera que la connexion locale conservera les abonnements, indépendamment de la connexion distante.

Par défaut à la valeur de bridge.cleansession sauf spécification explicite.

connection nom

Cette variable marque le début d'une nouvelle connexion de pont. Elle est également utilisée pour donner un nom au pont qui est utilisé comme client id sur le broker distant.

keepalive_interval secondes

Définissez le nombre de secondes après lequel le pont doit envoyer un ping si aucun autre trafic n'a eu lieu. Par défaut à 60. Une valeur minimale de 5 secondes est autorisée.

idle_timeout secondes

Définissez le temps pendant lequel un pont utilisant le type de démarrage paresseux doit être inactif avant d'être arrêté. Par défaut à 60 secondes.

local_clientid id

Définissez l'identifiant client à utiliser sur le broker local. S'il n'est pas défini, il prend par défaut local.<remote_clientid>. Si vous faites le pont entre un broker et lui-même, il est important que local_clientid et remote_clientid ne correspondent pas.

local_password mot de passe

Configurez le mot de passe à utiliser lors de la connexion de ce pont au broker local. Cela peut être important lorsque l'authentification et les ACL sont utilisées.

local_username nom d'utilisateur

Configurez le nom d'utilisateur à utiliser lors de la connexion de ce pont au broker local. Cela peut être important lorsque l'authentification et les ACL sont utilisées.

notifications [ true | false ]

Si défini à true, publiez des messages de notification sur les brokers local et distant donnant des informations sur l'état de la connexion du pont. Les messages conservés sont publiés sur le topic $SYS/broker/connection/<remote_clientid>/state sauf indication contraire dans notification_topics. Si le message est 1, la connexion est active, ou 0 si la connexion a échoué. Par défaut à true.

Ceci utilise la fonctionnalité Last Will and Testament (LWT).

notifications_local_only [ true | false ]

Si défini à true, publiez uniquement les messages de notification sur le broker local donnant des informations sur l'état de la connexion du pont. Par défaut à false.

notification_topic topic

Choisissez le topic sur lequel les notifications seront publiées pour ce pont. S'il n'est pas défini, les messages seront envoyés sur le topic $SYS/broker/connection/<remote_clientid>/state.

remote_clientid id

Définissez l'identifiant client pour cette connexion de pont. S'il n'est pas défini, il prend par défaut 'name.hostname', où name est le nom de la connexion et hostname est le nom d'hôte de cet ordinateur.

Ceci remplace l'ancienne option "clientid" pour éviter la confusion avec les côtés local/distant du pont. "clientid" reste valide pour le moment.

remote_password valeur

Configurez un mot de passe pour le pont. Ceci est utilisé à des fins d'authentification lors de la connexion à un broker qui prend en charge MQTT v3.1 et supérieur et nécessite un nom d'utilisateur et/ou un mot de passe pour se connecter. Cette option n'est valide que si un remote_username est également fourni.

Ceci remplace l'ancienne option "password" pour éviter la confusion avec les côtés local/distant du pont. "password" reste valide pour le moment.

remote_username nom

Configurez un nom d'utilisateur pour le pont. Ceci est utilisé à des fins d'authentification lors de la connexion à un broker qui prend en charge MQTT v3.1 et supérieur et nécessite un nom d'utilisateur et/ou un mot de passe pour se connecter. Voir aussi l'option remote_password.

Ceci remplace l'ancienne option "username" pour éviter la confusion avec les côtés local/distant du pont. "username" reste valide pour le moment.

restart_timeout base cap, restart_timeout constant

Définissez le temps d'attente avant de tenter de se reconnecter pour un pont utilisant le type de démarrage automatique.

Cette option peut être configurée pour utiliser un délai constant en secondes, ou pour utiliser un mécanisme de backoff basé sur le "Decorrelated Jitter", qui ajoute un degré d'aléatoire au moment où le redémarrage se produit, commençant à la base et augmentant jusqu'à la limite supérieure. Définir un délai constant de 20 secondes :

restart_timeout 20

Définir le backoff avec une base (valeur de départ) de 10 secondes et une limite (valeur maximale) de 60 secondes :

restart_timeout 10 30

Par défaut à jitter avec une base de 5 secondes et une limite de 30 secondes.

round_robin [ true | false ]

Si le pont a plus d'une adresse spécifiée dans la configuration address/addresses, l'option round_robin définit le comportement du pont en cas de défaillance de la connexion du pont. Si round_robin est false, la valeur par défaut, alors la première adresse est traitée comme la connexion principale du pont. Si la connexion échoue, les autres adresses secondaires seront tentées à tour de rôle. Pendant la connexion à un pont secondaire, le pont tentera périodiquement de se reconnecter au pont principal jusqu'à succès.

Si round_robin est true, alors toutes les adresses sont traitées comme égales. Si une connexion échoue, la prochaine adresse sera essayée et si elle réussit, la connexion restera active jusqu'à ce qu'elle échoue.

start_type [ automatic | lazy | once ]

Définissez le type de démarrage du pont. Ceci contrôle la façon dont le pont démarre et peut être l'un des trois types : automatic, lazy et once. Notez que RSMB fournit un quatrième type de démarrage "manual" qui n'est actuellement pas pris en charge par mosquitto.

automatic est le type de démarrage par défaut et signifie que la connexion du pont sera démarrée automatiquement au démarrage du broker et également redémarrée après un court délai (30 secondes) si la connexion échoue.

Les ponts utilisant le type de démarrage lazy seront démarrés automatiquement lorsque le nombre de messages mis en file d'attente dépasse le nombre défini avec l'option threshold. Il sera arrêté automatiquement après le temps défini par le paramètre idle_timeout. Utilisez ce type de démarrage si vous souhaitez que la connexion ne soit active que lorsqu'elle est nécessaire.

Un pont utilisant le type de démarrage once sera démarré automatiquement au démarrage du broker mais ne sera pas redémarré si la connexion échoue.

threshold compte

Définissez le nombre de messages qui doivent être mis en file d'attente pour qu'un pont avec un type de démarrage paresseux soit redémarré. Par défaut à 10 messages.

topic pattern [[[ out | in | both ] qos-level] local-prefix remote-prefix]

Définissez un pattern de topic à partager entre les deux brokers. Tous les topics correspondant au pattern (qui peut inclure des caractères génériques) sont partagés. Le deuxième paramètre définit la direction dans laquelle les messages seront partagés, il est donc possible d'importer des messages d'un broker distant en utilisant in, d'exporter des messages vers un broker distant en utilisant out ou de partager des messages dans les deux directions. Si ce paramètre n'est pas défini, la valeur par défaut de out est utilisée. Le niveau QoS définit le niveau QoS de publication/abonnement utilisé pour ce topic et par défaut à 0.

Les options local-prefix et remote-prefix permettent de remapper les topics lors de la publication et de la réception depuis des brokers distants. Cela permet d'insérer un arbre de topics du broker local dans l'arbre de topics du broker distant à un endroit approprié.

Pour les topics entrants, le pont ajoutera le préfixe du pattern avec le préfixe distant et s'abonnera au topic résultant sur le broker distant. Lorsqu'un message entrant correspondant est reçu, le préfixe distant sera supprimé du topic, puis le préfixe local sera ajouté.

Pour les topics sortants

, le pont préfixera le motif avec le préfixe local et s'abonnera au sujet résultant sur le broker local. Quand un message sortant est traité, le préfixe local sera retiré du sujet, puis le préfixe distant sera ajouté.

Lors de l'utilisation du mappage de sujets, un préfixe vide peut être défini en utilisant le marqueur de remplacement "". L'utilisation du marqueur vide pour le sujet lui-même est également valide. Le tableau ci-dessous définit quelles combinaisons de vide ou de valeur sont valides. Les sujets locaux complets et sujets distants complets affichent les sujets résultants qui seraient utilisés aux extrémités locale et distante du pont. Par exemple, pour la première ligne du tableau, si vous publiez sur L/topic sur le broker local, alors le broker distant recevra un message sur le sujet R/topic.

motif L/ R/ valide L/motif R/motif
motif L/ "" valide L/motif motif
motif "" R/ valide motif R/motif
motif "" "" valide (pas de remappage) motif motif
"" local distant valide (remappage d'un sujet local unique vers distant) local distant
"" local "" invalide    
"" "" distant invalide    
"" "" "" invalide    

Pour remapper un arbre de sujets entier, utilisez par exemple :

topic # both 2 local/topic/ remote/topic/

Cette option peut être spécifiée plusieurs fois par pont.

Il faut veiller à ne pas créer de boucles avec cette option. Si vous constatez une charge CPU élevée sur un broker, il est possible que vous ayez une boucle où chaque broker se renvoie mutuellement les mêmes messages indéfiniment.

Voir aussi l'option cleansession si vous recevez des messages sur des sujets inattendus lors de l'utilisation de sujets entrants.

Exemple de remappage de sujets de pont.  La configuration ci-dessous connecte un pont au broker à test.mosquitto.org. Il s'abonne au sujet distant $SYS/broker/clients/total et republie les messages reçus sur le sujet local test/mosquitto/org/clients/total

connection test-mosquitto-org
address test.mosquitto.org
cleansession true
topic clients/total in 0 test/mosquitto/org/ $SYS/broker/

try_private [ true | false ]

Si try_private est défini sur true, le pont tentera d'indiquer au broker distant qu'il s'agit d'un pont et non d'un client ordinaire. En cas de succès, la détection de boucles sera plus efficace et les messages conservés seront correctement propagés. Tous les brokers ne prennent pas en charge cette fonctionnalité, il peut donc être nécessaire de définir try_private sur false si votre pont ne se connecte pas correctement.

Par défaut à true.

Support SSL/TLS

Les options suivantes sont disponibles pour tous les ponts afin de configurer le support SSL/TLS.

bridge_alpn alpn

Configure l'option de négociation du protocole de couche application pour la session TLS. Utile pour les brokers qui prennent en charge à la fois les websockets et MQTT sur le même port.

bridge_cafile chemin du fichier

Soit bridge_cafile, soit bridge_capath doit être fourni pour permettre le support SSL/TLS.

bridge_cafile est utilisé pour définir le chemin vers un fichier contenant les certificats CA encodés en PEM qui ont signé le certificat du broker distant.

bridge_capath chemin du fichier

Soit bridge_capath, soit bridge_cafile doit être fourni pour permettre le support SSL/TLS.

bridge_capath est utilisé pour définir le chemin vers un répertoire contenant les certificats CA encodés en PEM qui ont signé le certificat du broker distant. Pour que bridge_capath fonctionne correctement, les fichiers de certificat doivent avoir l'extension ".crt" et vous devez exécuter "openssl rehash <chemin vers bridge_capath>" chaque fois que vous ajoutez/supprimez un certificat.

bridge_certfile chemin du fichier

Chemin vers le certificat client encodé en PEM pour ce pont, si requis par le broker distant.

bridge_identity identité

Le chiffrement par clé pré-partagée offre une alternative au chiffrement basé sur certificat. Un pont peut être configuré pour utiliser PSK avec les options bridge_identity et bridge_psk. Ceci est l'identité client utilisée avec le chiffrement PSK. Une seule des méthodes de chiffrement par certificat et par PSK peut être utilisée sur un pont à la fois.

bridge_insecure [ true | false ]

Lors de l'utilisation de TLS basé sur certificat, le pont tentera de vérifier si le nom d'hôte fourni dans le certificat distant correspond à l'hôte/adresse de connexion. Cela peut causer des problèmes dans les scénarios de test, donc bridge_insecure peut être défini sur true pour désactiver la vérification du nom d'hôte.

Définir cette option sur true signifie qu'une tierce partie malveillante pourrait potentiellement usurper l'identité de votre serveur, elle doit donc toujours être définie sur false dans les environnements de production.

bridge_keyfile chemin du fichier

Chemin vers la clé privée encodée en PEM pour ce pont, si requis par le broker distant.

bridge_psk clé

Le chiffrement par clé pré-partagée offre une alternative au chiffrement basé sur certificat. Un pont peut être configuré pour utiliser PSK avec les options bridge_identity et bridge_psk. Ceci est la clé pré-partagée au format hexadécimal sans "0x". Une seule des méthodes de chiffrement par certificat et par PSK peut être utilisée sur un pont à la fois.

bridge_require_ocsp [ true | false ]

Lorsqu'il est défini sur true, le pont exige OCSP sur la connexion TLS qu'il ouvre en tant que client.

bridge_tls_version version

Configure la version du protocole TLS à utiliser pour ce pont. Les valeurs possibles sont tlsv1.3, tlsv1.2 et tlsv1.1. Par défaut à tlsv1.2. Le broker distant doit prendre en charge la même version de TLS pour que la connexion réussisse.
