NOM

mosquitto_ctrl - un outil pour initialiser/configurer une instance de broker Mosquitto

SYNTAXE

mosquitto_ctrl [options-de-connexion | -o fichier-config] nom-module commande-module [options-de-commande]

options-de-connexion: {[-h nom-hote] [--unix chemin-socket] [-p numero-port] [-u nom-utilisateur] [-P mot-de-passe] | -L URL} [-A adresse-liaison] [-c] [-d] [-i id-client] [-q qos-message] [--quiet] [-V version-protocole] [[{--cafile fichier | --capath rep} [--cert fichier] [--key fichier] [--ciphers chiffrements] [--tls-version version] [--tls-alpn protocole] [--tls-engine moteur] [--keyform {pem | moteur}] [--tls-engine-kpass-sha1 kpass-sha1] [--insecure]] | [--psk clef-hex --psk-identity identite [--ciphers chiffrements] [--tls-use-os-certs] [--tls-version version]]] [--proxy url-socks]

mosquitto_ctrl [--help]

DESCRIPTION

mosquitto_ctrl est un outil pour aider à la configuration d'une instance de broker Mosquitto.

CONNEXIONS CHIFFRÉES

mosquitto_ctrl prend en charge les connexions chiffrées TLS. Il est fortement recommandé d'utiliser une connexion chiffrée pour toute utilisation à distance de mosquitto_ctrl.

Pour activer les connexions TLS lors de l'utilisation de certificats x509, l'une des options --cafile ou --capath doit être fournie.

Pour activer les connexions TLS lors de l'utilisation de TLS-PSK, vous devez utiliser les options --psk et --psk-identity.

MODULES

Sécurité dynamique

Authentification, et contrôle d'accès basé sur les rôles avec utilisateurs et groupes. Utilise le nom de module dynsec. Voir : mosquitto_ctrl_dynsec(1)

Modules externes

mosquitto_ctrl a la capacité de charger des modules externes sous forme de bibliothèques partagées. Par exemple, utiliser le nom de module example essaiera de charger le module externe mosquitto_ctrl_example.so ou mosquitto_ctrl_example.dll, selon la plateforme. Cela permet d'ajouter de nouvelles fonctionnalités à Mosquitto en combinant un plugin et un module mosquitto_ctrl, sans avoir à recompilier le code source de Mosquitto.

OPTIONS DE CONNEXION

Les options ci-dessous peuvent être fournies sur la ligne de commande, mais peuvent également être placées dans un fichier de configuration situé à $XDG_CONFIG_HOME/mosquitto_ctrl ou $HOME/.config/mosquitto_ctrl.

Le fichier de configuration peut être spécifié manuellement avec l'option -o fichier-config.

Le fichier de configuration doit contenir une paire -option valeur par ligne. Les valeurs dans le fichier de configuration seront utilisées comme valeurs par défaut et pourront être remplacées en utilisant la ligne de commande. Les exceptions à cela sont les options de type message, dont une seule peut être spécifiée. Notez également que certaines options ne peuvent actuellement pas être niées, par exemple -S. Les lignes du fichier de configuration qui commencent par un caractère # sont traitées comme des commentaires et ne sont pas traitées davantage.

-A

Lier la connexion sortante à une adresse IP/nom d'hôte local. Utilisez cet argument si vous devez restreindre la communication réseau à une interface particulière.

--cafile

Définir le chemin vers un fichier contenant les certificats d'autorité de certification (CA) encodés en PEM qui sont approuvés. Utilisé pour activer la communication SSL.

Voir aussi --capath

--capath

Définir le chemin vers un répertoire contenant les certificats d'autorité de certification (CA) encodés en PEM qui sont approuvés. Utilisé pour activer la communication SSL.

Pour que --capath fonctionne correctement, les fichiers de certificat doivent avoir ".crt" comme extension de fichier et vous devez exécuter "openssl rehash <chemin vers capath>" chaque fois que vous ajoutez/supprimez un certificat.

Voir aussi --cafile

--cert

Définir le chemin vers un fichier contenant un certificat encodé en PEM pour ce client, si requis par le serveur.

Voir aussi --key.

--ciphers

Une liste de chiffrements TLS compatible openssl pour supporter le client. Voir ciphers(1) pour plus d'informations.

-d, --debug

Activer les messages de débogage.

-D, --property

Utiliser une propriété MQTT v5 avec cette publication. Si vous utilisez cette option, le client sera configuré comme un client MQTT v5. Cette option a deux formes :

-D commande identifiant valeur

-D commande identifiant nom valeur

commande est l'identifiant de la commande/paquet MQTT et peut être CONNECT, PUBLISH, PUBREL, DISCONNECT, AUTH ou WILL. Les propriétés disponibles pour chaque commande sont listées dans la section Propriétés.

identifiant est le nom de la propriété à ajouter. Ceci est tel que décrit dans la spécification, mais avec '-' comme séparateur de mots. Par exemple : payload-format-indicator. Plus de détails sont dans la section Propriétés.

valeur est la valeur de la propriété à ajouter, avec un type de données spécifique à la propriété.

nom est utilisé uniquement pour la propriété user-property comme première des deux chaînes de la paire de chaînes. Dans ce cas, valeur est la seconde des chaînes de la paire.

--help

Afficher les informations d'utilisation.

-h, --host

Spécifier l'hôte auquel se connecter. La valeur par défaut est localhost.

-i, --id

L'identifiant à utiliser pour ce client. S'il n'est pas fourni, un identifiant client sera généré en fonction de la version MQTT utilisée. Pour v3.1.1/v3.1, le client génère un identifiant client au format mosq-XXXXXXXXXXXXXXXXXX, où les X sont remplacés par des caractères alphanumériques aléatoires. Pour v5.0, le client envoie un identifiant client de longueur nulle, et le serveur générera un identifiant client pour le client.

Cette option ne peut pas être utilisée en même temps que l'argument --id-prefix.

--insecure

Lors de l'utilisation du chiffrement basé sur les certificats, cette option désactive la vérification du nom d'hôte du serveur dans le certificat du serveur. Cela peut être utile lors des tests de configuration initiale du serveur, mais permet à un tiers malveillant d'usurper l'identité de votre serveur par le biais d'un spoofing DNS, par exemple. Utilisez cette option uniquement pour les tests. Si vous devez recourir à cette option dans un environnement de production, votre configuration est défaillante et il est inutile d'utiliser le chiffrement.

--key

Définir le chemin vers un fichier contenant une clé privée encodée en PEM pour ce client, si requis par le serveur.

Voir aussi --cert.

--keyform

Spécifie le type de clé privée utilisée lors de l'établissement des connexions TLS. Il peut s'agir de "pem" ou "engine". Ce paramètre est utile lorsqu'un module TPM est utilisé et que la clé privée a été créée avec lui. Par défaut, "pem", ce qui signifie que les fichiers de clé privée normaux sont utilisés.

Voir aussi --tls-engine.

-L, --url

Spécifiez l'utilisateur, le mot de passe, le nom d'hôte, le port et le sujet en même temps sous forme d'URL. L'URL doit être de la forme : mqtt(s)://[utilisateur[:mot-de-passe]@]hôte[:port]/sujet

Si le schéma est mqtt:// alors le port est 1883 par défaut. Si le schéma est mqtts:// alors le port est 8883 par défaut.

--nodelay

Désactive l'algorithme de Nagle pour le socket. Cela signifie que la latence des messages envoyés est réduite, ce qui est particulièrement perceptible pour les messages petits et raisonnablement peu fréquents. L'utilisation de cette option peut entraîner l'envoi de plus de paquets que normalement nécessaire.

-o fichier-config

Utiliser les options de connexion dans le fichier-config.

-p, --port

Spécifiez le numéro de port du broker Mosquitto. La valeur par défaut est 1883.

-P, --password

Spécifiez le mot de passe à utiliser lors de la connexion à un broker qui nécessite une authentification.

--proxy

Utiliser un proxy SOCKS pour la connexion. Le format de l'URL est socks4a://[utilisateur[:mot-de-passe]@]hôte[:port].

-q, --qos

Spécifiez le niveau de qualité de service (QoS) par défaut à utiliser pour les messages publiés. La valeur doit être comprise entre 0 et 2.

--psk

La clé pré-partagée (PSK) à utiliser lors de l'établissement d'une connexion TLS. La clé doit être fournie sous forme de chaîne hexadécimale.

--psk-identity

L'identité PSK à utiliser lors de l'établissement d'une connexion TLS.

-s, --subtract

Si présent, les résultats des commandes de module seront soustraits de l'état actuel du broker. Par exemple, si vous utilisez mosquitto_ctrl dynsec users list -s, la liste résultante contiendra les utilisateurs qui ne sont pas actuellement configurés sur le broker.

-u, --username

Spécifiez le nom d'utilisateur à utiliser lors de la connexion à un broker qui nécessite une authentification.

--unix

Se connecter à un broker via un socket de domaine Unix.

-V, --protocol-version

Spécifiez la version du protocole MQTT à utiliser. Les valeurs possibles sont 3.1, 3.1.1 et 5. La valeur par défaut est 5.

--tls-alpn

Spécifie le protocole ALPN (Application-Layer Protocol Negotiation) à utiliser lors de l'établissement d'une connexion TLS. Pour MQTT, cela doit être "mqtt".

--tls-engine

Spécifie le moteur crypto à utiliser lors de l'établissement d'une connexion TLS. Ceci est utile lorsque vous utilisez un module matériel tel qu'un TPM.

--tls-engine-kpass-sha1

Le mot de passe du moteur crypto, sous forme de SHA1, utilisé lorsque --keyform est défini sur 'engine'.

--tls-use-os-certs

Utilise les certificats du système d'exploitation au lieu de ceux fournis via les options --cafile / --capath, --cert et --key lors de l'établissement d'une connexion TLS.

--tls-version

Spécifie la version minimale de TLS à utiliser lors de l'établissement d'une connexion TLS. Les valeurs possibles sont tlsv1, tlsv1.1, tlsv1.2 et tlsv1.3.

--quiet

Supprime les messages de sortie non essentiels.

EXEMPLES

Lister tous les utilisateurs du broker Mosquitto s'exécutant sur le port 1883 de la machine locale :

mosquitto_ctrl dynsec users list

Lister tous les groupes et soustraire ceux qui sont déjà configurés sur le broker :

mosquitto_ctrl dynsec groups list -s

Ajouter un nouvel utilisateur 'testuser' avec le mot de passe 'pa$$word' et le rôle 'reader' :

mosquitto_ctrl dynsec users create testuser --password pa$$word --role reader

Créer une nouvelle connexion TLS chiffrée vers un broker sur mosquitto.org, port 8883, en utilisant un certificat client et une clé privée :

mosquitto_ctrl --cafile /path/to/ca.crt --cert /path/to/client.crt --key /path/to/client.key -h mosquitto.org -p 8883 --unix /var/run/mosquitto.sock

OPTIONS

-c, --cafile

Path to a file containing the concatenation of trusted Certificate Authority (CA) certificates.

-C, --capath

Path to a directory containing the trusted CA certificates.

-d, --debug

Enable network debugging output.

-e, --enable-pwm

Enable PWM output on the specified pin. This option is only available when using the `mqtt_broker` program.

-f, --file

Provide a path to a config file to load options from. The config file should have one pair of -option value per line. The values in the config file will be used as defaults and can be overridden by using the command line. The exceptions to this are the message type options, of which only one can be specified. Note also that currently some options cannot be negated, e.g. -S. Config file lines that have a # as the first character are treated as comments and not processed any further.

-p, --port

Connect to the port specified. If not given, the default of 1883 for plain MQTT or 8883 for MQTT over TLS will be used.

-P, --pw

Provide a password to be used for authenticating with the broker. Using this argument without also specifying a username is invalid when using MQTT v3.1 or v3.1.1. See also the --username option.

--proxy

Specify a SOCKS5 proxy to connect through. "None" and "username" authentication types are supported. The socks-url must be of the form socks5h://[username[:password]@]host[:port]. The protocol prefix socks5h means that hostnames are resolved by the proxy. The symbols %25, %3A and %40 are URL decoded into %, : and @ respectively, if present in the username or password.

If username is not given, then no authentication is attempted. If the port is not given, then the default of 1080 is used.

More SOCKS versions may be available in the future, depending on demand, and will use different protocol prefixes as described in curl(1).

--psk

Provide the hexadecimal (no leading 0x) pre-shared-key matching the one used on the broker to use TLS-PSK encryption support. --psk-identity must also be provided to enable TLS-PSK.

--psk-identity

The client identity to use with TLS-PSK support. This may be used instead of a username if the broker is configured to do so.

-q, --qos

Specify the quality of service to use for messages, from 0, 1 and 2. Defaults to 1.

--quiet

If this argument is given, no runtime errors will be printed. This excludes any error messages given in case of invalid user input (e.g. using --port without a port).

--tls-alpn

Provide a protocol to use when connecting to a broker that has multiple protocols available on a single port, e.g. MQTT and WebSockets.

--tls-engine

A valid openssl engine id. These can be listed with openssl engine command.

See also --keyform.

--tls-engine-kpass-sha1

SHA1 of the private key password when using an TLS engine. Some TLS engines such as the TPM engine may require the use of a password in order to be accessed. This option allows a hex encoded SHA1 hash of the password to the engine directly, instead of the user being prompted for the password.

See also --tls-engine.

--tls-use-os-certs

If used, this will load and trust the OS provided CA certificates. This can be used in conjunction with --cafile and --capath and can be used on its own to enable TLS mode. This will be set by default if -L mqtts://... is used, or if port is 8883 and no other certificate options are used.

--tls-version

Choose which TLS protocol version to use when communicating with the broker. Valid options are tlsv1.3, tlsv1.2 and tlsv1.1. The default value is tlsv1.2. Must match the protocol version used by the broker.

-u, --username

Provide a username to be used for authenticating with the broker. See also the --pw argument.

--unix

Connect to a broker through a local unix domain socket instead of a TCP socket. This is a replacement for -h and -L. For example: mosquitto_ctrl --unix /tmp/mosquitto.sock ...

See the socket_domain option in mosquitto.conf(5) to configure Mosquitto to listen on a unix socket.

-V, --protocol-version

Specify which version of the MQTT protocol should be used when connecting to the rmeote broker. Can be 5, 311, 31, or the more verbose mqttv5, mqttv311, or mqttv31. Defaults to 311.

STATUT DE SORTIE

mosquitto_sub renvoie zéro en cas de succès, ou une valeur non nulle en cas d'erreur. Si la connexion est refusée par le broker au niveau MQTT, le code de sortie est le code de raison CONNACK. Si une autre erreur se produit, le code de sortie est une valeur de retour de libmosquitto.

Codes CONNACK MQTT v3.1.1 :

•0 Succès
•1 Connexion refusée : Mauvais protocole (version)
•2 Connexion refusée : Identifiant rejeté
•3 Connexion refusée : Serveur indisponible
•4 Connexion refusée : Nom d'utilisateur / mot de passe incorrect
•5 Connexion refusée : Non autorisé

Codes CONNACK MQTT v5 :

•0 Succès
•128 Erreur non spécifiée
•129 Paquet malformé
•130 Erreur de protocole
•131 Erreur spécifique à l'implémentation
•132 Version de protocole non prise en charge
•133 ID client invalide
•134 Nom d'utilisateur ou mot de passe incorrect
•135 Non autorisé
•136 Serveur indisponible
•137 Serveur occupé
•138 Bannière
•139 Arrêt du serveur
•140 Méthode d'authentification incorrecte
•141 Timeout keep-alive
•142 Session reprise
•143 Filtre de sujet invalide
•144 Nom de sujet invalide
•147 Réception maximale dépassée
•148 Alias de sujet invalide
•149 Paquet trop grand
•148 Taux de messages trop élevé
•151 Quota dépassé
•152 Action administrative
•153 Format de charge utile invalide
•154 Retain non pris en charge
•155 QoS non pris en charge
•156 Utiliser un autre serveur
•157 Serveur déplacé
•158 Abonnements partagés non pris en charge
•159 Taux de connexion dépassé
•160 Temps de connexion maximum
•161 IDs d'abonnement non pris en charge
•162 Abonnements génériques non pris en charge
