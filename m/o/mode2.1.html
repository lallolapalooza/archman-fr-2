MODE2(1) 0.10.2" MODE2(1)

NOM

mode2 - Afficher la sortie du noyau disponible pour les pilotes LIRC

SYNTAXE

mode2 --driver <pilote> [--device <périphérique>] [autres options]

mode2 --raw --device <périphérique> [autres options]

mode2 --driver <pilote> --list-devices

DESCRIPTION

Le but initial de ce programme était de vérifier le fonctionnement du matériel récepteur LIRC home-brew et de visualiser la forme d'onde IR de la télécommande sans oscilloscope coûteux. Au fil du temps, mode2 a évolué pour devenir un outil générique permettant de vérifier quel type de sortie le noyau met à disposition pour lirc.

mode2 imprimera simplement les longueurs d'impulsion et d'espace sur la sortie standard pour les pilotes prenant en charge LIRC_MODE_MODE2. Pour les pilotes prenant en charge LIRC_MODE_LIRCCODE tels que les cartes TV et le pilote irman, il écrira les valeurs décodées, entières.

Depuis la version 0.9.4, mode2 peut également lister les périphériques disponibles pour un pilote donné. Cela nécessite une prise en charge de l'énumération, disponible dans la plupart des pilotes mais pas tous.

Avec le pilote correct, mode2 devrait toujours fonctionner. Sans pilote, l'option --raw devrait toujours fonctionner pour les périphériques /dev/lirc*. Au moment de la rédaction, les périphériques USB fonctionnent également dans la plupart des cas. Cependant, comme il est difficile d'obtenir le chemin du périphérique USB, ceux-ci sont normalement mieux accessibles en utilisant un pilote.

Tous les pilotes ne nécessitent pas de périphérique.

OPTIONS

-d --device=périphérique
Lire depuis le périphérique donné.
-H --driver=pilote
Utiliser le pilote donné.
-m --mode
Écrire les données d'impulsion/espace sous forme de fichiers de configuration bruts. N'affecte pas les pilotes LIRCCODE.
-s --scope=temps
Activer l'affichage type 'scope' avec temps microsecondes par caractère. N'affecte pas les pilotes lirccode.
-k --keep-root
Ne pas abandonner les privilèges root après l'ouverture du périphérique. Voir EXECUTION EN TANT QUE ROOT.
-l --list-devices
Lister tous les périphériques disponibles pour le pilote donné. Nécessite une prise en charge non présente dans tous les pilotes.
-g --gap=temps
Traiter les espaces plus longs que temps comme la séparation. Le temps est en microsecondes.
-r --raw
Accéder au périphérique directement. Ceci est principalement destiné à être utilisé avec les pilotes rc du noyau, c'est-à-dire lors de l'accès aux périphériques /dev/lirc*. L'utilisation d'autres périphériques peut fonctionner, mais est généralement non définie.
-A --driver-options=clé:valeur[|clé:valeur...]
Définir l'option spécifique au pilote nommée clé à la valeur donnée.
-U --plugindir=répertoire
Charger les pilotes depuis le répertoire. Voir CHARGEMENT DES PILOTES.
-O, --options-file <chemin>
Fichier contenant les valeurs par défaut pour toutes les options. Un chemin relatif est interprété à partir du répertoire courant. Voir [FICHIERS] ci-dessous.
-D --loglevel=niveau
Détermine la quantité d'informations de journalisation. [niveau] peut être un niveau symbolique syslog : 'error', 'warning', 'info', 'notice' ou 'debug'. lirc définit également trois niveaux supplémentaires 'trace', 'trace1' et 'trace2' qui fournissent encore plus de messages ('trace2' produisant le plus). Cependant, dans le journal, ces messages sont marqués comme 'debug'. Le niveau peut également être un entier dans la plage de 3 (presque aucun message) à 10.
-h --help
Afficher le résumé d'utilisation.
-v --version
Afficher la version.

EXECUTION EN TANT QUE ROOT

Dans de nombreux cas, mode2 doit être exécuté en tant que root pour accéder aux périphériques non disponibles pour les utilisateurs réguliers. D'autre part, l'exécution en tant que root crée des problèmes tels que des fichiers journaux appartenant à root, des problèmes de sécurité, etc.

Pour faire face à cela, mode2 abandonne par défaut les privilèges root après l'ouverture du périphérique d'entrée. Cette prise en charge repose sur le fait que les autorisations root sont acquises à l'aide de sudo(1), par exemple en utilisant

        $ sudo mode2 --raw /dev/lirc0
Si vous n'utilisez pas sudo, le même comportement pourrait être accompli en utilisant la variable d'environnement SUDO_USER, par exemple 
        # SUDO_USER=$LOGNAME mode2 --raw /dev/lirc0
L'option --keep-root empêchera mode2 de conserver les privilèges root pendant toute son exécution.

EXEMPLES

Invoqué avec un pilote de type MODE2, mode2 imprime les temporisations espace/marque :

     al@snorken $ ./mode2 --driver default --device /dev/lirc0
     Using driver default on device /dev/lirc0
     Trying device: /dev/lirc0
     Using device: /dev/lirc0
     pulse 2750
     space 800
     pulse 500
     space 350
     pulse 550
     space 350
     pulse 550
     ...
Invoqué avec un pilote de type LIRCCODE, mode2 imprime les valeurs décodées :
     $ ./mode2 --driver atilibusb
     Using driver atilibusb on device /dev/lirc0
     Trying device: /dev/bus/usb/001/007
     Using device: /dev/bus/usb/001/007
     code: 0x14709b0000
     code: 0x14709b0000
     code: 0x14709b0000
     code: 0x14709b0000
     code: 0x14709b0000
     ...
Invoqué en utilisant mode2 --list-devices pour le pilote devinput avec
un seul périphérique USB X10 RF branché :
    $ ./mode2 --list-devices --driver devinput
    /dev/input/event12 [0bc7:0006] X10 WTI RF receiver vers:  1.10 serial: ?
    /dev/input/by-id/usb-X10_WTI_RF_receiver-event-if00 -> ../event12
    /dev/input/by-path/pci-0000:0b:00.0-usb-0:1:1.0-event -> ../event12

CHARGEMENT DES PILOTES

Les pilotes sont chargés dynamiquement. Le chemin de recherche utilisé pour cela est déterminé par (priorité décroissante) :

  • L'option --plugindir.
  • L'entrée 'plugindir' dans la section [lircd] du fichier lirc_options.conf.
  • La variable d'environnement LIRC_PLUGINDIR.
  • Un chemin par défaut codé en dur (/usr/lib/lirc/plugins).

ENVIRONNEMENT

LIRC_LOGLEVEL
Utilisé comme solution de repli lorsqu'il n'y a pas d'option --loglevel présente. La syntaxe est la même que pour --loglevel, voir OPTIONS.

FICHIERS

/etc/lirc/lirc_options.conf
Le fichier d'options contenant les valeurs par défaut pour les options de ligne de commande dans la section [mode2]. Pour certaines valeurs, y compris debug, plugindir, driver et device, mode2 se rabat sur la section [lircd] si elles ne sont pas trouvées dans [mode2].
L'emplacement de ce fichier peut être modifié à l'aide de l'option de ligne de commande -O/--options-file ou à l'aide de la variable d'environnement LIRC_OPTIONS_PATH.
~/.cache/mode2.log
Journal de débogage. La définition de la variable d'environnement XDG_CACHE_HOME déplace ce fichier vers $XDG_CACHE_HOME/mode2.log. La quantité de journalisation respecte la variable d'environnement LIRC_LOGLEVEL, se rabattant par défaut sur la valeur debug dans lirc_options.conf.
