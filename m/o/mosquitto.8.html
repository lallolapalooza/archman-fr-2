MOSQUITTO(8) Commandes de gestion système MOSQUITTO(8)

NOM

mosquitto - un broker MQTT

SYNTAXE

mosquitto [-c fichier_de_configuration] [-d | --daemon] [-p numéro_de_port] [-v]

DESCRIPTION

mosquitto est un broker pour le protocole MQTT version 5.0/3.1.1/3.1.

OPTIONS

-c, --config-file

Charge la configuration depuis un fichier. Si absent, le broker écoute sur le port 1883 lié à l'interface de bouclage, et les valeurs par défaut décrites dans mosquitto.conf(5) sont utilisées.

Important
Voir l'option -p pour une description des changements de comportement entre 1.6.x et 2.0.

-d, --daemon

Exécute mosquitto en arrière-plan en tant que démon. Tout autre comportement reste le même.

-p, --port

Écoute sur le port spécifié. Peut être spécifié jusqu'à 10 fois pour ouvrir plusieurs sockets écoutant sur différents ports.

Important
Dans la version 1.6.x et antérieures, l'écoute définie par -p (ou le port par défaut de 1883) était liée à toutes les interfaces et donc accessible depuis n'importe quel réseau. Elle pouvait également être utilisée en combinaison avec -c.

À partir de la version 2.0, les écoutes définies avec -p sont liées uniquement à l'interface de bouclage, et ne peuvent donc être connectées que depuis la machine locale. Si -p est utilisé et qu'une écoute est définie dans un fichier de configuration, les options -p sont IGNORÉES.

-v, --verbose

Utilise une journalisation détaillée. Ceci est équivalent à définir log_type sur all dans le fichier de configuration. Ceci remplace toutes les options de journalisation données dans le fichier de configuration.

CONFIGURATION

Le broker peut être configuré à l'aide d'un fichier de configuration tel que décrit dans mosquitto.conf(5) et c'est le point d'information principal pour mosquitto. Les fichiers requis pour le support SSL/TLS sont décrits dans mosquitto-tls(7).

LIMITATIONS DE PLATEFORME

Certaines versions de Windows ont des limitations sur le nombre de connexions simultanées en raison de l'API Windows utilisée. Dans les versions modernes de Windows, par exemple Windows 10 ou Windows Server 2019, cela correspond à environ 8192 connexions. Dans les versions antérieures de Windows, cette limite est de 2048 connexions.

SUPPORT MQTT

Mosquitto prend en charge MQTT v5.0, v3.1.1 et v3.1.

MQTT v5.0

Mosquitto offre un support complet de MQTT v5.0, mais certaines fonctionnalités ne sont pas utilisées directement. Les sections suivantes décrivent les nouvelles fonctionnalités et expliquent où Mosquitto n'utilise pas une fonctionnalité.

Fonctionnalités

Authentification améliorée

L'authentification MQTT de base utilise des vérifications de nom d'utilisateur/mot de passe. L'authentification améliorée permet d'intégrer différents schémas d'authentification dans MQTT, même ceux avec des processus en plusieurs étapes. Les clients demandent un type d'authentification particulier et si le broker est configuré pour ce schéma, l'authentification se poursuit. Mosquitto prend en charge l'authentification améliorée via des plugins.

Gestion des erreurs

La plupart des paquets MQTT ont maintenant un concept de code de raison qui indique le succès ou l'échec, et quelle est la nature de l'échec. Mosquitto offre un support complet des codes de raison, mais n'utilise pas la fonctionnalité de chaîne de raison qui peut être utilisée pour fournir une chaîne d'erreur lisible par l'homme pour expliquer le code de raison.

Contrôle de flux

Le nombre de messages "en transit" pour QoS 1 et QoS 2 peut être contrôlé à la fois par le client et le broker.

Requête / réponse

MQTT v5.0 ajoute un modèle requête/réponse qui permet à un client de publier un message et d'indiquer aux abonnés de ce message où publier une réponse.

Redirection de serveur

La redirection de serveur est le concept qui consiste à dire à un client de se connecter à un broker MQTT différent, soit lors de la connexion (CONNECT), soit avec une déconnexion initiée par le broker. Mosquitto n'utilise pas actuellement cette fonctionnalité.

Abonnements partagés

Lorsque plusieurs clients s'abonnent au même abonnement partagé, un seul client du groupe recevra chaque message, ce qui permet de distribuer la charge de travail.

VERSIONS DU PROTOCOLE

MQTT v3.1.1

Mosquitto offre un support complet du protocole MQTT v3.1.1.

MQTT v3.1

Mosquitto offre un support complet du protocole MQTT v3.1.

MQTT v3

MQTT v3 est une version obsolète du protocole qui ne prend pas en charge l'authentification par nom d'utilisateur/mot de passe et utilisait le drapeau clean start dans le paquet CONNECT, qui ne s'appliquait qu'au début d'une session. Un client MQTT v3 pourra se connecter avec succès à une instance Mosquitto qui ne nécessite pas d'authentification.

STATUT DU BROKER

Les clients peuvent obtenir des informations sur le broker en s'abonnant aux rubriques de la hiérarchie $SYS comme suit. Les rubriques marquées comme statiques ne sont envoyées qu'une seule fois par client lors de l'abonnement. Toutes les autres rubriques sont mises à jour toutes les sys_interval secondes. Si sys_interval est égal à 0, alors les mises à jour ne sont pas envoyées.

Notez que si vous utilisez un client en ligne de commande pour interagir avec les rubriques $SYS et que votre shell interprète $ comme une variable d'environnement, vous devez placer la rubrique entre apostrophes singulières '$SYS/...' ou échapper le symbole dollar : \$SYS/... sinon le $SYS sera traité comme une variable d'environnement.

$SYS/broker/bytes/received

Le nombre total d'octets reçus depuis le démarrage du broker.

$SYS/broker/bytes/sent

Le nombre total d'octets envoyés depuis le démarrage du broker.

$SYS/broker/clients/connected, $SYS/broker/clients/active (obsolète)

Le nombre de clients actuellement connectés.

$SYS/broker/clients/expired

Le nombre de clients persistants déconnectés qui ont expiré et ont été supprimés via l'option persistent_client_expiration.

$SYS/broker/clients/disconnected, $SYS/broker/clients/inactive (obsolète)

Le nombre total de clients persistants (avec clean session désactivé) qui sont enregistrés sur le broker mais qui sont actuellement déconnectés.

$SYS/broker/clients/maximum

Le nombre maximum de clients qui ont été connectés au broker simultanément.

$SYS/broker/clients/total

Le nombre total de clients actifs et inactifs actuellement connectés et enregistrés sur le broker.

$SYS/broker/connection/#

Lorsque des ponts sont configurés vers/depuis le broker, la pratique courante consiste à fournir une rubrique d'état qui indique l'état de la connexion. Ceci est fourni par défaut dans $SYS/broker/connection/. Si la valeur de la rubrique est 1, la connexion est active, si 0, elle n'est pas active. Voir la section Ponts ci-dessous pour plus d'informations sur les ponts.

$SYS/broker/heap/current size

La taille actuelle de la mémoire du tas utilisée par mosquitto. Notez que cette rubrique peut être indisponible en fonction des options de compilation.

$SYS/broker/heap/maximum size

La plus grande quantité de mémoire du tas utilisée par mosquitto. Notez que cette rubrique peut être indisponible en fonction des options de compilation.

$SYS/broker/load/connections/+

La moyenne mobile du nombre de paquets CONNECT reçus par le broker sur différentes périodes. Le "+" final de la hiérarchie peut être 1min, 5min ou 15min. La valeur renvoyée représente le nombre de connexions reçues en 1 minute, moyenné sur 1, 5 ou 15 minutes.

$SYS/broker/load/bytes/received/+

La moyenne mobile du nombre d'octets reçus par le broker sur différentes périodes. Le "+" final de la hiérarchie peut être 1min, 5min ou 15min. La valeur renvoyée représente le nombre d'octets reçus en 1 minute, moyenné sur 1, 5 ou 15 minutes.

$SYS/broker/load/bytes/sent/+

La moyenne mobile du nombre d'octets envoyés par le broker sur différentes périodes. Le "+" final de la hiérarchie peut être 1min, 5min ou 15min. La valeur renvoyée représente le nombre d'octets envoyés en 1 minute, moyenné sur 1, 5 ou 15 minutes.

$SYS/broker/load/messages/received/+

La moyenne mobile du nombre de messages MQTT de tous types reçus par le broker sur différentes périodes. Le "+" final de la hiérarchie peut être 1min, 5min ou 15min. La valeur renvoyée représente le nombre de messages reçus en 1 minute, moyenné sur 1, 5 ou 15 minutes.

$SYS/broker/load/messages/sent/+

La moyenne mobile du nombre de messages MQTT de tous types envoyés par le broker sur différentes périodes. Le "+" final de la hiérarchie peut être 1min, 5min ou 15min. La valeur renvoyée représente le nombre de messages envoyés en 1 minute, moyenné sur 1, 5 ou 15 minutes.

$SYS/broker/load/publish/dropped/+

La moyenne mobile du nombre de messages de publication rejetés par le broker sur différentes périodes. Ceci montre le taux auquel les clients durables déconnectés perdent des messages. Le "+" final de la hiérarchie peut être 1min, 5min ou 15min. La valeur renvoyée représente le nombre de messages rejetés en 1 minute, moyenné sur 1, 5 ou 15 minutes.

$SYS/broker/load/publish/received/+

La moyenne mobile du nombre de messages de publication reçus par le broker sur différentes périodes. Le "+" final de la hiérarchie peut être 1min, 5min ou 15min. La valeur renvoyée représente le nombre de messages de publication reçus en 1 minute, moyenné sur 1, 5 ou 15 minutes.

$SYS/broker/load/publish/sent/+

La moyenne mobile du nombre de messages de publication envoyés par le broker sur différentes périodes. Le "+" final de la hiérarchie peut être 1min, 5min ou 15min. La valeur renvoyée représente le nombre de messages de publication envoyés en 1 minute, moyenné sur 1, 5 ou 15 minutes.

$SYS/broker/load/sockets/+

La moyenne mobile du nombre de connexions de socket ouvertes vers le broker sur différentes périodes. Le "+" final de la hiérarchie peut être 1min, 5min ou 15min. La valeur renvoyée représente le nombre de connexions de socket en 1 minute, moyenné sur 1, 5 ou 15 minutes.

$SYS/broker/messages/inflight

Le nombre de messages avec QoS>0 qui sont en attente d'accusés de réception.

$SYS/broker/messages/received

Le nombre total de messages de tout type reçus depuis le démarrage du broker.

$SYS/broker/messages/sent

Le nombre total de messages de tout type envoyés depuis le démarrage du broker.

$SYS/broker/publish/messages/dropped

Le nombre total de messages de publication rejetés en raison des limites inflight/queuing. Voir les options max_inflight_messages et max_queued_messages dans mosquitto.conf(5) pour plus d'informations.

$SYS/broker/publish/messages/received

Le nombre total de messages PUBLISH reçus depuis le démarrage du broker.

$SYS/broker/publish/messages/sent

Le nombre total de messages PUBLISH envoyés depuis le démarrage du broker.

$SYS/broker/retained messages/count

Le nombre total de messages conservés actifs sur le broker.

$SYS/broker/store/messages/count, $SYS/broker/messages/stored (obsolète)

Le nombre de messages actuellement conservés dans le stockage de messages. Cela inclut les messages conservés et les messages mis en file d'attente pour les clients durables.

$SYS/broker/store/messages/bytes

Le nombre d'octets actuellement stockés par les charges utiles des messages dans le stockage de messages. Cela inclut les messages conservés et les messages mis en file d'attente pour les clients durables.

$SYS/broker/subscriptions/count

Le nombre total d'abonnements actifs sur le broker.

$SYS/broker/version

La version du broker. Statique.

ABONNEMENTS AUX RUBRIQUES WILDCARDS

En plus de permettre aux clients de s'abonner à des rubriques spécifiques, mosquitto autorise également l'utilisation de deux caractères wildcards dans les abonnements. Le caractère + est le wildcard utilisé pour correspondre à un seul niveau de hiérarchie. Par exemple, pour une rubrique de type « a/b/c/d », les abonnements exemples suivants correspondent :

•a/b/c/d
•+/b/c/d
•a/+/c/d
•a/+/+/d
•+/+/+/+

Les abonnements suivants ne correspondent pas :

•a/b/c
•b/+/c/d
•+/+/+

Le second wildcard est le caractère # et il est utilisé pour correspondre à tous les niveaux de hiérarchie suivants. Avec une rubrique « a/b/c/d », les abonnements exemples suivants correspondent :

•a/b/c/d
•#
•a/#
•a/b/#
•a/b/c/#
•+/b/c/#

La hiérarchie $SYS ne correspond pas à un abonnement de type « # ». Si vous souhaitez observer l'intégralité de la hiérarchie $SYS, abonnez-vous à $SYS/#.

Notez que les wildcards doivent toujours être utilisés seuls, ainsi un abonnement de type « a/b+/c » n'est pas une utilisation valide d'un wildcard. Le wildcard # doit toujours être utilisé comme dernier caractère d'un abonnement.

PONTS

Plusieurs brokers peuvent être connectés ensemble grâce à la fonctionnalité de pont. Ceci est utile lorsqu'il est souhaitable de partager des informations entre différents emplacements, mais où toutes les informations ne doivent pas nécessairement être partagées. Un exemple pourrait être lorsque plusieurs utilisateurs exécutent un broker pour enregistrer la consommation d'énergie et pour d'autres raisons. La consommation d'énergie pourrait être partagée en pontant tous les brokers des utilisateurs vers un broker commun, permettant ainsi de collecter et comparer la consommation d'énergie de tous les utilisateurs. Les autres informations resteraient locales à chaque broker.

Pour plus d'informations sur la configuration des ponts, voir mosquitto.conf(5).

SIGNaux

Sur les systèmes POSIX, Mosquitto peut recevoir des signaux et agir en conséquence comme décrit ci-dessous. Pour envoyer des signaux, utilisez par exemple kill -HUP <ID du processus de mosquitto>

>

SIGHUP

Lors de la réception du signal SIGHUP, mosquitto tentera de recharger les données du fichier de configuration, en supposant que l'argument -c a été fourni lors du démarrage de mosquitto. Tous les paramètres de configuration ne peuvent pas être rechargés sans redémarrage. Voir mosquitto.conf(5) pour les détails.

Si des certificats TLS sont utilisés, mosquitto rechargera également les certificats à la réception d'un SIGHUP.

SIGUSR1

Lors de la réception du signal SIGUSR1, mosquitto écrira la base de données de persistance sur le disque. Ce signal n'est traité que si la persistance est activée.

SIGUSR2

Le signal SIGUSR2 provoque l'affichage par mosquitto de l'arborescence des abonnements actuelle, ainsi que des informations sur l'existence des messages conservés. Ceci est destiné uniquement à des fins de test et peut être supprimé à tout moment.
