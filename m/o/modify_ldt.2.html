modify_ldt(2) Manuel des appels système modify_ldt(2)

NOM

modify_ldt - obtenir ou définir une entrée LDT par processus

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNOPSIS

#include <asm/ldt.h>         /* Définition de struct user_desc */
#include <sys/syscall.h>     /* Définition des constantes SYS_* */
#include <unistd.h>
int syscall(unsigned long bytecount;
            SYS_modify_ldt, int func, void ptr[bytecount],
            unsigned long bytecount);

Note : glibc ne fournit pas d'enveloppe pour modify_ldt(), rendant nécessaire l'utilisation de syscall(2).

DESCRIPTION

modify_ldt() lit ou écrit la table des descripteurs locaux (LDT) pour un processus. La LDT est un tableau de descripteurs de segment qui peuvent être référencés par le code utilisateur. Linux permet aux processus de configurer une LDT par processus (en fait par-mm). Pour plus d'informations sur la LDT, consultez le manuel du développeur Intel ou le manuel de programmation de l'architecture AMD.

Lorsque func vaut 0, modify_ldt() lit la LDT dans la mémoire pointée par ptr. Le nombre d'octets lus est le plus petit entre bytecount et la taille réelle de la LDT, bien que le noyau puisse se comporter comme si la LDT était complétée par des octets nuls supplémentaires en fin de tableau. En cas de succès, modify_ldt() retourne le nombre d'octets lus.

Lorsque func vaut 1 ou 0x11, modify_ldt() modifie l'entrée LDT indiquée par ptr->entry_number. ptr pointe vers une structure user_desc et bytecount doit être égal à la taille de cette structure.

La structure user_desc est définie dans <asm/ldt.h> comme suit :


struct user_desc {
    unsigned int  entry_number;
    unsigned int  base_addr;
    unsigned int  limit;
    unsigned int  seg_32bit:1;
    unsigned int  contents:2;
    unsigned int  read_exec_only:1;
    unsigned int  limit_in_pages:1;
    unsigned int  seg_not_present:1;
    unsigned int  useable:1;
};

Sous Linux 2.4 et versions antérieures, cette structure était nommée modify_ldt_ldt_s.

Le champ contents est le type de segment (données, données extensibles vers le bas, code non conforme, ou code conforme). Les autres champs correspondent à leurs descriptions dans le manuel du processeur, bien que modify_ldt() ne puisse pas définir le bit matériel « accédé » décrit dans le manuel du processeur.

Un descripteur user_desc est considéré comme « vide » si read_exec_only et seg_not_present sont mis à 1 et si tous les autres champs sont à 0. Une entrée LDT peut être effacée en la définissant sur un user_desc « vide » ou, si func vaut 1, en mettant à la fois base et limit à 0.

Un segment de code conforme (c'est-à-dire avec contents==3) sera rejeté si func vaut 1 ou si seg_not_present vaut 0.

Lorsque func vaut 2, modify_ldt() lit des zéros. Ceci semble être un vestige de Linux 2.4.

VALEUR DE RETOUR

En cas de succès, modify_ldt() retourne soit le nombre réel d'octets lus (pour la lecture), soit 0 (pour l'écriture). En cas d'échec, modify_ldt() retourne -1 et définit errno pour indiquer l'erreur.

ERREURS

EFAULT
ptr pointe en dehors de l'espace d'adressage.
EINVAL
ptr est 0, ou func vaut 1 et bytecount n'est pas égal à la taille de la structure user_desc, ou func vaut 1 ou 0x11 et la nouvelle entrée LDT contient des valeurs invalides.
ENOSYS
func n'est ni 0, ni 1, ni 2, ni 0x11.

NORMES

Linux.

NOTES

modify_ldt() ne doit pas être utilisé pour le stockage local aux threads, car cela ralentit les changements de contexte et ne prend en charge qu'un nombre limité de threads. Les bibliothèques de threads devraient utiliser set_thread_area(2) ou arch_prctl(2) à la place, sauf sur des noyaux extrêmement anciens qui ne prennent pas en charge ces appels système.

L'utilisation normale de modify_ldt() est d'exécuter du code hérité 16 bits ou segmenté 32 bits. Cependant, tous les noyaux ne permettent pas l'installation de segments 16 bits.

Même sur les noyaux 64 bits, modify_ldt() ne peut pas être utilisé pour créer un segment de code en mode long (c'est-à-dire 64 bits). Le champ non documenté « lm » dans user_desc n'est pas utile et, malgré son nom, ne résulte pas en un segment en mode long.

BOGUES

Sur les noyaux 64 bits antérieurs à Linux 3.19, la définition du bit « lm » dans user_desc empêche le descripteur d'être considéré comme vide. Gardez à l'esprit que le bit « lm » n'existe pas dans les en-têtes 32 bits, mais ces noyaux défectueux remarqueront toujours le bit même lorsqu'il est défini dans un processus 32 bits.

VOIR AUSSI

arch_prctl(2), set_thread_area(2), vm86(2)
