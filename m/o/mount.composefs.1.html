NOM

mount.composefs - monter une image de système de fichiers composefs

SYNOPSIS

mount.composefs [-o OPTIONS] IMAGE REPERTOIRE_CIBLE

DESCRIPTION

Le projet composefs utilise un fichier image EROFS pour stocker les métadonnées, et un ou plusieurs répertoires séparés contenant des données de base adressées par contenu pour les fichiers réguliers.

mount.composefs monte un tel fichier EROFS en combinaison avec un ensemble donné de répertoires de base à l'emplacement spécifié. Il peut être appelé directement, ou comme aide au montage en exécutant mount -t composefs ....

OPTIONS

L'argument IMAGE fourni doit être une image de métadonnées composefs (EROFS) valide. Le REPERTOIRE_CIBLE sera utilisé comme cible de montage.

mount.composefs accepte les options de montage séparées par des deux-points lorsqu'elles sont passées via l'argument -o OPTIONS.

basedir=CHEMIN
Ce chemin sera utilisé pour résoudre les références de fichiers non vides stockées dans l'image de métadonnées composefs. Un cas d'utilisation principal est que ce soit le même chemin que celui fourni à mkcomposefs --digest-store=CHEMIN.

Plusieurs chemins peuvent être spécifiés, séparés par :.

digest=DIGEST
Le fichier image est validé pour avoir le digest fs-verity spécifié avant d'être utilisé. Cela permet une chaîne de confiance qui garantit que seules les données attendues sont visibles dans le montage.

Cette option implique également verity.

idmap=CHEMIN
Spécifiez un chemin vers un espace de noms utilisateur dont le mappage d'ID doit être utilisé. Le format typique pour ce type de chemin est /proc/<pid>/ns/user
verity
Si cela est spécifié, tous les fichiers dans IMAGE doivent spécifier un digest fs-verity, et tous les fichiers dans les répertoires de base doivent avoir un digest fs-verity correspondant.

Note : Cela nécessite la prise en charge de l'option "verity" d'overlayfs dans le noyau, qui a été ajoutée dans 6.6rc1.

ro
Monte le système de fichiers en lecture seule. Ceci est principalement utile lors de l'utilisation de upperdir car les images composefs non superposées sont naturellement en lecture seule.
rw
Remplace une option ro précédente
upperdir
Spécifiez un répertoire supérieur dans le montage overlayfs que composefs utilise. Cela permet une couche inscriptible au-dessus de l'image composefs. Voir la documentation d'overlayfs pour les détails.
workdir
Spécifie un répertoire de travail overlayfs pour accompagner upperdir.
