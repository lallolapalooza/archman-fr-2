MDB_LOAD(1) Manuel des commandes générales MDB_LOAD(1)

NOM

mdb_load - Outil d'importation d'environnement LMDB

SYNTAXE

mdb_load [-V] [-f fichier] [-n] [-s sousdb] [-N] [-T]  chemin-env

DESCRIPTION

L'utilitaire mdb_load lit depuis l'entrée standard et la charge dans l'environnement LMDB chemin-env.

L'entrée de mdb_load doit être dans le format de sortie spécifié par l'utilitaire mdb_dump(1) ou comme spécifié par l'option -T ci-dessous.

OPTIONS

-V
Écrit le numéro de version de la bibliothèque sur la sortie standard et quitte.
-a
Ajoute tous les enregistrements dans l'ordre où ils apparaissent dans l'entrée. L'entrée est supposée être déjà dans un ordre trié correct et aucun tri ou vérification de valeurs redondantes ne sera effectué. Cette option doit être utilisée pour recharger des données produites en exécutant mdb_dump sur une base de données qui utilise des fonctions de comparaison personnalisées.
-f fichier
Lit depuis le fichier spécifié au lieu de l'entrée standard.
-n
Charge une base de données LMDB qui n'utilise pas de sous-répertoires.
-s sousdb
Charge une sous-base de données spécifique. Si aucune base de données n'est spécifiée, les données sont chargées dans la base de données principale.
-N
Ne pas écraser les enregistrements existants lors du chargement dans une base de données déjà existante ; les ignorer simplement.
-T
Charge des données à partir de simples fichiers texte. L'entrée doit être constituée de paires de lignes de texte, où la première ligne de la paire est l'élément clé et la seconde ligne de la paire est son élément de donnée correspondant.

Un simple mécanisme d'échappement, où les caractères de nouvelle ligne et de barre oblique inverse (\) sont spéciaux, est appliqué à l'entrée texte. Les caractères de nouvelle ligne sont interprétés comme des séparateurs d'enregistrements. Les caractères de barre oblique inverse dans le texte seront interprétés de l'une des deux manières suivantes : Si le caractère de barre oblique inverse précède un autre caractère de barre oblique inverse, la paire sera interprétée comme une barre oblique inverse littérale. Si le caractère de barre oblique inverse précède tout autre caractère, les deux caractères suivant la barre oblique inverse seront interprétés comme une spécification hexadécimale d'un seul caractère ; par exemple, \0a est un caractère de nouvelle ligne dans la table des caractères ASCII.

Pour cette raison, toutes les barres obliques inverses ou les caractères de nouvelle ligne qui se produisent naturellement dans l'entrée texte doivent être échappés pour éviter une mauvaise interprétation par mdb_load.

DIAGNOSTICS

Le statut de sortie est zéro s'il n'y a pas d'erreurs. Les erreurs entraînent un statut de sortie non nul et un message de diagnostic écrit sur la sortie d'erreur standard.
