MDSEARCH(1) Commandes utilisateur MDSEARCH(1)

NOM

mdsearch - Exécute des recherches Spotlight sur un serveur SMB

SYNTAXE

mdfine {serveur} {nompartage} {requête} [-p, --path=CHAINE] [-L, --live] [-?|--help] [--usage] [-d|--debuglevel=NIVEAUDEBUG] [--debug-stdout] [--configfile=FICHIERCONFIG] [--option=nom=valeur] [-l|--log-basename=FICHIERLOGBASE] [--leak-report] [--leak-report-full] [-R|--name-resolve=ORDRERESOLNAME] [-O|--socket-options=OPTIONSOCKET] [-m|--max-protocol=MAXPROTOCOLE] [-n|--netbiosname=NOMETBIOS] [--netbios-scope=SCOPE] [-W|--workgroup=GROUPE] [--realm=DOMAINE] [-U|--user=[DOMAINE/]NOMUTILISATEUR[%MOTDEPASSE]] [-N|--no-pass] [--password=CHAINE] [--pw-nt-hash] [-A|--authentication-file=FICHIER] [-P|--machine-pass] [--simple-bind-dn=DN] [--use-kerberos=desired|required|off] [--use-krb5-ccache=CCACHE] [--use-winbind-ccache] [--client-protection=sign|encrypt|off] [-V|--version]

DESCRIPTION

Cet outil fait partie de la suite samba(1).

mdsearch est un utilitaire simple pour exécuter des recherches Spotlight sur un serveur SMB exécutant le service RPC Spotlight mdssvc.

OPTIONS

serveur

Nom ou adresse IP du serveur SMB auquel se connecter.

nompartage

Nom d'un partage sur le serveur.

requête

La syntaxe de l'expression de requête est une forme simplifiée de globbing de noms de fichiers familière aux utilisateurs de shell. Les requêtes ont le format suivant :

attribut=="valeur"

Pour les requêtes sur un serveur Samba avec Spotlight activé utilisant le backend Elasticsearch, la liste des attributs de métadonnées pris en charge est fournie par le fichier de mappage d'attributs JSON, généralement installé à /usr/share/samba/mdssvc/elasticsearch_mappings.json

-p PATH, --path=PATH

Chemin côté serveur à rechercher, par défaut "/"

-L, --live

La requête reste en cours d'exécution.

-?|--help

Imprime un résumé des options de la ligne de commande.

--usage

Affiche un bref message d'utilisation.

-d|--debuglevel=niveau

niveau est un entier de 0 à 10. La valeur par défaut si ce paramètre n'est pas spécifié est 1 pour les applications client.

Plus cette valeur est élevée, plus les journaux contiendront d'informations sur les activités du serveur. Au niveau 0, seuls les erreurs critiques et les avertissements graves seront enregistrés. Le niveau 1 est un niveau raisonnable pour une utilisation quotidienne - il génère une petite quantité d'informations sur les opérations effectuées.

Les niveaux supérieurs à 1 généreront une quantité considérable de données de journalisation et ne doivent être utilisés que lors de l'investigation d'un problème. Les niveaux supérieurs à 3 sont conçus pour être utilisés uniquement par les développeurs et génèrent d'énormes quantités de données de journalisation, dont la plupart sont extrêmement cryptiques.

Notez que la spécification de ce paramètre ici remplacera le paramètre log level du fichier /etc/samba/smb.conf.

--debug-stdout

Redirigera la sortie de débogage vers STDOUT. Par défaut, tous les clients enregistrent sur STDERR.

--configfile=<fichier de configuration>

Le fichier spécifié contient les détails de configuration requis par le client. Les informations de ce fichier peuvent être générales pour le client et le serveur ou ne fournir que des options spécifiques au client telles que client smb encrypt. Voir /etc/samba/smb.conf pour plus d'informations. Le nom du fichier de configuration par défaut est déterminé lors de la compilation.

--option=<nom>=<valeur>

Définit l'option smb.conf(5) "<nom>" à la valeur "<valeur>" depuis la ligne de commande. Cela remplace les valeurs par défaut compilées et les options lues dans le fichier de configuration. Si un nom ou une valeur inclut un espace, entourez tout --option=nom=valeur de guillemets.

-l|--log-basename=répertoire_journal

Nom de base du répertoire pour les fichiers de journal/débogage. L'extension ".progname" sera ajoutée (par exemple, log.smbclient, log.smbd, etc...). Le fichier journal n'est jamais supprimé par le client.

--leak-report

Active le rapport de fuite talloc à la sortie.

--leak-report-full

Active le rapport complet de fuite talloc à la sortie.

-V|--version

Affiche le numéro de version du programme.

-U|--user=[DOMAINE\]NOMUTILISATEUR[%MOTDEPASSE]

Définit le nom d'utilisateur SMB ou le nom d'utilisateur et le mot de passe.

Si %MOTDEPASSE n'est pas spécifié, l'utilisateur sera invité à le saisir. Le client vérifiera d'abord la variable d'environnement USER (qui est également autorisée à contenir le mot de passe séparé par un %), puis la variable LOGNAME (qui n'est pas autorisée à contenir de mot de passe) et si l'un ou l'autre existe, la valeur sera utilisée. Si ces variables d'environnement ne sont pas trouvées, le nom d'utilisateur trouvé dans un cache d'informations d'identification Kerberos peut être utilisé.

Une troisième option consiste à utiliser un fichier d'informations d'identification contenant le mot de passe en clair du nom d'utilisateur et du mot de passe. Cette option est principalement fournie pour les scripts où l'administrateur ne souhaite pas passer les informations d'identification sur la ligne de commande ou via des variables d'environnement. Si cette méthode est utilisée, assurez-vous que les autorisations du fichier restreignent l'accès aux utilisateurs non désirés. Voir le paramètre -A pour plus de détails.

Soyez prudent lorsque vous incluez des mots de passe dans les scripts ou que vous passez des valeurs fournies par l'utilisateur sur la ligne de commande. Pour des raisons de sécurité, il est préférable de laisser l'outil client Samba demander le mot de passe si nécessaire, ou d'obtenir le mot de passe une fois avec kinit.

Bien que Samba tente de supprimer le mot de passe du titre de processus (tel qu'affiché dans ps), cela se produit après le démarrage et est donc sujet à une course.

-N|--no-pass

Si spécifié, ce paramètre supprime l'invite normale de mot de passe du client à l'utilisateur. Ceci est utile lors de l'accès à un service qui ne nécessite pas de mot de passe.

Sauf si un mot de passe est spécifié sur la ligne de commande ou si ce paramètre est spécifié, le client demandera un mot de passe.

Si un mot de passe est spécifié sur la ligne de commande et que cette option est également définie, le mot de passe sur la ligne de commande sera silencieusement ignoré et aucun mot de passe ne sera utilisé.

--password

Spécifie le mot de passe sur la ligne de commande.

Soyez prudent lorsque vous incluez des mots de passe dans les scripts ou que vous passez des valeurs fournies par l'utilisateur sur la ligne de commande. Pour des raisons de sécurité, il est préférable de laisser l'outil client Samba demander le mot de passe si nécessaire, ou d'obtenir le mot de passe une fois avec kinit.

Si --password n'est pas spécifié, l'outil vérifiera la variable d'environnement PASSWD, suivie de PASSWD_FD qui est censé contenir un descripteur de fichier (FD) ouvert.

Enfin, il vérifiera PASSWD_FILE (contenant un chemin de fichier à ouvrir). Le fichier ne doit contenir que le mot de passe. Assurez-vous que les autorisations du fichier restreignent l'accès aux utilisateurs non désirés !

Bien que Samba tente de supprimer le mot de passe du titre de processus (tel qu'affiché dans ps), cela se produit après le démarrage et est donc sujet à une course.

--pw-nt-hash

Le mot de passe fourni est le hachage NT.

-A|--authentication-file=nomfichier

Cette option permet de spécifier un fichier à partir duquel lire le nom d'utilisateur et le mot de passe utilisés dans la connexion. Le format du fichier est : 
nomutilisateur = <valeur>
motdepasse = <valeur>
domaine   = <valeur>

Assurez-vous que les autorisations du fichier restreignent l'accès aux utilisateurs non désirés !

-P|--machine-pass

Utilise le mot de passe du compte machine stocké.

--simple-bind-dn=DN

DN à utiliser pour une liaison simple.

--use-kerberos=desired|required|off

Ce paramètre détermine si les outils client Samba tentent de s'authentifier via Kerberos. Pour l'authentification Kerberos, vous devez utiliser des noms DNS plutôt que des adresses IP lors de la connexion à un service. Par défaut, les outils client Samba tentent d'utiliser le cache d'informations d'identification Kerberos par défaut (ccache). Si le ccache n'existe pas ou si l'option -U|--user a été spécifiée, les clients demanderont la saisie d'un mot de passe et obtiendront un ticket Kerberos (kinit) pour vous. Si vous souhaitez utiliser un cache d'informations d'identification Kerberos alternatif, utilisez l'option --use-krb5-ccache.

Notez que la spécification de ce paramètre ici remplacera le paramètre client use kerberos du fichier /etc/samba/smb.conf.

--use-krb5-ccache=CCACHE

Spécifie l'emplacement du cache d'informations d'identification pour l'authentification Kerberos.

Cela appliquera --use-kerberos=required.

--use-winbind-ccache

Essayer d'utiliser le cache d'identification par winbind.

--client-protection=sign|encrypt|off

Définit la protection de connexion que l'outil client doit utiliser.

Notez que la spécification de ce paramètre ici remplacera le paramètre client protection du fichier /etc/samba/smb.conf.

Si vous avez besoin d'un contrôle plus précis, vous pouvez utiliser : --option=clientsmbencrypt=OPTION, --option=clientipcsigning=OPTION, --option=clientsigning=OPTION.

EXEMPLES

Rechercher tous les attributs de métadonnées indexés, correspondance exacte :

      '*=="Samba"'

Rechercher tous les attributs de métadonnées indexés, correspondance préfixée :

      '*=="Samba*"'

Rechercher par nom de fichier :

      'kMDItemFSName=="Samba*"'

Rechercher par date :

      'kMDItemFSContentChangeDate<$time.iso(2018-10-01T10:00:00Z)'

Rechercher le contenu des fichiers :

      'kMDItemTextContent=="Samba*"'

Expressions :

      kMDItemFSName=="Samba*"||kMDItemTextContent=="Tango*"'
