MD4(3) Manuel des fonctions de bibliothèque MD4(3)

NOM

MD4Init, MD4Update, MD4Pad, MD4Final, MD4Transform, MD4End, MD4File, MD4FileChunk, MD4Data — calculer la condensation de message « MD4 » de RSA Data Security, Inc.

BIBLIOTHÈQUE

Bibliothèque de support pour la condensation de message (MD4, MD5, etc.) (libmd, -lmd)

SYNTAXE

#include <sys/types.h>
#include <md4.h>

void
MD4Init(MD4_CTX *context);

void
MD4Update(MD4_CTX *context, const uint8_t *data, size_t len);

void
MD4Pad(MD4_CTX *context);

void
MD4Final(uint8_t digest[MD4_DIGEST_LENGTH], MD4_CTX *context);

void
MD4Transform(uint32_t state[4], uint8_t block[MD4_BLOCK_LENGTH]);

char *
MD4End(MD4_CTX *context, char *buf);

char *
MD4File(const char *filename, char *buf);

char *
MD4FileChunk(const char *filename, char *buf, off_t offset, off_t length);

char *
MD4Data(const uint8_t *data, size_t len, char *buf);

DESCRIPTION

Les fonctions MD4 calculent une somme de contrôle cryptographique de 128 bits (condensation) pour un nombre quelconque d'octets d'entrée. Une somme de contrôle cryptographique est une fonction de hachage à sens unique, c'est-à-dire que vous ne pouvez pas trouver (sauf par recherche exhaustive) l'entrée correspondant à une sortie donnée. Le résultat net est une « empreinte digitale » des données d'entrée, qui ne révèle pas l'entrée réelle.

MD2 est le plus lent, MD4 est le plus rapide et MD5 est quelque part au milieu. MD2 ne peut être utilisé que pour Privacy-Enhanced Mail. MD4 a été critiqué pour être trop faible, donc MD5 a été développé en réponse comme « MD4 avec des ceintures de sécurité ». MD4 et MD5 ont été cassés ; ils ne devraient être utilisés que lorsque cela est nécessaire pour des raisons de compatibilité ascendante. Les attaques sur MD4 et MD5 visent toutes deux à trouver des « collisions » - c'est-à-dire plusieurs entrées qui hachées vers la même valeur ; il est toujours peu probable qu'un attaquant puisse déterminer l'entrée exacte d'origine étant donné une valeur de hachage.

Les fonctions MD4Init(), MD4Update(), et MD4Final() sont les fonctions principales. Allouez un MD4_CTX, initialisez-le avec MD4Init(), traitez les données avec MD4Update(), et extrayez enfin le résultat en utilisant MD4Final().

La fonction MD4Pad() peut être utilisée pour appliquer un remplissage au digest du message comme dans MD4Final(), mais le contexte actuel peut toujours être utilisé avec MD4Update().

La fonction MD4Transform() est utilisée par MD4Update() pour hacher des blocs de 512 bits et constitue le cœur de l'algorithme. La plupart des programmes devraient utiliser l'interface fournie par MD4Init(), MD4Update() et MD4Final() au lieu d'appeler MD4Transform() directement.

MD4End() est un wrapper pour MD4Final() qui convertit la valeur de retour en une chaîne ASCII de MD4_DIGEST_STRING_LENGTH caractères (y compris le '\0' final) représentant les 128 bits en hexadécimal.

MD4File() calcule le digest d'un fichier et utilise MD4End() pour retourner le résultat. Si le fichier ne peut pas être ouvert, un pointeur nul est retourné.

MD4FileChunk() se comporte comme MD4File() mais calcule le digest uniquement pour cette partie du fichier commençant à l'offset et continuant pendant length octets ou jusqu'à la fin du fichier, selon ce qui arrive en premier. Une length de zéro peut être spécifiée pour lire jusqu'à la fin du fichier. Une length ou un offset négatif sera ignoré. MD4Data() calcule le digest d'un bloc de données en mémoire et utilise MD4End() pour retourner le résultat.

Lors de l'utilisation de MD4End(), MD4File(), MD4FileChunk(), ou MD4Data(), l'argument buf peut être un pointeur nul, auquel cas la chaîne retournée est allouée avec malloc(3) et devra par la suite être explicitement désallouée en utilisant free(3) après utilisation. Si l'argument buf n'est pas nul, il doit pointer vers au moins MD4_DIGEST_STRING_LENGTH caractères d'espace tampon.

HISTORIQUE

Ces fonctions sont apparues dans OpenBSD 2.0 et NetBSD 1.3.

AUTEURS

Les routines MD4 originales ont été développées par RSA Data Security, Inc., et publiées dans les références ci-dessus. Ce code est dérivé d'une implémentation du domaine public écrite par Colin Plumb.

Les fonctions d'aide MD4End(), MD4File(), MD4FileChunk(), et MD4Data() sont dérivées de code écrit par Poul-Henning Kamp.

BOGUES

Des collisions ont été trouvées pour les versions complètes de MD4 et de MD5. L'utilisation de sha2(3) est recommandée à la place.
