NOM

mdcat - Rendu du Markdown CommonMark dans les terminaux texte

SYNTAXE

mdcat [OPTIONS] [FICHIER]...

mdless [OPTIONS] [FICHIER]...

DESCRIPTION

mdcat rend les FICHIERs Markdown en dialecte CommonMark dans les terminaux texte avec un formatage sophistiqué. Si aucun FICHIER n'est donné, ou si FICHIER est '-', il lit depuis l'entrée standard.

Si invoqué sous le nom mdless, il utilise automatiquement un pagineur pour afficher la sortie, voir ci-dessous.

CommonMark et support terminal

mdcat prend en charge toute la syntaxe CommonMark de base plus quelques extensions, met en surbrillance la syntaxe dans les blocs de code, et affiche les liens en ligne et même les images en ligne dans certains programmes de terminal. Dans iTerm2, il ajoute également des marques de saut pour les titres de section.

Voir la section Support terminal ci-dessous pour une liste des programmes de terminal pris en charge et de leurs fonctionnalités.

Détection du terminal

Pour activer les extensions de formatage telles que les images en ligne, mdcat doit détecter le programme de terminal, en vérifiant les variables d'environnement suivantes dans l'ordre donné :

1.$TERM
2.$TERM_PROGRAM
3.$TERMINOLOGY

Pour certains terminaux, mdcat vérifie également $TERM_PROGRAM_VERSION pour déterminer si le terminal prend en charge l'ensemble des fonctionnalités attendues.

Voir la section ENVIRONNEMENT ci-dessous pour une description détaillée de chaque variable d'environnement.

Pagination

mdcat peut rendre la sortie dans un pagineur ; c'est le comportement par défaut lorsqu'il est exécuté sous le nom mdless. Les variables d'environnement $MDCAT_PAGER et $PAGER contrôlent le pagineur utilisé.

Notez que les pagineurs courants ne prennent pas en charge les codes de terminal propriétaires pour, par exemple, le support des images. mdcat se rabat donc sur le formatage ANSI pur lorsque la pagination est activée. En particulier, cela désactive tout support d'image qui repose sur des codes d'échappement propriétaires.

Support des images

Dans iTerm2, kitty, Terminology, WezTerm et VSCode (version 1.80 ou plus récente), mdcat affiche les images en ligne. mdcat prend en charge la plupart des formats d'image standard par défaut.

mdcat ignore silencieusement les images de plus de 100 MiB, sous l'hypothèse que des images de cette taille ne peuvent pas raisonnablement être rendues dans un terminal.

Support SVG

Dans Terminology, mdcat rend également les images SVG, en utilisant le support intégré de Terminology.

Dans iTerm2, kitty, VSCode et WezTerm, mdcat rend les images SVG en graphiques pixellisés à l'aide de la bibliothèque resvg https://github.com/RazrFalcon/resvg. Actuellement, cette bibliothèque ne prend en charge que le SVG 1, et seulement son sous-ensemble statique ; voir Support SVG https://github.com/RazrFalcon/resvg#svg-support pour plus de détails. Bien que cela suffise pour la plupart des images SVG simples, les images SVG complexes peuvent ne pas être rendues ou être rendues de manière incomplète.

Pour les fichiers SVG locaux, mdcat s'appuie sur l'extension de fichier pour identifier les images SVG. Pour les images distantes provenant d'URL HTTP(S), mdcat inspecte l'en-tête Content-Type pour identifier les images SVG.

Support HTTP/HTTPS

mdcat récupère les images depuis les URL HTTP(S) pour le rendu si le terminal sous-jacent prend en charge le rendu d'images ; passez l'option --local pour désactiver cela et forcer mdcat à n'utiliser que les images du système de fichiers local. Dans ce cas, les images distantes sont rendues comme des hyperliens.

Notez que certains terminaux (par ex. Terminology) rendent directement les images depuis les URL et ne nécessitent pas que mdcat récupère d'abord les données de l'image. Dans ce cas, --local n'a aucun effet : mdcat passe toujours l'URL au terminal, et laisse au terminal le soin de la récupérer.

OPTIONS

-p, --paginate

Pagine la sortie de mdcat avec un pagineur comme less.

Note : lors de la pagination, mdcat utilise uniquement le formatage ANSI standard et les hyperliens, mais aucune image ou autre code de format propriétaire, car les programmes de pagineur ne prennent normalement en charge aucun de ceux-ci.

C'est le comportement par défaut lorsqu'il est exécuté sous le nom mdless.

-P, --no-pager

Ne pas paginer la sortie.

C'est le comportement par défaut lorsqu'il est exécuté sous le nom mdcat.

-c, --no-colour

Désactiver toutes les couleurs et autres styles.

--ansi

Ignorer la détection du terminal et utiliser uniquement le formatage ANSI.

--columns=COLONNES

Nombre maximal de colonnes à utiliser pour la sortie texte. Par défaut, la taille du terminal sous-jacent est utilisée si omis.

-l, --local

Ne pas accéder aux ressources distantes.

--fail

Échouer immédiatement au premier FICHIER qui ne peut pas être lu. Par défaut, mdcat continue avec le fichier suivant.

--detect-terminal

Détecter le programme de terminal, afficher son nom et quitter.

--completions=SHELL

Générer les complétions pour SHELL vers la sortie standard et quitter. 
_SHELL_ peut être l'un des : `bash`, `zsh`, `fish`, `powershell` ou `elvish`.

-h, --help

Afficher un message d'aide à l'utilisateur et quitter.

-V, --version

Afficher la version de mdcat et quitter. Le drapeau long inclut également des informations sur les fonctionnalités intégrées.

STATUT DE SORTIE

mdcat se termine avec 0 si aucune erreur ne s'est produite, ou 1 sinon.

Si exécuté sous le nom mdless ou si --paginate est donné et que le pagineur échoue à démarrer, mdcat se termine avec 128.

ENVIRONNEMENT

TERM


mdcat vérifie d'abord cette variable pour identifier le programme de terminal (voir la section Détection du terminal). Il comprend les valeurs suivantes.
•wezterm : WezTerm. Notez que WezTerm définit $TERM sur xterm-256color par défaut, et n'utilise wezterm pour $TERM que s'il est explicitement configuré pour le faire.
•xterm-kitty : kitty
•xterm-ghostty : Ghostty

Pour toutes les autres valeurs, mdcat continue en vérifiant $TERM_PROGRAM.

TERM_PROGRAM

Si $TERM n'identifie pas de manière concluante le programme de terminal, mdcat vérifie ensuite cette variable. Il comprend les valeurs suivantes :
•iTerm.app : iTerm2
•WezTerm : WezTerm
•vscode : Terminal intégré VSCode, mais uniquement si $TERM_PROGRAM_VERSION indique une version suffisante pour prendre en charge toutes les fonctionnalités requises.
•ghostty : Ghostty

Pour toutes les autres valeurs, mdcat continue en vérifiant $TERMINOLOGY.

TERM_PROGRAM_VERSION

Si $TERM_PROGRAM est vscode, mdcat vérifie cette variable pour déterminer si VSCode a une version suffisante pour prendre en charge toutes les fonctionnalités requises.

TERMINOLOGY

Si cette variable est 1, mdcat suppose que le terminal est Terminol

ogy.

Autrement mdcat termine la détection du terminal et suppose que le terminal n'est capable que du formatage ANSI standard.

COLUMNS

Le nombre de colonnes de caractères à l'écran.

mdcat n'utilise cette variable que s'il ne parvient pas à interroger la taille auprès du terminal sous-jacent.

ROWS

Le nombre de lignes de caractères à l'écran.

mdcat n'utilise cette variable que s'il ne parvient pas à interroger la taille auprès du terminal sous-jacent.

MDCAT_PAGER

Le programme de pagination à utiliser pour mdless ou si --paginate est donné.

Le programme de pagination doit prendre en charge les séquences de formatage ANSI de base, comme par exemple less -r.

La valeur de cette variable est soumise à la séparation des mots de type shell. Elle n'est soumise à aucune sorte d'expansion ou de substitution (par exemple, expansion de paramètres, substitution de processus, etc.).

Si elle est définie sur une valeur vide, mdcat désactive complètement la pagination.

PAGER

Le programme de pagination à utiliser si $MDCAT_PAGER n'est pas défini.

Soumis aux mêmes règles que $MDCAT_PAGER.

Si $PAGER et $MDCAT_PAGER sont tous deux non définis, utilisez less -r comme pagination.

http_proxy, https_proxy, HTTPS_PROXY, all_proxy, ALL_PROXY, no_proxy, NO_PROXY

Paramètres de proxy pour les requêtes HTTP effectuées par mdcat afin de récupérer des ressources distantes.

mdcat utilise curl pour ses transferts réseau, voir donc curl(1) pour ces variables.

MDCAT_LOG

Directives pour configurer la sortie des informations de traçage.

Voir https://docs.rs/tracing-subscriber/latest/tracing_subscriber/struct.EnvFilter.html#directives pour les détails de syntaxe ; utilisez MDCAT_LOG=trace pour des informations de débogage complètes, et MDCAT_LOG=pulldown_cmark_mdcat::render=trace pour tracer uniquement le rendu.

CONFORMING TO

Prise en charge de CommonMark, extensions et limitations

mdcat prend en charge la version 0.30 du CommonMark Spec https://spec.commonmark.org/, ainsi que les Listes de tâches <https://github.github.com/gfm/#task-list-items-extension-> et barré <https://github.github.com/gfm/#strikethrough-extension->, via pulldown-cmark https://github.com/raphlinus/pulldown-cmark.

mdcat ne prend pas encore en charge les notes de bas de page. La prise en charge des tableaux <https://github.github.com/gfm/#tables-extension-> est limitée ; le retour à la ligne du texte et le balisage en ligne dans les cellules de tableau ne sont pas encore pris en charge. mdcat analyse les blocs HTML et les balises en ligne mais n'applique pas de rendu spécial ; il imprime le HTML tel quel.

Prise en charge du terminal

Sauf si --no-colour est donné, mdcat traduit le texte CommonMark en texte formaté ANSI, avec des codes de formatage SGR standard et des hyperliens. Il utilise le formatage gras (SGR 1), italique (SGR 3) et barré (SGR 9), ainsi que les séquences de couleurs 4 bits standard, et OSC 8 https://gist.github.com/egmontkob/eb114294efbcd5adb1944c9f3cb5feda pour les hyperliens. Il n'utilise pas de séquences de couleurs 8 bits ou 24 bits, bien que cela puisse changer dans les futures versions.

De plus, il utilise des codes d'échappement propriétaires s'il détecte l'un des émulateurs de terminal suivants (voir les sections Détection du terminal et ENVIRONNEMENT pour plus de détails) :

•iTerm2 https://iterm2.com/ : Images en ligne ( protocole iTerm2 https://iterm2.com/documentation-images.html) et Marques https://iterm2.com/documentation-escape-codes.html.
•kitty https://github.com/kovidgoyal/kitty : Images en ligne ( protocole graphique kitty https://sw.kovidgoyal.net/kitty/graphics-protocol.html).
•Terminology http://terminolo.gy : Images en ligne (protocole terminology).
•WezTerm https://wezfurlong.org/wezterm/ : Images en ligne (protocole graphique kitty, voir ci-dessus).
•VSCode https://code.visualstudio.com/ 1.80 ou plus récent, terminal intégré : Images en ligne (protocole iTerm2, voir ci-dessus)

BUGS

Veuillez signaler les bugs à https://github.com/swsnr/mdcat/issues.

Actuellement, il n'existe aucun moyen de personnaliser les styles et les couleurs.

EXEMPLES

mdcat hello - world

Affiche le markdown dans hello, puis depuis l'entrée standard, puis depuis world.

mdless hello

Affiche le markdown depuis mdless à travers un pagineur.
