MDADM.CONF(5) Manuel des formats de fichiers MDADM.CONF(5)

NOM

mdadm.conf - configuration pour la gestion des RAID logiciels avec mdadm

SYNTAXE

/etc/mdadm.conf

DESCRIPTION

mdadm est un outil pour créer, gérer et surveiller des périphériques RAID en utilisant le pilote md sous Linux.

Certaines tâches courantes, telles que l'assemblage de tous les tableaux, peuvent être simplifiées en décrivant les périphériques et les tableaux dans ce fichier de configuration.

SYNTAXE DU FICHIER

Le fichier doit être considéré comme une collection de mots séparés par des espaces blancs (espace, tabulation ou nouvelle ligne). Tout mot commençant par un signe dièse (#) initie un commentaire et ce mot, ainsi que le reste de la ligne, est ignoré.

Les espaces peuvent être inclus dans un mot en utilisant des guillemets. Les guillemets simples (') ou doubles (") peuvent être utilisés. Tous les caractères d'un guillemet à un autre guillemet identique sont protégés et ne seront pas utilisés pour séparer des mots ou démarrer de nouvelles chaînes entre guillemets. Pour inclure un guillemet simple, il doit être entre guillemets doubles. Pour inclure un guillemet double, il doit être entre guillemets simples.

Toute ligne commençant par un espace blanc (espace ou tabulation) est traitée comme une continuation de la ligne précédente.

Les lignes vides sont ignorées, mais sinon chaque ligne (non de continuation) doit commencer par un mot-clé tel que listé ci-dessous. Les mots-clés ne sont pas sensibles à la casse et peuvent être abrégés à 3 caractères.

Les mots-clés sont :

DEVICE
Une ligne device liste les périphériques (périphériques complets ou partitions) qui pourraient contenir un composant d'un tableau MD. Lors de la recherche des composants d'un tableau, mdadm analysera ces périphériques (ou tout périphérique listé sur la ligne de commande).

La ligne device peut contenir plusieurs périphériques différents (séparés par des espaces) et chaque nom de périphérique peut contenir des jokers tels que définis dans glob(7).

De plus, il peut y avoir plusieurs lignes device dans le fichier.

Alternativement, une ligne device peut contenir l'un ou les deux mots containers et partitions. Le mot containers indiquera à mdadm de rechercher les tableaux CONTAINER assemblés et de les inclure comme source pour assembler d'autres tableaux.

Le mot partitions indiquera à mdadm de lire /proc/partitions et d'inclure tous les périphériques et partitions qui s'y trouvent. mdadm n'utilise pas les noms de /proc/partitions mais uniquement les numéros de périphérique majeur et mineur. Il analyse /dev pour trouver le nom qui correspond aux numéros.

Si aucune ligne DEVICE n'est présente dans un fichier de configuration, alors "DEVICE partitions containers" est supposé.

Par exemple :

DEVICE /dev/hda* /dev/hdc*
DEV /dev/sd*
DEVICE /dev/disk/by-path/pci*
DEVICE partitions
ARRAY
Les lignes ARRAY identifient les tableaux réels. Le second mot de la ligne peut être le nom du périphérique où le tableau est normalement assemblé, tel que /dev/md1 ou /dev/md/backup. Si le nom ne commence pas par un slash ('/'), il est traité comme étant dans /dev/md/. Alternativement, le mot <ignore> (avec les chevrons) peut être donné, auquel cas tout tableau correspondant au reste de la ligne ne sera jamais assemblé automatiquement. Si aucun nom de périphérique n'est donné, mdadm utilisera diverses heuristiques pour déterminer un nom approprié.

Les mots suivants identifient le tableau, ou identifient le tableau comme membre d'un groupe. Si plusieurs identités sont données, alors un périphérique composant doit correspondre à TOUTES les identités pour être considéré comme une correspondance. Chaque mot d'identité a une balise, un signe égal et une valeur. Les balises sont :

uuid=
La valeur doit être un UUID de 128 bits en hexadécimal, avec une ponctuation intercalée si désiré. Ceci doit correspondre à l'UUID stocké dans le superbloc.
super-minor=
La valeur est un entier indiquant le numéro mineur qui a été stocké dans le superbloc lors de la création du tableau. Lorsqu'un tableau est créé comme /dev/mdX, alors le numéro mineur X est stocké.
devices=
La valeur est une liste de noms de périphériques ou de motifs de noms de périphériques séparés par des virgules. Seuls les périphériques dont les noms correspondent à une entrée dans la liste seront utilisés pour assembler le tableau. Notez que les périphériques listés là-bas doivent également être listés sur une ligne DEVICE.
level=
La valeur est un niveau RAID. Ceci n'est normalement pas utilisé pour identifier un tableau, mais est pris en charge afin que la sortie de

mdadm --examine --scan

puisse être utilisée directement dans le fichier de configuration.

num-devices=
La valeur est le nombre de périphériques dans un tableau actif complet. Comme pour level=, ceci est principalement pour la compatibilité avec la sortie de

mdadm --examine --scan.

spares=
La valeur est un nombre de périphériques de secours attendus pour le tableau. L'unique utilisation de ce mot-clé et de cette valeur est la suivante : mdadm --monitor signalera un tableau s'il s'avère avoir moins de ce nombre de secours lorsque --monitor démarre ou lorsque --oneshot est utilisé.
spare-group=
La valeur est un nom textuel pour un groupe de tableaux. Tous les tableaux ayant le même nom spare-group sont considérés comme faisant partie du même groupe. La signification d'un groupe de tableaux est que mdadm, lorsqu'il surveille les tableaux, déplacera un disque de secours d'un tableau vers un autre tableau de ce groupe si le premier tableau avait un disque défaillant ou manquant mais aucun secours.
bitmap=
L'option spécifie un fichier dans lequel un bitmap d'intention d'écriture doit être trouvé. Lors de l'assemblage du tableau, mdadm fournira ce fichier au pilote md comme fichier bitmap. Ceci a la même fonction que l'option --bitmap-file de --assemble.
metadata=
Spécifie le format des métadonnées que possède le tableau. Ceci est principalement reconnu pour la comparabilité avec la sortie de mdadm -Es.
container=
Spécifie que ce tableau est un tableau membre d'un conteneur. La valeur donnée peut être soit un nom de chemin dans /dev, soit un UUID du tableau conteneur.
member=
Spécifie que ce tableau est un tableau membre d'un conteneur. Chaque type de conteneur a un moyen d'énumérer les tableaux membres, souvent un simple numéro de séquence. La valeur identifie de quel membre d'un conteneur il s'agit. Elle accompagnera généralement un mot "container=".
MAILADDR
La ligne mailaddr donne une adresse E-mail à laquelle les alertes doivent être envoyées lorsque mdadm s'exécute en mode --monitor (et a reçu l'option --scan). Il ne devrait y avoir qu'une seule ligne MAILADDR et elle ne devrait contenir qu'une seule adresse. Les adresses ultérieures sont silencieusement ignorées.
MAILFROM
La ligne mailfrom (qui ne peut être abrégée qu'à 5 caractères au minimum) donne une adresse qui apparaîtra dans l'adresse "De" pour les e-mails d'alerte. Ceci peut être utile si vous souhaitez définir explicitement un domaine, car l'adresse d'origine par défaut est "root" sans domaine. Tous les mots de cette ligne sont concaténés avec des espaces pour former l'adresse.

Notez que cette valeur ne peut pas être définie via la ligne de commande mdadm. Elle ne peut être définie que via le fichier de configuration. Il ne devrait y avoir qu'une seule ligne MAILADDR et elle ne devrait contenir qu'une seule adresse. Les adresses ultérieures sont silencieusement ignorées.

PROGRAM
La ligne program donne le nom d'un programme à exécuter lorsque mdadm --monitor détecte des événements potentiellement intéressants sur l'un des tableaux qu'il

est en cours de surveillance. Ce programme est exécuté avec deux ou trois arguments, qui sont l'événement, le périphérique md, et éventuellement le périphérique composant associé.

Il ne devrait y avoir qu'une seule ligne program et elle ne devrait contenir qu'un seul programme. Les programmes suivants sont silencieusement ignorés.

CREATE
La ligne create fournit les valeurs par défaut à utiliser lors de la création de tableaux, de nouveaux membres de tableaux et d'entrées de périphériques pour les tableaux.

Il ne devrait y avoir qu'une seule ligne create. Les lignes suivantes remplaceront les paramètres précédents.

Les mots-clés utilisés dans la ligne CREATE et leurs valeurs prises en charge sont les suivants :

owner=
group=
Ceux-ci peuvent fournir des identifiants d'utilisateur/groupe ou des noms à utiliser au lieu des valeurs par défaut du système (root/wheel ou root/disk).
mode=
Un mode de fichier octal tel que 0660 peut être fourni pour remplacer la valeur par défaut de 0600.
metadata=
Le nom du format de métadonnées à utiliser si aucun n'est explicitement spécifié. Ceci peut être utile pour imposer une valeur par défaut au niveau du système de superblocs de version 1.
names=yes
Il a été possible de créer des périphériques md avec un nom tel que md_home plutôt qu'un simple numéro, comme md3. mdadm utilisera l'alternative numérique par défaut car d'autres outils qui interagissent avec les tableaux md peuvent s'attendre uniquement à des nombres. Si names=yes est spécifié dans mdadm.conf, alors mdadm utilisera un nom lorsque cela est approprié. Si names=no est spécifié, alors les noms de périphériques md non numériques ne seront pas utilisés, même si la valeur par défaut change dans une future version de mdadm.
bbl=no
Par défaut, mdadm réservera de l'espace pour une liste de blocs défectueux (bbl) sur tous les périphériques inclus ou ajoutés à un tableau qui les prend en charge. Définir bbl=no empêchera cela, de sorte que les nouveaux périphériques ajoutés n'auront pas de journal de blocs défectueux.
HOMEHOST
La ligne homehost fournit une valeur par défaut pour l'option --homehost= de mdadm. Il ne devrait normalement y avoir qu'un seul autre mot sur la ligne. Ce devrait être soit un nom d'hôte, soit l'un des mots spéciaux <system>, <none> et <ignore>. Si <system> est spécifié, alors l'appel système gethostname(2) est utilisé pour obtenir le nom d'hôte. C'est la valeur par défaut.

Si <ignore> est spécifié, alors un indicateur est défini de sorte que lorsque les tableaux sont auto-assemblés, la vérification du homehost enregistré est désactivée. Si <ignore> est spécifié, il est également possible de donner un nom explicite qui sera utilisé lors de la création de tableaux. C'est le seul cas où il peut y avoir plus d'un autre mot sur la ligne HOMEHOST. S'il y a d'autres mots, ou d'autres lignes HOMEHOST, ils sont silencieusement ignorés.

Si <none> est spécifié, alors la valeur par défaut d'utilisation de gethostname(2) est annulée et aucun nom d'hôte d'origine n'est supposé.

Lors de la création de tableaux, ce nom d'hôte sera stocké dans les métadonnées. Lors de l'assemblage de tableaux à l'aide de l'auto-assemblage, les tableaux qui n'enregistrent pas le bon nom d'hôte dans leurs métadonnées seront assemblés en utilisant un nom "étranger". Un nom "étranger" se termine toujours par une chaîne de chiffres précédée d'un tiret bas pour le différencier de tout nom local possible. Par exemple, /dev/md/1_1 ou /dev/md/home_0.

HOMECLUSTER
La ligne homecluster fournit une valeur par défaut pour l'option --homecluster= de mdadm. Elle spécifie le nom du cluster pour le périphérique md. Le périphérique md ne peut être assemblé que sur le cluster qui correspond au nom spécifié. Si homcluster n'est pas fourni, mdadm essaie de détecter automatiquement le nom du cluster.

Il ne devrait y avoir qu'une seule ligne homecluster. Les lignes suivantes seront silencieusement ignorées.

AUTO
Une liste de noms de formats de métadonnées peut être fournie, chacun précédé d'un signe plus ou moins. Le mot homehost est également autorisé, tout comme all précédé d'un signe plus ou moins. all est généralement le dernier.

Lorsque mdadm auto-assemble un tableau, que ce soit via --assemble ou --incremental, et qu'il trouve des métadonnées d'un type donné, il vérifie ce type de métadonnées par rapport à ceux listés dans cette ligne. La première correspondance trouvée l'emporte, où all correspond à n'importe quoi. Si une correspondance est trouvée précédée d'un signe plus, l'auto-assemblage est autorisé. Si la correspondance était précédée d'un signe moins, l'auto-assemblage est interdit. Si aucune correspondance n'est trouvée, l'auto-assemblage est autorisé.

Si les métadonnées indiquent que le tableau a été créé pour *ce* système, et que le mot homehost apparaît avant toute autre correspondance, alors le tableau est traité comme un candidat valide pour l'auto-assemblage.

Ceci peut être utilisé pour désactiver tout auto-assemblage (de sorte que seuls les tableaux explicitement listés dans mdadm.conf ou sur la ligne de commande soient assemblés), ou pour désactiver l'assemblage de certains types de métadonnées qui pourraient être gérés par d'autres logiciels. Il peut également être utilisé pour désactiver l'assemblage de tous les tableaux étrangers - normalement, ces tableaux sont assemblés mais reçoivent un nom non déterministe dans /dev/md/.

Les types de métadonnées connus sont 0.90, 1.x, ddf, imsm.

AUTO ne doit être spécifié qu'une seule fois. Les lignes suivantes sont silencieusement ignorées. Ainsi, un fichier de configuration ultérieur dans un répertoire de configuration n'écrasera pas le paramètre d'un fichier de configuration précédent.

POLICY
Ceci est utilisé pour spécifier quel comportement automatique est autorisé sur les périphériques apparaissant nouvellement dans le système et fournit un moyen de marquer les pièces de rechange qui peuvent être déplacées vers d'autres tableaux, ainsi que les domaines de migration. Un domaine peut être défini par une ligne de politique en spécifiant un nom de domaine pour un certain nombre de chemins depuis /dev/disk/by-path/. Un périphérique peut appartenir à plusieurs domaines. Le domaine d'un tableau est l'union des domaines de tous les périphériques de ce tableau. Une pièce de rechange peut être automatiquement déplacée d'un tableau à un autre si l'ensemble des domaines du tableau de destination contient tous les domaines du nouveau disque ou si les deux tableaux partagent le même spare-group.

Pour mettre à jour la configuration de branchement à chaud, il est nécessaire d'exécuter la commande mdadm --udev-rules=<path_to_file>, par exemple /etc/udev/rules.d/65-md-bare.rules, après avoir modifié le fichier de configuration. Et aussi d'exécuter udevadm control --reload sinon un redémarrage est nécessaire.

Les mots-clés utilisés dans la ligne POLICY et les valeurs prises en charge sont les suivants :

domain=
toute chaîne arbitraire
metadata=
0.9 1.x ddf ou imsm
path=
glob de fichier correspondant à n'importe quoi depuis /dev/disk/by-path
type=
soit disk, soit part.
action=
include, re-add, spare, spare-same-slot, ou force-spare
auto=
yes, no, ou homehost.

L'élément action détermine le comportement automatique autorisé pour les périphériques correspondant au path et au type sur la même ligne. Si un périphérique correspond à plusieurs lignes avec des actions différentes, la plus permissive s'appliquera. L'ordre des lignes de politique n'a pas d'importance pour le résultat final.

include
permet d'ajouter un disque à un tableau si les métadonnées sur ce disque correspondent à ce tableau
re-add
inclura le périphérique dans le tableau s'il semble être un membre actuel ou un membre qui a été récemment retiré et que le tableau possède un bitmap d'intention d'écriture pour permettre la fonctionnalité re-add.
spare
comme ci-dessus et en plus : si le périphérique est nu, il peut devenir une pièce de rechange s'il existe un tableau pour lequel il est candidat en fonction des domaines et des métadonnées.
spare-same-slot
comme ci-dessus et en plus si un slot donné a été utilisé par un tableau qui est récemment passé en mode dégradé et que le périphérique branché n'a pas de métadonnées, il sera automatiquement ajouté à ce tableau (ou à son conteneur)
force-spare
comme ci-dessus et le disque deviendra une pièce de rechange dans les autres cas
PART-POLICY
Ceci est similaire à POLICY et accepte les mêmes affectations de mots-clés. Il permet d'appliquer un ensemble cohérent de politiques à chacune des partitions d'un périphérique.

Une ligne PART-POLICY doit définir type=disk et identifier le chemin d'accès à un ou plusieurs périphériques disque. Chaque partition sur ces disques sera traitée conformément au paramètre action= de cette ligne. Si un domaine est défini sur la ligne, alors le domaine associé à chaque partition sera basé sur le domaine, mais avec "-partN" ajouté, où N est le numéro de partition pour la partition qui a été trouvée.

SYSFS
La ligne SYSFS liste les attributs personnalisés du sysfs des périphériques MD qui seront stockés dans sysfs après l'assemblage du tableau. Plusieurs lignes sont autorisées et chaque ligne doit contenir l'uuid ou le nom du périphérique auquel elle se rapporte. Les lignes sont appliquées dans l'ordre inverse.
uuid=
identifiant hexadécimal du périphérique MD. Il doit correspondre à l'uuid stocké dans le superbloc.
name=
nom du périphérique MD tel que donné à mdadm lors de la création du tableau. Il sera ignoré si uuid n'est pas vide.
MONITORDELAY
La ligne monitordelay donne un délai en secondes que mdadm doit attendre avant de regrouper les tableaux md lorsque mdadm est en mode --monitor. L'argument de ligne de commande -d/--delay a la priorité sur le fichier de configuration.

Si plusieurs lignes MINITORDELAY sont fournies, seule la première valeur non nulle est prise en compte.

ENCRYPTION_NO_VERIFY
ENCRYPTION_NO_VERIFY désactive la vérification du chiffrement pour les périphériques avec un support de chiffrement particulier détecté. Actuellement, seule la vérification du chiffrement SATA OPAL peut être désactivée. Elle ne désactive pas la vérification du chiffrement de sécurité ATA. Actuellement effective uniquement pour les métadonnées IMSM. Paramètre disponible : sata_opal.

FICHIERS

/etc/mdadm.conf

L'emplacement par défaut du fichier de configuration, utilisé lorsque mdadm s'exécute sans l'option --config.

/etc/mdadm.conf.d

Le répertoire par défaut contenant les fichiers de configuration. Utilisé lorsque mdadm s'exécute sans l'option --config, après la lecture réussie du fichier de configuration par défaut /etc/mdadm.conf. Les fichiers dans ce répertoire sont lus dans l'ordre lexical.

/etc/mdadm/mdadm.conf

Fichier de configuration alternatif qui est lu lorsque mdadm s'exécute sans l'option --config et que le fichier de configuration par défaut /etc/mdadm.conf n'a pas pu être ouvert.

/etc/mdadm/mdadm.conf.d

Le répertoire alternatif contenant les fichiers de configuration. Utilisé lorsque mdadm s'exécute sans l'option --config, après la lecture du fichier de configuration alternatif /etc/mdadm/mdadm.conf, que cette lecture ait réussi ou non. Les fichiers dans ce répertoire sont lus dans l'ordre lexical.

EXEMPLE

DEVICE /dev/sd[bcdjkl]1
DEVICE /dev/hda1 /dev/hdb1

# /dev/md0 est connu par son UUID.
ARRAY /dev/md0 UUID=3aaa0122:29827cfa:5331ad66:ca767371
# /dev/md1 contient tous les périphériques avec un numéro mineur
# 1 dans le superfichier.
ARRAY /dev/md1 superminor=1
# /dev/md2 est composé précisément de ces deux périphériques
ARRAY /dev/md2 devices=/dev/hda1,/dev/hdb1

# /dev/md4 et /dev/md5 font partie d'un groupe de secours et les secours
# peuvent être déplacés entre eux
ARRAY /dev/md4 uuid=b23f3c6d:aec43a9f:fd65db85:369432df
spare-group=group1
ARRAY /dev/md5 uuid=19464854:03f71b1b:e0df2edd:246cc977
spare-group=group1
# /dev/md/home est créé s'il doit être un tableau md partitionnable
# tout numéro de périphérique de secours est alloué.
ARRAY /dev/md/home UUID=9187a482:5dde19d9:eea3cc4a:d646ab8b
auto=part
# Un domaine comprenant des périphériques connectés aux chemins spécifiés est défini.
# Le périphérique brut correspondant au premier chemin deviendra un secours imsm lors d'une connexion à chaud.
# Si plus d'un tableau est créé sur des périphériques appartenant au domaine1 et
# que l'un d'eux devient dégradé, alors tout secours imsm correspondant à un chemin pour
# le nom de domaine donné peut être migré.
POLICY domain=domain1 metadata=imsm path=pci-0000:00:1f.2-scsi-*
action=spare
POLICY domain=domain1 metadata=imsm path=pci-0000:04:00.0-scsi-[01]*
action=include
MAILADDR root@mydomain.tld
PROGRAM /usr/sbin/handle-mdadm-events
CREATE group=system mode=0640 auto=part-8
HOMEHOST <system>
AUTO +1.x homehost -all
SYSFS name=/dev/md/raid5 group_thread_cnt=4 sync_speed_max=1000000
SYSFS uuid=bead5eb6:31c17a27:da120ba2:7dfda40d group_thread_cnt=4 sync_speed_max=1000000
MONITORDELAY 60
ENCRYPTION_NO_VERIFY sata_opal
