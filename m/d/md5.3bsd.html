MD5Init, MD5Update, MD5Pad, MD5Final, MD5Transform, MD5End, MD5File, MD5FileChunk, MD5Data — calculer le condensat de message ``MD5'' de RSA Data Security, Inc.

DESCRIPTION

Les fonctions MD5 calculent une somme de contrôle cryptographique de 128 bits (condensat) pour n'importe quel nombre d'octets d'entrée. Une somme de contrôle cryptographique est une fonction de hachage à sens unique, c'est-à-dire que vous ne pouvez pas trouver (sauf par recherche exhaustive) l'entrée correspondant à une sortie donnée. Le résultat net est une « empreinte » des données d'entrée, qui ne révèle pas l'entrée réelle.

MD4 a été cassé ; il ne devrait être utilisé que lorsque nécessaire pour des raisons de compatibilité ascendante. MD5 n'a pas encore (11-02-1999) été cassé, mais des attaques récentes ont jeté un doute sur ses propriétés de sécurité. Les attaques sur MD4 et MD5 visent toutes deux à trouver des « collisions » - c'est-à-dire plusieurs entrées qui hachent vers la même valeur ; il est toujours peu probable qu'un attaquant puisse déterminer l'entrée d'origine exacte étant donné une valeur de hachage.

Les fonctions MD5Init(), MD5Update() et MD5Final() sont les fonctions principales. Allouez un MD5_CTX, initialisez-le avec MD5Init(), traitez les données avec MD5Update(), et extrayez enfin le résultat en utilisant MD5Final().

La fonction MD5Pad() peut être utilisée pour appliquer un remplissage au condensat du message, comme dans MD5Final(), mais le contexte actuel peut toujours être utilisé avec MD5Update().

La fonction MD5Transform() est utilisée par MD5Update() pour hacher des blocs de 512 bits et constitue le cœur de l'algorithme. La plupart des programmes devraient utiliser l'interface fournie par MD5Init(), MD5Update() et MD5Final() plutôt que d'appeler MD5Transform() directement.

MD5End() est un wrapper pour MD5Final() qui convertit la valeur de retour en une chaîne ASCII de longueur MD5_DIGEST_STRING_LENGTH (y compris le '\0' final) représentant les 128 bits en hexadécimal.

MD5File() calcule le condensat d'un fichier et utilise MD5End() pour retourner le résultat. Si le fichier ne peut pas être ouvert, un pointeur nul est retourné.

MD5FileChunk() se comporte comme MD5File() mais calcule le condensat uniquement pour la partie du fichier commençant à offset et se poursuivant sur length octets ou jusqu'à la fin du fichier, selon ce qui arrive en premier. Une length nulle peut être spécifiée pour lire jusqu'à la fin du fichier. Une length ou offset négative sera ignorée. MD5Data() calcule le condensat d'un bloc de données en mémoire et utilise MD5End() pour retourner le résultat.

Lors de l'utilisation de MD5End(), MD5File(), MD5FileChunk() ou MD5Data(), l'argument buf peut être un pointeur nul, auquel cas la chaîne retournée est allouée avec malloc(3) et devra ensuite être explicitement désallouée avec free(3) après utilisation. Si l'argument buf n'est pas nul, il doit pointer vers au moins MD5_DIGEST_STRING_LENGTH caractères de mémoire tampon.

md5.3bsd - MD5 crypt(3) password hash, MD5 digest, and MD5 compress

NAME

md5, MD5_Init, MD5_Update, MD5_Final, MD5End, MD5File, MD5FileChunk, MD5Data — MD5 crypt(3) password hash, MD5 digest, and MD5 compress

LIBRARY

Standard C Library (libc, -lc)

SYNOPSIS

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/types.h>
#include <sys/md5.h>

char *
md5(const char *data, size_t len);

void
MD5_Init(MD5_CTX *ctx);

void
MD5_Update(MD5_CTX *ctx, const void *data, size_t len);

void
MD5_Final(unsigned char *digest, MD5_CTX *ctx);

char *
MD5End(MD5_CTX *ctx, char *buf);

char *
MD5File(const char *filename, char *buf);

char *
MD5FileChunk(const char *filename, char *buf, off_t offset, off_t length);

char *
MD5Data(const void *data, size_t len, char *buf);

DESCRIPTION

The MD5 message-digest algorithm is a cryptographically weak 128-bit hash function. It is used for message integrity checks and is also widely used for password hashing. The MD5 algorithm is described in RFC 1321.

The functions MD5_Init, MD5_Update, and MD5_Final implement the core MD5 hashing algorithm.

The MD5_Init function initializes a message-digest context ctx.

The MD5_Update function processes the len bytes of data starting at data and updates the hash code in the message-digest context ctx.

The MD5_Final function completes the hash calculation and places the 16-byte message-digest into digest.

The md5, MD5End, MD5File, MD5FileChunk, and MD5Data functions are convenience functions.

The md5 function computes the MD5 hash of the len bytes of data in data and returns a pointer to a 32-byte statically-allocated buffer containing the hexadecimal representation of the hash.

The MD5End function completes the current MD5 hash calculation and places the hexadecimal representation of the digest into the buffer buf, which must be large enough to hold 33 bytes (32 hexadecimal digits plus a null terminator). It returns a pointer to buf.

The MD5File function computes the MD5 hash of the contents of the file named by filename and returns a pointer to a hexadecimal representation of the digest in buf. buf must be large enough to hold 33 bytes.

The MD5FileChunk function computes the MD5 hash of the contents of the file named by filename starting at offset for length bytes. It returns a pointer to a hexadecimal representation of the digest in buf. buf must be large enough to hold 33 bytes.

The MD5Data function computes the MD5 hash of the len bytes of data in data and returns a pointer to a hexadecimal representation of the digest in buf. buf must be large enough to hold 33 bytes.

For the convenience functions, buf may be NULL, in which case the functions will use a static buffer. The static buffer is not thread-safe. When computing multiple hashes, the user must either provide a buffer, or ensure that MD5End, MD5File, MD5FileChunk, or MD5Data are called only once for each hash computation. The return value is the address of the buffer containing the hash.

The md5 function is equivalent to calling MD5Data with a NULL buffer.

The MD5FileChunk function is useful for generating hashes for specific parts of a file, or for files that may be too large to fit into memory.

A common use case is to generate the MD5 hash for a password. To do this, the MD5End function should be used, after initializing the context with MD5_Init, updating it with the password using MD5_Update, and then calling MD5End with a buffer.

The MD5 hash is typically represented as a 32-character hexadecimal string. The MD5End, MD5File, MD5FileChunk, and MD5Data functions return the hash in this format.

The internal structure MD5_CTX is defined in the header file <sys/md5.h>.

crypt(3), sha2(3), rmd160(3), RFC 1321

HISTORY

These functions appeared in OpenBSD 2.0.

AUTHORS

The original MD5 routines were developed by RSA Data Security, Inc., and published in the above references. This code is derived from a public domain implementation written by Colin Plumb.

The MD5End(), MD5File(), MD5FileChunk(), and MD5Data() helper functions are derived from code written by Poul-Henning Kamp.

BUGS

Collisions have been found for the full versions of both MD4 and MD5 as well as strong attacks against the SHA-0 and SHA-1 family. The use of sha2(3), or rmd160(3) is recommended instead.
