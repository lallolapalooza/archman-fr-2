NOM

MD2Init, MD2Update, MD2Pad, MD2Final, MD2Transform, MD2End, MD2File, MD2FileChunk, MD2Data — calculer la somme de contrôle de message RSA Data Security, Inc., “MD2”

BIBLIOTHEQUE

Bibliothèque de support pour les sommes de contrôle de message (MD4, MD5, etc.) (libmd, -lmd)

SYNOPIS

#include <sys/types.h>
#include <md2.h>

void
MD2Init(MD2_CTX *context);

void
MD2Update(MD2_CTX *context, const uint8_t *data, size_t len);

void
MD2Pad(MD2_CTX *context);

void
MD2Final(uint8_t digest[MD2_DIGEST_LENGTH], MD2_CTX *context);

void
MD2Transform(uint32_t state[4], uint8_t block[MD2_BLOCK_LENGTH]);

char *
MD2End(MD2_CTX *context, char *buf);

char *
MD2File(const char *filename, char *buf);

char *
MD2FileChunk(const char *filename, char *buf, off_t offset, off_t length);

char *
MD2Data(const uint8_t *data, size_t len, char *buf);

DESCRIPTION

Les fonctions MD2 calculent une somme de contrôle cryptographique de 128 bits (digest) pour n'importe quel nombre d'octets d'entrée. Une somme de contrôle cryptographique est une fonction de hachage à sens unique, c'est-à-dire que vous ne pouvez pas trouver (sauf par recherche exhaustive) l'entrée correspondant à une sortie particulière. Le résultat net est une “empreinte digitale” des données d'entrée, qui ne divulgue pas l'entrée réelle.

MD2 est le plus lent, MD4 est le plus rapide et MD5 se situe quelque part au milieu. MD2 ne peut être utilisé que pour le courrier à confidentialité améliorée. MD4 a été critiqué pour être trop faible, donc MD5 a été développé en réponse comme “MD4 avec des ceintures de sécurité”. MD4 et MD5 ont été cassés ; ils ne devraient être utilisés que lorsque cela est nécessaire pour des raisons de compatibilité descendante. Les attaques sur MD4 et MD5 consistent toutes deux à trouver des “collisions” - c'est-à-dire, plusieurs entrées qui hachent vers la même valeur ; il est toujours peu probable qu'un attaquant puisse déterminer l'entrée originale exacte étant donné une valeur de hachage.

Les fonctions MD2Init(), MD2Update(), et MD2Final() sont les fonctions principales. Allouez un MD2_CTX, initialisez-le avec MD2Init(), parcourez les données avec MD2Update(), et enfin extrayez le résultat à l'aide de MD2Final().

La fonction MD2Pad() peut être utilisée pour appliquer un rembourrage à la somme de contrôle du message comme dans MD2Final(), mais le contexte actuel peut toujours être utilisé avec MD2Update().

La fonction MD2Transform() est utilisée par MD2Update() pour hacher des blocs de 512 bits et forme le cœur de l'algorithme. La plupart des programmes devraient utiliser l'interface fournie par MD2Init(), MD2Update() et MD2Final() au lieu d'appeler MD2Transform() directement.

MD2End() est un wrapper pour MD2Final() qui convertit la valeur de retour en une chaîne ASCII de longueur MD2_DIGEST_STRING_LENGTH (y compris le '\0' final) qui représente les 128 bits en hexadécimal.

MD2File() calcule la somme de contrôle d'un fichier et utilise MD2End() pour retourner le résultat. Si le fichier ne peut pas être ouvert, un pointeur nul est retourné.

MD2FileChunk() se comporte comme MD2File() mais calcule la somme de contrôle uniquement pour cette partie du fichier commençant à l'offset et continuant pendant length octets ou jusqu'à la fin du fichier, selon la première éventualité. Une length nulle peut être spécifiée pour lire jusqu'à la fin du fichier. Une length ou un offset négatif sera ignoré. MD2Data() calcule la somme de contrôle d'un bloc de données en mémoire et utilise MD2End() pour retourner le résultat.

Lors de l'utilisation de MD2End(), MD2File(), MD2FileChunk(), ou MD2Data(), l'argument buf peut être un pointeur nul, auquel cas la chaîne retournée est allouée avec malloc(3) et doit ensuite être explicitement désallouée à l'aide de free(3) après utilisation. Si l'argument buf n'est pas nul, il doit pointer vers au moins MD2_DIGEST_STRING_LENGTH caractères d'espace tampon.

NAME

md2, MD2Init, MD2Update, MD2End, MD2File, MD2FileChunk, MD2Data — Cryptographic Hash Function

LIBRARY

Message Digest libmd

SYNOPSIS

#include <stdio.h>
#include <sys/types.h>
#include <libmd.h>

void MD2Init(unsigned char *result);
void MD2Update(unsigned char *state, const unsigned char *input, unsigned int inputlen);
void MD2End(unsigned char *result);
int MD2File(const char *filename, unsigned char *result);
int MD2FileChunk(const char *filename, unsigned char *result, off_t offset, off_t length);
int MD2Data(const unsigned char *data, unsigned int datalen, unsigned char *result);

DESCRIPTION

The MD2 algorithm is a cryptographic hash function developed by RSA Data Security, Inc. It produces a 128-bit (16-byte) message digest from an arbitrary length input message. MD2 is designed to be relatively fast on 8-bit microprocessors, but it is generally slower than MD5 and SHA-1.

The MD2 algorithm consists of two passes. The first pass processes the message and computes an intermediate hash. The second pass processes the intermediate hash and the message padding, producing the final hash value. The padding ensures that the message length is a multiple of 16 bytes.

The functions provided are:

MD2Init
Initializes the MD2 state. The state is an array of 48 bytes. The result argument is a pointer to a 16-byte buffer where the final hash will be stored.
MD2Update
Updates the MD2 state with the given input data. The state argument is a pointer to the current MD2 state, input is a pointer to the data to be processed, and inputlen is the length of the input data.
MD2End
Completes the MD2 computation. The result argument is a pointer to a 16-byte buffer where the final hash will be stored. This function should be called after all MD2Update calls. The state is reset internally after calling this function.
MD2File
Computes the MD2 hash of the file specified by filename. The hash is stored in the 16-byte buffer pointed to by result. This function opens the file, computes the hash, and closes the file. It returns 0 on success, and -1 on error.
MD2FileChunk
Computes the MD2 hash of a specific chunk of the file specified by filename. The hash is stored in the 16-byte buffer pointed to by result. The chunk is defined by offset (starting position) and length (number of bytes to read). It returns 0 on success, and -1 on error.
MD2Data
Computes the MD2 hash of the data buffer specified by data and datalen. The hash is stored in the 16-byte buffer pointed to by result. This is a convenience function that combines MD2Init, MD2Update, and MD2End. It returns 0 on success, and -1 on error.

HISTORY

The MD2 functions first appeared in OpenBSD 2.0 and NetBSD 1.3.

AUTHORS

The original MD2 routines were developed by RSA Data Security, Inc., and published in the above references. This code is derived from a public domain implementation written by Colin Plumb.

The MD2End(), MD2File(), MD2FileChunk(), and MD2Data() helper functions are derived from code written by Poul-Henning Kamp.

BUGS

Collisions have been found for the full versions of both MD4 and MD5. The use of sha2(3) is recommended instead.
