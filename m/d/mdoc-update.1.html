mdoc-update(1) Manuel des commandes générales mdoc-update(1)

NOM

mdoc update - Support du format de documentation mdoc(5)

SYNTAXE

mdoc update [OPTIONS]* ASSEMBLIES

DESCRIPTION

mdoc update est responsable des actions suivantes :

*
Création de stubs de documentation basés sur ASSEMBLIES. Le processus de création de stubs créera de nouveaux fichiers XML mdoc(5) pour chaque type au sein de ASSEMBLIES, et fournira des stubs de documentation pour chaque membre de ces types.
*
Mise à jour des stubs de documentation basés sur ASSEMBLIES. La documentation mdoc(5) existante peut être mise à jour pour refléter les changements dans ASSEMBLIES, tels que l'ajout de types et de membres, tout en préservant la documentation existante.

Dans certaines circonstances limitées, les renommages seront suivis, minimisant ainsi la charge de documentation lorsqu'un paramètre, par exemple, est renommé.

mdoc update ne s'appuie pas sur la documentation trouvée dans le code source, bien qu'il puisse importer des commentaires de documentation XML via l'option -i.

Voir mdoc(1) et mdoc(5) pour plus d'informations.

OPTIONS

--delete
Permet à mdoc update de supprimer des membres des fichiers de documentation. Les seuls membres supprimés sont ceux qui ne sont plus présents dans ASSEMBLIES et qui ne sont présents dans aucune autre version d'assembly.

Si un type n'est plus présent, le fichier de documentation n'est pas supprimé, mais est plutôt renommé avec une extension .remove.

La détection de version se fait avec les éléments //AssemblyVersion ; s'il n'y a pas d'éléments //AssemblyVersion pour un <Type> ou <Member/> donné, alors le <Type> sera renommé et/ou le <Member/> sera supprimé.

--exceptions[=SOURCES]
EXPÉRIMENTAL. Ceci n'est pas fiable à 100 %, mais vise à aider les auteurs de documentation.

Inspecte les corps des membres pour déterminer quelles exceptions peuvent être générées à partir du membre.

SOURCES est une liste optionnelle séparée par des virgules des sources suivantes qui doivent être recherchées pour les exceptions:

        added   Générer uniquement des éléments <exception/> pour les membres
                  ajoutés pendant l'exécution actuelle du programme.
                  Cela empêche mdoc-update de régénérer
                  des éléments <exception/> pour tous les membres (et donc
                  d'empêcher la réinsertion pour les membres dont les
                  éléments <exception/> ont été supprimés).
        all     Trouver les exceptions créées dans le membre lui-même,
                  les références aux membres du même assembly,
                  et les références aux membres des assemblies dépendants.
        asm     Trouver les exceptions créées dans le membre lui-même et
                  les références aux membres au sein du même assembly
                  que le membre.
        depasm  Trouver les exceptions créées dans le membre lui-même et
                  les références aux membres des assemblies dépendants.

Si SOURCES n'est pas fourni (par défaut), alors seules les exceptions créées dans le membre lui-même seront documentées.

LIMITATIONS : La recherche d'exceptions est actuellement implémentée en recherchant les types d'exceptions explicitement créés en fonction des types connus au moment de la compilation. Cela présente les limitations suivantes :

*
Cela ne trouvera pas les exceptions qui sont implicites au IL, comme NullReferenceException et IndexOutOfRangeException.
*
Cela trouvera des exceptions qui ne sont pas lancées, par ex. 
    public void CreateAnException ()
    {
        Exception e = new Exception ();
    }
*
Cela ne "suivra" pas les appels de délégués et d'interfaces : 
    public void UsesDelegates ()
    {
        Func<int, int> a = x => {throw new Exception ();};
        a (4);
    }
La fonction UsesDelegates() n'aura aucune exception documentée.
*
Cela trouvera des exceptions qui "ne peuvent pas se produire", comme ArgumentNullExceptions pour des arguments qui sont "connus" pour être non nuls : 
    public void A ()
    {
        B ("ce paramètre n'est pas nul");
    }
    public void B (string s)
    {
        if (s == null)
            throw new ArgumentNullException ("s");
    }
Pour ce qui précède, si --exceptions=asm est fourni, alors A() sera documenté comme lançant une ArgumentNullException, ce qui ne peut pas arriver.
-f=FLAG
Spécifier un indicateur pour modifier le comportement. Les indicateurs valides incluent :
no-assembly-versions
Voir la documentation de -fno-assembly-versions ci-dessous.
-fno-assembly-versions
Ne pas générer les éléments /Type/AssemblyInfo/AssemblyVersion et /Type/Members/Member/AssemblyInfo.

Ceci est utile pour éviter le "fouillis" lors des mises à jour. Normalement, si un type ou un membre n'a pas changé mais que la version de l'assembly a changé, alors tous les types et membres seront mis à jour pour inclure un nouvel élément //AssemblyVersion, augmentant ainsi la quantité de changements qui doivent être revus avant de valider (en supposant que tous les changements sont effectivement revus avant de valider).

ATTENTION : Ceci interagira mal avec l'option --delete, car --delete utilise les éléments //AssemblyVersion pour suivre les changements de version. Ainsi, si vous avez un membre présent dans une version antérieure de l'assembly et supprimé dans une version ultérieure, comme System.Text.UTF8Encoding.GetBytes(string) (présent dans le .NET 1.0 mais pas dans le .NET 2.0), alors le membre sera supprimé lorsque les options --delete -fno-assembly-versions sont spécifiées, le membre était présent dans une version antérieure de l'assembly et la version actuelle de l'assembly ne contient pas le membre.

Par conséquent, cette option ne doit être spécifiée que si les types et les membres ne seront jamais supprimés d'un assembly.

-i, --import=FICHIER
Importer la documentation trouvée dans FICHIER.

FICHIER peut contenir du XML csc /doc ou du XML ECMA-335.

-L, --lib=RÉPERTOIRE
Ajoute RÉPERTOIRE au chemin de recherche des assemblies, afin que les dépendances de ASSEMBLIES puissent être trouvées sans documenter ces assemblies.
-o, --out=RÉPERTOIRE
Placer les stubs générés dans RÉPERTOIRE.

Lors de la mise à jour de la documentation, RÉPERTOIRE est également le répertoire source.

-r=ASSEMBLY
ASSEMBLY est une dépendance pour l'un des ASSEMBLIES qui ne doit pas être documenté mais est nécessaire pour traiter l'un des ASSEMBLIES. Ajouter le répertoire contenant ASSEMBLY au chemin de recherche des assemblies.

Cette option est équivalente à spécifier -L `dirname ASSEMBLY`.

--since=VERSION
Lors de la mise à jour de la documentation pour un assembly, si un type ou un membre est rencontré qui n'existait pas dans la version précédente de l'assembly, un élément <since version="VERSION"/> sera inséré.
--type=TYPE
Mettre à jour la documentation uniquement pour le type TYPE.
-h, -?, --help
Afficher un message d'aide et quitter.
