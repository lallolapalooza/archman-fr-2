mdoc(1) Manuel des commandes générales mdoc(1)

NOM

mdoc - Outil de gestion de la documentation Mono

SYNTAXE

mdoc commande [options] [arguments]

APERÇU

mdoc est un système de gestion de documentation basé sur les assemblages.

mdoc permet de créer et de mettre à jour des stubs de documentation basés sur le contenu d'un assemblage. Il ne se repose pas sur la documentation trouvée dans le code source.

Les avantages sont :

*
Lisibilité du code. Une bonne documentation est souvent (a) verbeuse et (b) remplie d'exemples. (Pour comparaison, comparez la documentation du Framework .NET de Microsoft, qui fait souvent une page ou plus de docs pour chaque membre, à la documentation JavaDoc, qui peut souvent être une phrase pour chaque membre.)

Insérer une bonne documentation dans le code source peut souvent gonfler le fichier source, car la documentation peut être plus longue que la méthode réelle documentée.

*
Localisation. Les formats de documentation intégrés au code source (comme csc /doc) n'ont aucun support pour plusieurs langues humaines. Si vous devez supporter plus d'une langue humaine à des fins de documentation, mdoc est utile car il permet à la sortie de chaque langue de résider dans son propre répertoire, et mdoc peut ajouter des types/membres pour chaque répertoire de documentation séparé.
*
Administration. Il n'est pas rare d'avoir des équipes de documentation et de développement séparées. Il est également possible que l'équipe de documentation ait une expérience minimale du langage de programmation utilisé. Dans de telles circonstances, la documentation intégrée n'est pas souhaitable car l'équipe de documentation pourrait introduire involontairement une erreur dans le code source lors de la mise à jour de la documentation. Alternativement, vous pourriez ne pas vouloir que l'équipe de documentation ait accès au code source pour des raisons de sécurité. mdoc permet que la documentation soit maintenue complètement séparée et distincte du code source utilisé pour créer l'assemblage.

La documentation peut être générée à l'aide de la commande mdoc update :

    mdoc update -o docs/en ProjectName.dll
Une fois les stubs de documentation générés (et, espérons-le, remplis plus tard avec la documentation réelle), il y a trois façons de visualiser la documentation :
*
Pour générer un répertoire simple de pages HTML (un fichier HTML par type), utilisez mdoc export-html : 
    mdoc export-html -o /srv/www/htdocs/ProjectName docs/en
*
Pour utiliser une application web ASP.NET pour afficher les sources, voir : http://anonsvn.mono-project.com/source/trunk/monodoc/engine/web/.

Depuis un checkout source de monodoc, vous pouvez faire ceci :

    cd engine
    make web
Cela utilisera xsp(1) pour servir l'application web ASP.NET ; visitez http://localhost:8080/ pour voir la documentation.
*
Pour utiliser le navigateur de documentation monodoc(1), vous devez d'abord assembler la documentation : 
    mdoc assemble -o ProjectName docs/en
La commande ci-dessus crée les fichiers ProjectName.tree et ProjectName.zip. Un fichier ProjectName.sources supplémentaire doit être fourni, qui décrit où le système d'aide la documentation doit être connectée ; c'est un fichier XML très simple, comme ceci : 
    <?xml version="1.0"?>
    <monodoc>
      <source provider="ecma" basefile="ProjectName"
        path="various" />
    </monodoc>
Le fichier de configuration ci-dessus décrit que la documentation est au format ECMA, que le nom de fichier de base est ProjectName et qu'elle doit être connectée dans la partie "various" de l'arbre de documentation. Si vous voulez regarder les différents nœuds définis dans la documentation, vous pouvez regarder le fichier monodoc.xml qui est typiquement installé dans /usr/lib/monodoc/monodoc.xml.

Une fois que vous avez tous les fichiers requis (.zip, .tree et .sources), vous pouvez les installer dans le système avec la commande suivante :

    cp ProjectName.tree ProjectName.zip ProjectName.source \
      `pkg-config monodoc --variable sourcesdir`
Ce qui précède copiera les fichiers dans le répertoire que Monodoc a enregistré ; vous pourriez avoir besoin des permissions root pour le faire. Le répertoire réel est retourné par l'invocation de pkg-config.

COMMANDES MDOC

mdoc assemble

Compile la documentation pour une utilisation dans le navigateur monodoc(1).

Voir la page de manuel mdoc-assemble(1) pour plus de détails.

mdoc export-html

Exporte la documentation dans une structure de répertoire de fichiers HTML.

Voir la page de manuel mdoc-export-html(1) pour plus de détails.

mdoc export-msxdoc

Exporte la documentation au format unique Microsoft XML Documentation.

Voir la page de manuel mdoc-export-msxdoc(1) pour plus de détails.

mdoc help

Affiche l'aide interne pour une commande donnée. 
    mdoc help assemble

est équivalent à :

    mdoc assemble --help

Plusieurs sous-commandes peuvent être listées à la fois :

    mdoc help assemble export-html update validate

mdoc update

Met à jour la documentation, en ajoutant et supprimant des membres basés sur un assemblage de référence.

Voir la page de manuel mdoc-update(1) pour plus de détails.

mdoc validate

Valide la documentation par rapport au schéma de documentation Mono.

Voir la page de manuel mdoc-validate(1) pour plus de détails.
