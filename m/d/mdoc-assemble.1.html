mdoc-assemble(1) Manuel des commandes générales mdoc-assemble(1)

NOM

mdoc assemble - Compiler la documentation pour utilisation dans le navigateur de documentation monodoc(1)

SYNTAXE

mdoc assemble [OPTIONS]+ CHEMINS+

DESCRIPTION

mdoc assemble crée des fichiers .tree et .zip à partir des CHEMINS pour utilisation dans le navigateur de documentation monodoc(1).

Les fichiers d'entrée doivent avoir un format supporté, spécifié avec l'option --format.

Les fichiers .tree et .zip sont copiés dans le répertoire sources de monodoc, à côté d'un fichier .source qui est utilisé par monodoc(1) pour spécifier où la documentation doit être affichée.

Le fichier .source a le format suivant :

  <?xml version="1.0"?>
  <monodoc>
    <node label="LIBELLE" name="CHEMIN" parent="PARENT">
      <node label="LIBELLE2" name="CHEMIN2" />
      <!-- ... -->
    </node>
    <source provider="FOURNISSEUR" basefile="FICHIERBASE" path="CHEMIN" />
    <!-- autres éléments <source/> -->
  </monodoc>
Le nœud /monodoc/node est un nœud optionnel qui spécifie où dans l'arborescence monodoc la documentation doit être affichée, et les éléments //node peuvent être imbriqués à n'importe quelle profondeur pour créer des arborescences. //node/@label est le libellé qui sera affiché dans l'arborescence monodoc.

//node/@name est le nom du nœud de l'arborescence monodoc, et peut être utilisé comme valeur de la valeur /monodoc/source/@path.

//node/@parent est le nom du nœud à utiliser comme nœud parent. $MONO_INSTALL_PREFIX/lib/monodoc/monodoc.xml contient une liste de tels noms, et cela peut être n'importe quelle valeur //node/@name. Si la valeur //node/@parent n'est pas trouvée, elle est insérée sous le nœud d'arborescence "Divers".

L'attribut /monodoc/source/@provider spécifie quel fournisseur de format doit être utilisé lors de la lecture des fichiers .tree et .zip ; cela doit correspondre à l'une des valeurs de --format.

L'attribut /monodoc/source/@basefile spécifie le préfixe du nom de fichier pour les fichiers de documentation. Il doit s'agir du même préfixe que celui utilisé avec le paramètre --out. Il ne doit y avoir aucune extension de fichier sur cette valeur.

L'attribut /monodoc/source/@path spécifie le nœud parent dans la vue arborescente de monodoc(1) où la documentation sera insérée. Voir le fichier $MONO_INSTALL_PREFIX/lib/monodoc/monodoc.xml pour une liste des valeurs CHEMIN (les valeurs //node/@name), ou il peut s'agir d'une valeur //node/@name dans le même fichier .source.

Une fois le fichier FICHIERBASE.source écrit, la documentation peut être installée afin que monodoc(1) affiche la documentation avec la commande :

  cp FICHIERBASE.source FICHIERBASE.tree FICHIERBASE.zip \
    `pkg-config monodoc --variable=sourcesdir`

OPTIONS

-f, --format=FORMAT
Spécifie le format de documentation utilisé dans CHEMINS. Les valeurs valides pour FORMAT incluent : ecma, ecmaspec, error, hb, man, simple, et xhtml.

Voir la section FORMATS ci-dessous pour plus d'informations sur ces formats.

Le format par défaut (si aucun n'est spécifié) est ecma.

L'option --format peut être intercalée avec les CHEMINS pour changer le format utilisé pour les paramètres restants (jusqu'à ce que la prochaine option --format soit rencontrée), par exemple :

  mdoc assemble -o PREFIX A B --format=man C D --format=xhtml E
assemblera les répertoires A et B avec le format ecma, les fichiers C et D avec le format man, et le répertoire E avec le format xhtml.
-o, --out=PREFIXE
Spécifie le préfixe du fichier de sortie. mdoc assemble crée les fichiers PREFIXE.zip et PREFIXE.tree.
-h, -?, --help
Affiche un message d'aide et quitte.

FORMATS

Les formats de documentation suivants sont supportés :

ecma

Le Format de Documentation ECMA Mono, un format de documentation XML avec un fichier par type.

Voir la page de manuel mdoc(5) pour plus d'informations.

ecmaspec

Le Format de Documentation de Spécification ECMA Mono. Ce n'est pas le format que vous recherchez ; c'est le format utilisé pour représenter la norme ECMA-334 (C#) au sein de monodoc(1). Il n'est pas utilisé pour afficher la documentation de la bibliothèque de classes ; pour la documentation de la bibliothèque de classes, utilisez le format ecma.

error

Le Format de Documentation d'Erreur est utilisé pour présenter des messages d'erreur détaillés, et est utilisé dans l'arborescence "Référence des Erreurs du Compilateur C#" de monodoc(1).

Dans ce format, CHEMINS est un fichier de configuration, contenant le XML :

    <ErrorProviderConfig>
        <FilesPath>../../mcs/errors</FilesPath>
        <Match>cs????*.cs</Match>
        <ErrorNumSubstringStart>2</ErrorNumSubstringStart>
        <ErrorNumSubstringLength>4</ErrorNumSubstringLength>
        <FriendlyFormatString>CS{0:0###}</FriendlyFormatString>
    </ErrorProviderConfig>
Les éléments signifient :
/ErrorProviderConfig/FilesPath
Spécifie où chercher les fichiers.
/ErrorProviderConfig/Match
Spécifie le motif de nom de fichier à rechercher dans le répertoire /ErrorProviderConfig/FilesPath.
/ErrorProviderConfig/ErrorNumSubstringStart
Spécifie où, dans le nom de fichier, commence le numéro d'erreur.
/ErrorProviderConfig/ErrorNumSubstringLength
Spécifie combien de caractères après /ErrorProviderConfig/ErrorNumSubstringStart utiliser pour le numéro d'erreur.
/ErrorProviderConfig/FriendlyFormatString
Spécifie la mise en forme/l'affichage du nœud dans l'arborescence monodoc(1).

Pour chaque fichier trouvé, il est converti en HTML avec coloration syntaxique C# appliquée.

simple

Le format de fichier Format de Documentation Simple ajoute récursivement tous les fichiers et répertoires sous CHEMINS. Lors de l'affichage, les fichiers HTML sont affichés tels quels. Les fichiers texte sont convertis en HTML en traduisant chaque saut de ligne en un élément HTML <br>. Aucun autre type de fichier n'est supporté.

man

Le Format de Documentation des Pages Man affiche les pages man groff. (Ce n'est pas un analyseur groff complet, et ne gère que les constructions de page man utilisées dans les pages man mono.)

CHEMINS est un ensemble de fichiers XML contenant :

  <?xml version="1.0"?>
  <manpages>
    <manpage name="NOM" page="FICHIER" />
  </manpages>
Il peut y avoir plusieurs éléments //manpage dans l'élément racine /manpage.

L'attribut /manpages/manpage/@name contient le nom d'affichage pour le nœud de la vue arborescente, qui est également l'URL de la page man lors de l'utilisation de la commande URL de Recherche de monodoc(1) (avant de préfixer avec un préfixe man:). Ainsi, si /manpages/manpage/@name contient mono(1), alors man:mono(1) peut être utilisé dans la commande URL de Recherche pour afficher la page man de mono(1).

L'attribut /manpages/manpage/@page est le nom du fichier qui contient la page man. Si ce fichier n'existe pas, alors /manpages/manpage/@name ne sera pas affiché dans la vue arborescente.

xhtml

Le fournisseur XHTML interprète CHEMINS comme un fichier TOC XHTML de fichier d'aide Windows et recherche les références
