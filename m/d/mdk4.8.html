MDK4(2) Manuel des appels système MDK4(2)

NOM

mdk4 - Outil PoC IEEE 802.11

SYNTAXE

mdk4 <interface> <mode_attaque> [options_attaque]
mdk4 <interface entrante> <interface sortante> <mode_attaque> [options_attaque]

DESCRIPTION

mdk4 est un outil de preuve de concept (PoC) pour exploiter les faiblesses courantes du protocole IEEE 802.11.

OPTIONS

Essayez mdk4 --help <mode_attaque> pour obtenir des informations sur une seule attaque.

Essayez mdk4 --fullhelp pour toutes les options d'attaque.

MODES D'ATTAQUE

b - Inondation de balises (Beacon Flooding)
Envoie des trames de balises pour afficher de faux points d'accès (AP) aux clients.
Cela peut parfois faire planter les analyseurs réseau et même les pilotes !
-n <ssid>
Utilise le SSID <ssid> au lieu de ceux générés aléatoirement
-a
Utilise également des caractères non imprimables dans les SSID générés et crée des SSID qui dépassent la limite de 32 octets
-f <nom_fichier>
Lit les SSID depuis un fichier
-v <nom_fichier>
Lit les adresses MAC et les SSID depuis un fichier. Voir le fichier d'exemple !
-t <adhoc>
-t 1 = Crée uniquement des réseaux Ad-Hoc
-t 0 = Crée uniquement des réseaux gérés (AP)
sans cette option, les deux types sont générés
-w <chiffrements>
sans cette option, les deux types sont générés
Options valides : n = Pas de chiffrement, w = WEP, t = TKIP (WPA), a = AES (WPA2)
Vous pouvez sélectionner plusieurs types, par exemple "-w wta" ne créera que des réseaux WEP et WPA
-b <débit_binaire>
Sélectionne si des réseaux à 11 Mbit (b) ou 54 Mbit (g) sont créés Sans cette option, les deux types seront utilisés.
-m
Utilise une adresse MAC de point d'accès valide provenant de la base de données OUI intégrée
-h
Commute sur le canal où le réseau est usurpé
Ceci est plus efficace avec certains appareils/pilotes
Mais cela réduit le débit de paquets en raison du saut de canal.
-c <canal>
Crée de faux réseaux sur le canal <canal>. Si vous voulez que votre carte saute sur ce canal, vous devez également définir l'option -h.
-i <HEX>
Ajoute des IE (Information Element) définis par l'utilisateur en hexadécimal à la fin des paramètres tagués
-s <pps>
Définit la vitesse en paquets par seconde (Défaut : 50)

a - Déni de Service d'Authentification (Authentication Denial-Of-Service)
Envoie des trames d'authentification à tous les AP trouvés à portée.
Trop de clients peuvent geler ou réinitialiser plusieurs AP.

-a <mac_ap>
Ne teste que l'AP spécifié
-m
Utilise une adresse MAC de client valide provenant de la base de données OUI intégrée
-i <mac_ap>
Effectue un test intelligent sur l'AP
Ce test connecte des clients à l'AP et réinjecte des données renifées pour les maintenir actifs.
-s <pps>
Définit la vitesse en paquets par seconde (Défaut : illimité)

p - Sondage et Bruteforce de SSID
Sonde les AP et vérifie la réponse, utile pour vérifier si un SSID a été correctement démasqué et si l'AP est à portée d'émission. Le bruteforce de SSID cachés avec ou sans liste de mots est également disponible.

-e <ssid>
SSID à sonder
-f <nom_fichier>
Lit les SSID depuis un fichier pour le bruteforce de SSID cachés
-t <bssid>
Définit l'adresse MAC de l'AP cible
-s <pps>
Définit la vitesse (Défaut : 400)
-b <ensembles_caracteres>
Utilise le mode Bruteforce complet (recommandé uniquement pour les SSID courts !)
Vous pouvez sélectionner plusieurs ensembles de caractères à la fois :
* n (Chiffres : 0-9)
* u (Majuscules : A-Z)
* l (Minuscules : a-z)
* s (Symboles : ASCII)
-p <mot>
Continue le bruteforce, en commençant à <mot>
-r <canal>
Tests de requêtes de sondage (mod-musket)

d - Désauthentification et Désassociation
Envoie des paquets de désauthentification et de désassociation aux stations basées sur le trafic de données pour déconnecter tous les clients d'un AP.

-w <nom_fichier>
Lit un fichier contenant les adresses MAC à ignorer (Mode liste blanche)
-b <nom_fichier>
Lit un fichier contenant les adresses MAC sur lesquelles effectuer le test (Mode liste noire)
-s <pps>
Définit la vitesse en paquets par seconde (Défaut : illimité)
-x
Active la furtivité IDS complète en faisant correspondre tous les numéros de séquence. Les paquets ne seront envoyés qu'avec les adresses des clients.
-c [chan,chan,...,chan[:vitesse]]
Active le saut de canal. Lorsque -c h est donné, mdk4 sautera sur les 14 canaux b/g. Le canal sera changé toutes les 3 secondes, si la vitesse n'est pas spécifiée. La valeur de la vitesse est en millisecondes !
-E <essid>
Spécifie un ESSID d'AP à attaquer.
-B <bssid>
Spécifie un BSSID d'AP à attaquer.
-S <mac>
Spécifie une adresse MAC de station à attaquer.
-W <mac>
Spécifie une adresse MAC de station autorisée.

m - Exploitation des contre-mesures Michael
Envoie des paquets aléatoires ou réinjecte des doublons sur une autre file d'attente QoS pour provoquer les contre-mesures Michael sur les AP TKIP. L'AP s'arrêtera alors pendant une minute entière, ce qui en fait un DoS efficace.

-t <bssid>
Définit l'AP cible, qui utilise le chiffrement TKIP
-j
Utilise le nouvel exploit QoS qui ne nécessite que la réinjection de quelques paquets au lieu de l'injection de paquets aléatoires, qui est peu fiable mais fonctionne sans QoS.
-s <pps>
Définit la vitesse en paquets par seconde (Défaut : 400)
-w <secondes>
Attend <secondes> entre chaque rafale de paquets aléatoires (Défaut : 10)
-n <compte>
Envoie <compte> paquets aléatoires par rafale (Défaut : 70)

e - Injection de paquets EAPOL Start et Logoff
Inonde un AP avec des trames EAPOL Start pour le maintenir occupé avec de fausses sessions et l'empêcher ainsi de gérer des clients légitimes.
Ou déconnecte des clients en injectant de faux messages EAPOL Logoff.

-t <bssid>
Définit l'AP WPA cible
-s <pps>
Définit la vitesse en paquets par seconde (Défaut : 400)
-l
Utilise les messages Logoff pour déconnecter les clients

s - Attaques pour les réseaux maillés IEEE 802.11s
Diverses attaques sur la gestion des liens et le routage dans les réseaux maillés.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

/> Inondez les voisins et les routes, créez des trous noirs et détournez le trafic !

-f <type>
Tests de fuzzing basiques. Capture des trames Action et Beacon de l'air, les modifie et les rejoue :
Les types de modification suivants sont implémentés :
1 : Rejouer la même trame jusqu'à ce qu'une nouvelle arrive (inondation par duplication)
2 : Changer la Source et le BSSID (pouvant résulter en inondation de voisins)
3 : Tronquer le paquet, laisser l'en-tête 802.11 intact (trouver des erreurs de tampon)
4 : Mode shotgun, écrasement aléatoire d'octets après l'en-tête (trouver des bugs)
5 : Attaque automatisée de skript-kid essayant tout ce qui précède aléatoirement :)
-b <point_de_connexion_imite>
Crée un Blackhole, en utilisant l'adresse MAC du point de connexion imité.
mdk4 répondra à chaque Route Request entrant avec une route parfaite via le nœud imité.
-p <point_de_connexion_imite>
Inondation de requêtes de chemin (Path Request) en utilisant l'adresse du point de connexion imité. Ajustez le commutateur de vitesse (-s) pour un profit maximum !
-l
Crée simplement des boucles sur chaque route trouvée en modifiant les Réponses de Chemin (Path Replies).
-s <pps>
Définit la vitesse en paquets par seconde (Défaut : 100)
-n <meshID>
Cible ce réseau mesh

w - Confusion WIDS
Confondre/abuser des systèmes de détection et de prévention d'intrusion en interconnectant les clients à plusieurs nœuds WDS ou de faux points d'accès non autorisés.
Confond un WDS avec des clients multi-authentifiés, ce qui perturbe les tables de routage.

-e <SSID>
SSID du réseau WDS cible
-c [chan,chan,...,chan[:vitesse]]
Active le saut de canal. Lorsque -c h est donné, mdk4 sautera sur les 14 canaux b/g. Le canal sera changé toutes les 3 secondes, si la vitesse n'est pas spécifiée. La valeur de la vitesse est en millisecondes !
-z
active l'exploit WIDS de Zero_Chaos (authentifie les clients d'un WDS auprès de points d'accès étrangers pour rendre les WIDS fous)
-s <pps>
Définit la vitesse en paquets par seconde (Défaut : 100)

f - Packet Fuzzer
Un simple fuzzer de paquets avec de multiples sources de paquets et un bel ensemble de modificateurs. Soyez prudent ! mdk4 sélectionne aléatoirement les sources données et un ou plusieurs modificateurs.

-s <sources>
Spécifie une ou plusieurs des sources de paquets suivantes :
a - Écoute des paquets dans l'air
b - Crée des trames beacon valides avec des SSIDs et des propriétés aléatoires
c - Crée des trames CTS à diffuser (vous pouvez également l'utiliser pour un DoS par CTS)
p - Crée des requêtes de sonde (probe requests) en diffusion
-m <modificateurs>
Sélectionne au moins un des modificateurs ici :
n - Pas de modificateur, ne pas modifier les paquetscc
b - Définit l'adresse de destination sur diffusion (broadcast)
m - Définit l'adresse source sur diffusion (broadcast)
s - Shotgun : écrase aléatoirement quelques octets
t - ajoute des octets aléatoires (crée des paramètres tagués incorrects dans les beacons/probes)
c - Tronque les paquets, de préférence quelque part dans les en-têtes ou les tags
d - Insère des valeurs aléatoires dans les champs Durée et Indicateurs (Flags)
-c [chan,chan,...,chan[:vitesse]]
Active le saut de canal. Lorsque -c h est donné, mdk4 sautera sur les 14 canaux b/g. Le canal sera changé toutes les 3 secondes, si la vitesse n'est pas spécifiée. La valeur de la vitesse est en millisecondes !
-p <pps>
Définit la vitesse en paquets par seconde (Défaut : 250)
c x - Tests Poc
Preuves de concept de tests de vulnérabilité d'implémentation du protocole WiFi.
-s <pps>
Définit la vitesse en paquets par seconde (Défaut : illimité)
-c [chan,chan,...,chan[:vitesse]]
Active le saut de canal. Lorsque -c h est donné, mdk4 sautera sur les 14 canaux b/g. Le canal sera changé toutes les 3 secondes, si la vitesse n'est pas spécifiée. La valeur de la vitesse est en millisecondes !
-v<vendor>
Nom de fichier dans le répertoire pocs, par défaut teste tout.
-A <MAC AP>
Définit une MAC de point d'accès
-S <MAC Station>
Définit une MAC de station
