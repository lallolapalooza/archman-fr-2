MD5(3) Manuel des fonctions de bibliothèque MD5(3)

NOM

MD5Init, MD5Update, MD5Pad, MD5Final, MD5Transform, MD5End, MD5File, MD5FileChunk, MD5Data — calculer le condensat de message « MD5 » de RSA Data Security, Inc.

BIBLIOTHÈQUE

Bibliothèque de support des condensats de message (MD4, MD5, etc.) (libmd, -lmd)

SYNTAXE

#include <sys/types.h>
#include <md5.h>

void
MD5Init(MD5_CTX *context);

void
MD5Update(MD5_CTX *context, const uint8_t *data, size_t len);

void
MD5Pad(MD5_CTX *context);

void
MD5Final(uint8_t digest[MD5_DIGEST_LENGTH], MD5_CTX *context);

void
MD5Transform(uint32_t state[4], uint8_t block[MD5_BLOCK_LENGTH]);

char *
MD5End(MD5_CTX *context, char *buf);

char *
MD5File(const char *filename, char *buf);

char *
MD5FileChunk(const char *filename, char *buf, off_t offset, off_t length);

char *
MD5Data(const uint8_t *data, size_t len, char *buf);

DESCRIPTION

Les fonctions MD5 calculent un condensat cryptographique de 128 bits (digest) pour n'importe quel nombre d'octets d'entrée. Un condensat cryptographique est une fonction de hachage unidirectionnelle, c'est-à-dire que vous ne pouvez pas trouver (sauf par recherche exhaustive) l'entrée correspondant à une sortie donnée. Le résultat net est une « empreinte digitale » des données d'entrée, qui ne divulgue pas l'entrée réelle.

MD2 est le plus lent, MD4 est le plus rapide et MD5 se situe quelque part entre les deux. MD2 ne peut être utilisé que pour le courrier à préserver la confidentialité (Privacy-Enhanced Mail). MD4 a été critiqué pour être trop faible, c'est pourquoi MD5 a été développé en réponse comme « MD4 avec des ceintures de sécurité ». MD4 et MD5 ont été compromis ; ils ne devraient être utilisés que lorsque cela est nécessaire pour des raisons de compatibilité descendante. Les attaques sur MD4 et MD5 consistent principalement à trouver des « collisions » – c'est-à-dire plusieurs entrées qui hachent vers la même valeur ; il est toujours peu probable qu'un attaquant puisse déterminer l'entrée exacte d'origine étant donné une valeur de hachage.

Les fonctions MD5Init(), MD5Update(), et MD5Final() sont les fonctions principales. Allouez un MD5_CTX, initialisez-le avec MD5Init(), parcourez les données avec MD5Update() et extrayez finalement le résultat en utilisant MD5Final().

La fonction MD5Pad() peut être utilisée pour appliquer un remplissage au condensat de message comme dans MD5Final(), mais le contexte actuel peut toujours être utilisé avec MD5Update().

La fonction MD5Transform() est utilisée par MD5Update() pour hacher des blocs de 512 bits et constitue le cœur de l'algorithme. La plupart des programmes devraient utiliser l'interface fournie par MD5Init(), MD5Update() et MD5Final() au lieu d'appeler MD5Transform() directement.

MD5End() est une enveloppe pour MD5Final() qui convertit la valeur de retour en une chaîne ASCII de MD5_DIGEST_STRING_LENGTH caractères (y compris le '\0' final) qui représente les 128 bits en hexadécimal.

MD5File() calcule le condensat d'un fichier et utilise MD5End() pour retourner le résultat. Si le fichier ne peut pas être ouvert, un pointeur nul est retourné.

MD5FileChunk() se comporte comme MD5File() mais calcule le condensat uniquement pour la partie du fichier commençant à l'offset et continuant pendant length octets ou jusqu'à la fin du fichier, selon ce qui arrive en premier. Une length nulle peut être spécifiée pour lire jusqu'à la fin du fichier. Une length ou un offset négatif sera ignoré. MD5Data() calcule le condensat d'un bloc de données en mémoire et utilise MD5End() pour retourner le résultat.

Lors de l'utilisation de MD5End(), MD5File(), MD5FileChunk(), ou MD5Data(), l'argument buf peut être un pointeur nul, auquel cas la chaîne retournée est allouée avec malloc(3) et doit ensuite être explicitement désallouée en utilisant free(3) après utilisation. Si l'argument buf n'est pas nul, il doit pointer vers au moins MD5_DIGEST_STRING_LENGTH caractères d'espace tampon.

HISTORIQUE

Ces fonctions sont apparues dans OpenBSD 2.0 et NetBSD 1.3.

AUTEURS

Les routines MD5 originales ont été développées par RSA Data Security, Inc., et publiées dans les références ci-dessus. Ce code est dérivé d'une implémentation du domaine public écrite par Colin Plumb.

Les fonctions d'aide MD5End(), MD5File(), MD5FileChunk() et MD5Data() sont dérivées de code écrit par Poul-Henning Kamp.

BOGUES

Des collisions ont été trouvées pour les versions complètes de MD4 et MD5. L'utilisation de sha2(3) est recommandée à la place.
