MIX(1) Manuel des commandes générales MIX(1)

NOM

mix — L'outil de gestion de projet logiciel

SYNTAXE

mix [TACHE] [nom_projet]

elixir [OPTIONS] -S mix [TACHE] [nom_projet]

DESCRIPTION

mix est destiné à la fois à l'organisation du code en projets et à leur maintenance. Pour cette dernière, l'outil offre des fonctionnalités avancées telles que la gestion des dépendances, le packaging, la préparation de la documentation, les tests, etc.

Regardez la section SYNTAXE et la deuxième façon d'exécuter mix qu'elle propose. L'idée est que l'outil n'est autre que le script Elixir, donc il peut être appelé via elixir(1) de la même manière que n'importe quel autre script. C'est utile lorsque vous souhaitez exécuter mix avec des options particulières.

DÉFINITIONS

Toutes les fonctionnalités de mix sont représentées par un ensemble de tâches. Une tâche est un morceau de code écrit en Elixir et destiné à résoudre un problème particulier. Comme les programmes, de nombreuses tâches acceptent des paramètres d'entrée et/ou prennent en charge des options qui modifient légèrement leur comportement, mais d'autres non. Il existe deux types de tâches : celles qui sont disponibles après l'installation de telle ou telle archive (tâches locales) et celles qui sont proposées par mix (tâches intégrées). La tâche run sera exécutée par défaut si aucune autre n'a été spécifiée.

Bien que la majeure partie de mix soit constituée de tâches, la page de manuel ne contient pas les informations d'aide relatives à chacune d'elles car mix est auto-descriptif. Ainsi, en utilisant la tâche help, vous pouvez obtenir à la fois la liste complète des tâches locales/intégrées et les informations relatives à une tâche particulière.

Une archive, en termes Erlang/OTP, est le fichier ZIP avec l'extension .ez qui contient une application OTP précompilée avec toutes ses dépendances [1].

Une application est une entité qui aide à combiner des ensembles de composants en une seule unité pour simplifier leur réutilisation dans d'autres systèmes [2].

ENVIRONNEMENT

MIX_ARCHIVES
Permet de spécifier le répertoire dans lequel les archives doivent être installées (voir mix help archive.install). Le répertoire ~/.mix/archives est utilisé à cette fin par défaut.
MIX_DEBUG
Lorsqu'il est défini, affiche des informations de débogage sur chaque tâche avant de l'exécuter.
MIX_ENV
Permet de spécifier quel environnement doit être utilisé. L'environnement dev est utilisé par défaut si aucun autre n'a été spécifié.

Parfois, vous devez utiliser un ensemble particulier de valeurs de paramètres de configuration ou effectuer des étapes particulières lors de la compilation ou de l'exécution d'un projet (ou dans d'autres cas). Les environnements mix permettent de regrouper les valeurs des paramètres de configuration et les étapes pour basculer entre eux en spécifiant l'environnement nécessaire via MIX_ENV.

MIX_TARGET
Permet de spécifier quelle cible doit être utilisée. La cible host est utilisée par défaut si aucune autre n'a été spécifiée.
MIX_EXS
Permet de modifier le chemin complet du fichier mix.exs (voir la section FICHIERS section). Le cas d'utilisation le plus évident est d'avoir plus d'une copie de mix.exs dans un projet, mais il est à noter que MIX_EXS ne doit être utilisé que si les environnements mix (voir ci-dessus) ne suffisent pas à résoudre le problème.
MIX_HOME
chemin du répertoire personnel de Mix, stocke les fichiers de configuration et les scripts utilisés par Mix
MIX_INSTALL_DIR
Spécifie le répertoire où Mix.install/2 conserve le cache d'installation
MIX_INSTALL_FORCE
Exécute Mix.install/2 avec un cache d'installation vide
MIX_PATH
Permet d'étendre le chemin de code. Si la variable d'environnement MIX_PATH a une valeur composée de plusieurs chemins, ils doivent être séparés par des deux-points (pour les systèmes d'exploitation de type Unix) ou par des points-virgules (pour Windows).

Comme mentionné ci-dessus, il existe deux types de tâches : locales et intégrées. Ces tâches sont toujours visibles pour mix car les répertoires dans lesquels elles se trouvent font partie du chemin de code. Si une tâche n'appartient ni à l'un ni à l'autre type, MIX_PATH vous aide à indiquer à mix où il doit rechercher la tâche.

MIX_QUIET
Lorsqu'il est défini, n'imprime pas les messages d'information dans le terminal.

FICHIERS

mix.exs
Contient les informations les plus significatives relatives au projet, telles que son nom, sa version, sa liste de dépendances, etc. En règle générale, le fichier est nommé mix.exs et se trouve en haut de l'arborescence source du projet, mais vous pouvez modifier le chemin complet vers celui-ci en utilisant la variable d'environnement MIX_EXS (voir la section ENVIRONNEMENT section).
mix.lock
Permet de verrouiller les dépendances du projet avec une plage de versions appropriée avant d'effectuer des mises à jour. C'est utile lorsque vous savez que votre projet est incompatible avec les versions plus récentes de certaines dépendances. Le fichier est situé en haut de l'arborescence source du projet, tout comme mix.exs (voir ci-dessus).
