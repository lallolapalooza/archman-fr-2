NOM

mimetype - Déterminer le type de fichier

SYNTAXE

mimetype [options] [-] fichiers

DESCRIPTION

Ce script tente de déterminer le type MIME d'un fichier en utilisant la base de données Shared MIME-info. Il est conçu pour fonctionner de manière similaire à file(1), mais utilise des types MIME au lieu de descriptions.

Si vous créez un lien symbolique de la commande file vers mimetype, il se comportera un peu plus en mode de compatibilité, voir "--file-compat". Les options en ligne de commande pour spécifier des fichiers magiques alternatifs ne sont pas implémentées de la même manière en raison des formats de données conflictuels. De plus, la formulation des descriptions différera.

Pour la dénomination des commutateurs, j'ai suivi le manuel de file(1) version 4.02 lorsque c'était possible. Ils semblent différer complètement de la spécification dans le chapitre 'utilities' de IEEE Std 1003.1-2001 (POSIX).

OPTIONS

-a, --all
Afficher la sortie de toutes les règles qui correspondent au fichier.

TODO : cette méthode ne retourne actuellement qu'une seule correspondance pour chaque méthode (globs, magic, etc.).

-b, --brief
Ne pas précéder les noms de fichiers aux lignes de sortie (mode bref).
--database=mimedir:mimedir:...
Forcer le programme à rechercher dans ces répertoires la base de données shared mime-info. Les répertoires spécifiés par la spécification basedir sont ignorés.
-d, --describe
Afficher des descriptions de fichiers au lieu de types MIME, c'est le défaut lorsque vous utilisez "--file-compat".
-D, --debug
Afficher des informations de débogage sur la manière dont le type MIME a été déterminé.
-f namefile, --namefile=namefile
Lire les noms des fichiers à examiner dans le fichier 'namefile' (un par ligne) avant la liste des arguments.
--file-compat
Faire en sorte que mimetype se comporte un peu plus en compatibilité avec file(1). Ceci est activé automatiquement lorsque vous appelez mimetype via un lien appelé 'file'.

Un simple '-' ne sera plus considéré comme un séparateur entre les options et les noms de fichiers, mais deviendra identique à "--stdin". ( Vous pouvez toujours utiliser '--' comme séparateur, mais ce n'est pas rétrocompatible avec la commande file d'origine. ) De plus, le comportement par défaut devient l'affichage des descriptions au lieu des types MIME.

-F chaîne, --separator=chaîne
Utiliser la chaîne comme séparateur personnalisé entre le nom du fichier et son type MIME ou sa description, par défaut ':' .
-h, --help
-u, --usage
Afficher un message d'aide et quitter.
-i, --mimetype
Utiliser les types MIME, à l'opposé de "--describe", c'est le défaut lorsque vous n'utilisez PAS "--file-compat".
-L, --dereference
Suivre les liens symboliques.
-l code, --language=code
L'attribut language spécifie un code de langue à deux lettres, cela permet d'afficher les descriptions dans la langue spécifiée.
-M, --magic-only
Ne pas vérifier les extensions, les globs ou le type d'inode, regarder uniquement le contenu du fichier. Ceci est particulièrement utile si, pour une raison quelconque, vous n'avez pas confiance dans le nom ou l'extension d'un fichier.
-N, --noalign
Ne pas aligner les champs de sortie.
--output-format
Si vous souhaitez un format de sortie alternatif, vous pouvez spécifier une chaîne de format contenant les échappements suivants : 
%f pour le nom du fichier
%d description
%m type MIME

L'alignement n'est pas disponible lorsque vous utilisez ceci, vous devez post-traiter la sortie pour cela.

--stdin
Déterminer le type de contenu à partir de STDIN, moins puissant que la vérification normale des fichiers car il utilise uniquement la classification magique. Cela se produira également si le descripteur de fichier STDIN est un pipe.

Pour utiliser cette option, IO::Scalar doit être installé.

-v, --version
Afficher la version du programme et quitter.

ENVIRONNEMENT

XDG_DATA_HOME
XDG_DATA_DIRS
Ces variables peuvent lister les répertoires de base pour rechercher les fichiers de données. Le fichier shared mime-info sera attendu dans le sous-répertoire "mime" de l'un de ces répertoires. S'ils ne sont pas définis, les répertoires suivants seront recherchés : 
$HOME/.local/share/mime
/usr/local/share/mime
/usr/share/mime

Voir aussi la "Spécification des Répertoires de Base XDG" http://freedes.org/Standards/basedir-spec

FICHIERS

Le répertoire de base pour tous les fichiers de données est déterminé par deux variables d'environnement, voir "ENVIRONNEMENT".

BASE/mime/packages/SOURCE.xml
Tous les autres fichiers sont compilés à partir de ces fichiers source. Pour les recompiler, utilisez update-mime-database(1).
BASE/mime/globs
Informations compilées sur les globs.
BASE/mime/magic
Informations compilées sur les nombres magiques.
BASE/mime/MEDIA/SUBTYPE.xml
Descriptions d'un type MIME dans plusieurs langues, utilisées pour le commutateur "--describe".

DIAGNOSTICS

Si un fichier a un type MIME vide ou une description vide, il est fort probable que le fichier n'existe pas et que le nom donné ne correspond à aucun glob. Une description vide peut également signifier qu'aucune description n'est disponible dans la langue que vous avez spécifiée.

Le programme se termine avec une valeur de sortie non nulle si les arguments de la ligne de commande ont échoué, si un module dont il dépend n'a pas été trouvé ou si la base de données shared mime-info n'était pas accessible. Voir File::MimeInfo pour plus de détails.

BUGS

Si vous trouvez des bugs, veuillez les signaler dans notre suivi des problèmes Github à https://github.com/mbeijen/File-MimeInfo/issues.

mimetype ne fournit pas de commutateur pour regarder à l'intérieur des fichiers compressés car il me semble que cela ne peut être fait qu'en décompressant le fichier, ce qui va à l'encontre du but recherché. D'un autre côté, l'option devrait exister pour une compatibilité stricte avec file(1). Une sous-classe pourrait éventuellement être créée pour cela un jour.
