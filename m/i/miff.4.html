NOM

MIFF - Magick Image File Format

SYNTAXE

#include <image.h>

DESCRIPTION

Le format de fichier image Magick (MIFF) est un format indépendant de la plateforme pour stocker des images bitmap. MIFF fait partie de la boîte à outils ImageMagick d'utilitaires de manipulation d'images pour le système de fenêtrage X. ImageMagick est capable de convertir de nombreux formats de fichiers image différents vers et depuis MIFF (par exemple, JPEG, XPM, TIFF, etc.).

Un fichier image MIFF se compose de deux sections. La première section est un en-tête composé de clés décrivant l'image sous forme de texte. La section suivante sont les données binaires de l'image. L'en-tête est séparé des données de l'image par un caractère : immédiatement suivi d'un saut de ligne.

L'en-tête MIFF est entièrement composé de caractères LATIN-1. Les champs de l'en-tête sont des combinaisons de clés et de valeurs au format clé=valeur, chaque clé et valeur étant séparées par un signe égal (=). Chaque combinaison clé=valeur est délimitée par au moins un caractère de contrôle ou un espace. Les commentaires peuvent apparaître dans la section d'en-tête et sont toujours délimités par des accolades. L'en-tête MIFF se termine toujours par un caractère deux-points (:), suivi d'un caractère ctrl-Z. Il est également courant de faire précéder le deux-points par un saut de formulaire et un caractère de saut de ligne. Le saut de formulaire empêche l'affichage des données binaires lors de l'utilisation de more(1) sous Unix, tandis que le ctrl-Z a le même effet avec la commande type sur la ligne de commande Win32.

Voici une liste des combinaisons clé=valeur que l'on peut trouver dans un fichier MIFF :

couleur-de-fond=couleur
couleur-de-bordure=couleur couleur-matte=couleur ces clés optionnelles reflètent respectivement les couleurs d'arrière-plan, de bordure et matte de l'image. Une couleur peut être un nom (par exemple, blanc) ou une valeur hexadécimale (par exemple, #ccc).
classe=ClasseDirecte
classe=ClassePseudo le type de données d'image binaire stockées dans le fichier MIFF. Si cette clé est absente, des données d'image ClasseDirecte sont supposées.
couleurs=valeur
le nombre de couleurs dans une image ClasseDirecte. Pour une image ClassePseudo, cette clé spécifie la taille de la palette de couleurs. Si cette clé est absente de l'en-tête et que l'image est ClassePseudo, une palette de 256 niveaux de gris est utilisée avec les données de l'image. Le nombre maximum d'entrées dans la palette est de 65535. espace-couleur=CMYK l'espace colorimétrique des données de pixels. La valeur par défaut est RVB.
colonnes=valeur
la largeur de l'image en pixels. C'est une clé requise et elle n'a pas de valeur par défaut.
compression=BZip
compression=Fax compression=JPEG compression=LZW compression=RLE compression=Zip le type d'algorithme utilisé pour compresser les données de l'image. Si cette clé est absente, les données de l'image sont supposées non compressées.
délai <1/100èmes de seconde>
le délai inter-images dans une séquence d'images. Le délai maximum est de 65535.
profondeur=8
profondeur=16 la profondeur d'une seule valeur de couleur représentant des valeurs allant de 0 à 255 (profondeur 8) ou 65535 (profondeur 16). Si cette clé est absente, une profondeur de 8 est supposée.
disposer valeur
méthode de disposition GIF.

Voici les méthodes valides :

     0  Aucune disposition spécifiée.
     1  Ne pas disposer entre les images.
     2  Écraser l'image avec la couleur d'arrière-plan de l'en-tête.
     3  Écraser avec l'image précédente.
gamma=valeur
le gamma de l'image. S'il n'est pas spécifié, un gamma de 1.0 (réponse de luminosité linéaire) est supposé.
id=ImageMagick
identifie le fichier comme un fichier image au format MIFF. Cette clé est obligatoire et n'a pas de valeur par défaut. Bien que cette clé puisse apparaître n'importe où dans l'en-tête, elle devrait commencer comme la première clé de l'en-tête en colonne 1. Cela permettra à des programmes comme file(1) d'identifier facilement le fichier comme MIFF.
itérations valeur
le nombre de fois qu'une séquence d'images est répétée avant de s'arrêter.
étiquette={valeur}
définit un titre court ou une légende pour l'image. Si un espace apparaît dans l'étiquette, il doit être entouré d'accolades.
matte=Vrai
matte=Faux spécifie si une image ClasseDirecte a des données matte. Les données matte sont généralement utiles pour la composition d'images. Cette clé n'a pas de signification pour les images pseudo-couleur.
montage=<largeur>x<hauteur>{+-}<décalage x>{+-}<décalage y>
taille et emplacement des tuiles individuelles d'une image composite. Voir X(1) pour plus de détails sur la spécification de la géométrie.

Utilisez cette clé lorsque l'image est une composition d'un certain nombre de tuiles différentes. Une tuile se compose d'une image et facultativement d'une bordure et d'une étiquette. <largeur> est la taille en pixels de chaque tuile individuelle dans la direction horizontale et <hauteur> est la taille dans la direction verticale. Chaque tuile doit avoir un nombre égal de pixels en largeur et égal en hauteur. Cependant, la largeur peut différer de la hauteur. <décalage x> est le décalage en nombre de pixels par rapport au bord vertical de l'image composite où commence la première tuile d'une ligne et <décalage y> est le décalage par rapport au bord horizontal où commence la première tuile d'une colonne.

Si cette clé est spécifiée, un répertoire de noms de tuiles doit suivre l'en-tête de l'image. Le format du répertoire est expliqué ci-dessous.

page=valeur
taille et emplacement préférés d'une toile d'image.
profil-icc=valeur
le nombre d'octets dans le profil de couleur du Consortium International de la Couleur. Le profil est défini par la spécification du profil ICC située à ftp://sgigate.sgi.com/pub/icc/icc34.ps.
espace-couleur=RVB
primaire-rouge=x,y
primaire-vert=x,y primaire-bleu=x,y point-blanc=x,y cette clé optionnelle reflète les primaires chromatiques et le point blanc.
intention-rendu=saturation
intention-rendu=perceptuel intention-rendu=absolu intention-rendu=relatif L'intention de rendu est la propriété CSS-1 définie par le Consortium International de la Couleur (http://www.color.org).
resolution=<resolution x>x<resolution y>
résolution verticale et horizontale de l'image. Voir unités pour les unités de résolution spécifiques (par exemple, pixels par pouce).
lignes=valeur
la hauteur de l'image en pixels. C'est une clé requise et elle n'a pas de valeur par défaut.
scène=valeur
le numéro de séquence pour ce fichier image MIFF. Cette clé optionnelle est utilisée lorsqu'un fichier image MIFF fait partie d'une séquence de fichiers utilisés dans une animation.
signature=valeur
cette clé optionnelle contient une chaîne qui identifie de manière unique le contenu des pixels de l'image. L'algorithme de résumé de message SHA-256 de NIST est recommandé.
unités=pixels-par-pouce
unités=pixels-par-centimètre unités de résolution de l'image.

NOM

miff - Format d'échange d'images Magick

SYNTAXE

miff ...

DESCRIPTION

Le format d'échange d'images Magick (MIFF) est un format d'image propriétaire pour les données d'image raster utilisé par ImageMagick. Il est conçu pour stocker des informations sur l'image dans un format lisible et portable.

id=ImageMagick
class=PseudoClass
colors=256
compression=RunlengthEncoded
packets=27601
columns=1280
rows=1024
signature=d79e1c308aa5bbcdeea8ed63df412da9
copyright={Copyright (c) 2001 ImageMagick Studio}
<FF>
:

Notez que les combinaisons clé=valeur peuvent être séparées par des sauts de ligne ou des espaces et peuvent apparaître dans n'importe quel ordre dans l'en-tête. Les commentaires (entre accolades) peuvent apparaître n'importe où avant les deux points.

Si vous spécifiez la clé montage dans l'en-tête, suivez l'en-tête d'un répertoire de vignettes d'image. Ce répertoire se compose d'un nom pour chaque vignette de l'image composite séparé par un caractère de saut de ligne. La liste est terminée par un caractère NUL.

Si vous spécifiez la clé color-profile dans l'en-tête, suivez l'en-tête (ou le répertoire de montage si la clé montage est dans l'en-tête) du profil de couleur binaire.

Vient ensuite le données binaires de l'image elle-même. La façon dont les données de l'image sont formatées dépend de la classe de l'image telle que spécifiée (ou non spécifiée) par la valeur de la clé class dans l'en-tête.

Les images DirectClass (class=DirectClass) sont des images en ton continu, stockées sous forme de valeurs d'intensité RVB (rouge, vert, bleu), RVBA (rouge, vert, bleu, alpha) ou CMJN (cyan, jaune, magenta, noir) telles que définies par la clé colorspace. Chaque valeur d'intensité a la longueur d'un octet pour les images de profondeur 8 (0..255), tandis que les images de profondeur 16 (0..65535) nécessitent deux octets dans l'ordre de l'octet le plus significatif en premier.

Les images PseudoClass (class=PseudoClass) sont des images RVB avec une palette de couleurs. La palette de couleurs est stockée sous forme d'une série de valeurs de pixels rouge, vert et bleu, chaque valeur étant d'un octet. Si la profondeur de l'image est de 16, chaque entrée de palette consomme deux octets, l'octet le plus significatif étant le premier. Le nombre d'entrées de palette est défini par la clé colors. Les données de la palette se trouvent immédiatement après l'en-tête (ou le répertoire d'images si la clé montage est dans l'en-tête). Les données d'image PseudoClass sont un tableau d'indices dans la carte de couleurs. S'il y a 256 couleurs ou moins dans l'image, chaque octet de données d'image contient une valeur d'indice. Si l'image contient plus de 256 couleurs ou si la profondeur de l'image est de 16, la valeur d'indice est stockée sous forme de deux octets contigus avec l'octet le plus significatif en premier. Si matte est vrai, chaque indice de palette est suivi d'une valeur alpha de 1 ou 2 octets.

Les données d'image dans un fichier MIFF peuvent être non compressées, compressées par codage run-length, compressées par Zip, ou compressées par BZip. La clé compression dans l'en-tête définit comment les données d'image sont compressées. Les pixels non compressés sont simplement stockés une ligne de balayage à la fois dans l'ordre des lignes. La compression par codage run-length compte les séquences de pixels adjacents identiques et stocke les pixels suivis d'un octet de longueur (le nombre de pixels identiques moins 1). La compression Zip et BZip compresse chaque ligne d'une image et précède la ligne compressée par la longueur des octets de pixels compressés sous forme de mot dans l'ordre de l'octet le plus significatif en premier.

Les fichiers MIFF peuvent contenir plus d'une image. Il suffit de concaténer chaque image individuelle (composée d'un en-tête et de données d'image) dans un seul fichier.
