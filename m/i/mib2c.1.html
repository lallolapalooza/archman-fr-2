NOM

mib2c -- génère du code modèle pour étendre l'agent

SYNOPIS

mib2c [-h] -c FICHIER_CONFIG [-I CHEMIN] [-f NOM_SORTIE] [-i][-s][-q][-S VAR=VAL] NOEUD_MIB

DESCRIPTION

L'outil mib2c est conçu pour prendre une partie de l'arborescence MIB (telle que définie par un fichier MIB) et générer le code C modèle nécessaire pour implémenter les objets de gestion pertinents.

Pour implémenter un nouveau module MIB, trois fichiers sont nécessaires :

- Fichier de définition MIB
- Fichier d'en-tête C
- Fichier d'implémentation C.

L'outil mib2c utilise le fichier de définition MIB pour produire les deux fichiers de code C. Ainsi, mib2c génère un modèle que vous pouvez modifier pour ajouter la logique nécessaire pour obtenir des informations du système d'exploitation ou de l'application afin de compléter le module.

NOEUD_MIB est le nœud MIB de plus haut niveau pour lequel vous souhaitez générer du code. Vous devez fournir à mib2c un nœud MIB (par exemple, ifTable) sur la ligne de commande, pas un fichier MIB. C'est l'erreur la plus courante.

L'outil mib2c accepte les deux MIB SMIv1 et SMIv2.

mib2c doit pouvoir trouver et charger un fichier MIB afin de générer du code C pour le MIB. Pour permettre à mib2c de trouver le fichier MIB, définissez la variable d'environnement MIBS pour inclure le fichier MIB que vous utilisez. Un exemple de définition de cette variable d'environnement est :


MIBS=+NET-SNMP-TUTORIAL-MIB


ou


MIBS=ALL

Le premier exemple garantit que mib2c trouve le MIB NET-SNMP-TUTORIAL-MIB, en plus des modules MIB par défaut. La liste par défaut des modules MIB est définie lors de la première configuration et compilation de la suite et correspond essentiellement à la liste des modules pris en charge par l'agent. Le second exemple garantit que mib2c trouve tous les MIBs dans l'emplacement de recherche des fichiers MIB. L'emplacement de recherche par défaut pour les fichiers MIB est /usr/share/snmp/mibs. Cet emplacement de recherche peut être modifié par la variable d'environnement MIBDIRS.

Les fichiers MIB à charger et l'emplacement de recherche des fichiers MIB peuvent également être configurés dans le fichier snmp.conf. Veuillez consulter snmp.conf(5) pour plus d'informations.

Les fichiers *.c et *.h générés seront créés dans le répertoire de travail courant.

OPTIONS

-h
Affiche un message d'aide.
-c FICHIER_CONFIG
Utilise FICHIER_CONFIG lors de la génération de code. Ces fichiers seront recherchés d'abord dans le répertoire courant, puis dans le répertoire /usr/share (où se trouvent les fichiers de configuration mib2c par défaut). L'exécution de mib2c sans l'option -c FICHIER_CONFIG affichera une description des valeurs valides pour FICHIER_CONFIG, c'est-à-dire les fichiers de configuration disponibles, y compris ceux que vous pourriez créer.
Par exemple,
% mib2c ifTable
affichera une description des valeurs actuellement disponibles pour FICHIER_CONFIG.
Les valeurs suivantes sont prises en charge pour FICHIER_CONFIG :
mib2c.mfd.conf
mib2c.scalar.conf
mib2c.int_watch.conf
mib2c.iterate.conf
mib2c.create-dataset.conf
mib2c.array-user.conf
mib2c.column_defines.conf
mib2c.column_enums.conf
GÉNÉRATION DE CODE POUR LES OBJETS SCALAIRES :
Si vous écrivez du code pour des scalaires, exécutez :

mib2c -c mib2c.scalar.conf NOEUD_MIB

Si vous souhaitez lier magiquement des variables entières à des scalaires entiers, utilisez :

mib2c -c mib2c.int_watch.conf NOEUD_MIB

GÉNÉRATION DE CODE POUR LES TABLEAUX :

Le fichier de configuration recommandé pour les tableaux est le fichier de configuration MIBs for Dummies, ou MFD. Il masque autant que possible les détails SNMP, générant des fonctions petites et faciles à comprendre. C'est aussi le fichier de configuration le plus flexible et le mieux documenté. Voir les fichiers agent/mibgroup/if-mib/ifTable/ifTable*.c pour un exemple :


mib2c -c mib2c.mfd.conf NOEUD_MIB

Si les données de votre tableau sont conservées ailleurs (par exemple, dans le noyau et non dans la mémoire de l'agent lui-même) et que vous devez les "itérer" pour trouver les bonnes données pour la ligne SNMP accédée. Voir le fichier agent/mibgroup/mibII/vacm_context.c pour un exemple :

mib2c -c mib2c.iterate.conf NOEUD_MIB

Si les données de votre tableau sont conservées dans l'agent (c'est-à-dire qu'elles ne sont pas situées dans une source externe) et qu'elles sont purement pilotées par les données (c'est-à-dire que vous n'avez pas besoin d'effectuer de travail lors d'une définition) : Voir le fichier agent/mibgroup/examples/data_set.c pour un exemple d'un tel tableau :

mib2c -c mib2c.create-dataset.conf NOEUD_MIB

Si les données de votre tableau sont conservées dans l'agent (c'est-à-dire qu'elles ne sont pas situées dans une source externe), et que vous pouvez conserver vos données triées par l'index du tableau, mais que vous devez effectuer des opérations lors d'une définition :

mib2c -c mib2c.array-user.conf NOEUD_MIB

GÉNÉRATION DES DÉFINITIONS DE FICHIERS D'EN-TÊTE

Pour générer uniquement un en-tête avec une définition pour chaque numéro de colonne de votre tableau :

mib2c -c mib2c.column_defines.conf NOEUD_MIB

Pour générer uniquement un en-tête avec une définition pour chaque énumération pour toute colonne contenant des énumérations :

mib2c -c mib2c.column_enums.conf NOEUD_MIB

GÉNÉRATION DE CODE POUR LA LIGNE DE CODE 4.X (API PLUS ANCIENNE)

mib2c -c mib2c.old-api.conf NOEUD_MIB

-ICHEMIN
Recherche les fichiers de configuration dans CHEMIN. Plusieurs chemins peuvent être spécifiés en utilisant plusieurs commutateurs -I ou en utilisant un seul avec une liste de chemins séparés par des virgules.
-f NOM_SORTIE
Place le code de sortie dans NOM_SORTIE.c et NOM_SORTIE.h. Normalement, mib2c placera le code de sortie dans des fichiers qui correspondent aux noms de tableaux pour lesquels il génère du code, ce qui est probablement ce que vous voulez de toute façon.
-i
N'exécute pas indent sur le code résultant.
-s
Ne recherche pas MIBNODE.sed et n'exécute pas sed sur le code résultant. Ceci est utile pour raccourcir les noms de variables MIB longs dans le code.
-q
Exécute en mode "silencieux", ce qui minimise les messages d'état générés par mib2c.
-SVAR=VAL
Prédéfinit une variable VAR, dans le fichier mib2c.*.conf, à la valeur VAL. Aucun des fichiers de configuration mib2c.*.conf existants n'utilise actuellement cette fonctionnalité, par conséquent, cette option doit être considérée comme disponible uniquement pour une utilisation future.

EXEMPLES

Ce qui suit génère du code C modèle pour les fichiers d'en-tête et d'implémentation pour implémenter UCD-DEMO-MIB::ucdDemoPublic.

% mib2c -c mib2c.scalar.conf ucdDemoPublic
écriture dans ucdDemoPublic.h
écriture dans ucdDemoPublic.c
exécution de indent sur ucdDemoPublic.h
exécution de indent sur ucdDemoPublic.c

Les fichiers ucdDemoPublic.c et ucdDemoPublic.h résultants sont générés dans le répertoire de travail courant.

Ce qui suit génère du code C modèle pour les fichiers d'en-tête et d'implémentation pour le module permettant d'implémenter TCP-MIB::tcpConnTable.

% mib2c -c mib2c.iterate.conf tcpConnTable
écriture dans tcpConnTable.h
écriture dans tcpConnTable.c
exécution de indent sur tcpConnTable.h
exécution de indent sur tcpConnTable.c

Les fichiers tcpConnTable.c et tcpConnTable.h résultants sont générés dans le répertoire de travail courant.
