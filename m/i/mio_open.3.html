NOM

mio_open, mio_close, mio_read, mio_write, mio_nfds, mio_pollfd, mio_revents, mio_eof — Interface sndio pour les flux MIDI

SYNTAXE

#include <sndio.h>

struct mio_hdl *
mio_open(const char *name, unsigned int mode, int nbio_flag);

void
mio_close(struct mio_hdl *hdl);

size_t
mio_read(struct mio_hdl *hdl, void *addr, size_t nbytes);

size_t
mio_write(struct mio_hdl *hdl, const void *addr, size_t nbytes);

int
mio_nfds(struct mio_hdl *hdl);

int
mio_pollfd(struct mio_hdl *hdl, struct pollfd *pfd, int events);

int
mio_revents(struct mio_hdl *hdl, struct pollfd *pfd);

int
mio_eof(struct mio_hdl *hdl);

DESCRIPTION

La bibliothèque sndio permet aux processus utilisateurs d'accéder au matériel midi(4) ainsi qu'aux boîtes MIDI thru et ports de contrôle sndiod(8) de manière uniforme.

Ouverture et fermeture d'un flux MIDI

L'application doit d'abord appeler la fonction mio_open() pour obtenir un descripteur représentant le flux nouvellement créé ; il sera passé plus tard comme argument hdl à la plupart des autres fonctions. Le paramètre name donne la chaîne de périphérique discutée dans sndio(7). Si le programme utilise un seul périphérique et ne fournit pas de sélecteur de périphérique, il doit être défini à MIO_PORTANY pour permettre à l'utilisateur de le sélectionner via la variable d'environnement MIDIDEVICE.

Le paramètre mode donne la direction du flux. Les modes suivants sont pris en charge :

MIO_OUT
Le flux est en sortie uniquement ; les données écrites dans le flux seront envoyées au matériel ou à d'autres programmes.
MIO_IN
Le flux est en entrée uniquement ; les données reçues du matériel ou d'autres programmes doivent être lues depuis le flux.
MIO_IN | MIO_OUT
Le flux envoie et reçoit des données. Ce mode doit être utilisé plutôt que d'appeler mio_open() deux fois.

Si l'argument nbio_flag est vrai (c'est-à-dire non nul), alors les fonctions mio_read() et mio_write() (voir ci-dessous) seront non bloquantes.

La fonction mio_close() ferme le flux et libère toutes les ressources allouées associées au descripteur libsndio.

Envoi et réception de données

Lorsque le mode entrée est sélectionné, la fonction mio_read() doit être appelée pour récupérer les données reçues ; elle doit être appelée assez souvent pour s'assurer que les tampons internes ne déborderont pas. Elle stockera au maximum nbytes octets à l'emplacement addr. À moins que le drapeau nbio_flag ne soit défini, elle se bloquera jusqu'à ce que des données soient disponibles et ne retournera zéro qu'en cas d'erreur.

Lorsque le mode sortie est sélectionné, la fonction mio_write() peut être appelée pour fournir des données à transmettre. À moins que nbio_flag ne soit défini, mio_write() se bloquera jusqu'à ce que la quantité de données demandée soit écrite.

Opération en mode non bloquant

Si le drapeau nbio_flag est défini lors de l'appel à mio_open(), alors les fonctions mio_read() et mio_write() ne bloqueront jamais ; si aucune donnée n'est disponible, elles retourneront immédiatement zéro.

Pour éviter les boucles d'attente active lorsque le mode non bloquant est utilisé, l'appel système poll(2) peut être utilisé pour vérifier si des données peuvent être lues ou écrites sur le flux. La fonction mio_pollfd() prépare le tableau pfd de structures pollfd pour une utilisation avec poll(2). La taille optimale du tableau pfd, que l'appelant doit pré-allouer, est fournie par la fonction mio_nfds().

poll(2) dormira jusqu'à ce que l'un des events demandés avec mio_pollfd() se produise. Les événements sont représentés par un masque de bits des constantes POLLIN et POLLOUT. Les événements qui ont réveillé poll(2) peuvent être obtenus avec la fonction mio_revents(). Si POLLIN est défini, mio_read() peut être appelée sans bloquer. Si POLLOUT est défini, mio_write() peut être appelée sans bloquer. POLLHUP peut être défini s'il y a une erreur, même s'il n'est pas demandé avec mio_pollfd().

Gestion des erreurs

Les erreurs liées au sous-système MIDI (comme les erreurs matérielles ou les connexions interrompues) et les erreurs de programmation (comme un appel à mio_read() sur un flux de lecture uniquement) sont considérées comme fatales. Une fois qu'une erreur se produit, toutes les fonctions qui prennent un argument mio_hdl, à l'exception de mio_close() et mio_eof(), cessent de fonctionner (c'est-à-dire qu'elles retournent toujours 0).

VALEURS DE RETOUR

La fonction mio_open() retourne le descripteur nouvellement créé en cas de succès ou NULL en cas d'échec.

La fonction mio_pollfd() retourne le nombre de structures pollfd remplies. La fonction mio_nfds() retourne le nombre de structures pollfd que l'appelant doit pré-allouer afin d'être sûr que mio_pollfd() ne débordera jamais.

La fonction mio_revents() retourne le masque de bits défini par poll(2) dans le tableau pfd des structures pollfd.
