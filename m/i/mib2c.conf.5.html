NOM

mib2c.conf - Comment écrire des fichiers mib2c.conf pour faire N'IMPORTE QUOI basé sur l'entrée MIB.

SYNTAXE

% cat > mib2c.test.conf << EOF @foreach $t table@
Début de la table $t
@foreach $c column@
echo $t a une colonne $c qui a une syntaxe de $c.syntax
@end@

@end@ EOF

% mib2c -c mib2c.test.conf internet

DESCRIPTION

Le langage de script mib2c.conf est un langage particulier aux MIB, conçu pour traiter facilement les nœuds MIB de la manière souhaitée. mib2c est un terme impropre (pour des raisons historiques), car vous pouvez produire n'importe quoi (pas seulement du code C). Regardez dans le répertoire « local » de Net-SNMP pour trouver un tas de fichiers mib2c.*.conf d'exemple et constatez la puissance qui se trouve devant vous.

COMMANDES

Toutes les commandes dans les fichiers mib2c.conf sont entourées de signes @. Tout ce qui a un signe @ au début et à la fin de la ligne est généralement censé être une commande spécifique à mib2c. Celles-ci sont détaillées ici :

@open FICHIER@
écrit la sortie générée dans FICHIER. Notez que pour les spécifications de fichiers, ouvrir « - » imprimera sur la sortie standard.
@append FICHIER@
ajoute le FICHIER donné.
@close FICHIER@
ferme le FICHIER donné.
@push@
sauvegarde les sorties actuelles, puis efface les sorties. À utiliser avec @open@ et @pop@ pour écrire dans un nouveau fichier sans interférer avec les sorties actuelles.
@pop@
remonte la pile de processus d'un niveau. À utiliser après un @push@ pour revenir au niveau précédent des fichiers ouverts.
@foreach $VAR scalaire@
répète l'itération sur le code jusqu'à @end@ en définissant $VAR sur tous les scalaires connus.
@foreach $VAR table@
répète l'itération sur le code jusqu'à @end@ en définissant $VAR sur toutes les tables connues.
@foreach $VAR colonne@
répète l'itération sur le code jusqu'à @end@ en définissant $VAR sur toutes les colonnes connues dans une table donnée. Évidemment, cela doit être appelé dans une clause foreach-table.
@foreach $VAR nonindex@
répète l'itération sur le code jusqu'à @end@ en définissant $VAR sur toutes les colonnes non-index connues dans une table donnée. Évidemment, cela doit être appelé dans une clause foreach-table.
@foreach $VAR indexinterne@
répète l'itération sur le code jusqu'à @end@ en définissant $VAR sur toutes les colonnes d'index internes connues dans une table donnée. Évidemment, cela doit être appelé dans une clause foreach-table.
@foreach $VAR indexexterne@
répète l'itération sur le code jusqu'à @end@ en définissant $VAR sur toutes les colonnes d'index externes connues dans une table donnée. Évidemment, cela doit être appelé dans une clause foreach-table.
@foreach $VAR index@
répète l'itération sur le code jusqu'à @end@ en définissant $VAR sur tous les index connus dans une table donnée. Évidemment, cela doit être appelé dans une clause foreach-table.
@foreach $VAR notifications@
répète l'itération sur le code jusqu'à @end@ en définissant $VAR sur toutes les notifications connues.
@foreach $VAR varbinds@
répète l'itération sur le code jusqu'à @end@ en définissant $VAR sur tous les varbinds connus. Évidemment, cela doit être appelé dans une clause foreach-notifications.
@foreach $LABEL, $VALEUR enum@
répète l'itération sur le code jusqu'à @end@ en définissant $LABEL et $VALEUR sur l'étiquette et les valeurs de la liste enum.
@foreach $DEBUT_PLAGE, $FIN_PLAGE plage NOEUD@
répète l'itération sur le code jusqu'à @end@ en définissant $DEBUT_PLAGE et $FIN_PLAGE sur l'ensemble de la plage légalement acceptée pour un NŒUD mib donné.
@foreach $var truc a b c d@
répète l'itération sur les valeurs a, b, c, d telles qu'elles sont attribuées génériquement (c'est-à-dire que les valeurs sont prises directement dans la liste sans expansion mib, etc.).
@while expression@
répète l'itération sur le code jusqu'à ce que l'expression soit fausse.
@eval $VAR = expression@
évalue l'expression et attribue les résultats à $VAR. Ce n'est pas un eval complet de perl, mais une sorte d'eval « pseudo » utile pour des expressions simples tout en conservant le même espace de noms de variables. Voir ci-dessous pour une exportation complète vers perl.
@perleval STUFF@
évalue STUFF directement en perl. Notez que toutes les variables mib2c interprétées dans les fichiers .conf sont dans $vars{NAME} et qu'un avertissement sera imprimé si STUFF ne renvoie pas 0. (ajouter un « return 0; » à la fin de STUFF est une solution de contournement).
@startperl@
@endperl@
traite tout ce qui se trouve entre ces balises comme du code perl et l'évalue.
@next@
redémarre foreach ; ne doit être utilisé qu'à l'intérieur d'une condition. saute hors de la condition actuelle, puis continue à sauter jusqu'à la fin pour la clause foreach actuelle.
@if expression@
évalue l'expression, et si l'expression est vraie, traite la partie contenue jusqu'à ce que le @end@ approprié soit atteint. Si l'expression est fausse, la prochaine expression @elsif expression@ (si elle existe) sera évaluée, jusqu'à ce qu'une expression soit vraie. Si aucune expression de ce type n'existe et qu'une clause @else@ est trouvée, elle sera évaluée.
@ifconf fichier@
Si le fichier spécifié peut être trouvé dans le chemin de recherche des fichiers de configuration, et s'il est trouvé, traite la partie contenue jusqu'à ce qu'un @end@ approprié soit trouvé. Comme avec un @if expression@ régulier, @elsif expression@ et @else@ peuvent être utilisés.
@ifdir dir@
Si le répertoire spécifié existe, traite la partie contenue jusqu'à ce qu'un @end@ approprié soit trouvé. Comme avec un @if expression@ régulier, @elsif expression@ et @else@ peuvent être utilisés.
@define NOM@
@enddefine@
Mémorise « du truc » entre les balises define et enddefine pour un appel ultérieur en tant que NOM par @calldefine NOM@.
@calldefine NOM@
Exécute le truc mémorisé précédemment sous le nom NOM.
@printf « expression » truc1, truc2, ...@
Comme tous les autres printf que vous connaissez et aimez.
@run FICHIER@
Charge le contenu de FICHIER en tant que fichier mib2c, mais n'affecte pas les fichiers actuellement ouverts.
@include FICHIER@
Charge le contenu de FICHIER en tant que fichier mib2c et ajoute sa sortie à la sortie actuelle.
@prompt $var QUESTION@
Présente à l'utilisateur la QUESTION, attend une réponse et la place dans $var.
@print STUFF@
Imprime directement STUFF sur l'écran de l'utilisateur (c'est-à-dire pas là où va la sortie normale de mib2c).
@quit@
Quitter (silencieusement).
@exit@
Quitter !

VARIABLES

Les variables dans le langage mib2c ressemblent beaucoup aux variables perl, en ce sens qu'elles commencent par un « $ ». Elles peuvent être utilisées pour tout ce que vous voulez, mais le plus souvent, elles contiendront les noms des nœuds mib traités par les clauses @foreach ...@.

Elles ont également des propriétés spéciales lorsqu'elles représentent un nœud mib, de sorte que l'ajout de suffixes spéciaux leur permet d'être interprétées d'une manière ou d'une autre. La façon la plus simple de comprendre cela est par un exemple. Si la variable 'x' contenait le mot 'ifType', alors des choses magiques se produiraient. Dans la sortie mib2c, chaque fois que $x est vu, il est remplacé par « ifType ». Des suffixes supplémentaires peuvent être utilisés pour obtenir d'autres aspects de ce nœud mib. Si $x.objectID est vu, il sera remplacé par l'OID pour ifType : « .1.3.6.1.2.1.2.2.1.3 ». D'autres suffixes qui peuvent apparaître après un point sont listés ci-dessous.

Une dernière chose : vous pouvez utiliser des choses comme $vartext se terminant immédiatement par un autre texte ; vous pouvez utiliser des accolades {} pour obtenir une expansion correcte d'une partie seulement de l'entrée mib2c. Par exemple, $xtext produira « $xtext », mais ${x}text produira « ifTypetext » à la place.

$var.uc
version tout en majuscules de $var.
$var.objectID
OID entièrement qualifié, numérique et pointillé.
$var.commaoid
OID numérique séparé par des virgules pour l'initialisation de tableaux.
$var.oidlength
longueur de l'OID.
$var.subid
dernier composant numérique de l'OID.
$var.module
nom du MIB dont provient l'objet.
$var.parent
contient l'étiquette du nœud parent de $var.
$var.isscalar
renvoie 1 si var contient le nom d'un scalaire.
$var.iscolumn
renvoie 1 si var contient le nom d'une colonne.
$var.children
renvoie 1 si var a des enfants.
$var.perltype
SYNTAXE perl du nœud ($SNMP::MIB{node}{'syntax'}).
$var.type
type ASN_XXX du nœud (#define spécifique à Net-SNMP).
$var.decl
type de données C (char, u_long, ...).
$var.readable
1 si un objet est lisible, 0 sinon.
$var.settable
1 si un objet est inscriptible, 0 sinon.
$var.creatable
1 si un objet de colonne peut être créé dans le cadre d'une nouvelle ligne, 0 sinon.
$var.noaccess
1 si non accessible, 0 sinon.
$var.accessible
1 si accessible, mib2c.conf(5) — Arch manual pages

NAME

mib2c.conf(5)

configuration file for MIB2C

SYNOPSIS

mib2c.conf

DESCRIPTION

The MIB2C tool uses a configuration file to control how it generates code. This file is read by MIB2C and is used to configure MIB2C's behavior. The configuration file format is a simple ini(5)-like syntax.

Comments start with a '#' and continue to the end of the line.

The configuration file supports two main sections: OPTIONS and MODULES.

OPTIONS

The OPTIONS section contains general configuration options.

MODULES

The MODULES section is used to configure the behavior of specific MIB2C modules.

COMMANDS

The following commands are supported:

m2c
This command is used to generate code from a MIB file. The syntax is:

m2c [-c config_file] [-h header_file] [-i include_dir] [-o output_file] mib_file

-c
Specifies the configuration file to use. If not specified, MIB2C will look for mib2c.conf in the current directory and then in the user's home directory.
-h
Specifies the header file to generate. If not specified, the header file will be named after the MIB file.
-i
Specifies an include directory to search for other MIB files. This option can be specified multiple times.
-o
Specifies the output file for the generated code. If not specified, the code will be printed to standard output.

The mib_file is the MIB file to process.
