MESON(1) Commandes utilisateur MESON(1)

NOM

meson - un système de construction à haute productivité

DESCRIPTION

Meson est un système de construction conçu pour optimiser la productivité des programmeurs. Il vise à y parvenir en offrant un support simple, prêt à l'emploi, pour les outils et les pratiques de développement logiciel modernes, tels que les tests unitaires, les rapports de couverture, Valgrind, Ccache et similaires.

L'exécutable principal de Meson fournit de nombreuses sous-commandes pour accéder à toutes les fonctionnalités.

La commande setup

L'utilisation de Meson est simple et suit le processus courant en deux phases de la plupart des systèmes de construction. D'abord, vous exécutez Meson pour configurer votre construction :

meson setup [ options ] [ répertoire de construction ] [ répertoire source ]

Notez que le répertoire de construction doit être différent du répertoire source. Meson ne supporte pas la construction à l'intérieur du répertoire source et toute tentative entraînera une erreur.

Après une étape de configuration réussie, vous pouvez construire la source en exécutant la commande de construction réelle dans le répertoire de construction. Le backend par défaut de Meson est Ninja, qui peut être appelé comme suit :

ninja [ cible ]

Vous n'avez besoin d'exécuter la commande Meson qu'une seule fois : lors de la première configuration de votre répertoire de construction. Après cela, vous exécutez simplement la commande de construction. Meson détectera automatiquement les changements dans votre arborescence source et régénérera tous les fichiers nécessaires pour construire le projet.

Meson inclut de nombreuses options intégrées qui peuvent être utilisées pour ajuster la configuration d'un répertoire de construction ; les projets peuvent également ajouter leurs propres options. Pour définir les valeurs des options, utilisez l'argument de ligne de commande -D comme suit :

meson setup -Dopt1=valeur1 -Dopt2=valeur2 le reste de la ligne de commande...

options :

--version
affiche le numéro de version
--help
affiche l'aide de la ligne de commande

La commande configure

meson configure fournit un moyen de configurer un projet Meson depuis la ligne de commande. Son utilisation est simple :

meson configure [ répertoire de construction ] [ options à définir ]

Si le répertoire de construction est omis, le répertoire courant est utilisé à la place.

Si aucun paramètre n'est défini, meson configure affichera la valeur de toutes les options de construction dans la console.

Pour définir des valeurs, utilisez l'argument de ligne de commande -D comme suit.

meson configure -Dopt1=valeur1 -Dopt2=valeur2

La commande dist

meson dist génère une archive de distribution.

meson dist [ options ]

options :

-h, --help
affiche ce message d'aide et quitte
-C WD
répertoire dans lequel se placer avant l'exécution
--allow-dirty
Permet même lorsque le dépôt contient des modifications non validées.
--formats FORMATS
Liste séparée par des virgules des types d'archives à créer. Prend en charge xztar (par défaut), gztar et zip.
--include-subprojects
Inclure le code source des sous-projets utilisés pour la construction.
--no-tests
Ne pas construire et tester les paquets générés.

La commande install

meson install installe le projet.

meson install [ options ]

options :

-h, --help
affiche ce message d'aide et quitte
-C WD
répertoire dans lequel se placer avant l'exécution
--no-rebuild
Ne pas reconstruire avant d'installer.
--only-changed
Écrase uniquement les fichiers plus anciens que le fichier copié.
--quiet
N'imprime pas chaque fichier installé.
--destdir DESTDIR
Définit ou remplace l'environnement DESTDIR. (Depuis 0.57.0)
--dry-run, -n
N'installe pas réellement, mais affiche les journaux. (Depuis 0.57.0)
--skip-subprojects [SKIP_SUBPROJECTS]
Ne pas installer les fichiers des sous-projets donnés. (Depuis 0.58.0)
--tags TAGS
Installe uniquement les cibles ayant l'une des étiquettes données. (Depuis 0.60.0)
--strip
Supprime les cibles même si l'option de suppression n'a pas été définie lors de la configuration. (Depuis 0.62.0)

La commande introspect

Meson introspect est une commande conçue pour faciliter l'intégration avec d'autres outils, tels que les IDE. La sortie de cette commande est au format JSON.

meson introspect [ répertoire de construction ] [ option ]

Si le répertoire de construction est omis, le répertoire courant est utilisé à la place.

options :

--targets
affiche toutes les cibles de haut niveau (exécutables, bibliothèques, etc.)
--target-files
affiche les fichiers source de la cible donnée
--buildsystem-files
affiche tous les fichiers qui composent le système de construction (meson.build, meson.options, meson_options.txt, etc.)
--tests
affiche tous les tests unitaires
--help
affiche l'aide de la ligne de commande

La commande init

meson init crée un nouveau projet

meson init [ options ] [ fichier source... ]

arguments positionnels :

fichier source...
fichiers source. par défaut : tous les fichiers reconnus dans le répertoire courant

options :

-h, --help
affiche ce message d'aide et quitte
-C WD
répertoire dans lequel se placer avant l'exécution
-n NOM, --name NOM
nom du projet. par défaut : nom du répertoire courant
-e EXECUTABLE, --executable EXECUTABLE
nom de l'exécutable. par défaut : nom du projet
-d DEPS, --deps DEPS
dépendances, séparées par des virgules
-l {c,cpp,cs,cuda,d,fortran,java,objc,objcpp,rust,vala}, --language {c,cpp,cs,cuda,d,fortran,java,objc,objcpp,rust,vala}
langage du projet. par défaut : détecté automatiquement en fonction des fichiers source
-b, --build
construire après la génération

--builddir BUILDDIR

répertoire pour la compilation
-f, --force
forcer l'écrasement des fichiers et répertoires existants.
--type {executable,library}
type de projet. par défaut : projet basé sur un exécutable
--version VERSION
version du projet. par défaut : 0.1

La commande test

meson test est un outil auxiliaire pour exécuter des suites de tests de projets utilisant Meson. La manière par défaut d'exécuter les tests est d'invoquer la commande de compilation par défaut :

ninja [ test ]

meson test fournit un ensemble d'outils plus riches pour invoquer les tests.

meson test reconstruit automatiquement les cibles nécessaires pour exécuter les tests lorsqu'il est utilisé avec le backend Ninja. En cas d'échec de la compilation, meson test retournera un code de sortie de 125. Ce code de retour indique à git bisect run de sauter le commit actuel. Ainsi, le bisecting avec git peut être fait commodément comme ceci.

git bisect run meson test -C build_dir

options :

--repeat
exécuter les tests autant de fois que spécifié
--gdb
exécuter les tests sous gdb
--list
lister tous les tests disponibles
--wrapper
invoquer tous les tests via le wrapper donné (par ex. valgrind)
-C
changer de répertoire avant d'exécuter les tests (doit être la racine du répertoire de compilation).
--suite
exécuter les tests de cette suite
--no-suite
ne pas exécuter les tests de cette suite
--no-stdsplit
ne pas séparer stderr et stdout dans les journaux de tests
--benchmark
exécuter les benchmarks au lieu des tests
--logbase
base du nom de fichier à utiliser pour écrire les journaux de tests
--num-processes
nombre de processus parallèles à utiliser pour exécuter les tests
--verbose
ne pas rediriger stdout et stderr
-t
un multiplicateur à utiliser pour les valeurs de temps d'attente des tests (généralement quelque chose comme 100 pour Valgrind)
--setup
utiliser la configuration de test spécifiée --slice SLICE/NUM_SLICES Divise les tests en NUM_SLICES tranches et exécute la tranche numéro SLICE. (Depuis 1.8.0)

La commande wrap

Wraptool est un utilitaire auxiliaire pour gérer les dépendances sources en utilisant le service wrapdb en ligne.

meson wrap < commande > [ options ]

Vous devriez exécuter cette commande dans le répertoire source de niveau supérieur de votre projet.

Commandes :

list
lister tous les projets disponibles
search
rechercher des projets par nom
install
installer un projet avec le nom donné
update
mettre à jour le projet spécifié vers la dernière version disponible
info
afficher les versions disponibles du projet spécifié
status
afficher les versions installées et disponibles des sous-projets actuellement utilisés

La commande subprojects

meson subprojects est utilisé pour gérer les sous-projets.

meson subprojects [ options ] [ commande ]

options :

-h, --help
afficher ce message d'aide et quitter

commandes :

update
Mettre à jour tous les sous-projets depuis les fichiers wrap
checkout
Extraire une branche (git seulement)
download
S'assurer que les sous-projets sont récupérés, même s'ils ne sont pas utilisés. Les sous-projets déjà téléchargés ne sont pas modifiés. Ceci peut être utilisé pour pré-récupérer tous les sous-projets et éviter les téléchargements pendant la configuration.
foreach
Exécuter une commande dans chaque répertoire de sous-projet.
purge
Supprimer tous les artefacts de sous-projets basés sur wrap
packagefiles
Gérer la superposition de packagefiles

La commande compile

meson compile compile le projet.

meson compile [ options ] [ TARGET... ]

arguments positionnels :

TARGET
Cibles à compiler. La cible a le format suivant : [CHEMIN_VERS_LA_CIBLE/]NOM_CIBLE.EXTENSION_CIBLE[:TYPE_CIBLE].

options :

-h, --help
afficher ce message d'aide et quitter
--clean
Nettoyer le répertoire de compilation.
-C WD
répertoire dans lequel se déplacer avant d'exécuter
-j JOBS, --jobs JOBS
Le nombre de tâches d'ouvrier à exécuter (si pris en charge). Si la valeur est inférieure à 1, le programme de compilation devinera.
-l LOAD_AVERAGE, --load-average LOAD_AVERAGE
La moyenne de charge du système à essayer de maintenir (si prise en charge).
-v, --verbose
Afficher une sortie plus détaillée.
--ninja-args NINJA_ARGS
Arguments à passer à `ninja` (appliqué uniquement sur le backend `ninja`).
--vs-args VS_ARGS
Arguments à passer à `msbuild` (appliqué uniquement sur le backend `vs`).
--xcode-args XCODE_ARGS
Arguments à passer à `xcodebuild` (appliqué uniquement sur le backend `xcode`).

The format command

meson format formats a meson source file.

meson format [ options ] [ sources... ]

positional arguments:

sources...
meson source files

options:

-h, --help
show this help message and exit
-q, --check-only
exit with 1 if files would be modified by meson format
-i, --inplace
format files in-place
-r, --recursive
recurse subdirs (requires --check-only or --inplace option)
-c meson.format, --configuration meson.format
read configuration from meson.format
-e, --editor-config
try to read configuration from .editorconfig
-o OUTPUT, --output OUTPUT
output file (implies having exactly one input)

When no command is specified

If you run Meson without a subcommand, it will assume you meant meson setup. However, this syntax is deprecated, and Meson will print a warning message if it is used. You should always use meson setup explicitly, instead of relying on the default.
