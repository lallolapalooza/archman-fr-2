NOM

meek-client - Le plugin de transport client meek

SYN。PSIS

meek-client [OPTIONS]

DESCRIPTION

meek-client est un plugin de transport pour Tor qui encode un flux comme une séquence de requêtes et de réponses HTTP. Il possède une option url pour contrôler vers quel serveur de destination les requêtes sont dirigées, et une option front pour le camouflage de nom de domaine : Le nom de domaine dans l'URL est remplacé par le domaine de front avant que la requête ne soit effectuée, mais l'en-tête Host à l'intérieur de la requête HTTP pointe toujours vers le domaine d'origine. L'idée est de passer par un domaine qui n'est pas bloqué pour atteindre un domaine qui est bloqué.

CONFIGURATION

La configuration de meek-client se fait généralement dans un fichier torrc.

Les options par pont sont configurées avec des arguments SOCKS (paires clé=valeur dans une ligne Bridge). Les arguments SOCKS possibles sont :

url=URL (obligatoire)

L'URL d'une instance de meek-server. Le composant nom de domaine sera typiquement caché par la valeur de l'argument front.

front=DOMAINE

Nom de domaine de front. S'il est fourni, ce nom de domaine remplacera le nom de domaine de url dans la requête DNS et le champ SNI TLS. Le vrai nom de domaine de l'URL apparaîtra toujours dans l'en-tête Host des requêtes HTTP.

utls=CLIENTHELLOID

Utilise la bibliothèque uTLS avec l'empreinte TLS nommée pour le camouflage TLS. Cet argument est incompatible avec l'option de ligne de commande --helper. Les valeurs possibles de CLIENTHELLOID sont :

•HelloRandomizedNoALPN
•HelloFirefox_55
•HelloFirefox_56
•HelloFirefox_63
•HelloFirefox_65
•HelloFirefox_99
•HelloFirefox_102
•HelloFirefox_105
•HelloFirefox_Auto = HelloFirefox_105
•HelloChrome_58
•HelloChrome_62
•HelloChrome_70
•HelloChrome_72
•HelloChrome_83
•HelloChrome_87
•HelloChrome_96
•HelloChrome_100
•HelloChrome_102
•HelloChrome_Auto = HelloChrome_102
•HelloIOS_11_1
•HelloIOS_12_1
•HelloIOS_13
•HelloIOS_14
•HelloIOS_Auto = HelloIOS_14
•HelloEdge_85
•HelloEdge_Auto = HelloEdge_85
•HelloSafari_16_0
•HelloSafari_Auto = HelloSafari_16_0
•Hello360_7_5
•Hello360_Auto = Hello360_7_5
•HelloQQ_11_1
•HelloQQ_Auto = HelloQQ_11_1

Comme cas spécial, les valeurs "none" et "HelloGolang" sont reconnues comme des alias pour omettre l'argument SOCKS utls; c'est-à-dire, utiliser le TLS natif de Go.

Pour des raisons de compatibilité ascendante, chaque argument SOCKS a également une option de ligne de commande équivalente. Par exemple, cette configuration utilisant des arguments SOCKS :

Bridge meek 0.0.2.0:1 url=https://forbidden.example/ front=allowed.example
ClientTransportPlugin meek exec ./meek-client

est la même que celle-ci utilisant des options de ligne de commande :

Bridge meek 0.0.2.0:1
ClientTransportPlugin meek exec ./meek-client --url=https://forbidden.example/ --front=allowed.example

Les arguments SOCKS sont préférés aux options de ligne de commande car ils vous permettent d'avoir plusieurs lignes Bridge avec des paramètres différents. Si un argument SOCKS et une option de ligne de commande sont donnés pour le même paramètre, l'argument SOCKS a la priorité.

L'option globale --helper empêche meek-client d'effectuer des opérations réseau lui-même. Au lieu de cela, il enverra toutes les requêtes via une extension de navigateur, qui doit être configurée séparément.

Un proxy global (s'applique à toutes les lignes Bridge) peut être configuré en utilisant des options torrc spéciales :

Socks4Proxy localhost:1080
Socks5Proxy localhost:1080
Socks5ProxyUsername username
Socks5ProxyPassword password
HTTPSProxy localhost:8080
HTTPSProxyAuthenticator username:password

ou, de manière équivalente, en utilisant l'option de ligne de commande --proxy. L'option de ligne de commande a la priorité.

Lorsque l'option --helper est utilisée, vous pouvez utiliser des proxies de type http, socks4a ou socks5, mais vous ne pouvez pas utiliser de nom d'utilisateur ou de mot de passe avec le proxy. Sans --helper, vous pouvez utiliser des proxies de type http, https ou socks5, et vous pouvez facultativement utiliser un nom d'utilisateur et un mot de passe.

OPTIONS

--front=DOMAINE

Nom de domaine de front. Préférez utiliser l'argument SOCKS front sur une ligne de pont plutôt que d'utiliser cette option de ligne de commande.

--helper=ADRESSE

Adresse de l'extension de navigateur d'aide HTTP. Par exemple, --helper=127.0.0.1:7000.

--proxy=URL

URL du proxy en amont. Par exemple, --proxy=http://localhost:8080/, --proxy=socks4a://localhost:1080, ou --proxy=socks5://localhost:1080. Peut également être configuré en utilisant les options HTTPSProxy, Socks4Proxy, ou Socks5Proxy dans un fichier torrc.

--log=NOM_FICHIER

Nom d'un fichier auquel écrire les messages de journalisation (par défaut stderr).

--url=URL

URL à laquelle correspondre. Préférez utiliser l'argument SOCKS url sur une ligne de pont plutôt que d'utiliser cette option de ligne de commande.

--utls=CLIENTHELLOID

Utilise uTLS avec l'empreinte TLS donnée pour le camouflage TLS. Cette option est incompatible avec --helper. Préférez utiliser l'argument SOCKS utls plutôt que d'utiliser cette option de ligne de commande.

-h, --help

Affiche un message d'aide et quitte.
