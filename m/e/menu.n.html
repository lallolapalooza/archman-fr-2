NOM

menu, tk_menuSetFocus - Créer et manipuler les widgets 'menu' et les barres de menu

SYNOPSIS

menu cheminNom ?options?
tk_menuSetFocus cheminNom

OPTIONS STANDARD

-activebackground	-borderwidth	-foreground
-activeborderwidth	-cursor	-relief
-activeforeground	-disabledforeground	-takefocus
-background	-font

Voir la page de manuel options pour plus de détails sur les options standard.

OPTIONS SPÉCIFIQUES AU WIDGET

Nom de ligne de commande :	-postcommand
Nom de base de données :	postCommand
Classe de base de données :	Command
Si cette option est spécifiée, elle fournit une commande Tcl à exécuter à chaque fois que le menu est affiché. La commande est appelée par la commande widget post avant d'afficher le menu. Notez que dans Tk 8.0 sur Macintosh et Windows, toutes les commandes de post d'un système de menus sont exécutées avant que l'un de ces menus ne soit affiché. Ceci est dû aux limitations des gestionnaires de menus des plateformes individuelles.
Nom de ligne de commande :	-selectcolor
Nom de base de données :	selectColor
Classe de base de données :	Background
Pour les éléments de menu qui sont des cases à cocher ou des boutons radio, cette option spécifie la couleur à afficher dans l'indicateur lorsque la case à cocher ou le bouton radio est sélectionné.
Nom de ligne de commande :	-tearoff
Nom de base de données :	tearOff
Classe de base de données :	TearOff
Cette option doit avoir une valeur booléenne valide, spécifiant si le menu doit inclure ou non un élément détachable en haut. Si c'est le cas, il existera comme élément 0 du menu et les autres éléments seront numérotés à partir de 1. Les liaisons de menu par défaut permettent de détacher le menu lorsque l'élément détachable est appelé. Cette option est ignorée sous Aqua/macOS, où les menus ne peuvent pas être détachés.
Nom de ligne de commande :	-tearoffcommand
Nom de base de données :	tearOffCommand
Classe de base de données :	TearOffCommand
Si cette option a une valeur non vide, elle spécifie une commande Tcl à appeler chaque fois que le menu est détaché. La commande réelle consistera en la valeur de cette option, suivie d'un espace, suivie du nom de la fenêtre du menu, suivie d'un espace, suivie du nom de la fenêtre du menu détaché. Par exemple, si la valeur de l'option est “a b” et que le menu .x.y est détaché pour créer un nouveau menu .x.tearoff1, alors la commande “a b .x.y .x.tearoff1” sera appelée. Cette option est ignorée sous Aqua/macOS, où les menus ne peuvent pas être détachés.
Nom de ligne de commande :	-title
Nom de base de données :	title
Classe de base de données :	Title
La chaîne sera utilisée pour titrer la fenêtre créée lorsque ce menu est détaché. Si le titre est NUL, alors la fenêtre aura le titre du bouton de menu ou le texte de l'élément de cascade à partir duquel ce menu a été appelé.
Nom de ligne de commande :	-type
Nom de base de données :	type
Classe de base de données :	Type
Cette option peut être menubar, tearoff ou normal, et est définie lors de la création du menu. Bien que la chaîne renvoyée par la base de données de configuration change si cette option est modifiée, cela n'affecte pas le comportement du widget menu. Ceci est utilisé par le mécanisme de clonage et n'est normalement pas défini en dehors de la bibliothèque Tk.

INTRODUCTION

La commande menu crée une nouvelle fenêtre de niveau supérieur (donnée par l'argument cheminNom) et en fait un widget de menu. Ce widget de menu peut soit être utilisé comme une fenêtre contextuelle, soit être appliqué à un toplevel (avec son option -menu) pour en faire la barre de menu de ce toplevel. Des options supplémentaires, décrites ci-dessus, peuvent être spécifiées sur la ligne de commande ou dans la base de données d'options pour configurer des aspects du menu tels que ses couleurs et sa police. La commande menu renvoie son argument cheminNom. Au moment où cette commande est appelée, il ne doit pas exister de fenêtre nommée cheminNom, mais le parent de cheminNom doit exister.

Un menu est un widget qui affiche une collection d'éléments sur une seule ligne, disposés en une ou plusieurs colonnes. Il existe plusieurs types d'éléments, chacun ayant des propriétés différentes. Des éléments de types différents peuvent être combinés dans un seul menu. Les éléments de menu ne sont pas les mêmes que les widgets d'entrée. En fait, les éléments de menu ne sont même pas des widgets distincts ; le menu entier est un seul widget.

Les éléments de menu sont affichés avec jusqu'à trois champs distincts. Le champ principal est une étiquette sous forme de chaîne de texte, d'icône bitmap ou d'image, contrôlée par les options -label, -bitmap et -image pour l'élément. Si l'option -accelerator est spécifiée pour un élément, un second champ textuel est affiché à droite de l'étiquette. L'accélérateur décrit typiquement une séquence de touches qui peut être utilisée dans l'application pour obtenir le même résultat que l'appel de l'élément de menu. Ceci est une option d'affichage, elle ne définit pas réellement la liaison correspondante (ce qui peut être réalisé en utilisant la commande bind). Le troisième champ est un *indicateur*. L'indicateur est présent uniquement pour les éléments de type case à cocher ou bouton radio. Il indique si l'élément est sélectionné ou non, et est affiché à gauche de la chaîne de l'élément.

En utilisation normale, un élément devient actif (s'affiche différemment) dès que le pointeur de la souris se trouve sur l'élément. Si un bouton de la souris est relâché sur l'élément, celui-ci est *appelé*. L'effet de l'appel est différent pour chaque type d'élément ; ces effets sont décrits ci-dessous dans les sections sur les éléments individuels.

Les éléments peuvent être *désactivés*, ce qui fait que leurs étiquettes et accélérateurs sont affichés avec des couleurs plus ternes. Les liaisons de menu par défaut ne permettront pas à un élément désactivé d'être activé ou appelé. Les éléments désactivés peuvent être réactivés, auquel cas il redevient possible de les activer et de les appeler.

Chaque fois que l'élément actif d'un menu est modifié, un événement virtuel <<MenuSelect>> est envoyé au menu. L'élément actif peut alors être interrogé à partir du menu, et une action peut être effectuée, telle que la définition d'un texte d'aide contextuel pour l'élément.

TYPES D'ÉLÉMENTS

ÉLÉMENTS DE COMMANDE

Le type d'élément de menu le plus courant est un élément de commande, qui se comporte de manière similaire à un widget bouton. Lorsque un élément de commande est appelé, une commande Tcl est exécutée. La commande Tcl est spécifiée avec l'option -command.

ÉLÉMENTS SÉPARATEURS

Un séparateur est un élément qui s'affiche comme une ligne horizontale de séparation. Un séparateur ne peut être activé ou appelé, et n'a aucun comportement autre que son apparence.

ÉLÉMENTS BOUTONS COCHE

Un élément de menu de type case à cocher se comporte de manière similaire à un widget case à cocher. Lorsqu'il est appelé, il bascule entre l'état sélectionné et non sélectionné. Lorsque l'élément est sélectionné, une valeur particulière est stockée dans une variable globale particulière (telle que déterminée par les options -onvalue et -variable de l'élément) ; lorsque l'élément est non sélectionné, une autre valeur (déterminée par l'option -offvalue) est stockée dans la variable globale. Une boîte indicateur est affichée à gauche de l'étiquette dans un élément de case à cocher. Si l'élément est sélectionné, le centre de l'indicateur est affiché dans la couleur donnée par l'option -selectcolor de l'élément ; sinon, le centre de l'indicateur est affiché dans la couleur de fond du menu. Si une option -command est spécifiée pour un élément de case à cocher, sa valeur est évaluée comme une commande Tcl chaque fois que l'élément est appelé ; cela se produit après le basculement de l'état sélectionné de l'élément.

TYPES OF ENTRIES

The following types of entries may be added to a menu. Each type is described below, along with its options. The options are specified in the form -name value. Options not specified are given default values.

COMMAND ENTRIES

A command entry is the simplest type of menu entry. Its purpose is to execute a Tcl command when invoked. If a -command option is specified for a command entry, then its value is evaluated as a Tcl command each time the entry is invoked.

CHECKBUTTON ENTRIES

A checkbutton entry is used to display an indicator that can be turned on or off. The indicator is typically a small square. The state of the checkbutton is controlled by a variable specified by the -variable option. If this variable is non-empty and not equal to 0, the checkbutton is considered selected (on), otherwise it is considered unselected (off). When the checkbutton is selected, its indicator is displayed in the color given by the -selectcolor option for the entry; otherwise, the indicator is displayed in the background color for the menu. The variable is updated automatically whenever the checkbutton's state changes. If a -command option is specified for a checkbutton entry, then its value is evaluated as a Tcl command each time the entry is invoked; this happens after changing the checkbutton's variable.

RADIOBUTTON ENTRIES

A radiobutton entry is similar to a checkbutton, but it belongs to a group of related entries. Only one radiobutton entry in a group may be selected at any given time. When a radiobutton entry is selected, its associated variable is set to the value specified by the -value option for the entry. This action causes any previously-selected entry in the same group to deselect itself. Once an entry has become selected, any change to the entry's associated variable will cause the entry to deselect itself. Grouping of radiobutton entries is determined by their associated variables: if two entries have the same associated variable then they are in the same group. An indicator diamond is displayed to the left of the label in each radiobutton entry. If the entry is selected then the indicator's center is displayed in the color given by the -selectcolor option for the entry; otherwise the indicator's center is displayed in the background color for the menu. If a -command option is specified for a radiobutton entry, then its value is evaluated as a Tcl command each time the entry is invoked; this happens after selecting the entry.

CASCADE ENTRIES

A cascade entry is one with an associated menu (determined by the -menu option). Cascade entries allow the construction of cascading menus. The postcascade widget command can be used to post and unpost the associated menu just next to of the cascade entry. The associated menu must be a child of the menu containing the cascade entry (this is needed in order for menu traversal to work correctly).

A cascade entry posts its associated menu by invoking a Tcl command of the form

menu post x y
where menu is the path name of the associated menu, and x and y are the root-window coordinates of the upper-right corner of the cascade entry. On Unix, the lower-level menu is unposted by executing a Tcl command with the form 
menu unpost
where menu is the name of the associated menu. On other platforms, the platform's native code takes care of unposting the menu.

If a -command option is specified for a cascade entry then it is evaluated as a Tcl command whenever the entry is invoked. This is not supported on Windows.

TEAR-OFF ENTRIES

A tear-off entry appears at the top of the menu if enabled with the -tearoff option. It is not like other menu entries in that it cannot be created with the add widget command and cannot be deleted with the delete widget command. When a tear-off entry is created it appears as a dashed line at the top of the menu. Under the default bindings, invoking the tear-off entry causes a torn-off copy to be made of the menu and all of its submenus.

MENUBARS

Any menu can be set as a menubar for a toplevel window (see toplevel command for syntax). On the Macintosh, whenever the toplevel is in front, this menu's cascade items will appear in the menubar across the top of the main monitor. On Windows and Unix, this menu's items will be displayed in a menubar across the top of the window. These menus will behave according to the interface guidelines of their platforms. For every menu set as a menubar, a clone menu is made. See the CLONES section for more information.

As noted, menubars may behave differently on different platforms. One example of this concerns the handling of checkbuttons and radiobuttons within the menu. While it is permitted to put these menu elements on menubars, they may not be drawn with indicators on some platforms, due to system restrictions.

SPECIAL MENUS IN MENUBARS

Certain menus in a menubar will be treated specially. On the Macintosh, access to the special Application, Window and Help menus is provided. On Windows, access to the Windows System menu in each window is provided. On X Windows, a special right-justified help menu may be provided if Motif menu compatibility is enabled. In all cases, these menus must be created with the command name of the menubar menu concatenated with the special name. So for a menubar named .menubar, on the Macintosh, the special menus would be .menubar.apple, .menubar.window and .menubar.help; on Windows, the special menu would be .menubar.system; on X Windows, the help menu would be .menubar.help.

When Tk sees a .menubar.apple menu as the first menu in a menubar on the Macintosh, that menu's contents make up the first items of the Application menu whenever the window containing the menubar is in front. After all of the Tk-defined items, the menu will have a separator, followed by all standard Application menu items. Such a .apple menu must be present in a menu when that menu is first configured as a toplevel's menubar, otherwise a default application menu (hidden from Tk) will be inserted into the menubar at that time and subsequent addition of a .apple menu will no longer result in it becoming the Application menu.

When Tk sees a .menubar.window menu on the Macintosh, the menu's contents are inserted into the standard Window menu of the user's menubar whenever the window's menubar is in front. The first items in the menu are provided by macOS, and the names of the current toplevels are automatically appended after all the Tk-defined items and a separator. The Window menu on the Mac also allows toggling the window into a fullscreen state, and managing a tabbed window interface (multiple windows grouped into a single window) if supported by that version of the operating system.

When Tk sees a .menubar.help menu on the Macintosh, the menu's contents are appended to the standard Help menu of the user's menubar whenever the window's menubar is in front. The first items in the menu are provided by macOS.

When Tk sees a System menu on Windows, its items are appended to the system menu that the menubar is attached to. This menu is tied to the application icon and can be invoked with the mouse or by typing Alt+Spacebar. Due to limitations in the Windows API, any font changes, colors, images, bitmaps, or tearoff images will not appear in the system menu.

When Tk sees a Help menu on X Windows and Motif menu compatibility is enabled the menu is moved to be last in the menubar and is right justified. Motif menu compatibility is enabled by setting the Tk option *Menu.useMotifHelp to true or by calling tk::classic::restore menu.

CLONES

When a menu is set as a menubar for a toplevel window, or when a menu is torn off, a clone of the menu is made. This clone is a menu widget in its own right, but it is a child of the original. Changes in the configuration of the original are reflected in the clone. Additionally, any cascades that are pointed to are also cloned so that menu traversal will work right. Clones are destroyed when either the tearoff or menubar goes away, or when the original menu is destroyed.

WIDGET COMMAND

The menu command creates a new Tcl command whose name is pathName. This command may be used to invoke various operations on the widget. It has the following general form:

pathName option ?arg arg ...?
Option and the args determine the exact behavior of the command.

Many of the widget commands for a menu take as one argument an indicator of which entry of the menu to operate on. These indicators are called indexes and may be specified in any of the following forms:

active
Indicates the entry that is currently active. If no entry is active then this form is equivalent to none. This form may not be abbreviated.
end
Indicates the bottommost entry in the menu. If there are no entries in the menu then this form is equivalent to none. This form may not be abbreviated.
last
Same as end.
none
Indicates “no entry at all”; this is used most commonly with the activate option to deactivate all the entries in the menu. In most cases the specification of none causes nothing to happen in the widget command. This form may not be abbreviated.
@x,y
Indicates the entry that covers the point in the menu's window specified by x and y (in pixel coordinates). If no entry covers that point, then this form is equivalent to none. If only a single number is specified, it is treated as the y-coordinate.
number
Specifies the entry numerically, where 0 corresponds to the top-most entry of the menu, 1 to the entry below it, and so on.
pattern
If the index does not satisfy one of the above forms then this form is used. Pattern is pattern-matched against the label of each entry in the menu, in order from the top down, until a matching entry is found. The rules of string match are used.

If the index could match more than one of the above forms, then the form earlier in the above list takes precedence.

The following widget commands are possible for menu widgets:

pathName activate index
Change the state of the entry indicated by index to active and redisplay it using its active colors. Any previously-active entry is deactivated. If index is specified as none, or if the specified entry is disabled, then the menu ends up with no active entry. Returns an empty string.
pathName add type ?option value option value ...?
Add a new entry to the bottom of the menu. The new entry's type is given by type and must be one of cascade, checkbutton, command, radiobutton, or separator, or a unique abbreviation of one of the above. If additional arguments are present, they specify the options listed in the MENU ENTRY OPTIONS section below. The add widget command returns an empty string.
pathName cget option
Returns the current value of the configuration option given by option. Option may have any of the values acce
pté par la commande menu.
nomChemin clone nouveauNomChemin ?typeClone?
Crée un clone du menu actuel nommé nouveauNomChemin. Ce clone est un menu à part entière, mais toute modification apportée au clone est propagée au menu d'origine et vice versa. typeClone peut être normal, menubar ou tearoff. Ne devrait normalement pas être appelé en dehors de la bibliothèque Tk. Voir la section CLONES pour plus d'informations.
nomChemin configure ?option? ?valeur option valeur ...?
Interroge ou modifie les options de configuration du widget. Si aucune option n'est spécifiée, renvoie une liste décrivant toutes les options disponibles pour nomChemin (voir Tk_ConfigureInfo pour des informations sur le format de cette liste). Si option est spécifiée sans valeur, la commande renvoie une liste décrivant l'option nommée (cette liste sera identique à la sous-liste correspondante de la valeur renvoyée si aucune option n'est spécifiée). Si une ou plusieurs paires option-valeur sont spécifiées, la commande modifie les options du widget données pour qu'elles aient les valeurs données ; dans ce cas, la commande renvoie une chaîne vide. Option peut avoir n'importe laquelle des valeurs acceptées par la commande menu.
nomChemin delete index1 ?index2?
Supprime toutes les entrées de menu entre index1 et index2 inclus. Si index2 est omis, il prend par défaut la valeur de index1. Les tentatives de suppression d'une entrée de menu détachable (tear-off) sont ignorées (il faut plutôt changer l'option -tearoff pour supprimer l'entrée détachable).
nomChemin entrycget index option
Renvoie la valeur actuelle d'une option de configuration pour l'entrée donnée par index. Option peut avoir n'importe lequel des noms décrits dans la section OPTIONS DES ENTRÉES DE MENU ci-dessous.
nomChemin entryconfigure index ?options...?
Cette commande est similaire à la commande configure, sauf qu'elle s'applique aux options d'une entrée individuelle, tandis que configure s'applique aux options du menu dans son ensemble. Options peut avoir n'importe laquelle des valeurs décrites dans la section OPTIONS DES ENTRÉES DE MENU ci-dessous. Si des options sont spécifiées, les options sont modifiées comme indiqué dans la commande et la commande renvoie une chaîne vide. Si aucune option n'est spécifiée, renvoie une liste décrivant les options actuelles pour l'entrée index (voir Tk_ConfigureInfo pour des informations sur le format de cette liste).
nomChemin index index
Renvoie l'index numérique correspondant à index, ou none si index a été spécifié comme none.
nomChemin insert index type ?option valeur option valeur ...?
Identique à la commande de widget add, sauf qu'elle insère la nouvelle entrée juste avant l'entrée donnée par index, au lieu de l'ajouter à la fin du menu. Le type, les arguments option et valeur ont la même interprétation que pour la commande de widget add. Il n'est pas possible d'insérer de nouvelles entrées de menu avant l'entrée détachable, si le menu en a une.
nomChemin invoke index
Déclenche l'action de l'entrée de menu. Voir les sections sur les entrées individuelles ci-dessus pour les détails de ce qui se passe. Si l'entrée de menu est désactivée, rien ne se passe. Si l'entrée a une commande associée, le résultat de cette commande est renvoyé comme résultat de la commande de widget invoke. Sinon, le résultat est une chaîne vide. Note : invoquer une entrée de menu ne déroule pas automatiquement le menu ; les liaisons par défaut s'en chargent normalement avant d'invoquer la commande de widget invoke.
nomChemin post x y ?index?
Organise l'affichage du menu à l'écran aux coordonnées de la fenêtre racine données par x et y. Si un index est spécifié, le menu sera placé de sorte que l'entrée avec cet index soit affichée au point donné. Ces coordonnées sont ajustées si nécessaire pour garantir que l'intégralité du menu soit visible à l'écran. Cette commande renvoie normalement une chaîne vide. Si l'option -postcommand a été spécifiée, alors sa valeur est exécutée comme un script Tcl avant de publier le menu et le résultat de ce script est renvoyé comme résultat de la commande de widget post. Si une erreur survient lors de l'exécution de la commande, l'erreur est renvoyée sans publier le menu.
nomChemin postcascade index
Publie le sous-menu associé à l'entrée cascade donnée par index, et dépublie tout sous-menu précédemment publié. Si index ne correspond pas à une entrée cascade, ou si nomChemin n'est pas publié, la commande n'a aucun effet, sauf celui de dépublier tout sous-menu actuellement publié.
nomChemin type index
Renvoie le type de l'entrée de menu donnée par index. Il s'agit de l'argument type passé à la commande de widget add ou insert lors de la création de l'entrée, tel que command ou separator, ou tearoff pour une entrée détachable.
nomChemin unpost
Désactive la fenêtre afin qu'elle ne soit plus affichée. Si un menu en cascade de niveau inférieur est publié, dépublie ce menu. Renvoie une chaîne vide. Cette sous-commande ne fonctionne pas sous Windows et Macintosh, car ces plateformes ont leur propre manière de dépublier les menus.
nomChemin xposition index
Renvoie une chaîne décimale indiquant la coordonnée x dans la fenêtre du menu du pixel le plus à gauche de l'entrée spécifiée par index.
nomChemin yposition index
Renvoie une chaîne décimale indiquant la coordonnée y dans la fenêtre du menu du pixel le plus haut de l'entrée spécifiée par index.

OPTIONS DES ENTRÉES DE MENU

Les options suivantes sont autorisées sur les entrées de menu. La plupart des options ne sont pas supportées par tous les types d'entrée.

-activebackground valeur
Spécifie une couleur d'arrière-plan à utiliser pour afficher cette entrée lorsqu'elle est active. Cette option est ignorée sur Aqua/macOS. Si elle est spécifiée comme une chaîne vide (par défaut), alors l'option -activebackground du menu global est utilisée. Si la variable tk_strictMotif a été définie pour demander une conformité stricte avec Motif, alors cette option est ignorée et l'option -background est utilisée à la place. Cette option n'est pas disponible pour les entrées de type séparateur ou détachable.
-activeforeground valeur
Spécifie une couleur de premier plan à utiliser pour afficher cette entrée lorsqu'elle est active. Cette option est ignorée sur Aqua/macOS. Si cette option est spécifiée comme une chaîne vide (par défaut), alors l'option -activeforeground du menu global est utilisée. Cette option n'est pas disponible pour les entrées de type séparateur ou détachable.
-accelerator valeur
Spécifie une chaîne à afficher sur le côté droit de l'entrée de menu. Décrit normalement une séquence de touches d'accélérateur qui peut être utilisée pour déclencher la même fonction que l'entrée de menu. Il s'agit d'une option d'affichage, elle ne définit pas réellement la liaison correspondante (ce qui peut être réalisé en utilisant la commande bind). Cette option n'est pas disponible pour les entrées de type séparateur ou détachable.
-background valeur
Spécifie une couleur d'arrière-plan à utiliser pour afficher cette entrée lorsqu'elle est dans l'état normal (ni active ni désactivée). Cette option est ignorée sur Aqua/macOS. Si elle est spécifiée comme une chaîne vide (par défaut), alors l'option -background du menu global est utilisée. Cette option n'est pas disponible pour les entrées de type séparateur ou détachable.
-bitmap valeur
Spécifie un bitmap à afficher dans le menu au lieu d'une étiquette textuelle, sous l'une des formes acceptées par Tk_GetBitmap. Cette option annule l'option -label (contrôlée par l'option -compound) mais peut être réinitialisée à une chaîne vide pour permettre l'affichage d'une étiquette textuelle. Si une option -image a été spécifiée, elle annule -bitmap. Cette option n'est pas disponible pour les entrées de type séparateur ou détachable.
-columnbreak valeur
Lorsque cette option est à zéro, l'entrée apparaît en dessous de l'entrée précédente. Lorsque cette option est à un, l'entrée apparaît en haut d'une nouvelle colonne dans le menu. Cette option est ignorée sur Aqua/macOS, où les menus sont toujours en une seule colonne.
-command valeur
Spécifie une commande Tcl à exécuter lorsque l'entrée de menu est invoquée. Non disponible pour les entrées de type séparateur ou détachable.
-compound valeur
Spécifie si l'entrée de menu doit afficher à la fois une image et du texte, et si oui, où l'image doit être placée par rapport au texte. Les valeurs valides pour cette option sont bottom, center, left, none, right et top. La valeur par défaut est none, ce qui signifie que le bouton affichera soit une image, soit du texte, en fonction des valeurs des options -image et -bitmap.
-font valeur
Spécifie la police à utiliser lors du dessin de l'étiquette ou de la chaîne d'accélérateur dans cette entrée. Si cette option est spécifiée comme une chaîne vide (par défaut), alors l'option -font du menu global est utilisée.
