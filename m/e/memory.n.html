memory(n) Commandes intégrées Tcl memory(n)

NOM

memory - Contrôler les capacités de débogage mémoire de Tcl

SYNTAXE

memory option ?arg arg ...?

DESCRIPTION

La commande memory donne au développeur Tcl le contrôle des capacités de débogage mémoire de Tcl. La commande memory possède plusieurs sous-options, décrites ci-dessous. Elle n'est disponible que lorsque Tcl a été compilé avec le débogage mémoire activé (lorsque TCL_MEM_DEBUG est défini au moment de la compilation), et après que Tcl_InitMemory ait été appelée.

memory active fichier
Écrit une liste de toute la mémoire actuellement allouée dans le fichier spécifié.
memory break_on_malloc compteur
Après que compteur allocations aient été effectuées, ckalloc affiche un message à cet effet et indique qu'il tente maintenant d'entrer dans le débogueur C. Tcl émettra alors un signal SIGINT contre lui-même. Si vous exécutez Tcl sous un débogueur C, il devrait alors entrer en mode commande du débogueur.
memory info
Retourne un rapport contenant le total des allocations et libérations depuis le début de Tcl, les paquets actuellement alloués (le nombre actuel d'appels à ckalloc non satisfaits par un appel correspondant à ckfree), les octets actuellement alloués, et le nombre maximum de paquets et d'octets alloués.
memory init [on|off]
Active ou désactive la pré-initialisation de toute la mémoire allouée avec des octets bidons. Utile pour détecter l'utilisation de valeurs non initialisées.
memory objs fichier
Force l'écriture immédiate d'une liste de toutes les valeurs Tcl_Obj allouées dans le fichier spécifié, ainsi que l'endroit où elles ont été allouées. Utile pour vérifier les fuites de valeurs.
memory onexit fichier
Force l'écriture d'une liste de toute la mémoire allouée dans le fichier spécifié lors de la finalisation du sous-système mémoire de Tcl. Utile pour vérifier que la mémoire est correctement nettoyée lors de la sortie du processus.
memory tag chaîne
Chaque paquet de mémoire alloué par ckalloc peut avoir une étiquette associée, de type chaîne. Dans les listes de mémoire allouée générées par memory active et memory onexit, l'étiquette de chaque paquet est imprimée avec d'autres informations sur le paquet. La commande memory tag définit la valeur de l'étiquette pour les appels ultérieurs à ckalloc à être chaîne.
memory trace [on|off]
Active ou désactive le traçage mémoire. Lorsque le traçage mémoire est activé, chaque appel à ckalloc provoque l'écriture d'une ligne d'informations de trace sur stderr, composée du mot ckalloc, suivi de l'adresse retournée, de la quantité de mémoire allouée, et du nom du fichier C et du numéro de ligne du code effectuant l'allocation. Par exemple :
ckalloc 40e478 98 tclProc.c 1406

Les appels à ckfree sont tracés de la même manière.

memory trace_on_at_malloc compteur
Active le traçage mémoire après que compteur appels à ckalloc aient été effectués. Par exemple, si vous entrez memory trace_on_at_malloc 100, après le 100ème appel à ckalloc, les informations de trace mémoire commenceront à être affichées pour toutes les allocations et libérations. Comme il peut y avoir beaucoup d'activité mémoire avant qu'un problème ne survienne, une utilisation judicieuse de cette option peut réduire le ralentissement causé par le traçage (et la quantité d'informations de trace produites), si vous pouvez identifier un certain nombre d'allocations qui se produisent avant que le problème ne s'installe. Le nombre actuel d'allocations mémoire qui se sont produites depuis le démarrage de Tcl est imprimé sur une zone de garde en cas d'échec.
memory validate [on|off]
Active ou désactive la validation mémoire. Lorsque la validation mémoire est activée, à chaque appel à ckalloc ou ckfree, les zones de garde sont vérifiées pour chaque bloc mémoire existant actuellement et ayant été alloué par ckalloc. Cela a un impact important sur les performances et ne devrait être utilisé que lorsque des problèmes d'écrasement sont fortement suspectés. L'avantage d'activer la validation mémoire est qu'un écrasement de zone de garde peut être détecté dès le premier appel à ckalloc ou ckfree après que l'écrasement se soit produit, plutôt que lorsque la mémoire spécifique avec la ou les zones de garde écrasées est libérée, ce qui peut se produire longtemps après l'écrasement.

VOIR AUSSI

ckalloc, ckfree, Tcl_ValidateAllMemory, Tcl_DumpActiveMemory, TCL_MEM_DEBUG

MOTS CLÉS
