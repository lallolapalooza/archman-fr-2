NOM

metalog.conf - fichier de configuration pour metalog

SYNTAXE

[valeurs par défaut]
<titre de section :>
<valeurs de section>
<titre de section 2 :>
<valeurs de section 2>
# Les commentaires sont introduits par "#", ce qui est UNIQUEMENT autorisé en début de ligne.
<etc.>

DESCRIPTION

[valeurs par défaut] seront utilisées si vous ne les redéfinissez pas dans une section. Vous pouvez choisir le <titre de section> comme vous le souhaitez. Il ne signifie rien, il permet juste de conserver un fichier de configuration facile à lire.

Les noms de valeurs peuvent être l'un des suivants :

maxsize = <nombre (octets)>
Une fois qu'un fichier journal a dépassé la valeur définie (en octets), il sera archivé. Si maxfile est égal à zéro, l'archivage des journaux est désactivé. Définir une valeur par défaut est une bonne idée.
maxtime = <nombre (secondes)>
Une fois qu'un fichier journal est plus ancien que la valeur définie (en secondes), il sera archivé. Définir une valeur par défaut est une bonne idée.

NB : Un fichier journal est archivé lorsque la limite maxsize ou maxtime est atteinte. Si l'une ou les deux sont égales à 0, alors l'archivage des journaux est désactivé.

maxfiles = <nombre>
Cette valeur indique le nombre maximum de fichiers archivés conservés. Vous aurez donc x fichiers archivés (journal-date-chaîne nom de fichier type), plus le fichier nommé "current".
facility = "<facility>"
Enregistre un message uniquement si l'application qui l'a émis utilise la facilité syslog <facility>. Les noms de facilitées sont : "auth", "authpriv", "cron", "daemon", "ftp", "kern", "lpr", "mail", "news", "security", "syslog", "user", "uucp", "local0", "local1" ... "local7". Tous les messages du noyau sont journalisés avec la facilité "kern". Une section peut avoir plusieurs lignes "facility = ..." pour correspondre à plusieurs facilités. Si <facility> est "*", il correspondra à toutes les facilités.
remote_host = "<adresse IP ou nom de domaine>"
Les entrées du journal sont envoyées au serveur de journalisation distant défini par cette adresse IP ou ce nom de domaine. Un seul serveur de journalisation distant peut être défini. Ceci ne peut être défini que dans la section des valeurs par défaut. Tous les messages de journal sont envoyés là-bas, les limitations via "ratelimit", "ratelimit_burst" ou "showrepeats" sont ignorées pour les messages de journal envoyés au serveur de journalisation distant. Dans le cas où un nom de domaine ou d'hôte est configuré, la requête DNS nécessaire sera répétée après chaque tentative échouée ou après 120 secondes lorsque le nom a été résolu avec succès.
remote_port = "<valeur>"
Le port UDP du serveur de journalisation distant. La valeur par défaut est "514". Ceci ne peut être défini que dans la section des valeurs par défaut.
remote_log = "<nombre>"
Par défaut 0. Les messages de journal sont envoyés au serveur de journalisation distant lorsque défini sur 1. Peut être défini pour les valeurs par défaut ou dans les sections.
break = <nombre>
Par défaut 0. Si défini sur 1 et qu'une section correspond, effectuez l'action, mais ne considérez plus aucune correspondance de section ultérieure dans ce fichier de configuration. Ceci est utile pour créer une configuration où des types spécifiques de messages de journal sont mis en correspondance et distribués, tandis qu'une section "capture tout" au bas du fichier de configuration gère le cas par défaut.

Utiliser 0 entraînerait potentiellement le traitement des messages par plusieurs sections, causant la duplication des messages, tandis que l'utilisation de 1 sur les sections précédant une section finale "capture tout" éviterait la duplication.

minimum = <niveau>
Enregistre un message uniquement si son urgence est inférieure ou égale à <niveau>. Le niveau '0' est le plus critique, tandis que le niveau '7' est pour les messages de débogage. 5 supprimera tous les messages non importants. Le niveau minimum par défaut est 7 (c'est-à-dire conserver tous les messages).
maximum = <niveau>
Ne journalise pas si le niveau du message dépasse cette valeur. Par défaut, maximum est le niveau le plus élevé possible.
logdir = "/dir/où/les/journaux/seront/écrits/"
Les fichiers seront écrits dans le répertoire spécifié. La valeur spéciale "NONE" ignorera le message de journalisation.
perms = <mode>
Permissions pour le répertoire de journaux. Par défaut 0700
program = "nom"
Peut être utilisé pour le filtrage au lieu de facility. N'oubliez pas d'utiliser le nom de l'exécutable.
regex = "expression régulière compatible perl"
Peut être utilisé lorsque vous souhaitez uniquement enregistrer les messages qui correspondent au modèle (comme "invalide", "échec", etc...) pour les envoyer dans un répertoire unique.

Plusieurs regex peuvent être définies dans une seule section, une seule doit correspondre.

neg_regex = "expression régulière compatible perl"
Peut être utilisé lorsque vous souhaitez uniquement enregistrer les messages qui ne correspondent pas au modèle.

Une correspondance neg_regex annulera toute correspondance regex et n'enregistrera pas le message.

Lorsque une ou plusieurs regex sont fournies, au moins une d'entre elles doit correspondre pour enregistrer le message. L'absence de toute regex entraînera l'enregistrement du message lorsqu'aucune neg_regex ne correspond.

Plusieurs neg_regex peuvent être définies dans une section, une seule doit correspondre.

postrotate_cmd = "/chemin/vers/un/programme"
Exécute le programme spécifié après qu'un fichier journal a été archivé.

Le programme reçoit la date, le nom du programme ("metalog"), et le nom du nouveau fichier journal.

program_regex = "expression régulière compatible perl"
Similaire à program, ceci est une expression régulière qui correspond au nom du programme pour envoyer tous les messages des programmes associés au même fichier journal.

Plusieurs program_regex peuvent être définies dans une section, une seule doit correspondre.

program_neg_regex = "expression régulière compatible perl"
L'inverse de program_regex pour filtrer les journaux des programmes qui correspondent.

Une correspondance program_neg_regex annulera toute correspondance program_regex et n'enregistrera pas le message.

Lorsque une ou plusieurs program_regex sont fournies, au moins une d'entre elles doit correspondre pour enregistrer le message. L'absence de toute program_regex entraînera l'enregistrement du message lorsqu'aucune program_neg_regex ne correspond.

Plusieurs program_neg_regex peuvent être définies dans une section, une seule doit correspondre.

showrepeats = <nombre>
Défini à 0 pour filtrer les messages de journal répétés.
command = "/chemin/vers/programme/à/exécuter"
Exécute le programme spécifié dès que quelque chose est enregistré dans une section donnée.

Le programme reçoit la date, le nom du programme correspondant, et le message de journal.

Si le programme n'existe pas au démarrage de metalog, metalog ne s'arrêtera pas et ignorera simplement cette ligne de configuration.

Format de l'horodatage lisible par l'homme préfixant tous les messages de journal. La chaîne de format prend en charge toutes les spécifications de conversion de strftime plus

NAME

metalog.conf - configuration file for metalog

SYNTAX

timestamp_format = "%[nnn]N"
flush = <number>
ratelimit = "5/m"
ratelimit_burst = <number>
configdir = "/path/to/directory/with/more/config/files"

DESCRIPTION

timestamp_format = "%[nnn]N"
Le format de date/heure est passé à la fonction strftime(3). Les spécificateurs de format sont les mêmes que ceux de strftime(3). Le spécificateur de format %[nnn]N est utilisé pour la nanoseconde. Les nnn sont au nombre de neuf chiffres par défaut, mais peuvent être raccourcis si nnn < 9. Une chaîne vide désactive les timestamps.
flush = <nombre>
Si défini sur 0, les messages de log correspondants seront toujours mis en mémoire tampon. Si défini sur 1, ils seront toujours écrits immédiatement dans le système de fichiers.

Ces deux paramètres remplacent la valeur par défaut globale donnée par les paramètres de ligne de commande (-a/-s) ou les signaux.

ratelimit = "5/m"
Limite le débit des messages de log au nombre spécifié de messages par unité de temps. Les unités de temps valides sont seconde, minute, heure et day, chacune identifiée par sa première lettre. Les valeurs fractionnaires sont autorisées, comme "0.5/m" pour faciliter l'analyse humaine.

Une limite de 0 (par défaut) peut être utilisée pour désactiver toute gestion de limite de débit. Dans ce cas, l'unité de temps peut être omise.

ratelimit_burst = <nombre>
Jusqu'à ce nombre de lignes seront imprimées au début d'une rafale de messages, si le débit des messages a été bien inférieur à la limite auparavant. Le débit de messages spécifié ne sera pas dépassé. La valeur par défaut de 1 désactive le traitement spécial des rafales. Les valeurs inférieures à 1 sont invalides et seront rejetées.
configdir = "/chemin/vers/un/repertoire/avec/plus/de/fichiers/config"
Ce répertoire optionnel peut contenir d'autres fichiers de configuration qui seront interprétés au démarrage de metalog. Seuls les noms de fichiers se terminant par ".conf" sont interprétés. Cette option n'est autorisée qu'une seule fois, toutes les répétitions seront ignorées.
