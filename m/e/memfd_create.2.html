memfd_create(2) Manuel des appels système memfd_create(2)

NOM

memfd_create - créer un fichier anonyme

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#define _GNU_SOURCE         /* Voir feature_test_macros(7) */
#include <sys/mman.h>
int memfd_create(const char *name, unsigned int flags);

DESCRIPTION

memfd_create() crée un fichier anonyme et renvoie un descripteur de fichier qui y fait référence. Le fichier se comporte comme un fichier ordinaire, et peut donc être modifié, tronqué, mappé en mémoire, etc. Cependant, contrairement à un fichier ordinaire, il réside en RAM et dispose d'un stockage de sauvegarde volatil. Une fois que toutes les références au fichier sont supprimées, il est automatiquement libéré. La mémoire anonyme est utilisée pour toutes les pages de sauvegarde du fichier. Par conséquent, les fichiers créés par memfd_create() ont les mêmes sémantiques que les autres allocations de mémoire anonyme, telles que celles allouées à l'aide de mmap(2) avec le drapeau MAP_ANONYMOUS.

La taille initiale du fichier est définie à 0. Après l'appel, la taille du fichier doit être définie à l'aide de ftruncate(2). (Alternativement, le fichier peut être rempli par des appels à write(2) ou similaire.)

Le nom fourni dans name est utilisé comme nom de fichier et sera affiché comme cible du lien symbolique correspondant dans le répertoire /proc/self/fd/. Le nom affiché est toujours préfixé par memfd: et ne sert qu'à des fins de débogage. Les noms n'affectent pas le comportement du descripteur de fichier, et par conséquent, plusieurs fichiers peuvent avoir le même nom sans aucun effet secondaire.

Les valeurs suivantes peuvent être combinées par un OU bit à bit dans flags pour modifier le comportement de memfd_create():

MFD_CLOEXEC
Définit le drapeau close-on-exec (FD_CLOEXEC) sur le nouveau descripteur de fichier. Voir la description du drapeau O_CLOEXEC dans open(2) pour les raisons pour lesquelles cela peut être utile.
MFD_ALLOW_SEALING
Autorise les opérations de scellement sur ce fichier. Voir la discussion des opérations F_ADD_SEALS et F_GET_SEALS dans fcntl(2), et aussi les NOTES, ci-dessous. L'ensemble initial de sceaux est vide. Si ce drapeau n'est pas défini, l'ensemble initial de sceaux sera F_SEAL_SEAL, ce qui signifie qu'aucun autre sceau ne peut être appliqué au fichier.
MFD_HUGETLB (depuis Linux 4.14)
Le fichier anonyme sera créé dans le système de fichiers hugetlbfs en utilisant des pages volumineuses. Voir le fichier source du noyau Linux Documentation/admin-guide/mm/hugetlbpage.rst pour plus d'informations sur hugetlbfs. La spécification simultanée de MFD_HUGETLB et MFD_ALLOW_SEALING dans flags est prise en charge depuis Linux 4.16.
MFD_HUGE_2MB
MFD_HUGE_1GB
...
Utilisé en conjonction avec MFD_HUGETLB pour sélectionner des tailles de pages hugetlb alternatives (respectivement, 2 Mo, 1 Go, ...) sur les systèmes qui prennent en charge plusieurs tailles de pages hugetlb. Les définitions pour les tailles de pages volumineuses connues sont incluses dans le fichier d'en-tête <linux/memfd.h>.
Pour plus de détails sur l'encodage des tailles de pages volumineuses non incluses dans le fichier d'en-tête, voir la discussion des constantes de noms similaires dans mmap(2).

Les bits inutilisés dans flags doivent être à 0.

En tant que valeur de retour, memfd_create() renvoie un nouveau descripteur de fichier qui peut être utilisé pour faire référence au fichier. Ce descripteur de fichier est ouvert en lecture et en écriture (O_RDWR) et O_LARGEFILE est défini pour le descripteur de fichier.

En ce qui concerne fork(2) et execve(2), les sémantiques habituelles s'appliquent au descripteur de fichier créé par memfd_create(). Une copie du descripteur de fichier est héritée par l'enfant produit par fork(2) et fait référence au même fichier. Le descripteur de fichier est préservé lors de execve(2), sauf si le drapeau close-on-exec a été défini.

VALEUR DE RETOUR

En cas de succès, memfd_create() renvoie un nouveau descripteur de fichier. En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

EFAULT
L'adresse dans name pointe vers une mémoire invalide.
EINVAL
flags contenait des bits inconnus.
EINVAL
name était trop long. (La limite est de 249 octets, hors le caractère nul de fin.)
EINVAL
À la fois MFD_HUGETLB et MFD_ALLOW_SEALING ont été spécifiés dans flags.
EMFILE
La limite par processus du nombre de descripteurs de fichiers ouverts a été atteinte.
ENFILE
La limite du système pour le nombre total de fichiers ouverts a été atteinte.
ENOMEM
Il n'y avait pas assez de mémoire pour créer un nouveau fichier anonyme.
EPERM
Le drapeau MFD_HUGETLB a été spécifié, mais l'appelant n'était pas privilégié (n'avait pas la capacité CAP_IPC_LOCK) et n'est pas membre du groupe hugetlb_shm_group; voir la description de /proc/sys/vm/hugetlb_shm_group dans proc_sys_vm(5).

NORMES

Linux.

HISTORIQUE

Linux 3.17, glibc 2.27.

NOTES

L'appel système memfd_create() fournit une alternative simple au montage manuel d'un système de fichiers tmpfs(5) et à la création et ouverture d'un fichier dans ce système de fichiers. Le but principal de memfd_create() est de créer des fichiers et des descripteurs de fichiers associés qui sont utilisés avec les API de scellement de fichiers fournies par fcntl(2).

L'appel système memfd_create() a également des utilisations sans scellement de fichier (c'est pourquoi le scellement de fichier est désactivé, sauf demande explicite avec le drapeau MFD_ALLOW_SEALING). En particulier, il peut être utilisé comme alternative à la création de fichiers dans tmp ou comme alternative à l'utilisation de open(2) O_TMPFILE dans les cas où il n'y a aucune intention de lier réellement le fichier résultant dans le système de fichiers.

Scellement de fichier

En l'absence de scellement de fichier, les processus qui communiquent via la mémoire partagée doivent soit se faire confiance, soit prendre des mesures pour faire face à la possibilité qu'un pair non fiable manipule la région de mémoire partagée de manière problématique. Par exemple, un pair non fiable pourrait modifier le contenu de la mémoire partagée à tout moment, ou réduire la région de mémoire partagée. La première possibilité laisse le processus local vulnérable aux conditions de concurrence de type "time-of-check to time-of-use" (généralement traitées en copiant les données de la région de mémoire partagée avant de les vérifier et de les utiliser). NOM

memfd_create - créer un fichier anonyme dans tmpfs

BIBLIOTHQUE

Bibliothèque C standard (libc, -lc)

SYNOPSIS

#include <sys/memfd.h>

int memfd_create(const char *name, unsigned int flags);

DESCRIPTION

La fonction memfd_create() crée un fichier anonyme dans le système de fichiers en mémoire tmpfs(5). Le nom du fichier spécifié par name est utilisé comme nom du fichier dans le système de fichiers, mais il n'est pas visible dans les systèmes de fichiers normaux et est utilisé uniquement à des fins de débogage et d'identification (par exemple, dans la sortie de proc(5)). Le nom ne doit pas contenir le caractère `/`.

Le descripteur de fichier retourné est ouvert en lecture/écriture.

Le drapeau flags est un masque de bits qui doit contenir soit zéro, soit l'une des valeurs suivantes :

MFD_CLOEXEC
Définir l'indicateur close-on-exec sur le nouveau descripteur de fichier. Voir fcntl(2) pour plus d'informations.
MFD_ALLOW_SEALING
Permettre l'application de sceaux sur le fichier. Voir fcntl(2) pour plus d'informations sur les sceaux de fichiers. Sans ce drapeau, la plupart des opérations de sceaux échoueront avec EINVAL.
MFD_HUGETLB
Le fichier doit être créé sur une énorme page (huge page) hugetlb(7). Cela ne fonctionne que si le processus a les capacités nécessaires et si le noyau est configuré pour prendre en charge les énormes pages. L'espace d'adressage utilisé pour les énormes pages est géré différemment des pages normales, et le comportement exact peut dépendre de la configuration du système.
MFD_NONBLOCK
Définir l'indicateur O_NONBLOCK sur le nouveau descripteur de fichier. Voir open(2) pour plus d'informations.

Les valeurs de flags sont interprétées de manière indépendante, elles peuvent donc être combinées en utilisant un OU au niveau du bit.

Le nom du fichier spécifié par name n'est pas garanti d'être unique. Si vous avez besoin d'un nom unique, vous devriez le générer vous-même.

Les fichiers créés par memfd_create() existent tant qu'un descripteur de fichier y fait référence. Ils ne sont pas associés à un chemin d'accès dans le système de fichiers.

Un fichier créé par memfd_create() peut être manipulé de la même manière qu'un fichier ordinaire, avec quelques exceptions :

  • Il ne peut pas être renommé(e).
  • Il ne peut pas être créé de liens vers lui.
  • Il ne peut pas être supprimé(e) (car il n'a pas de nom dans le système de fichiers).
  • Il ne peut pas être monté(e).
  • Il ne peut pas être tronqué(e) à une taille plus petite que sa taille actuelle, sauf si le sceau F_SEAL_SHRINK est appliqué.

Si le drapeau MFD_ALLOW_SEALING est défini, le fichier peut être protégé contre les modifications ultérieures en appliquant des sceaux à l'aide de l'opération fcntl() F_ADD_SEALS. Les sceaux suivants sont disponibles :

F_SEAL_GROW
Empêche toute augmentation future de la taille du fichier. Si cette opération est appliquée, les opérations ultérieures de ftruncate(2) qui augmentent la taille du fichier échoueront.
F_SEAL_SHRINK
Empêche toute diminution future de la taille du fichier. Si cette opération est appliquée, les opérations ultérieures de ftruncate(2) qui diminuent la taille du fichier échoueront.
F_SEAL_WRITE
Empêche toute opération d'écriture future sur le fichier. Si cette opération est appliquée, les opérations d'écriture ultérieures sur le fichier (y compris via mmap(2) avec PROT_WRITE) échoueront.
F_SEAL_FUTURE_WRITE
Empêche toute opération d'écriture future sur le fichier via mmap(2) ou write(2). Cela n'affecte pas les mappages d'écriture existants.
F_SEAL_SEAL
Empêche l'application de sceaux supplémentaires sur le fichier. Cette opération doit être appliquée en dernier, car elle empêche d'autres opérations de sceaux.

Une fois qu'un sceau est appliqué à un fichier, il ne peut pas être retiré. De plus, certains sceaux ne peuvent pas être appliqués si le fichier est dans un état qui violerait le sceau. Par exemple, F_SEAL_WRITE ne peut pas être appliqué si le fichier est actuellement mappé en mémoire avec des droits d'écriture. Les sceaux peuvent être vérifiés à l'aide de fcntl() avec l'opération F_GET_SEALS.

L'utilisation de memfd_create() permet la création de régions de mémoire partagée sécurisées et sans fichier, qui peuvent être utilisées pour le partage de données entre processus sans les risques associés à l'utilisation de fichiers temporaires ordinaires. Cela peut être particulièrement utile pour des applications sensibles à la sécurité qui nécessitent un partage de mémoire interprocessus sans risque de fuite de données ou de modification non autorisée de la mémoire partagée.

Un exemple d'utilisation du mécanisme de sceaux est le suivant :

(1)
Le premier processus crée un fichier tmpfs(5) en utilisant memfd_create(). L'appel renvoie un descripteur de fichier utilisé dans les étapes suivantes.
(2)
Le premier processus dimensionne le fichier créé à l'étape précédente en utilisant ftruncate(2), le mappe en utilisant mmap(2), et peuple la mémoire partagée avec les données souhaitées.
(3)
Le premier processus utilise l'opération F_ADD_SEALS de fcntl(2) pour placer un ou plusieurs sceaux sur le fichier, afin de restreindre les modifications ultérieures sur le fichier. (Si le sceau F_SEAL_WRITE est placé, il sera nécessaire de d'abord démapper le mappage partagé accessible en écriture créé à l'étape précédente. Sinon, un comportement similaire à F_SEAL_WRITE peut être obtenu en utilisant F_SEAL_FUTURE_WRITE, ce qui empêchera les écritures futures via mmap(2) et write(2) de réussir tout en conservant les mappages partagés accessibles en écriture existants).
(4)
Un second processus obtient un descripteur de fichier pour le fichier tmpfs(5) et le mappe. Parmi les moyens possibles pour que cela se produise, on trouve les suivants :
•
Le processus qui a appelé memfd_create() pourrait transférer le descripteur de fichier résultant au second processus via un socket de domaine UNIX (voir unix(7) et cmsg(3)). Le second processus mappe alors le fichier en utilisant mmap(2).
•
Le second processus est créé via fork(2) et hérite donc automatiquement du descripteur de fichier et du mappage. (Notez que dans ce cas et le suivant, il existe une relation de confiance naturelle entre les deux processus, puisqu'ils s'exécutent sous le même ID utilisateur. Par conséquent, le sceau de fichier ne serait normalement pas nécessaire.)
•
Le second processus ouvre le fichier /proc/pid/fd/fd, où <pid> est le PID du premier processus (celui qui a appelé memfd_create()), et <fd> est le numéro du descripteur de fichier retourné par l'appel à memfd_create() dans ce processus. Le second processus mappe alors le fichier en utilisant mmap(2).
(5)
Le second processus utilise l'opération F_GET_SEALS de fcntl(2) pour récupérer le masque de bits des sceaux qui a été appliqué au fichier. Ce masque de bits peut être inspecté afin de déterminer quels types de restrictions ont été imposés aux modifications du fichier. Si désiré, le second processus peut appliquer d'autres sceaux pour imposer des restrictions supplémentaires (tant que le sceau F_SEAL_SEAL n'a pas encore été appliqué).

VALEUR DE RETOUR

En cas de succès, memfd_create() renvoie le nouveau descripteur de fichier. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

Les erreurs suivantes peuvent être définies pour memfd_create() :

EBADF
Le descripteur de fichier name n'est pas valide.
EINVAL
Le champ name est un pointeur NULL, ou le nom contient le caractère `/`, ou les flags spécifiés ne sont pas valides.
EMFILE
Le processus a atteint la limite de descripteurs de fichiers ouverts.
ENFILE
Le système a atteint la limite globale de descripteurs de fichiers ouverts.
ENOMEM
Pas assez de mémoire pour allouer le fichier.
ENOSPC
Il n'y a pas assez d'espace sur le système de fichiers.

CONFORMIT

La fonction memfd_create() a été introduite dans le noyau Linux 3.17. Elle est disponible dans les versions de la glibc à partir de la 2.14.

HISTORIQUE

La fonction memfd_create() a été introduite dans le noyau Linux 3.17.

NOTES

Les fichiers créés par memfd_create() sont stockés dans le système de fichiers tmpfs(5). Ils ne sont donc pas persistants et sont perdus lorsque le système est redémarré.

Si le drapeau MFD_HUGETLB est utilisé, les énormes pages doivent être disponibles et configurées sur le système. L'utilisation des énormes pages peut avoir des implications sur les performances et la gestion de la mémoire, et doit être utilisée avec précaution.

L'utilisation de MFD_ALLOW_SEALING permet d'améliorer la sécurité en empêchant la modification non désirée du contenu des fichiers en mémoire. C'est particulièrement utile pour le partage de code ou de données sensibles entre processus.

Les opérations de sceaux sur les fichiers créés par memfd_create() peuvent être utilisées pour garantir l'intégrité des données. Par exemple, après avoir chargé un programme ou des données sensibles dans un fichier tmpfs(5), l'application de sceaux peut empêcher que ces données ne soient modifiées par d'autres processus, ou même par le processus créateur lui-même après un certain point.

L'exemple de la section EXAMPLES montre comment créer un fichier en mémoire, y appliquer des sceaux, puis inspecter ces sceaux depuis un autre processus. Cela illustre le potentiel de memfd_create() et des sceaux de fichiers pour la création de mécanismes de partage de mémoire sécurisés et contrôlés.

Une manière courante d'accéder à un fichier créé avec memfd_create() depuis un autre processus (qui ne l'a pas créé directement ou hérité du descripteur) est via le système de fichiers virtuel proc(5). En accédant à /proc/pid/fd/fd, où pid est l'ID du processus créateur et fd est le descripteur de fichier renvoyé par memfd_create(), on peut obtenir un descripteur de fichier vers le même fichier anonyme. Ceci est utile pour la communication interprocessus, où un processus peut créer une région de mémoire partagée et en donner l'accès à d'autres processus.

Il est important de noter que l'utilisation de MFD_HUGETLB peut entraîner une fragmentation de la mémoire et une charge plus élevée sur le gestionnaire de mémoire du système. Son utilisation doit être évaluée soigneusement en fonction des besoins spécifiques de l'application.

La combinaison de memfd_create() avec des mécanismes de partage de mémoire comme les pipes anonymes ou les sockets de domaine UNIX permet des schémas de communication interprocessus complexes et sécurisés.

L'utilisation de MFD_CLOEXEC est une bonne pratique de sécurité pour s'assurer que les descripteurs de fichier ne sont pas accidentellement transmis aux processus enfants lors de l'exécution de nouveaux programmes.

Si vous utilisez MFD_ALLOW_SEALING, assurez-vous de bien comprendre l'ordre et l'implication de l'application des différents sceaux. L'application du sceau F_SEAL_SEAL doit généralement être la dernière étape après toutes les autres opérations de configuration et de sceau.

Il est crucial de gérer correctement les descripteurs de fichiers renvoyés par memfd_create(). Le descripteur de fichier sera automatiquement fermé lorsque le processus se termine, ou lorsqu'il est explicitement fermé avec close(2).

Si le nom fourni à memfd_create() contient des caractères non imprimables ou des séquences d'échappement, cela peut rendre le débogage plus difficile. Il est recommandé d'utiliser des noms simples et descriptifs.

L'utilisation de memfd_create() est particulièrement utile pour les applications qui chargent des binaires ou des bibliothèques dynamiquement, car elle permet de le faire à partir de sources en mémoire sans avoir à écrire sur le système de fichiers, ce qui réduit la surface d'attaque et simplifie la gestion des permissions.

La fonction memfd_create() offre une alternative plus sûre et plus flexible aux méthodes plus anciennes de création de mémoire partagée, comme l'utilisation de shmget(2) ou la création de fichiers temporaires dans des répertoires comme /tmp.

Il est important de noter que même avec les sceaux, si le noyau est compromis ou si des vulnérabilités sont exploitées, la sécurité de la mémoire partagée ne peut pas être absolument garantie.

EXEMPLES

Ci-dessous sont présentés deux programmes exemples qui démontrent l'utilisation de memfd_create() et de l'API des sceaux de fichiers.

Le premier programme, t_memfd_create.c, crée un fichier tmpfs(5) en utilisant memfd_create(), définit une taille pour le fichier, le mappe en mémoire, et place optionnellement quelques sceaux sur le fichier. Le programme accepte jusqu'à trois arguments en ligne de commande, dont les deux premiers sont requis. Le premier argument est le nom à associer au fichier, le second argument est la taille à définir pour le fichier, et le troisième argument optionnel est une chaîne de caractères qui spécifie les sceaux à définir sur le fichier.

Le second programme, t_get_seals.c, peut être utilisé pour ouvrir un fichier existant qui a été créé via memfd_create() et inspecter l'ensemble des sceaux qui ont été appliqués à ce fichier.

La session shell suivante démontre l'utilisation de ces programmes. Nous créons d'abord un fichier tmpfs(5) et définissons quelques sceaux dessus :


$ ./t_memfd_create my_memfd_file 4096 sw &
[1] 11775
PID: 11775; fd: 3; /proc/11775/fd/3

À ce stade, le programme t_memfd_create continue de s'exécuter en arrière-plan. Depuis un autre programme, nous pouvons obtenir un descripteur de fichier pour le fichier créé par memfd_create() en ouvrant le fichier /proc/pid/fd qui correspond au descripteur de fichier ouvert par memfd_create(). En utilisant ce chemin, nous inspectons le contenu du lien symbolique /proc/pid/fd, et utilisons notre programme t_get_seals pour voir les sceaux qui ont été placés sur le fichier :


$ readlink /proc/11775/fd/3;
/memfd:my_memfd_file (deleted)
$ ./t_get_seals /proc/11775/fd/3;
Existing seals: WRITE SHRINK

#include <unistd.h>
int
main(int argc, char *argv[])
{
    int           fd;
    char          *name, *seals_arg;
    ssize_t       size;
    unsigned int  seals;
    if (argc < 3) {
        fprintf(stderr, "%s name size [seals]\n", argv[0]);
        fprintf(stderr, "\t'seals' peut contenir l'un des caractères suivants :\n");
        fprintf(stderr, "\t\tg - F_SEAL_GROW\n");
        fprintf(stderr, "\t\ts - F_SEAL_SHRINK\n");
        fprintf(stderr, "\t\tw - F_SEAL_WRITE\n");
        fprintf(stderr, "\t\tW - F_SEAL_FUTURE_WRITE\n");
        fprintf(stderr, "\t\tS - F_SEAL_SEAL\n");
        exit(EXIT_FAILURE);
    }
    name = argv[1];
    size = atoi(argv[2]);
    seals_arg = argv[3];
    /* Créer un fichier anonyme dans tmpfs ; permettre l'application de sceaux
       sur le fichier.  */
    fd = memfd_create(name, MFD_ALLOW_SEALING);
    if (fd == -1)
        err(EXIT_FAILURE, "memfd_create");
    /* Dimensionner le fichier comme spécifié en ligne de commande.  */
    if (ftruncate(fd, size) == -1)
        err(EXIT_FAILURE, "truncate");
    printf("PID: %jd; fd: %d; /proc/%jd/fd/%d\n",
           (intmax_t) getpid(), fd, (intmax_t) getpid(), fd);
    /* Code pour mapper le fichier et le peupler avec des données
       omis.  */
    /* Si un argument de ligne de commande 'seals' a été fourni, définir quelques
       sceaux sur le fichier.  */
    if (seals_arg != NULL) {
        seals = 0;
        if (strchr(seals_arg, 'g') != NULL)
            seals |= F_SEAL_GROW;
        if (strchr(seals_arg, 's') != NULL)
            seals |= F_SEAL_SHRINK;
        if (strchr(seals_arg, 'w') != NULL)
            seals |= F_SEAL_WRITE;
        if (strchr(seals_arg, 'W') != NULL)
            seals |= F_SEAL_FUTURE_WRITE;
        if (strchr(seals_arg, 'S') != NULL)
            seals |= F_SEAL_SEAL;
        if (fcntl(fd, F_ADD_SEALS, seals) == -1)
            err(EXIT_FAILURE, "fcntl");
    }
    /* Continuer à s'exécuter, afin que le fichier créé par memfd_create()
       continue d'exister.  */
    pause();
    exit(EXIT_SUCCESS);
}

    fd = open(argv[1], O_RDWR);

    seals = fcntl(fd, F_GET_SEALS);
