NOM

mergecap - Fusionne un ou plusieurs fichiers de capture en un seul

SYNTAXE

mergecap [ -a ] [ -F <format de fichier> ] [ -I <mode de fusion IDB> ] [ -s <longueur de capture> ] [ -V ] -w <fichier de sortie>|- <fichier d’entrée> [<fichier d’entrée> ...]

mergecap -h|--help

mergecap -v|--version

DESCRIPTION

Mergecap est un programme qui combine plusieurs fichiers de capture sauvegardés en un seul fichier de sortie spécifié par l'argument -w. Mergecap sait lire les fichiers de capture pcap et pcapng, y compris ceux de tcpdump, Wireshark et d'autres outils qui écrivent des captures dans ces formats.

Par défaut, Mergecap écrit le fichier de capture au format pcapng et écrit tous les paquets des fichiers de capture d'entrée dans le fichier de sortie.

Mergecap est capable de détecter, lire et écrire les mêmes fichiers de capture que ceux pris en charge par Wireshark. Les fichiers d'entrée n'ont pas besoin d'une extension de nom de fichier spécifique ; le format du fichier et une compression gzip, zstd ou lz4 optionnelle seront automatiquement détectés. Près du début de la section DESCRIPTION de wireshark(1) ou https://www.wireshark.org/docs/man-pages/wireshark.html se trouve une description détaillée de la façon dont Wireshark gère cela, qui est la même façon dont Mergecap gère cela.

Mergecap peut écrire le fichier dans plusieurs formats de sortie. L'option -F peut être utilisée pour spécifier le format dans lequel écrire le fichier de capture, mergecap -F fournit une liste des formats de sortie disponibles.

Les paquets des fichiers d'entrée sont fusionnés dans un ordre chronologique basé sur l'horodatage de chaque trame, sauf si l'option -a est spécifiée. Mergecap suppose que les trames au sein d'un même fichier de capture sont déjà dans l'ordre chronologique. Lorsque l'option -a est spécifiée, les paquets sont copiés directement de chaque fichier d'entrée vers le fichier de sortie, indépendamment de l'horodatage de chaque trame.

Le type d'encapsulation des trames du fichier de sortie est défini sur le type des fichiers d'entrée si tous les fichiers d'entrée ont le même type. Si tous les fichiers d'entrée n'ont pas le même type d'encapsulation de trame, le type du fichier de sortie est défini sur WTAP_ENCAP_PER_PACKET. Notez que certains formats de fichiers de capture, notamment pcap, ne prennent pas actuellement en charge WTAP_ENCAP_PER_PACKET. Cette combinaison provoquera l'échec de la création du fichier de sortie.

OPTIONS

-a

Ignore les horodatages des trames, écrivant tous les paquets du premier fichier d'entrée suivis de tous les paquets du second fichier d'entrée. Par défaut, lorsque -a n'est pas spécifié, le contenu des fichiers d'entrée est fusionné dans un ordre chronologique basé sur l'horodatage de chaque trame.

Note : lors de la fusion, mergecap suppose que les paquets d'un fichier de capture sont déjà dans l'ordre chronologique.

-F <format de fichier>

Définit le format du fichier de capture de sortie. Mergecap peut écrire le fichier dans plusieurs formats ; mergecap -F fournit une liste des formats de sortie disponibles. Par défaut, c'est le format pcapng.

-h|--help

Affiche le numéro de version et les options, puis quitte.

-I <mode de fusion IDB>

Définit le mode de fusion des blocs de description d'interface (IDB) à utiliser lors de la fusion. mergecap -I fournit une liste des modes de fusion IDB disponibles.

Chaque fichier d'entrée possède un ou plusieurs IDB, qui décrivent l'interface (ou les interfaces) sur lesquelles la capture a été effectuée initialement. Cela inclut le type d'encapsulation, le nom de l'interface, etc. Lorsque mergecap fusionne plusieurs fichiers d'entrée, il doit fusionner ces IDB d'une manière ou d'une autre pour le nouveau fichier de sortie fusionné. Ce drapeau contrôle comment cela est accompli. Les modes actuellement disponibles sont :

none : Aucune fusion d'IDB n'est effectuée, et à la place, tous les IDB sont copiés dans le fichier de sortie fusionné.

all : Les IDB ne sont fusionnés que si tous les fichiers d'entrée ont le même nombre d'IDB, et que chaque IDB correspond à son entrée respective dans les autres fichiers. (Seuls les IDB qui se trouvent au début des fichiers, avant tout bloc de paquets, sont comparés. Les IDB qui se trouvent plus tard dans les fichiers sont fusionnés avec des doublons si les IDB initiaux ont été fusionnés.) C'est le mode par défaut.

any : Tous les IDB dupliqués sont fusionnés en un seul IDB, quel que soit le fichier dans lequel ils se trouvent.

Notez qu'un IDB n'est considéré comme un doublon correspondant que s'il a le même type d'encapsulation, nom, vitesse, précision temporelle, commentaires, description, etc.

-s <longueur de capture>

Définit la longueur de la capture à utiliser lors de l'écriture des données. Si l'option -s est utilisée pour spécifier une longueur de capture, les trames du fichier d'entrée avec plus de données capturées que la longueur de capture spécifiée n'auront que la quantité de données spécifiée par la longueur de capture écrite dans le fichier de sortie. Cela peut être utile si le programme qui doit lire le fichier de sortie ne peut pas gérer des paquets plus gros qu'une certaine taille (par exemple, les versions de snoop dans Solaris 2.5.1 et Solaris 2.6 semblent rejeter les trames Ethernet plus grandes que le MTU Ethernet standard, ce qui les rend incapables de gérer les captures Gigabit Ethernet si des trames jumbo ont été utilisées).

-v|--version

Affiche les informations complètes sur la version et quitte.

-V

Demande à mergecap d'afficher un certain nombre de messages pendant son exécution.

-w <fichier de sortie>|-

Définit le nom du fichier de sortie. Si le nom est '-', stdout sera utilisé. Si l'option --compress n'est pas donnée, alors l'extension du nom de fichier est utilisée pour déduire la méthode de compression souhaitée, le cas échéant ; par exemple, si le nom a l'extension '.gz', alors le fichier de sortie est compressé dans une archive gzip. Ce paramètre est obligatoire.

--compress <type>

Compresse le fichier de sortie en utilisant le format de compression de type spécifié. --compress sans argument fournit une liste des formats de compression pris en charge pour l'écriture. Le type donné a la priorité sur l'extension de fichier de sortie.

OPTIONS DIAGNOSTIQUES

--log-level <level>

Définit le niveau de journalisation actif. Les niveaux pris en charge dans l'ordre du plus bas au plus élevé sont "noisy", "debug", "info", "message", "warning", "critical" et "error". Les messages à chaque niveau et supérieurs seront imprimés, par exemple "warning" imprime les messages "warning", "critical" et "error", et "noisy" imprime tous les messages. Les niveaux ne sont pas sensibles à la casse.

--log-fatal <level>

Arrête le programme si des messages sont journalisés au niveau spécifié ou supérieur. Par exemple, "warning" arrête en cas de message "warning", "critical" ou "error".

--log-domains <liste>

N'imprime les messages que pour les domaines de journalisation spécifiés, par exemple "GUI,Epan,sshdump". La liste des domaines doit être séparée par des virgules. Peut être niée avec "!" comme premier caractère (inverse la correspondance).

--log-debug <liste>

Force les domaines spécifiés à se connecter au niveau "debug". La liste des domaines doit être séparée par des virgules. Peut être niée avec "!" comme premier caractère (inverse la correspondance).

--log-noisy <liste>

Force les domaines spécifiés à se connecter au niveau "noisy". La liste des domaines doit être séparée par des virgules. Peut être niée avec "!" comme premier caractère (inverse la correspondance).

--log-fatal-domains <liste>

Arrête le programme si des messages sont journalisés pour les domaines de journalisation spécifiés. La liste des domaines doit être séparée par des virgules.

--log-file <chemin>

Écrit les messages de journalisation et la sortie stderr dans le fichier spécifié.

mergecap(8) - Manuel ArchWiki

NOM

mergecap - fusionne plusieurs fichiers de capture enregistrés en un seul

SYNOPSIS

mergecap [ -a ] [ -h ] [ -V ] [ -d mesg ] [ -i interval ] [ -s snaplen ] [ -L ] [ -p ] [ -o offset ] [ -t time_shift ] [ -w outfile ] [ -F fileformat ] [ -S ] [ -T textcap ] infile...

DESCRIPTION

La commande mergecap est un utilitaire qui fusionne plusieurs fichiers de capture enregistrés en un seul, choisissant les paquets de ces fichiers dans l'ordre chronologique. Elle peut également modifier les horodatages des paquets.

Le format des fichiers d'entrée doit être le même.

Les options -a, -h, -V, -d, -i, -s, -L, -p, -o, -t, -w, -F, -S et -T ont la même signification que dans la page de manuel editcap(8).

OPTIONS

Les options ci-dessous sont disponibles.

-a
Spécifie que les fichiers de capture d'entrée sont fusionnés dans l'ordre chronologique. Si cette option n'est pas spécifiée, les fichiers d'entrée sont fusionnés dans l'ordre dans lequel ils apparaissent sur la ligne de commande.
-d mesg
Imprime un message de diagnostic lorsqu'un paquet est ignoré. L'entier mesg spécifie le niveau de détail du message.
-F fileformat
Définit le format des fichiers de sortie. Les formats disponibles sont ceux qui peuvent être écrits par dumpcap(1) et sont répertoriés dans la page de manuel dumpcap(1).
-h
Affiche un message d'aide et quitte.
-i interval
Crée un nouveau fichier de sortie toutes les interval secondes. La valeur de interval est exprimée en secondes. Par exemple, -i 60 crée un nouveau fichier de sortie toutes les minutes.
-L
Laisse les horodatages des paquets intacts. Par défaut, les horodatages des paquets sont ajustés pour qu'ils correspondent à l'heure de capture.
-o offset
Ajoute un décalage de offset secondes aux horodatages de tous les paquets.
-p
Génère une sortie de paquets qui peut être analysée par text2pcap(1).
-S
Ignore la longueur de capture et les informations d'instantané lors de la fusion.
-s snaplen
Définit la longueur de capture du fichier de sortie sur snaplen octets. Si snaplen est 0, la longueur de capture sera illimitée.
-T textcap
Convertit le fichier textcap en un fichier de capture binaire.
-t time_shift
Ajoute time_shift secondes aux horodatages de tous les paquets. La valeur de time_shift peut être positive ou négative.
-V
Affiche la version et quitte.
-w outfile
Spécifie le nom du fichier de sortie.

OPTIONS DE DIAGNOSTIC

mergecap inclut les options de diagnostic suivantes :

-d mesg
Imprime un message de diagnostic lorsqu'un paquet est ignoré. L'entier mesg spécifie le niveau de détail du message.

EXEMPLES

Pour fusionner les fichiers a.pcap et b.pcap en un seul fichier nommé compare.pcap, tout en s'assurant que les paquets de b.pcap apparaissent 100 secondes avant le début de a.pcap, utilisez la séquence de commandes suivante.

Tout d'abord, utilisez :

capinfos -aeS a.pcap b.pcap

pour déterminer les heures de début et de fin des deux fichiers de capture, en secondes depuis le 1er janvier 1970, 00:00:00 UTC.

Si a.pcap démarre à 1009932757 et b.pcap se termine à 873660281, alors le décalage temporel à appliquer à b.pcap pour qu'il se termine 100 secondes avant le début de a.pcap serait 1009932757 - 873660281 - 100 = 136272376 secondes.

Ainsi, la prochaine étape serait d'utiliser :

editcap -t 136272376 b.pcap b-shifted.pcap

pour générer une version de b.pcap avec ses horodatages décalés de 136272376.

Ensuite, l'étape finale serait d'utiliser :

mergecap -w compare.pcap a.pcap b-shifted.pcap

pour fusionner a.pcap et le b.pcap décalé en compare.pcap.
