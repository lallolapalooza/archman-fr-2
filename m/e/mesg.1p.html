MESG(1P) Manuel du programmeur POSIX MESG(1P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

mesg — autoriser ou refuser les messages

SYNTAXE

mesg [y|n]

DESCRIPTION

L'utilitaire mesg contrôle si les autres utilisateurs sont autorisés à envoyer des messages via write, talk ou d'autres utilitaires vers un périphérique terminal. Le périphérique terminal affecté est déterminé en recherchant le premier terminal dans la séquence des périphériques associés à l'entrée standard, à la sortie standard et à l'erreur standard, respectivement. Sans arguments, mesg signale l'état actuel sans le modifier. Les processus disposant des privilèges appropriés peuvent être en mesure d'envoyer des messages au terminal indépendamment de l'état actuel.

OPTIONS

Aucune.

OPÉRANDES

Les opérandes suivants sont pris en charge dans la locale POSIX :

y
Accorde la permission aux autres utilisateurs d'envoyer des messages au périphérique terminal.
n
Refuse la permission aux autres utilisateurs d'envoyer des messages au périphérique terminal.

ENTRÉE STANDARD

Non utilisée.

FICHIERS D'ENTRÉE

Aucun.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affectent l'exécution de mesg :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume des Définitions de Base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si définie à une chaîne de caractères non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition à multi-octets dans les arguments).
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages diagnostiques écrits (par mesg) sur l'erreur standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

SORTIE STANDARD

Si aucun opérande n'est spécifié, mesg affiche l'état actuel du terminal dans un format non spécifié.

ERREUR STANDARD

L'erreur standard est utilisée uniquement pour les messages diagnostiques.

FICHIERS DE SORTIE

Aucun.

DESCRIPTION ÉTENDUE

Aucune.

STATUT DE SORTIE

Les valeurs de sortie suivantes sont retournées :

 0
La réception des messages est autorisée.
 1
La réception des messages n'est pas autorisée.
>1
Une erreur s'est produite.

CONSÉQUENCES DES ERREURS

Par défaut.

Les sections suivantes sont informatives.

UTILISATION PAR L'APPLICATION

Le mécanisme par lequel le statut du terminal est modifié n'est pas spécifié. Par conséquent, des actions non spécifiées peuvent entraîner un changement de statut du terminal après la fin réussie de mesg. Ces actions peuvent inclure, sans s'y limiter : une autre invocation de l'utilitaire mesg, des procédures de connexion ; l'invocation de l'utilitaire stty, l'invocation de l'utilitaire chmod ou de la fonction chmod(), etc.

EXEMPLES

Aucun.

JUSTIFICATION

Le terminal modifié par mesg est celui associé à l'entrée, la sortie ou l'erreur standard, plutôt que le terminal de contrôle de la session. Ceci est parce que les utilisateurs connectés plus d'une fois devraient être capables de modifier chacun de leurs terminaux de connexion sans avoir à arrêter le travail en cours dans ces sessions. Ce n'est pas un problème de sécurité impliquant les terminaux d'autres utilisateurs car des privilèges appropriés seraient requis pour affecter le terminal d'un autre utilisateur.

La méthode de vérification de chacun des trois premiers descripteurs de fichiers en séquence jusqu'à ce qu'un terminal soit trouvé a été adoptée de System V.

Le fichier /dev/tty n'est pas spécifié pour le périphérique terminal car il était jugé trop restrictif. Les changements typiques d'environnement pour l'opérande n sont que les permissions d'écriture sont supprimées pour autres et groupe du périphérique approprié. Il a été décidé de laisser la description réelle de ce qui est fait comme non spécifiée en raison des différences potentielles entre les implémentations.

Le format de la sortie standard n'est pas spécifié en raison des différences entre les implémentations historiques. Cette sortie n'est généralement pas utile pour les scripts shell (ils peuvent utiliser le statut de sortie), donc un analyse syntaxique exacte de la sortie n'est pas nécessaire.
