MEMCACHE_TABLE(5) Manuel des formats de fichiers MEMCACHE_TABLE(5)

NOM

memcache_table - Configuration du client memcache de Postfix

SYNTAXE

postmap -q "chaîne" memcache:/etc/postfix/nom_fichier
postmap -q - memcache:/etc/postfix/nom_fichier <fichier_entrée

DESCRIPTION


Le système de messagerie Postfix utilise des tables optionnelles pour la réécriture d'adresses ou le routage de courriels. Ces tables sont généralement au format dbm ou db.

Alternativement, les tables de recherche peuvent être spécifiées comme des instances memcache. Pour utiliser des recherches memcache, définissez une source memcache comme table de recherche dans main.cf, par exemple :

    virtual_alias_maps = memcache:/etc/postfix/memcache-aliases.cf

Le fichier /etc/postfix/memcache-aliases.cf a le même format que le fichier main.cf de Postfix et spécifie les paramètres décrits ci-dessous.

Le client memcache de Postfix prend en charge les opérations de recherche, de mise à jour, de suppression et de séquence (premier/suivant). L'opération de séquence nécessite une base de données de sauvegarde qui prend en charge l'opération.

PARAMETRES MEMCACHE PRINCIPAUX

memcache (par défaut: inet:localhost:11211)
Le serveur memcache (note : singulier) auquel Postfix tentera de se connecter. Pour un serveur TCP, spécifiez "inet:" suivi d'un nom d'hôte ou d'une adresse, de ":", et d'un nom ou numéro de port. Spécifiez une adresse IPv6 entre crochets "[]". Pour un serveur de domaine UNIX, spécifiez "unix:" suivi du chemin d'accès du socket. Exemples : 
    memcache = inet:memcache.example.com:11211
    memcache = inet:127.0.0.1:11211
    memcache = inet:[fc00:8d00:189::3]:11211
    memcache = unix:/chemin/vers/socket

NOTE : pour accéder à un socket de domaine UNIX avec le serveur proxymap(8), le socket doit être accessible par l'utilisateur postfix non privilégié.

backup (par défaut: non défini)
Une base de données Postfix optionnelle qui fournit une sauvegarde persistante pour la base de données memcache. Le client memcache de Postfix mettra à jour la base de données memcache chaque fois qu'il recherchera ou modifiera des informations dans la base de données persistante. Spécifiez une base de données Postfix de type "type:table". Exemples : 
    # Cache postscreen non partagé.
    backup = btree:/var/lib/postfix/postscreen_cache_map
    # Cache postscreen partagé pour les processus sur le même hôte.
    backup = proxy:btree:/var/lib/postfix/postscreen_cache_map

L'accès aux serveurs proxymap distants est en cours de développement.

NOTE 1 : Lors du partage d'un cache postscreen(8) ou verify(8) persistant, désactivez le nettoyage automatique du cache (définissez *_cache_cleanup_interval = 0) sauf avec une seule instance Postfix qui sera responsable du nettoyage du cache.

NOTE 2 : Lorsque plusieurs tables partagent la même base de données memcache, chaque table doit utiliser la fonctionnalité key_format (voir ci-dessous) pour préfixer sa propre chaîne unique à la clé de recherche. Sinon, le nettoyage automatique du cache postscreen(8) ou verify(8) pourrait ne pas fonctionner.

NOTE 3 : Lorsque la base de données de sauvegarde est accessible via des recherches "proxy:", le nom complet de la base de données de sauvegarde (y compris le préfixe "proxy:") doit être spécifié dans le paramètre proxy_read_maps ou proxy_write_maps du serveur proxymap (selon que l'accès est en lecture seule ou en lecture/écriture).

flags (par défaut: 0)
Indicateurs optionnels qui doivent être stockés avec une mise à jour memcache. Les indicateurs sont ignorés lors de la recherche d'informations.
ttl (par défaut: 3600)
Le temps d'expiration en secondes des mises à jour memcache.

NOTE 1 : Lors de l'utilisation d'une table memcache comme cache postscreen(8) ou verify(8) sans sauvegarde persistante, spécifiez une valeur *_cache_cleanup_interval nulle avec toutes les instances Postfix qui utilisent memcache, et spécifiez la plus grande valeur *_ttl de postscreen(8) ou la valeur *_expire_time de verify(8) comme valeur ttl de la table memcache.

NOTE 2 : Selon la documentation du protocole memcache, une valeur supérieure à 30 jours (2592000 secondes) spécifie une heure UNIX absolue. Des valeurs plus petites sont relatives à l'heure de la mise à jour.

PARAMETRES CLE MEMCACHE

key_format (par défaut: %s)
Format des clés de recherche et de mise à jour que le client memcache de Postfix envoie au serveur memcache. Par défaut, elles sont identiques aux clés de recherche et de mise à jour que le client memcache reçoit des applications Postfix.

NOTE 1 : La fonctionnalité key_format n'est pas utilisée pour les requêtes de la base de données backup.

NOTE 2 : Lorsque plusieurs tables partagent la même base de données memcache, chaque table doit préfixer sa propre chaîne unique à la clé de recherche. Sinon, le nettoyage automatique du cache postscreen(8) ou verify(8) pourrait ne pas fonctionner.

Exemples :

    key_format = aliases:%s
    key_format = verify:%s
    key_format = postscreen:%s

Le paramètre key_format prend en charge les expansions '%' suivantes :

%%
Ceci est remplacé par un caractère '%' littéral.
%s
Ceci est remplacé par la clé d'entrée du client memcache.
%u
Lorsque la clé d'entrée est une adresse de la forme utilisateur@domaine, %u est remplacé par la partie locale de l'adresse mise entre guillemets SQL. Sinon, %u est remplacé par la chaîne de recherche entière. Si la partie locale est vide, une recherche est silencieusement supprimée et ne retourne aucun résultat (une mise à jour est ignorée avec un avertissement).
%d
Lorsque la clé d'entrée est une adresse de la forme utilisateur@domaine, %d est remplacé par la partie domaine de l'adresse. Sinon, une recherche est silencieusement supprimée et ne retourne aucun résultat (une mise à jour est ignorée avec un avertissement).
%[SUD]
Les équivalents en majuscules des expansions ci-dessus se comportent dans le paramètre key_format de manière identique à leurs homologues en minuscules.
%[1-9]
Les motifs %1, %2, ... %9 sont remplacés par le composant le plus significatif correspondant du domaine de la clé d'entrée. Si la clé d'entrée est utilisateur@mail.example.com, alors %1 est com, %2 est example et %3 est mail. Si la clé d'entrée n'est pas qualifiée ou n'a pas suffisamment de composants de domaine pour satisfaire tous les motifs spécifiés, une recherche est silencieusement supprimée et ne retourne aucun résultat (une mise à jour est ignorée avec un avertissement).
domain (par défaut: pas de liste de domaines)
Cette fonctionnalité peut réduire considérablement la charge du serveur de base de données. Spécifiez une liste de noms de domaines, de chemins vers des fichiers ou de bases de données "type:table". Lorsqu'il est spécifié, seuls les clés de recherche entièrement qualifiées avec une partie locale *non vide* et un domaine correspondant sont éligibles pour la recherche ou la mise à jour : les recherches de 'utilisateur' brutes, les recherches de domaine brutes et les recherches "@domaine" sont silencieusement ignorées (les mises à jour sont ignorées avec un avertissement). Exemple : 
    domain = example.com, hash:/etc/postfix/searchdomains

CONTROLES ERREUR MEMCACHE

data_size_limit (par défaut: 10240)
La longueur maximale des données de réponse memcache en octets.
line_size_limit (par défaut: 1024)
La longueur maximale d'une ligne de réponse memcache en octets.
max_try (par défaut: 2)
Le nombre de tentatives pour une commande memcache avant d'abandonner. Le client memcache ne réessaie pas une commande lorsque le serveur memcache n'accepte pas de connexion.
retry_pause (par défaut: 1)
Le temps en secondes avant de réessayer une commande memcache échouée.
timeout (par défaut: memcache_table(5)

MEMCACHE_ERROR_CONTROLS

3)
Le délai pour envoyer une commande memcache et pour recevoir une réponse memcache.

BOGUES


Le client memcache de Postfix ne peut pas être utilisé pour des tables sensibles à la sécurité telles que alias_maps (celles-ci peuvent contenir des destinations "|commande" et "/nom/de/fichier"), ou virtual_uid_maps, virtual_gid_maps et virtual_mailbox_maps (celles-ci spécifient des privilèges de processus UNIX ou des destinations "/nom/de/fichier"). Dans un déploiement typique, une base de données memcache est accessible en écriture par tout processus capable de communiquer avec le serveur memcache ; en revanche, les tables sensibles à la sécurité ne doivent jamais être accessibles en écriture par l'utilisateur non privilégié de Postfix.

Le client memcache de Postfix nécessite une configuration supplémentaire lorsqu'il est utilisé comme cache pour postscreen(8) ou verify(8). Pour plus de détails, voir les discussions sur les paramètres backup et ttl dans la section PARAMÈTRES PRINCIPAUX DE MEMCACHE ci-dessus.
