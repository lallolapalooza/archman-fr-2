NOM

mako - fichier de configuration

DESCRIPTION

Le fichier de configuration se trouve à ~/.config/mako/config ou à $XDG_CONFIG_HOME/mako/config. Les lignes d'options peuvent être spécifiées pour configurer mako comme suit :

clé=valeur

Les lignes vides et les lignes commençant par # sont ignorées.

OPTIONS DE CONFIGURATION GLOBALES

max-history=n

Définit le nombre maximum de notifications expirées à conserver dans le tampon d'historique à n. Si le tampon est plein, les nouvelles notifications expirées remplacent les plus anciennes. Si 0, l'historique est désactivé.

Par défaut : 5

sort=+/-time | +/-priority

Trie les notifications entrantes par heure et/ou priorité dans l'ordre croissant (+) ou décroissant (-).

Par défaut : -time

include=chemin de configuration

Inclut une configuration au chemin spécifié. Le chemin doit être absolu ou commencer par ~/.

Par défaut : aucun

OPTIONS DE LIAISON

Les liaisons permettent d'effectuer une action lorsqu'un événement est déclenché.

Options supportées :

on-button-left=action

Exécute l'action lorsque le bouton gauche de la souris est pressé.

Par défaut : invoke-default-action

on-button-middle=action

Exécute l'action lorsque le bouton du milieu de la souris est pressé.

Par défaut : none

on-button-right=action

Exécute l'action lorsque le bouton droit de la souris est pressé.

Par défaut : dismiss

on-touch=action

Exécute l'action lorsqu'on touche avec un appareil tactile.

Par défaut : dismiss

on-notify=action

Exécute l'action lorsque la notification est ouverte.

Par défaut : none

Actions supportées :

none

Ne rien faire.

dismiss [--no-history]

Rejette la notification actuelle. Si --no-history est passé, la notification ne sera pas ajoutée à l'historique.

dismiss-all

Rejette toutes les notifications.

dismiss-group

Rejette les notifications du groupe actuel.

invoke-action <action>

Appelle l'action nommée sur la notification.

Un jeton xdg-activation sera envoyé au client, permettant au client de demander le focus au compositeur. Le compositeur doit supporter le protocole xdg_activation_v1 et autoriser la demande de focus pour que l'exemple suivant fonctionne correctement :

[app-name="some-app-id" actionable]
on-button-left=invoke-action mail-reply-sender

invoke-default-action

Appelle l'action par défaut sur la notification.

exec <commande>

Exécute une commande shell.

La commande sera exécutée dans un shell POSIX. La variable shell id sera définie sur l'ID de la notification. Par exemple, l'option suivante affichera un menu d'actions interactif au clic du milieu :

on-button-middle=exec makoctl menu -n "$id" dmenu -p 'Sélectionner l'action : '

L'option suivante jouera un son lorsqu'une nouvelle notification sera ouverte :

on-notify=exec mpv /usr/share/sounds/freedesktop/stereo/message.oga

OPTIONS DE STYLE

font=police

Définit la police sur police, en tant que description de police Pango. Pour plus d'informations sur les descriptions de polices Pango, voir : https://docs.gtk.org/Pango/type_func.FontDescription.from_string.html#description

Par défaut : monospace 10

background-color=couleur

Définit la couleur d'arrière-plan sur couleur. Voir COULEURS pour plus d'informations.

Par défaut : #285577FF

text-color=couleur

Définit la couleur du texte sur couleur. Voir COULEURS pour plus d'informations.

Par défaut : #FFFFFFFF

width=px

Définit la largeur des popups de notification.

Par défaut : 300

height=px

Définit la hauteur maximale des popups de notification. Les notifications dont le texte prend moins de place sont redimensionnées pour s'adapter.

Par défaut : 100

outer-margin=directionnel

Définit la marge extérieure de chaque bord à la taille spécifiée par directionnel. Voir VALEURS DIRECTIONNELLES pour plus d'informations. Cette marge s'applique à l'extérieur de la liste entière des notifications.

Par défaut : 0

margin=directionnel

Définit la marge de chaque bord à la taille spécifiée par directionnel. Voir VALEURS DIRECTIONNELLES pour plus d'informations. Cette marge s'applique à chaque notification individuelle. Notez qu'elle s'ajoute à la marge extérieure, ce qui signifie que les première et dernière notifications utiliseront la somme des deux marges.

Par défaut : 10

padding=directionnel

Définit le remplissage de chaque côté à la taille spécifiée par directionnel. Voir VALEURS DIRECTIONNELLES pour plus d'informations.

Par défaut : 5

border-size=px

Définit la taille de la bordure du popup à px pixels.

Par défaut : 2

border-color=couleur

Définit la couleur de la bordure du popup sur couleur. Voir COULEURS pour plus d'informations.

Par défaut : #4C7899FF

border-radius=directionnel

Définit le rayon des coins du popup sur la taille spécifiée par directionnel. Voir VALEURS DIRECTIONNELLES pour plus d'informations.

Par défaut : 0

progress-color=[over|source] couleur

Définit la couleur de l'indicateur de progression du popup sur couleur. Voir COULEUR pour plus d'informations. Pour dessiner l'indicateur de progression par-dessus la couleur d'arrière-plan, utilisez l'attribut over. Pour remplacer la couleur d'arrière-plan, utilisez l'attribut source (cela peut être utile lorsque la notification est semi-transparente).

La progression peut être indiquée dans une notification en définissant l'indice "value" sur un entier entre 0 et 100 inclus.

Par défaut : over #5588AAFF

icons=0|1

Affiche les icônes dans les notifications.

Par défaut : 1

max-icon-size=px

Définit la taille maximale de l'icône à px pixels.

Par défaut : 64

icon-path=chemin[:chemin...]

Chemins à rechercher pour les icônes lorsqu'une notification spécifie un nom au lieu d'un chemin complet. Séparés par des deux-points. Ceci est une approximation de l'algorithme de recherche utilisé par la spécification XDG Icon Theme, mais ne supporte aucun des métadonnées du thème. Par conséquent, si vous souhaitez rechercher les thèmes parents, vous devrez les ajouter manuellement au chemin.

Le chemin doit être la racine du thème d'icônes, les catégories et les résolutions seront recherchées pour trouver la correspondance la plus appropriée.

Les répertoires /usr/share/icons/hicolor et /usr/share/pixmaps sont toujours recherchés.

Par défaut : ""

icon-location=position

Position de l'icône par rapport au texte affiché. Les options valides sont left, right, top et bottom.

Par défaut : left

icon-border-radius=px

Définit le rayon des coins de l'icône à px pixels.

Par défaut : 0

markup=0|1

Si 1, active le balisage Pango. Si 0, désactive le balisage Pango. Si activé, le balisage Pango sera interprété dans votre spécificateur de format et dans le corps des notifications.

Par défaut : 1

actions=0|1

Les applications peuvent demander une action associée à l'activation d'une notification. Désactiver cela fera en sorte que mako ignore ces requêtes.

Par défaut : 1

history=0|1

Si défini, mako enregistrera
e notifications qui ont atteint leur expiration dans le tampon d'historique au lieu de les supprimer immédiatement. max-history détermine la taille du tampon d'historique.

Par défaut : 1

format=format

Définit la chaîne de format de notification sur format. Voir SYNTAXE DE FORMATAGE pour plus d'informations. Pour modifier cela pour les notifications groupées, définissez-le dans un critère grouped.

Par défaut : <b>%s</b>\n%b
Par défaut lors du regroupement : (%g) <b>%s</b>\n%b

text-alignment=left|center|right

Définit l'alignement du texte de la notification.

Par défaut : left

default-timeout=timeout

Définit le délai d'expiration par défaut à timeout en millisecondes. Pour désactiver le délai d'expiration, définissez-le sur zéro.

Par défaut : 0

ignore-timeout=0|1

S'il est défini, mako ignorera le délai d'expiration envoyé par les notifications et utilisera celui fourni par default-timeout à la place.

Par défaut : 0

group-by=champ[,champ,...]

Une liste de champs de critères séparés par des virgules qui seront comparés à d'autres notifications visibles pour déterminer si celle-ci doit former un groupe avec elles. Tous les critères listés doivent être exactement égaux pour que deux notifications forment un groupe.

Par défaut : none

max-visible=n

Définit le nombre maximum de notifications visibles à n. Les notifications plus anciennes seront masquées. Si -1, toutes les notifications sont visibles.

Par défaut : 5

output=nom

Affiche les notifications sur la sortie spécifiée. Si vide, les notifications apparaîtront sur la sortie active.

Nécessite que le compositeur prenne en charge le protocole Wayland xdg-output-unstable-v1 version 2.

Par défaut : ""

layer=couche

Dispose mako dans la couche spécifiée, par rapport aux fenêtres normales. Les valeurs prises en charge sont background, bottom, top, et overlay. Utiliser overlay provoquera l'affichage des notifications au-dessus des fenêtres plein écran, bien que cela puisse également se produire à top selon votre compositeur.

Par défaut : top

anchor=position

Affiche les notifications à la position spécifiée sur la sortie. Les valeurs prises en charge sont top-right, top-center, top-left, bottom-right, bottom-center, bottom-left, center-right, center-left et center.

Par défaut : top-right

CRITÈRES

En plus de l'ensemble d'options en haut du fichier, le fichier de configuration peut contenir zéro section ou plus, chacune contenant n'importe quelle combinaison des OPTIONS DE LIAISON et des OPTIONS DE STYLE. Les sections, appelées critères, sont définies avec une syntaxe de crochets de type INI. Les crochets peuvent contenir n'importe quel nombre de champs, comme suit :

[champ=valeur champ2=valeur2 ...]

Lorsqu'une notification est reçue, elle sera comparée aux champs définis dans chaque critère. Si tous les champs correspondent, les options de style qu'ils contiennent seront appliquées à la notification. Les champs non inclus dans le critère ne sont pas pris en compte lors de la correspondance. Une notification peut correspondre à n'importe quel nombre de critères. Cette correspondance se produit dans l'ordre où les critères sont définis dans le fichier de configuration, ce qui signifie que si plusieurs critères correspondent à une notification, la dernière occurrence d'une option de style donnée "gagnera".

Les champs suivants sont disponibles dans les critères :

  • app-name (chaîne)
  • app-icon (chaîne)
  • summary (chaîne) : correspondance exacte sur le résumé de la notification. Ce champ entre en conflit avec summary~.
  • summary~ (chaîne) : une correspondance d'expression régulière étendue POSIX sur le résumé de la notification. Ce champ entre en conflit avec summary.
  • body (chaîne) : une correspondance exacte sur le corps de la notification. Ce champ entre en conflit avec body~.
  • body~ (chaîne) : une correspondance d'expression régulière étendue POSIX sur le corps de la notification. Ce champ entre en conflit avec body.
  • urgency (l'un de "low", "normal", "critical")
  • category (chaîne)
  • desktop-entry (chaîne)
  • actionable (booléen)
  • expiring (booléen)
  • mode (chaîne) : n'appliquez les options de style de cette section que si le mode fourni est actuellement activé. Pour plus d'informations sur les modes, voir la section MODES.

Les champs suivants sont également disponibles pour la correspondance lors d'une deuxième passe, en fonction de l'endroit où les options de style précédentes ont décidé de placer chaque notification :

  • grouped (booléen) : indique si la notification est groupée avec d'autres.
  • group-index (int) : l'index de la notification dans son groupe, ou -1 si elle n'est pas groupée.
  • hidden (booléen) : champ spécial qui définit le style du placeholder affiché lorsque le nombre de notifications ou de groupes dépasse max-visible.
  • output (chaîne) : sur quelle sortie la notification a été triée. Voir l'option de style output pour les valeurs possibles.
  • anchor (chaîne) : à quelle position sur la sortie la notification a été assignée. Voir l'option de style anchor pour les valeurs possibles.

Il n'y a que deux passes effectuées sur chaque notification, de sorte que les critères de la deuxième passe ne sont pas autorisés à repositionner la notification.

Si la valeur d'un champ contient des caractères spéciaux, ils peuvent être échappés avec une barre oblique inverse, ou mis entre guillemets :

[app-name="Google Chrome"]

[app-name=Google\ Chrome]

Les guillemets dans les guillemets peuvent également être échappés, et une barre oblique inverse littérale peut être spécifiée comme \\. Aucune espace n'est autorisée autour du signe égal. L'échappement des signes égal dans les valeurs n'est pas nécessaire.

De plus, les valeurs booléennes peuvent être spécifiées en utilisant n'importe lequel de true/false, 0/1, ou comme mots nus :

[actionable=true] [actionable=1] [actionable]

[actionable=false] [actionable=0] [!actionable]

Il y a trois critères toujours présents au début de la liste :

  • Un critère vide qui correspond à toutes les notifications et contient les valeurs par défaut pour toutes les options de style, remplacées par celles configurées dans la section globale.
  • [grouped], qui définit le format par défaut pour les notifications groupées et les rend invisibles.
  • [group-index=0], qui rend à nouveau visible le premier membre de chaque groupe.

Ces options peuvent être remplacées en définissant simplement vous-même les critères et en les surchargeant.

Il existe quelques règles restreignant ce qui peut être configuré en fonction de ce qui est mis en correspondance par un critère donné. Les critères correspondant à grouped ou group-index ne sont pas autorisés à modifier anchor, output ou group-by, car cela invaliderait le regroupement. Le regroupement n'est effectué qu'une seule fois plutôt que de manière récursive, pour éviter le potentiel de boucles infinies.

OPTIONS DE STYLE UNIQUEMENT POUR LES CRITÈRES

Certaines options de style ne sont pas utiles dans le contexte global et n'ont par conséquent pas d'option de ligne de commande associée.

invisible=0|1

Indique si cette notification doit être invisible même si elle se trouve au-dessus du seuil max-visible. Ceci est principalement utilisé pour masquer les membres des groupes. Si vous souhaitez rendre plus d'un membre de groupe visible, désactivez cette option dans un critère group-index.

Par défaut : 0

COULEURS

Les couleurs peuvent être spécifiées comme #RRGGBB ou #RRGGBBAA.

VALEURS DIRECTIONNELLES

Certaines options définissent des valeurs qui affectent les quatre bords d'une notification. Ces options peuvent être spécifiées de plusieurs manières différentes, en fonction du contrôle souhaité sur chaque bord :

  • Une seule valeur s'appliquera aux quatre bords.
  • Deux valeurs définiront séparément les bords verticaux et horizontaux.
  • Trois définiront séparément les bords supérieur, horizontal et inférieur.
  • Quatre définiront séparément les bords supérieur, droit, inférieur et gauche.

Lors de la spécification de plusieurs valeurs, elles doivent être séparées par des virgules. Par exemple, ceci définirait la marge supérieure à 10, les marges gauche et droite à 20, et la marge inférieure à 5 :

margin = 10,20,5

SYNTAXE DE FORMATAGE

Le formatage fonctionne de manière similaire à printf(3), mais avec un ensemble de spécificateurs différent.

%% "%" littéral

\\ "\" littéral

\n Nouvelle ligne

Pour les notifications

%a Nom de l'application

%s Résumé de la notification

%b Corps de la notification

%g Nombre de notifications dans le groupe actuel

%i ID de la notification

Pour le placeholder des notifications masquées

%h Nombre de notifications masquées

%t Nombre total de notifications

MODES

mako prend en charge l'application conditionnelle d'options de style via des modes. Une section de configuration avec un critère mode ne sera appliquée que si le mode actuel correspond. makoctl(1) peut être utilisé pour changer le mode actuel.

La liste initiale des modes contient un seul mode appelé "default". Ceci est déprécié, dans une future version la liste initiale des modes sera vide.

Par exemple, pour masquer toutes les notifications si le mode "do-not-disturb" est activé :

[mode=do-not-disturb]
invisible=1

makoctl mode -a do-not-disturb masquera toutes les notifications, makoctl mode -r do-not-disturb les affichera à nouveau.
