NOM

machine-info - Fichier d'informations sur la machine locale

SYNTAXE

/etc/machine-info

DESCRIPTION

Le fichier /etc/machine-info contient des métadonnées sur la machine.

Le format de machine-info est une liste séparée par des sauts de ligne d'affectations de variables de type shell, ignorant les commentaires et les lignes vides. Il est possible de sourcer la configuration à partir de scripts shell, cependant, au-delà des simples affectations de variables, aucune fonctionnalité shell n'est supportée, permettant aux applications de lire le fichier sans implémenter un moteur d'exécution compatible shell. Voir os-release(5) pour une description détaillée du format.

/etc/machine-info contient des métadonnées sur la machine qui sont définies par l'utilisateur ou l'administrateur. Les paramètres configurés ici ont la priorité la plus élevée. Lorsqu'ils ne sont pas définis, des valeurs appropriées peuvent être déterminées automatiquement, sur la base des informations sur le matériel ou d'autres fichiers de configuration. Il est donc tout à fait acceptable que ce fichier n'existe pas.

Vous pouvez utiliser hostnamectl(1) pour modifier les paramètres de ce fichier en ligne de commande.

OPTIONS

Les paramètres de métadonnées de machine suivants peuvent être définis en utilisant /etc/machine-info :

Informations sur la machine

PRETTY_HOSTNAME=

Une chaîne d'identifiant de machine joliment lisible, en UTF-8. Elle doit contenir un nom tel que « L'ordinateur portable de Lénart » qui est utile à présenter à l'utilisateur et ne souffre pas des limitations syntaxiques des noms de domaine Internet. Si possible, le nom d'hôte Internet tel que configuré dans /etc/hostname doit être similaire à celui-ci. Exemple : si cette valeur est « L'ordinateur de Lénart », un nom d'hôte Internet de « lennarts-ordinateur » pourrait être un bon choix. Si ce paramètre n'est pas défini, une application devrait se rabattre sur le nom d'hôte Internet à des fins de présentation.

ICON_NAME=

Une icône identifiant cette machine conformément à la Spécification de nommage des icônes XDG[1]. Si ce paramètre n'est pas défini, une application devrait se rabattre sur « computer » ou un nom d'icône similaire.

CHASSIS=

Le type de châssis. Actuellement, les types de châssis suivants sont définis : « desktop », « laptop », « convertible », « server », « tablet », « handset », « watch » et « embedded », ainsi que les types de châssis spéciaux « vm » et « container » pour les systèmes virtualisés qui manquent de châssis physique immédiat.

Notez que la plupart des systèmes permettent la détection automatique du type de châssis (basée sur les informations du firmware ou similaire). Ce paramètre ne doit être utilisé que pour remplacer une mauvaise détection ou pour configurer manuellement le type de châssis lorsque la détection automatique n'est pas disponible.

Ajouté dans la version 197.

DEPLOYMENT=

Décrit l'environnement de déploiement du système. L'une des options suivantes est suggérée : « development », « integration », « staging », « production ».

Ajouté dans la version 216.

LOCATION=

Décrit l'emplacement du système si applicable et connu. Prend une chaîne de caractères conviviale et libre. Cela peut être aussi générique que « Berlin, Allemagne » ou aussi spécifique que « Rack gauche, 2ème étagère ».

Ajouté dans la version 216.

HARDWARE_VENDOR=

Spécifie le vendeur du matériel. Si non spécifié, le vendeur du matériel défini dans DMI ou hwdb(7) sera utilisé.

Ajouté dans la version 251.

HARDWARE_MODEL=

Spécifie le modèle du matériel. Si non spécifié, le modèle du matériel défini dans DMI ou hwdb(7) sera utilisé.

Ajouté dans la version 251.

HARDWARE_SKU=

Spécifie le SKU (Stock-Keeping Unit) du matériel. Si non spécifié, le SKU du matériel défini dans DMI sera utilisé.

Ajouté dans la version 258.

HARDWARE_VERSION=

Spécifie la version du matériel. Si non spécifié, la version du matériel définie dans DMI sera utilisée.

Ajouté dans la version 258.

Champs personnalisés

Les vendeurs de systèmes d'exploitation et les administrateurs système peuvent étendre le format de fichier et introduire de nouveaux champs. Il est fortement recommandé de préfixer les nouveaux champs avec un nom spécifique à l'OS afin d'éviter les conflits de noms. Les applications lisant ce fichier doivent ignorer les champs inconnus.

Exemple : "_LOCAL_EMERGENCY_CONTACT="user@example.org"".

EXEMPLE

PRETTY_HOSTNAME="Tablette de Lénart"
ICON_NAME=computer-tablet
CHASSIS=tablet
DEPLOYMENT=production
