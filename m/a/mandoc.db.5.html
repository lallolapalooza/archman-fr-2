MANDOC.DB(5) Manuel des formats de fichiers MANDOC.DB(5)

NOM

mandoc.db — base de données des pages de manuel

DESCRIPTION

Le format de fichier mandoc.db est utilisé pour stocker des informations sur les pages de manuel installées afin de faciliter la recherche sémantique de manuels. Chaque arborescence de pages de manuel contient son propre fichier mandoc.db ; voir FICHIERS pour des exemples.

Ces fichiers de base de données sont générés par makewhatis(8) et utilisés par man(1), apropos(1) et whatis(1).

Le format de fichier utilise trois types de données :

  • Nombres entiers signés de 32 bits en ordre d'octets big endian (réseau)
  • Chaînes de caractères terminées par NUL
  • Listes de chaînes de caractères terminées par NUL, terminées par un second caractère NUL

Les nombres sont alignés sur des frontières de quatre octets ; là où ils suivent des chaînes ou des listes de chaînes, un remplissage avec des caractères NUL supplémentaires se produit. Certains nombres, mais pas tous, pointent vers des positions dans le fichier. Ces pointeurs sont mesurés en octets, et le premier octet du fichier est considéré comme l'octet 0.

Chaque fichier est composé de :

  • Un nombre magique, 0x3a7d0cdb.
  • Un numéro de version, actuellement 1.
  • Un pointeur vers la table des macros.
  • Un pointeur vers le nombre magique final.
  • La table des pages (longueur variable).
  • La table des macros (longueur variable).
  • Le nombre magique une fois de plus, 0x3a7d0cdb.

La table des pages contient une entrée pour chaque fichier physique de page de manuel, quelle que soit le nombre de liens physiques ou symboliques qu'il puisse avoir dans le système de fichiers. La table des pages est composée de :

  • Le nombre de pages dans la base de données.
  • Pour chaque page :
    • Un pointeur vers la liste des noms.
    • Un pointeur vers la liste des sections.
    • Un pointeur vers la liste des architectures ou 0 si la page est indépendante de la machine.
    • Un pointeur vers la chaîne de description en une ligne.
    • Un pointeur vers la liste des noms de fichiers.
  • Pour chaque page, la liste des noms. Chaque nom est précédé d'un octet indiquant les sources du nom. La signification des bits est la suivante :
    • 0x10 : Le nom apparaît dans un nom de fichier.
    • 0x08 : Le nom apparaît dans une ligne d'en-tête, c'est-à-dire dans une macro .Dt ou .TH.
    • 0x04 : Le nom est le premier dans la ligne de titre, c'est-à-dire qu'il apparaît dans la première macro .Nm de la section NAME.
    • 0x02 : Le nom apparaît dans n'importe quelle macro .Nm de la section NAME.
    • 0x01 : Le nom apparaît dans un bloc .Nm de la section SYNOPSIS.
  • Pour chaque page, la liste des sections. Chaque section est donnée sous forme de chaîne de caractères, et non de nombre.
  • Pour chaque page dépendante de l'architecture, la liste des architectures.
  • Pour chaque page, la chaîne de description en une ligne tirée de la macro .Nd.
  • Pour chaque page, la liste des noms de fichiers relatifs à la racine du manpath respectif. Cette liste comprend les liens physiques, les liens symboliques et les liens simulés avec des requêtes .so de roff(7). Le premier nom de fichier est précédé d'un octet ayant la signification suivante :
    • FORM_SRC = 0x01 : Le format du fichier est mdoc(7) ou man(7).
    • FORM_CAT = 0x02 : La page de manuel est préformatée.
  • Zéro à trois octets NUL pour le remplissage.

La table des macros est composée de :

  • Le nombre de clés de macros différentes, actuellement 36. L'ordre des macros est défini dans <mansearch.h> et la signification des clés de macros est documentée dans apropos(1).
  • Pour chaque clé de macro, un pointeur vers la table de macros respective.
  • Pour chaque clé de macro, la table de macros (longueur variable).

Chaque table de macros est composée de :

  • Le nombre d'entrées dans la table.
  • Pour chaque entrée :
    • Un pointeur vers la valeur de la clé de macro. Chaque valeur est une chaîne de texte provenant d'une invocation de macro.
    • Un pointeur vers la liste des pages.
  • Pour chaque entrée, la valeur de la clé de macro.
  • Zéro à trois octets NUL pour le remplissage.
  • Pour chaque entrée, un ou plusieurs pointeurs vers des pages dans la table des pages, pointant vers le pointeur vers la liste des noms, suivi du nombre 0.

FICHIERS

/usr/share/man/mandoc.db
La base de données des pages de manuel pour le système de base.
/usr/X11R6/man/mandoc.db
Pareil pour le système de fenêtrage X(7).
/usr/local/man/mandoc.db
Pareil pour les packages(7).

Un programme permettant d'extraire les fichiers mandoc.db dans un format lisible par l'homme, adapté pour diff(1), est fourni dans le répertoire /usr/src/regress/usr.bin/mandoc/db/dbm_dump/.

VOIR AUSSI

apropos(1), man(1), whatis(1), makewhatis(8)

HISTORIQUE

Une base de données de pages de manuel /usr/lib/whatis est apparue pour la première fois dans 2BSD. Le format actuel est apparu pour la première fois dans OpenBSD 6.1.

AUTEURS

La version originale de makewhatis(8) a été écrite par Bill Joy en 1979. Le format de base de données actuel a été conçu par Ingo Schwarze <schwarze@openbsd.org> en 2016.
