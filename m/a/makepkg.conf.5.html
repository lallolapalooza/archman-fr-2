MAKEPKG.CONF(5) Manuel Pacman MAKEPKG.CONF(5)

NOM

makepkg.conf - fichier de configuration de makepkg

SYNTAXE

/etc/makepkg.conf, $XDG_CONFIG_HOME/pacman/makepkg.conf, ~/.makepkg.conf

DESCRIPTION

Les options de configuration pour makepkg sont stockées dans makepkg.conf. Ce fichier est sourcé, vous pouvez donc y inclure les indicateurs spéciaux du compilateur que vous souhaitez utiliser. Ceci est utile lors de la compilation pour différentes architectures ou avec différentes optimisations. Cependant, seules les variables décrites ci-dessous sont exportées dans l'environnement de compilation.


Note

Cela ne garantit pas que tous les Makefiles de paquets utiliseront vos variables exportées. Certains d'entre eux ne sont pas standard.

Le fichier de configuration système se trouve dans /etc/makepkg.conf. Des ajouts spécifiques (par exemple, des indicateurs de construction pour des langues supplémentaires) peuvent être placés dans /etc/makepkg.conf.d/*.conf.

Les options individuelles peuvent être remplacées (ou ajoutées) par utilisateur dans $XDG_CONFIG_HOME/pacman/makepkg.conf ou ~/.makepkg.conf, le premier ayant la priorité.

Le fichier par défaut est assez bien commenté, il peut donc être plus facile de suivre les instructions données pour la personnalisation.

OPTIONS

DLAGENTS=('protocole::/chemin/vers/commande [options]' ...)

Définit les agents de téléchargement utilisés pour récupérer les fichiers source spécifiés avec une URL dans le fichier PKGBUILD(5). Des options peuvent être spécifiées pour chaque commande, et n'importe quel protocole peut avoir un agent de téléchargement. Les espaces dans les arguments d'option doivent être échappés pour éviter qu'ils ne soient divisés. Plusieurs exemples sont fournis dans le makepkg.conf par défaut.

Si présent, %u sera remplacé par l'URL de téléchargement. Sinon, l'URL de téléchargement sera placée à la fin de la commande. Si présent, %o sera remplacé par le nom du fichier local, avec une extension “.part”, ce qui permet à makepkg de gérer la reprise des téléchargements de fichiers.

VCSCLIENTS=('protocole::paquet' ...)

Définit les paquets requis pour récupérer les fichiers source sous contrôle de version. Lorsque requis, makepkg vérifiera que ces paquets sont installés ou inclus dans les tableaux depends ou makedepends du PKGBUILD.

CARCH="carch"

Spécifie l'architecture de votre ordinateur ; les valeurs possibles incluent “i686”, “x86_64”, “ppc”, etc. Ceci devrait être défini automatiquement à l'installation.

CHOST="chost"

Une chaîne telle que “i686-pc-linux-gnu” ; ne touchez pas à cela à moins que vous ne sachiez ce que vous faites. La plupart des utilisateurs peuvent commenter ceci s'ils le souhaitent.

CPPFLAGS="cppflags"

Indicateurs utilisés pour le préprocesseur C ; voir CFLAGS pour plus d'informations.

CFLAGS="cflags"

Indicateurs utilisés pour le compilateur C. C'est une partie clé de l'utilisation de makepkg. Généralement, plusieurs options sont spécifiées, et la chaîne la plus courante ressemble à ceci : “-march=i686 -O2 -pipe”. Une autre option utile peut être -mcpu à la place de -march. Lisez gcc(1) pour plus de détails sur la large variété d'indicateurs de compilateur disponibles.

CXXFLAGS="cxxflags"

Indicateurs utilisés pour le compilateur C++ ; voir CFLAGS pour plus d'informations.

LDFLAGS="ldflags"

Indicateurs utilisés pour l'éditeur de liens. Plusieurs options peuvent être spécifiées avec une utilisation courante ressemblant à “-Wl,--hash-style=gnu”. Lisez ld(1) pour plus de détails sur les indicateurs de l'éditeur de liens disponibles.

LTOFLAGS="ltoflags"

Indicateurs supplémentaires du compilateur et de l'éditeur de liens ajoutés à CFLAGS, CXXFLAGS et LDFLAGS lors de la compilation avec optimisation au moment de l'édition des liens. Si vide, “-flto” est utilisé.

MAKEFLAGS="makeflags"

Ceci est souvent utilisé pour définir le nombre de tâches utilisées ; par exemple, -j2. D'autres indicateurs que make accepte peuvent également être passés.

DEBUG_CFLAGS="debug_cflags"

Indicateurs de compilation supplémentaires ajoutés à CFLAGS pour le débogage. Habituellement, cela inclurait : “-g”. Lisez gcc(1) pour plus de détails sur la large variété d'indicateurs de compilation disponibles.

DEBUG_CXXFLAGS="debug_cxxflags"

Indicateurs de débogage utilisés pour le compilateur C++ ; voir DEBUG_CFLAGS pour plus d'informations.

BUILDENV=(!distcc !color !ccache check !sign)

Ce tableau contient des options qui affectent l'environnement de construction ; les valeurs par défaut sont présentées ici. Toutes les options doivent toujours rester dans le tableau ; pour activer ou désactiver une option, retirez simplement ou ajoutez un “!” au début de l'option. Si une option est spécifiée plusieurs fois, la dernière valeur prend le dessus. Chaque option fonctionne comme suit :

distcc

Utilise le compilateur distribué C/C++/ObjC pour répartir la compilation entre plusieurs machines. Si cette option est activée, DISTCC_HOSTS doit également être spécifié.

color

Colore les messages de sortie, rendant la sortie plus facile à lire.

ccache

Utilise ccache pour mettre en cache la compilation par défaut. Cela permet des compilations plus rapides si vous recompilez continuellement les mêmes paquets. Cela peut être désactivé pour des paquets individuels en plaçant !ccache dans le tableau d'options du PKGBUILD.

check

Exécute la fonction check() si elle est présente dans le PKGBUILD. Cela peut être activé ou désactivé pour des paquets individuels grâce aux options --check et --nocheck de makepkg, respectivement.

sign

Génère un fichier de signature PGP en utilisant GnuPG. Cela exécutera gpg --detach-sign sur le paquet construit pour générer un fichier de signature détachée, en utilisant l'agent GPG, s'il est disponible. Le fichier de signature sera le nom de fichier complet du paquet avec une extension “.sig”.

DISTCC_HOSTS="hôte1 ..."

Si vous utilisez DistCC, ceci est utilisé pour spécifier une liste d'hôtes séparés par des espaces fonctionnant dans le cluster DistCC. De plus, vous voudrez modifier vos MAKEFLAGS.

BUILDDIR="/chemin/vers/répertoire"

Si cette valeur n'est pas définie, les paquets seront, par défaut, construits dans des sous-répertoires du répertoire à partir duquel makepkg est appelé. Cette option permet de définir l'emplacement de construction vers un autre répertoire. Une utilisation incorrecte de $startdir dans un PKGBUILD peut entraîner l'échec de la construction avec cette option.

GPGKEY=""

Spécifie une clé à utiliser pour la signature GPG au lieu de la clé par défaut du trousseau. Peut être remplacée par l'option --key de makepkg.

OPTIONS=(!strip docs libtool staticlibs emptydirs ...)

Ce tableau contient des options qui affectent l'empaquetage par défaut. Elles sont équivalentes aux options qui peuvent être placées dans le PKGBUILD ; les valeurs par défaut sont présentées ici. Toutes les options doivent toujours rester dans le tableau ; pour activer ou désactiver une option, retirez simplement ou ajoutez un “!” au début de l'option. Si une option est spécifiée plusieurs fois, la dernière valeur prend le dessus. Chaque option fonctionne comme suit :

strip

Supprime les symboles des binaires et des bibliothèques. Si vous utilisez fréquemment un débogueur sur des programmes ou des bibliothèques, il peut être utile de désactiver cette option.

docs

Sauvegarde les répertoires de documentation. Si vous souhaitez supprimer les répertoires de documentation, spécifiez !docs dans le tableau. Les répertoires affectés sont spécifiés par la variable DOC_DIRS.

libtool

Laisse les fichiers libtool (.la) dans les paquets. Spécifiez !libtool pour les supprimer.

staticlibs

Laisse les fichiers de bibliothèque statique (.a) dans les paquets. Spécifiez !staticlibs pour les supprimer, s'ils ont un homologue partagé.

emptydirs

Laisse les répertoires vides dans les paquets.

zipman

Compresse les pages de manuel (man et info) avec gzip. Les répertoires affectés sont spécifiés par la variable MAN_DIRS.

purge

Supprime les fichiers spécifiés par la variable PURGE_TARGETS du paquet.

debug

Ajoute les indicateurs de débogage spécifiés par l'utilisateur

ags tels que spécifiés dans DEBUG_CFLAGS et DEBUG_CXXFLAGS à leurs drapeaux de compilation correspondants. Crée un paquet séparé contenant les symboles de débogage lorsqu'il est utilisé avec ‘strip’.

lto

Active la compilation des paquets à l'aide de l'optimisation au moment de l'édition des liens. Ajoute les drapeaux spécifiés dans LTOFLAGS à CFLAGS, CXXFLAGS et LDFLAGS (ou “-flto” si LTOFLAGS est vide).

autodeps

Active l'ajout automatique de bibliothèques aux tableaux depends et provides. Les répertoires de recherche des bibliothèques sont contrôlés par la variable LIB_DIRS définie ci-dessous.

INTEGRITY_CHECK=(check1 ...)

Vérifications d'intégrité des fichiers à utiliser. Plusieurs vérifications peuvent être spécifiées ; cela affecte à la fois la génération et la vérification. Les options valides actuelles sont : ck, md5, sha1, sha224, sha256, sha384, sha512 et b2.

STRIP_BINARIES="--strip-all"

Options à utiliser lors de la suppression des binaires. Voir strip(1) pour les détails.

STRIP_SHARED="--strip-unneeded"

Options à utiliser lors de la suppression des bibliothèques partagées ou des exécutables PIE. Voir strip(1) pour les détails.

STRIP_STATIC="--strip-debug"

Options à utiliser lors de la suppression des bibliothèques statiques. Voir strip(1) pour les détails.

MAN_DIRS=({usr{,/local}{,/share},opt/*}/{man,info} ...)

Si zipman est spécifié dans le tableau OPTIONS, cette variable indiquera à makepkg où chercher pour compresser les pages de manuel (man et info). Si vous compilez des paquets situés dans opt/, vous pourriez avoir besoin d'ajouter le répertoire à ce tableau. NOTE : N'ajoutez pas la barre oblique initiale au nom du répertoire.

DOC_DIRS=(usr/{,share/}{doc,gtk-doc} ...)

Si !docs est spécifié dans le tableau OPTIONS, cette variable indiquera à makepkg où chercher pour supprimer les documentations. Si vous compilez des paquets situés dans opt/, vous pourriez avoir besoin d'ajouter le répertoire à ce tableau. NOTE : N'ajoutez pas la barre oblique initiale au nom du répertoire.

LIB_DIRS=(lib:usr/lib ...)

Si autodeps est spécifié dans le tableau OPTIONS, cette variable indiquera à makepkg où chercher les bibliothèques à ajouter au tableau provides. Le format est « préfixe:chemin », où provides sera ajouté pour les bibliothèques trouvées dans « chemin » avec le préfixe spécifié ajouté.

PURGE_TARGETS=(usr/{,share}/info/dir .podlist *.pod...)

Si purge est spécifié dans le tableau OPTIONS, cette variable indiquera à makepkg quels fichiers supprimer du paquet. Ceci est utile pour les fichiers d'index ajoutés par plusieurs paquets.

DBGSRCDIR="/usr/src/debug"

Si strip et debug sont spécifiés dans le tableau OPTIONS, cette variable indiquera à makepkg où placer les fichiers sources des binaires installés. Les binaires seront modifiés pour lier ce répertoire pour le chemin de recherche du débogueur.

PKGDEST="/chemin/vers/repertoire"

Si cette valeur n'est pas définie, les paquets seront, par défaut, placés dans le répertoire courant (l'emplacement du PKGBUILD(5)). Beaucoup de gens aiment garder tous leurs paquets au même endroit, cette option permet ce comportement. Un emplacement courant est “/home/packages”.

SRCDEST="/chemin/vers/repertoire"

Si cette valeur n'est pas définie, les fichiers sources téléchargés ne seront stockés que dans le répertoire courant. Beaucoup de gens aiment garder tous les fichiers sources dans un emplacement central pour un nettoyage facile, donc ce chemin peut être défini ici.

SRCPKGDEST="/chemin/vers/repertoire"

Si cette valeur n'est pas définie, les fichiers de paquets sources seront stockés dans le répertoire courant. Beaucoup de gens aiment garder tous les fichiers de paquets sources dans un emplacement central pour un nettoyage facile, donc ce chemin peut être défini ici.

LOGDEST="/chemin/vers/repertoire"

Si cette valeur n'est pas définie, les fichiers journaux sont écrits dans le répertoire courant. Cela centralise l'emplacement des journaux, facilitant le nettoyage et la compression.

PACKAGER="John Doe <john@example.com>"

Cette valeur est utilisée lors de l'interrogation d'un paquet pour savoir qui était le constructeur. Le format donné est requis pour la recherche de clé PGP via WKD. Il est recommandé de la changer pour votre nom et votre adresse e-mail.

COMPRESSGZ="(gzip -c -f -n)", COMPRESSBZ2="(bzip2 -c -f)", COMPRESSXZ="(xz -c -z -)", COMPRESSZST="(zstd -c -z -)", COMPRESSLZO"(lzop -q)", COMPRESSLRZ="(lrzip -q)", COMPRESSLZ4="(lz4 -q)", COMPRESSZ="(compress -c -f)", COMPRESSLZ="(lzip -c -f)"

Définit la commande et les options utilisées lors de la compression des paquets compilés ou sources dans le format nommé.

PKGEXT=".pkg.tar.gz", SRCEXT=".src.tar.gz"

Définit la compression utilisée lors de la création de paquets compilés ou sources. Les suffixes valides sont .pkg ou .src (pour PKGEXT et SRCEXT respectivement) suivis de l'un des suffixes .tar.gz, .tar.bz2, .tar.xz, .tar.zst, .tar.lzo, .tar.lrz, .tar.lz4, .tar.lz et .tar.Z, ou simplement .tar pour désactiver la compression entièrement.

PACMAN_AUTH=()

Spécifie un préfixe de commande pour exécuter pacman en tant que root. Si non défini, makepkg vérifiera la présence de sudo(8) et su(1) à tour de rôle, et essaiera le premier qu'il trouve.

Si présent, %c sera remplacé par la forme citée par le shell de la commande à exécuter. Sinon, la commande à exécuter sera ajoutée à la commande auth.

Bogues ? Vous vous moquez de nous ; il n'y a pas de bogues dans ce logiciel.
