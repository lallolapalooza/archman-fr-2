NOM

makeindex - un processeur d'index généraliste indépendant du formateur

SYNOPIS

makeindex [-c] [-g] [-i] [-l] [-o ind] [-p num] [-q] [-r] [-s sfile] [-t log] [-L] [-T] [idx0 idx1 idx2...]

DESCRIPTION

Le programme makeindex est un générateur d'index hiérarchique généraliste ; il accepte un ou plusieurs fichiers d'entrée (souvent produits par un formateur de texte tel que TeX (tex(1L)) ou troff(1), trie les entrées et produit un fichier de sortie qui peut être formaté. L'index peut avoir jusqu'à trois niveaux (0, 1 et 2) d'imbrication de sous-éléments. La façon dont les mots sont signalés pour l'indexation dans le document principal est spécifique au formateur utilisé ; makeindex n'automatise pas le processus de sélection de ces mots. Comme l'index de sortie est hiérarchique, makeindex peut être considéré comme un complément au système make.index(1L) basé sur awk(1) de Bentley et Kernighan, qui est spécifique à troff(1), génère des index non hiérarchiques et emploie une syntaxe beaucoup plus simple pour indiquer les entrées d'index. Pour une illustration de l'utilisation avec troff et TeX, voir la section EXEMPLES ci-dessous.

Les formats des fichiers d'entrée et de sortie sont spécifiés dans un fichier de style ; par défaut, l'entrée est supposée être un fichier .idx, tel que généré par LaTeX.

Sauf indication explicite, le nom de base du premier fichier d'entrée (idx0) est utilisé pour déterminer les noms des autres fichiers. Pour chaque nom de fichier d'entrée spécifié, un fichier de ce nom est recherché. Si ce fichier n'est pas trouvé et que le nom de fichier n'a pas d'extension, l'extension .idx est ajoutée. Si aucun fichier portant ce nom n'est trouvé, makeindex s'arrête.

Si un seul fichier d'entrée a été fourni et qu'aucun fichier de style explicite n'a été spécifié avec -s, makeindex utilise un fichier avec l'extension .mst comme fichier de style par défaut (lorsqu'il est présent).

Pour des notes importantes sur la façon de sélectionner les mots-clés d'index, voir le document de Lamport cité ci-dessous. En dehors de la sélection des mots-clés d'index, un mécanisme systématique pour placer les termes d'index dans un document est suggéré dans Index Preparation and Processing, un article cité ci-dessous.

OPTIONS

-c
Compresse les espaces intermédiaires (en ignorant les espaces et tabulations en début et fin de ligne). Par défaut, les espaces dans la clé d'index sont conservés.
-g
Utilise l'ordre alphabétique allemand dans l'index, conformément aux règles définies dans la norme DIN 5007. Par défaut, makeindex utilise un ordre alphabétique où la priorité est la suivante : symboles, nombres, lettres majuscules, lettres minuscules. La séquence dans l'ordre alphabétique allemand est : symboles, lettres minuscules, lettres majuscules, nombres. De plus, cette option permet à makeindex de reconnaître les commandes TeX allemandes {"a, "o, "u et "s} comme {ae, oe, ue et ss} lors du tri des entrées. Le caractère guillemet doit être redéfini dans un fichier de style (par exemple, redéfinir quote comme '+'). Si le caractère guillemet n'est pas redéfini, makeindex produira un message d'erreur et s'arrêtera.
-i
Prend l'entrée depuis stdin. Lorsque cette option est spécifiée et que -o ne l'est pas, la sortie est écrite sur stdout.
-l
Ordre alphabétique des lettres ; par défaut, l'ordre par mot est utilisé (voir la section ORDRE).
-o ind
Utilise ind comme fichier d'index de sortie. Par défaut, le nom de fichier est créé en ajoutant l'extension .ind au nom de base du premier fichier d'entrée (idx0).
-p num
Définit le numéro de page de départ du fichier d'index de sortie à num (utile lorsque le fichier d'index doit être formaté séparément). L'argument num peut être numérique ou l'un des éléments suivants :
any
La page de départ est le dernier numéro de page source plus 1.
odd
La page de départ est la première page impaire suivant le dernier numéro de page source.
even
La page de départ est la première page paire suivant le dernier numéro de page source.
Le dernier numéro de page source est obtenu en recherchant en arrière dans le fichier journal la première occurrence d'un nombre inclus dans des crochets carrés ([...]). Si un numéro de page est manquant ou si le fichier journal n'est pas trouvé, aucune tentative ne sera faite pour définir le numéro de page de départ. Le nom du fichier journal source est déterminé en ajoutant l'extension .log au nom de base du premier fichier d'entrée (idx0).
-q
Mode silencieux ; n'envoie aucun message à stderr. Par défaut, les messages de progression et d'erreur sont envoyés à stderr ainsi qu'au fichier de transcription.
-r
Désactive la formation implicite de plages de pages ; les plages de pages doivent être créées en utilisant des opérateurs de plage explicites ; voir EFFETS SPÉCIAUX ci-dessous. Par défaut, trois pages ou plus successives sont automatiquement abrégées sous forme de plage (par exemple, 1 à 5).
-s sty
Utilise sty comme fichier de style (pas de défaut). La variable d'environnement INDEXSTYLE définit le chemin où le fichier de style doit être trouvé.
-t log
Utilise log comme fichier de transcription. Par défaut, le nom de fichier est créé en ajoutant l'extension .ilg au nom de base du premier fichier d'entrée (idx0).
-L
Tri basé sur les paramètres régionaux. Non disponible sur tous les systèmes.
-T
Support spécial pour les documents thaïlandais. Non disponible sur tous les systèmes.

FICHIER DE STYLE

Le fichier de style informe makeindex sur le format des fichiers d'entrée .idx et le format souhaité du fichier de sortie final ; des exemples apparaissent ci-dessous. Ce fichier peut résider n'importe où dans le chemin défini par la variable d'environnement INDEXSTYLE. Le fichier de style contient une liste de paires <spécificateur, attribut>. Il existe deux types de spécificateurs : entrée et sortie. Les paires n'ont pas à apparaître dans un ordre particulier. Une ligne commençant par `%` est un commentaire. Dans la liste suivante des spécificateurs et des arguments, <string> est une chaîne arbitraire délimitée par des guillemets doubles ("..."), <char> est une seule lettre entre apostrophes ('...'), et <number> est un entier non négatif. La longueur maximale d'une <string> est de 2048. Un backslash littéral ou un guillemet doit être échappé (par un backslash). Tout ce qui n'est pas spécifié dans le fichier de style se verra attribuer une valeur par défaut, qui est indiquée en haut de la colonne la plus à droite.

EXEMPLES

EXEMPLE TeX

L'exemple suivant montre un fichier de style appelé book.ist, qui définit un index pour un livre qui peut être formaté indépendamment de la source principale :

preamble
"\\documentstyle[12pt]{book}
\\begin{document}
\\begin{theindex}
{\\small\n"
postamble
"\n\n}
\\end{theindex}
\\end{document}\n"

En supposant qu'un style de livre particulier exige que l'index (ainsi que tous les chapitres) commence à un numéro de page impair, et que le fichier d'entrée s'appelle foo.idx, la commande suivante produit une sortie dans le fichier footmp.ind :

makeindex -s book.ist -o footmp.ind -p odd foo

Ici, un nom de fichier de sortie non par défaut est utilisé pour éviter d'écraser la sortie du livre lui-même (probablement foo.dvi, qui aurait été le nom par défaut pour le fichier de sortie de l'index !).

CRÉATION DU FICHIER INDEX DANS LE SHELL BOURNE

Pour créer un fichier d'entrée pour makeindex, dans l'environnement du shell Bourne, exécutez l'équivalent sur votre site de la commande :

psroff -ms -Tpsc -t sample.txt > /dev/null 2> sample.tmp

Certains sites nécessiteront ditroff au lieu de psroff. Pour filtrer les éventuels messages d'erreur réels, invoquez grep(1) :

grep '^IX: ' sample.tmp > sample.idx

CRÉATION DU FICHIER INDEX UTILISANT LE TROFF/TRANSCRIPT AMÉLIORÉ DE L'UCSF

Avec le troff/TRANSCRIPT amélioré de l'UCSF, l'option -I de psroff(1L) peut produire à la fois la sortie du formatteur et un fichier d'index :

psroff -ms -I sample.inp -Tpsc sample.txt

Si l'on souhaite supprimer la sortie du formatteur :

psroff -ms -I sample.inp -Tpsc -t sample.txt > /dev/null

ACHÈVEMENT DE L'INDEX

Toutes les procédures ci-dessus laissent l'entrée pour makeindex dans sample.inp. L'étape suivante consiste à invoquer makeindex :

makeindex -s sample.ist sample.idx

Cela laisse une sortie prête pour troff(1) dans le fichier sample.ind.

TRI

Par défaut, makeindex suppose le tri par mot ; si l'option -l est active, le tri par lettre est utilisé. Dans le tri par mot, un espace précède chaque lettre de l'alphabet, tandis que dans le tri par lettre, il n'est pas du tout pris en compte. Ceci est illustré par l'exemple suivant :

ordre par mot ordre par lettre
sea lion seal
seal sea lion

Les nombres sont toujours triés par ordre numérique. Par exemple,

9 (neuf), 123
10 (dix), voir Derek, Bo

Les lettres sont d'abord triées sans tenir compte de la casse ; lorsque les mots sont identiques, la version en majuscules précède sa contrepartie en minuscules.

Un symbole spécial est défini ici comme tout caractère ne figurant pas dans l'union des chiffres et des caractères alphabétiques anglais. Les motifs commençant par des symboles spéciaux précèdent les nombres, qui précèdent les motifs commençant par des lettres. À titre de cas spécial, une chaîne commençant par un chiffre mais mêlée de non-chiffres est considérée comme un motif commençant par un caractère spécial.

EFFETS SPÉCIAUX

Des entrées telles que

\indexentry{alpha}{1}
\indexentry{alpha!beta}{3}
\indexentry{alpha!beta!gamma}{10}

dans le fichier d'entrée seront converties en

\item alpha, 1
   \subitem beta, 3
      \subsubitem gamma, 10

dans le fichier d'index de sortie. Remarquez que le symbole de niveau ('!') est utilisé ci-dessus pour délimiter les niveaux hiérarchiques.

Il est possible de faire apparaître un élément sous une forme désignée en utilisant l'opérateur actual ('@'). Par exemple,

\indexentry{alpha@{\it alpha\/}}{1}

deviendra

\item {\it alpha\/}, 1

après traitement. Le motif précédant '@' est utilisé comme clé de tri, tandis que celui qui le suit est écrit dans le fichier de sortie. Notez que deux apparitions de la même clé, l'une avec et l'autre sans l'opérateur actual, sont considérées comme des entrées distinctes.

Les champs élément, sous-élément et sous-sous-élément peuvent avoir des clés de tri individuelles :

\indexentry{aa@{\it aa\/}!bb@{\it bb\/}!cc@{\it cc\/}}{1}

Cela sera converti en

\item {\it aa}, 1
   \subitem {\it bb}, 3
      \subsubitem {\it cc}, 10

Il est possible d'encapsuler un numéro de page avec une commande désignée en utilisant l'opérateur encap ('|') :

\indexentry{alpha|bold}{1}

sera converti en

\item alpha, \bold{1}

où, avec une définition appropriée pour TeX, \bold{n} se développera en {\bf n}. Dans cet exemple, les trois attributs de sortie associés à l'encapsulation de page encap_prefix, encap_infix et encap_suffix correspondent respectivement à la barre oblique inverse, à l'accolade ouvrante et à l'accolade fermante. Ce mécanisme permet de définir les numéros de page dans différentes polices. Par exemple, la page où apparaît la définition d'un mot-clé peut être dans une police, l'emplacement d'un exemple primaire dans une autre police, et les autres apparitions dans une troisième police.

L'opérateur encap peut également être utilisé pour créer des renvois dans l'index :

\indexentry{alpha|see{beta}}{1}

deviendra

\item alpha, \see{beta}{1}

dans le fichier de sortie, où

\see{beta}{1}

se développera en

{\it see\/} beta

Notez que dans un tel renvoi, le numéro de page disparaît.

Une paire de encap concaténés avec range_open ('|(') et range_close ('|)') crée une plage de pages explicite :

\indexentry{alpha|(}{1}
\indexentry{alpha|)}{5}

deviendra

\item alpha, 1—5

Les pages intermédiaires indexées par la même clé seront fusionnées dans la plage implicitement. Ceci est particulièrement utile lorsqu'une section entière sur un sujet particulier doit être indexée, auquel cas seuls les opérateurs d'ouverture et de fermeture de plage doivent être insérés au début et à la fin de la section. La formation explicite de plage de pages peut également inclure une commande supplémentaire pour définir la plage de pages dans une police désignée :

\indexentry{alpha|(bold}{1}
\indexentry{alpha|)}{5}

deviendra

\item alpha, \bold{1--5}

Plusieurs problèmes potentiels méritent d'être mentionnés. Premièrement, des entrées telles que

\indexentry{alpha|(}{1}
\indexentry{alpha|bold}{3}
\indexentry{alpha|)}{5}

seront interprétées comme

\item alpha, \bold{3}, 1--5

mais avec un message d'avertissement dans la transcription concernant la rencontre d'un encapsuleur de page incohérent. Une plage explicite commençant par un numéro de page romain et se terminant par un arabe est également considérée comme une erreur. Dans ce cas, (si possible) la plage est divisée en deux sous-plages, l'une en romain et l'autre en arabe. Par exemple,

\indexentry{alpha|(}{i}
\indexentry{alpha}{iv}
\indexentry{alpha}{3}
\indexentry{alpha|)}{7}

sera transformé en

\item alpha, i--iv, 3--7

makeindex(1) - man page

NAME

makeindex — a database program for processing LaTeX, grap, soe, and Makefiles index files

SYNOPSIS

makeindex [-i] [-o] [-g] [-l] [-s stylefile] [-t transcriptfile] [-e epsilon] [-E] [-c] [-C] [-F] [-q] [-Q] [-r] [-h] [-V] [inputfile(s)]

DESCRIPTION

The program makeindex is a general purpose index creation utility. Given an input file, it rearranges the information and outputs it in a format suitable for inclusion in a LaTeX, grap, soe, or Makefile document. The input file is usually generated by the macro package of the document preparation system in use.

The program sorts the index entries according to the rules specified in a style file. The sorted entries are then written to an output file, which is typically named output.ind. The default name for the transcript file is output.ilg.

The program processes inputfiles that are specified on the command line. If no input files are specified, makeindex reads from standard input.

The default input file extension is .idx.

OPTIONS

makeindex recognizes the following command-line options:

-i
Input is a madeindex (grap) style index file.
-o
Input is a soe style index file.
-g
Input is a grap style index file.
-l
Input is a LaTeX index file.
-s stylefile
Use the style commands in stylefile to determine the sorting order and the output format. The default style file is named mexico.mst.
-t transcriptfile
Use transcriptfile for the transcript file, rather than the default name output.ilg.
-e epsilon
Use epsilon as the page number delimiter rather than the default hyphen (-). This option is used for composite page numbers.
-E
Treat the page number delimiter character as a printable character rather than a delimiter for composite page numbers.
-c
Make a pagkaged index. The program first checks for duplicate page entries and then merges them.
-C
Make a compact index. Duplicate page number entries are merged.
-F
Format the index for the plain TeX macro package.
-q
Quote all special characters. This is the default behavior for LaTeX.
-Q
Do not quote any special characters. This is the default behavior for plain TeX.
-r
Make an raw index. The program does not perform any special character processing.
-h
Print a help message and exit.
-V
Print version information and exit.

STYLE FILE

The style file is used to specify the sorting order and the output format for the index. The default style file is named mexico.mst. The style file contains commands that are interpreted by makeindex.

The following commands are recognized in the style file:

preamble
Text to be printed before the index.
postamble
Text to be printed after the index.
setpagecompositor char
Use char as the page number delimiter. The default is -.
setdelim delim
Use delim as the field delimiter. The default is @.
define-charclass name character(s)
Define a character class named name. The characters in the class are specified as a sequence of characters or ranges.
define-sort-order class1 class2 ...
Define the sort order of character classes. The classes are listed in order of precedence.
headings class1 class2 ...
Specify the headings to be used for each character class. The headings are specified as strings.

The style file also contains directives for formatting the index entries. These directives are typically TeX commands that are inserted into the output file.

EXAMPLES

The following example shows how to create an index for a LaTeX document:

\documentclass{article}
\usepackage{makeidx}
\makeindex
\begin{document}
\index{first}
\index{second}
\index{third}
\printindex
\end{document}

This will create an index file named .idx containing the following entries:

\indexentry{first}{1}
\indexentry{second}{1}
\indexentry{third}{1}

Running makeindex on this file will produce an output file named .ind containing the formatted index.

ORDERING

The sorting order of the index entries is determined by the style file. The default sorting order is based on the ASCII values of the characters.

The style file can be used to specify a custom sorting order for different languages or character sets.

SPECIAL EFFECTS

The following special characters have significance in index entries:

quote
The quote operator (`"') is used to quote special characters. For example, \indexentry{alpha"@beta}{1} will be processed as alpha@beta.
escape
The escape operator (`\') can be used to escape the quote operator. For example, \indexentry{f\"ur}{1} will be processed as f"ur, which represents an umlaut-accented `u' in TeX.
page_compositor
The page_compositor operator (`-') is used to separate fields in composite page numbers. For example, II-12 represents page 12 of Chapter II.

Since version 2.11 of makeindex, the quote operator may quote any character in the range 1 ... 255. Character 0 is excluded because it is used internally as a string terminator.

The sorting order is:

punctuation characters (in ASCII order),
digits,
control characters (1 ... 31),
space (32),
letters (ignoring case),
characters 127 ... 255.

Here is an example showing the indexing of all printable ASCII characters other than letters and digits, assuming the default TeX format. For convenience, the page number references are the corresponding ASCII ordinal values.

\indexentry{" @"  (space)}{32}
\indexentry{"!@"! (exclamation point)}{33}
\indexentry{""@"" (quotation mark)}{34}
\indexentry{"#@"\# (sharp sign)}{35}
\indexentry{"$@"\$ (dollar sign)}{36}
\indexentry{"%@"\% (percent sign)}{37}
\indexentry{"&@"\& (ampersand)}{38}
\indexentry{"<@"$<$ (left angle bracket)}{60}
\indexentry{"=@"= (equals)}{61}
\indexentry{">@"$>$ (right angle bracket)}{62}
\indexentry{"?@"? (query)}{63}
\indexentry{"@@"@ (at sign)}{64}
\indexentry{"[@"[ (left square bracket)}{91}
\indexentry{"\@"\verb=\= (backslash)}{92}
\indexentry{"]@"] (right square bracket)}{93}
\indexentry{"^@"\verb=^= (caret)}{94}
\indexentry{"_@"\verb=_= (underscore)}{95}
\indexentry{"`@"\verb=~= (grave accent)}{96}
\indexentry{"{@"\"{ (left brace)}{123}
\indexentry{"|@"\verb="|= (vertical bar)}{124}
\indexentry{"}@"\"} (right brace)}{125}
\indexentry{"~@"\verb=~= (tilde)}{126}

Characters in the actual fields following the `@' character which have special significance to TeX must be represented as control sequences, or as math mode characters. Note particularly how the entries for the at sign, left and right braces, and the vertical bar, are coded. The index file output by makeindex for this example looks like this:

\begin{theindex}
  \item ! (exclamation point), 33
  \item " (quotation mark), 34
  \item \# (sharp sign), 35
  \item \$ (dollar sign), 36
  \item \% (percent sign), 37
  \item \& (ampersand), 38
  \item $<$ (left angle bracket), 60
  \item = (equals), 61
  \item $>$ (right angle bracket), 62
  \item ? (query), 63
  \item @ (at sign), 64
  \item [ (left square bracket), 91
  \item \verb=\= (backslash), 92
  \item ] (right square bracket), 93
  \item \verb=^= (caret), 94
  \item \verb=_= (underscore), 95
  \item \verb=~= (grave accent), 96
  \item \{ (left brace), 123
  \item \verb=|= (vertical bar), 124
  \item \} (right brace), 125
  \item \verb=~= (tilde), 126
  \indexspace
  \item   (space), 32
\end{theindex}
