__malloc_hook(3) Manuel des fonctions de bibliothèque __malloc_hook(3)

NOM

__malloc_hook, __malloc_initialize_hook, __memalign_hook, __free_hook, __realloc_hook, __after_morecore_hook - Variables de débogage malloc (OBSOLÈTE)

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <malloc.h>
typeof(void *(size_t size, const void *caller))
    *volatile  __malloc_hook;
typeof(void *(void *p, size_t size, const void *caller))
    *volatile  __realloc_hook;
typeof(void *(size_t align, size_t size, const void *caller))
    *volatile  __memalign_hook;
typeof(void *(void *p, const void *caller))
    *volatile  __free_hook;
typeof(void (void))            *__malloc_initialize_hook;
typeof(void (void)) *volatile   __after_mrecore_hook;

DESCRIPTION

La bibliothèque C GNU vous permet de modifier le comportement de malloc(3), realloc(3), et free(3) en spécifiant des fonctions de crochet appropriées. Vous pouvez utiliser ces crochets pour vous aider à déboguer des programmes qui utilisent l'allocation de mémoire dynamique, par exemple.

La variable __malloc_initialize_hook pointe vers une fonction qui est appelée une seule fois lorsque l'implémentation de malloc est initialisée. Il s'agit d'une variable faible (weak), elle peut donc être remplacée dans l'application par une définition comme celle-ci :


typeof(void (void))  *__malloc_initialize_hook = my_init_hook;

Maintenant, la fonction my_init_hook() peut effectuer l'initialisation de tous les crochets.

Les quatre fonctions pointées par __malloc_hook, __realloc_hook, __memalign_hook, __free_hook ont un prototype similaire aux fonctions malloc(3), realloc(3), memalign(3), free(3), respectivement, à la différence qu'elles ont un argument final caller qui donne l'adresse de l'appelant de malloc(3), etc.

La variable __after_morecore_hook pointe vers une fonction qui est appelée chaque fois après que sbrk(2) a été appelé pour obtenir plus de mémoire.

NORMES

GNU.

NOTES

L'utilisation de ces fonctions de crochet n'est pas sûre dans les programmes multithreadés, et elles sont maintenant obsolètes. À partir de glibc 2.24, la variable __malloc_initialize_hook a été supprimée de l'API, et à partir de glibc 2.34, toutes les variables de crochet ont été supprimées de l'API. Les programmeurs devraient plutôt intercepter les appels aux fonctions pertinentes en définissant et en exportant malloc(), free(), realloc(), et calloc().

EXEMPLES

Voici un bref exemple d'utilisation de ces variables.

#include <stdio.h>
#include <malloc.h>
/* Prototypes pour nos crochets */
static void my_init_hook(void);
static void *my_malloc_hook(size_t, const void *);
/* Variables pour sauvegarder les crochets originaux */
static typeof(void *(size_t, const void *))  *old_malloc_hook;
/* Remplacer le crochet d'initialisation de la bibliothèque C */
typeof(void (void))  *__malloc_initialize_hook = my_init_hook;
static void
my_init_hook(void)
{
    old_malloc_hook = __malloc_hook;
    __malloc_hook = my_malloc_hook;
}
static void *
my_malloc_hook(size_t size, const void *caller)
{
    void *result;
    /* Restaurer tous les anciens crochets */
    __malloc_hook = old_malloc_hook;
    /* Appeler récursivement */
    result = malloc(size);
    /* Sauvegarder les crochets sous-jacents */
    old_malloc_hook = __malloc_hook;
    /* printf() peut appeler malloc(), le protéger aussi */
    printf("malloc(%zu) appelé depuis %p retourne %p\n",
            size, caller, result);
    /* Restaurer nos propres crochets */
    __malloc_hook = my_malloc_hook;
    return result;
}
