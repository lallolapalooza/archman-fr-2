MAIRIXRC(5) Manuel des formats de fichiers MAIRIXRC(5)

NOM

mairixrc - fichier de configuration pour mairix(1)

SYNTAXE

$HOME/.mairixrc

DESCRIPTION

Le fichier mairixrc indique à mairix où se trouvent vos dossiers de courrier. Il indique également à mairix où les résultats des recherches doivent être écrits.

mairix recherche ce fichier à l'emplacement $HOME/.mairixrc sauf si l'option -f est utilisée.

Les directives base, mfolder et database doivent toujours apparaître dans le fichier. Il doit également y avoir des définitions de dossiers (en utilisant les directives maildir, mh ou mbox).

Commentaires

Toute ligne commençant par un caractère '#' est traitée comme un commentaire.

Directives

base=répertoire-de-base

Définit le chemin d'accès au répertoire parent commun de tous vos dossiers maildir.
imap_server=nom-hôte

Si des dossiers sources IMAP sont spécifiés ou si le dossier de résultats est un dossier IMAP, ceci définit le nom d'hôte du serveur IMAP. Le port est actuellement toujours 143. Cette option est mutuellement exclusive avec l'option 'imap_pipe'.
imap_pipe=commande-shell

Si des dossiers sources IMAP sont spécifiés ou si le dossier de résultats est un dossier IMAP, ceci définit une commande shell qui peut être utilisée pour se connecter au serveur IMAP et communiquer avec lui via des pipes UNIX au lieu d'une connexion TCP/IP. Cette option est mutuellement exclusive avec l'option 'imap_server'.
imap_username=nom-utilisateur

Si des dossiers sources IMAP sont spécifiés ou si le dossier de résultats est un dossier IMAP, ceci définit le nom d'utilisateur à utiliser pour se connecter au serveur IMAP. Ce paramètre est facultatif, mais les serveurs IMAP exigent normalement que les clients se connectent, il est donc normalement nécessaire de le spécifier. Un exemple de cas où il n'est pas requis est si l'option 'imap_pipe' est utilisée et que la commande shell établit une connexion avec un serveur IMAP dans un état pré-authentifié.
imap_password=mot-de-passe

Si des dossiers sources IMAP sont spécifiés ou si le dossier de résultats est un dossier IMAP, ceci définit le mot de passe à utiliser pour se connecter au serveur IMAP. Ce paramètre est facultatif, mais les serveurs IMAP exigent normalement que les clients se connectent, il est donc normalement nécessaire de le spécifier.
maildir=liste-de-spécifications-de-dossiers
Ceci est une liste séparée par des deux-points des dossiers Maildir (relatifs à `base') que vous souhaitez indexer. Toute entrée se terminant par `...' est analysée récursivement pour trouver tous les dossiers Maildir en dessous.

Plusieurs lignes commençant par `maildir' peuvent être incluses. Dans ce cas, mairix joint les lignes avec des deux-points comme si une seule liste de dossiers avait été donnée sur une seule très longue ligne.

Chaque entrée séparée par deux-points peut être un joker. Voir la discussion sous mbox (ci-dessous) pour la syntaxe des jokers. Par exemple

maildir=zzz/foo*...
correspondra aux dossiers maildir comme ceux-ci (relatifs au répertoire-de-base)
zzz/foobar/xyz
zzz/fooquux
zzz/foo
zzz/fooabc/u/v/w

et

maildir=zzz/foo[abc]*
correspondra aux dossiers maildir comme ceux-ci (relatifs à la base du dossier)
zzz/fooa
zzz/fooaaaxyz
zzz/foobcd
zzz/fooccccccc
Si un nom de dossier contient un deux-points, vous pouvez l'écrire en utilisant la séquence '\:' pour échapper le deux-points. Sinon, le caractère antislash est traité normalement. (Si le nom de dossier contient réellement la séquence '\:', vous êtes malchanceux.)
mh=liste-de-spécifications-de-dossiers

Ceci est une liste séparée par des deux-points des dossiers MH (relatifs à `base') que vous souhaitez indexer. Toute entrée se terminant par '...' est analysée récursivement pour trouver tous les dossiers MH en dessous.

Plusieurs lignes commençant par 'mh' peuvent être incluses. Dans ce cas, mairix joint les lignes avec des deux-points comme si une seule liste de dossiers avait été donnée sur une seule très longue ligne.

Chaque entrée séparée par deux-points peut être un joker, voir la discussion sous maildir (ci-dessus) et mbox (ci-dessous) pour la syntaxe et la sémantique de la spécification des jokers.

mairix reconnaît les types de dossiers MH créés par les applications de courrier électronique suivantes :

  • xmh
  • sylpheed
  • claws-mail
  • evolution
  • NNML
  • Mew
mbox=liste-de-spécifications-de-dossiers

Ceci est une liste séparée par des deux-points des dossiers mbox ou MMDF (relatifs à `base') que vous souhaitez indexer.

Chaque élément de la liste séparé par des deux-points peut être suffixé par `...'. Si l'élément correspond à un fichier ordinaire, ce fichier est traité comme un dossier mbox et le suffixe '...' est ignoré. Si l'élément correspond à un répertoire, une analyse récursive de tout ce qui se trouve dans ce répertoire est effectuée, et tous les fichiers ordinaires sont initialement considérés comme des dossiers mbox/MMDF. (Tous les répertoires trouvés dans cette analyse sont eux-mêmes analysés, car l'analyse est récursive.)

Chaque élément séparé par des deux-points peut contenir des opérateurs de joker, mais uniquement dans son composant de chemin final. Les opérateurs de joker actuellement pris en charge sont

*

Correspond à zéro ou plusieurs caractères (chaque caractère correspondant est arbitraire)
?

Correspond à exactement un caractère arbitraire
[abcs-z]

Classe de caractères : correspond à un seul caractère parmi les ensembles a, b, c, s, t, u, v, w, x, y et z.

Pour inclure un ']' littéral dans la classe, placez-le immédiatement après le '[' d'ouverture. Pour inclure un '-' littéral dans la classe, placez-le immédiatement avant le ']' de fermeture.

Si ces métacaractères sont inclus dans des composants de chemin non finaux, ils n'ont aucune signification spéciale.

Voici quelques exemples

mbox=foo/bar*

correspond à 'foo/bar', 'foo/bar1', 'foo/barrrr', etc.
mbox=foo*/bar*

correspond à 'foo*/bar', 'foo*/bar1', 'foo*/barrrr', etc.
mbox=foo/*

correspond à 'foo/bar', 'foo/bar1', 'foo/barrrr', 'foo/foo', 'foo/x', etc.
mbox=foo...

correspond à tout fichier ordinaire dans l'arborescence dont la racine est 'foo'.
mbox=foo/*...

identique à ce qui précède.
mbox=foo/[a-z]*...

correspond à 'foo/a', 'foo/aardvark/xxx', 'foo/zzz/foobar', 'foo/w/x/y/zzz', mais pas à 'foo/A/foobar'.

Les fichiers ordinaires qui sont des candidats pour des dossiers mbox sont examinés en interne. Seuls les fichiers contenant des lignes de séparation mbox standard 'From ' ou MMDF '^A^A^A^A' seront analysés pour les messages.

Si un fichier ordinaire a un nom se terminant par '.gz', et que le support gzip est compilé dans le binaire mairix, le fichier sera traité comme un mbox zippé.

Si un fichier ordinaire a un nom se terminant par '.bz2', et que le support bzip est compilé dans le binaire mairix, le fichier sera traité comme un mbox bzip2é.

Plusieurs lignes commençant par 'mbox' peuvent être incluses. Dans ce cas, mairix joint les lignes avec des deux-points comme si une seule liste de dossiers avait été donnée sur une seule très longue ligne.

mairix n'effectue aucun verrouillage des mbo

Si un programme de distribution de courrier modifie la mbox en même temps, il est probable qu'un ou plusieurs messages de la mbox ne soient jamais indexés par mairix (jusqu'à ce que la base de données soit supprimée et recréée à partir de zéro, de toute façon.) L'hypothèse est que mairix sera utilisé pour indexer des dossiers d'archives plutôt que des dossiers entrants, donc ce ne devrait pas être un problème majeur en pratique.

mairix peut supporter un maximum de 65536 mboxes distinctes, et un maximum de 65536 messages dans une mbox.

imap=liste-de-dossiers

Ceci est une liste séparée par des deux-points des dossiers IMAP que vous souhaitez indexer.

Ces dossiers doivent tous être situés sur le même compte du même serveur IMAP. Les options de configuration imap_server et imap_pipe spécifient comment se connecter au serveur IMAP.

Plusieurs lignes commençant par 'imap' peuvent être incluses. Dans ce cas, mairix joint les lignes avec des deux-points comme si une seule liste de dossiers avait été donnée sur une seule très longue ligne.

omit=liste-de-modèles-glob
Ceci est une liste séparée par des deux-points de modèles glob pour les dossiers à omettre de l'indexation. Cela permet d'utiliser des jokers étendus et des éléments récursifs dans les directives maildir, mh, et mbox, avec l'option omit utilisée pour supprimer sélectivement les dossiers indésirables des listes de dossiers.

Dans les modèles glob, un seul '*' correspond à n'importe quelle séquence de caractères autre que '/'. Cependant, '**' correspond à n'importe quelle séquence de caractères incluant '/'. Cela permet de construire des modèles glob qui ont un joker pour un seul composant de répertoire, ou pour n'importe quel nombre de composants de répertoire.

L'option omit peut être spécifiée autant de fois que nécessaire afin que la liste de modèles n'ait pas à tenir sur une seule ligne.

Par exemple,

mbox=bulk...
omit=bulk/spam*
indexera tous les dossiers mbox à n'importe quel niveau sous le sous-répertoire 'bulk' du dossier de base, à l'exception des dossiers dont le nom commence par 'bulk/spam', par exemple 'bulk/spam', 'bulk/spam2005' etc.

En revanche,

mbox=bulk...
omit=bulk/spam**
indexera tous les dossiers mbox à n'importe quel niveau sous le sous-répertoire 'bulk' du dossier de base, à l'exception des dossiers dont le nom commence par 'bulk/spam', par exemple 'bulk/spam', 'bulk/spam2005', 'bulk/spam/2005', 'bulk/spam/2005/jan' etc.
nochecks
Ceci ne prend aucun argument. Si une ligne commençant par nochecks est présente, elle équivaut à spécifier le drapeau -Q à chaque exécution d'indexation.
mfolder=nom-du-dossier-correspondant
Ceci définit le nom du dossier (dans le répertoire spécifié par base) dans lequel le mode de recherche écrit sa sortie. (Si le format mformat utilisé est 'raw' ou 'excerpt', alors ce paramètre n'est pas utilisé et peut être omis.)

Le paramètre mfolder peut être remplacé pour une recherche particulière en utilisant l'option -o de mairix.

mairix refusera d'écrire les résultats de recherche dans un dossier qui semble faire partie de ceux qui sont indexés. Ceci afin d'empêcher la suppression accidentelle d'e-mails.

Si le premier caractère de la valeur de mfolder est '/' ou '.', il est considéré comme un chemin d'accès en soi. Cela vous permet de spécifier des chemins absolus et des chemins relatifs au répertoire actuel où le mfolder doit être écrit. Sinon, la valeur de mfolder est ajoutée à la valeur de base, de la même manière que pour les dossiers source.

mformat=format
Ceci définit le type de dossier utilisé pour le dossier correspondant où vont les résultats de la recherche. Il y a six réglages valides pour format, à savoir 'maildir', 'mh', 'mbox', 'imap', 'raw', ou 'excerpt' (les résultats de recherche MMDF ne sont pas supportés). Si le réglage 'raw' est utilisé, mairix affichera simplement les noms de fichiers correspondants et aucun dossier de correspondance ne sera créé. Si le réglage 'excerpt' est utilisé, mairix affichera également les en-têtes To:, Cc:, From:, Subject: et Date: des messages correspondants. 'maildir' est le défaut si cette option n'est pas définie. Le réglage est insensible à la casse.
database=chemin-vers-la-base-de-données

Ceci définit le chemin où la base de données d'indexation de mairix est conservée. Vous pouvez garder ce fichier où vous voulez.

Actuellement, mairix placera un seul fichier de base de données à l'emplacement indiqué par chemin-vers-la-base-de-données. Cependant, une future version de mairix pourrait à la place y placer un répertoire contenant plusieurs fichiers.

chemin-vers-la-base-de-données doit être un chemin absolu (commençant par '/'). Si un chemin relatif est utilisé, il sera interprété par rapport au répertoire actuel au moment de l'exécution de mairix (pas par rapport à l'emplacement du fichier mairixrc ou quoi que ce soit de ce genre).

follow_mbox_symlinks

Ceci ne prend aucun argument. Par défaut, mairix ignorera les liens symboliques vers les mboxes ou les fichiers MMDF lors de l'indexation. Si une ligne commençant par follow_mbox_symlinks est présente, mairix les suivra au lieu de les ignorer.
sort=date+

Les résultats de la recherche seront triés par ordre chronologique croissant. Aucune autre valeur pour sort n'est actuellement acceptée. En l'absence de cette entrée, les résultats ne sont pas triés.

Expansions

La partie de chaque ligne dans '.mairixrc' suivant le signe égal peut contenir les types d'expansion suivants :

Expansion du répertoire personnel
Si la séquence '~/' apparaît au début du texte après le signe égal, elle est étendue au répertoire personnel de l'utilisateur. Exemple :
database=~/Mail/mairix_database
Expansion de l'environnement
Si un '$' est suivi d'une séquence de caractères alphanumériques (ou '_'), la chaîne entière est remplacée en recherchant la variable d'environnement correspondante. De même, si '$' est suivi d'une accolade ouverte ('{'), tout jusqu'à la prochaine accolade fermante est recherché comme variable d'environnement et le résultat remplace la séquence entière.

Supposons que dans le shell nous fassions

export FOO=bar
et que le fichier '.mairixrc' contienne
maildir=xxx/$FOO
mbox=yyy/a${FOO}b
ceci est équivalent à
maildir=xxx/bar
mbox=yyy/abarb
Si la variable d'environnement spécifiée n'est pas définie, le remplacement est la chaîne vide.

NOTES

Un chemin alternatif vers le fichier de configuration peut être donné avec l'option -f de mairix(1).
