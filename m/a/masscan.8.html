NOM

masscan — Scan rapide d'Internet

SYNTAXE

masscan <adresses IP/plages> -p ports options

DESCRIPTION

masscan est un scanner de ports à l'échelle d'Internet, utile pour des enquêtes à grande échelle d'Internet, ou de réseaux internes. Bien que le taux d'émission par défaut ne soit que de 100 paquets/seconde, il peut optionnellement atteindre 25 millions de paquets/seconde, un taux suffisant pour scanner Internet en 3 minutes pour un port.

OPTIONS

  • <ip/plage> : tout ce qui se trouve sur la ligne de commande sans le préfixe ´-´ est supposé être une adresse IP ou une plage. Il existe trois formats valides. Le premier est une adresse IPv4 unique comme "192.168.0.1". Le second est une plage comme "10.0.0.1-10.0.0.100". Le troisième est une adresse CIDR, comme "0.0.0.0/0". Au moins une cible doit être spécifiée. Plusieurs cibles peuvent être spécifiées. Ceci peut être spécifié comme plusieurs options séparées par un espace, ou peut être séparé par une virgule comme une seule option, tel que 10.0.0.0/8,192.168.0.1.
  • --range <ip/plage> : identique à la spécification de plage cible décrite ci-dessus, sauf qu'il s'agit d'un paramètre nommé au lieu d'un paramètre non nommé.
  • -p <ports, --ports <ports> : spécifie le(s) port(s) à scanner. Un port unique peut être spécifié, comme -p80. Une plage de ports peut être spécifiée, comme -p 20-25. Une liste de ports/plages peut être spécifiée, comme -p80,20-25. Les ports UDP peuvent également être spécifiés, comme --ports U:161,U:1024-1100.
  • --banners : spécifie que les bannières doivent être récupérées, comme les versions de serveur HTTP, les titres de page HTML, etc. Seuls quelques protocoles sont pris en charge.
  • --rate <paquets-par-seconde> : spécifie le taux souhaité pour la transmission des paquets. Cela peut être de très petits nombres, comme 0.1 pour transmettre des paquets à des taux d'un toutes les 10 secondes, à de très grands nombres comme 10000000, qui tente de transmettre à 10 millions de paquets/seconde. D'après mon expérience, Windows peut gérer 250 000 paquets par seconde, et les dernières versions de Linux peuvent gérer 2,5 millions de paquets par seconde. Le pilote PF_RING est nécessaire pour atteindre 25 millions de paquets/seconde.
  • -c <nom_fichier>, --conf <nom_fichier> : lit un fichier de configuration. Le format du fichier de configuration est décrit ci-dessous.
  • --resume <nom_fichier> : identique à --conf, sauf que quelques options sont automatiquement définies, telles que --append-output. Le format du fichier de configuration est décrit ci-dessous.
  • --echo : ne pas exécuter, mais afficher la configuration actuelle dans un fichier. Ce fichier peut ensuite être utilisé avec l'option -c. Le format de cette sortie est décrit ci-dessous sous «FICHIER DE CONFIGURATION».
  • -e <nom_interface>, --adapter <nom_interface> : utilise l'interface réseau brute nommée, telle que "eth0" ou "dna1". Si non spécifié, la première interface réseau trouvée avec une passerelle par défaut sera utilisée.
  • --adapter-ip <adresse-ip> : envoie des paquets en utilisant cette adresse IP. Si non spécifié, la première adresse IP liée à l'interface réseau sera utilisée. Au lieu d'une adresse IP unique, une plage peut être spécifiée. REMARQUE : La taille de la plage doit être une puissance de 2, comme 1, 2, 4, 8, 16, 1024 adresses, etc.
  • --adapter-port <port> : envoie des paquets en utilisant ce numéro de port comme source. Si non spécifié, un port aléatoire sera choisi dans la plage 40000 à 60000. Ce port doit être filtré par le pare-feu de l'hôte (comme iptables) pour empêcher la pile réseau de l'hôte d'interférer avec les paquets entrants. Au lieu d'un port unique, une plage peut être spécifiée, comme 40000-40003. REMARQUE : La taille de la plage doit être une puissance de 2, comme dans l'exemple ci-dessus qui a un total de 4 adresses.
  • --adapter-mac <adresse-mac> : envoie des paquets en utilisant ceci comme adresse MAC source. Si non spécifié, la première adresse MAC liée à l'interface réseau sera utilisée.
  • --router-mac <adresse-mac> : envoie des paquets à cette adresse MAC comme destination. Si non spécifié, l'adresse de la passerelle de l'interface réseau sera résolue par ARP.
  • --ping : indique que le scan doit inclure une requête d'écho ICMP. Ceci peut être inclus avec le scan TCP et UDP.
  • --exclude <ip/plage> : met en liste noire une adresse IP ou une plage, l'empêchant d'être scannée. Ceci remplace toute spécification de cible, garantissant que cette adresse/plage ne sera pas scannée. Ceci a le même format que la spécification de cible normale.
  • --excludefile <nom_fichier> : lit une liste de plages à exclure, dans le même format de cible décrit ci-dessus. Ces plages remplacent toutes les cibles, les empêchant d'être scannées.
  • --append-output : fait en sorte que la sortie soit ajoutée au fichier, plutôt que de l'écraser.
  • --iflist : liste les interfaces réseau disponibles, puis se termine.
  • --retries : le nombre de nouvelles tentatives d'envoi, à intervalles de 1 seconde. Notez que comme ce scanner est sans état, les nouvelles tentatives sont envoyées indépendamment de la réception de réponses.
  • --nmap : affiche l'aide sur les alternatives compatibles nmap pour ces options.
  • --pcap-payloads : lit les paquets d'un fichier libpcap contenant des paquets et extrait les charges utiles UDP, et associe ces charges utiles aux ports de destination. Ces charges utiles seront ensuite utilisées lors de l'envoi de paquets UDP avec le port de destination correspondant. Une seule charge utile sera mémorisée par port. Similaire à --nmap-payloads.
  • --nmap-payloads <nom_fichier> : lit un fichier dans le même format que le fichier nmap nmap-payloads. Il contient une charge utile UDP, afin que nous puissions envoyer des paquets UDP utiles au lieu de paquets vides. Similaire à --pcap-payloads.
  • --http-user-agent <user-agent> : remplace le champ user-agent existant par la valeur indiquée lors des requêtes HTTP.
  • --open-only : signale uniquement les ports ouverts, pas les ports fermés.
  • --pcap <nom_fichier> : enregistre les paquets reçus (mais pas les paquets transmis) dans le fichier au format libpcap.
  • --packet-trace : affiche un résumé des paquets envoyés et reçus. Ceci est utile à bas taux, comme quelques paquets par seconde, mais submergera le terminal à des taux élevés.
  • --pfring : force l'utilisation du pilote PF_RING. Le programme se terminera si les pilotes PF_RING DNA ne sont pas disponibles.
  • --resume-index : le point dans le scan auquel il a été mis en pause.
  • --resume-count : le nombre maximum de sondes à envoyer avant de sortir. Ceci est utile avec --resume-index pour découper un scan et le répartir entre plusieurs instances, bien que l'option --shards puisse être préférable.
  • --shards <x>/<y> : divise le scan entre les instances. x est l'identifiant de ce scan, tandis que y est le nombre total d'instances. Par exemple, --shards 1/2 dit à une instance d'envoyer un paquet sur deux, en commençant par l'index 0. De même, --shards 2/2 envoie un paquet sur deux, mais en commençant par l'index 1, afin qu'il ne chevauche pas le premier exemple.
  • --rotate <temps> : fait pivoter le fichier de sortie, le renommant avec l'horodatage actuel, le déplaçant vers un répertoire séparé. Le temps est spécifié en nombre de secondes, comme "3600" pour une heure. Ou, des unités de temps peuvent être spécifiées, telles que "hourly", "6hours", ou "10min". Les temps sont alignés sur une limite paire, donc si "daily" est spécifié, le fichier sera pivoté chaque jour à minuit.
  • --rotate-offset <temps> : un décalage dans le temps. Ceci est pour tenir compte des fuseaux horaires.
  • --rotate-dir <répertoire> : lors du pivotement du fichier, ceci spécifie dans quel répertoire déplacer le fichier. Un répertoire utile est /var/log/masscan.
  • --seed <entier> : un entier qui initialise le générateur de nombres aléatoires. L'utilisation d'une graine différente entraînera l'envoi des paquets dans un ordre aléatoire différent. Au lieu d'un entier, la chaîne time peut être spécifiée, qui initialise en utilisant l'horodatage local, générant automatiquement un ordre de scan aléatoire différent. Si aucune graine n'est spécifiée, time est la valeur par défaut.
  • --regress : exécute un test de régression, retourne ´0´ en cas de succès et ´1´ en cas d'échec.
  • --ttl <num> : spécifie le TTL des paquets sortants, par défaut 255.
  • --wait <secondes> : spécifie le nombre de secondes à attendre pour recevoir des paquets après la fin de la transmission avant de quitter le programme. La valeur par défaut est 10 secondes.

OPTIONS

--rate <rate>
Sets the transmit rate of packets per second. The string forever can be specified to never terminate.
--offline:
don´t actually transmit packets. This is useful with a low rate and --packet-trace to look at what packets might´ve been transmitted. Or, it´s useful with --rate 100000000 in order to benchmark how fast transmit would work (assuming a zero-overhead driver). PF_RING is about 20% slower than the benchmark result from offline mode.
-sL:
this doesn´t do a scan, but instead creates a list of random addresses. This is useful for importing into other tools. The options --shard, --resume-index, and --resume-count can be useful with this feature.
--interactive:
show the results in realtime on the console. It has no effect if used with --output-format or --output-filename.
--output-format <fmt>:
indique le format du fichier de sortie, qui peut être xml, binary, grepable, list, ou JSON. L'option --output-filename doit être spécifiée.
--output-filename <filename>:
le fichier dans lequel enregistrer les résultats. Si le paramètre --output-format n'est pas spécifié, alors la valeur par défaut xml sera utilisée.
-oB <filename>:
définit le format de sortie sur binaire et enregistre la sortie dans le fichier donné. Ceci est équivalent à utiliser les paramètres --output-format et --output-filename. L'option --readscan peut ensuite être utilisée pour lire le fichier binaire. Les fichiers binaires sont beaucoup plus petits que leurs équivalents XML, mais nécessitent une étape séparée pour être reconvertis en XML ou dans un autre format lisible.
-oX <filename>:
définit le format de sortie sur XML et enregistre la sortie dans le fichier donné. Ceci est équivalent à utiliser les paramètres --output-format xml et --output-filename.
-oG <filename>:
définit le format de sortie sur grepable et enregistre la sortie dans le fichier donné. Ceci est équivalent à utiliser les paramètres --output-format grepable et --output-filename.
-oJ <filename>:
définit le format de sortie sur JSON et enregistre la sortie dans le fichier donné. Ceci est équivalent à utiliser les paramètres --output-format json et --output-filename.
-oL <filename>:
définit le format de sortie sur un format de liste simple et enregistre la sortie dans le fichier donné. Ceci est équivalent à utiliser les paramètres --output-format list et --output-filename.
--readscan <binary-files>:
lit les fichiers créés par l'option -oB à partir d'un scan, puis les affiche dans l'un des autres formats, en fonction des paramètres de la ligne de commande. En d'autres termes, il peut prendre la version binaire de la sortie et la convertir en format XML ou JSON.

FORMAT DU FICHIER DE CONFIGURATION

Le fichier de configuration utilise les mêmes noms de paramètres que sur la ligne de commande, mais sans le préfixe --, et avec un signe = entre le nom et la valeur. Un exemple de fichier de configuration pourrait être :

# cibles
range = 10.0.0.0/8,192.168.0.0/16
range = 172.16.0.0/14
ports = 20-25,80,U:53
ping = true
# adaptateur
adapter = eth0
adapter-ip = 192.168.0.1
router-mac = 66-55-44-33-22-11
# autre
exclude-file = /etc/masscan/exludes.txt

Par défaut, le programme lira la configuration par défaut dans le fichier /etc/masscan/masscan.conf. Ceci est utile pour les paramètres spécifiques au système, tels que les options --adapter-xxx. C'est également utile pour les adresses IP exclues, de sorte que vous puissiez scanner tout Internet, tout en sautant les adresses dangereuses, comme celles appartenant au DoD, et sans faire d'erreur accidentelle.

COMPORTEMENT DE CONTROL-C

Lorsque l'utilisateur appuie sur ctrl-c, le scan s'arrête et l'état actuel du scan est enregistré dans le fichier ´paused.conf´. Le scan peut être repris avec l'option --resume :

# masscan --resume paused.conf

Le programme ne se fermera pas immédiatement, mais attendra 10 secondes par défaut pour recevoir les résultats d'Internet et enregistrer les résultats avant de se fermer complètement. Ce délai peut être modifié avec l'option --wait.

EXEMPLES SIMPLES

L'exemple suivant scanne tous les réseaux privés pour les serveurs web, et imprime tous les ports ouverts qui ont été trouvés.

# masscan 10.0.0.0/8 192.168.0.0/16 172.16.0.0/12 -p80 --open-only

L'exemple suivant scanne tout Internet pour les serveurs DNS, en récupérant leurs versions, puis enregistre les résultats dans un fichier XML.

# masscan 0.0.0.0/0 --excludefile no-dod.txt -pU:53 --banners --output-filename dns.xml

Vous devriez être capable d'importer le XML dans des bases de données et autres.

L'exemple suivant lit un fichier de résultats de scan binaire appelé bin-test.scan et affiche les résultats sur la console.

# masscan --readscan bin-test.scan

L'exemple suivant lit un fichier de résultats de scan binaire appelé bin-test.scan et crée un fichier de sortie XML appelé bin-test.xml.

# masscan --readscan bin-test.scan -oX bin-test.xml

EXEMPLES AVANCÉS

Disons que vous voulez scanner tout Internet et répartir le scan sur trois machines. Masscan serait lancé sur les trois machines en utilisant les commandes suivantes :

# masscan 0.0.0.0/0 -p0-65535 --shard 1/3
# masscan 0.0.0.0/0 -p0-65535 --shard 2/3
# masscan 0.0.0.0/0 -p0-65535 --shard 3/3

Une alternative est la fonctionnalité "resume". Un scan a un indice interne qui va de zéro au nombre de ports multiplié par le nombre d'adresses IP. L'exemple suivant montre comment diviser un scan en morceaux de 1000 éléments chacun :

# masscan 0.0.0.0/0 -p0-65535 --resume-index 0 --resume-count 1000
# masscan 0.0.0.0/0 -p0-65535 --resume-index 1000 --resume-count 1000
# masscan 0.0.0.0/0 -p0-65535 --resume-index 2000 --resume-count 1000
# masscan 0.0.0.0/0 -p0-65535 --resume-index 3000 --resume-count 1000

Un script peut utiliser cela pour diviser des tâches plus petites sur de nombreuses autres machines, telles que des instances Amazon EC2. À mesure que chaque instance termine un travail, le script peut envoyer une requête à un serveur de coordination central pour obtenir plus de travail.

RÉINITIALISATIONS INTEMPESTIVES

Lors du scan TCP en utilisant l'adresse IP par défaut de votre adaptateur, la pile intégrée générera des paquets RST. Cela empêchera la capture de bannières. Il y a deux façons de résoudre ce problème. La première façon est de créer une règle de pare-feu pour bloquer ce port afin qu'il ne soit pas vu par la pile. La façon dont cela fonctionne dépend du système d'exploitation, mais sous Linux, cela ressemble à ceci :

# iptables -A INPUT -p tcp -i eth0 --dport 61234 -j DROP

Ensuite, lors du scan, le même port doit être utilisé comme source :

# masscan 10.0.0.0/8 -p80 --banners --adapter-port 61234

Une alternative est d'usurper une adresse IP différente. Cette adresse IP doit être dans la plage du réseau local, mais ne doit pas être utilisée par votre propre ordinateur ou par un autre ordinateur sur le réseau. Un exemple de ceci ressemblerait à :

# masscan 10.0.0.0/8 -p80 --banners --adapter-ip 192.168.1.101

Définir votre adresse IP source de cette manière est la manière préférée d'exécuter ce scanner.

PLAINTE POUR ABUS

Ce scanner est conçu pour des relevés à grande échelle, soit d'une organisation, soit d'Internet dans son ensemble. Ces scans seront remarqués par ceux qui surveillent leurs journaux, ce qui générera des plaintes.

Si vous scannez votre propre organisation, cela peut entraîner votre licenciement. Ne scannez jamais en dehors de votre sous-réseau local sans obtenir l'autorisation de votre patron, avec une déclaration écrite claire expliquant pourquoi vous scannez.

Il en va de même pour le scan d'Internet depuis votre employeur. C'est une autre bonne façon de se faire licencier, car votre département informatique sera inondé de plaintes expliquant pourquoi votre organisation les pirate.

Lorsque vous scannez seul, par exemple votre réseau domestique ou votre FAI, cela entraînera probablement l'annulation de votre compte en raison des plaintes d'abus.

Une solution consiste à travailler avec votre FAI, à être clair sur ce que nous faisons exactement, à leur prouver que nous recherchons sur Internet, et non que nous le "piratons". Nous demandons à notre FAI d'envoyer les plaintes d'abus directement à nous. Pour toute personne qui le demande, nous l'ajoutons à notre "--excludefile", la mettant sur liste noire afin que nous ne la scannions plus. En interagissant avec ces personnes, certaines nous ajoutent plutôt à leur liste blanche, de sorte que leurs pare-feux ne nous enregistrent plus (ils nous bloqueront toujours, bien sûr, ils n'enregistreront pas ce fait pour éviter de remplir leurs journaux avec nos scans).

En fin de compte, je ne sais pas s'il est possible de résoudre complètement ce problème. Malgré le fait qu'Internet soit un réseau public de bout en bout, vous êtes toujours "coupable jusqu'à preuve du contraire" lorsque vous effectuez un scan.

COMPATIBILITÉ

Bien que non listés dans ce document, de nombreux paramètres compatibles avec nmap fonctionneront également.

NAME

masscan - extremely fast network scanner

SYNOPSIS

masscan [OPTIONS] <expression>

DESCRIPTION

Masscan is a fast, experimental network port scanner. The goal of the project is to find port 80 on Windows machines in less than 5 minutes, including the entire internet. This implies a scan rate of 125 million ports per second. This is achieved by using an asynchronous algorithm that operates in a different way than traditional scanners like nmap.

The syntax for the target expression is the same as for nmap. You can specify targets like:

  • 192.168.0.1
  • 192.168.0.0/16
  • 192.168.0.0-192.168.1.255
  • 192.168.0.1,192.168.1.1
  • A file containing IPs
  • scanme.nmap.org

You can specify ports like:

  • 80
  • 10-20
  • 80,443
  • A file containing ports

OPTIONS

-p <ports> --ports <ports> Specifies the ports to scan. Defaults to 1-65535.

-i <file> --input-file <file> Read target IPs from a file.

-o <file> --output-file <file> Write results to a file. The default format is JSON.

-l <file> --log-file <file> Log the scan activity to a file.

-m <rate> --max-rate <rate> Set the maximum scan rate. Defaults to 1000 packets per second.

-M <rate> --max-concurrency <rate> Set the maximum number of concurrent probes. Defaults to 1000.

-n <seconds> --timeout <seconds> Set the timeout for responses. Defaults to 3 seconds.

-e <interface> --interface <interface> Specify the network interface to use.

-s <source-ip> --source-ip <source-ip> Specify the source IP address to use.

-r <file> --readscan <file> Read scan results from a file and continue scanning.

-f <format> --output-format <format> Specify the output format. Supported formats: bin, csv, grepable, json, nmap, xml.

-b --bpf Enable Berkeley Packet Filter (BPF) for faster packet capture.

-D --debug Enable debugging output.

-w --no-window Disable the sliding window feature for faster scanning (use with caution).

-S --save-state Save scan state to disk for resuming later.

-V --verbose Increase verbosity.

-h --help Show help message.

-v --version Show version information.

CONFIGURATION FILE FORMAT

Masscan can read configuration from a file specified with the --conf option. The file format is simple key-value pairs, one per line. Comments start with a # character.

# Example configuration file
ports = 80,443
rate = 10000
output-file = scan_results.json

CONTROL-C BEHAVIOR

When you press Ctrl-C, Masscan will save its state to disk (if the -S option is used) and exit gracefully. You can resume the scan later by running Masscan with the same options and the saved state file.

SIMPLE EXAMPLES

Scan the top 1000 most common ports on a single IP address:

masscan 192.168.1.1 -p1-1000

Scan port 80 on all hosts in the 192.168.0.0/24 network:

masscan 192.168.0.0/24 -p80

Scan ports 80 and 443 on a list of hosts from a file:

masscan -i hosts.txt -p80,443

ADVANCED EXAMPLES

Scan the entire internet for port 80 at a rate of 100,000 packets per second and save the results to a JSON file:

masscan 0.0.0.0/0 -p80 --rate 100000 -o results.json

Scan a range of IPs for a specific port, with a higher concurrency and lower timeout:

masscan 10.0.0.0-10.0.255.255 -p22 --max-concurrency 5000 --timeout 1

SPURIOUS RESETS

Masscan may encounter spurious TCP resets. This is often due to network devices that perform stateful packet inspection or other forms of network manipulation. If you are experiencing issues, try reducing the scan rate or disabling features like SYN-only scanning.

ABUSE COMPLAINTS

If you receive abuse complaints related to Masscan scans, please ensure that you have obtained permission from the network owner before scanning. You can also configure Masscan to use a specific source IP address and rate limit your scans to minimize disruption.

COMPATIBILITY

Masscan is designed to be compatible with nmap's target and port specifications. However, due to its different scanning methodology, some advanced nmap features may not be directly supported.
