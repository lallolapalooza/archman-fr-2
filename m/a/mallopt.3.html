mallopt(3) Manuel des fonctions de bibliothèque mallopt(3)

NOM

mallopt - définir les paramètres d'allocation de mémoire

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <malloc.h>
int mallopt(int param, int value);

DESCRIPTION

La fonction mallopt() ajuste les paramètres qui contrôlent le comportement des fonctions d'allocation de mémoire (voir malloc(3)). L'argument param spécifie le paramètre à modifier, et value spécifie la nouvelle valeur pour ce paramètre.

Les valeurs suivantes peuvent être spécifiées pour param :

M_ARENA_MAX
Si ce paramètre a une valeur non nulle, il définit une limite stricte sur le nombre maximum d'arènes pouvant être créées. Une arène représente un pool de mémoire qui peut être utilisé par les appels malloc(3) (et similaires) pour satisfaire les requêtes d'allocation. Les arènes sont thread-safe et peuvent donc avoir plusieurs requêtes de mémoire concurrentes. Le compromis est entre le nombre de threads et le nombre d'arènes. Plus vous avez d'arènes, plus la contention par thread est faible, mais plus l'utilisation de la mémoire est élevée.
La valeur par défaut de ce paramètre est 0, ce qui signifie que la limite sur le nombre d'arènes est déterminée selon le réglage de M_ARENA_TEST.
Ce paramètre est disponible depuis glibc 2.10 via --enable-experimental-malloc, et depuis glibc 2.15 par défaut. Dans certaines versions de l'allocateur, il n'y avait pas de limite au nombre d'arènes créées (par exemple, CentOS 5, RHEL 5).
Lors de l'utilisation de versions glibc plus récentes, les applications peuvent dans certains cas présenter une forte contention lors de l'accès aux arènes. Dans ces cas, il peut être bénéfique d'augmenter M_ARENA_MAX pour correspondre au nombre de threads. Ceci est similaire en comportement aux stratégies adoptées par tcmalloc et jemalloc (par exemple, pools d'allocation par thread).
M_ARENA_TEST
Ce paramètre spécifie une valeur, en nombre d'arènes créées, à partir de laquelle la configuration du système sera examinée pour déterminer une limite stricte sur le nombre d'arènes créées. (Voir M_ARENA_MAX pour la définition d'une arène.)
Le calcul de la limite stricte d'arène est défini par l'implémentation et est généralement calculé comme un multiple du nombre de CPU disponibles. Une fois la limite stricte calculée, le résultat est final et contraint le nombre total d'arènes.
La valeur par défaut pour le paramètre M_ARENA_TEST est 2 sur les systèmes où sizeof(long) est égal à 4 ; sinon, la valeur par défaut est 8.
Ce paramètre est disponible depuis glibc 2.10 via --enable-experimental-malloc, et depuis glibc 2.15 par défaut.
La valeur de M_ARENA_TEST n'est pas utilisée lorsque M_ARENA_MAX a une valeur non nulle.
M_CHECK_ACTION
La définition de ce paramètre contrôle la manière dont glibc réagit lorsque divers types d'erreurs de programmation sont détectés (par exemple, libérer le même pointeur deux fois). Les 3 bits les moins significatifs (2, 1 et 0) de la valeur attribuée à ce paramètre déterminent le comportement de glibc, comme suit :
Bit 0
Si ce bit est activé, un message d'une ligne est imprimé sur stderr et fournit des détails sur l'erreur. Le message commence par la chaîne "*** glibc detected ***", suivi du nom du programme, du nom de la fonction d'allocation de mémoire dans laquelle l'erreur a été détectée, d'une brève description de l'erreur et de l'adresse mémoire où l'erreur a été détectée.
Bit 1
Si ce bit est activé, alors, après avoir imprimé tout message d'erreur spécifié par le bit 0, le programme est terminé en appelant abort(3). Depuis glibc 2.4, si le bit 0 est également activé, le programme imprime également une trace de la pile à la manière de backtrace(3), et imprime le mapping mémoire du processus dans le style de /proc/pid/maps (voir proc(5)).
Bit 2 (depuis glibc 2.4)
Ce bit n'a d'effet que si le bit 0 est également activé. Si ce bit est activé, le message d'une ligne décrivant l'erreur est simplifié pour ne contenir que le nom de la fonction où l'erreur a été détectée et la brève description de l'erreur.
Les bits restants dans value sont ignorés.
En combinant les détails ci-dessus, les valeurs numériques suivantes sont significatives pour M_CHECK_ACTION :
0
Ignorer les conditions d'erreur ; continuer l'exécution (avec des résultats indéfinis).
1
Imprimer un message d'erreur détaillé et continuer l'exécution.
2
Terminer le programme.
3
Imprimer un message d'erreur détaillé, une trace de la pile et les mappings mémoire, puis terminer le programme.
5
Imprimer un message d'erreur simple et continuer l'exécution.
7
Imprimer un message d'erreur simple, une trace de la pile et les mappings mémoire, puis terminer le programme.
Depuis glibc 2.3.4, la valeur par défaut pour le paramètre M_CHECK_ACTION est 3. Dans glibc 2.3.3 et antérieur, la valeur par défaut est 1.
L'utilisation d'une valeur non nulle pour M_CHECK_ACTION peut être utile car sinon un plantage peut survenir beaucoup plus tard, et la cause réelle du problème est alors très difficile à identifier.
M_MMAP_MAX
Ce paramètre spécifie le nombre maximum de requêtes d'allocation qui peuvent être traitées simultanément en utilisant mmap(2). Ce paramètre existe car certains systèmes ont un nombre limité de tables internes à utiliser par mmap(2), et l'utilisation de plus que quelques-unes d'entre elles peut dégrader les performances.
La valeur par défaut est 65 536, une valeur qui n'a pas de signification spéciale et qui sert uniquement de mesure de sécurité. Définir ce paramètre à 0 désactive l'utilisation de mmap(2) pour traiter les requêtes d'allocation importantes.
M_MMAP_THRESHOLD
Pour les allocations supérieures ou égales à la limite spécifiée (en octets) par M_MMAP_THRESHOLD qui ne peuvent pas être satisfaites à partir de la liste des blocs libres, les fonctions d'allocation de mémoire utilisent mmap(2) au lieu d'augmenter le pointeur de fin du segment de données (program break) en utilisant sbrk(2).
L'allocation de mémoire à l'aide de mmap(2) présente l'avantage significatif que les blocs de mémoire alloués peuvent toujours être indépendamment rendus au système. (En revanche, le tas ne peut être réduit que si la mémoire est libérée à son extrémité supérieure.) D'autre part, il y a quelques inconvénients à l'utilisation de mmap(2) : l'espace désalloué n'est pas placé dans la liste des blocs libres pour être réutilisé par les allocations ultérieures ; la mémoire peut être gaspillée car les allocations mmap(2) doivent être alignées sur les pages ; et le noyau doit effectuer la tâche coûteuse de mettre à zéro la mémoire allouée via mmap(2). L'équilibre entre ces facteurs conduit à un réglage par défaut de 128 Ko pour le paramètre M_MMAP_THRESHOLD.
La limite inférieure pour ce paramètre est 0. La limite supérieure est DEFAULT_MMAP_THRESHOLD_MAX : 512 Ko sur les systèmes 32 bits ou 4*1024*1024*sizeof(long) sur les systèmes 64 bits.
Note : De nos jours, glibc utilise un seuil mmap dynamique par défaut. La valeur initiale du seuil est de 128 Ko, mais lorsque des blocs plus grands que le seuil actuel et inférieurs ou égaux à DEFAULT_MMAP_THRESHOLD_MAX sont libérés, le seuil est ajusté vers le haut à la taille du bloc libéré. Lorsque le seuil mmap dynamique est activé, le seuil pour réduire le tas est également ajusté dynamiquement à b

M_MXFAST (depuis glibc 2.3)
Définit la limite supérieure pour les requêtes d'allocation de mémoire qui sont satisfaites en utilisant des "fastbins". (L'unité de mesure pour ce paramètre est en octets.) Les fastbins sont des zones de stockage qui contiennent des blocs de mémoire libérés de la même taille sans fusionner les blocs libres adjacents. Les réallocations ultérieures de blocs de même taille peuvent être traitées très rapidement en allouant à partir du fastbin, bien que la fragmentation de la mémoire et l'empreinte mémoire globale du programme puissent augmenter.
La valeur par défaut pour ce paramètre est *64*sizeof(size_t)/4* (c'est-à-dire 64 sur les architectures 32 bits). La plage pour ce paramètre est de 0 à *80*sizeof(size_t)/4. Définir M_MXFAST à 0 désactive l'utilisation des fastbins.
M_PERTURB (depuis glibc 2.4)
Si ce paramètre est défini sur une valeur non nulle, les octets de la mémoire allouée (autres que les allocations via calloc(3)) sont initialisés au complément de la valeur du bit le moins significatif de *value*, et lorsque la mémoire allouée est libérée en utilisant free(3), les octets libérés sont définis à la valeur du bit le moins significatif de *value*. Ceci peut être utile pour détecter des erreurs où les programmes s'appuient incorrectement sur le fait que la mémoire allouée est initialisée à zéro, ou réutilisent des valeurs dans la mémoire qui a déjà été libérée.
La valeur par défaut pour ce paramètre est 0.
M_TOP_PAD
Ce paramètre définit la quantité de rembourrage à utiliser lors de l'appel à sbrk(2) pour modifier le point de rupture du programme. (L'unité de mesure pour ce paramètre est en octets.) Ce paramètre a un effet dans les circonstances suivantes :
•
Lorsque le point de rupture du programme est augmenté, alors M_TOP_PAD octets sont ajoutés à la demande sbrk(2).
•
Lorsque le tas est rogné à la suite d'un appel à free(3) (voir la discussion sur M_TRIM_THRESHOLD), cet espace libre est préservé en haut du tas.
Dans les deux cas, la quantité de rembourrage est toujours arrondie à une limite de page système.
Modifier M_TOP_PAD est un compromis entre l'augmentation du nombre d'appels système (lorsque le paramètre est réglé bas) et le gaspillage de mémoire inutilisée en haut du tas (lorsque le paramètre est réglé haut).
La valeur par défaut pour ce paramètre est 128*1024.
M_TRIM_THRESHOLD
Lorsque la quantité de mémoire libre contiguë en haut du tas devient suffisamment importante, free(3) utilise sbrk(2) pour libérer cette mémoire au système. (Cela peut être utile dans les programmes qui continuent de s'exécuter pendant une longue période après avoir libéré une quantité importante de mémoire.) Le paramètre M_TRIM_THRESHOLD spécifie la taille minimale (en octets) que ce bloc de mémoire doit atteindre avant que sbrk(2) ne soit utilisé pour rogner le tas.
La valeur par défaut pour ce paramètre est 128*1024. Définir M_TRIM_THRESHOLD à -1 désactive complètement le rognage.
Modifier M_TRIM_THRESHOLD est un compromis entre l'augmentation du nombre d'appels système (lorsque le paramètre est réglé bas) et le gaspillage de mémoire inutilisée en haut du tas (lorsque le paramètre est réglé haut).

Variables d'environnement

Plusieurs variables d'environnement peuvent être définies pour modifier certains des mêmes paramètres que ceux contrôlés par mallopt(). L'utilisation de ces variables présente l'avantage de ne pas nécessiter de modification du code source du programme. Pour être efficaces, ces variables doivent être définies avant le premier appel à une fonction d'allocation de mémoire. (Si les mêmes paramètres sont ajustés via mallopt(), les paramètres mallopt() ont la priorité.) Pour des raisons de sécurité, ces variables sont ignorées dans les programmes set-user-ID et set-group-ID.

Les variables d'environnement sont les suivantes (notez le trait de soulignement final à la fin du nom de certaines variables) :

MALLOC_ARENA_MAX
Contrôle le même paramètre que mallopt() M_ARENA_MAX.
MALLOC_ARENA_TEST
Contrôle le même paramètre que mallopt() M_ARENA_TEST.
MALLOC_CHECK_
Cette variable d'environnement contrôle le même paramètre que mallopt() M_CHECK_ACTION. Si cette variable est définie sur une valeur non nulle, une implémentation spéciale des fonctions d'allocation de mémoire est utilisée. (Ceci est réalisé à l'aide de la fonctionnalité malloc_hook(3).) Cette implémentation effectue des vérifications d'erreurs supplémentaires, mais est plus lente que l'ensemble standard des fonctions d'allocation de mémoire. (Cette implémentation ne détecte pas toutes les erreurs possibles ; des fuites de mémoire peuvent toujours se produire.)
La valeur attribuée à cette variable d'environnement doit être un seul chiffre, dont la signification est celle décrite pour M_CHECK_ACTION. Tous les caractères au-delà du chiffre initial sont ignorés.
Pour des raisons de sécurité, l'effet de MALLOC_CHECK_ est désactivé par défaut pour les programmes set-user-ID et set-group-ID. Cependant, si le fichier /etc/suid-debug existe (le contenu du fichier est sans importance), alors MALLOC_CHECK_ a également un effet pour les programmes set-user-ID et set-group-ID.
MALLOC_MMAP_MAX_
Contrôle le même paramètre que mallopt() M_MMAP_MAX.
MALLOC_MMAP_THRESHOLD_
Contrôle le même paramètre que mallopt() M_MMAP_THRESHOLD.
MALLOC_PERTURB_
Contrôle le même paramètre que mallopt() M_PERTURB.
MALLOC_TRIM_THRESHOLD_
Contrôle le même paramètre que mallopt() M_TRIM_THRESHOLD.
MALLOC_TOP_PAD_
Contrôle le même paramètre que mallopt() M_TOP_PAD.

VALEUR DE RETOUR

En cas de succès, mallopt() retourne 1. En cas d'erreur, il retourne 0.

ERREURS

En cas d'erreur, errno n'est *pas* défini.

VERSIONS

Une fonction similaire existe sur de nombreux dérivés de System V, mais la plage de valeurs pour param varie selon les systèmes. Le SVID a défini les options M_MXFAST, M_NLBLKS, M_GRAIN et M_KEEP, mais seule la première est implémentée dans glibc.

NORMES

Aucune.

HISTORIQUE

glibc 2.0.

BOGUES

La spécification d'une valeur invalide pour param ne génère pas d'erreur.

Une erreur de calcul dans l'implémentation glibc signifie qu'un appel de la forme :


mallopt(M_MXFAST, n)

n'entraîne pas l'utilisation des fastbins pour toutes les allocations de taille jusqu'à n. Pour garantir les résultats souhaités, n doit être arrondi à la prochaine multiple supérieure ou égale à *(2k+1)*sizeof(size_t)*, où *k* est un entier.

Si mallopt() est utilisé pour définir M_PERTURB, alors, comme prévu, les octets de la mémoire allouée sont initialisés au complément de l'octet dans value*, et lorsque cette mémoire est libérée, les octets de la région sont initialisés à l'octet spécifié dans value*. Cependant, il y a une erreur de *sizeof(size_t)* dans l'implémentation : au lieu d'initialiser précisément le bloc de mémoire libéré par l'appel free(p), le bloc commençant à p+sizeof(size_t) est initialisé.

NOM

mallopt — options de configuration de l'allocateur

BIBLIOTHQUE

Bibliothèque C standard (libc)

Avec gcc : Lien avec -lc

SYNTAXE

#include <malloc.h>

int mallopt(int parameter_number, int value);

DESCRIPTION

La fonction mallopt permet de modifier certains paramètres du comportement de l'allocateur mémoire malloc(3) dans la bibliothèque C standard GNU (glibc).

Le premier argument, parameter_number, est un entier spécifiant quel paramètre de configuration doit être modifié. Les valeurs possibles pour parameter_number sont définies dans le fichier d'en-tête <malloc.h> :

M_CHECK_ACTION
Définit l'action à effectuer en cas de détection d'une erreur d'allocation mémoire. Les valeurs possibles pour value sont :
0
(Par défaut) Ne rien faire, continuer l'exécution.
1
Imprimer un message d'erreur sur la sortie d'erreur standard (stderr) et continuer.
2
Déclencher un assert (en cas de débogage).
3
Appeler abort() pour terminer le programme immédiatement.
La valeur effective de value est limitée à la plage [0, 3].
M_MMAP_MAX
Définit le nombre maximal de régions mémoire mappées (mmap()) que l'allocateur peut utiliser pour satisfaire les requêtes d'allocation. La valeur par défaut est 65536. Une valeur de 0 désactive l'utilisation de mmap().
M_ARENA_MAX
Définit le nombre maximal d'arènes mémoire indépendantes que l'allocateur peut créer. Les arènes sont des structures de données utilisées pour gérer les allocations. La valeur par défaut est 0, ce qui signifie que le nombre d'arènes est déterminé dynamiquement. Pour les applications multithread, une valeur supérieure à 1 peut améliorer les performances en réduisant la contention entre les threads. Pour les applications monothread, une valeur de 1 peut être bénéfique.
M_ kebijakan_ACTION
Définit l'action à effectuer en cas d'échec d'une requête d'allocation (malloc(), calloc(), realloc(), memalign()). Les valeurs possibles pour value sont les mêmes que pour M_CHECK_ACTION.
M_ kebijakan_MMAP_THRESHOLD
Définit la taille seuil (en octets) à partir de laquelle les allocations seront effectuées à l'aide de mmap() plutôt qu'en agrandissant le tas avec sbrk(). La valeur par défaut est 128 Ko. Si value est défini à une valeur inférieure à la taille d'une page mémoire, les allocations utiliseront toujours sbrk().
M_ politika_TRIM_THRESHOLD
Définit la quantité maximale de mémoire libre (en octets) qui peut être renvoyée au système d'exploitation par malloc_trim(). La valeur par défaut est 2 Mo. Si la valeur est définie à 0, aucune mémoire ne sera renvoyée au système.

La fonction mallopt est généralement utilisée pour ajuster les performances de l'allocateur mémoire pour des charges de travail spécifiques.

Il est important de noter que les options disponibles et leur comportement peuvent varier en fonction de la version de la glibc utilisée. Il est recommandé de consulter la documentation de la glibc pour connaître les détails précis.

Exemple

Le programme suivant tente de libérer deux fois la même mémoire, ce qui provoquera une erreur. La gestion de cette erreur peut être contrôlée par le paramètre M_CHECK_ACTION.

Le premier exemple montre le comportement par défaut lorsque l'option n'est pas définie :

$ ./a.out
main(): returned from first free() call
main(): returned from second free() call

Le deuxième exemple montre comment définir le même paramètre à l'aide de la variable d'environnement MALLOC_CHECK_ :

$ MALLOC_CHECK_=1 ./a.out
main(): returned from first free() call
*** glibc detected *** ./a.out: free(): invalid pointer: 0x092c2008 ***
main(): returned from second free() call

Source du programme

#include <malloc.h>
#include <stdio.h>
#include <stdlib.h>
int
main(int argc, char *argv[])
{
    char *p;
    if (argc > 1) {
        if (mallopt(M_CHECK_ACTION, atoi(argv[1])) != 1) {
            fprintf(stderr, "mallopt() failed");
            exit(EXIT_FAILURE);
        }
    }
    p = malloc(1000);
    if (p == NULL) {
        fprintf(stderr, "malloc() failed");
        exit(EXIT_FAILURE);
    }
    free(p);
    printf("%s(): returned from first free() call\n", __func__);
    free(p);
    printf("%s(): returned from second free() call\n", __func__);
    exit(EXIT_SUCCESS);
}
