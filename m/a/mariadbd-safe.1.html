MARIADBD-SAFE(1) Système de base de données MariaDB MARIADBD-SAFE(1)

NOM

mariadbd-safe - Script de démarrage du serveur MariaDB (mariadbd-safe est maintenant un lien symbolique vers mariadbd-safe)

SYNTAXE

mariadbd-safe options

DESCRIPTION

mariadbd-safe est la méthode recommandée pour démarrer un serveur mariadbd sous Unix. mariadbd-safe ajoute des fonctions de sécurité telles que le redémarrage du serveur en cas d'erreur et l'enregistrement des informations d'exécution dans un fichier journal d'erreurs. Les descriptions de la journalisation des erreurs sont données plus loin dans cette section.

mariadbd-safe essaie de démarrer un exécutable nommé mariadbd. Pour remplacer le comportement par défaut et spécifier explicitement le nom du serveur que vous souhaitez exécuter, spécifiez une option --mariadbd ou --mariadbd-version pour mariadbd-safe. Vous pouvez également utiliser --ledir pour indiquer le répertoire où mariadbd-safe doit rechercher le serveur.

Plusieurs options de mariadbd-safe sont identiques aux options de mariadbd.

Les options inconnues de mariadbd-safe sont transmises à mariadbd si elles sont spécifiées sur la ligne de commande, mais ignorées si elles sont spécifiées dans les sections [mariadbd-safe] ou [mariadbd_safe] d'un fichier d'options.

mariadbd-safe lit toutes les options des sections [mariadbd], [server], [mariadbd-safe] et [mariadbd_safe] des fichiers d'options. Par exemple, si vous spécifiez une section [mariadbd] comme suit, mariadbd-safe trouvera et utilisera l'option --log-error :

[mariadbd]
log-error=error.log

Pour des raisons de compatibilité descendante, mariadbd-safe lit également les sections [safe_mariadbd], bien que vous devriez renommer de telles sections en [mariadbd-safe] dans les installations actuelles.

mariadbd-safe prend en charge les options de la liste suivante. Il lit également les fichiers d'options et prend en charge les options pour les traiter.

•--help

Affiche un message d'aide et quitte.

•--basedir=chemin

Le chemin vers le répertoire d'installation de MariaDB.

•--core-file-size=taille

La taille du fichier core que mariadbd doit pouvoir créer. La valeur de l'option est transmise à ulimit -c.

•--crash-script=fichier

Script à appeler en cas de crash de mariadbd.

•--datadir=chemin

Le chemin vers le répertoire de données.

•--defaults-extra-file=chemin

Le nom d'un fichier d'options à lire en plus des fichiers d'options habituels. Ce doit être la première option sur la ligne de commande s'il est utilisé. Si le fichier n'existe pas ou n'est pas accessible, le serveur se terminera avec une erreur.

•--defaults-file=nom_fichier

Le nom d'un fichier d'options à lire au lieu des fichiers d'options habituels. Ce doit être la première option sur la ligne de commande s'il est utilisé.

•--flush-caches

Vide et purge les tampons/caches avant de démarrer le serveur.

•--ledir=chemin

Si mariadbd-safe ne trouve pas le serveur, utilisez cette option pour indiquer le nom du chemin vers le répertoire où se trouve le serveur.

•--log-error=nom_fichier

Écrit le journal d'erreurs dans le fichier donné.

•--malloc-lib=lib

Précharge la bibliothèque partagée lib si disponible.

•--mariadbd=nom_prog

Le nom du programme serveur (dans le répertoire ledir) que vous souhaitez démarrer. Cette option est nécessaire si vous utilisez la distribution binaire de MariaDB mais que le répertoire de données est en dehors de la distribution binaire. Si mariadbd-safe ne trouve pas le serveur, utilisez l'option --ledir pour indiquer le nom du chemin vers le répertoire où se trouve le serveur.

•--mariadbd-version=suffixe

Cette option est similaire à l'option --mariadbd, mais vous ne spécifiez que le suffixe du nom du programme serveur. Le nom de base est supposé être mariadbd. Par exemple, si vous utilisez --mariadbd-version=debug, mariadbd-safe démarre le programme mariadbd-debug dans le répertoire ledir. Si l'argument de --mariadbd-version est vide, mariadbd-safe utilise mariadbd dans le répertoire ledir.

•--nice=priorité

Utilise le programme nice pour définir la priorité d'ordonnancement du serveur à la valeur donnée.

•--no-auto-restart, --nowatch, --no-watch

Quitte après le démarrage de mariadbd.

•--no-defaults

Ne lit aucun fichier d'options. Ce doit être la première option sur la ligne de commande si elle est utilisée.

•--numa-interleave

Exécute mariadbd avec sa mémoire entrelacée sur tous les nœuds NUMA.

•--open-files-limit=compte

Le nombre de fichiers que mariadbd devrait pouvoir ouvrir. La valeur de l'option est transmise à ulimit -n. Notez que vous devez démarrer mariadbd-safe en tant que root pour que cela fonctionne correctement !

•--pid-file=nom_fichier

Le nom du chemin du fichier d'ID de processus.

•--plugin-dir=nom_rep

Répertoire pour les plugins côté client.

•--port=num_port

Le numéro de port que le serveur doit utiliser lors de l'écoute des connexions TCP/IP. Le numéro de port doit être de 1024 ou plus, sauf si le serveur est démarré par l'utilisateur système root.

•--skip-kill-mariadbd

N'essaie pas de tuer les processus mariadbd errants au démarrage. Cette option ne fonctionne que sous Linux.

•--socket=chemin

Le fichier de socket Unix que le serveur doit utiliser lors de l'écoute des connexions locales.

•--syslog, --skip-syslog

--syslog provoque l'envoi des messages d'erreur à syslog sur les systèmes qui prennent en charge le programme logger. --skip-syslog supprime l'utilisation de syslog ; les messages sont écrits dans un fichier journal d'erreurs.

•--syslog-tag=tag

Pour la journalisation dans syslog, les messages de mariadbd-safe et mariadbd sont écrits avec un tag de mariadbd-safe et mariadbd, respectivement. Pour spécifier un suffixe pour le tag, utilisez --syslog-tag=tag, qui modifie les tags pour être mariadbd-safe-tag et mariadbd-tag.

•--timezone=fuseau_horaire

Définit la variable d'environnement TZ (fuseau horaire) à la valeur donnée de l'option. Consultez la documentation de votre système d'exploitation pour connaître les formats de spécification de fuseau horaire valides.

•--user={nom_utilisateur|id_utilisateur}

Exécute le serveur mariadbd en tant qu'utilisateur portant le nom nom_utilisateur ou l'ID utilisateur numérique id_utilisateur. (« Utilisateur » dans ce contexte fait référence à un compte de connexion système, pas à un utilisateur MariaDB listé dans les tables de grant.)

Si vous exécutez mariadbd-safe avec l'option --defaults-file ou --defaults-extra-file pour nommer un fichier d'options, l'option doit être la première donnée sur la ligne de commande ou le fichier d'options ne sera pas utilisé. Par exemple, cette commande n'utilisera pas le fichier d'options nommé :

mariadb> mariadbd-safe --port=num_port --defaults-file=nom_fichier

Au lieu de cela, utilisez la commande suivante :

mariadb> mariadbd-safe --defaults-file=nom_fichier --port=num_port

Le script mariadbd-safe est écrit de manière à pouvoir normalement démarrer un serveur installé à partir d'une distribution source ou binaire de MariaDB, même si ces types de distributions installent généralement le serveur dans des emplacements légèrement différents. mariadbd-safe s'attend à ce que l'une des conditions suivantes soit vraie :

•Le serveur et les bases de données peuvent être trouvés par rapport au répertoire de travail (le répertoire depuis lequel mariadbd-safe est invoqué). Pour les distributions binaires

mariadbd-safe(1) — MariaDB 11.8

NAME

mariadbd-safe -- MariaDB server startup script

SYNOPSIS

mariadbd-safe [options]

DESCRIPTION

mariadbd-safe est un script qui démarre le serveur MariaDB (mariadbd). Il exécute un certain nombre de vérifications de sécurité avant de démarrer le serveur.

mariadbd-safe cherche les répertoires bin et data sous son répertoire de travail. Pour les distributions sources, il cherche les répertoires libexec et var. Cette condition est remplie si vous exécutez mariadbd-safe depuis le répertoire d'installation de MariaDB (par exemple, /usr/local/mysql pour une distribution binaire).

•Si le serveur et les bases de données ne peuvent pas être trouvés par rapport au répertoire de travail, mariadbd-safe tente de les localiser par leurs noms de chemin absolus. Les emplacements typiques sont /usr/local/libexec et /usr/local/var. Les emplacements réels sont déterminés à partir des valeurs configurées dans la distribution au moment de sa création. Ils devraient être corrects si MariaDB est installé à l'emplacement spécifié au moment de la configuration.

Étant donné que mariadbd-safe essaie de trouver le serveur et les bases de données par rapport à son propre répertoire de travail, vous pouvez installer une distribution binaire de MariaDB n'importe où, tant que vous exécutez mariadbd-safe depuis le répertoire d'installation de MariaDB :

shell> cd répertoire_installation_mysql
shell> bin/mariadbd-safe &

Si mariadbd-safe échoue, même lorsqu'il est invoqué depuis le répertoire d'installation de MariaDB, vous pouvez spécifier les options --ledir et --datadir pour indiquer les répertoires où se trouvent le serveur et les bases de données sur votre système.

Lorsque vous utilisez mariadbd-safe pour démarrer mariadbd, mariadbd-safe s'assure que les messages d'erreur (et de notification) provenant de lui-même et de mariadbd vont à la même destination.

Il existe plusieurs options mariadbd-safe pour contrôler la destination de ces messages :

•--syslog : Écrit les messages d'erreur dans syslog sur les systèmes qui prennent en charge le programme logger.
•--skip-syslog : N'écrit pas les messages d'erreur dans syslog. Les messages sont écrits dans le fichier journal d'erreurs par défaut (nom_hote.err dans le répertoire de données), ou dans un fichier nommé si l'option --log-error est donnée.
•--log-error=nom_fichier : Écrit les messages d'erreur dans le fichier d'erreurs nommé.

Si aucune de ces options n'est donnée, la valeur par défaut est --skip-syslog.


Note

Si --syslog et --log-error sont tous deux donnés, un avertissement est émis et --log-error a la priorité.

Lorsque mariadbd-safe écrit un message, les notifications vont à la destination de journalisation (syslog ou le fichier journal d'erreurs) et à stdout. Les erreurs vont à la destination de journalisation et à stderr.

Normalement, vous ne devriez pas modifier le script mariadbd-safe. Configurez plutôt mariadbd-safe en utilisant des options de ligne de commande ou des options dans la section [mariadbd-safe] d'un fichier d'options my.cnf. Dans de rares cas, il peut être nécessaire de modifier mariadbd-safe pour qu'il démarre le serveur correctement. Cependant, si vous le faites, votre version modifiée de mariadbd-safe pourrait être écrasée si vous mettez à niveau MariaDB à l'avenir, vous devriez donc faire une copie de votre version éditée que vous pourrez réinstaller.

Sur NetWare, mariadbd-safe est un module chargeable NetWare (NLM) qui est porté depuis le script shell Unix d'origine. Il démarre le serveur comme suit :

1.Exécute un certain nombre de vérifications système et d'options.
2.Exécute une vérification des tables MyISAM.
3.Fournit une présence à l'écran pour le serveur MariaDB.
4.Démarre mariadbd, le surveille et le redémarre s'il se termine par une erreur.
5.Envoie les messages d'erreur de mariadbd au fichier nom_hote.err dans le répertoire de données.
6.Envoie la sortie de l'écran de mariadbd-safe au fichier nom_hote.safe dans le répertoire de données.
