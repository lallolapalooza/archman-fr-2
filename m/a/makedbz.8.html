NOM

makedbz - Reconstruire les fichiers dbz

SYNTAXE

makedbz [-io] [-f nom_fichier] [-s taille]

DESCRIPTION

makedbz reconstruit la base de données dbz (également connue sous le nom de fichier history). Le nom par défaut du fichier texte est chemin_bd/history ; pour spécifier un nom différent, utilisez l'option -f.

OPTIONS

-f nom_fichier
Si l'option -f est utilisée, alors les fichiers de base de données sont nommés "nom_fichier.dir", "nom_fichier.index", et "nom_fichier.hash". Si l'option -f n'est pas utilisée, alors un lien temporaire vers le nom "history.n" est créé et les fichiers de base de données sont écrits sous les noms "history.n.index" , "history.n.hash" et "history.n.dir".
-i
Pour ignorer l'ancienne base de données lors de la détermination de la taille de la nouvelle à créer, utilisez l'option -i. L'utilisation des options -o ou -s implique l'option -i.

Lorsque l'ancienne base de données est ignorée et qu'une taille n'est pas spécifiée avec -s, makedbz comptera le nombre de lignes du fichier history texte actuel, ajoutera 10 % à ce compte (pour les prochains articles à arriver), et 50 % supplémentaires (ou 100 % si le format de hachage étiqueté plus lent est utilisé) pour déterminer la taille de la nouvelle base de données à créer. L'objectif est d'optimiser les performances de la base de données, en la maintenant remplie en dessous des 2/3 de sa taille (ou 1/2 avec le format de hachage étiqueté).

Si aucun fichier history texte n'existe, le nouveau aura la taille de création par défaut (voir -s).

-o
Si l'option -o est utilisée, alors le lien temporaire vers "history.n" (ou le nom spécifié par l'option -f) n'est pas créé et tous les fichiers history existants sont écrasés. Si l'ancienne base de données existe, makedbz l'utilisera pour déterminer la taille de la nouvelle base de données (voir -i).
-s taille
makedbz ignorera également toute ancienne base de données si l'option -s est utilisée pour spécifier le nombre approximatif d'entrées dans la nouvelle base de données. Spécifier précisément la taille est une optimisation qui créera une base de données plus efficace. Le serveur de news acceptera toujours plus d'articles, mais sera plus lent. La taille est mesurée en paires clé-valeur (c'est-à-dire en lignes). (La taille devrait être la taille finale estimée du fichier, typiquement la taille de l'ancien fichier.)

La taille effective utilisée sera plus grande, pour optimiser les performances de la base de données. Pour plus d'informations, voir -i et la discussion de dbzfresh et dbzsize dans libinn_dbz(3).

La valeur par défaut est 6 666 666 lors de la création d'une nouvelle base de données history. (Si le format de hachage étiqueté plus lent est utilisé, la valeur par défaut est 500 000.)
