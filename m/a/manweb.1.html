NOM

manweb - parcourir la documentation netpbm (et autres)

SYNOPSIS

manweb -help

manweb [-config=fichier_config] [sujet [ sous_sujet ... ] ]

EXEMPLES

manweb

Ceci récupère un index maître de la documentation.

manweb netpbm

Ceci récupère la page de documentation principale du paquet Netpbm, avec des hyperliens vers le reste de la documentation.

manweb netpbm pngtopam

Ceci va directement à la page de documentation du programme Pngtopam du paquet Netpbm.

manweb pngtopam

Ceci va également directement à la page de documentation du programme Pngtopam du paquet Netpbm, si c'est ce qui serait exécuté en réponse à une commande shell pngtopam (votre variable d'environnement PATH est impliquée).

manweb 3 fopen

Ceci récupère la page man traditionnelle pour la sous-routine fopen() en utilisant man.

manweb cp

Ceci récupère le manuel GNU Info pour le programme cp, en utilisant info.

DESCRIPTION

manweb affiche la documentation de référence via des commandes shell rapides. C'est un remplacement pour le bien connu man.

Différences entre Man et Manweb

Les avantages de manweb par rapport à man sont :


  • Vous pouvez accéder à la documentation qui se trouve sur le web au lieu
    d'avoir des copies installées localement. Cela économise du travail d'installation et vous
    obtient une documentation plus à jour.


  • La documentation peut être en HTML, qui est plus largement connu, plus
    utile et plus expressif que le format nroff/troff utilisé par
    man.


  • manweb organise vos sujets dans une arborescence pour une documentation
    multiniveau. man est destiné à un seul niveau de documentation. Par
    exemple, vous pouvez avoir une page man pour chaque commande shell, mais pas pour
    les sous-commandes d'une commande shell. Et vous ne pouvez pas correctement avoir
    des pages man pour les membres de plusieurs bibliothèques de sous-routines.


  • La documentation peut être hyperliée.

Les serveurs web ne sont pas nécessaires - la documentation peut se trouver dans des fichiers locaux. Les graphiques ne sont pas nécessaires - le navigateur lynx fonctionne très bien dans le même type de terminaux où fonctionne man.

manweb trouve la documentation que vous spécifiez et appelle un navigateur web de votre choix pour l'afficher. La documentation que manweb trouve peut être soit un fichier HTML sur votre système, auquel cas, manweb donne une URL file: à votre navigateur, soit une URL explicite. Cette URL explicite peut être une URL http: faisant référence à un fichier HTML sur un serveur web quelque part, ou tout autre chose que votre navigateur comprend.

Si manweb ne trouve ni fichier HTML ni URL, mais que vos paramètres semblent pouvoir signifier quelque chose pour man, manweb appelle man. Par conséquent, vous pouvez utiliser une seule commande pour accéder à la vaste quantité de pages man traditionnelles, plus toute nouvelle documentation manweb. Vous pouvez faire de "man" un alias shell de "manweb".

manweb trouve également la documentation Info. Il recherche le sujet que vous spécifiez comme sujet Info après avoir cherché la documentation HTML et URL et avant d'exécuter man. Si manweb trouve un sujet Info correspondant, il exécute le programme info dessus. Info est le système de documentation que le projet GNU a inventé pour, entre autres, remplacer les pages man traditionnelles d'Unix. Cependant, HTML et le World Wide Web ont été inventés peu après, donc Info a échoué. Mais il existe toujours beaucoup de logiciels GNU qui sont documentés comme sujets Info.

Comment Manweb trouve la documentation

manweb transmet une URL à un navigateur web. Cette section explique comment vos paramètres d'invocation manweb se transforment en cette URL.

La recherche de manweb commence dans le répertoire "répertoire web". C'est soit la valeur du mot-clé webdir dans votre fichier de configuration manweb, soit le défaut /usr/man/web.

Vos paramètres d'invocation forment une "chaîne de sujets". En allant de gauche à droite, le premier paramètre est le sujet principal, le 2ème est un sous-sujet du sujet principal, et ainsi de suite.

Examinons le cas simple où vous spécifiez exactement un paramètre - un sujet principal. Nous l'appellerons sujetprincipal et examinerons 4 façons dont manweb pourrait le trouver :

  • Si manweb trouve un fichier nommé sujetprincipal.html
    dans le répertoire web, l'URL que manweb transmet au
    navigateur est juste une URL file: qui spécifie ce fichier .html.

  • S'il n'y a pas de fichier .html, mais qu'il y a un fichier nommé
    sujetprincipal.url, le contenu de la première ligne de
    ce fichier .url est ce que manweb transmet au navigateur. Il
    n'interprète pas du tout le contenu. Si c'est du charabia, le
    navigateur s'étouffe avec.

  • S'il n'y a ni fichier .html ni fichier .url, mais qu'il y a un
    répertoire nommé sujetprincipal, manweb cherche dans le
    répertoire un fichier nommé index.html. S'il y en a un,
    manweb transmet une URL file: spécifiant ce fichier
    index.html au navigateur. S'il n'y a pas d'
    index.html, manweb utilise une URL file: qui
    spécifie le répertoire lui-même.

  • Si manweb ne trouve pas la documentation par l'une des
    manières ci-dessus, il recherche dans votre chemin de recherche d'exécutables (tel que défini
    par votre variable d'environnement PATH) un programme nommé
    sujetprincipal. S'il en trouve un, il recherche dans le répertoire
    qui contient le programme un fichier nommé doc.url. S'il
    en trouve un, il ajoute sujetprincipal.html à la
    première ligne du fichier et transmet cela au navigateur. Sauf si
    la première ligne ne se termine pas par une barre oblique - dans ce
    cas, manweb transmet la première ligne du fichier telle quelle
    au navigateur.

Cela devient un peu plus intéressant lorsque vous avez des sous-sujets. En regardant chacun des 4 cas ci-dessus :


  • Là où sujetprincipal.html existe, les sous-sujets sont invalides.
    Vous recevez un message d'avertissement et les sous-sujets sont ignorés.


  • Là où il n'y a pas de fichier .html mais sujetprincipal.url existe,
    manweb ajoute la chaîne de sous-sujets à l'URL qu'il obtient du
    fichier .url comme dans l'exemple suivant : le fichier .url contient
    http://acme.com/productxyz/ et les sous-sujets sont
    create et
    database. L'URL que manweb transmet au navigateur est
    http://acme.com/productxyz/create/database.html.

    manweb ne vérifie pas que ce type d'ajout a du sens pour l'URL en question, sauf que si l'URL dans le
    fichier .url ne se termine pas par une barre oblique (/), manweb
    émet un avertissement et n'ajoute rien (ignore les sous-sujets).


  • Là où il n'y a ni fichier .html ni fichier .url, mais qu'il y a un
    répertoire sujetprincipal, manweb se recursive dans ce
    répertoire et commence une toute nouvelle recherche en utilisant le premier sous-sujet
    comme sujet principal et le reste des sous-sujets comme sous-sujets de celui-ci.


  • Quand il y a des sous-sujets, le truc PATH n'a pas de sens,
    donc manweb ne le fait pas.

    Si vous donnez des sous-sujets, la chose PATH décrite ci-dessus pour un sujet ne s'applique pas.

Si manweb ne trouve pas de documentation correspondante pour le sujet principal après avoir fait ces recherches, il exécute la commande man avec vos paramètres.

Il recherche ensuite un sujet Info. Si vous lui avez donné une chaîne de sujets, il fait une recherche récursive dans les sujets Info comme il le fait avec les répertoires de fichiers.

Si aucune documentation Info n'est trouvée, il exécute man.

CONFIGURATION

Vous pouvez spécifier un fichier de configuration en utilisant le mot-clé -config=fichier.

Les fichiers de configuration sont de simples fichiers texte. Les lignes qui commencent par un # sont ignorées. Les lignes qui ne commencent pas par un # sont traitées comme des mots-clés et une valeur.

Les mots-clés pris en charge sont :

webdir

Ce mot-clé spécifie le répertoire dans lequel manweb recherche la documentation HTML et URL. La valeur est un chemin absolu ou relatif.

Si vous ne spécifiez pas ce mot-clé, le répertoire par défaut est /usr/man/web.

browser

Ce mot-clé spécifie quel navigateur web utiliser. La valeur est le nom de la commande à exécuter pour lancer le navigateur.

Si vous ne spécifiez pas ce mot-clé, manweb utilise la valeur de la variable d'environnement BROWSER, si elle existe. Sinon, il utilise le navigateur par défaut du système.

man

Ce mot-clé spécifie quelle commande utiliser pour les pages man traditionnelles. La valeur est le nom de la commande.

Si vous ne spécifiez pas ce mot-clé, manweb utilise la commande man.

info

Ce mot-clé spécifie quelle commande utiliser pour la documentation Info. La valeur est le nom de la commande.

Si vous ne spécifiez pas ce mot-clé, manweb utilise la commande info.

Voici un exemple de fichier de configuration :

# Mon fichier de configuration manweb
webdir=/srv/www/man
browser=firefox
man=gman
info=texinfo

manweb(1) — netpbm documentation

NAME

manweb - web interface to man pages

SYNOPSIS

manweb [options] [section] [command]

EXAMPLES

manweb

manweb graphics

manweb -config /etc/manweb.conf graphics

manweb -browser lynx graphics

DESCRIPTION

manweb is a utility that serves manual pages as HTML pages via the web. It is most useful as a CGI script, but can also be run directly.

The URL for manweb can be generated in several ways.

  • If the command line has no arguments, manweb generates a URL for the main index page of the web directory.

  • If the command line has one argument, manweb assumes it is the name of a subdirectory of the web directory, and generates a URL for that subdirectory.

  • If the command line has two arguments, manweb assumes the first argument is a subdirectory name and the second is the name of a man page within that subdirectory, and generates a URL for that man page.

If you give no parameters at all, manweb generates a URL for the web directory itself as described above for subdirectories.

The above is simplified by the assumption of a single web directory. In reality, the webdir keyword in the configuration file can specify a chain of web directories. manweb searches each one in turn, doing all the kinds of searches in each web directory before moving on to the next one.

The Configuration File

The default location of the manweb configuration file is /etc/manweb.conf. But you can override this with the environment variable MANWEB_CONF_FILE, and override that with the -config invocation option.

Lines starting with "#" are comments and are ignored, as are blank lines.

All other lines have the format keyword=value. The keywords defined are:

webdir


A colon-delimited sequence of directories to search for
documentation as described above. If you
don't specify this, the default is /usr/man/web alone.

browser


The file specification manweb of the web browser manweb
is to invoke
to display documentation (except when it uses man to display
a conventional man page).
If the file specification does not include a slash, manweb
searches for the file in the PATH search path.

If you don't specify this, the default is the value of the
BROWSER environment variable, and if that is not set,
lynx.

Example:

# Configuration file for Manweb
webdir=/usr/share/manweb
browser=netscape
