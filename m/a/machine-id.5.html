NOM

machine-id - Fichier de configuration de l'identifiant machine local

SYNTAXE

/etc/machine-id

DESCRIPTION

Le fichier /etc/machine-id contient l'identifiant unique de la machine locale qui est défini lors de l'installation ou du démarrage. L'identifiant machine est un identifiant unique, hexadécimal, de 32 caractères, en minuscules, se terminant par un retour à la ligne. Lorsqu'il est décodé de l'hexadécimal, cela correspond à une valeur de 16 octets / 128 bits. Cet identifiant ne peut pas être entièrement constitué de zéros.

L'identifiant machine est généralement généré à partir d'une source aléatoire lors de l'installation du système ou du premier démarrage et reste constant pour tous les démarrages ultérieurs. Optionnellement, pour les systèmes sans état (stateless), il est généré au moment de l'exécution pendant le démarrage précoce si nécessaire.

L'identifiant machine peut être défini, par exemple lors du démarrage en réseau, avec le paramètre de ligne de commande du noyau systemd.machine_id= ou en passant l'option --machine-id= à systemd. Un identifiant spécifié de cette manière a une priorité plus élevée et sera utilisé à la place de l'identifiant stocké dans /etc/machine-id.

L'identifiant machine ne change pas en fonction de la configuration locale ou réseau, ni lors du remplacement de matériel. En raison de cela et de sa longueur plus importante, il constitue un remplacement plus utile de l'appel gethostid(3) spécifié par POSIX.

Cet identifiant machine respecte le même format et la même logique que l'identifiant machine D-Bus.

Cet identifiant identifie l'hôte de manière unique. Il doit être considéré comme « confidentiel » et ne doit pas être exposé dans des environnements non fiables, en particulier sur le réseau. Si un identifiant unique stable lié à la machine est nécessaire pour une application, l'identifiant machine ou une partie de celui-ci ne doit pas être utilisé directement. Au lieu de cela, l'identifiant machine doit être haché avec une fonction de hachage cryptographique, à clé, en utilisant une clé fixe et spécifique à l'application. De cette façon, l'identifiant sera correctement unique et dérivé de manière constante de l'identifiant machine, mais il n'y aura aucun moyen de récupérer l'identifiant machine d'origine à partir de celui spécifique à l'application. L'API sd_id128_get_machine_app_specific(3) fournit une implémentation d'un tel algorithme.

INITIALISATION

Chaque machine doit avoir un identifiant non vide en fonctionnement normal. L'identifiant de chaque machine doit être unique. Pour atteindre ces objectifs, /etc/machine-id peut être initialisé de plusieurs manières différentes.

Pour les installations normales de systèmes d'exploitation, où une image personnalisée est créée pour une machine spécifique, /etc/machine-id doit être peuplé lors de l'installation.

systemd-machine-id-setup(1) peut être utilisé par les outils d'installation pour initialiser l'identifiant machine au moment de l'installation, mais /etc/machine-id peut également être écrit par tout autre moyen.

Pour les images de systèmes d'exploitation qui sont créées une fois et utilisées sur plusieurs machines, par exemple pour les conteneurs ou dans le cloud, /etc/machine-id doit être soit manquant, soit un fichier vide dans l'image système de fichiers générique (la différence entre les deux options est décrite ci-dessous sous "Sémantique du premier démarrage"). Un identifiant sera généré lors du démarrage et enregistré dans ce fichier si possible. Avoir un fichier vide en place est recommandé car cela permet de monter un fichier temporaire par-dessus le fichier réel, dans le cas où l'image est utilisée en lecture seule et lorsque /etc est monté en lecture seule au début du démarrage. Voir aussi Construire des images en toute sécurité[1].

systemd-firstboot(1) peut être utilisé pour initialiser /etc/machine-id sur des images système montées (mais pas démarrées).

Lorsqu'une machine démarre avec systemd(1), l'identifiant de la machine sera établi. Si les options systemd.machine_id= ou --machine-id= (voir la première section) sont spécifiées, cette valeur sera utilisée. Sinon, la valeur dans /etc/machine-id sera utilisée. Si ce fichier est vide ou manquant, systemd tentera d'utiliser l'identifiant machine D-Bus de /var/lib/dbus/machine-id, la valeur de l'option de ligne de commande du noyau container_uuid, le KVM DMI product_uuid ou le devicetree vm,uuid (sur les systèmes KVM), l'UUID de l'hyperviseur Xen, et enfin un UUID généré aléatoirement. systemd.machine_id=firmware peut être défini pour générer l'identifiant machine à partir du firmware.

Une fois l'identifiant machine établi, systemd(1) tentera de l'enregistrer dans /etc/machine-id. Si cela échoue, il tentera de monter un fichier temporaire par-dessus /etc/machine-id. C'est une erreur si le système de fichiers est en lecture seule et ne contient pas un fichier /etc/machine-id (éventuellement vide).

systemd-machine-id-commit.service(8) tentera d'écrire l'identifiant machine sur le système de fichiers si /etc/machine-id ou /etc/ sont en lecture seule pendant le démarrage précoce mais deviennent accessibles en écriture plus tard.

SÉMANTIQUE DU PREMIER DÉMARRAGE

Le fichier /etc/machine-id est utilisé pour décider si un démarrage est le premier. Les règles sont les suivantes :

1.L'argument de ligne de commande du noyau systemd.condition_first_boot= peut être utilisé pour outrepasser la logique de détection automatique, voir kernel-command-line(7).
2.Sinon, si /etc/machine-id n'existe pas, c'est un premier démarrage. Pendant le démarrage précoce, systemd écrira "uninitialized\n" dans ce fichier et montera par-dessus un fichier temporaire contenant l'identifiant machine réel. Plus tard (après l'atteinte de first-boot-complete.target), l'identifiant machine réel sera écrit sur le disque.
3.Si /etc/machine-id contient la chaîne "uninitialized", un démarrage est également considéré comme le premier démarrage. Le même mécanisme que ci-dessus s'applique.
4.Si /etc/machine-id existe et est vide, un démarrage n'est *pas* considéré comme le premier démarrage. systemd montera toujours un fichier contenant l'identifiant machine réel par-dessus et tentera plus tard de le valider sur le disque (si /etc/ est accessible en écriture).
5.Si /etc/machine-id contient déjà un identifiant machine valide, ce n'est pas un premier démarrage.

Si, selon les règles ci-dessus, un premier démarrage est détecté, les unités avec ConditionFirstBoot=yes seront exécutées et systemd effectuera des étapes d'initialisation supplémentaires, en particulier la préconfiguration des unités.

RELATION AVEC LES UUIDS OSF

Il est à noter que l'identifiant machine n'est historiquement pas un UUID OSF tel que défini par la RFC 4122[2], ni un GUID Microsoft ; cependant, à partir de systemd v30, les nouveaux identifiants machines générés sont conformes aux UUID Version 4, Variante 1, selon la RFC 4122.

Afin de maintenir la compatibilité avec les installations existantes, une application nécessitant un UUID strictement conforme à la RFC 4122 doit décoder l'identifiant machine, puis (de manière irréversible) appliquer les opérations suivantes pour le transformer en un UUID Variant 1 Version 4 conforme à la RFC 4122. Avec "id" étant un tableau de caractères non signé :

/* Définir la version de l'UUID à 4 --- génération réellement aléatoire */
id[6] = (id[6] & 0x0F) | 0x40;
/* Définir le variant de l'UUID à DCE */
id[8] = (id[8] & 0x3F) | 0x80;

(Ce code est inspiré de "generate_random_uuid()" de drivers/char/random.c des sources du noyau Linux.)

HISTORIQUE

Le format de fichier de configuration simple de /etc/machine-id provient du fichier /var/lib/dbus/machine-id introduit par D-Bus. En fait, ce dernier fichier peut être un lien symbolique vers /etc/machine-id.
