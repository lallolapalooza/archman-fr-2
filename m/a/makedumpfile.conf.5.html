MAKEDUMPFILE.CONF(5) Manuel de l'administrateur système Linux MAKEDUMPFILE.CONF(5)

NOM

makedumpfile.conf - Le fichier de configuration de filtre pour makedumpfile(8).

DESCRIPTION

makedumpfile.conf est un fichier de configuration pour l'outil makedumpfile. Le fichier makedumpfile.conf contient les commandes d'effacement pour filtrer les données désirées du noyau à partir du vmcore lors de la création de DUMPFILE en utilisant l'outil makedumpfile. makedumpfile lit la configuration du filtre et construit la liste des adresses mémoire et leurs tailles après traitement des commandes de filtre. Les emplacements mémoire qui nécessitent d'être filtrés sont ensuite corrompus avec le caractère X (58 en hexadécimal).

FORMAT DU FICHIER

Le fichier se compose de sections de modules qui contiennent des commandes de filtre. Une section commence par le nom de la section entre crochets et continue jusqu'à ce qu'une autre section commence.

"["<NomModule>"]"
<CommandesFiltre>

où
"[" est le caractère [
"]" est le caractère ]

<NomModule>
est soit 'vmlinux', soit le nom d'un module du noyau Linux.
<CommandesFiltre>
est une liste d'une ou plusieurs commandes de filtre telles que décrites dans la section COMMANDES FILTRE de cette page de manuel.

Le nom de la section indique le nom d'un module du noyau (y compris vmlinux) auquel appartiennent les symboles spécifiés dans les commandes d'effacement suivantes. La section sans nom par défaut est la section [vmlinux]. Cependant, un utilisateur peut aussi définir explicitement la section [vmlinux]. Les sections aident l'outil makedumpfile à sélectionner le fichier debuginfo du noyau ou du module approprié avant de traiter les commandes d'effacement suivantes. Avant de sélectionner le fichier debuginfo approprié, le nom du module est validé par rapport aux modules chargés du vmcore. Si aucune correspondance n'est trouvée, la section est ignorée et makedumpfile passe à la section de module suivante. Si une correspondance est trouvée, makedumpfile essaiera de charger le fichier debuginfo du module correspondant. Si le debuginfo du module n'est pas disponible, makedumpfile ignorera la section avec un message d'avertissement.

COMMANDES FILTRE

commande filtre

Une commande de filtre est soit une commande d'effacement, soit une construction de boucle. Chaque commande d'effacement et construction de boucle doit commencer sur une nouvelle ligne. Chaque commande de filtre décrit les données dans la vidage à effacer. Syntaxe :

<CommandesEffacement>|<ConstructionBoucle>

où

<CommandesEffacement>
Décrit dans la sous-section commande effacement de cette page de manuel.
<ConstructionBoucle>
Décrit dans la sous-section Construction de boucle de cette page de manuel.

commande effacement

Efface une taille spécifiée de données du noyau référencée par un symbole du noyau/module spécifié ou son composant membre. La syntaxe de la commande d'effacement est :

erase <Symbole>[.membre[...]] [taille <ValeurTaille>[K|M]]
erase <Symbole>[.membre[...]] [taille <SymboleTaille>]
erase <Symbole>[.membre[...]] [nullifier]

où

<Symbole>
Un nom de symbole (variable) du noyau ou du module qui fait partie des symboles globaux de /proc/kallsyms.
<ValeurTaille>
Une valeur entière positive comme taille des données en octets à effacer. Les suffixes 'K' et 'M' peuvent être utilisés pour spécifier des kilo-octets et des méga-octets respectivement, où K signifie 1024 octets et M signifie 1024 ^ 2 = 1048576 octets. Les suffixes ne sont pas sensibles à la casse.
<SymboleTaille>
Une expression simple de la forme <Symbole>[.membre[...]] qui représente un symbole contenant une valeur entière positive comme taille des données en octets à effacer.
<Symbole>[.membre[...]]
Une expression simple qui résulte soit en un nom de symbole global du noyau, soit en ses composants membres. L'expression utilise toujours l'opérateur '.' pour spécifier le composant membre du symbole du noyau ou de ses membres, que ce soit un type pointeur ou non.
membre[...]
Membre ou composant de membre dans <Symbole>.

La commande erase prend deux arguments : 1. le nom du symbole du noyau ou ses composants membres et 2. la taille des données référencées par l'argument (1) OU le mot-clé nullifier. Le deuxième argument taille OU nullifier est optionnel. L'unité pour la valeur de taille est en octets. Si l'option taille n'est pas spécifiée, la taille du premier argument est déterminée selon son type de données en utilisant les informations dwarf du fichier debuginfo. Dans le cas du type de données 'char *', la longueur de la chaîne pointée par le pointeur 'char *' est déterminée avec une limite supérieure de 1024. La taille peut être spécifiée sous deux formes : 1. une valeur entière comme expliqué ci-dessus (<ValeurTaille>) et 2. une expression simple sous la forme de <Symbole>[.membre[...]]] qui résulte en une variable de type de base (entier).

Si le <Symbole> spécifié est de type 'void *', l'utilisateur doit fournir l'option taille ou nullifier, sinon la commande d'effacement n'aura aucun effet.

L'option nullifier ne fonctionne que si le <Symbole> spécifié est un pointeur. Au lieu d'effacer les données pointées par le pointeur spécifié, nullifier efface la valeur du pointeur et la met à '0' (NULL). Veuillez noter que la nullification des valeurs des pointeurs peut affecter la capacité de débogage du DUMPFILE créé. Utilisez l'option nullifier uniquement lorsque la taille des données à effacer n'est pas connue. par ex. les données pointées par 'void *'.

Examinons le fichier makedumpfile.conf de l'exemple ci-dessous qui a été configuré pour effacer les données désirées du noyau du module du noyau nommé mymodule. Aux lignes 1 et 3, l'utilisateur n'a pas spécifié d'option de taille lors de l'effacement des symboles 'array_var' et 'mystruct1.name'. Au lieu de cela, l'utilisateur compte sur makedumpfile pour déterminer automatiquement les tailles à effacer, c'est-à-dire 100 octets pour 'array_var' et 11 octets pour 'mystruct1.name'. À la ligne 2, lors de l'effacement du membre 'mystruct1.buffer', l'utilisateur a spécifié la valeur de taille 25 contre la taille réelle de 50. Dans ce cas, la taille spécifiée par l'utilisateur prend le dessus et makedumpfile n'efface que 25 octets de ´mystruct1.buffer'. À la ligne 4, la taille des données pointées par le pointeur void * 'mystruct1.addr1' est inconnue. Par conséquent, l'option nullifier a été spécifiée pour réinitialiser la valeur du pointeur à NULL. À la ligne 5, le '´mystruct2.addr_size' est spécifié comme argument de taille pour déterminer la taille des données pointées par le pointeur void * 'mystruct2.addr'.

Exemple :

En supposant que le fragment de code suivant provient du module du noyau 'mymodule' :

struct s1 {
char *name;
void *addr1;
void *addr2;
char buffer[50];
};
struct s2 {
void *addr;
long addr_size;
};

/* Symboles globaux */
char array_var[100];
struct s1 mystruct1;
struct s2 *mystruct2;

int foo()
{
...
s1.name = "Hello World";
...
}

makedumpfile.conf :
[mymodule]
erase array_var
erase mystruct1.buffer size 25
erase mystruct1.name
erase mystruct1.addr1 nullify
# Supposons que addr2 pointe vers 1024 octets
erase mystruct1.addr2 size 1K
erase mystruct2.addr size mystruct2.addr_size
EOF

Construction de boucle

Une construction de boucle permet à l'utilisateur de parcourir les éléments d'une liste chaînée ou d'un tableau et d'effacer le contenu des données référencées par chaque élément.

for <id> in {<VarTableau> |
<VarStructure> via <MembreSuivant> |
<VarTeteListe> dans <NomStructure>:<MembreTeteListe>}
erase <id>[.ExpressionMembre] [taille <ExpressionTaille>|nullifier]
[erase <id>...]
[...]
endfor

où

<id>

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

class="Bl-tag">
<id>
Nom arbitraire utilisé pour pointer temporairement vers les éléments de la liste. C'est aussi appelé variable d'itération.
<ArrayVar>
Une expression simple sous la forme de <Symbole>[.membre[...]] qui aboutit à une variable tableau.
<StructVar>
Une expression simple sous la forme de <Symbole>[.membre[...]] qui aboutit à une variable pointant vers une structure.
<NextMember>
Membre à l'intérieur de <StructVar> qui pointe vers un objet du même type que <StructVar>.
<ListHeadVar>
Une expression simple sous la forme de <Symbole>[.membre[...]] qui aboutit à une variable de type struct list_head.
<StructName>
Nom du type de structure qui peut être parcouru en utilisant la variable HEAD <ListHeadVar> et qui contient un membre nommé <ListHeadMember>.
<ListHeadMember>
Nom d'un membre dans <StructName>, de type struct list_head.
<MemberExpression>
Une expression simple sous la forme de [.membre[...]] pour spécifier un membre ou un composant d'un élément dans <ArrayVar>, <StructVar> ou <StructName>.
<SizeExpression>
Valeur de taille sous la forme de <SizeValue>, <id>[.MemberExpression] ou <Symbole>[.membre[...]].

La construction de boucle for permet d'itérer sur une liste d'éléments dans un tableau ou des listes chaînées. Chaque élément de la liste est assigné à la variable d'itération <id>. Le type de la variable d'itération est déterminé par celui des éléments de la liste. L'entrée spécifiée après le terminal 'in' est appelée entrée LIST. L'entrée LIST peut être une variable tableau, une variable/pointeur structure ou une variable de type struct list_head. L'ensemble des commandes erase spécifiées entre for et endfor sera exécuté pour chaque élément de l'entrée LIST.

Si l'entrée LIST spécifiée est une variable tableau, la boucle sera exécutée pour chaque élément du tableau. La taille du tableau sera déterminée en utilisant les informations dwarf.

Si l'entrée LIST spécifiée est une variable/pointeur structure, un membre de parcours (<NextMember>) doit être spécifié en utilisant le terminal 'via'. La boucle for continuera jusqu'à ce que la valeur du membre de parcours soit NULL ou corresponde à l'adresse du premier nœud <StructVar> s'il s'agit d'une liste chaînée circulaire.

Si l'entrée LIST est spécifiée en utilisant une variable de type struct list_head, le terminal within doit être utilisé pour spécifier le nom de la structure <StructName> qui la contient ainsi que le membre de type struct list_head après ':' qui fait partie de la liste chaînée. Dans l'instruction erase, <id> désigne alors la structure dans laquelle se trouve la list_head (ELEMENT_OF).

L'exemple ci-dessous illustre comment utiliser la construction de boucle pour parcourir un tableau, une liste chaînée via un membre suivant et une list_head.

Exemple :

En supposant que le morceau de code suivant provient du module noyau 'mymodule' :

struct s1 {
struct *next;
struct list_head list;
char private[100];
void *key;
long key_size;
};

/* Symboles globaux */
struct s1 mystruct1;
static LIST_HEAD(s1_list_head);
struct s1 myarray[100];

void foo()
{
struct s1 *s1_ptr;
...
...
s1_ptr = malloc(...);
...
...
list_add(&s1_ptr->list, &s1_list_head);
...
}

makedumpfile.conf :
[mymodule]
# effacer les champs privés de la liste commençant par mystruct1 connectée via
# le membre 'next':
for mys1 in mystruct1 via next
erase mys1.private
erase mys1.key size mys1.key_size
endfor

# effacer les champs privés de la liste commençant par la variable list_head
# s1_list_head.
for mys1 in s1_list_head.next within s1:list
erase mys1.private
erase mys1.key size mys1.key_size
endfor

# effacer les champs privés de tous les éléments du tableau myarray :
for mys1 in myarray
erase mys1.private
erase mys1.key size mys1.key_size
endfor
EOF

Dans l'exemple ci-dessus, la première construction for parcourt la liste chaînée à travers une variable structure spécifiée mystruct1 de type struct s1. La liste chaînée peut être parcourue en utilisant le membre 'next' de mystruct1. Par conséquent, un terminal via a été utilisé pour spécifier le nom du membre de parcours 'next'.

La deuxième construction for parcourt la liste chaînée à travers une variable struct list_head spécifiée s1_list_head.next. Le symbole global s1_list_head est l'adresse de départ de la liste chaînée et son membre next pointe vers l'adresse du membre de type struct list_head 'list' de struct s1. Par conséquent, un terminal within est utilisé pour spécifier le nom de la structure 's1' qui peut être parcourue en utilisant la variable s1_list_head.next ainsi que le nom du membre de type struct list_head 'list' qui fait partie de la liste chaînée commençant par le symbole global s1_list_head.

La troisième construction for parcourt les éléments du tableau spécifiés par la variable tableau myarray.
