NOM

mariadbd-multi - gérer plusieurs serveurs MariaDB (mariadbd-multi est maintenant un lien symbolique vers mariadbd-multi)

SYNTAXE

mariadbd-multi [options] {start|stop|report} [GNR[,GNR] ...]

DESCRIPTION

mariadbd-multi est conçu pour gérer plusieurs processus mariadbd qui écoutent les connexions sur différents fichiers de socket Unix et ports TCP/IP. Il peut démarrer, arrêter des serveurs ou signaler leur état actuel.

mariadbd-multi recherche des groupes nommés [mariadbdN] dans my.cnf (ou dans le fichier spécifié par l'option --config-file). N peut être n'importe quel entier positif. Ce nombre est désigné dans la discussion suivante comme le numéro de groupe d'options, ou GNR. Les numéros de groupe distinguent les groupes d'options les uns des autres et sont utilisés comme arguments pour mariadbd-multi afin de spécifier quels serveurs vous souhaitez démarrer, arrêter ou pour lesquels vous souhaitez obtenir un rapport d'état. Les options listées dans ces groupes sont les mêmes que celles que vous utiliseriez dans le groupe [mariadbd] utilisé pour démarrer mariadbd. Cependant, lors de l'utilisation de plusieurs serveurs, il est nécessaire que chacun utilise sa propre valeur pour des options telles que le fichier de socket Unix et le numéro de port TCP/IP.

Pour invoquer mariadbd-multi, utilisez la syntaxe suivante :

shell> mariadbd-multi [options] {start|stop|report} [GNR[,GNR] ...]

start, stop et report indiquent l'opération à effectuer. Vous pouvez effectuer l'opération désignée pour un seul serveur ou plusieurs serveurs, en fonction de la liste GNR qui suit le nom de l'option. S'il n'y a pas de liste, mariadbd-multi effectue l'opération pour tous les serveurs du fichier d'options.

Chaque valeur GNR représente un numéro de groupe d'options ou une plage de numéros de groupe. La valeur doit être le numéro à la fin du nom du groupe dans le fichier d'options. Par exemple, le GNR d'un groupe nommé [mariadbd17] est 17. Pour spécifier une plage de nombres, séparez le premier et le dernier nombre par un tiret. La valeur GNR 10-13 représente les groupes [mariadbd10] à [mariadbd13]. Plusieurs groupes ou plages de groupes peuvent être spécifiés sur la ligne de commande, séparés par des virgules. Il ne doit y avoir aucun espace blanc (espaces ou tabulations) dans la liste GNR ; tout ce qui suit un espace blanc est ignoré.

Cette commande démarre un seul serveur en utilisant le groupe d'options [mariadbd17] :

shell> mariadbd-multi start 17

Cette commande arrête plusieurs serveurs, en utilisant les groupes d'options [mariadbd8] et [mariadbd10] à [mariadbd13] :

shell> mariadbd-multi stop 8,10-13

Pour un exemple de la manière dont vous pourriez configurer un fichier d'options, utilisez cette commande :

shell> mariadbd-multi --example

mariadbd-multi recherche les fichiers d'options comme suit :

•Avec --no-defaults, aucun fichier d'options n'est lu.
•Avec --defaults-file=nom_fichier, seul le fichier nommé est lu.
•Sinon, les fichiers d'options aux emplacements standard sont lus, y compris tout fichier nommé par l'option --defaults-extra-file=nom_fichier, si elle est fournie. (Si l'option est donnée plusieurs fois, la dernière valeur est utilisée.)

Les fichiers d'options lus sont recherchés pour les groupes d'options [mariadbd-multi] et [mariadbdN]. Le groupe [mariadbd-multi] peut être utilisé pour les options de mariadbd-multi lui-même. Les groupes [mariadbdN] peuvent être utilisés pour les options transmises à des instances spécifiques de mariadbd.

Les groupes [mariadbd] ou [mariadbd_safe] peuvent être utilisés pour les options communes lues par toutes les instances de mariadbd ou mariadbd_safe. Vous pouvez spécifier une option --defaults-file=nom_fichier pour utiliser un fichier de configuration différent pour cette instance, auquel cas les groupes [mariadbd] ou [mariadbd_safe] de ce fichier seront utilisés pour cette instance.

mariadbd-multi prend en charge les options suivantes.

•--help

Afficher un message d'aide et quitter.

•--example

Afficher un exemple de fichier d'options.

•--log=nom_fichier

Spécifier le nom du fichier journal. Si le fichier existe, la sortie du journal lui sera ajoutée.

•--mariadb-admin=nom_prog

Le binaire mariadb-admin à utiliser pour arrêter les serveurs.

•--mariadbd=nom_prog

Le binaire mariadbd à utiliser. Notez que vous pouvez également spécifier mariadbd_safe comme valeur pour cette option. Si vous utilisez mariadbd_safe pour démarrer le serveur, vous pouvez inclure les options mariadbd ou ledir dans le groupe d'options [mariadbdN] correspondant. Ces options indiquent le nom du serveur que mariadbd_safe doit démarrer et le chemin du répertoire où se trouve le serveur. (Voir les descriptions de ces options dans mariadbd_safe(1).) Exemple :

[mariadbd38]
mariadbd = mariadbd-debug
ledir  = /opt/local/mysql/libexec
•--no-log

Afficher les informations du journal sur stdout plutôt que dans le fichier journal. Par défaut, la sortie va dans le fichier journal.

•--password=mot_de_passe

Le mot de passe du compte MariaDB à utiliser lors de l'invocation de mariadb-admin. Notez que la valeur du mot de passe n'est pas facultative pour cette option, contrairement à d'autres programmes MariaDB.

•--silent

Mode silencieux ; désactiver les avertissements.

•--tcp-ip

Se connecter aux serveurs MariaDB via le port TCP/IP au lieu du socket UNIX. Cela affecte l'arrêt et le rapport. Si un fichier de socket est manquant, le serveur peut toujours être en cours d'exécution, mais ne peut être accédé que via le port TCP/IP. Par défaut, la connexion se fait via le socket UNIX. Cette option affecte les opérations d'arrêt et de rapport.

•--user=nom_utilisateur

Le nom d'utilisateur du compte MariaDB à utiliser lors de l'invocation de mariadb-admin.

•--verbose

Être plus verbeux.

•--version

Afficher les informations de version et quitter.

•--wsrep-new-cluster

Démarrer un cluster.

Quelques notes sur mariadbd-multi :

•Le plus important : Avant d'utiliser mariadbd-multi, assurez-vous de bien comprendre la signification des options transmises aux serveurs mariadbd et pourquoi vous souhaiteriez avoir des processus mariadbd distincts. Méfiez-vous des dangers d'utiliser plusieurs serveurs mariadbd avec le même répertoire de données. Utilisez des répertoires de données séparés, sauf si vous savez ce que vous faites. Démarrer plusieurs serveurs avec le même répertoire de données ne vous apporte pas de performances supplémentaires dans un système à threads.
•Important : Assurez-vous que le répertoire de données de chaque serveur est entièrement accessible par le compte Unix sous lequel le processus mariadbd spécifique est démarré. N'utilisez pas le compte Unix root pour cela, sauf si vous savez ce que vous faites.
•Assurez-vous que le compte MariaDB utilisé pour arrêter les serveurs mariadbd (avec le programme mariadbadmin) a le même nom d'utilisateur et mot de passe pour chaque serveur. Assurez-vous également que le compte a le privilège SHUTDOWN. Si les serveurs que vous souhaitez gérer ont des noms d'utilisateur ou des mots de passe différents pour les comptes administratifs, vous pourriez vouloir créer un compte sur chaque serveur qui a le même nom d'utilisateur et mot de passe. Par exemple, vous pourriez configurer un compte multi_admin commun en exécutant les commandes suivantes pour chaque serveur : 
shell> mariadb -u root -S /tmp/mariadb.sock -p
Entrer le mot de passe :
mariadb> GRANT SHUTDOWN ON *.*
    -> TO 'multi_admin'@'localhost' IDENTIFIED BY 'multipass';

Modifiez les paramètres de connexion de manière appropriée lors de la connexion à chacun d'eux. Notez que la partie nom d'hôte du nom de compte doit vous permettre de vous connecter en tant que multi_admin depuis l'hôte où vous souhaitez exécuter mariadbd-multi.

Si l'hôte possède plusieurs adresses réseau, vous pouvez utiliser --bind-address pour que différents serveurs écoutent sur différentes interfaces.

•L'option --pid-file est très importante si vous utilisez mariadbd-safe pour démarrer mariadbd (par exemple, --mariadbd=mariadbd-safe). Chaque mariadbd doit avoir son propre fichier d'ID de processus. L'avantage d'utiliser mariadbd-safe au lieu de mariadbd est que mariadbd-safe surveille son processus mariadbd et le redémarre si le processus se termine en raison d'un signal envoyé avec kill -9 ou pour d'autres raisons, telles qu'une faute de segmentation. Veuillez noter que le script mariadbd-safe peut exiger que vous le démarriez depuis un certain endroit. Cela signifie que vous pourriez avoir à changer de répertoire avant d'exécuter mariadbd-multi. Si vous rencontrez des problèmes pour démarrer, veuillez consulter le script mariadbd-safe. Vérifiez en particulier les lignes : 
----------------------------------------------------------------
MY_PWD=`pwd`
# Check if we are starting this relative (for the binary release)
if test -d $MY_PWD/data/mariadb -a \
   -f ./share/mariadb/english/errmsg.sys -a \
   -x ./bin/mariadbd
----------------------------------------------------------------

Le test effectué par ces lignes doit réussir, sinon vous pourriez rencontrer des problèmes. Voir mariadbd-safe(1).

•Vous pourriez vouloir utiliser l'option --user pour mariadbd, mais pour ce faire, vous devez exécuter le script mariadbd-multi en tant qu'utilisateur root Unix. Avoir l'option dans le fichier d'options n'a pas d'importance ; vous obtiendrez juste un avertissement si vous n'êtes pas le superutilisateur et que les processus mariadbd sont démarrés sous votre propre compte Unix.

L'exemple suivant montre comment vous pourriez configurer un fichier d'options pour une utilisation avec mariadbd-multi. L'ordre dans lequel les programmes mariadbd sont démarrés ou arrêtés dépend de l'ordre dans lequel ils apparaissent dans le fichier d'options. Les numéros de groupe n'ont pas besoin de former une séquence ininterrompue. Les premier et cinquième groupes [mariadbdN] ont été intentionnellement omis de l'exemple pour illustrer que vous pouvez avoir des « lacunes » dans le fichier d'options. Cela vous donne plus de flexibilité.

# Ce fichier devrait probablement se trouver dans votre répertoire personnel (~/.my.cnf)
# ou dans /etc/my.cnf
# Version 2.1 par Jani Tolonen
[mariadbd-multi]
mariadbd     = /usr/local/bin/mariadbd-safe
mariadb-admin = /usr/local/bin/mariadb-admin
user       = multi_admin
password   = multipass
[mariadbd2]
socket     = /tmp/mariadb.sock2
port       = 3307
pid-file   = /usr/local/mysql/var2/hostname.pid2
datadir    = /usr/local/mysql/var2
language   = /usr/local/share/mariadb/english
user       = john
[mariadbd3]
socket     = /tmp/mysql.sock3
port       = 3308
pid-file   = /usr/local/mysql/var3/hostname.pid3
datadir    = /usr/local/mysql/var3
language   = /usr/local/share/mariadb/swedish
user       = monty
[mariadbd4]
socket     = /tmp/mysql.sock4
port       = 3309
pid-file   = /usr/local/mysql/var4/hostname.pid4
datadir    = /usr/local/mysql/var4
language   = /usr/local/share/mariadb/estonia
user       = tonu
[mariadbd6]
socket     = /tmp/mysql.sock6
port       = 3311
pid-file   = /usr/local/mysql/var6/hostname.pid6
datadir    = /usr/local/mysql/var6
language   = /usr/local/share/mariadb/japanese
user       = jani
