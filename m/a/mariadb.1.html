MARIADB(1) Système de base de données MariaDB MARIADB(1)

NOM

mariadb - l'outil de ligne de commande MariaDB (mysql est maintenant un lien symbolique vers mariadb)

SYNTAXE

mariadb [options] nom_base

DESCRIPTION

mariadb est un simple shell SQL (avec les capacités de lecture de GNU readline). Il prend en charge une utilisation interactive et non interactive. Lorsqu'il est utilisé interactivement, les résultats des requêtes sont présentés dans un format de tableau ASCII. Lorsqu'il est utilisé de manière non interactive (par exemple, comme filtre), le résultat est présenté dans un format séparé par des tabulations. Le format de sortie peut être modifié à l'aide des options de commande.

Si vous rencontrez des problèmes en raison d'une mémoire insuffisante pour les grands ensembles de résultats, utilisez l'option --quick. Cela force mariadb à récupérer les résultats du serveur une ligne à la fois plutôt que de récupérer l'intégralité de l'ensemble de résultats et de le mettre en mémoire tampon avant de l'afficher. Ceci est réalisé en renvoyant l'ensemble de résultats à l'aide de la fonction d'API C mariadb_use_result() de la bibliothèque client/serveur plutôt que mysql_store_result().

L'utilisation de mariadb est très simple. Appelez-le depuis l'invite de votre interpréteur de commandes comme suit :

shell> mariadb nom_base

Ou :

shell> mariadb --user=nom_utilisateur --password=votre_mot_de_passe nom_base

Ensuite, tapez une instruction SQL, terminez-la par “;”, \g, ou \G et appuyez sur Entrée.

Taper Control-C fait que mariadb tente d'annuler l'instruction en cours. Si cela ne peut pas être fait, ou si Control-C est tapé à nouveau avant que l'instruction ne soit annulée, mariadb se termine.

Vous pouvez exécuter des instructions SQL dans un fichier de script (fichier batch) comme ceci :

shell> mariadb nom_base < script.sql > sortie.tab

OPTIONS MARIADB

mariadb prend en charge les options suivantes, qui peuvent être spécifiées sur la ligne de commande ou dans les groupes de fichiers d'options [mariadb], [client], [client-server] ou [client-mariadb]. mariadb prend également en charge les options pour le traitement des fichiers d'options.

•--help, -?, -I

Affiche un message d'aide et quitte.

•--abort-source-on-error

Interrompt les opérations 'source nom_fichier' en cas d'erreur.

•--auto-rehash

Active le re-hachage automatique. Cette option est activée par défaut, ce qui permet la complétion des noms de bases de données, de tables et de colonnes. Utilisez --disable-auto-rehash, --no-auto-rehash, ou --skip-auto-rehash pour désactiver le re-hachage. Cela fait démarrer mariadb plus rapidement, mais vous devez émettre la commande rehash si vous souhaitez utiliser la complétion de noms.

Pour compléter un nom, entrez la première partie et appuyez sur Tab. Si le nom est sans ambiguïté, mariadb le complète. Sinon, vous pouvez appuyer à nouveau sur Tab pour voir les noms possibles qui commencent par ce que vous avez tapé jusqu'à présent. La complétion ne se produit pas s'il n'y a pas de base de données par défaut.

•--auto-vertical-output

Passe automatiquement en mode de sortie verticale si le résultat est plus large que la largeur du terminal.

•--batch, -B

Affiche les résultats en utilisant la tabulation comme séparateur de colonnes, avec chaque ligne sur une nouvelle ligne. Avec cette option, mariadb n'utilise pas le fichier d'historique.

Le mode batch produit un format de sortie non tabulaire et échappe les caractères spéciaux. L'échappement peut être désactivé en utilisant le mode brut ; voir la description de l'option --raw.

•--binary-mode

Le mode binaire permet à certaines séquences de caractères d'être traitées comme des données qui seraient autrement traitées avec une signification spéciale par l'analyseur. Plus précisément, ce commutateur désactive l'analyse de toutes les commandes client sauf \C et DELIMITER en mode non interactif (c'est-à-dire, lorsque le mode binaire est combiné avec soit 1) une entrée pipée, 2) l'option --batch de mariadb, ou 3) la commande 'source'). De plus, en mode binaire, les occurrences de '\r\n' et de '\0' ASCII sont conservées dans les chaînes, alors que par défaut, '\r\n' est traduit en '\n' et '\0' est interdit dans l'entrée utilisateur.

•--character-sets-dir=chemin

Le répertoire où sont installés les jeux de caractères.

•--column-names

Écrit les noms des colonnes dans les résultats.

•--column-type-info, -m

Affiche les métadonnées de l'ensemble de résultats.

•--comments, -c

Indique si les commentaires doivent être conservés dans les instructions envoyées au serveur. La valeur par défaut est --skip-comments (ignorer les commentaires), activez avec --comments (conserver les commentaires).

•--compress, -C

Compresse toutes les informations envoyées entre le client et le serveur si les deux prennent en charge la compression.

•--connect-timeout=secondes

Définit le nombre de secondes avant l'expiration du délai de connexion. (Valeur par défaut : 0.)

•--database=nom_base, -D nom_base

La base de données à utiliser.

•--debug[=options_debug], -# [options_debug]

Écrit un journal de débogage. Une chaîne options_debug typique est 'd:t:o,nom_fichier'. La valeur par défaut est 'd:t:o,/tmp/mysql.trace'.

•--debug-check

Affiche des informations de débogage lors de la sortie du programme.

•--debug-info, -T

Affiche des informations de débogage et des statistiques d'utilisation de la mémoire et du processeur lors de la sortie du programme.

•--default-auth=nom

Plugin client par défaut à utiliser pour l'authentification.

•--default-character-set=nom_jeu_caractere

Utilise nom_jeu_caractere comme jeu de caractères par défaut pour le client et la connexion.

Un problème courant qui peut survenir lorsque le système d'exploitation utilise utf8 ou un autre jeu de caractères multi-octets est que la sortie du client mariadb est mal formatée, en raison du fait que le client MariaDB utilise le jeu de caractères latin1 par défaut. Vous pouvez généralement résoudre ces problèmes en utilisant cette option pour forcer le client à utiliser le jeu de caractères du système à la place.

•--defaults-extra-file=nom_fichier

Définit nom_fichier comme fichier à lire pour les options par défaut après la lecture des fichiers d'options globaux. Doit être donné comme première option.

•--defaults-file=nom_fichier

Définit nom_fichier comme fichier à lire pour les options par défaut, remplaçant les fichiers d'options globaux. Doit être donné comme première option.

•--defaults-group-suffix=suffixe

En plus des groupes nommés sur la ligne de commande, lit les groupes qui ont le suffixe donné.

•--delimiter=str

Définit le délimiteur d'instruction. La valeur par défaut est le point-virgule (“;”).

•--disable-named-commands

Désactive les commandes nommées. Utilisez uniquement la forme \* ou utilisez les commandes nommées uniquement au début d'une ligne se terminant par un point-virgule (“;”). mariadb démarre avec cette option activée par défaut. Cependant, même avec cette option, les commandes au format long fonctionnent toujours à partir de la première ligne. Voir la section “COMMANDES MARIADB”.

•--enable-cleartext-plugin

Option obsolète. Existe uniquement pour la compatibilité MySQL.

•--execute=instruction, -e instruction

Exécute l'instruction et quitte. Désactive --force et le fichier d'historique. Le format de sortie par défaut est similaire à celui produit avec --batch.

•--force, -f

Continue même si une erreur SQL se produit. Définit --abort-source-on-error à 0.

•--host=nom_hote, -h nom_hote

Se connecte au serveur MariaDB sur l'hôte donné.

•--html, -H

Produit une sortie HTML.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

•--ignore-spaces, -i

Ignore les espaces après les noms de fonctions. Permet d'avoir des espaces (y compris les tabulations et les sauts de ligne) entre le nom de la fonction et le '('. L'inconvénient est que cela rend les fonctions intégrées des mots réservés.

•--init-command=str

Commande SQL à exécuter lors de la connexion au serveur MariaDB. Sera automatiquement réexécutée lors de la reconnexion.

•--line-numbers

Affiche les numéros de ligne pour les erreurs. Désactivez ceci avec --skip-line-numbers.

•--local-infile[={0|1}]

Active ou désactive la capacité LOCAL pour LOAD DATA INFILE. Sans valeur, l'option active LOCAL. L'option peut être donnée comme --local-infile=0 ou --local-infile=1 pour désactiver ou activer explicitement LOCAL. L'activation de LOCAL n'a aucun effet si le serveur ne le prend pas également en charge.

•--max-allowed-packet=num

Définit la longueur maximale des paquets à envoyer ou à recevoir du serveur. (Valeur par défaut : 16 Mo, maximum : 1 Go.)

•--max-join-size=num

Définit la limite automatique pour les lignes dans une jointure lors de l'utilisation de --safe-updates. (Valeur par défaut : 1 000 000.)

•--named-commands, -G

Active les commandes nommées mariadb. Les commandes au format long sont autorisées, pas seulement les commandes au format court. Par exemple, quit et \q sont tous deux reconnus. Utilisez --skip-named-commands pour désactiver les commandes nommées. Voir la section « COMMANDES MARIADB ». Désactivé par défaut.

•--net-buffer-length=size

Définit la taille du tampon pour la communication TCP/IP et socket. (Valeur par défaut : 16 Ko.)

•--no-auto-rehash, -A

A le même effet que --skip-auto-rehash. Voir la description de --auto-rehash.

•--no-beep, -b

Ne pas émettre de bip lors d'erreurs.

•--no-defaults

Ne pas lire les options par défaut à partir d'un fichier d'options. Doit être donné comme premier argument.

•--one-database, -o

Ignore les instructions sauf celles qui se produisent pendant que la base de données par défaut est celle nommée dans la ligne de commande. Ce filtrage est limité et basé uniquement sur les instructions USE. Ceci est utile pour ignorer les mises à jour d'autres bases de données dans le journal binaire.

•--pager[=command]

Utilise la commande donnée pour la pagination de la sortie des requêtes. Si la commande est omise, le pager par défaut est la valeur de votre variable d'environnement PAGER. Les pagers valides sont less, more, cat [> filename], et ainsi de suite. Cette option ne fonctionne que sur Unix et uniquement en mode interactif. Pour désactiver la pagination, utilisez --skip-pager. La section « COMMANDES MARIADB » discute plus en détail de la pagination de la sortie.

•--password[=password], -p[password]

Le mot de passe à utiliser lors de la connexion au serveur. Si vous utilisez la forme courte de l'option (-p), vous *ne pouvez pas* laisser d'espace entre l'option et le mot de passe. Si vous omettez la valeur du mot de passe suivant l'option --password ou -p dans la ligne de commande, mariadb en demandera un.

Spécifier un mot de passe dans la ligne de commande doit être considéré comme non sécurisé. Vous pouvez utiliser un fichier d'options pour éviter de donner le mot de passe dans la ligne de commande.

•--pipe, -W

Sous Windows, connectez-vous au serveur via un pipe nommé. Cette option s'applique uniquement si le serveur prend en charge les connexions par pipe nommé.

•--plugin-dir=dir_name

Répertoire pour les plugins côté client.

•--port=port_num, -P port_num

Le numéro de port TCP/IP à utiliser pour la connexion ou 0 pour utiliser par défaut, par ordre de préférence : my.cnf, $MYSQL_TCP_PORT, /etc/services, la valeur par défaut intégrée (3306). Force --protocol=tcp lorsqu'il est spécifié dans la ligne de commande sans autres propriétés de connexion.

•--print-defaults

Affiche la liste des arguments du programme et quitte. Doit être donné comme premier argument.

•--progress-reports

Obtient des rapports de progression pour les commandes de longue durée (telles que ALTER TABLE). (Activé par défaut ; utilisez --skip-progress-reports pour désactiver.)

•--prompt=format_str

Définit l'invite au format spécifié. Les séquences spéciales que l'invite peut contenir sont décrites dans la section « COMMANDES MARIADB ».

•--protocol={TCP|SOCKET|PIPE|MEMORY}

Le protocole de connexion à utiliser pour se connecter au serveur. Il est utile lorsque les autres paramètres de connexion provoqueraient normalement l'utilisation d'un protocole autre que celui que vous souhaitez.

•--quick, -q

Ne pas mettre en cache chaque résultat de requête, afficher chaque ligne dès qu'elle est reçue. Cela peut ralentir le serveur si la sortie est suspendue. Avec cette option, mariadb n'utilise pas le fichier d'historique.

•--raw, -r

Pour la sortie tabulaire, l'encadrement autour des colonnes permet de distinguer une valeur de colonne d'une autre. Pour la sortie non tabulaire (telle que celle produite en mode batch ou lorsque l'option --batch ou --silent est donnée), les caractères spéciaux sont échappés dans la sortie afin qu'ils puissent être facilement identifiés. Les sauts de ligne, tabulations, NUL et antislash sont écrits comme \n, \t, \0 et \\. L'option --raw désactive cet échappement de caractères.

L'exemple suivant démontre la sortie tabulaire par rapport à la sortie non tabulaire et l'utilisation du mode brut pour désactiver l'échappement :

% mariadb
mariadb> SELECT CHAR(92);
+----------+
| CHAR(92) |
+----------+
| \        |
+----------+
% mariadb -s
mariadb> SELECT CHAR(92);
CHAR(92)
\\
% mariadb -s -r
mariadb> SELECT CHAR(92);
CHAR(92)
\
•--reconnect

Si la connexion au serveur est perdue, tentez automatiquement de vous reconnecter. Une seule tentative de reconnexion est effectuée chaque fois que la connexion est perdue. Activé par défaut, pour désactiver utilisez --skip-reconnect ou --disable-reconnect.

•--safe-updates, --i-am-a-dummy, -U

N'autorise que les instructions UPDATE et DELETE qui spécifient quelles lignes modifier en utilisant des valeurs de clé. Si vous avez défini cette option dans un fichier d'options, vous pouvez la remplacer en utilisant --safe-updates dans la ligne de commande. Voir la section « CONSEILS MARIADB » pour plus d'informations sur cette option.

•--secure-auth

N'envoie pas les mots de passe au serveur dans l'ancien format (avant 4.1.1). Cela empêche les connexions sauf pour les serveurs qui utilisent le nouveau format de mot de passe.

•--select-limit=limit

Définit la limite automatique pour SELECT lors de l'utilisation de --safe-updates. (Valeur par défaut : 1 000.)

•--server-arg=name

Envoie name comme paramètre au serveur embarqué.

•--show-warnings

Force l'affichage des avertissements après chaque instruction s'il y en a. Cette option s'applique au mode interactif et au mode batch.

•--sigint-ignore

Ignore les signaux SIGINT (généralement le résultat de la frappe de Control-C).

•--silent, -s

Mode silencieux. Produit moins de sortie. Cette option peut être donnée plusieurs fois pour produire de moins en moins de sortie.

Cette option produit un format de sortie non tabulaire et un échappement des caractères spéciaux. L'échappement peut être désactivé en utilisant le mode brut ; voir la description de l'option --raw.

•--skip-auto-rehash

Désactive le rehachage automatique. Synonyme de --disable-auto-rehash.

•--skip-column-names, -N

Ne pas afficher les noms de colonnes dans les résultats.

•--skip-line-numbers, -L

Ne pas afficher les numéros de ligne pour les erreurs. Utile lorsque vous souhaitez comparer des fichiers de résultats qui incluent des messages d'erreur.

•--socket=path, -S path

Pour les connexions à localhost, le fichier de socket Unix à utiliser, ou, sous Windows, le nom du pipe nommé à utiliser. Force --protocol=socket lorsqu'il est spécifié dans la ligne de commande sans autres propriétés de connexion ; sous Windows, force --protocol=pipe.

•--ssl

Active SSL pour la connexion (automatiquement activé avec d'autres indicateurs). Désactivez avec --skip-ssl.

•--ssl-ca=name

Fichier CA au format PEM (vérifiez la documentation OpenSSL, implique --ssl).

•--ssl-capath=name

Répertoire CA (vérifiez la documentation OpenSSL, implique --ssl).

•--ssl-cert=name

Certificat X509 au format PEM (vérifiez la documentation OpenSSL, implique --ssl).

•--ssl-cipher=name

Chiffrement SSL à utiliser (vérifiez la documentation OpenSSL, implique --ssl).

•--ssl-key=name

Clé X509 au format PEM (vérifiez la documentation OpenSSL, implique --ssl).

•--ssl-crl=name

Liste de révocation de certificats (vérifiez la documentation OpenSSL, implique --ssl).

•--ssl-crlpath=name

Chemin de la liste de révocation de certificats (vérifiez la documentation OpenSSL, implique --ssl).

•--ssl-verify-server-cert

Vérifie le « Common Name » du serveur dans son certificat par rapport au nom d'hôte utilisé lors de la connexion. Cette option est désactivée par défaut.

•--table, -t

Affiche la sortie au format tableau. C'est le comportement par défaut pour une utilisation interactive, mais peut être utilisé pour produire une sortie tabulaire en mode batch.

•--tee=file_name

Ajoute une copie de la sortie au fichier donné. Cette option ne fonctionne qu'en mode interactif. La section « COMMANDES MARIADB » discute plus en détail des fichiers tee.

On Unix, the mariadb client writes a record of executed statements to a history file. By default, this file is named .mariadb_history and is created in your home directory. For backwards compatibility .mariadb_history will be used if present and .mariadb_history is missing. To specify a different file, set the value of the MARIADB_HISTFILE environment variable. The environment variable MYSQL_HISTFILE will be used if MARIADB_HISTFILE isn't present.

The .mariadb_history should be protected with a restrictive access mode because sensitive information might be written to it, such as the text of SQL statements that contain passwords.

If you do not want to maintain a history file, first remove .mariadb_history if it exists, and then use either of the following techniques:

•Set the MARIADB_HISTFILE variable to /dev/null. To cause this setting to take effect each time you log in, put the setting in one of your shell's startup files.
•Create .mariadb_history as a symbolic link to /dev/null: 
shell> ln -s /dev/null $HOME/.mariadb_history

You need do this only once.

MARIADB COMMANDS

mariadb sends each SQL statement that you issue to the server to be executed. There is also a set of commands that mariadb itself interprets. For a list of these commands, type help or \h at the mariadb> prompt:

mariadb> help
List of all MariaDB commands:
Note that all text commands must be first on line and end with ';'
?         (\?) Synonym for 'help'.
clear     (\c) Clear command.
connect   (\r) Reconnect to the server. Optional arguments are db and host.
delimiter (\d) Set statement delimiter.
edit      (\e) Edit command with $EDITOR.
ego       (\G) Send command to mariadb server, display result vertically.
exit      (\q) Exit mariadb. Same as quit.
go        (\g) Send command to mariadb server.
help      (\h) Display this help.
nopager   (\n) Disable pager, print to stdout.
notee     (\t) Don't write into outfile.
pager     (\P) Set PAGER [to_pager]. Print the query results via PAGER.
print     (\p) Print current command.
prompt    (\R) Change your mariadb prompt.
quit      (\q) Quit mariadb.
rehash    (\#) Rebuild completion hash.
source    (\.) Execute an SQL script file. Takes a file name as an argument.
status    (\s) Get status information from the server.
system    (\!) Execute a system shell command.
tee       (\T) Set outfile [to_outfile]. Append everything into given
               outfile.
use       (\u) Use another database. Takes database name as argument.
charset   (\C) Switch to another charset. Might be needed for processing
               binlog with multi-byte charsets.
warnings  (\W) Show warnings after every statement.
nowarning (\w) Don't show warnings after every statement.
For server side help, type 'help contents'

Each command has both a long and short form. The long form is not case sensitive; the short form is. The long form can be followed by an optional semicolon terminator, but the short form should not.

The use of short-form commands within multi-line /* ... */ comments is not supported.

If you provide an argument to the help command, mariadb uses it as a search string to access server-side help. For more information, see the section called “MARIADB SERVER-SIDE HELP”.

•charset charset_name, \C charset_name

Change the default character set and issue a SET NAMES statement. This enables the character set to remain synchronized on the client and server if mariadb is run with auto-reconnect enabled (which is not recommended), because the specified character set is used for reconnects.

•clear, \c

Clear the current input. Use this if you change your mind about executing the statement that you are entering.

•connect [db_name host_name]], \r [db_name host_name]]

Reconnect to the server. The optional database name and host name arguments may be given to specify the default database or the host where the server is running. If omitted, the current values are used.

•delimiter str, \d str

Change the string that mariadb interprets as the separator between SQL statements. The default is the semicolon character (“;”).

The delimiter can be specified as an unquoted or quoted argument. Quoting can be done with either single quote (') or double quote (") characters. To include a quote within a quoted string, either quote the string with the other quote character or escape the quote with a backslash (“\”) character. Backslash should be avoided outside of quoted strings because it is the escape character for MariaDB. For an unquoted argument, the delimiter is read up to the first space or end of line. For a quoted argument, the delimiter is read up to the matching quote on the line.

When the delimiter recognized by mariadb is set to something other than the default of “;”, instances of that character are sent to the server without interpretation. However, the server itself still interprets “;” as a statement delimiter and processes statements accordingly. This behavior on the server side comes into play for multiple-statement execution, and for parsing the body of stored procedures and functions, triggers, and events.

•edit, \e

Edit the current input statement. mariadb checks the values of the EDITOR and VISUAL environment variables to determine which editor to use. The default editor is vi if neither variable is set.

The edit command works only in Unix.

•ego, \G

Send the current statement to the server to be executed and display the result using vertical format.

•exit, \q

Exit mariadb.

•go, \g

Send the current statement to the server to be executed.

•nopager, \n

Disable output paging. See the description for pager.

The nopager command works only in Unix.

•notee, \t

Disable output copying to the tee file. See the description for tee.

•nowarning, \w

Enable display of warnings after each statement.

•pager [command], \P [command]

Enable output paging. By using the --pager option when you invoke mariadb, it is possible to browse or search query results in interactive mode with Unix programs such as less, more, or any other similar program. If you specify no value for the option, mariadb checks the value of the PAGER environment variable and sets the pager to that. Pager functionality works only in interactive mode.

Output paging can be enabled interactively with the pager command and disabled with nopager. The command takes an optional argument; if given, the paging program is set to that. With no argument, the pager is set from the PAGER environment variable.

The pager command works only in Unix.

•print, \p

Print the current input statement.

•prompt, \R

Change the prompt string. See the description for --prompt.

•quit, \q

Exit mariadb.

•rehash, \#

Rebuild the name-completion hash map. Use this if you add new databases, tables, or columns.

•source filename, \. filename

•status, \s

Display status information about the server connection.

Voici quelques conseils concernant la commande pager :

•Vous pouvez l'utiliser pour écrire dans un fichier et les résultats vont uniquement dans le fichier : 
mariadb> pager cat > /tmp/log.txt

Vous pouvez également passer toutes les options du programme que vous souhaitez utiliser comme pager :

mariadb> pager less -n -i -S
•Dans l'exemple précédent, remarquez l'option -S. Vous pourriez la trouver très utile pour parcourir les résultats de requêtes larges. Parfois, un jeu de résultats très large est difficile à lire à l'écran. L'option -S pour less peut rendre le jeu de résultats beaucoup plus lisible car vous pouvez le faire défiler horizontalement en utilisant les touches fléchées gauche et droite. Vous pouvez également utiliser -S de manière interactive dans less pour activer et désactiver le mode de navigation horizontale. Pour plus d'informations, lisez la page de manuel de less : 
shell> man less
•Les options -F et -X peuvent être utilisées avec less pour faire en sorte qu'il se ferme si la sortie tient sur un écran, ce qui est pratique lorsqu'aucun défilement n'est nécessaire : 
mariadb> pager less -n -i -S -F -X
•Vous pouvez spécifier des commandes de pager très complexes pour gérer la sortie des requêtes : 
mariadb> pager cat | tee /dr1/tmp/res.txt \
          | tee /dr2/tmp/res2.txt | less -n -i -S

Dans cet exemple, la commande enverrait les résultats de la requête à deux fichiers dans deux répertoires différents sur deux systèmes de fichiers différents montés sur /dr1 et /dr2, tout en affichant toujours les résultats à l'écran via less.

Vous pouvez également combiner les fonctions tee et pager. Activez un fichier tee et définissez pager sur less, et vous pourrez parcourir les résultats en utilisant le programme less tout en ayant tout ajouté au fichier en même temps. La différence entre le tee Unix utilisé avec la commande pager et la commande intégrée tee de mariadb est que le tee intégré fonctionne même si vous n'avez pas le tee Unix disponible. Le tee intégré enregistre tout ce qui est affiché à l'écran, tandis que le tee Unix utilisé avec pager n'enregistre pas autant. De plus, l'enregistrement dans le fichier tee peut être activé et désactivé interactivement depuis mariadb. Ceci est utile lorsque vous souhaitez enregistrer certaines requêtes dans un fichier, mais pas d'autres.

Vous pouvez définir l'invite de plusieurs manières :

•Utiliser une variable d'environnement. Vous pouvez définir la variable d'environnement MYSQL_PS1 sur une chaîne d'invite. Par exemple : 
shell> export MYSQL_PS1="(\u@\h) [\d]> "
•Utiliser une option de ligne de commande. Vous pouvez définir l'option --prompt sur la ligne de commande de mariadb. Par exemple : 
shell> mariadb --prompt="(\u@\h) [\d]> "
(utilisateur@hôte) [base_de_donnees]>
•Utiliser un fichier d'options. Vous pouvez définir l'option prompt dans le groupe [mariadb] de n'importe quel fichier d'options MariaDB, tel que /etc/my.cnf ou le fichier .my.cnf dans votre répertoire personnel. Par exemple : 
[mariadb]
prompt=(\\u@\\h) [\\d]>\\_

Dans cet exemple, notez que les backslashes sont doublés. Si vous définissez l'invite en utilisant l'option prompt dans un fichier d'options, il est conseillé de doubler les backslashes lors de l'utilisation des options d'invite spéciales. Il y a un certain chevauchement entre l'ensemble des options d'invite autorisées et l'ensemble des séquences d'échappement spéciales qui sont reconnues dans les fichiers d'options. Le chevauchement peut causer des problèmes si vous utilisez des backslashes simples. Par exemple, \s est interprété comme un espace plutôt que comme la valeur des secondes actuelles. L'exemple suivant montre comment définir une invite dans un fichier d'options pour inclure l'heure actuelle au format HH:MM:SS> :

[mariadb]
prompt="\\r:\\m:\\s> "
•Définir l'invite interactivement. Vous pouvez modifier votre invite interactivement en utilisant la commande prompt (ou \R). Par exemple : 
mariadb> prompt (\u@\h) [\d]>\_
PROMPT défini sur '(\u@\h) [\d]>\_'
(utilisateur@hôte) [base_de_donnees]>
(utilisateur@hôte) [base_de_donnees]> prompt

mariadb>

NOM

mariadb – ligne de commande du client MariaDB

SYNTAXE

mariadb [options] [nom_base [nom_table]] [< nom_fichier]

DESCRIPTION

mariadb est un client en ligne de commande pour le serveur MariaDB. Il peutêtre utilisé de deux manières :

  • En mode interactif, en tapant la commande sans arguments ou avec le nom de la base de données.
  • Pour exécuter des commandes SQL à partir d'un fichier.

EXÉCUTER DES INSTRUCTIONS SQL DEPUIS UN FICHIER TEXTE

Le client mariadb est généralement utilisé interactivement, comme suit :

shell> mariadb nom_base

Cependant, il est également possible de placer vos instructions SQL dans un fichier et de demander à mariadb de lire son entrée depuis ce fichier. Pour ce faire, créez un fichier texte fichier_texte contenant les instructions que vous souhaitez exécuter. Ensuite, lancez mariadb comme indiqué ci-dessous :

shell> mariadb nom_base < fichier_texte

Si vous placez une instruction USE nom_base comme première instruction dans le fichier, il est inutile de spécifier le nom de la base de données sur la ligne de commande :

shell> mariadb < fichier_texte

Si vous utilisez déjà mariadb, vous pouvez exécuter un fichier script SQL en utilisant la commande source ou la commande \. :

mariadb> source nom_fichier
mariadb> \. nom_fichier

Parfois, vous voudrez peut-être que votre script affiche des informations de progression à l'utilisateur. Pour cela, vous pouvez insérer des instructions comme celle-ci :

SELECT '<info_à_afficher>' AS ' ';

L'instruction ci-dessus affiche <info_à_afficher>.

Vous pouvez également lancer mariadb avec l'option --verbose, qui provoque l'affichage de chaque instruction avant le résultat qu'elle produit.

mariadb ignore les caractères de marque d'ordre d'octets Unicode (BOM) au début des fichiers d'entrée. La présence d'un BOM ne provoque pas le changement de jeu de caractères par défaut de mariadb. Pour ce faire, lancez mariadb avec une option telle que --default-character-set=utf8.

Utilisation de l'Option --safe-updates

Pour les débutants, une option de démarrage utile est --safe-updates (ou --i-am-a-dummy, qui a le même effet). Elle est utile dans les cas où vous pourriez avoir effectué une instruction DELETE FROM nom_tbl en oubliant la clause WHERE. Normalement, une telle instruction supprime toutes les lignes de la table. Avec --safe-updates, vous ne pouvez supprimer des lignes qu'en spécifiant les valeurs clés qui les identifient. Cela permet d'éviter les accidents.

Lorsque vous utilisez l'option --safe-updates, mariadb exécute l'instruction suivante lors de la connexion au serveur MariaDB :

SET sql_safe_updates=1, sql_select_limit=1000, sql_max_join_size=1000000;

L'instruction SET a les effets suivants :

•Vous n'ètes pas autorisé à exécuter une instruction UPDATE ou DELETE sauf si vous spécifiez une contrainte de clé dans la clause WHERE ou fournissez une clause LIMIT (ou les deux). Par exemple : 
UPDATE nom_tbl SET col_non_clé=val WHERE col_clé=val;
UPDATE nom_tbl SET col_non_clé=val LIMIT 1;
•Le serveur limite tous les grands ensembles de résultats SELECT à 1 000 lignes, sauf si l'instruction inclut une clause LIMIT.
•Le serveur abandonne les instructions SELECT multi-tables qui devraient probablement examiner plus de 1 000 000 de combinaisons de lignes.

Pour spécifier des limites différentes de 1 000 et 1 000 000, vous pouvez remplacer les défauts en utilisant les options --select-limit et --max-join-size :

shell> mariadb --safe-updates --select-limit=500 --max-join-size=10000

Désactivation de la Reconnexion Automatique de mariadb

Si le client mariadb perd sa connexion au serveur lors de l'envoi d'une instruction, il tente immédiatement et automatiquement de se reconnecter une fois au serveur et de renvoyer l'instruction. Cependant, même si mariadb réussit à se reconnecter, votre première connexion s'est terminée et tous vos objets et paramètres de session précédents sont perdus : tables temporaires, mode autocommit, et variables utilisateur et de session. De plus, toute transaction en cours est annulée. Ce comportement peut êt;re dangereux pour vous, comme dans l'exemple suivant où le serveur a été arrêté et redémarré entre la première et la deuxième instruction sans que vous le sachiez :

mariadb> SET @a=1;
Query OK, 0 rows affected (0.05 sec)
mariadb> INSERT INTO t VALUES(@a);
ERROR 2006: MariaDB server has gone away
No connection. Trying to reconnect...
Connection id:    1
Current database: test
Query OK, 1 row affected (1.30 sec)
mariadb> SELECT * FROM t;
+------+
| a    |
+------+
| NULL |
+------+
1 row in set (0.05 sec)

La variable utilisateur @a a été perdue avec la connexion, et après la reconnexion, elle est indéfinie. S'il est important que mariadb se termine par une erreur si la connexion a été perdue, vous pouvez lancer le client mariadb avec l'option --skip-reconnect.
