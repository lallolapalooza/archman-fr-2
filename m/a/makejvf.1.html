MAKEJVF(1) Manuel des commandes générales MAKEJVF(1)

NOM

makejvf - Créer un fichier VF japonais à partir d'un fichier TFM TeX japonais

SYNOPSIS

makejvf [<options>] <fichier TFM TeX> <TFM de police PS>

DESCRIPTION

makejvf est un outil pour générer un fichier VF japonais à partir d'un fichier TFM TeX japonais (JFM) pour utilisation avec dvips.

Lors du traitement de textes japonais, pTeX fait référence aux fichiers JFM (min10.tfm, jis.tfm etc.), qui incluent des définitions de différentes largeurs de caractères et de collages/kerns métriques. Pour la plupart des ponctuations et guillemets, les largeurs de caractères sont tronquées à moins de 1 zw (zenkaku-width ; la largeur des caractères Kanji ordinaires), et des collages/kerns métriques sont insérés en remplacement.
D'autre part, dans les polices PS japonaises, toutes les ponctuations et guillemets ont les mêmes largeurs de caractères que les caractères Kanji ordinaires. Pour cette raison, lorsque dvips traite le fichier DVI résultant, ces caractères doivent être décalés vers la gauche du montant du collage/kern inséré.
Pour réaliser cela, des polices virtuelles (VF) et des fichiers TFM PS sont requis ; lorsque le VF contient les commandes de décalage des caractères, le TFM de police PS peut avoir les largeurs de caractères exactes des polices PS.
Le programme makejvf peut être utilisé à cette fin. Il prend en entrée un fichier JFM pTeX (référencé comme <fichier TFM TeX> dans la SYNOPSIS ci-dessus), et génère un fichier VF correspondant (avec le même nom de base que <fichier TFM TeX>) et un fichier JFM pour un fichier TFM de police PS (<TFM de police PS> ci-dessus).

OPTIONS

-C
Mode condensé ("Cho-tai").
-K <PS-TFM>
Mapper les caractères Kana (plus précisément, les non-Kanji) vers un autre fichier JFM PS nommé <PS-TFM>.
-b <entier>
Décalage de la ligne de base ; l'<entier> représente une valeur relative, utilisant la hauteur du caractère comme base de 1000. Lorsqu'un entier positif est spécifié, les caractères sont abaissés. Lorsqu'un entier négatif est spécifié, les caractères sont élevés.
-m
Remplacer les apostrophes/guillemets simples/doubles par des apostrophes/guillemets droits simples/doubles (soi-disant "minute") en écriture verticale. Le remplacement est réalisé en manipulant les glyphes d'apostrophe et d'apostrophe double (JIS 0x216C et 0x216D ; Unicode U+2032 et U+2033), *pas* en insérant des glyphes réels conçus pour les guillemets (Unicode U+301D et U+301E/U+301F).
-a <fichier AFM>
Nom du fichier AFM d'entrée utilisé pour le mode Kana-tsume. Cette option n'est pas prise en charge.
-k <entier>
Marge Kana-tsume (espaces plus étroits entre les caractères Kana) ; l'<entier> représente une valeur relative, utilisant la largeur du caractère comme base de 1000. Cette option doit être accompagnée de l'option -a. Cette option n'est pas prise en charge.
-i
Démarrer l'ID de la police mappée à partir du numéro 0 dans le VF de sortie (par défaut, makejvf utilise le numéro 1).
-e
Mode amélioré ; le décalage horizontal est déterminé à partir de la table de collage/kern du fichier JFM d'entrée.
Par défaut, makejvf utilise la valeur codée en dur comme montant du décalage horizontal, qui est (principalement) optimisée pour les polices japonaises. Lorsque le mode amélioré (option -e) est activé, le montant du décalage est déterminé à partir du fichier TFM pTeX (JFM) d'entrée, ce qui est susceptible de produire le VF le plus approprié pour le JFM.
Pour la plupart des JFM japonais standard (comme jis.tfm et ses dérivés), les VF de sortie des deux modes n'auront pas de différence significative. Pour les JFM chinois simplifié/traditionnel (comme upschrm-h.tfm et uptchrm-h.tfm), le VF de sortie du mode amélioré sera meilleur. Pour min10.tfm et ses dérivés, le mode amélioré ne doit *jamais* être activé, car la caractérisation dans min10.tfm n'est pas standard.
-t <fichier CNF>
Utiliser <fichier CNF> comme fichier de configuration.
-O
Omettre les entrées dans le VF pour les caractères avec des métriques par défaut. Cette option n'est pas autorisée à être utilisée avec l'option -t.
-u <Jeu de caractères>
Mode UCS. Les jeux de caractères disponibles sont : gb (GB = chinois simplifié), cns (CNS = chinois traditionnel), ks (KS = coréen), jis (JIS = japonais), jisq (uniquement guillemets JIS), custom (CHARSET défini par l'utilisateur à partir du <fichier CNF> ; voir la section FORMAT DU FICHIER DE CONFIGURATION).
Les options ci-dessous sont effectives uniquement en mode UCS :
-J <PS-TFM>
Mapper les guillemets simples/doubles vers un autre TFM de police PS encodé en JIS.
-U <PS-TFM>
Mapper les guillemets simples/doubles vers un autre TFM de police PS encodé en UCS.
-3
Utiliser set3, c'est-à-dire activer la prise en charge des caractères non-BMP (avec le mode UCS). Par défaut, makejvf ne génère pas les caractères >=U+10000, pour réduire la taille du fichier et éviter les problèmes avec les anciens pilotes DVI. Les versions récentes de dvipdfmx et d'autres peuvent gérer les VF avec >=U+10000 (= set3 dans le langage DVI), par conséquent -3 pourrait être utile.
-H
Utiliser le Katakana demi-chasse.

EXEMPLE

Si vous voulez utiliser min10 comme Ryumin-Light-H, exécutez

makejvf min10.tfm rml
Ceci génère min10.vf et rml.tfm. Placez ces fichiers dans un répertoire approprié sous l'arbre TEXMF, et ajoutez la ligne suivante à psfonts.map.

rml Ryumin-Light-H

FORMAT DU FICHIER DE CONFIGURATION

Avec l'option -t, vous pouvez donner à makejvf des paramètres personnalisés pour générer le VF. La syntaxe est :


% ligne de commentaire


MOVE <code> <droite> <bas>


REPLACE <code> <nouveau code>
CHARSET <code>,<code>,<code>..<code>,<code>,
+ <code>,<code>..<code>

Chaque ligne doit commencer par une commande et doit être séparée par des TAB. Les lignes commençant par % sont des commentaires, et les lignes vides sont ignorées.
La commande MOVE spécifie le montant du décalage horizontal/vertical pour le caractère individuel <code>. La commande REPLACE remplace le caractère <code> par <nouveau code>. La commande CHARSET définit le jeu de caractères personnalisé du VF de sortie ; le caractère + continue à partir de la ligne précédente.
Un exemple d'utilisation peut être trouvé dans le projet uptex-fonts. Voir le dépôt GitHub

https://github.com/texjporg/uptex-fonts.
