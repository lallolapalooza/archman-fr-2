MASTER(8) Manuel de l'administrateur système MASTER(8)

NOM

master - Processus maître de Postfix

SYNOPIS

master [-Dditvw] [-c rép_config] [-e temps_sortie]

DESCRIPTION


Le démon master(8) est le processus résident qui exécute les démons Postfix à la demande : démons pour envoyer ou recevoir des messages via le réseau, démons pour livrer le courrier localement, etc. Ces démons sont créés à la demande jusqu'à un nombre maximum configurable par service.

Les démons Postfix se terminent volontairement, soit après une période d'inactivité configurable, soit après avoir traité un nombre configurable de requêtes. Les exceptions à cette règle sont le gestionnaire de file d'attente résident, le serveur de vérification d'adresse, et le serveur de cache de sessions TLS et de nombres pseudo-aléatoires.

Le comportement du démon master(8) est contrôlé par le fichier de configuration master.cf, tel que décrit dans master(5).

Options :

-c rép_config
Lit les fichiers de configuration main.cf et master.cf dans le répertoire nommé au lieu du répertoire de configuration par défaut. Ceci remplace également les fichiers de configuration pour d'autres processus démons de Postfix.
-D
Après l'initialisation, lance un débogueur sur le processus maître. La commande de débogage est spécifiée avec debugger_command dans le fichier de configuration globale main.cf.
-d
Ne redirige pas stdin, stdout ou stderr vers /dev/null, et ne supprime pas le terminal de contrôle. Ceci doit être utilisé uniquement pour le débogage.
-e temps_sortie
Termine le processus maître après temps_sortie secondes. Les processus enfants se terminent à leur convenance.
-i
Active le mode init : ne devient pas un chef de session ou de groupe de processus ; et similaire à -s, ne redirige pas stdout vers /dev/null, de sorte que "maillog_file = /dev/stdout" fonctionne. Ce mode n'est autorisé que si l'ID du processus est égal à 1.

Cette fonctionnalité est disponible dans Postfix 3.3 et versions ultérieures.

-s
Ne redirige pas stdout vers /dev/null, de sorte que "maillog_file = /dev/stdout" fonctionne.

Cette fonctionnalité est disponible dans Postfix 3.4 et versions ultérieures.

-t
Mode test. Retourne un statut de sortie nul lorsque le fichier de verrouillage master.pid n'existe pas ou lorsque ce fichier n'est pas verrouillé. Ceci prouve que le démon master(8) ne fonctionne pas.
-v
Active la journalisation détaillée à des fins de débogage. Cette option est transmise aux processus enfants. Plusieurs options -v rendent le logiciel de plus en plus verbeux.
-w
Attend dans un processus factice en avant-plan, tandis que le véritable démon maître s'initialise dans un processus en arrière-plan. Le processus factice en avant-plan retourne un statut de sortie nul uniquement si l'initialisation du démon maître est réussie et si elle s'achève dans un délai raisonnable.

Cette fonctionnalité est disponible dans Postfix 2.10 et versions ultérieures.

Signaux :

SIGHUP
À la réception d'un signal HUP (par exemple, après "postfix reload"), le processus maître relit ses fichiers de configuration. Si un service a été supprimé du fichier master.cf, ses processus en cours d'exécution sont immédiatement terminés. Sinon, les processus en cours d'exécution sont autorisés à se terminer dès que possible, de sorte que les changements dans les paramètres de configuration n'affectent que les nouvelles requêtes de service.
SIGTERM
À la réception d'un signal TERM (par exemple, après "postfix abort"), le processus maître transmet le signal à ses processus enfants et se termine. Ceci est utile pour un arrêt d'urgence. Normalement, on arrêterait uniquement le maître ("postfix stop") et on laisserait les processus en cours d'exécution terminer ce qu'ils font.

DIAGNOSTICS


Les problèmes sont signalés à syslogd(8) ou postlogd(8). Le statut de sortie est différent de zéro en cas de problèmes, y compris lors de l'initialisation en tant que processus démon maître en arrière-plan.

ENVIRONNEMENT

MAIL_DEBUG
Après l'initialisation, démarre un débogueur tel que spécifié par le paramètre de configuration debugger_command dans le fichier de configuration main.cf.
MAIL_CONFIG
Répertoire contenant les fichiers de configuration Postfix.

PARAMETRES DE CONFIGURATION

Contrairement à la plupart des processus démons de Postfix, le serveur master(8) ne prend pas en compte automatiquement les modifications apportées à main.cf. Les modifications apportées à master.cf ne sont jamais prises en compte automatiquement. Utilisez la commande "postfix reload" après une modification de configuration.

CONTROLES DE RESSOURCES ET DE DEBIT

default_process_limit (100)
Le nombre maximum par défaut de processus enfants Postfix qui fournissent un service donné.
max_idle (100s)
La durée maximale pendant laquelle un processus démon Postfix inactif attend une connexion entrante avant de se terminer volontairement.
max_use (100)
Le nombre maximal de connexions entrantes qu'un processus démon Postfix traitera avant de se terminer volontairement.
service_throttle_time (60s)
Combien de temps le master(8) de Postfix attend avant de lancer un serveur qui semble défectueux.

Disponible dans la version Postfix 2.6 et ultérieures :

master_service_disable (vide)
Désactive sélectivement les ports d'écoute master(8) par type de service ou par nom de service et type.

CONTROLES DIVERS

config_directory (voir la sortie de 'postconf -d')
L'emplacement par défaut des fichiers de configuration main.cf et master.cf de Postfix.
daemon_directory (voir la sortie de 'postconf -d')
Le répertoire contenant les programmes de support et les programmes démons de Postfix.
debugger_command (vide)
La commande externe à exécuter lorsqu'un programme démon Postfix est appelé avec l'option -D.
inet_interfaces (all)
Les adresses d'interface réseau locales sur lesquelles ce système de messagerie reçoit le courrier.
inet_protocols (voir la sortie de 'postconf -d')
Les protocoles Internet que Postfix tentera d'utiliser lors de l'établissement ou de l'acceptation de connexions.
import_environment (voir la sortie de 'postconf -d')
La liste des variables d'environnement qu'un processus Postfix privilégié importera d'un processus parent non-Postfix, ou des remplacements d'environnement nom=valeur.
mail_owner (postfix)
Le compte système UNIX qui possède la file d'attente Postfix et la plupart des démons

FICHIERS

Pour développer les noms de répertoires ci-dessous en leurs valeurs réelles, utilisez la commande « postconf config_directory », etc.

$config_directory/main.cf, fichier de configuration global.
$config_directory/master.cf, fichier de configuration du serveur maître.
$queue_directory/pid/master.pid, fichier de verrouillage maître.
$data_directory/master.lock, fichier de verrouillage maître.
