math.h(0P) Manuel du programmeur POSIX math.h(0P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

math.h — déclarations mathématiques

SYNOPIS

#include <math.h>

DESCRIPTION

Une partie des fonctionnalités décrites dans cette page de référence étend la norme ISO C. Les applications doivent définir la macro de test de fonctionnalité appropriée (voir le volume Interfaces Système de POSIX.1‐2017, Section 2.2, L'environnement de compilation) pour activer la visibilité de ces symboles dans cet en-tête.

L'en-tête <math.h> doit définir au moins les types suivants :

float_t
Un type flottant réel d'au moins la largeur de float.
double_t
Un type flottant réel d'au moins la largeur de double, et d'au moins la largeur de float_t.

Si FLT_EVAL_METHOD est égal à 0, float_t et double_t seront float et double, respectivement ; si FLT_EVAL_METHOD est égal à 1, ils seront tous deux double ; si FLT_EVAL_METHOD est égal à 2, ils seront tous deux long double ; pour d'autres valeurs de FLT_EVAL_METHOD, ils sont autrement indéfinis par l'implémentation.

L'en-tête <math.h> doit définir les macros suivantes, où flottant-réel indique que l'argument doit être une expression de type flottant-réel :

L'en-tête <math.h> doit définir les macros suivantes :

HUGE_VAL
Une expression constante positive de type double, pas nécessairement représentable comme un float. Utilisée comme valeur d'erreur retournée par la bibliothèque mathématique. HUGE_VAL est égal à +infini sur les systèmes supportant IEEE Std 754‐1985.
HUGE_VALF
Une expression constante positive de type float. Utilisée comme valeur d'erreur retournée par la bibliothèque mathématique. HUGE_VALF est égal à +infini sur les systèmes supportant IEEE Std 754‐1985.
HUGE_VALL
Une expression constante positive de type long double. Utilisée comme valeur d'erreur retournée par la bibliothèque mathématique. HUGE_VALL est égal à +infini sur les systèmes supportant IEEE Std 754‐1985.
INFINITY
Une expression constante de type float représentant l'infini positif ou non signé, si disponible ; sinon une constante positive de type float qui déborde à la compilation.
NAN
Une expression constante de type float représentant un NaN silencieux. Cette macro n'est définie que si l'implémentation supporte les NaNs silencieux pour le type float.

Les macros suivantes sont définies pour la classification des nombres. Elles représentent les types mutuellement exclusifs de valeurs flottantes. Elles se développent en expressions constantes entières avec des valeurs distinctes. Des classifications flottantes supplémentaires, indéfinies par l'implémentation, avec des définitions de macros commençant par FP_ et une lettre majuscule, peuvent également être spécifiées par l'implémentation.

FP_INFINITE FP_NAN FP_NORMAL FP_SUBNORMAL FP_ZERO

Les macros optionnelles suivantes indiquent si la famille de fonctions fma() est rapide par rapport au code direct :

FP_FAST_FMA FP_FAST_FMAF FP_FAST_FMAL

Si la macro FP_FAST_FMA est définie, elle se développe en la constante entière 1 et indique que la fonction fma() s'exécute généralement aussi vite que, ou plus vite qu'une multiplication et une addition d'opérandes double. Si elle n'est pas définie, la vitesse d'exécution n'est pas spécifiée. Les autres macros ont une signification équivalente pour les versions float et long double.

Les macros suivantes se développent en expressions constantes entières dont les valeurs sont retournées par ilogb(x) si x est zéro ou NaN, respectivement. La valeur de FP_ILOGB0 est soit {INT_MIN}, soit -{INT_MAX}. La valeur de FP_ILOGBNAN est soit {INT_MAX}, soit {INT_MIN}.

FP_ILOGB0 FP_ILOGBNAN

Les macros suivantes se développent en constantes entières 1 et 2, respectivement ;

MATH_ERRNO MATH_ERREXCEPT

La macro suivante se développe en une expression qui a le type int et la valeur MATH_ERRNO, MATH_ERREXCEPT, ou le OU bit à bit des deux :

math_errhandling

La valeur de math_errhandling est constante pendant la durée du programme. Il n'est pas spécifié si math_errhandling est une macro ou un identificateur avec liaison externe. Si une définition de macro est supprimée ou si un programme définit un identificateur du nom de math_errhandling, le comportement est indéfini. Le comportement de chacune des fonctions définies dans <math.h> est spécifié dans le volume Interfaces système de POSIX.1‐2017 pour toutes les valeurs représentables de ses arguments d'entrée, sauf indication contraire. Chaque fonction doit s'exécuter comme si elle était une opération unique sans générer de conditions exceptionnelles externes visibles.

Les sections suivantes sont informatives.

UTILISATION APPLICATIVE

Le pragma FP_CONTRACT peut être utilisé pour autoriser (si l'état est activé) ou interdire (si l'état est désactivé) à l'implémentation de contracter les expressions. Chaque pragma peut apparaître soit à l'extérieur des déclarations externes, soit précédant toutes les déclarations et instructions explicites à l'intérieur d'une instruction composée. Lorsqu'il est à l'extérieur des déclarations externes, le pragma prend effet à partir de son occurrence jusqu'à ce qu'un autre pragma FP_CONTRACT soit rencontré, ou jusqu'à la fin de l'unité de traduction. Lorsqu'il est à l'intérieur d'une instruction composée, le pragma prend effet à partir de son occurrence jusqu'à ce qu'un autre pragma FP_CONTRACT soit rencontré (y compris dans une instruction composée imbriquée), ou jusqu'à la fin de l'instruction composée ; à la fin d'une instruction composée, l'état du pragma est restauré à sa condition juste avant l'instruction composée. Si ce pragma est utilisé dans tout autre contexte, le comportement est indéfini. L'état par défaut (activé ou désactivé) pour le pragma est défini par l'implémentation.

Les applications doivent utiliser FLT_MAX comme décrit dans l'en-tête <float.h> au lieu de MAXFLOAT obsolète.

Notez que si FLT_EVAL_METHOD n'est ni 0 ni 1, certaines constantes pourraient ne pas être comparées comme attendu ; par exemple, (double)M_PI == M_PI peut échouer.

RATIONALE

Avant la norme ISO/IEC 9899:1999, la bibliothèque mathématique n'était définie que pour le type flottant double. Tous les noms formés en ajoutant 'f' ou 'l' à un nom dans <math.h> étaient réservés pour permettre la définition des bibliothèques pour float et long double ; et la norme ISO/IEC 9899:1999 prévoit les trois versions des fonctions mathématiques.

Les fonctions ecvt(), fcvt(), et gcvt() ont été supprimées de la norme ISO C car leur capacité est disponible via sprintf().
