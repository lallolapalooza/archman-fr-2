NOM

mausezahn - générateur de paquets rapide et polyvalent avec CLI Cisco

SYNOPSIS

mausezahn { [options] "<chaîne-d'arguments> | <chaîne-hexadécimale>" }

DESCRIPTION

mausezahn est un générateur de trafic rapide qui vous permet d'envoyer presque tous les paquets possibles et impossibles. Contrairement à trafgen(8), la configuration des paquets de mausezahn se fait au niveau protocolaire plutôt qu'au niveau des octets, et mausezahn intègre une interface en ligne de commande (CLI) de type Cisco, ce qui le rend adapté comme générateur de trafic réseau dans votre laboratoire réseau.

En plus des laboratoires réseau, il peut également être utilisé comme outil didactique et pour des audits de sécurité, y compris des tests de pénétration et des tests DoS. En tant que générateur de trafic, mausezahn est également capable de tester les réseaux multicast IP ou VoIP. Des débits de paquets proches de la limite physique sont atteignables, en fonction de la plateforme matérielle.

mausezahn prend en charge deux modes : le ''mode direct'' et le ''mode interactif'' multi-threadé.

Le ''mode direct'' vous permet de créer un paquet directement sur la ligne de commande, et chaque paramètre du paquet est spécifié dans la liste d'arguments lors de l'appel de mausezahn.

Le ''mode interactif'' est un mode de configuration multi-threadé avancé avec sa propre interface en ligne de commande (CLI). Ce mode vous permet de créer un nombre arbitraire de types de paquets et de flux en parallèle, chacun avec des paramètres différents.

Le mode interactif utilise un framework protocolaire entièrement repensé et plus flexible, appelé ''mops'' (mausezahn's own packet system). L'apparence et la convivialité de la CLI sont très proches de l'interface en ligne de commande Cisco IOS^tm.

Vous pouvez démarrer le mode interactif en exécutant mausezahn avec l'argument ''-x'' (un numéro de port facultatif peut suivre, sinon c'est 25542). Utilisez ensuite telnet(1) pour vous connecter à cette instance de mausezahn. Sauf indication contraire, la combinaison par défaut de nom d'utilisateur et de mot de passe est mz:mz et le mot de passe d'activation est : mops. Cela peut être modifié dans /etc/netsniff-ng/mausezahn.conf.

Le mode direct prend en charge deux schémas de spécification : le schéma ''raw-layer-2'', où chaque octet à envoyer peut être spécifié, et le schéma ''higher-layer'', où des constructeurs de paquets sont utilisés (en utilisant l'option ''-t'').

Pour utiliser le schéma ''raw-layer-2'', spécifiez simplement le cadre souhaité sous forme de séquence hexadécimale (la ''chaîne-hexadécimale''), par exemple :


mausezahn eth0 "00:ab:cd:ef:00 00:00:00:00:00:01 08:00 ca:fe:ba:be"

Dans cet exemple, les espaces blancs dans la chaîne d'octets sont optionnels et séparent les champs Ethernet (adresse de destination et source, champ de type, et une courte charge utile). Les seules options supplémentaires supportées sont ''-a'', ''-b'', ''-c'', et ''-p''. La longueur du cadre doit être supérieure ou égale à 15 octets.

Le schéma ''higher-layer'' est activé à l'aide de l'option ''-t <type-paquet>''. Cette option active un constructeur de paquet, et en plus du ''type-paquet'', une ''chaîne-d'arguments'' facultative peut être spécifiée. La ''chaîne-d'arguments'' contient des paramètres spécifiques au paquet, tels que des indicateurs TCP, des numéros de port, etc. (voir la section exemples).

OPTIONS

mausezahn fournit une aide contextuelle intégrée. Ajoutez le mot-clé
''help'' après les options de configuration. Les options les plus importantes sont :

-x [<port>]

Démarre mausezahn en mode interactif avec une CLI de type Cisco. Utilisez telnet pour vous connecter à l'instance locale de mausezahn. Si aucun port n'a été spécifié, le port 25542 est utilisé par défaut.

-6

Spécifie le mode IPv6 (IPv4 est le mode par défaut).

-l <IP>

Spécifie l'adresse IP à laquelle mausezahn doit se lier en mode interactif, par défaut : 0.0.0.0.

-R <PRIO>

Définit la priorité des paquets envoyés. Ceci configure SO_PRIORITY au niveau du socket via lequel les paquets sont envoyés. Les numéros de priorité habituels sont 0..15, mais la valeur peut aussi être un ID de classe pour des raisons de classification Qdisc. Dans ce cas, un ID de classe tel que 1234:5678 serait spécifié comme 0x12345678.

-v

Mode verbeux. Un -V majuscule est encore plus verbeux.

-S

Mode simulation, c'est-à-dire ne rien envoyer sur le réseau. Ceci est généralement combiné avec le mode verbeux.

-q

Mode silencieux où seuls les avertissements et les erreurs sont affichés.

-c <compte>

Envoyer le paquet compte fois (défaut : 1, infini : 0).

-d <délai>

Appliquer un délai entre les transmissions. La valeur du délai peut être spécifiée en microsecondes (défaut, aucune unité supplémentaire n'est requise), ou en millisecondes (par exemple, 100m ou 100msec), ou en secondes (par exemple, 100s ou 100sec). Remarque : mops prend également en charge la résolution de délai en nanosecondes si vous en avez besoin (voir le mode interactif).

-r

Multiplier le délai spécifié par une valeur aléatoire.

-p <longueur>

Rembourrer le cadre brut jusqu'à la longueur spécifiée en utilisant des octets nuls. Notez que pour les cadres de couche 2 bruts, la longueur spécifiée définit la longueur totale du cadre, tandis que pour les paquets de couche supérieure, le nombre d'octets de remplissage supplémentaires est spécifié.

-a <mac-src|mot-clé>

Utiliser l'adresse MAC source spécifiée en notation hexadécimale telle que 00:00:aa:bb:cc:dd. Par défaut, l'adresse MAC de l'interface sera utilisée. Les mots-clés ''rand'' et ''own'' font référence à une adresse MAC aléatoire (seules les adresses unicast sont créées) et à la propre adresse, respectivement. Vous pouvez également utiliser les mots-clés mentionnés ci-dessous, bien que les adresses source de type broadcast soient officiellement invalides.

-b <mac-dst|mot-clé>

Utiliser l'adresse MAC de destination spécifiée. Par défaut, un broadcast est envoyé en mode couche 2 brut ou aux hôtes de destination ou à l'adresse MAC de l'interface passerelle en mode normal (IP). Vous pouvez utiliser les mêmes mots-clés que ceux mentionnés ci-dessus, ainsi que ''bc'' ou ''bcast'', ''cisco'', et ''stp''.

-A <ip-src|plage|rand>

Utiliser l'adresse IP source spécifiée, par défaut l'adresse de la propre interface. Optionnellement, le mot-clé ''rand'' peut à nouveau être utilisé pour une adresse IP source aléatoire ou une plage peut être spécifiée, telle que ''192.168.1.1-192.168.1.100'' ou ''10.1.0.0/16''. De plus, un nom DNS peut être spécifié pour lequel mausezahn tente de déterminer automatiquement l'adresse IP correspondante.

-B <ip-dst|plage>

Utiliser l'adresse IP de destination spécifiée (par défaut : broadcast c'est-à-dire 255.255.255.255). Comme pour l'adresse source (voir ci-dessus), vous pouvez également spécifier une plage ou un nom DNS.

-t <type-paquet [aide] | aide>

Créer le type de paquet spécifié en utilisant le constructeur de paquet intégré. Actuellement, les types de paquets supportés sont : ''arp'', ''bpdu'', ''ip'', ''udp'', ''tcp'', ''rtp'', et ''dns''. Actuellement, il y a aussi un support limité pour ''icmp''. Tapez
''-t help'' pour vérifier quels constructeurs de paquets votre version actuelle de mausezahn supporte. Également, pour un type de paquet particulier, par exemple le type ''tcp'', tapez
''mausezahn -t tcp help'' pour recevoir des informations plus détaillées

contexte spécifique aide.

-T <type-de-paquet>

Faire de cette instance de mausezahn la station réceptrice. Actuellement, seul ''rtp'' est une option ici et fournit des mesures de gigue précises. Pour ce faire, démarrez une autre instance de mausezahn sur la station émettrice et la station réceptrice locale affichera des statistiques de gigue. Voir ''mausezahn -T rtp help'' pour une aide détaillée.

-Q <[CoS:]vlan> [, <[CoS:]vlan>, ...]

Spécifiez le tag VLAN 802.1Q et éventuellement la Classe de Service. Un nombre arbitraire de tags VLAN peut être spécifié (c'est-à-dire que vous pouvez simuler QinQ ou même QinQinQinQ..). Les tags multiples doivent être séparés par une virgule ou un point (par exemple, "5:10,20,2:30"). Les tags VLAN ne sont pas pris en charge pour les paquets ARP et BPDU (auquel cas vous pourriez spécifier la trame entière en hexadécimal en utilisant l'interface de couche 2 brute de mausezahn).

-M <label[:cos[:ttl]][bos]> [, <label...>]

Spécifiez une étiquette MPLS ou même une pile d'étiquettes MPLS. Optionnellement, pour chaque étiquette, les bits expérimentaux (généralement la Classe de Service, CoS) et le Temps de Vie (TTL) peuvent être spécifiés. Si vous êtes vraiment fou, vous pouvez définir et désactiver le bit Bottom of Stack (BoS) pour chaque étiquette en utilisant l'option ''S'' (définir) et ''s'' (désactiver). Par défaut, le BoS est défini automatiquement et correctement. Tout autre réglage entraînera des trames invalides. Entrez ''-M help'' pour des instructions détaillées et des exemples.

-P <charge-utile-ascii>

Spécifiez une charge utile en clair. Alternativement, chaque type de paquet prend en charge une spécification hexadécimale de la charge utile (voir par exemple ''-t udp help'').

-f <nom-de-fichier>

Lire la charge utile ASCII depuis le fichier spécifié.

-F <nom-de-fichier>

Lire la charge utile hexadécimale depuis le fichier spécifié. En fait, ce fichier doit également être un fichier texte ASCII, mais doit contenir des chiffres hexadécimaux, par exemple "aa:bb:cc:0f:e6...". Vous pouvez également utiliser des espaces comme caractères de séparation.

EXEMPLE D'UTILISATION

Pour des exemples plus complets, consultez les deux sections HOWTO suivantes.

mausezahn eth0 -c 0 -d 2s -t bpdu vlan=5

Envoyer des trames BPDU pour le VLAN 5 tel qu'utilisé avec le type STP de Cisco PVST+. Par défaut, mausezahn suppose que vous voulez devenir le pont racine.

mausezahn eth0 -c 128000 -a rand -p 64

Effectuer une attaque par débordement de table CAM.

mausezahn eth0 -c 0 -Q 5,100 -t tcp flags=syn,dp=1-1023 -p 20 -A rand -B 10.100.100.0/24

Effectuer une attaque par inondation SYN vers un autre VLAN en utilisant le VLAN hopping. Cela ne fonctionne que si vous êtes connecté au même VLAN qui est configuré comme VLAN natif sur le trunk. Nous supposons que le VLAN victime est le VLAN 100 et le VLAN natif est le VLAN 5. Attaquons chaque hôte dans le VLAN 100 qui utilise un préfixe IP de 10.100.100.0/24, essayons également tous les ports entre 1 et 1023 et utilisons une adresse IP source aléatoire.

mausezahn eth0 -c 0 -d 10msec -B 230.1.1.1 -t udp dp=32000,dscp=46 -P Test de paquet de multidiffusion

Envoyer des paquets IP de multidiffusion au groupe de multidiffusion 230.1.1.1 en utilisant un en-tête UDP avec le port de destination 32000 et définir le champ DSCP IP sur EF (46). Envoyer une trame toutes les 10 msec.

mausezahn eth0 -Q 6:420 -M 100,200,300:5 -A 172.30.0.0/16 -B target.anynetwork.foo -t udp sp=666,dp=1-65535 -p 1000 -c 10

Envoyer des paquets UDP à l'hôte de destination target.anynetwork.foo en utilisant tous les ports de destination possibles et envoyer chaque paquet avec toutes les adresses source possibles de la plage 172.30.0.0/16; utiliser en plus un port source de 666 et trois étiquettes MPLS, 100, 200 et 300, l'externe (300) avec le champ QoS 5. Envoyer la trame avec un tag VLAN 420 et CoS 6; éventuellement compléter avec 1000 octets et répéter le tout 10 fois.

mausezahn -t syslog sev=3 -P Le réacteur principal a atteint une température critique. -A 192.168.33.42 -B 10.1.1.9 -c 6 -d 10s

Envoyer six messages syslog forgés avec une sévérité 3 à un serveur Syslog 10.1.1.9; utiliser une adresse IP source forgée 192.168.33.42 et laisser mausezahn décider quelle interface locale utiliser. Utiliser un délai inter-paquet de 10 secondes.

mausezahn -t tcp flags=syn|urg|rst, sp=145, dp=145, win=0, s=0-4294967295, ds=1500, urg=666 -a bcast -b bcast -A bcast -B 10.1.1.6 -p 5

Envoyer un paquet TCP invalide avec une charge utile de seulement 5 octets en broadcast de couche 2 et utiliser également l'adresse MAC de diffusion comme adresse source. La cible devrait être 10.1.1.6 mais utiliser une adresse source de diffusion. Le port source et destination doit être 145 et la taille de la fenêtre 0. Définir les drapeaux TCP SYN, URG et RST simultanément et balayer tout l'espace des numéros de séquence TCP avec un incrément de 1500. Finalement, définir le pointeur urgent à 666, c'est-à-dire qu'il ne pointe nulle part.

FICHIER DE CONFIGURATION

Lorsque mausezahn est exécuté en mode interactif, il recherche et lit automatiquement un fichier de configuration situé dans /etc/netsniff-ng/mausezahn.conf pour les options personnalisées si le fichier est disponible, sinon il utilise les valeurs par défaut définies à la compilation.

Fichier de config : /etc/netsniff-ng/mausezahn.conf

Le fichier de configuration contient des lignes de la forme :

option = valeur

Les options prises en charge dans le fichier de configuration sont :
Option : Description :


user Nom d'utilisateur pour l'authentification (défaut : mz)
password Mot de passe pour l'authentification (défaut : mz)
enable Mot de passe pour entrer en mode privilège (défaut : mops)
port Le port d'écoute pour la CLI (défaut : 25542)
listen-addr Adresse IP à lier à la CLI (défaut : 0.0.0.0)
management-only Définir l'interface de gestion (aucun trafic de données n'est autorisé à passer par celle-ci)
cli-device Interface à lier à la CLI (défaut : toutes) *pas entièrement implémenté*
automops Chemin vers le fichier automops (contient des données XML décrivant les protocoles) *en développement*

Exemple :


$ cat /etc/netsniff-ng/mausezahn.conf
user = mzadmin
password = mzpasswd
enable = privilege-mode-passwd
port = 65000
listen-addr = 127.0.0.1

MODE INTERACTIF HOWTO

Telnet :

L'utilisation du mode interactif nécessite de démarrer mausezahn en tant que serveur :


# mausezahn -x

Vous pouvez maintenant vous connecter en telnet (1) à ce serveur en utilisant le numéro de port par défaut 25542, mais un numéro de port arbitraire peut également être spécifié :


# mausezahn -x 99
mausezahn accepte les connexions telnet entrantes sur le port 99.
mz : Problèmes à l'ouverture du fichier de configuration. Utilisation des valeurs par défaut.

Depuis un autre terminal ou depuis un autre hôte, essayez de vous connecter en telnet au serveur mausezahn :


caprica$ telnet galactica 99
Essai de connexion à 192.168.0.4...
Connecté à galactica.
Caractère d'échappement : '^]'.
mausezahn <version>


Nom d'utilisateur : mz
Mot de passe : mz


mz> enable
Mot de passe : mops
mz#

Il est recommandé de configurer vos propres identifiants dans /etc/netsniff-ng/mausezahn.conf, (voir la section fichier de configuration)

Bases :

Maintenant que vous avez atteint l'invite mausezahn, essayons quelques commandes courantes. Vous pouvez utiliser le caractère '?' à tout moment pour obtenir de l'aide contextuelle. Notez que les formes courtes de commandes de type Cisco sont acceptées en mode interactif. Par exemple, on peut utiliser "sh pac" au lieu de "show packet"; un autre exemple courant est d'utiliser "config t" au lieu de "configure terminal". Pour des raisons de lisibilité, ce manuel continuera avec les commandes complètes.

Essayons d'abord la commande show :


mz# show ?

mausezahn maintient sa propre table ARP et observe les anomalies. Il existe une entrée pour chaque interface physique (cependant cet hôte n'en a qu'une) :

MODE DIRECT COMMENTAIRE

Comment spécifier des chiffres hexadécimaux :

De nombreux arguments permettent l'entrée directe d'octets. Les octets sont représentés par deux chiffres hexadécimaux. Plusieurs octets doivent être séparés par des espaces, des deux-points ou des tirets - selon votre préférence. Les chaînes d'octets suivantes sont équivalentes :


"aa:bb cc-dd-ee ff 01 02 03-04 05"
"aa bb cc dd ee ff:01:02:03:04 05"

Pour commencer, vous voudrez peut-être envoyer une trame arbitraire (éventuellement invalide) directement sur votre carte réseau :


mausezahn ff:ff:ff:ff:ff:ff:ff:ff:ff:ff:ff:ff:08:00:ca:fe:ba:be


ou équivalent mais plus lisible :


mausezahn ff:ff:ff:ff:ff:ff-ff:ff:ff:ff:ff:ff-08:00-ca:fe:ba:be

Opérations de base :

Toutes les options principales de la ligne de commande sont listées lorsque vous exécutez mausezahn sans arguments. Pour une utilisation pratique, gardez à l'esprit les options spéciales suivantes (pas très connues) :


-r Multiplie le délai spécifié par une valeur aléatoire.
-p <longueur> Remplit la trame brute jusqu'à la longueur spécifiée (en utilisant des octets aléatoires).
-P <Charge utile ASCII> Utilise la charge utile ASCII spécifiée.
-f <nom de fichier> Lit la charge utile ASCII à partir d'un fichier.
-F <nom de fichier> Lit la charge utile hexadécimale à partir d'un fichier.
-S Mode simulation : NE MET RIEN sur le fil.
Ceci est généralement combiné avec l'un des modes verbeux
(-v ou V).

De nombreuses options nécessitent un mot-clé ou un nombre, mais l'option -t fait exception car elle nécessite à la fois un type de paquet (tel que ip, udp, dns, etc.) et une chaîne d'arguments spécifique à ce type de paquet. Voici quelques exemples simples :


mausezahn -t help
mausezahn -t tcp help
mausezahn eth3 -t udp sp=69,dp=69,p=ca:fe:ba:be

Remarque : N'oubliez pas que sur l'interface de ligne de commande, le shell Linux (généralement Bash) interprète les espaces comme un délimiteur. C'est-à-dire, si vous spécifiez un argument composé de plusieurs mots avec des espaces entre eux, vous DEVEZ les grouper entre guillemets. Par exemple, au lieu de


mausezahn eth0 -t udp sp=1,dp=80,p=00:11:22:33


vous pouvez soit omettre les espaces


mausezahn eth0 -t udp sp=1,dp=80,p=00:11:22:33


soit, pour plus de sécurité, utiliser des guillemets :


mausezahn eth0 -t udp "sp=1,dp=80,p=00:11:22:33"

Afin de surveiller ce qui se passe, vous pouvez activer le mode verbeux en utilisant l'option -v. L'inverse est le mode silencieux (-q) qui gardera mausezahn absolument silencieux (sauf pour les messages d'erreur et les avertissements).

Ne confondez pas l'argument de charge utile p=... avec l'option de remplissage -p. Cette dernière est utilisée en dehors des guillemets !

Le constructeur de paquets automatique :

Un argument important est -t qui invoque un constructeur de paquets. Actuellement, il existe des constructeurs de paquets pour ARP, BPDU, CDP, IP, partiellement ICMP, UDP, TCP, RTP, DNS et SYSLOG. (De plus, vous pouvez insérer une étiquette VLAN ou une pile d'étiquettes MPLS, mais cela fonctionne indépendamment du constructeur de paquets.)

Vous obtenez une aide contextuelle pour chaque constructeur de paquets en utilisant le mot-clé help, tel que :


mausezahn -t bpdu help
mausezahn -t tcp help

Pour chaque paquet, vous pouvez spécifier une charge utile optionnelle. Ceci peut être fait soit via une notation hexadécimale en utilisant l'argument payload (ou court p), soit directement sous forme de texte ASCII en utilisant l'option -P :


mausezahn eth0 -t ip -P "Hello World" # Charge utile ASCII
mausezahn eth0 -t ip p=68:65:6c:6c:6f:20:77:6f:72:6c:64 # Charge utile hex
mausezahn eth0 -t ip "proto=89, \
p=68:65:6c:6c:6f:20:77:6f:72:6c:64, \ # identique avec autres
ttl=1" # Arguments IP

Remarque : Le mode d'accès direct à la liaison n'accepte que les charges utiles hexadécimales (car vous spécifiez tout en hexadécimal ici).

Nombre et délai des paquets :

Par défaut, un seul paquet est envoyé. Si vous souhaitez envoyer plus de paquets, utilisez l'option count -c <count>. Lorsque count est zéro, mausezahn enverra indéfiniment. Par défaut, mausezahn envoie à vitesse maximale (et c'est vraiment rapide ;-)). Si vous ne voulez pas submerger vos périphériques réseau ou si vous avez d'autres raisons d'envoyer à un rythme plus lent, vous pourriez vouloir spécifier un délai en utilisant l'option -d <delay>.

Si vous spécifiez seulement une valeur numérique, elle est interprétée en unités de microsecondes. Alternativement, pour une utilisation plus facile, vous pourriez spécifier des unités telles que secondes, sec, millisecondes ou msec. (Vous pouvez également l'abréger avec s ou m.) Remarque : N'utilisez pas d'espaces entre la valeur et l'unité ! Voici des exemples typiques :

Envoyer un nombre infini de trames aussi vite que possible :


mausezahn -c 0 "aa bb cc dd ...."

Envoyer 100 000 trames avec un intervalle de 50 ms :


mausezahn -c 100000 -d 50msec "aa bb cc dd ...."

Envoyer un nombre illimité de trames BPDU dans un intervalle de 2 secondes :


mausezahn -c 0 -d 2s -t bpdu conf

Remarque : mausezahn ne prend pas en charge les nombres fractionnaires. Si vous souhaitez spécifier par exemple 2,5 secondes, exprimez-le en millisecondes (2500 msec).

Adresses source et destination :

En guise de truc mnémotechnique, rappelez-vous que tous les paquets vont de "A" à "B". Vous pouvez toujours spécifier les adresses MAC source et destination en utilisant respectivement les options -a et -b. Ces options autorisent également des mots-clés tels que rand, own, bpdu, cisco, et d'autres.

De même, vous pouvez spécifier les adresses IP source et destination en utilisant respectivement les options -A et -B. Ces options prennent également en charge les FQDN (c'est-à-dire les noms de domaine) et les plages telles que 192.168.0.0/24 ou 10.0.0.11-10.0.3.22. De plus, l'option d'adresse source prend en charge le mot-clé rand (idéal pour les "attaques").

Remarque : Lorsque vous utilisez le constructeur de paquets pour les paquets basés sur IP (par exemple, UDP ou TCP), mausezahn s'occupe automatiquement des adresses MAC et IP correctes (c'est-à-dire qu'il effectue ARP, DHCP et DNS pour vous). Mais lorsque vous spécifiez au moins une adresse de couche de liaison (ou toute autre option L2 telle qu'une étiquette VLAN ou un en-tête MPLS), alors ARP est désactivé et vous devez vous occuper vous-même de l'adresse de destination Ethernet.

Couche-2 :

`-- Accès direct à la liaison :

mausezahn vous permet d'envoyer TOUTE chaîne d'octets directement via votre interface Ethernet :


mausezahn eth0 "ff:ff:ff:ff:ff:ff ff:ff:ff:ff:ff:ff 00:00 ca:fe:ba:be"

De cette façon, vous pouvez créer tous les paquets que vous souhaitez, mais vous devez le faire manuellement. Remarque : Sur les interfaces Wi-Fi, l'en-tête est beaucoup plus compliqué et un

automatiquement créé par le pilote Wi-Fi. Comme exemple pour introduire quelques options intéressantes, envoyons en continu des trames à vitesse maximale avec une adresse MAC source aléatoire et une adresse de destination de diffusion, et ajoutons en plus un bourrage de la trame à 1000 octets :


mausezahn eth0 -c 0 -a rand -b bcast -p 1000 "08 00 aa bb cc dd"

L'accès direct à la liaison prend en charge le bourrage automatique à l'aide de l'option -p <longueur totale de la trame>. Cela vous permet de bourrer une trame L2 brute à la longueur souhaitée. Vous devez spécifier la longueur totale, et la longueur totale de la trame doit être d'au moins 15 octets pour des raisons techniques. Zéro octet est utilisé pour le bourrage.

`-- ARP :

mausezahn fournit une interface simple pour le paquet ARP. Vous pouvez spécifier la méthode ARP (request|reply) et jusqu'à quatre arguments : sendermac, targetmac, senderip, targetip, ou leur abréviation smac, tmac, sip, tip. Par défaut, une réponse ARP est envoyée avec les adresses de votre propre interface comme adresse MAC et IP source, et une adresse MAC et IP de diffusion comme destination. Envoyez une requête ARP gratuite (utilisée pour la détection d'adresses IP dupliquées) :


mausezahn eth0 -t arp

Empoisonnement du cache ARP :


mausezahn eth0 -t arp "reply, senderip=192.168.0.1, targetmac=00:00:0c:01:02:03, \
targetip=172.16.1.50"


où par défaut votre adresse MAC d'interface sera utilisée comme sendermac, senderip désigne l'adresse IP usurpée, targetmac et targetip identifient le destinataire. Par défaut, l'adresse source Ethernet est votre adresse MAC d'interface et l'adresse de destination est l'adresse de diffusion. Vous pouvez modifier cela en utilisant les options -a et -b.

`-- BPDU :

mausezahn fournit une interface simple pour le format de trame BPDU 802.1D (utilisé pour créer l'arbre de Spanning dans les réseaux pontés). Par défaut, des BPDU IEEE 802.1D standard sont envoyées et il est supposé que votre ordinateur veut devenir le pont racine (rid=bid). Facultativement, l'adresse de destination 802.3 peut être une adresse MAC spécifiée, une adresse de diffusion, votre propre MAC, ou l'adresse MAC PVST+ de Cisco. L'adresse MAC de destination peut être spécifiée en utilisant la commande -b qui, en plus des adresses MAC, accepte des mots-clés tels que bcast, own, pvst, ou stp (par défaut). PVST+ est également pris en charge. Il suffit de spécifier le VLAN pour lequel vous souhaitez envoyer un BPDU :


mausezahn eth0 -t bpdu "vlan=123, rid=2000"

Consultez mausezahn -t bpdu help pour plus de détails.

`-- CDP :

mausezahn peut envoyer des messages Cisco Discovery Protocol (CDP) car ce protocole a une pertinence en matière de sécurité. Bien sûr, de nombreux tours de passe-passe sont possibles ; par exemple, des TLV arbitraires peuvent être créés (en utilisant l'argument de charge utile hexadécimale, par exemple p=00:0e:00:07:01:01:90) et si vous souhaitez stresser la base de données CDP d'un appareil, mausezahn peut envoyer chaque message CDP avec un identifiant de système différent en utilisant le mot-clé change :


mausezahn -t cdp change -c 0

Certains routeurs et commutateurs peuvent rencontrer de graves problèmes ;-) Consultez mausezahn -t cdp help pour plus de détails.

`-- Tags VLAN 802.1Q :

mausezahn permet un marquage VLAN simple pour les paquets IP (et autres couches supérieures). Utilisez simplement l'option -Q <[CoS:]VLAN>, telle que -Q 10 ou -Q 3:921. Par défaut, CoS=0. Par exemple, envoyez un paquet TCP dans le VLAN 500 en utilisant CoS=7 :


mausezahn eth0 -t tcp -Q 7:500 "dp=80, flags=rst, p=aa:aa:aa"

Vous pouvez créer autant de tags VLAN que vous le souhaitez ! C'est intéressant pour créer des encapsulations QinQ ou des sauts de VLAN : Envoyez un paquet UDP avec les tags VLAN 100 (externe) et 651 (interne) :


mausezahn eth0 -t udp "dp=8888, sp=13442" -P "Mausezahn is great" -Q 100,651

Je ne sais pas si c'est utile quelque part, mais au moins c'est possible :


mausezahn eth0 -t udp "dp=8888, sp=13442" -P "Mausezahn is great" \
-Q 6:5,7:732,5:331,5,6

Mélangez-le avec MPLS :


mausezahn eth0 -t udp "dp=8888, sp=13442" -P "Mausezahn is great" -Q 100,651 -M 314

En mode couche 2 brute, vous devez créer le tag VLAN entièrement vous-même. Par exemple, si vous souhaitez envoyer une trame dans le VLAN 5 en utilisant CoS 0, spécifiez simplement 81:00 comme champ de type et pour les deux octets suivants, les valeurs CoS (PCP), DEI (CFI) et ID de VLAN (toutes ensemble connues sous le nom de TCI) :


mausezahn eth0 -b bc -a rand "81:00 00:05 08:00 aa-aa-aa-aa-aa-aa-aa-aa-aa"

`-- Étiquettes MPLS :

mausezahn vous permet d'insérer une ou plusieurs en-têtes MPLS. Utilisez simplement l'option -M <label:CoS:TTL:BoS> où seule l'étiquette est obligatoire. Si vous spécifiez un deuxième nombre, il est interprété comme les bits expérimentaux (généralement le CoS). Si vous spécifiez un troisième nombre, il est interprété comme le TTL. Par défaut, le TTL est défini sur 255. Le drapeau Bottom of Stack (BoS) est automatiquement défini, sinon la trame serait invalide, mais si vous le souhaitez, vous pouvez également le définir ou le désactiver en utilisant les arguments S (set) et s (unset). Notez que BoS doit être le dernier argument de chaque définition d'en-tête MPLS. Voici quelques exemples :

Utilisation de l'étiquette MPLS 214 :


mausezahn eth0 -M 214 -t tcp "dp=80" -P "HTTP..." -B myhost.com

Utilisation de trois étiquettes (le 214 est maintenant l'extérieur) :


mausezahn eth0 -M 9999,51,214 -t tcp "dp=80" -P "HTTP..." -B myhost.com

Utilisation de deux étiquettes, une avec CoS=5 et TTL=1, l'autre avec CoS=7 :


mausezahn eth0 -M 100:5:1,500:7 -t tcp "dp=80" -P "HTTP..." -B myhost.com

Désactivation du drapeau BoS (ce qui entraînera une trame invalide) :


mausezahn eth0 -M 214:s -t tcp "dp=80" -P "HTTP..." -B myhost.com

Couche 3-7 :

Les paquets IP, UDP et TCP peuvent être bourrés en utilisant l'option -p. Actuellement, 0x42 est utilisé comme octet de bourrage ('la réponse'). Vous ne pouvez pas bourrer les paquets DNS (cela serait inutile de toute façon).

`-- IP :

mausezahn vous permet d'envoyer des paquets IP malformés ou corrects. Chaque champ de l'en-tête IP peut être manipulé. Les adresses IP peuvent être spécifiées via les options -A et -B, désignant respectivement l'adresse source et destination. Vous pouvez également spécifier une plage d'adresses ou un nom d'hôte (FQDN). De plus, l'adresse source peut également être aléatoire. Par défaut, l'adresse source est l'adresse IP de votre interface et l'adresse de destination est une adresse de diffusion. Voici quelques exemples :

Charge utile ASCII :


mausezahn eth0 -t ip -A rand -B 192.168.1.0/24 -P "hello world"

Charge utile hexadécimale :


mausezahn eth0 -t ip -A 10.1.0.1-10.1.255.254 -B 255.255.255.255 p=ca:fe:ba:be

Utilisera l'adresse IP source correcte :


mausezahn eth0 -t ip -B www.xyz.com

L'octet Type de Service (ToS) peut être spécifié directement par deux chiffres hexadécimaux, ce qui signifie que vous pouvez également définir facilement les bits ECN (Explicit Congestion Notification) (LSB 1 et 2), ou vous pouvez seulement vouloir spécifier une valeur DSCP commune (bits 3-8) en utilisant un nombre décimal (0..63) :

Paquet envoyé avec DSCP = Expedited Forwarding (EF) :


mausezahn eth0 -t ip dscp=46,ttl=1,proto=1,p=08:00:5a:a2:de:ad:be:af

Si vous laissez la somme de contrôle à zéro (ou non spécifiée), la somme de contrôle correcte sera calculée automatiquement. Notez que vous ne pouvez utiliser une somme de contrôle incorrecte que si vous spécifiez en même temps au moins un champ L2 manuellement.

`-- UDP :

mausezahn prend en charge la génération facile de datagrammes UDP. Spécifiez simplement l'adresse de destination (option -B) et éventuellement une adresse source arbitraire (option -A) et comme arguments, vous pouvez spécifier les numéros de port en utilisant les arguments dp (port de destination) et sp (port source) et une charge utile. Vous pouvez également spécifier facilement une plage de ports entière, ce qui entraînera l'envoi de plusieurs paquets. Voici quelques exemples :

Envoyer des paquets de test à la plage de ports RTP :


mausezahn eth0 -B 192.168.1.1 -t udp "dp=16384-32767, \
p=A1:00:CC:00:00:AB:CD:EE:EE:DD:DD:00"

Envoyer une requête DNS en diffusion locale (souvent un routeur local répond) :


mausezahn eth0 -t udp dp=53,p=c5-2f-01-00-00-01-00-00-00-00-00-00-03-77-77-\
77-03-78-79-7a-03-63-6f-6d-00-00-01-00-01"

De plus, vous pouvez spécifier la longueur et la somme de contrôle en utilisant les arguments len et sum (elles seront correctement définies par défaut). Remarque : plusieurs protocoles ont les mêmes arguments tels que len (longueur) et sum (somme de contrôle). Si vous avez spécifié un paquet de type UDP (via -t udp) et que vous souhaitez modifier la longueur IP, utilisez les mots-clés alternatifs iplen et ipsum. Notez également que vous devez spécifier au moins un champ L2 qui indique à mausezahn de construire tout sans l'aide de votre noyau (le noyau ne permettrait pas de modifier la somme de contrôle IP et la longueur IP).

`-- ICMP :

mausezahn prend actuellement en charge uniquement les méthodes ICMP suivantes : PING (requête d'écho), Redirect (divers types), Unreachable (divers types). D'autres types ICMP seront pris en charge à l'avenir. Actuellement, vous devriez les adapter vous-même, par exemple en utilisant le constructeur de paquets IP (en définissant proto=1). Utilisez mausezahn -t icmp help pour obtenir de l'aide sur les options actuellement implémentées.

`-- TCP :

mausezahn vous permet de configurer facilement n'importe quel paquet TCP. Similairement à UDP, vous pouvez spécifier des ports source et destination (plages) en utilisant les arguments sp et dp. Ensuite, vous pouvez spécifier directement les drapeaux souhaités en utilisant un "|" comme délimiteur si vous voulez spécifier plusieurs drapeaux. Par exemple, une attaque SYN-Flood contre l'hôte 1.1.1.1 en utilisant une adresse IP source aléatoire et en utilisant périodiquement tous les 1023 ports bien connus pourrait être créée via :


mausezahn eth0 -A rand -B 1.1.1.1 -c 0 -t tcp "dp=1-1023, flags=syn" \
-P "Good morning! This is a SYN Flood Attack. \
We apologize for any inconvenience."

Soyez prudent avec de telles inondations SYN et utilisez-les uniquement pour les tests de pare-feu. Vérifiez votre position légale ! Rappelez-vous qu'un hôte avec une session TCP ouverte n'accepte que les paquets

s avec des informations de socket correctes (adresses et ports) et un numéro de séquence TCP (SQNR) valide. Si vous voulez essayer une attaque DoS en envoyant un RST-flood et que vous NE connaissez PAS le SQNR initial de la cible (ce qui est normalement le cas), vous pouvez vouloir balayer une plage de numéros de séquence :


mausezahn eth0 -A legal.host.com -B target.host.com \
-t tcp "sp=80,dp=80,s=1-4294967295"

Heureusement, le SQNR doit correspondre au numéro d'acquittement de l'hôte cible plus la taille de fenêtre annoncée. Étant donné que la taille de fenêtre typique se situe entre 40000 et 65535, vous êtes BEAUCOUP plus rapide en utilisant un incrément via l'argument ds :


mausezahn eth0 -A legal.host.com -B target.host.com \
-t tcp "sp=80, dp=80, s=1-4294967295, ds=40000"

Dans ce dernier cas, mausezahn n'enverra que 107375 paquets au lieu de 4294967295 (ce qui se traduit par une durée d'environ 1 seconde contre 11 heures !). Bien sûr, vous pouvez adapter n'importe quel paquet TCP à votre guise. Comme avec les autres protocoles L4, mausezahn construit un en-tête IP correct, mais vous pouvez en plus accéder à chaque champ du paquet IP (ainsi qu'à la trame Ethernet).

`-- DNS:

mausezahn prend en charge les requêtes ou réponses DNS basées sur UDP. Typiquement, vous pourriez vouloir envoyer une requête ou une réponse. Comme d'habitude, vous pouvez modifier chaque drapeau dans l'en-tête. Voici un exemple de requête simple :


mausezahn eth0 -B mydns-server.com -t dns "q=www.ibm.com"

Vous pouvez également créer des messages de type serveur :


mausezahn eth0 -A spoofed.dns-server.com -B target.host.com \
"q=www.topsecret.com, a=172.16.1.1"

La syntaxe selon l'aide en ligne (-t dns help) est :


query|q = <name>[:<type>] ............. où type est par défaut "A"
(et la classe est toujours "IN")
answer|a = [<type>:<ttl>:]<rdata> ...... ttl est par défaut 0.
= [<type>:<ttl>:]<rdata>/[<type>:<ttl>:]<rdata>/...

Remarque : Si vous utilisez uniquement l'option 'query', une requête est envoyée. Si vous ajoutez en plus une option 'answer', une réponse est envoyée. Exemples :


q = www.xyz.com
q = www.xyz.com, a=192.168.1.10
q = www.xyz.com, a=A:3600:192.168.1.10
q = www.xyz.com, a=CNAME:3600:abc.com/A:3600:192.168.1.10

Essayez mausezahn -t dns help pour voir les nombreuses autres options de ligne de commande facultatives.

`-- Mesures de chemin RTP et VoIP :

mausezahn peut envoyer des paquets arbitraires du Real Time Protocol (RTP). Par défaut, un paquet de codec classique G.711 d'une taille de segment de 20 ms et de 160 octets est supposé. Vous pouvez mesurer la gigue, la perte de paquets et le réordonnancement le long d'un chemin entre deux hôtes exécutant mausezahn. La mesure de la gigue est effectuée soit en suivant l'estimation filtrée passe-bas de la variance spécifiée dans la RFC 3550, soit en utilisant une méthode alternative "en temps réel" encore plus précise (la méthode RFC est utilisée par défaut). Par exemple, sur l'Hôte1, vous démarrez un processus de transmission :


mausezahn -t rtp -B 192.168.1.19

Et sur l'Hôte2 (192.168.1.19), un processus de réception qui effectue la mesure :


mausezahn -T rtp

Notez que l'indicateur d'option avec le "T" majuscule signifie qu'il s'agit d'un processus RTP serveur, attendant les paquets RTP entrants de n'importe quelle source mausezahn. Si vous souhaitez limiter la mesure à une source spécifique ou effectuer une mesure bidirectionnelle, vous devez spécifier un identifiant de flux. Voici un exemple de mesures bidirectionnelles qui enregistre la moyenne courante de la gigue dans un fichier :


Hôte1# mausezahn -t rtp id=11:11:11:11 -B 192.168.2.2 &
Hôte1# mausezahn -T rtp id=22:22:22:22 "log, path=/tmp/mz/"


Hôte2# mausezahn -t rtp id=22:22:22:22 -B 192.168.1.1 &
Hôte2# mausezahn -T rtp id=11:11:11:11 "log, path=/tmp/mz/"

`-- Syslog:

Le protocole Syslog traditionnel est largement utilisé, même dans les réseaux professionnels, et est parfois vulnérable. Par exemple, vous pourriez insérer des messages Syslog forgés en usurpant votre adresse source (par exemple, en vous faisant passer pour un périphérique réseau légitime) :


mausezahn -t syslog sev=3 -P "You have been mausezahned." -A 10.1.1.109 -B 192.168.7.7

Voir mausezahn -t syslog help pour plus de détails.

NOTE

Lorsque plusieurs plages sont spécifiées, par exemple des plages de ports de destination et des plages d'adresses de destination, toutes les combinaisons possibles de ports et d'adresses sont utilisées pour la génération de paquets. De plus, cela peut être combiné avec d'autres plages, par exemple une plage de numéros de séquence TCP. Notez que la combinaison de plages peut entraîner un très grand nombre de trames à envoyer. En règle générale, vous pouvez supposer qu'environ 100 000 trames ou plus sont envoyées en une fraction de seconde, en fonction de votre interface réseau.

mausezahn a été conçu comme un générateur de trafic rapide, vous pouvez donc facilement submerger un segment LAN avec une myriade de paquets. Et comme mausezahn peut également prendre en charge les audits de sécurité, il est possible de créer des paquets malveillants ou invalides, des SYN floods, des balayages de ports et d'adresses, l'empoisonnement DNS et ARP, etc.

Par conséquent, n'utilisez pas cet outil si vous n'êtes pas conscient des conséquences possibles ou si vous avez peu de connaissances sur les réseaux et la communication de données. Si vous abusez de mausezahn pour des attaques "non autorisées" et que vous êtes pris, ou si vous endommagez quelque chose qui vous appartient, c'est entièrement de votre faute. La solution la plus sûre est donc de l'essayer dans un environnement de laboratoire.

Consultez également la section note de netsniff-ng(8) sur la manière de configurer et d'optimiser correctement votre système.

    NOM

    mausezahn — Générer du trafic réseau pour des tests

    SYNTAXE

    mausezahn [options] -f <fichier_de_paquets> [-o <fichier_de_paquets>] []
    mausezahn [options] -p <type_de_paquet> [-o <fichier_de_paquets>] []
    mausezahn [options] -i <interface>

    DESCRIPTION

    Mausezahn est un outil de génération de trafic réseau conçu pour la génération de trafic pour des tests.

    OPTIONS

    -f <fichier_de_paquets>
    Charge la définition des paquets à partir du fichier spécifié. Le fichier peut contenir des paquets dans un format texte lisible par l'homme.
    -p <type_de_paquet>
    Définit le type de paquet à générer. Par exemple : arp, udp, tcp, icmp.
    -o <fichier_de_paquets>
    Écrit les paquets générés dans le fichier spécifié. Utile pour capturer le trafic généré pour une analyse ultérieure.
    -i <interface>
    Spécifie l'interface réseau à utiliser pour envoyer le trafic. Par défaut, utilise la première interface disponible.
    <nombre_de_paquets>
    Le nombre de paquets à envoyer. S'il n'est pas spécifié, mausezahn fonctionne en mode interactif.
    -v
    Mode verbeux. Affiche des informations détaillées sur les paquets envoyés.
    -d
    Mode de débogage. Affiche des informations de débogage supplémentaires.
    -h
    Affiche l'aide.

    MODE INTERACTIF COMMENT FAIRE

    Pour exécuter mausezahn en mode interactif, ne spécifiez pas le nombre de paquets.

    1. Exécutez mausezahn -i eth0 (remplacez eth0 par votre interface).
    2. Vous serez invité à choisir le type de paquet ou à charger un fichier de définition de paquet.
    3. Suivez les instructions pour configurer les détails du paquet.
    4. Appuyez sur Entrée pour envoyer le paquet.
    5. Tapez quit ou exit pour quitter.

    MODE DIRECT COMMENT FAIRE

    Pour générer un certain nombre de paquets sans interaction :

    1. Utilisez l'option -p pour spécifier le type de paquet, par exemple -p udp.
    2. Spécifiez le nombre de paquets à envoyer, par exemple 1000.
    3. Exemple : mausezahn -i eth0 -p udp 1000 envoie 1000 paquets UDP sur l'interface eth0.
    4. Pour enregistrer le trafic, utilisez l'option -o : mausezahn -i eth0 -p udp -o capture.pcap 1000.

    NOTE

    L'utilisation de mausezahn pour générer du trafic réseau peut avoir des implications sur le réseau. Utilisez cet outil de manière responsable et uniquement sur des réseaux que vous êtes autorisé à tester.
