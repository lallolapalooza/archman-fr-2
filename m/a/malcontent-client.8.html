NOM

malcontent-client - Utilitaire d'accès aux contrôles parentaux

SYNTAXE

malcontent-client get-app-filter [-q] [-n] [UTILISATEUR]

malcontent-client check-app-filter [-q] [-n] [UTILISATEUR] ARG

malcontent-client set-app-filter [-q] [-n] [UTILISATEUR] ARG

malcontent-client oars-section [-q] [-n] [UTILISATEUR] SECTION

malcontent-client get-session-limits [-q] [-n] [UTILISATEUR]

malcontent-client monitor [-q] [UTILISATEUR]

DESCRIPTION

malcontent-client est un utilitaire permettant d'interroger et de modifier les paramètres des contrôles parentaux pour les utilisateurs du système. Il nécessitera généralement un accès administrateur pour faire autre chose que d'interroger les contrôles parentaux de l'utilisateur courant.

Il communique avec accounts-service, qui stocke les données des contrôles parentaux.

Son premier argument est une commande à exécuter. Les commandes supportées sont documentées ci-dessous.

L'API en ligne de commande et le format de sortie sont instables et susceptibles de changer dans les futures versions de malcontent-client.

OPTIONS get-app-filter

Obtenir le filtre d'applications pour un utilisateur. Par exemple :

# malcontent-client get-app-filter timmy
UTILISATEUR
Nom d'utilisateur ou ID de l'utilisateur pour lequel obtenir le filtre d'applications. S'il n'est pas spécifié, l'utilisateur actuel sera utilisé par défaut.
-q, --quiet
N'afficher que les messages d'erreur, et aucun message informatif, pendant la progression de l'opération. (Par défaut : Afficher les messages informatifs.)
-n, --no-interactive
Ne pas autoriser l'authentification interactive avec polkit. Si cela est nécessaire pour terminer l'opération, celle-ci échouera. (Par défaut : Autoriser l'authentification interactive.)

OPTIONS check-app-filter

Vérifier si un programme donné, un type de contenu ou une référence flatpak est autorisé à être utilisé par un utilisateur, conformément à son filtre d'applications actuel. Par exemple :

# malcontent-client check-app-filter timmy $(which gnome-calculator)

# malcontent-client check-app-filter timmy x-scheme-handler/http

# malcontent-client check-app-filter timmy app/com.realm667.WolfenDoom_Blade_of_Agony/x86_64/stable

UTILISATEUR
Nom d'utilisateur ou ID de l'utilisateur pour lequel obtenir le filtre d'applications. S'il n'est pas spécifié, l'utilisateur actuel sera utilisé par défaut.
ARG
Chemin d'un programme, d'un type de contenu ou d'une référence flatpak à vérifier par rapport au filtre d'applications, pour voir s'il est autorisé pour l'utilisateur spécifié.
-q, --quiet
N'afficher que les messages d'erreur, et aucun message informatif, pendant la progression de l'opération. (Par défaut : Afficher les messages informatifs.)
-n, --no-interactive
Ne pas autoriser l'authentification interactive avec polkit. Si cela est nécessaire pour terminer l'opération, celle-ci échouera. (Par défaut : Autoriser l'authentification interactive.)

OPTIONS set-app-filter

Définir le filtre d'applications pour un utilisateur, en remplaçant toutes les valeurs précédentes. Par exemple :

# malcontent-client set-app-filter timmy \
--disallow-user-installation \
$(which gnome-calculator) \
x-scheme-handler/http \
app/com.realm667.WolfenDoom_Blade_of_Agony/x86_64/stable
UTILISATEUR
Nom d'utilisateur ou ID de l'utilisateur pour lequel définir le filtre d'applications. S'il n'est pas spécifié, l'utilisateur actuel sera utilisé par défaut.
ARG
Élément à filtrer dans le filtre d'applications de l'utilisateur. Il peut s'agir d'un chemin d'accès absolu ou d'une référence flatpak d'un programme à bloquer ; d'un type de contenu pour lequel bloquer tous les programmes ; ou d'une paire section=valeur OARS pour bloquer l'installation d'applications avec une classification plus extrême pour cette section OARS. Plusieurs éléments peuvent être spécifiés, et ils remplaceront entièrement le filtre d'applications actuel de l'utilisateur. Si zéro élément est spécifié, le filtre d'applications est vidé.
--allow-user-installation
Autoriser l'utilisateur à installer des flatpaks dans son dépôt utilisateur.
--disallow-user-installation
Interdire à l'utilisateur d'installer des flatpaks dans son dépôt utilisateur.
--allow-system-installation
Autoriser l'utilisateur à installer des flatpaks dans le dépôt système.
--disallow-system-installation
Interdire à l'utilisateur d'installer des flatpaks dans le dépôt système.
-q, --quiet
N'afficher que les messages d'erreur, et aucun message informatif, pendant la progression de l'opération. (Par défaut : Afficher les messages informatifs.)
-n, --no-interactive
Ne pas autoriser l'authentification interactive avec polkit. Si cela est nécessaire pour terminer l'opération, celle-ci échouera. (Par défaut : Autoriser l'authentification interactive.)

OPTIONS oars-section

Obtenir la valeur définie pour une section OARS spécifique du filtre d'applications de l'utilisateur donné. Par exemple :

# malcontent-client oars-section timmy language-profanity
UTILISATEUR
Nom d'utilisateur ou ID de l'utilisateur pour lequel obtenir le filtre OARS. S'il n'est pas spécifié, l'utilisateur actuel sera utilisé par défaut.
SECTION
Section OARS pour laquelle obtenir le niveau de restriction de l'utilisateur donné. Par exemple, language-profanity.
-q, --quiet
N'afficher que les messages d'erreur, et aucun message informatif, pendant la progression de l'opération. (Par défaut : Afficher les messages informatifs.)
-n, --no-interactive
Ne pas autoriser l'authentification interactive avec polkit. Si cela est nécessaire pour terminer l'opération, celle-ci échouera. (Par défaut : Autoriser l'authentification interactive.)

OPTIONS get-session-limits

Obtenir les limites de session définies pour un utilisateur. Par exemple :

# malcontent-client get-session-limits timmy
UTILISATEUR
Nom d'utilisateur ou ID de l'utilisateur pour lequel obtenir les limites de session. S'il n'est pas spécifié, l'utilisateur actuel sera utilisé par défaut.
-q, --quiet
N'afficher que les messages d'erreur, et aucun message informatif, pendant la progression de l'opération. (Par défaut : Afficher les messages informatifs.)
-n, --no-interactive
Ne pas autoriser l'authentification interactive avec polkit. Si cela est nécessaire pour terminer l'opération, celle-ci échouera. (Par défaut : Autoriser l'authentification interactive.)
--now aaaa-mm-jjThh:mm:ssZ
Vérifier les limites de session (en particulier, l'heure d'expiration de la session) par rapport à la date/heure donnée, fournie au format ISO 8601. (Par défaut : Date/heure actuelle.)

OPTIONS monitor

Surveiller les modifications apportées aux paramètres des contrôles parentaux pour un utilisateur spécifique. Par exemple :

# malcontent-client monitor timmy
UTILISATEUR
Nom d'utilisateur ou ID de l'utilisateur pour lequel surveiller les contrôles parentaux. S'il n'est pas spécifié, l'utilisateur actuel sera utilisé par défaut.
-q, --quiet
N'afficher que les messages d'erreur, et aucun message informatif, pendant la progression de l'opération. (Par défaut : Afficher les messages informatifs.)

STATUT DE SORTIE

malcontent-client peut retourner l'un des codes d'erreur suivants s'il rencontre des problèmes.

0
Aucun problème n'est survenu. L'utilitaire s'est exécuté et a interrogé avec succès le filtre d'application. Si vous exécutez la commande check-app-filter, le chemin, le type de contenu ou la référence flatpak donné était autorisé pour l'utilisateur donné.
1
Une option invalide a été passée à malcontent-client au démarrage.
2
L'utilisateur actuel n'était pas autorisé à interroger le filtre d'application pour l'utilisateur donné.
3
Si vous exécutez la commande check-app-filter, le chemin, le type de contenu ou la référence flatpak donné n'était pas autorisé pour l'utilisateur donné.
4
Malcontent est désactivé au niveau du système, et donc les contrôles parentaux ne sont pas activés ou appliqués.
5
Une opération a échoué et aucune information d'erreur plus spécifique n'est disponible.
