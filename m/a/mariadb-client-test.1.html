MARIADB-CLIENT-TEST(1) Système de base de données MariaDB MARIADB-CLIENT-TEST(1)

NOM

mariadb-client-test - tester l'API client (mariadb-client-test est maintenant un lien symbolique vers mariadb-client-test)
mariadb-client-test-embedded - tester l'API client pour le serveur embarqué (mariadb-client-test-embedded est maintenant un lien symbolique vers mariadb-client-test-embedded)

SYNTAXE

mariadb-client-test [options] [nom_test] ...

mariadb-client-test-embedded [options] [nom_test] ...

DESCRIPTION

Le programme mariadb-client-test est utilisé pour tester des aspects de l'API client MariaDB qui ne peuvent pas être testés à l'aide de mariadb-test et de son langage de test. mariadb-client-test-embedded est similaire mais utilisé pour tester le serveur embarqué. Les deux programmes sont exécutés dans le cadre de la suite de tests.

Le code source des programmes se trouve dans tests/mariadb-client-test.c dans une distribution source. Le programme sert de bon exemple illustrant comment utiliser diverses fonctionnalités de l'API client.

mariadb-client-test est utilisé dans un test du même nom dans la suite principale de tests de mariadb-test-run.pl mais peut également être exécuté directement. Contrairement aux autres programmes listés ici, il ne lit pas de description externe des tests à exécuter. Au lieu de cela, tous les tests sont codés dans le programme, qui est écrit pour couvrir tous les aspects de l'API du langage C.

mariadb-client-test prend en charge les options suivantes :

•--help, -?

Affiche un message d'aide et quitte.

•--basedir=nom_rép, -b nom_rép

Le répertoire de base pour les tests.

•--count=compte, -t compte

Le nombre de fois où exécuter les tests.

•--database=nom_bd, -D nom_bd

La base de données à utiliser.

•--debug[=options_debug], -#[options_debug]

Écrit un journal de débogage si MariaDB est compilé avec la prise en charge du débogage. La valeur par défaut de options_debug est 'd:t:o,/tmp/mariadb-client-test.trace'.

•--getopt-ll-test=option, -g option

Option à utiliser pour tester les bogues dans la bibliothèque getopt.

•--host=nom_hôte, -h nom_hôte

Se connecte au serveur MariaDB sur l'hôte donné.

•--password[=mot_de_passe], -p[mot_de_passe]

Le mot de passe à utiliser lors de la connexion au serveur. Si vous utilisez la forme courte de l'option (-p), vous ne pouvez pas laisser d'espace entre l'option et le mot de passe. Si vous omettez la valeur de mot_de_passe suivant l'option --password ou -p sur la ligne de commande, vous serez invité à en saisir un.

•--port=num_port, -P num_port

Le numéro de port TCP/IP à utiliser pour la connexion.

•--server-arg=arg, -A arg

Argument à envoyer au serveur embarqué.

•--show-tests, -T

Affiche tous les noms de tests.

•--silent, -s

Soyez plus silencieux.

•--socket=chemin, -S chemin

Le fichier socket à utiliser lors de la connexion à localhost (qui est l'hôte par défaut).

•--testcase, -c

L'option est utilisée lorsqu'elle est appelée depuis mariadb-test-run.pl, afin que mariadb-client-test puisse éventuellement se comporter différemment de lorsqu'il est appelé manuellement, par exemple en sautant certains tests. Actuellement, il n'y a pas de différence de comportement mais l'option est incluse afin de rendre cela possible.

•--user=nom_utilisateur, -u nom_utilisateur

Le nom d'utilisateur MariaDB à utiliser lors de la connexion au serveur.

•-v nom_rép, --vardir=nom_rép

Le répertoire de données pour les tests. Par défaut, c'est mariadb-test/var.
