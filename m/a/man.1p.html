MAN(1P) Manuel du programmeur POSIX MAN(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

man — afficher la documentation du système

SYNOPIS

man [-k] nom...

DESCRIPTION

L'utilitaire man écrira des informations sur chacun des opérandes nom. Si nom est le nom d'un utilitaire standard, man écrira au minimum un message décrivant la syntaxe utilisée par l'utilitaire standard, ses options et ses opérandes. Si plus d'informations sont disponibles, l'utilitaire man les fournira d'une manière définie par l'implémentation.

Une implémentation peut fournir des informations pour des valeurs de nom autres que les utilitaires standard. Les utilitaires standard qui sont listés comme optionnels et qui ne sont pas pris en charge par l'implémentation provoqueront soit un bref message indiquant ce fait, soit un affichage complet des informations comme décrit précédemment.

OPTIONS

L'utilitaire man doit être conforme au volume des Définitions de base de POSIX.1‐2017, Section 12.2, Conventions de syntaxe des utilitaires.

L'option suivante doit être prise en charge :

-k
Interpréter les opérandes nom comme des mots-clés à utiliser pour rechercher dans une base de données de résumé des utilitaires qui contient une brève entrée de but pour chaque utilitaire standard et écrire les lignes de la base de données de résumé qui correspondent à l'un des mots-clés. La recherche par mot-clé produira des résultats équivalents à la sortie de la commande suivante :
grep -Ei '
nom
nom
...
' base-de-données-résumé

Cela suppose que la base-de-données-résumé est un fichier texte avec une entrée par ligne ; cette organisation n'est pas requise et l'exemple utilisant grep -Ei n'est qu'illustratif du type de recherche envisagé. L'entrée de but à inclure dans la base de données doit consister en une description concise du but de l'utilitaire.

OPÉRANDES

L'opérande suivant doit être pris en charge :

nom
Un mot-clé ou le nom d'un utilitaire standard. Lorsque -k n'est pas spécifié et que nom ne représente pas l'un des utilitaires standard, les résultats ne sont pas spécifiés.

ENTRÉE STANDARD

Non utilisé.

FICHIERS D'ENTRÉE

Aucun.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de man :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume des Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si elle est définie sur une chaîne de caractères non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments et dans la base de données de résumé). La valeur de LC_CTYPE n'a pas à affecter le format des informations écrites sur les opérandes nom.
LC_MESSAGES

Détermine la locale qui devrait être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard et les messages informatifs écrits sur la sortie standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.
PAGER
Détermine une commande de filtrage de sortie pour écrire la sortie sur un terminal. Toute chaîne acceptable comme opérande chaine_commande pour la commande sh -c est valide. Lorsque la sortie standard est un périphérique terminal, la sortie de la page de référence sera dirigée via la commande. Si la variable PAGER est nulle ou non définie, la commande sera soit more, soit un autre utilitaire de pagination documenté dans la documentation du système.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

SORTIE STANDARD

L'utilitaire man écrira un texte décrivant la syntaxe de l'utilitaire nom, ses options et ses opérandes, ou, lorsque -k est spécifié, des lignes de la base de données de résumé. Le format de ce texte est défini par l'implémentation.

SORTIE D'ERREUR

La sortie d'erreur standard sera utilisée pour les messages de diagnostic, et peut également être utilisée pour des messages informatifs de format non spécifié.

FICHIERS DE SORTIE

Aucun.

DESCRIPTION ÉTENDUE

Aucune.

 0
Achèvement réussi.
>0
Une erreur s'est produite.

JUSTIFICATION

Il est reconnu que l'utilitaire man n'a qu'une utilité minimale telle que spécifiée. L'avis des développeurs du standard était fortement divisé quant à la quantité d'informations que man devrait être obligé de fournir. Ils ont cependant considéré que la fourniture d'un moyen portable d'accéder à la documentation aiderait à la portabilité de l'utilisateur.

Les arguments contre une spécification plus complète étaient :

*
Des quantités importantes de documentation ne devraient pas être requises sur un système qui ne dispose pas d'espace disque excédentaire.
*
Le système manuel actuel ne présente pas les informations d'une manière qui facilite grandement la portabilité de l'utilisateur.
*
Un « meilleur système d'aide » est actuellement un domaine dans lequel les fournisseurs estiment pouvoir ajouter de la valeur à leurs implémentations POSIX.

L'option -f a été envisagée, mais en raison des différences d'implémentation, elle n'a pas été incluse dans ce volume de POSIX.1‐2017.

La description a été modifiée pour être plus spécifique sur ce qui doit être affiché pour un utilitaire. Les développeurs du standard ont estimé qu'il était insuffisant de permettre l'affichage de la seule synopsis sans donner une brève description de ce que fait chaque option et opérande.

L'entrée « but » à inclure dans la base de données peut être similaire au titre de section (moins le préfixe numérique) de ce volume de POSIX.1‐2017 pour chaque utilitaire. Ces titres sont similaires à ceux utilisés dans les systèmes historiques à cette fin.

La réserve dans la description de LC_CTYPE a été ajoutée car il n'est pas une exigence qu'une implémentation fournisse des pages de référence pour toutes ses locales prises en charge sur chaque système ; changer LC_CTYPE ne traduit pas nécessairement la page de référence dans une autre langue. Ceci est équivalent à l'état actuel de LC_MESSAGES dans POSIX.1-2008 — les messages spécifiques à la locale ne sont pas encore une exigence.

La variable historique MANPATH n'est pas incluse dans POSIX car aucune tentative n'est faite pour spécifier les conventions de nommage pour les fichiers de pages de référence, ni même pour imposer qu'il s'agisse de fichiers. Sur certaines implémentations, il pourrait s'agir d'une véritable base de données, d'un fichier hypertexte, ou même de chaînes fixes dans l'exécutable man. Les développeurs du standard ont considéré que la portabilité des pages de référence était en dehors de leur champ de travail. Cependant, les utilisateurs doivent être conscients que MANPATH est implémenté sur un certain nombre de systèmes historiques et qu'il peut être utilisé pour adapter le modèle de recherche des pages de référence des différentes catégories (utilitaires, fonctions, formats de fichiers, etc.) lorsque l'administrateur système révèle l'emplacement et les conventions pour les pages de référence sur le système.

La recherche par mot-clé peut s'appuyer au moins sur le texte des titres de section de ces descriptions d'utilitaires, et l'implémentation peut ajouter des mots-clés supplémentaires. Le terme « titres de section » fait référence aux chaînes telles que :

man — Affiche la documentation du système
ps — Rapporte le statut des processus
