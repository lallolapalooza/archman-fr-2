MAGIC(5) Formats de fichiers Manuel MAGIC(5)

NOM

magic — fichier de motifs magiques de la commande file

DESCRIPTION

Cette page de manuel documente le format des fichiers magiques tels qu'utilisés par la commande file(1), version 5.46. La commande file(1) identifie le type d'un fichier en utilisant, entre autres tests, un test pour déterminer si le fichier contient certains “motifs magiques”. La base de données de ces “motifs magiques” est généralement située dans un fichier binaire dans /usr/share/file/misc/magic.mgc ou dans un répertoire de fichiers fragments de motifs magiques sources dans /usr/share/file/misc/magic. La base de données spécifie quels motifs doivent être testés, quel message ou quel type MIME afficher si un motif particulier est trouvé, et quelles informations supplémentaires doivent être extraites du fichier.

Le format des fichiers fragments sources utilisés pour construire cette base de données est le suivant : chaque ligne d'un fichier fragment spécifie un test à effectuer. Un test compare les données commençant à un décalage particulier dans le fichier avec une valeur d'octet, une chaîne de caractères ou une valeur numérique. Si le test réussit, un message est affiché. La ligne se compose des champs suivants :

décalage
Un nombre spécifiant le décalage (en octets) dans le fichier des données qui doivent être testées. Ce décalage peut être un nombre négatif s'il s'agit :
  • Du premier décalage direct de l'entrée magique (au niveau de continuation 0), auquel cas il est interprété comme un décalage depuis la fin du fichier en remontant. Cela ne fonctionne que lorsqu'un descripteur de fichier pour le fichier est disponible et qu'il s'agit d'un fichier régulier.
  • D'un décalage de continuation par rapport à la fin du dernier champ de niveau supérieur (&).
Si le décalage commence par le symbole “+”, alors tous les décalages sont interprétés à partir du début du fichier (par défaut).
type
Le type des données à tester. Les valeurs possibles sont :
octet
Une valeur d'un octet.
court
Une valeur de deux octets dans l'ordre des octets natif de cette machine.
long
Une valeur de quatre octets dans l'ordre des octets natif de cette machine.
quad
Une valeur de huit octets dans l'ordre des octets natif de cette machine.
flottant
Un nombre à virgule flottante de précision simple IEEE 32 bits dans l'ordre des octets natif de cette machine.
double
Un nombre à virgule flottante de précision double IEEE 64 bits dans l'ordre des octets natif de cette machine.
chaine
Une chaîne d'octets. La spécification du type chaîne peut être suivie optionnellement d'une option /<largeur> et éventuellement suivie d'un ensemble d'indicateurs /[bCcftTtWw]*. La largeur limite le nombre de caractères à copier. Zéro signifie tous les caractères. Les indicateurs suivants sont pris en charge :
b
Forcer le test de fichier binaire.
C
Utiliser une correspondance insensible à la casse (majuscules) : les caractères majuscules dans le motif correspondent aux caractères minuscules et majuscules dans la cible, tandis que les caractères minuscules dans le motif ne correspondent qu'aux caractères majuscules dans la cible.
c
Utiliser une correspondance insensible à la casse (minuscules) : les caractères minuscules dans le motif correspondent aux caractères minuscules et majuscules dans la cible, tandis que les caractères majuscules dans le motif ne correspondent qu'aux caractères minuscules dans la cible. Pour une correspondance complètement insensible à la casse, spécifiez à la fois “c” et “C”.
f
Exiger que la chaîne correspondante soit un mot complet, et non une correspondance partielle.
T
Élaguer la chaîne, c'est-à-dire les espaces blancs en début et fin.
t
Forcer le test de fichier texte.
W
Compacter les espaces blancs dans la cible, qui doit contenir au moins un caractère d'espace blanc. Si le motif a n espaces consécutifs, la cible doit avoir au moins n espaces consécutifs pour correspondre.
w
Traiter chaque espace blanc dans le motif comme un espace blanc optionnel. est supprimé avant que la chaîne ne soit affichée.
pstring
Une chaîne de style Pascal où le premier octet/short/int est interprété comme la longueur non signée. La longueur est par défaut un octet et peut être spécifiée comme modificateur. Les modificateurs suivants sont pris en charge :
B
Une longueur d'octet (par défaut).
H
Une longueur de 2 octets en ordre big-endian.
h
Une longueur de 2 octets en ordre little-endian.
L
Une longueur de 4 octets en ordre big-endian.
l
Une longueur de 4 octets en ordre little-endian.
J
La longueur inclut sa propre valeur.
La chaîne n'est pas terminée par NUL. “J” est utilisé plutôt que le plus valable “I” car ce type de longueur est une caractéristique du format JPEG.
date
Une valeur de quatre octets interprétée comme une date UNIX.
qdate
Une valeur de huit octets interprétée comme une date UNIX.
ldate
Une valeur de quatre octets interprétée comme une date de style UNIX, mais interprétée comme l'heure locale plutôt que l'UTC.
qldate
Une valeur de huit octets interprétée comme une date de style UNIX, mais interprétée comme l'heure locale plutôt que l'UTC.
qwdate
Une valeur de huit octets interprétée comme une date de style Windows.
msdosdate
Une valeur de deux octets interprétée comme une date de style FAT/DOS.
msdostime
Une valeur de deux octets interprétée comme une heure de style FAT/DOS.
beid3
Une longueur ID3 de 32 bits en ordre big-endian.
beshort
Une valeur de deux octets en ordre big-endian.
belong
Une valeur de quatre octets en ordre big-endian.
bequad
Une valeur de huit octets en ordre big-endian.
befloat
Un nombre à virgule flottante de précision simple IEEE 32 bits en ordre big-endian.
bedouble
Un nombre à virgule flottante de précision double IEEE 64 bits en ordre big-endian.
bedate
Une valeur de quatre octets en ordre big-endian, interprétée comme une date Unix.
beqdate
Une valeur de huit octets en ordre big-endian, interprétée comme une date Unix.
beldate
Une valeur de quatre octets en ordre big-endian, interprétée comme une date de style UNIX, mais interprétée comme l'heure locale plutôt que l'UTC.

indirect
À partir du décalage donné, consulter à nouveau la base de données magique. Le décalage de la magie indirect est par défaut absolu dans le fichier, mais on peut spécifier /r pour indiquer que le décalage est relatif au début de l'entrée.
name
Définir une instance magique « nommée » qui peut être appelée à partir d'une autre entrée magique use, comme un appel de sous-routine. Les décalages magiques directs des instances nommées sont relatifs au décalage de l'entrée précédemment correspondante, mais les décalages indirects sont relatifs au début du fichier comme d'habitude. Les entrées magiques nommées correspondent toujours.
use
Appeler récursivement la magie nommée à partir du décalage actuel. Si le nom de la référence commence par un ^ alors l'endianness de la magie est inversée ; si la magie mentionne par exemple leshort, elle est traitée comme beshort et vice versa. Ceci est utile pour éviter de dupliquer les règles pour différentes endianness.
regex
Une correspondance d'expression régulière en syntaxe d'expression régulière POSIX étendue (comme egrep). Les expressions régulières peuvent prendre un temps exponentiel à traiter, et leur performance est difficile à prédire, donc leur utilisation est déconseillée. Lorsqu'elles sont utilisées dans des environnements de production, leur performance devrait être soigneusement vérifiée. La taille de la chaîne à rechercher devrait également être limitée en spécifiant /<longueur>, pour éviter les problèmes de performance lors du scan de longs fichiers. La spécification du type peut également être suivie facultativement de /[c][s][l]. Le drapeau « c » rend la correspondance insensible à la casse, tandis que le drapeau « s » met à jour le décalage au début de la correspondance, plutôt qu'à la fin. Le modificateur « l » change la limite de longueur pour signifier le nombre de lignes au lieu d'un nombre d'octets. Les lignes sont délimitées par le délimiteur de ligne natif de la plateforme. Lorsqu'un nombre de lignes est spécifié, un nombre d'octets implicite est également calculé en supposant que chaque ligne fait 80 caractères. Si ni un nombre d'octets ni un nombre de lignes n'est spécifié, la recherche est limitée automatiquement à 8Ko. ^ et $ correspondent respectivement au début et à la fin des lignes individuelles, et non au début et à la fin du fichier.
search
Une recherche de chaîne littérale commençant au décalage donné. Les mêmes drapeaux de modificateur peuvent être utilisés que pour les motifs de chaîne. L'expression de recherche doit contenir la plage sous la forme /nombre, c'est-à-dire le nombre de positions auxquelles la correspondance sera tentée, à partir du décalage de départ. Ceci convient pour rechercher de plus grandes expressions binaires avec des décalages variables, en utilisant des échappements \ pour les caractères spéciaux. L'ordre du modificateur et du nombre n'est pas pertinent.
default
Ceci est destiné à être utilisé avec le test x (qui est toujours vrai) et n'a pas de type. Il correspond lorsqu'aucun autre test à ce niveau de continuation n'a correspondu auparavant. L'effacement des tests correspondants pour un niveau de continuation peut être fait en utilisant le test clear.
clear
Ce test est toujours vrai et efface le drapeau de correspondance pour ce niveau de continuation. Il est destiné à être utilisé avec le test default.
der
Analyser le fichier comme un fichier de certificat DER. Le champ de test est utilisé comme un type DER qui doit correspondre. Les types DER sont : eoc, bool, int, bit_str, octet_str, null, obj_id, obj_desc, ext, real, enum, embed, utf8_str, rel_oid, time, res2, seq, set, num_str, prt_str, t61_str, vid_str, ia5_str, utc_time, gen_time, gr_str, vis_str, gen_str, univ_str, char_str, bmp_str, date, tod, datetime, duration, oid-iri, rel-oid-iri. Ces types peuvent être suivis d'une taille numérique optionnelle, qui indique la largeur du champ en octets.
guid
Un identifiant globalement unique, analysé et affiché comme XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX. Son format est une chaîne.
offset
Ceci est une valeur quad indiquant le décalage actuel du fichier. Il peut être utilisé pour déterminer la taille du fichier ou du tampon magique. Par exemple, les entrées magiques : 
-0	offset	x	this file is %lld bytes
-0	offset	<=100	must be more than 100 \
    bytes and is only %lld
octal
Une chaîne représentant un nombre octal.

De plus, le spécificateur de type dQ est équivalent à quad et le spécificateur de type uQ est équivalent à uquad.

Chaque motif magique de niveau supérieur (voir ci-dessous pour une explication des niveaux) est classé comme texte ou binaire selon les types utilisés. Les types « regex » et « search » sont classés comme tests textuels, à moins que des caractères non imprimables ne soient utilisés dans le motif. Tous les autres tests sont classés comme binaires. Un motif de niveau supérieur est considéré comme un test textuel lorsque tous ses motifs sont des motifs textuels ; sinon, il est considéré comme un motif binaire. Lors de la correspondance avec un fichier, les motifs binaires sont essayés en premier ; si aucune correspondance n'est trouvée, et que le fichier ressemble à du texte, alors son encodage est déterminé et les motifs textuels sont essayés.

Les types numériques peuvent éventuellement être suivis de & et d'une valeur numérique, pour spécifier que la valeur doit être mise en relation avec la valeur numérique avant toute comparaison. Préfixer par un u indique que les comparaisons ordonnées doivent être non signées.

test
La valeur à comparer avec la valeur du fichier. Si le type est numérique, cette valeur est spécifiée sous forme C ; si c'est une chaîne, elle est spécifiée comme une chaîne C avec les échappements habituels autorisés (par exemple, \n pour une nouvelle ligne).

Les valeurs numériques peuvent être précédées d'un caractère indiquant l'opération à effectuer. Il peut s'agir de =, pour spécifier que la valeur du fichier doit être égale à la valeur spécifiée, <, pour spécifier que la valeur du fichier doit être inférieure à la valeur spécifiée, >, pour spécifier que la valeur du fichier doit être supérieure à la valeur spécifiée, &, pour spécifier que la valeur du fichier doit avoir tous les bits définis qui sont définis dans la valeur spécifiée, ^, pour spécifier que la valeur du fichier doit avoir tous les bits effacés qui sont définis dans la valeur spécifiée, ou ~, la valeur spécifiée après est niée avant d'être testée. x, pour spécifier que toute valeur correspondra. Si le caractère est omis, il est supposé être =. Les opérateurs &, ^, et ~ ne fonctionnent pas avec les flottants et les doubles. L'opérateur ! spécifie que la ligne correspond si le test ne réussit pas.

Les valeurs numériques sont spécifiées sous forme C ; par exemple, 13 est décimal, 013 est octal, et 0x13 est hexadécimal.

Les opérations numériques ne sont pas effectuées sur les types date, au lieu de cela, la valeur numérique est interprétée comme un décalage.

Pour les valeurs de chaîne, la chaîne du fichier doit correspondre à la chaîne spécifiée. Les opérateurs =, < et > (mais pas &) peuvent être appliqués aux chaînes. La longueur utilisée pour la correspondance est celle de l'argument de chaîne dans le fichier magique. Cela signifie qu'une ligne peut correspondre à toute chaîne non vide (généralement utilisée pour imprimer ensuite la chaîne), avec >\0 (car toutes les chaînes non vides sont supérieures à la chaîne vide).

Les dates sont traitées comme des valeurs numériques dans leur représentation interne respective.

Le test spécial x est toujours évalué à vrai.

message
Le message à imprimer si la comparaison réussit. Si la chaîne contient une spécification de format printf(3), la valeur du fichier (avec tout masquage spécifié effectué) est imprimée en utilisant le message comme chaîne de format. Si la chaîne commence par « \b », le message imprimé est le reste de la chaîne sans espace ajouté avant : plusieurs correspondances sont normalement séparées par un seul espace.

Un créateur et un type de fichier APPLE 4+4 caractères peuvent être spécifiés comme suit :

!:apple	CREATYPE

Une liste d'extensions de nom de fichier couramment trouvées, séparées par des barres obliques, peut être spécifiée comme suit :

!:ext	ext[/ext...]

c'est-à-dire la chaîne littérale « !:ext » suivie d'une liste d'extensions couramment trouvées, séparées par des barres obliques ; par exemple pour les images JPEG :

!:ext jpeg/jpg/jpe/jfif

Un type MIME est donné sur une ligne séparée, qui doit être la ligne non vide ou commentaire suivante après la ligne magique qui identifie le type de fichier, et a le format suivant :

!:mime	MIMETYPE

c'est-à-dire la chaîne littérale « !:mime » suivie du type MIME.

Une force optionnelle peut être fournie sur une ligne séparée qui fait référence à la description magique actuelle en utilisant le format suivant :

!:strength OP VALUE

L'opérande OP peut être : +, -, *, ou / et VALUE est une constante comprise entre 0 et 255. Cette constante est appliquée en utilisant l'opérande spécifié à la force magique par défaut actuellement calculée.

Certains formats de fichiers contiennent des informations supplémentaires qui doivent être imprimées avec le type de fichier ou qui nécessitent des tests supplémentaires pour déterminer le vrai type de fichier. Ces tests supplémentaires sont introduits par un ou plusieurs caractères > précédant le décalage. Le nombre de > sur la ligne indique le niveau du test ; une ligne sans > au début est considérée comme étant au niveau 0. Les tests sont arrangés dans une hiérarchie arborescente : si le test sur une ligne au niveau n réussit, tous les tests suivants au niveau n+1 sont effectués, et les messages sont imprimés si les tests réussissent, jusqu'à ce qu'une ligne de niveau n (ou moins) apparaisse. Pour des fichiers plus complexes, on peut utiliser des messages vides pour obtenir juste l'effet « si/alors », de la manière suivante :

0      string    MZ
>0x18  uleshort  <0x40   MS-DOS executable
>0x18  uleshort  >0x3f   extended PC executable (e.g., MS Windows)

Les décalages n'ont pas besoin d'être constants, mais peuvent également être lus à partir du fichier examiné. Si le premier caractère suivant le dernier > est un ( alors la chaîne après la parenthèse est interprétée comme un décalage indirect. Cela signifie que le nombre après la parenthèse est utilisé comme décalage dans le fichier. La valeur à cet endroit est lue, et est utilisée à nouveau comme décalage dans le fichier. Les décalages indirects sont de la forme : (x [[.,][bBcCeEfFgGhHiIlmosSqQ]][+-][ y ]). La valeur de x est utilisée comme décalage dans le fichier. Un octet, une longueur id3, un short ou un long est lu à cet endroit selon le spécificateur de type [bBcCeEfFgGhHiIlLmsSqQ]. La valeur est traitée comme signée si « ,  » est spécifié ou non signée si « .  » est spécifié. Les types en majuscules interprètent le nombre comme une valeur big endian, tandis que les versions en minuscules interprètent le nombre comme une valeur little endian ; le type m interprète le nombre comme une valeur middle endian (PDP-11). À ce nombre, la valeur de y est ajoutée et le résultat est utilisé comme décalage dans le fichier. Le type par défaut s'il n'est pas spécifié est long. Les types suivants sont reconnus :

Type Mnémonique Sy Boutiste Sy Taille Sy
bcBC Octet/Caractère N/A 1
efg Double Little 8
EFG Double Big 8
hs Demi/Short Little 2
HS Demi/Short Big 2
i ID3 Little 4
I ID3 Big 4
l Long Little 4
L Long Big 4
m Middle Middle 4
o Octal Textuel Variable
q Quad Little 8
Q Quad Big 8

Ainsi, des structures de longueur variable peuvent être examinées :

# MS Windows executables are also valid MS-DOS executables
0           string   MZ
>0x18       uleshort <0x40  MZ executable (MS-DOS)
# skip the whole block below if it is not an extended executable
>0x18       uleshort >0x3f
>>(0x3c.l)  string   PE\0\0 PE executable (MS-Windows)
>>(0x3c.l)  string   LX\0\0 LX executable (OS/2)

Cette stratégie d'examen a un inconvénient : vous devez vous assurer d'imprimer quelque chose à la fin, sinon les utilisateurs peuvent obtenir une sortie vide (comme lorsqu'il n'y a ni PE\0\0 ni LE\0\0 dans l'exemple ci-dessus).

Si ce décalage indirect ne peut pas être utilisé directement, des calculs simples sont possibles : ajouter [+-*/%&|^]nombre

NAME

magic.5

magic file format

DESCRIPTION

The file command uses a magic number database to determine the type of an executable or text file. This file contains a list of tests that are performed on files. The tests are based on magic numbers, which are fixed byte sequences that appear at certain positions in files.

The syntax for the magic file is as follows:

[magiclevel,[needindirect]] opcode [type] [values] [alias] [comment]

The magiclevel and needindirect are optional.

The opcode is a type of test to perform. The following opcodes are available:

  • string: Matches a string.
  • byte: Matches a byte.
  • short: Matches a short integer (16 bits).
  • long: Matches a long integer (32 bits).
  • quad: Matches a quad integer (64 bits).
  • float: Matches a float.
  • double: Matches a double.
  • regex: Matches a regular expression.
  • search: Searches for a string.
  • clear: Clears the continuation level match.
  • default: Default case.

The type is the data type of the value to be matched. The following types are available:

  • string: String.
  • byte: Unsigned char.
  • char: Signed char.
  • uchar: Unsigned char.
  • short: Signed short.

The values are the values to be matched. The format of the values depends on the opcode and type.

The alias is an optional alias for the match.

The comment is an optional comment that starts with a `#'

The following example shows how to detect MS-DOS executables:

0       string          MZ                      MS-DOS executable, little
>0x18   leshort         <0x40                   has extended header
>>(4.s*512) leshort       0x014c                  COFF executable (MS-DOS, DJGPP)
>>(4.s*512) leshort       !0x014c                 MZ executable (MS-DOS)

The indentation of the lines indicates the continuation level. A line with no indentation is at level 0. A line indented with one tab is at level 1, and so on.

The character `>

The character `(`

The character `&

The following example shows how to detect MS-Windows executables:

0       string          MZ
>0x18   uleshort        >0x3f
>>(0x3c.l)        string          PE\0\0  PE executable (MS-Windows)
# immediately following the PE signature is the CPU type
>>>&0       leshort         0x14c   for Intel 80386
>>>&0       leshort         0x8664  for x86-64
>>>&0       leshort         0x184   for DEC Alpha

Indirect and relative offsets can be combined:

0             string   MZ
>0x18         uleshort <0x40
>>(4.s*512)   leshort  !0x014c MZ executable (MS-DOS)
# if it's not COFF, go back 512 bytes and add the offset taken
# from byte 2/3, which is yet another way of finding the start
# of the extended executable
>>>&(2.s-514) string   LE      LE executable (MS Windows VxD driver)

Or the other way around:

0                 string   MZ
>0x18             uleshort >0x3f
>>(0x3c.l)        string   LE\0\0  LE executable (MS-Windows)
# at offset 0x80 (-4, since relative offsets start at the end
# of the up-level match) inside the LE header, we find the absolute
# offset to the code area, where we look for a specific signature
>>>(&0x7c.l+0x26) string   UPX     \b, UPX compressed

Or even both!

0                string   MZ
>0x18            uleshort >0x3f
>>(0x3c.l)       string   LE\0\0 LE executable (MS-Windows)
# at offset 0x58 inside the LE header, we find the relative offset
# to a data area where we look for a specific signature
>>>&(&0x54.l-3)  string   UNACE  \b, ACE self-extracting archive

If you have to deal with offset/length pairs in your file, even the second value in a parenthesized expression can be taken from the file itself, using another set of parentheses. Note that this additional indirect offset is always relative to the start of the main indirect offset.

0                 string       MZ
>0x18             uleshort     >0x3f
>>(0x3c.l)        string       PE\0\0 PE executable (MS-Windows)
# search for the PE section called ".idata"...
>>>&0xf4          search/0x140 .idata
# ...and go to the end of it, calculated from start+length;
# these are located 14 and 10 bytes after the section name
>>>>(&0xe.l+(-4)) string       PK\3\4 \b, ZIP self-extracting archive

If you have a list of known values at a particular continuation level, and you want to provide a switch-like default case:

# clear that continuation level match
>18	clear	x
>18	lelong	1	one
>18	lelong	2	two
>18	default	x
# print default match
>>18	lelong	x	unmatched 0x%x

BUGS

The formats long, belong, lelong, melong, short, beshort, and leshort do not depend on the length of the C data types short and long on the platform, even though the Single UNIX Specification implies that they do. However, as OS X Mountain Lion has passed the Single UNIX Specification validation suite, and supplies a version of file(1) in which they do not depend on the sizes of the C data types and that is built for a 64-bit environment in which long is 8 bytes rather than 4 bytes, presumably the validation suite does not test whether, for example long refers to an item with the same size as the C data type long. There should probably be type names int8, uint8, int16, uint16, int32, uint32, int64, and uint64, and specified-byte-order variants of them, to make it clearer that those types have specified widths.
