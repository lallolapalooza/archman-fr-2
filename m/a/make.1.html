MAKE(1) Commandes utilisateur MAKE(1)

NOM

make - Utilitaire GNU Make pour maintenir des groupes de programmes

SYNOPSIS

make [OPTION]... [CIBLE]...

DESCRIPTION

L'utilitaire make déterminera automatiquement quelles pièces d'un grand programme doivent être recompilées et émettra les commandes pour les recompiler. Le manuel décrit l'implémentation GNU de make, qui a été écrite par Richard Stallman et Roland McGrath, et est actuellement maintenue par Paul Smith. Nos exemples montrent des programmes C, car ils sont très courants, mais vous pouvez utiliser make avec n'importe quel langage de programmation dont le compilateur peut être exécuté via une commande shell. En fait, make ne se limite pas aux programmes. Vous pouvez l'utiliser pour décrire toute tâche où certains fichiers doivent être mis à jour automatiquement à partir d'autres lorsque ces derniers changent.

Pour vous préparer à utiliser make, vous devez écrire un fichier appelé makefile qui décrit les relations entre les fichiers de votre programme et fournit les commandes pour mettre à jour chaque fichier. Dans un programme, généralement le fichier exécutable est mis à jour à partir des fichiers objets, qui sont eux-mêmes créés en compilant des fichiers source.

Une fois qu'un makefile approprié existe, chaque fois que vous modifiez certains fichiers sources, cette simple commande shell :

make

suffit à effectuer toutes les recompilations nécessaires. Le programme make utilise la description du makefile et les heures de dernière modification des fichiers pour décider lesquels doivent être mis à jour. Pour chacun de ces fichiers, il émet les commandes enregistrées dans le makefile.

make exécute les commandes dans le makefile pour mettre à jour une ou plusieurs cibles, où cible est généralement un programme. Si aucune option -f n'est présente, make recherchera les makefiles GNUmakefile, makefile, et Makefile, dans cet ordre.

Normalement, vous devriez appeler votre makefile soit makefile, soit Makefile. (Nous recommandons Makefile car il apparaît en bonne place au début d'une liste de répertoire, juste à côté d'autres fichiers importants tels que README.) Le premier nom vérifié, GNUmakefile, n'est pas recommandé pour la plupart des makefiles. Vous devriez utiliser ce nom si vous avez un makefile spécifique à GNU Make, et qui ne sera pas compris par d'autres versions de make. Si makefile est '-', l'entrée standard est lue.

make met à jour une cible si elle dépend de fichiers prérequis qui ont été modifiés depuis la dernière modification de la cible, ou si la cible n'existe pas.

OPTIONS

-b, -m
Ces options sont ignorées pour des raisons de compatibilité avec d'autres versions de make.
-B, --always-make
Construire inconditionnellement toutes les cibles.
-C dir, --directory=dir
Changer pour le répertoire dir avant de lire les makefiles ou de faire quoi que ce soit d'autre. Si plusieurs options -C sont spécifiées, chacune est interprétée par rapport à la précédente : -C / -C etc est équivalent à -C /etc. Ceci est généralement utilisé avec des invocations récursives de make.
-d
Afficher des informations de débogage en plus du traitement normal. Les informations de débogage indiquent quels fichiers sont considérés pour la reconstruction, quelles heures de fichier sont comparées et avec quels résultats, quels fichiers doivent réellement être reconstruits, quelles règles implicites sont considérées et lesquelles sont appliquées---tout ce qui est intéressant sur la manière dont make décide quoi faire.
--debug[=FLAGS]
Afficher des informations de débogage en plus du traitement normal. Si les FLAGS sont omis, le comportement est le même que si -d était spécifié. Les FLAGS peuvent être tout ou partie des noms suivants, séparés par des virgules ou des espaces. Seul le premier caractère est significatif : le reste peut être omis : all pour toute la sortie de débogage (identique à l'utilisation de -d), basic pour le débogage de base, verbose pour un débogage de base plus détaillé, implicit pour montrer les opérations de recherche de règles implicites, jobs pour les détails sur l'invocation des commandes, makefile pour le débogage lors de la reconstruction des makefiles, print montre toutes les recettes qui sont exécutées même si elles sont silencieuses, et why montre la raison pour laquelle make a décidé de reconstruire chaque cible. Utilisez none pour désactiver tous les drapeaux de débogage précédents.
-e, --environment-overrides
Donner la priorité aux variables provenant de l'environnement par rapport aux variables provenant des makefiles.
-E string, --eval string
Interpréter string en utilisant la fonction eval, avant d'analyser tout makefile.
-f file, --file=file, --makefile=FILE
Utiliser file comme makefile.
-i, --ignore-errors
Ignorer toutes les erreurs dans les commandes exécutées pour reconstruire les fichiers.
-I dir, --include-dir=dir
Spécifie un répertoire dir à rechercher pour les makefiles inclus. Si plusieurs options -I sont utilisées pour spécifier plusieurs répertoires, les répertoires sont recherchés dans l'ordre spécifié. Contrairement aux arguments des autres drapeaux de make, les répertoires donnés avec les drapeaux -I peuvent venir directement après le drapeau : -Idir est autorisé, ainsi que -I dir. Cette syntaxe est autorisée pour la compatibilité avec le drapeau -I du préprocesseur C.
-j [jobs], --jobs[=jobs]
Spécifie le nombre de jobs (commandes) à exécuter simultanément. S'il y a plus d'une option -j, la dernière est effective. Si l'option -j est donnée sans argument, make ne limitera pas le nombre de jobs pouvant s'exécuter simultanément.
--jobserver-style=style
Le style du jobserver à utiliser. Le style peut être fifo, pipe, ou sem (Windows uniquement).
-k, --keep-going
Continuer autant que possible après une erreur. Pendant que la cible qui a échoué, et celles qui en dépendent, ne peuvent pas être reconstruites, les autres dépendances de ces cibles peuvent être traitées quand même.
-l [load], --load-average[=load]
Spécifie qu'aucun nouveau job (commande) ne doit être démarré si d'autres jobs sont en cours d'exécution et que la charge moyenne est d'au moins load (un nombre à virgule flottante). Sans argument, supprime une limite de charge précédente.
-L, --check-symlink-times
Utiliser la dernière mtime entre les liens symboliques et la cible.
-n, --just-print, --dry-run, --recon
Afficher les commandes qui seraient exécutées, mais ne pas les exécuter (sauf dans certaines circonstances).
-o file, --old-file=file, --assume-old=file
Ne pas reconstruire le fichier file même s'il est plus ancien que ses dépendances, et ne rien reconstruire à cause de changements dans file. Essentiellement, le fichier est traité comme très ancien et ses règles sont ignorées.
-O[type], --output-sync[=type]
Lors de l'exécution de plusieurs jobs en parallèle avec -j, assurer que la sortie de chaque job est regroupée plutôt qu'entremêlée avec la sortie des autres jobs. Si type n'est pas spécifié ou est target, la sortie de la recette entière pour chaque cible est regroupée. Si type est line, la sortie de chaque ligne de commande au sein d'une recette est regroupée. Si type
make(1) - GNU Make

OPTIONS

--recurse=TYPE
Le rendu de recurse à partir d'un make récursif entier est regroupé. Si type est none, la synchronisation de sortie est désactivée.
-p, --print-data-base
Affiche la base de données (règles et valeurs de variables) résultant de la lecture des Makefiles ; puis exécute comme d'habitude ou comme spécifié autrement. Ceci affiche également les informations de version fournies par le commutateur -v (voir ci-dessous). Pour afficher la base de données sans essayer de reconstruire des fichiers, utilisez make -p -f/dev/null.
-q, --question
Mode ``question''. N'exécute aucune commande, et n'affiche rien ; renvoie simplement un code de sortie qui est zéro si les cibles spécifiées sont déjà à jour, non nul sinon.
-r, --no-builtin-rules
Élimine l'utilisation des règles implicites intégrées. Efface également la liste par défaut des suffixes pour les règles de suffixes.
-R, --no-builtin-variables
Ne définit aucune variable intégrée.
-s, --silent, --quiet
Fonctionnement silencieux ; n'affiche pas les commandes au fur et à mesure de leur exécution.
--no-silent
Annule l'effet de l'option -s.
-S, --no-keep-going, --stop
Annule l'effet de l'option -k.
-t, --touch
Touchez les fichiers (marquez-les comme étant à jour sans les modifier réellement) au lieu d'exécuter leurs commandes. Ceci est utilisé pour prétendre que les commandes ont été effectuées, afin de tromper les invocations futures de make.
--trace
Les informations sur la disposition de chaque cible sont imprimées (pourquoi la cible est reconstruite et quelles commandes sont exécutées pour la reconstruire).
-v, --version
Affiche la version du programme make, plus un copyright, une liste d'auteurs et une notification qu'il n'y a aucune garantie.
-w, --print-directory
Affiche un message contenant le répertoire de travail avant et après le traitement. Ceci peut être utile pour identifier les erreurs dans des chaînes complexes de commandes make récursives.
--no-print-directory
Désactive -w, même s'il a été activé implicitement.
--shuffle[=MODE]
Active le mélange de l'ordre des objectifs et des prérequis. MODE est l'un des éléments suivants : none pour désactiver le mode mélange, random pour mélanger les prérequis dans un ordre aléatoire, reverse pour considérer les prérequis dans l'ordre inverse, ou un entier <seed> qui active le mode random avec une valeur de seed spécifique. Si MODE est omis, la valeur par défaut est random.
-W fichier, --what-if=fichier, --new-file=fichier, --assume-new=fichier
Fait semblant que la cible fichier vient d'être modifiée. Lorsqu'il est utilisé avec le drapeau -n, cela vous montre ce qui se passerait si vous modifiiez ce fichier. Sans -n, c'est presque la même chose que d'exécuter une commande touch sur le fichier donné avant d'exécuter make, sauf que l'heure de modification n'est modifiée que dans l'imagination de make.
--warn-undefined-variables
Avertit lorsqu'une variable indéfinie est référencée.

STATUT DE SORTIE

GNU Make se termine avec un statut zéro si tous les Makefiles ont été analysés avec succès et si aucune des cibles construites n'a échoué. Un statut de un sera renvoyé si le drapeau -q a été utilisé et si make détermine qu'une cible doit être reconstruite. Un statut de deux sera renvoyé si des erreurs ont été rencontrées.

VOIR AUSSI

La documentation complète de make est maintenue sous forme de manuel Texinfo. Si les programmes info et make sont correctement installés sur votre site, la commande

info make

devrait vous donner accès au manuel complet.
