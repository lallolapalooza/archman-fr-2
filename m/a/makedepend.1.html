NOM

makedepend - crée des dépendances dans les makefiles

SYNTAXE

makedepend [ -Dnom=def ] [ -Dnom ] [ -Idossier_inclusion ] [ -Ydossier_inclusion ]
[ -a ] [ -fmakefile ] [ -include fichier ] [ -osuffixe_objet ]
[ -pprefixe_objet ] [ -schaine ] [ -wlargeur ] [ -v ] [ -m ]
[ -- autres_options -- ] fichier_source ...

DESCRIPTION

Le programme makedepend lit chaque fichier_source en séquence et le parse comme un préprocesseur C, traitant toutes les directives #include, #define, #undef, #ifdef, #ifndef, #endif, #if, #elif et #else afin de pouvoir déterminer correctement quelles directives #include seraient utilisées lors d'une compilation. Les directives #include peuvent référencer des fichiers contenant d'autres directives #include et le parsing se produira également dans ces fichiers.

Chaque fichier qu'un fichier_source inclut, directement ou indirectement, est ce que makedepend appelle une dépendance. Ces dépendances sont ensuite écrites dans un makefile de telle sorte que make(1) sache quels fichiers objets doivent être recompilés lorsqu'une dépendance a changé.

Par défaut, makedepend place sa sortie dans le fichier nommé makefile s'il existe, sinon Makefile. Un makefile alternatif peut être spécifié avec l'option -f. Il recherche d'abord dans le makefile la ligne

# DO NOT DELETE THIS LINE -- make depend depends on it.

ou celle fournie avec l'option -s, comme délimiteur pour la sortie des dépendances. S'il la trouve, il supprimera tout ce qui suit jusqu'à la fin du makefile et placera la sortie après cette ligne. S'il ne la trouve pas, le programme ajoutera la chaîne à la fin du makefile et placera la sortie après cela. Pour chaque fichier_source apparaissant sur la ligne de commande, makedepend place des lignes dans le makefile de la forme


fichier_source.o: fichier_dep ...

Où fichier_source.o est le nom provenant de la ligne de commande dont le suffixe est remplacé par ``.o'', et fichier_dep est une dépendance découverte dans une directive #include lors du parsing de fichier_source ou d'un des fichiers qu'il incluait.

EXEMPLE

Normalement, makedepend sera utilisé dans une cible de makefile afin que taper ``make depend'' mette à jour les dépendances pour le makefile. Par exemple,

    SRCS = fichier1.c fichier2.c ...
    CFLAGS = -O -DHACK -I../foobar -xyz
    depend:
            makedepend -- $(CFLAGS) -- $(SRCS)

OPTIONS

Le programme ignorera toute option qu'il ne comprend pas afin que vous puissiez utiliser les mêmes arguments que pour cc(1).

-Dnom=def ou -Dnom
Définir. Ceci place une définition pour nom dans la table des symboles de makedepend. Sans =def le symbole devient défini comme ``1''.
-Idossier_inclusion
Répertoire d'inclusion. Cette option indique à makedepend d'ajouter dossier_inclusion à sa liste de répertoires à rechercher lorsqu'il rencontre une directive #include. Par défaut, makedepend ne recherche que les répertoires d'inclusion standard (généralement /usr/include et potentiellement un répertoire dépendant du compilateur).
-Ydossier_inclusion
Remplace tous les répertoires d'inclusion standard par le répertoire d'inclusion spécifié unique ; vous pouvez omettre dossier_inclusion pour simplement empêcher la recherche dans les répertoires d'inclusion standard.
-a
Ajoute les dépendances à la fin du fichier au lieu de les remplacer.
-fmakefile
Nom de fichier. Ceci vous permet de spécifier un makefile alternatif dans lequel makedepend peut placer sa sortie. Spécifier ``-'' comme nom de fichier (c'est-à-dire -f-) envoie la sortie sur la sortie standard au lieu de modifier un fichier existant.
-include fichier
Traiter le fichier comme une entrée, et inclure toute la sortie résultante avant de traiter le fichier d'entrée régulier. Ceci a le même effet que si le fichier spécifié est une instruction include qui apparaît avant la toute première ligne du fichier d'entrée régulier.
-osuffixe_objet
Suffixe de fichier objet. Certains systèmes peuvent avoir des fichiers objets dont le suffixe est autre que ``.o''. Cette option vous permet de spécifier un autre suffixe, comme ``.b'' avec -o.b ou ``:obj'' avec -o:obj et ainsi de suite.
-pprefixe_objet
Préfixe de fichier objet. Le préfixe est ajouté au nom du fichier objet. Ceci est généralement utilisé pour désigner un répertoire différent pour le fichier objet. La valeur par défaut est la chaîne vide.
-schaine
Chaîne de délimiteur de départ. Cette option permet de spécifier une chaîne différente que makedepend doit rechercher dans le makefile.
-wlargeur
Largeur de ligne. Normalement, makedepend s'assure que chaque ligne de sortie qu'il écrit ne dépasse pas 78 caractères pour des raisons de lisibilité. Cette option vous permet de changer cette largeur.
-v
Opération verbeuse. Cette option fait que makedepend affiche la liste des fichiers inclus par chaque fichier d'entrée.
-m
Avertir de l'inclusion multiple. Cette option fait que makedepend produit un avertissement si un fichier d'entrée inclut un autre fichier plus d'une fois. Dans les versions précédentes de makedepend, c'était le comportement par défaut ; le comportement par défaut a été modifié pour mieux correspondre au comportement du compilateur C, qui ne considère pas l'inclusion multiple comme une erreur. Cette option est fournie pour la compatibilité ascendante, et pour aider au débogage des problèmes liés à l'inclusion multiple.
-- options --
Si makedepend rencontre un double trait d'union (--) dans la liste des arguments, alors tout argument non reconnu qui le suit sera ignoré silencieusement ; un second double trait d'union termine ce traitement spécial. De cette manière, makedepend peut être amené à ignorer en toute sécurité des arguments ésotériques du compilateur qui pourraient se trouver dans une macro make CFLAGS (voir la section EXEMPLE ci-dessus). Toutes les options reconnues par makedepend et apparaissant entre la paire de doubles traits d'union sont traitées normalement.

ALGORITHME

L'approche utilisée dans ce programme lui permet de fonctionner un ordre de grandeur plus rapidement que tout autre « générateur de dépendances » que j'aie jamais vu. Au cœur de cette performance se trouvent deux hypothèses : que tous les fichiers compilés par un seul makefile seront compilés avec des options -I et -D à peu près identiques ; et que la plupart des fichiers d'un même répertoire incluront largement les mêmes fichiers.

Compte tenu de ces hypothèses, makedepend s'attend à être appelé une fois pour chaque makefile, avec tous les fichiers source maintenus par le makefile apparaissant sur la ligne de commande. Il parse chaque fichier source et d'inclusion une seule fois, maintenant une table des symboles interne pour chacun. Ainsi, le premier fichier de la ligne de commande prendra un temps proportionnel au temps qu'un préprocesseur C normal prend. Mais pour les fichiers suivants, s'il rencontre un fichier d'inclusion qu'il a déjà parsé, il ne le reparsera pas.

Par exemple, imaginez que vous compiliez deux fichiers, file1.c et file2.c, qu'ils incluent chacun le fichier d'en-tête header.h, et que le fichier header.h à son tour inclut les fichiers def1.h et def2.h. Lorsque vous exécutez la commande


makedepend file1.c file2.c

makedepend parséra file1.c et par conséquent, header.h, puis def1.h et def2.h. Il décidera ensuite que les dépendances pour ce fichier sont


file1

.o : header.h def1.h def2.h

Mais lorsque le programme analyse file2.c et découvre qu'il inclut également header.h, il ne l'analyse pas, mais ajoute simplement header.h, def1.h et def2.h à la liste des dépendances pour file2.o.

VOIR AUSSI

cc(1), make(1)

BOGUES

makedepend analyse, mais n'évalue pas actuellement, l'expression du préprocesseur SVR4 #predicate(token-list) ; de telles expressions sont simplement supposées vraies. Cela peut entraîner l'évaluation incorrecte des directives #include.

Imaginez que vous analysez deux fichiers, disons file1.c et file2.c, chacun inclut le fichier def.h. La liste des fichiers que def.h inclut pourrait être réellement différente lorsque def.h est inclus par file1.c que lorsqu'il est inclus par file2.c. Mais une fois que makedepend arrive à une liste de dépendances pour un fichier, celle-ci est gravée dans le marbre.
