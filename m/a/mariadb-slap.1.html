MARIADB-SLAP(1) Système de base de données MariaDB MARIADB-SLAP(1)

NOM

mariadb-slap - client d'émulation de charge (mariadb-slap est maintenant un lien symbolique vers mariadb-slap)

SYNTAXE

mariadb-slap [options]

DESCRIPTION

mariadb-slap est un programme de diagnostic conçu pour émuler la charge client pour un serveur MariaDB et pour rapporter le temps d'exécution de chaque étape. Il fonctionne comme si plusieurs clients accédaient au serveur.

Invoquez mariadb-slap comme suit :

shell> mariadb-slap [options]

Certaines options comme --create ou --query vous permettent de spécifier une chaîne contenant une instruction SQL ou un fichier contenant des instructions. Si vous spécifiez un fichier, il doit contenir par défaut une instruction par ligne. (C'est-à-dire que le délimiteur d'instruction implicite est le caractère de nouvelle ligne.) Utilisez l'option --delimiter pour spécifier un délimiteur différent, ce qui vous permet de spécifier des instructions qui s'étendent sur plusieurs lignes ou de placer plusieurs instructions sur une seule ligne. Vous ne pouvez pas inclure de commentaires dans un fichier ; mariadb-slap ne les comprend pas.

mariadb-slap s'exécute en trois étapes :

1. Création du schéma, de la table et éventuellement des programmes stockés ou des données que vous souhaitez utiliser pour le test. Cette étape utilise une seule connexion client.
2. Exécution du test de charge. Cette étape peut utiliser de nombreuses connexions client.
3. Nettoyage (déconnexion, suppression de la table si spécifié). Cette étape utilise une seule connexion client.

Exemples :

Fournissez vos propres instructions SQL de création et de requête, avec 50 clients interrogeant et 200 sélections pour chacun :

mariadb-slap --delimiter=";" \
  --create="CREATE TABLE a (b int);INSERT INTO a VALUES (23)" \
  --query="SELECT * FROM a" --concurrency=50 --iterations=200

Laissez mariadb-slap construire l'instruction SQL de requête avec une table de deux colonnes INT et trois colonnes VARCHAR. Utilisez cinq clients interrogeant 20 fois chacun. Ne créez pas la table et n'insérez pas les données (c'est-à-dire utilisez le schéma et les données du test précédent) :

mariadb-slap --concurrency=5 --iterations=20 \
  --number-int-cols=2 --number-char-cols=3 \
  --auto-generate-sql

Indiquez au programme de charger les instructions SQL de création, d'insertion et de requête à partir des fichiers spécifiés, où le fichier create.sql contient plusieurs instructions de création de table délimitées par ';' et plusieurs instructions d'insertion délimitées par ';'. Le fichier --query contiendra plusieurs requêtes délimitées par ';'. Exécutez toutes les instructions de charge, puis toutes les requêtes du fichier de requête avec cinq clients (cinq fois chacune) :

mariadb-slap --concurrency=5 \
  --iterations=5 --query=query.sql --create=create.sql \
  --delimiter=";"

mariadb-slap prend en charge les options suivantes, qui peuvent être spécifiées sur la ligne de commande ou dans les groupes de fichiers d'options [mariadb-slap] et [client]. mariadb-slap prend également en charge les options de traitement des fichiers d'options.

•--help, -?

Affiche un message d'aide et quitte.

•--auto-generate-sql, -a

Génère automatiquement des instructions SQL lorsqu'elles ne sont pas fournies dans des fichiers ou via des options de commande.

•--auto-generate-sql-add-autoincrement

Ajoute une colonne AUTO_INCREMENT aux tables générées automatiquement.

•--auto-generate-sql-execute-number=N

Spécifie le nombre de requêtes à générer automatiquement.

•--auto-generate-sql-guid-primary

Ajoute une clé primaire basée sur GUID aux tables générées automatiquement.

•--auto-generate-sql-load-type=type

Spécifie le type de charge de test. Les valeurs autorisées sont read (lecture), write (écriture), key (clés primaires), update (mise à jour des clés primaires) ou mixed (moitié insertions, moitié sélections de scan). La valeur par défaut est mixed.

•--auto-generate-sql-secondary-indexes=N

Spécifie le nombre d'index secondaires à ajouter aux tables générées automatiquement. Par défaut, aucun n'est ajouté.

•--auto-generate-sql-unique-query-number=N

Combien de requêtes différentes générer pour les tests automatiques. Par exemple, si vous exécutez un test de clé qui effectue 1000 sélections, vous pouvez utiliser cette option avec une valeur de 1000 pour exécuter 1000 requêtes uniques, ou avec une valeur de 50 pour effectuer 50 sélections différentes. La valeur par défaut est 10.

•--auto-generate-sql-unique-write-number=N

Combien de requêtes différentes générer pour --auto-generate-sql-write-number. La valeur par défaut est 10.

•--auto-generate-sql-write-number=N

Combien d'insertions de lignes effectuer sur chaque thread. La valeur par défaut est 100.

•--commit=N

Combien d'instructions exécuter avant de valider. La valeur par défaut est 0 (aucune validation n'est effectuée).

•--compress, -C

Compresse toutes les informations envoyées entre le client et le serveur si les deux prennent en charge la compression.

•--concurrency=N, -c N

Le nombre de clients à simuler lors de l'émission de l'instruction SELECT.

•--create=valeur

Le fichier ou la chaîne contenant l'instruction à utiliser pour créer la table.

•--create-schema=valeur

Le schéma dans lequel exécuter les tests.

•--csv[=nom_fichier]

Génère la sortie au format de valeurs séparées par des virgules. La sortie va vers le fichier nommé, ou vers la sortie standard si aucun fichier n'est spécifié.

•--debug[=options_debug], -# [options_debug]

Écrit un journal de débogage. Une chaîne typique d'options_debug est 'd:t:o,nom_fichier'. La valeur par défaut est 'd:t:o,/tmp/mariadb-slap.trace'.

•--debug-check

Affiche des informations de débogage lors de la sortie du programme.

•--debug-info, -T

Affiche des informations de débogage et des statistiques d'utilisation de la mémoire et du processeur lors de la sortie du programme.

•--default-auth=nom

Plugin client d'authentification par défaut à utiliser.

•--defaults-extra-file=nom_fichier

Définit nom_fichier comme fichier à partir duquel lire les options par défaut après la lecture des fichiers de configuration globaux. Doit être spécifié comme première option.

•--defaults-file=nom_fichier

Définit nom_fichier comme fichier à partir duquel lire les options par défaut, en remplaçant les fichiers de configuration globaux. Doit être spécifié comme première option.

•--delimiter=chaîne, -F chaîne

Le délimiteur à utiliser dans les instructions SQL fournies dans les fichiers ou via les options de commande.

•--detach=N

Détache (ferme et rouvre) chaque connexion après chaque N instructions. La valeur par défaut est 0 (les connexions ne sont pas détachées).

•--engine=nom_moteur, -e nom_moteur

Liste séparée par des virgules des moteurs de stockage à utiliser pour la création de la table. Le test est exécuté pour chaque moteur. Vous pouvez également spécifier une option pour un moteur après un deux-points, par exemple memory:max_row=2300.

•--host=nom_hote, -h nom_hote

Se connecte au serveur MariaDB sur l'hôte spécifié.

•--init-command=chaîne

Commande SQL à exécuter lors de la connexion au serveur MariaDB. Sera automatiquement réexécutée lors des reconnexions.

•--iterations=N, -i N

Le nombre de fois où les tests seront exécutés.

•--no-defaults

Ne lit pas les options par défaut à partir d'un fichier d'options. Doit être spécifié comme premier argument.

•--no-drop

Ne supprime aucune base de données créée pendant le test après la fin du test.

La plupart des options peuvent être spécifiées dans les fichiers d'options de MariaDB.

FICHIERS D'OPTIONS

Les programmes clients MariaDB peuvent lire les options par défaut à partir de fichiers d'options. Ces fichiers sont lus dans l'ordre suivant :

1. Option files listed on the command line using --defaults-file, --defaults-extra-file.
2. Names in the [ `DEFAULT` ] group and any groups that are read directly,
    is read from the following files in the following order:
   `--defaults-file` (`--defaults-extra-file`)
   `--defaults-extra-file`
   The `my.cnf` file in the old 3rd_rd, 2nd_rd, 1st_rd, and home directory.
3. The following program-specific option files are read:
   `--defaults-file` (`--defaults-extra-file`)
   `--defaults-extra-file`
   `my.cnf` in the old 3rd_rd, 2nd_rd, 1st_rd, and home directory.
4. The [ `mariadb-slap` ] and [ `client` ] groups are read from the
    following files in the following order:
   `--defaults-file` (`--defaults-extra-file`)
   `--defaults-extra-file`
   `my.cnf` in the old 3rd_rd, 2nd_rd, 1st_rd, and home directory.

Le chemin d'accès aux fichiers `my.cnf` est : `/etc/my.cnf` (fichier global), `~/.my.cnf` (fichier personnel).

Le groupe [mariadb-slap] est lu avant le groupe [client].

EXEMPLES

Le fichier `my.cnf` peut contenir les sections suivantes :

[mariadb-slap]
auto-generate-sql
concurrency=50
iterations=100
[client]
host=127.0.0.1

Lorsque vous exécutez `mariadb-slap` sans options, il lit les fichiers d'options et applique les paramètres de ces fichiers.

mariadb-slap(1) — MariaDB 11.8

NAME

mariadb-slap — A simple benchmarking tool for MariaDB Server

SYNOPSIS

mariadb-slap [options] [--query=query | --file=query-file]

DESCRIPTION

mariadb-slap is a simple benchmarking tool for MariaDB Server. It connects to a MariaDB Server and executes a configurable number of queries, measuring the time taken. It is intended to be simple to use and useful for basic performance checks.

Note: It is not intended to be a replacement for more sophisticated benchmarking tools like sysbench.

The following options are available for mariadb-slap:

•--auto-generate-sql

Generate SQL statements for creating tables and inserting data. If this option is used, the --query and --file options are ignored. The number of columns and rows can be controlled using the --number-char-cols, --number-int-cols, and --number-of-queries options.

•--char-length=N

The length of strings to be generated if --auto-generate-sql is specified.

•--child[=N], -c [N]

The number of client threads to use for running the test. The default is 10.

•--delimiter=str

The statement delimiter to use when parsing queries. The default is ;.

•--detach, -d

Detach from the controlling terminal.

•--file=value, -f value

The file containing the SQL statements to execute.

•--host=host_name, -h host_name

The host name or IP address of the server to connect to.

•--iterations=N, -i N

The number of times to execute the queries. The total number of queries executed will be N * number-of-queries.

•--number-char-cols=N, -x N

The number of VARCHAR columns to use if --auto-generate-sql is specified.

•--number-int-cols=N, -y N

The number of INT columns to use if --auto-generate-sql is specified.

•--number-of-queries=N

Limit each client to approximately this many queries. Query counting takes into account the statement delimiter. For example, if you invoke mariadb-slap as follows, the ; delimiter is recognized so that each instance of the query string counts as two queries. As a result, 5 rows (not 10) are inserted.

shell> mariadb-slap --delimiter=";" --number-of-queries=10
         --query="use test;insert into t values(null)"
•--only-print

Do not connect to databases. mariadb-slap only prints what it would have done.

•--password[=password], -p[password]

The password to use when connecting to the server. If you use the short option form (-p), you cannot have a space between the option and the password. If you omit the password value following the --password or -p option on the command line, mariadb-slap prompts for one.

Specifying a password on the command line should be considered insecure. You can use an option file to avoid giving the password on the command line.

•--pipe, -W

On Windows, connect to the server via a named pipe. This option applies only if the server supports named-pipe connections.

•--plugin-dir=dir_name

Directory for client-side plugins.

•--port=port_num, -P port_num

The TCP/IP port number to use for the connection. Forces --protocol=tcp when specified on the command line without other connection properties.

•--post-query=value

The file or string containing the statement to execute after the tests have completed. This execution is not counted for timing purposes.

•--post-system=str

The string to execute via system() after the tests have completed. This execution is not counted for timing purposes.

•--pre-query=value

The file or string containing the statement to execute before running the tests. This execution is not counted for timing purposes.

•--pre-system=str

The string to execute via system() before running the tests. This execution is not counted for timing purposes.

•--print-defaults

Print the program argument list and exit. This must be given as the first argument.

•--protocol={TCP|SOCKET|PIPE|MEMORY}

The connection protocol to use for connecting to the server. It is useful when the other connection parameters normally would cause a protocol to be used other than the one you want.

•--query=value, -q value

The file or string containing the SELECT statement to use for retrieving data.

•--shared-memory-base-name=name

On Windows, the shared-memory name to use, for connections made via shared memory to a local server. This option applies only if the server supports shared-memory connections.

•--silent, -s

Silent mode. No output.

•--socket=path, -S path

For connections to localhost, the Unix socket file to use, or, on Windows, the name of the named pipe to use. Forces --protocol=socket when specified on the command line without other connection properties; on Windows, forces --protocol=pipe.

•--ssl

Enable SSL for connection (automatically enabled with other flags). Disable with --skip-ssl.

•--ssl-ca=name

CA file in PEM format (check OpenSSL docs, implies --ssl).

•--ssl-capath=name

CA directory (check OpenSSL docs, implies --ssl).

•--ssl-cert=name

X509 cert in PEM format (check OpenSSL docs, implies --ssl).

•--ssl-cipher=name

SSL cipher to use (check OpenSSL docs, implies --ssl).

•--ssl-key=name

X509 key in PEM format (check OpenSSL docs, implies --ssl).

•--ssl-crl=name

Certificate revocation list (check OpenSSL docs, implies --ssl).

•--ssl-crlpath=name

Certificate revocation list path (check OpenSSL docs, implies --ssl).

•--ssl-verify-server-cert

Verify server's "Common Name" in its cert against hostname used when connecting. This option is disabled by default.

•--user=user_name, -u user_name

The MariaDB user name to use when connecting to the server.

•--verbose, -v

Verbose mode. Print more information about what the program does. This option can be used multiple times to increase the amount of information.

•--version, -V

Display version information and exit.
