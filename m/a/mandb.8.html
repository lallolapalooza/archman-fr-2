MANDB(8) Outils de pagination du manuel MANDB(8)

NOM

mandb - créer ou mettre à jour les caches d'index des pages de manuel

SYNTAXE

mandb [-dqsucpt?V] [-C fichier] [manpath]
mandb [-dqsut] [-C fichier] -f nom_fichier ...

DESCRIPTION

mandb est utilisé pour initialiser ou mettre à jour manuellement les caches de bases de données index. Les caches contiennent des informations pertinentes pour l'état actuel du système de pages de manuel et les informations qu'ils stockent sont utilisées par les utilitaires man-db pour améliorer leur vitesse et leurs fonctionnalités.

Lors de la création ou de la mise à jour d'un index, mandb avertira des requêtes ROFF .so invalides, des noms de fichiers de pages de manuel erronés et des pages de manuel dont le whatis ne peut être analysé.

En fournissant à mandb un chemin optionnel délimité par des deux-points remplacera le chemin de recherche de la hiérarchie des pages de manuel du système, déterminé à partir des informations trouvées dans le fichier de configuration man-db.

CACHES DE_BASE_DE_DONNÉES

mandb peut être compilé avec le support de l'un des types de bases de données suivants.

Nom Asynchrone Nom de fichier
Berkeley db Oui index.bt
GNU gdbm Oui index.db
UNIX ndbm Non index.(dir|pag)

Les types de bases de données qui supportent les mises à jour asynchrones offrent une vitesse accrue au prix d'une corruption possible en cas de terminaison inhabituelle. Dans le cas inhabituel où cela s'est produit, il peut être nécessaire de réexécuter mandb avec l'option -c pour recréer les bases de données à partir de zéro.

OPTIONS

-d, --debug
Afficher les informations de débogage.
-q, --quiet
Ne produire aucun avertissement.
-s, --no-straycats
Ne pas passer de temps à rechercher ou à ajouter des informations aux bases de données concernant les chats errants.
-p, --no-purge
Ne pas passer de temps à vérifier les pages de manuel supprimées et à les purger des bases de données.
-c, --create
Par défaut, mandb tentera de mettre à jour toutes les bases de données précédemment créées. Si une base de données n'existe pas, elle sera créée. Cette option force mandb à supprimer les bases de données précédentes et à les recréer à partir de zéro, et implique --no-purge. Ceci peut être nécessaire si une base de données devient corrompue ou si un nouveau schéma de stockage de base de données est introduit à l'avenir.
-u, --user-db
Créer uniquement les bases de données utilisateur, même avec les permissions d'écriture nécessaires pour créer les bases de données système.
-t, --test
Effectuer des vérifications d'exactitude sur les pages de manuel dans le chemin de recherche de la hiérarchie. Avec cette option, mandb ne modifiera pas les bases de données existantes.
-f, --filename
Mettre à jour uniquement les entrées pour le nom de fichier donné. Cette option n'est pas pour un usage général ; elle est utilisée en interne par man lorsqu'il a été compilé avec l'option MAN_DB_UPDATES et découvre qu'une page est obsolète. Elle implique -p et désactive -c et -s.
-C fichier, --config-file=fichier
Utiliser ce fichier de configuration utilisateur plutôt que le fichier par défaut ~/.manpath.
-?, --help
Afficher le message d'utilisation, puis quitter.
--usage
Afficher un bref message d'utilisation et quitter.
-V, --version
Afficher la version, puis quitter.

STATUT DE_SORTIE

0
Exécution réussie du programme.
1
Erreur d'utilisation, de syntaxe ou de fichier de configuration.
2
Erreur opérationnelle.
3
Un processus enfant a échoué.

DIAGNOSTICS

Les messages d'avertissement suivants peuvent être émis lors de la construction de la base de données.

<nom_fichier>: échec de l'analyse whatis pour la page(sec)
Une tentative d'extraction de lignes whatis du <nom_fichier> donné a échoué. Ceci est généralement dû à une page de manuel mal écrite, mais si de nombreux messages de ce type sont émis, il est probable que le système contienne des pages de manuel non standard incompatibles avec l'analyseur whatis de man-db. Voir la section ANALYSE WHATIS de lexgrog(1) pour plus d'informations.
<nom_fichier>: est un lien symbolique pendant
<nom_fichier> n'existe pas mais est référencé par un lien symbolique. D'autres diagnostics sont généralement émis pour identifier le <nom_fichier> du lien fautif.
<nom_fichier>: lien symbolique invalide ou requête ROFF `.so'
<nom_fichier> est soit un lien symbolique vers un fichier inexistant, soit contient une requête d'inclusion ROFF vers un fichier inexistant.
<nom_fichier>: ignoré, nom de fichier invalide
Le <nom_fichier> peut ou peut ne pas être une page de manuel valide, mais son nom est invalide. Ceci est généralement dû à une page de manuel avec l'extension sectionnelle <x> étant placée dans la section <y> des pages de manuel.
<masque_nom_fichier>: extensions concurrentes
Le joker <masque_nom_fichier> n'est pas unique. Ceci est généralement causé par l'existence d'une version compressée et non compressée de la même page de manuel. Toutes sauf la plus récente sont ignorées.

FICHIERS

/etc/man_db.conf
Fichier de configuration man-db.
/var/cache/man/index.(bt|db|dir|pag)
Un cache de base de données index global conforme au FHS.

Les anciens emplacements du cache de base de données comprenaient :

/usr/man/index.(bt|db|dir|pag)
Un cache de base de données index global traditionnel.
/var/catman/index.(bt|db|dir|pag)
Un cache de base de données index global alternatif ou conforme FSSTND.
