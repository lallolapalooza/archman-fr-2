MARIADB-ADMIN(1) Système de base de données MariaDB MARIADB-ADMIN(1)

NOM

mariadb-admin - client pour l'administration d'un serveur MariaDB (mariadb-admin est maintenant un lien symbolique vers mariadb-admin)

SYNTAXE

mariadb-admin [options] commande [argument-commande] [commande [argument-commande]] ...

DESCRIPTION

mariadb-admin est un client pour effectuer des opérations administratives. Vous pouvez l'utiliser pour vérifier la configuration et l'état actuel du serveur, pour créer et supprimer des bases de données, et plus encore.

Appelez mariadb-admin comme ceci :

shell> mariadb-admin [options] commande [argument-commande] [commande [argument-commande]] ...

mariadb-admin prend en charge les commandes suivantes. Certaines commandes prennent un argument après le nom de la commande.

•create nom_bd

Crée une nouvelle base de données nommée nom_bd.

•debug

Indique au serveur d'écrire des informations de débogage dans le journal d'erreurs.

Cela inclut également des informations sur le planificateur d'événements.

•drop nom_bd

Supprime la base de données nommée nom_bd et toutes ses tables.

•extended-status

Affiche les variables d'état du serveur et leurs valeurs.

•flush-all-statistics

Vide toutes les tables de statistiques.

•flush-all-status

Vide toutes les statistiques et les états.

•flush-binary-log

Vide le journal binaire.

•flush-client-statistics

Vide les statistiques client.

•flush-engine-log

Vide le journal du moteur.

•flush-error-log

Vide le journal d'erreurs.

•flush-general-log

Vide le journal général des requêtes.

•flush-hosts

Vide toutes les informations dans le cache des hôtes.

•flush-index-statistics

Vide les statistiques d'index.

•flush-logs

Vide tous les journaux.

•flush-privileges

Recharge les tables de privilèges (équivalent de reload).

•flush-relay-log

Vide le journal de relais.

•flush-slow-log

Vide le journal des requêtes lentes.

•flush-ssl

Vide les certificats SSL.

•flush-status

Efface les variables d'état.

•flush-table-statistics

Vide les statistiques de table.

•flush-tables

Vide toutes les tables.

•flush-threads

Vide le cache des threads.

•flush-user-resources

Vide les ressources utilisateur.

•kill id,id,...

Arrête les threads du serveur. Si plusieurs identifiants de thread sont donnés, il ne doit pas y avoir d'espaces dans la liste.

•old-password nouveau-mot-de-passe

Ceci est comme la commande password, mais stocke le mot de passe en utilisant l'ancien format de hachage de mot de passe (avant MySQL 4.1).

•password nouveau-mot-de-passe

Définit un nouveau mot de passe. Cela change le mot de passe en nouveau-mot-de-passe pour le compte que vous utilisez avec mariadb-admin pour vous connecter au serveur. Ainsi, la prochaine fois que vous appellerez mariadb-admin (ou tout autre programme client) en utilisant le même compte, vous devrez spécifier le nouveau mot de passe.

Si la valeur nouveau-mot-de-passe contient des espaces ou d'autres caractères spéciaux pour votre interpréteur de commandes, vous devez l'entourer de guillemets. Sous Windows, assurez-vous d'utiliser des guillemets doubles plutôt que simples ; les guillemets simples ne sont pas supprimés du mot de passe, mais sont interprétés comme faisant partie du mot de passe. Par exemple :

shell> mariadb-admin password "mon nouveau mot de passe"

Attention
N'utilisez pas cette commande si le serveur a été démarré avec l'option --skip-grant-tables. Aucune modification de mot de passe ne sera appliquée. Ceci est vrai même si vous précédez la commande de mot de passe avec flush-privileges sur la même ligne de commande pour réactiver les tables de privilèges, car l'opération de vidage se produit après votre connexion. Cependant, vous pouvez utiliser mariadb-admin flush-privileges pour réactiver la table de privilèges, puis utiliser une commande distincte mariadb-admin password pour changer le mot de passe.
•ping

Vérifie si le serveur est actif. Le statut de retour de mariadb-admin est 0 si le serveur fonctionne, 1 s'il ne fonctionne pas. C'est 0 même en cas d'erreur telle que Accès refusé, car cela signifie que le serveur fonctionne mais a refusé la connexion, ce qui est différent d'un serveur qui ne fonctionne pas.

•processlist

Affiche une liste des threads actifs du serveur. Ceci est similaire à la sortie de l'instruction SHOW PROCESSLIST. Si l'option --verbose est fournie, la sortie est similaire à celle de SHOW FULL PROCESSLIST.

•reload

Recharge les tables de privilèges.

•refresh

Vide toutes les tables et ferme et ouvre les fichiers journaux.

•shutdown

Arrête le serveur.

•start-all-slaves

Démarre tous les esclaves.

•start-slave

Démarre la réplication sur un serveur esclave.

•status

Affiche un court message d'état du serveur.

•stop-all-slaves

Arrête tous les esclaves.

•stop-slave

Arrête la réplication sur un serveur esclave.

•variables

Affiche les variables système du serveur et leurs valeurs.

•version

Affiche les informations de version du serveur.

Toutes les commandes peuvent être raccourcies à n'importe quel préfixe unique. Par exemple :

shell> mariadb-admin proc stat
+----+-------+-----------+----+---------+------+-------+------------------+
| Id | User  | Host      | db | Command | Time | State | Info             |
+----+-------+-----------+----+---------+------+-------+------------------+
| 51 | monty | localhost |    | Query   | 0    |       | show processlist |
+----+-------+-----------+----+---------+------+-------+------------------+
Uptime: 1473624  Threads: 1  Questions: 39487
Slow queries: 0  Opens: 541  Flush tables: 1
Open tables: 19  Queries per second avg: 0.0268

La commande mariadb-admin status affiche les valeurs suivantes :

•Uptime

Le nombre de secondes pendant lesquelles le serveur MariaDB a été en exécution.

•Threads

Le nombre de threads (clients) actifs.

•Questions

Le nombre de questions (requêtes) des clients depuis le démarrage du serveur.

•Slow queries

Le nombre de requêtes qui ont pris plus de log_slow_query_time secondes.

•Opens

Le nombre de tables que le serveur a ouvertes.

•Flush tables

Le nombre de commandes flush-*, refresh et reload que le serveur a exécutées.

•Open tables

Le nombre de tables actuellement ouvertes.

•Memory in use

La quantité de mémoire allouée directement par mariadbd. Cette valeur n'est affichée que lorsque MariaDB a été compilé avec --with-debug=full.

•Maximum memory used

La quantité maximale de mémoire allouée directement par mariadbd. Cette valeur n'est affichée que lorsque MariaDB a été compilé avec --with-debug=full.

Si vous exécutez mariadb-admin shutdown lors de la connexion à un serveur local à l'aide d'un fichier socket Unix, mariadb-admin attend que le fichier d'identifiant de processus du serveur ait été supprimé, pour s'assurer que le serveur s'est arrêté correctement.

mariadb-admin prend en charge les options suivantes, qui peuvent

Voici le contenu traduit en français, tout en conservant la structure du fichier : spécifiés sur la ligne de commande ou dans les sections de fichiers d'options [mariadb-admin] et [client].

•--help, -?

Affiche l'aide et quitte.

•--character-sets-dir=chemin

Le répertoire où les jeux de caractères sont installés.

•--compress, -C

Compresse toutes les informations envoyées entre le client et le serveur si les deux prennent en charge la compression.

•--connect-timeout=délai

Équivalent de --connect_timeout, voir la fin de cette section.

•--count=N, -c N

Le nombre d'itérations à effectuer pour l'exécution répétée de commandes si l'option --sleep est donnée.

•--debug[=options_debug], -# [options_debug]

Écrit un journal de débogage. Une chaîne typique pour options_debug est 'd:t:o,nom_fichier'. La valeur par défaut est 'd:t:o,/tmp/mariadb-admin.trace'.

•--debug-check

Vérifie l'utilisation de la mémoire et des fichiers ouverts à la sortie.

•--debug-info

Affiche des informations de débogage ainsi que des statistiques d'utilisation de la mémoire et du CPU lors de la sortie du programme.

•--default-auth

Plugin d'authentification côté client par défaut à utiliser.

•--default-character-set=nom_jeu_caractères

Utilise nom_jeu_caractères comme jeu de caractères par défaut.

•--defaults-extra-file=nom_fichier

Définit nom_fichier comme le fichier à partir duquel lire les options par défaut après la lecture des fichiers d'options globaux. Doit être donné comme première option.

•--defaults-file=nom_fichier

Définit nom_fichier comme le fichier à partir duquel lire les options par défaut, en remplaçant les fichiers d'options globaux. Doit être donné comme première option.

•--force, -f

Ne demande pas de confirmation pour la commande drop nom_base_de_données. Avec plusieurs commandes, continue même si une erreur se produit.

•--host=nom_hôte, -h nom_hôte

Se connecte au serveur MariaDB sur l'hôte donné.

•--local, -l

Supprime l'écriture des commandes SQL dans le journal binaire en utilisant FLUSH LOCAL ou en activant sql_log_bin=0 pour la session.

•--no-beep, -b

Supprime le bip d'avertissement qui est émis par défaut pour les erreurs telles qu'un échec de connexion au serveur.

•--no-defaults

Ne lit pas les options par défaut à partir d'un fichier d'options. Doit être donné comme premier argument.

•--password[=mot_de_passe], -p[mot_de_passe]

Le mot de passe à utiliser lors de la connexion au serveur. Si vous utilisez la forme courte de l'option (-p), vous ne pouvez pas avoir d'espace entre l'option et le mot de passe. Si vous omettez la valeur mot_de_passe suivant l'option --password ou -p sur la ligne de commande, mariadb-admin en demandera un.

Spécifier un mot de passe sur la ligne de commande doit être considéré comme non sécurisé.

•--pipe, -W

Sous Windows, se connecte au serveur via un pipe nommé. Cette option ne s'applique que si le serveur prend en charge les connexions par pipe nommé.

•--port=num_port, -P num_port

Le numéro de port TCP/IP à utiliser pour la connexion ou 0 pour utiliser par défaut, dans l'ordre de préférence, my.cnf, $MYSQL_TCP_PORT, /etc/services, valeur par défaut intégrée (3306). Force --protocol=tcp lorsqu'il est spécifié sur la ligne de commande sans autres propriétés de connexion.

•--print-defaults

Affiche la liste des arguments du programme et quitte. Doit être donné comme premier argument.

•--protocol={TCP|SOCKET|PIPE|MEMORY}

Le protocole de connexion à utiliser pour se connecter au serveur. Il est utile lorsque les autres paramètres de connexion provoqueraient normalement l'utilisation d'un protocole différent de celui que vous souhaitez.

•--relative, -r

Affiche la différence entre les valeurs actuelles et précédentes lorsqu'il est utilisé avec l'option --sleep. Actuellement, cette option ne fonctionne qu'avec la commande extended-status.

•--shutdown-timeoutdélai

Équivalent de --shutdown_timeout, voir la fin de cette section.

•--silent, -s

Quitte silencieusement si une connexion au serveur ne peut pas être établie.

•--sleep=délai, -i délai

Exécute les commandes de manière répétée, en attendant délai secondes entre chaque exécution. L'option --count détermine le nombre d'itérations. Si --count n'est pas donné, mariadb-admin exécute les commandes indéfiniment jusqu'à interruption.

•--socket=chemin, -S chemin

Pour les connexions à localhost, le fichier de socket Unix à utiliser, ou, sous Windows, le nom du pipe nommé à utiliser. Force --protocol=socket lorsqu'il est spécifié sur la ligne de commande sans autres propriétés de connexion ; sous Windows, force --protocol=pipe.

•--ssl

Active le SSL pour la connexion (automatiquement activé avec d'autres drapeaux). Désactive avec --skip-ssl.

•--ssl-ca=nom

Fichier CA au format PEM (vérifier la documentation OpenSSL, implique --ssl).

•--ssl-capath=nom

Répertoire CA (vérifier la documentation OpenSSL, implique --ssl).

•--ssl-cert=nom

Certificat X509 au format PEM (vérifier la documentation OpenSSL, implique --ssl).

•--ssl-cipher=nom

Chiffrement SSL à utiliser (vérifier la documentation OpenSSL, implique --ssl).

•--ssl-key=nom

Clé X509 au format PEM (vérifier la documentation OpenSSL, implique --ssl).

•--ssl-crl=nom

Liste de révocation de certificats (vérifier la documentation OpenSSL, implique --ssl).

•--ssl-crlpath=nom

Chemin de la liste de révocation de certificats (vérifier la documentation OpenSSL, implique --ssl).

•--ssl-verify-server-cert

Vérifie le "Common Name" du serveur dans son certificat par rapport au nom d'hôte utilisé lors de la connexion. Cette option est désactivée par défaut.

•--tls-version=nom,

Accepte une liste de versions de protocoles TLS séparée par des virgules. Une version de protocole TLS ne sera activée que si elle est présente dans cette liste. Toutes les autres versions de protocoles TLS ne seront pas autorisées.

•--user=nom_utilisateur, -u nom_utilisateur

Le nom d'utilisateur MariaDB à utiliser lors de la connexion au serveur.

•--verbose, -v

Mode verbeux. Affiche plus d'informations sur ce que fait le programme.

•--version, -V

Affiche les informations de version et quitte.

•--vertical, -E

Affiche la sortie verticalement. Ceci est similaire à --relative, mais affiche la sortie verticalement.

•--wait[=compte], -w[compte]

Si la connexion ne peut pas être établie, attend et réessaie au lieu d'abandonner. Si une valeur de compte est donnée, elle indique le nombre de tentatives. La valeur par défaut est une tentative.

•--wait-for-all-slaves

Attend que le dernier événement du journal binaire soit envoyé à toutes les répliques connectées avant l'arrêt. Cette option est désactivée par défaut.

Vous pouvez également définir les variables suivantes en utilisant --nom_var=valeur

•connect_timeout

Le nombre maximum de secondes avant l'expiration du délai de connexion. La valeur par défaut est 43200 (12 heures).

•shutdown_timeout

Le nombre maximum de secondes à attendre pour l'arrêt du serveur. La valeur par défaut est 3600 (1 heure).
