SENDMAIL(1) Manuel des commandes générales SENDMAIL(1)

NOM

sendmail - Interface de compatibilité Postfix avec Sendmail

SYNTAXE

sendmail [option ...] [destinataire ...]
mailq
sendmail -bp
newaliases
sendmail -I

DESCRIPTION


La commande sendmail(1) de Postfix implémente l'interface de compatibilité de Postfix avec Sendmail. Pour des raisons de compatibilité avec les applications existantes, certaines options de ligne de commande de Sendmail sont reconnues mais ignorées silencieusement.

Par défaut, sendmail(1) de Postfix lit un message depuis l'entrée standard jusqu'à la fin de fichier (EOF) ou jusqu'à ce qu'il lise une ligne contenant uniquement le caractère ., et organise sa livraison. sendmail(1) de Postfix s'appuie sur la commande postdrop(1) pour créer un fichier dans la file d'attente du répertoire maildrop.

Des alias de commande spécifiques sont fournis pour d'autres modes de fonctionnement courants :

mailq
Liste la file d'attente des courriels. Chaque entrée affiche l'identifiant du fichier de la file d'attente, la taille du message, l'heure d'arrivée, l'expéditeur et les destinataires qui doivent encore être livrés. Si la livraison du courrier a échoué lors de la dernière tentative, la raison de l'échec est affichée. La chaîne d'identifiant de la file d'attente est suivie d'un caractère d'état optionnel :
*
Le message est dans la file d'attente active, c'est-à-dire que le message est sélectionné pour la livraison.
!
Le message est dans la file d'attente hold (en attente), c'est-à-dire qu'aucune nouvelle tentative de livraison ne sera effectuée tant que le courrier ne sera pas retiré de cette file d'attente.
#
Le message est forcé à expirer. Voir les options -e ou -f de postsuper(1).
Ce mode de fonctionnement est implémenté en exécutant la commande postqueue(1).
newaliases
Initialise la base de données des alias. Si aucun fichier d'entrée n'est spécifié (avec l'option -oA, voir ci-dessous), le programme traite le ou les fichiers spécifiés par le paramètre de configuration alias_database. Si aucun type de base de données d'alias n'est spécifié, le programme utilise le type spécifié par le paramètre de configuration default_database_type. Ce mode de fonctionnement est implémenté en exécutant la commande postalias(1).

Note : il peut s'écouler une minute ou deux avant qu'une mise à jour de la base de données des alias ne soit visible. Utilisez la commande "postfix reload" pour éliminer ce délai.

Ces fonctionnalités et d'autres peuvent être sélectionnées en spécifiant la combinaison appropriée d'options de ligne de commande. Certaines fonctionnalités sont contrôlées par des paramètres dans le fichier de configuration main.cf.

Les options suivantes sont reconnues :

-Am (ignoré)
-Ac (ignoré)
Postfix sendmail utilise le même fichier de configuration, qu'un message soit une soumission initiale ou non.
-B type_corps
Le type MIME du corps du message : 7BIT ou 8BITMIME.
-bd
Passe en mode démon. Ce mode de fonctionnement est implémenté en exécutant la commande "postfix start".
-bh (ignoré)
-bH (ignoré)
Postfix ne dispose pas de base de données d'état des hôtes persistante.
-bi
Initialise la base de données des alias. Voir la commande newaliases ci-dessus.
-bl
Passe en mode démon. Pour accepter uniquement les connexions locales, comme avec l'option -bl de Sendmail, spécifiez "inet_interfaces = loopback" dans le fichier de configuration Postfix main.cf.
-bm
Lit le courrier depuis l'entrée standard et organise sa livraison. C'est le mode de fonctionnement par défaut.
-bp
Liste la file d'attente des courriels. Voir la commande mailq ci-dessus.
-bs
Mode serveur SMTP autonome. Lit les commandes SMTP depuis l'entrée standard et écrit les réponses sur la sortie standard. En mode serveur SMTP autonome, le transfert de courrier et les autres contrôles d'accès sont désactivés par défaut. Pour les activer, exécutez le processus en tant qu'utilisateur mail_owner.

Ce mode de fonctionnement est implémenté en exécutant le démon smtpd(8).

-bv
Ne collecte ni ne livre de message. Au lieu de cela, envoie un rapport par courriel après vérification de chaque adresse de destinataire. Ceci est utile pour tester la réécriture d'adresses et les configurations de routage.

Cette fonctionnalité est disponible dans Postfix version 2.1 et ultérieures.

-C fichier_config
-C repertoire_config
Le chemin d'accès au fichier main.cf de Postfix, ou à son répertoire parent. Ces informations sont ignorées avec les versions de Postfix antérieures à 2.3.

Avec Postfix version 3.2 et ultérieures, un répertoire non standard doit être autorisé dans le fichier main.cf par défaut, via les paramètres alternate_config_directories ou multi_instance_directories.

Avec toutes les versions de Postfix, vous pouvez spécifier un chemin de répertoire avec la variable d'environnement MAIL_CONFIG pour remplacer l'emplacement des fichiers de configuration.

-F nom_complet
Définit le nom complet de l'expéditeur. Ceci remplace la variable d'environnement NAME et n'est utilisé qu'avec les messages qui n'ont pas d'en-tête de message From:.
-f expediteur
Définit l'adresse de l'expéditeur de l'enveloppe. C'est l'adresse à laquelle les problèmes de livraison sont envoyés. Avec les versions de Postfix antérieures à 2.1, l'en-tête de message Errors-To: remplace l'adresse de retour d'erreur.
-G
Soumission par passerelle (relais), par opposition à la soumission initiale par l'utilisateur. Soit ne réécrit aucune adresse, soit met à jour les adresses incomplètes avec les informations de domaine spécifiées par remote_header_rewrite_domain.

Cette option est ignorée avant Postfix version 2.3.

-h nombre_sauts (ignoré)
Limite du nombre de sauts. Utilisez plutôt le paramètre de configuration hopcount_limit.
-I
Initialise la base de données des alias. Voir la commande newaliases ci-dessus.
-i
Lors de la lecture d'un message depuis l'entrée standard, ne traite pas une ligne contenant uniquement le caractère . comme la fin de l'entrée.
-L etiquette (ignoré)
L'étiquette de journalisation. Utilisez plutôt le paramètre de configuration syslog_name.
-m (ignoré)
Compatibilité ascendante.
-N dsn (défaut : 'delay, failure')
Contrôle des notifications d'état de livraison (DSN). Spécifiez soit une liste séparée par des virgules avec un ou plusieurs des éléments suivants : failure (envoyer une notification en cas d'échec de livraison), delay (envoyer une notification en cas de retard de livraison), ou success (envoyer une notification lorsque le message est livré) ; soit spécifiez never (ne pas envoyer de notifications du tout).

Cette fonctionnalité est disponible dans Postfix 2.3 et ultérieures.

-n (ignoré)
Compatibilité ascendante.
-oAbase_donnees_alias
Base de données d'alias non par défaut. Spécifiez chemin_acces ou type:chemin_acces. Voir postalias(1) pour les détails.
-O option=valeur (ignoré)
Définit le paramètre nommé option à valeur. Utilisez plutôt le paramètre de configuration équivalent dans main.cf.
-o7 (ignoré)
-o8 (ignoré)
Pour envoyer du contenu 8 bits ou binaire, utilisez une
MIME et spécifiez l'option de ligne de commande -B appropriée.
-oi
Lors de la lecture d'un message à partir de l'entrée standard, ne traitez pas une ligne contenant uniquement un caractère . comme la fin de l'entrée.
-om (ignoré)
L'expéditeur n'est jamais éliminé des expansions d'alias, etc.
-o x valeur (ignoré)
Définissez l'option x sur valeur. Utilisez plutôt le paramètre de configuration équivalent dans main.cf.
-r expediteur
Définit l'adresse de l'expéditeur de l'enveloppe. C'est l'adresse où les problèmes de livraison sont envoyés. Avec les versions de Postfix antérieures à 2.1, l'en-tête de message Errors-To: remplace l'adresse de retour des erreurs.
-R retour
Contrôle de la notification d'état de livraison. Spécifiez "hdrs" pour retourner uniquement l'en-tête lorsqu'un message est rejeté, "full" pour retourner une copie complète (le comportement par défaut).

L'option -R spécifie une limite supérieure ; Postfix ne retournera que l'en-tête lorsqu'une copie complète dépasserait le paramètre bounce_size_limit.

Cette option est ignorée avant la version 2.10 de Postfix.

-q
Tente de livrer tout le courrier mis en file d'attente. Ceci est implémenté en exécutant la commande postqueue(1).

Attention : vider fréquemment le courrier non livrable entraînera une faible performance de livraison de tout autre courrier.

-qintervalle (ignoré)
L'intervalle entre les exécutions de file d'attente. Utilisez plutôt le paramètre de configuration queue_run_delay.
-qIid_file
Planifie la livraison immédiate du courrier avec l'ID de file d'attente spécifié. Cette option est implémentée en exécutant la commande postqueue(1), et est disponible à partir de la version 2.4 de Postfix.
-qRsite
Planifie la livraison immédiate de tout courrier mis en file d'attente pour le site nommé. Cette option n'accepte que les noms de site éligibles pour le service "fast flush", et est implémentée en exécutant la commande postqueue(1). Voir flush(8) pour plus d'informations sur le service "fast flush".
-qSsite
Cette commande n'est pas implémentée. Utilisez plutôt la commande plus lente "sendmail -q".
-t
Extrait les destinataires des en-têtes de message. Ceux-ci sont ajoutés à tous les destinataires spécifiés sur la ligne de commande.

Avec les versions de Postfix antérieures à 2.1, cette option exige qu'aucun destinataire ne soit spécifié sur la ligne de commande.

-U (ignoré)
Soumission initiale de l'utilisateur.
-V envid
Spécifie l'ID de l'enveloppe pour la notification par les serveurs qui prennent en charge DSN.

Cette fonctionnalité est disponible dans Postfix 2.3 et versions ultérieures.

-XV (Postfix 2.2 et antérieur : -V)
Variable Envelope Return Path. Étant donné une adresse d'expéditeur d'enveloppe de la forme propriétaire-liste@origine, chaque destinataire utilisateur@domaine reçoit un courrier avec une adresse d'expéditeur d'enveloppe personnalisée.

Par défaut, l'adresse d'expéditeur d'enveloppe personnalisée est propriétaire-liste+utilisateur=domaine@origine. Les caractères par défaut + et = sont configurables avec le paramètre de configuration default_verp_delimiters.

-XVxy (Postfix 2.2 et antérieur : -Vxy)
Comme -XV, mais utilise x et y comme caractères délimiteurs VERP, au lieu des caractères spécifiés avec le paramètre de configuration default_verp_delimiters.
-v
Envoie un rapport par e-mail de la première tentative de livraison (versions 2.1 de Postfix et ultérieures). La livraison de courrier se fait toujours en arrière-plan. Lorsque plusieurs options -v sont données, activez la journalisation détaillée à des fins de débogage.
-X fichier_journal (ignoré)
Journalise le trafic du répartiteur de courrier. Utilisez plutôt les paramètres de configuration debug_peer_list et debug_peer_level.

SÉCURITÉ

Par conception, ce programme n'a pas de privilèges set-user (ou set-group). Il est préparé pour gérer le contenu des messages provenant d'utilisateurs non fiables, potentiellement distants.

Cependant, comme la plupart des programmes Postfix, ce programme n'applique pas de politique de sécurité sur ses arguments de ligne de commande. Au lieu de cela, il s'appuie sur le système UNIX pour appliquer des politiques d'accès basées sur les identifiants effectifs de l'utilisateur et du groupe du processus. Concrètement, cela signifie qu'exécuter des commandes Postfix en tant que root (depuis sudo ou équivalent) pour le compte d'un utilisateur non-root est susceptible de créer des opportunités d'escalade de privilèges.

Si une application exécute des programmes Postfix pour le compte d'utilisateurs qui n'ont pas d'accès shell normal aux commandes Postfix, alors cette application DOIT restreindre les arguments de ligne de commande spécifiés par l'utilisateur pour éviter l'escalade de privilèges.

  • Filtrez tous les arguments de ligne de commande, par exemple les arguments contenant un chemin d'accès ou spécifiant une méthode d'accès à la base de données. Ces vérifications de chemin d'accès doivent rejeter les liens symboliques ou les liens physiques contrôlés par l'utilisateur vers des fichiers sensibles, et ne doivent pas être vulnérables aux attaques de concurrence TOCTOU.
  • Désactivez le traitement des options de commande pour tous les arguments de commande contenant des données spécifiées par l'utilisateur. Par exemple, la ligne de commande de la commande Postfix sendmail(1) DOIT être structurée comme suit : 
        /chemin/vers/sendmail arguments_systeme -- arguments_utilisateur

    Ici, le "--" désactive le traitement des options de commande pour tous les arguments_utilisateur qui suivent.

Sans le "--", un utilisateur malveillant pourrait activer les options de commande de la commande Postfix sendmail(1), en spécifiant une adresse e-mail commençant par "-".

DIAGNOSTICS


Les problèmes sont enregistrés dans syslogd(8) ou postlogd(8), et sur le flux d'erreur standard.

ENVIRONNEMENT

MAIL_CONFIG
Répertoire contenant les fichiers de configuration Postfix.
MAIL_VERBOSE (la valeur n'a pas d'importance)
Active la journalisation détaillée à des fins de débogage.
MAIL_DEBUG (la valeur n'a pas d'importance)
Active le débogage avec une commande externe, comme spécifié avec le paramètre de configuration debugger_command.
NAME
Le nom complet de l'expéditeur. Ceci est utilisé uniquement pour les messages sans en-tête de message From:. Voir également l'option -F ci-dessus.

Les paramètres main.cf suivants sont particulièrement pertinents pour ce programme. Le texte ci-dessous ne fournit qu'un résumé des paramètres. Voir postconf(5) pour plus de détails, y compris des exemples.

CONTRÔLES DE COMPATIBILITÉ

Disponible à partir de Postfix 2.9 :

sendmail_fix_line_endings (toujours)
Contrôle comment la commande sendmail de Postfix convertit les fins de ligne des messages électroniques de <CR><LF> au format UNIX (<LF>).

CONTRÔLES DE DÉPANNAGE

Le fichier DEBUG_README donne des exemples de la façon de dépanner un système Postfix.

debugger_command (vide)
La commande externe à exécuter lorsqu'un programme démon Postfix est invoqué avec l'option -D.
debug_peer_level (2)
L'incrément du niveau de journalisation détaillée lorsqu'une destination nexthop, un nom de client ou serveur distant, ou une adresse réseau correspond à un modèle donné avec le paramètre debug_peer_list.
debug_peer_list (vide)
Liste optionnelle des modèles de destination nexthop, de nom de client ou serveur distant, ou d'adresse réseau qui, s'ils correspondent, provoquent une augmentation du niveau de journalisation détaillée du montant spécifié dans $debug_peer_level.

CONTRÔLES D'ACCÈS

Disponible dans Postfix version 2.2 et ultérieures :

authorized_flush_users (statique:tous)
Liste des utilisateurs autorisés à vider la file d'attente.
authorized_mailq_users (statique:tous)
Liste des utilisateurs autorisés à consulter la file d'attente.
authorized_submit_users (statique:tous)
Liste des utilisateurs autorisés à soumettre du courrier avec la commande sendmail(1) (et avec la commande auxiliaire privilégiée postdrop(1)).

CONTRÔLES DE RESSOURCES ET DE TAUX

bounce_size_limit (50000)
La quantité maximale de texte du message original envoyée dans une notification de non-livraison.

NAME

mailq, sendmail — show keys for message queue

SYNOPSIS

mailq [-LA] [-qbatch_size] [-qaddress] [-Q] [-n]

sendmail [-LA] [-qbatch_size] [-qaddress] [-Q] [-n]

DESCRIPTION

The mailq command shows the status of the mail queue. It is a link to the sendmail command, so that existing mail delivery commands will continue to work.

The sendmail command is used to control the Postfix queue. The primary purpose of sendmail is to deliver mail to the local delivery agent. When invoked with arguments other than those for delivery, it provides a queue control interface that is compatible with the original sendmail(1) program.
