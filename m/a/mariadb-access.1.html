MARIADB-ACCESS(1) Système de base de données MariaDB MARIADB-ACCESS(1)

NOM

mariadb-access - client pour vérifier les privilèges d'accès (mariadb-access est maintenant un lien symbolique vers mariadb-access)

SYNTAXE

mariadb-access [nom_hote [nom_utilisateur [nom_base_de_donnees]]] [options]

DESCRIPTION

mariadb-access est un outil de diagnostic écrit par Yves Carlier. Il vérifie les privilèges d'accès pour une combinaison nom d'hôte, nom d'utilisateur et base de données. Notez que mariadb-access vérifie l'accès en utilisant uniquement les tables user, db et host. Il ne vérifie pas les privilèges sur les tables, colonnes ou routines spécifiés dans les tables tables_priv, columns_priv ou procs_priv.

Appelez mariadb-access comme ceci :

shell> mariadb-access [nom_hote [nom_utilisateur [nom_base_de_donnees]]] [options]

mariadb-access prend en charge les options suivantes.

•--help, -?

Affiche un message d'aide et quitte.

•--brief, -b

Génère des rapports au format tabulaire sur une seule ligne.

•--commit

Copie les nouveaux privilèges d'accès des tables temporaires vers les tables de privilèges d'origine. Les tables de privilèges doivent être rechargées pour que les nouveaux privilèges prennent effet. (Par exemple, exécutez une commande mariadb-admin reload.)

•--copy

Recharge les tables de privilèges temporaires à partir des tables d'origine.

•--db=nom_base_de_donnees, -d nom_base_de_donnees

Spécifie le nom de la base de données.

•--debug=N

Spécifie le niveau de débogage. N peut être un entier de 0 à 3.

•--host=nom_hote, -h nom_hote

Le nom d'hôte à utiliser dans les privilèges d'accès.

•--howto

Affiche des exemples montrant comment utiliser mariadb-access.

•--old_server

Se connecte à un très vieux serveur MySQL (avant MySQL 3.21) qui ne sait pas gérer les clauses WHERE complètes.

•--password[=mot_de_passe], -p[mot_de_passe]

Le mot de passe à utiliser lors de la connexion au serveur. Si vous omettez la valeur du mot_de_passe après l'option --password ou -p sur la ligne de commande, mariadb-access vous le demandera.

Spécifier un mot de passe sur la ligne de commande doit être considéré comme non sécurisé. Voir Section 5.3.2.2, « Recommandations pour les utilisateurs finaux concernant la sécurité des mots de passe ».

•--plan

Affiche des suggestions et des idées pour les futures versions.

•--preview

Affiche les différences de privilèges après avoir apporté des modifications aux tables de privilèges temporaires.

•--relnotes

Affiche les notes de version.

•--rhost=nom_hote, -H nom_hote

Se connecte au serveur MariaDB sur l'hôte donné.

•--rollback

Annule les modifications les plus récentes apportées aux tables de privilèges temporaires.

•--spassword[=mot_de_passe], -P[mot_de_passe]

Le mot de passe à utiliser lors de la connexion au serveur en tant que superutilisateur. Si vous omettez la valeur du mot_de_passe après l'option --spassword ou -p sur la ligne de commande, mariadb-access vous le demandera.

Spécifier un mot de passe sur la ligne de commande doit être considéré comme non sécurisé. Voir Section 5.3.2.2, « Recommandations pour les utilisateurs finaux concernant la sécurité des mots de passe ».

•--superuser=nom_utilisateur, -U nom_utilisateur

Spécifie le nom d'utilisateur pour se connecter en tant que superutilisateur.

•--table, -t

Génère des rapports au format table.

•--user=nom_utilisateur, -u nom_utilisateur

Le nom d'utilisateur à utiliser dans les privilèges d'accès.

•--version, -v

Affiche les informations de version et quitte.

Si votre distribution MariaDB est installée dans un emplacement non standard, vous devez modifier l'emplacement où mariadb-access s'attend à trouver le client mariadb. Éditez le script mariadb-access à environ la ligne 18. Recherchez une ligne ressemblant à ceci :

$MYSQL     = '/usr/local/bin/mariadb';    # chemin vers l'exécutable mariadb

Modifiez le chemin pour qu'il corresponde à l'emplacement où mariadb est réellement stocké sur votre système. Si vous ne le faites pas, une erreur "Broken pipe" se produira lorsque vous exécuterez mariadb-access.
