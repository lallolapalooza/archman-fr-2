NOM

match_parens - trouver les incompatibilités de divers crochets et guillemets

SYNOPSIS

match_parens [nom_de_fichier]

Options

-h

affiche cette aide et quitte
-H,--help
affiche la documentation complète et quitte
-V,--version
affiche la version et quitte
-l,--latex
convertit ``...'' en «... » avant le test
-n,--number=N
définit le nombre de caractères non concordants à afficher sur N (par défaut : 10)
-p,--pairs=S
définit les paires correspondantes sur S (par défaut : {}[]()«»''‘’
--test
effectue un test interne et quitte

DESCRIPTION

Les incompatibilités de parenthèses, accolades, crochets (angulaires), notamment dans les sources TeX qui peuvent en être riches, peuvent être difficiles à tracer. Ce petit script vous aide en écrivant votre texte sur la sortie standard, après avoir ajouté une marge gauche à votre texte, qui sera normalement presque vide, mais qui affichera clairement jusqu'à 10 incompatibilités. (Essayez-moi sur moi-même pour voir que la parenthèse qui commence cette phrase ne sera pas trouvée comme correspondante à la fin du fichier. Si vous me regardez dans l'éditeur vim, alors sélectionnez ce paragraphe et essayez la commande : :!%.

Par défaut, les paires suivantes sont testées :

()

parenthèses rondes
{}
accolades
[]
crochets carrés
<>
crochets angulaires (uniquement dans le texte HTML)
guillemets doubles ASCII
«»
guillemets doubles Unicode
''
apostrophes simples ASCII
‘’
apostrophes simples Unicode

La valeur de sortie du script est 0 en l'absence d'incompatibilités, 1 sinon.

Les crochets angulaires ne sont recherchés qu'à l'intérieur du texte HTML, où le HTML est censé commencer par <html> ou =begin␣rdoc et se terminer par </html> ou =end.

Options

-h,--help

affiche une aide courte et quitte.
-H,--Help
affiche la documentation complète via less et quitte.
-V,--version
affiche la version de ce script et quitte.
-l,--latex
convertit ``...'' en «... » avant le test.
-n,--number=N
Définit le nombre de caractères non concordants affichés sur N. Par défaut, seuls les 10 premiers sont affichés.
-p,--pairs=S
Définit les paires correspondantes sur S (par défaut : {}[]()«»''‘’ ). Par exemple, si vous ne voulez rechercher que les apostrophes simples ASCII, utilisez --pairs="''". Ou, si vous voulez uniquement faire correspondre les accolades et les guillemets, utilisez -p«». Notez que si du html est détecté dans votre texte, <> est automatiquement ajouté à la liste des paires. Ainsi, par défaut, <...> n'est testé qu'en html, mais vous pouvez le tester dans d'autres textes en spécifiant la paire <> dans l'option --pairs.
--test
effectue un test interne et quitte. Notez que si, avec l'option --pairs, vous spécifiez une liste de paires autre que celle par défaut, le test échouera probablement, mais vous pourrez tout de même voir les effets de votre liste de paires sur les données de test.

EXEMPLES

Supposons que nous ayons deux fichiers, bon et mauvais, contenant les textes suivants :

bon:

Ceci est un test (simple) sans incompatibilités

mauvais:

Ceci est un test (simple contenant des incompatibilités

Alors voici quelques exemples d'utilisation. D'abord un test simple sur ces fichiers : $ matchparens bon
1 || Ceci est un test (simple)
2 || sans incompatibilités
$ echo $?
0
$ matchparens mauvais
1 | (| Ceci est un test (simple
2 | (| contenant des incompatibilités
$ echo $?
1

Signaler simplement s'il y a des incompatibilités : $ matchparens bon >/dev/null && echo correct || echo problèmes
correct
$ matchparens mauvais >/dev/null && echo correct || echo problèmes
problèmes

Signaler tous les fichiers tex avec des incompatibilités dans le répertoire courant : $ for i in *.tex; do matchparens $i >/dev/null || echo $i; done

Les correspondances doivent être dans le bon ordre : $ echo -e "Ceci est un ([simple)] test0 | match_parens
1 ([)]Ceci est un ([simple)] test
2 ([)]
