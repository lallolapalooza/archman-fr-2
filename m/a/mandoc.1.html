MANDOC(1) Manuel des commandes générales MANDOC(1)

NOM

mandoc — met en forme les pages de manuel

SYNTAXE

mandoc [-ac] [-I os=nom] [-K encodage] [-mdoc | -man] [-O options] [-T sortie] [-W niveau] [fichier ...]

DESCRIPTION

L'utilitaire mandoc met en forme les pages de manuel pour l'affichage.

Par défaut, mandoc lit le texte mdoc(7) ou man(7) depuis l'entrée standard et produit une sortie au format -T locale.

Les options sont les suivantes :

-a
Si la sortie standard est un terminal et que -c n'est pas spécifié, utilise less(1) pour paginer la sortie, tout comme man(1) le ferait.
-c
Copie les pages de manuel formatées vers la sortie standard sans utiliser less(1) pour les paginer. C'est le comportement par défaut. Il peut être spécifié pour annuler -a.
-I os=nom
Remplace le nom du système d'exploitation par défaut nom pour la macro Os de mdoc(7) et pour la macro TH de man(7).
-K encodage
Spécifie l'encodage d'entrée. Les arguments encodage supportés sont us-ascii, iso-8859-1, et utf-8. Si non spécifié, la détection automatique utilise la première correspondance de la liste suivante :
  1. Si les trois premiers octets du fichier d'entrée sont le marqueur d'ordre des octets UTF-8 (BOM, 0xefbbbf), l'entrée est interprétée comme utf-8.
  2. Si la première ou la seconde ligne du fichier d'entrée correspond au format de ligne de mode emacs
    .\" -*- [...;] coding: encodage; -*-

    alors l'entrée est interprétée selon encodage.

  3. Si le premier octet non-ASCII dans le fichier introduit une séquence UTF-8 valide, l'entrée est interprétée comme utf-8.
  4. Sinon, l'entrée est interprétée comme iso-8859-1.
-mdoc | -man
Avec -mdoc, tous les fichiers d'entrée sont interprétés comme mdoc(7). Avec -man, tous les fichiers d'entrée sont interprétés comme man(7). Par défaut, le langage d'entrée est automatiquement détecté pour chaque fichier : si la première macro est Dd ou Dt, le parseur mdoc(7) est utilisé ; sinon, le parseur man(7) est utilisé. Avec d'autres arguments, -m est silencieusement ignoré.
-O options
Options de sortie séparées par des virgules. Voir la description des formats de sortie individuels pour les options supportées.
-T sortie
Sélectionne le format de sortie. Les valeurs supportées pour l'argument sortie sont ascii, html, le défaut locale, man, markdown, pdf, ps, tree, et utf8.

Le mode spécial -T lint analyse uniquement l'entrée et ne produit aucune sortie. Il implique -W all et redirige les messages du parseur, qui apparaissent normalement sur la sortie d'erreur standard, vers la sortie standard.

-W niveau
Spécifie le niveau minimum des messages niveau à signaler sur la sortie d'erreur standard et à affecter le code de sortie. Le niveau peut être base, style, warning, error, ou unsupp. Le niveau base dérive automatiquement le système d'exploitation du contenu de la macro Os, de l'option de ligne de commande -Ios, ou de la valeur de retour de uname(3). Les niveaux openbsd et netbsd sont des variantes de base qui contournent la détection automatique et demandent la validation des conventions du système de base pour un système d'exploitation particulier. Le niveau all est un alias pour base. Par défaut, mandoc est silencieux. Voir CODE DE SORTIE et DIAGNOSTICS pour plus de détails.

L'option spéciale -W stop indique à mandoc de sortir après avoir analysé un fichier qui provoque des avertissements ou des erreurs d'au moins le niveau demandé. Aucune sortie formatée ne sera produite à partir de ce fichier. Si un niveau et stop sont demandés, ils peuvent être joints par une virgule, par exemple -W error,stop.

fichier
Lit depuis le fichier d'entrée donné. Si plusieurs fichiers sont spécifiés, ils sont traités dans l'ordre donné. Si non spécifié, mandoc lit depuis l'entrée standard.

Les options -fhklw sont également supportées et sont documentées dans le manuel man(1). En mode -f et -k, mandoc supporte également les options -CMmOSs décrites dans le manuel apropos(1). Les options -fkl sont mutuellement exclusives et se remplacent les unes les autres.

Sortie ASCII

Utilisez -T ascii pour forcer la sortie texte dans l'encodage de caractères ASCII 7 bits documenté dans la page de manuel ascii(7), en ignorant le locale(1) défini dans l'environnement.

Les styles de police sont appliqués en utilisant un encodage avec retour arrière, de sorte qu'un caractère souligné ‘c’ est rendu comme ‘_\[bs]c’, où ‘\[bs]’ est le caractère retour arrière numéro 8. Les caractères en gras sont rendus comme ‘c\[bs]c’. Ce balisage est généralement converti en séquences de terminal appropriées par le pagineur ou ul(1). Pour supprimer le balisage, redirigez la sortie vers col(1) -b à la place.

Les caractères spéciaux documentés dans mandoc_char(7) sont rendus au mieux dans un équivalent ASCII. En particulier, les guillemets ouvrants et fermants ‘guillemets simples’ sont représentés par les caractères numéro 0x60 et 0x27, respectivement, ce qui est conforme à toutes les normes ASCII de 1965 à la dernière révision (2012) et qui correspond à la manière traditionnelle dont

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

h Les formateurs roff(7) représentent les apostrophes dans la sortie ASCII. Ce rendu ASCII correct peut sembler étrange avec les polices modernes compatibles Unicode car, contrairement à l'ASCII, Unicode utilise le point de code U+0060 uniquement pour l'accent grave, jamais pour une guillemet ouvrant.

Les arguments -O suivants sont acceptés :

indent=indent
La marge gauche pour le texte normal est définie sur indent caractères blancs au lieu des cinq par défaut pour mdoc(7) et sept pour man(7). Il n'est pas recommandé d'augmenter cette valeur ; cela pourrait entraîner une dégradation du formatage, par exemple des lignes trop pleines ou des sauts de ligne disgracieux. Lorsque la sortie est dirigée vers un pagineur sur un terminal de moins de 66 colonnes de large, la valeur par défaut est réduite à trois colonnes.
mdoc
Formate les fichiers d'entrée man(7) dans le style de sortie mdoc(7). Cela imprime le nom du système d'exploitation plutôt que le titre de la page sur le côté droit de la ligne de pied de page, et cela implique -O indent=5. Une application utile est de vérifier que la sortie -T man est formatée de la même manière que la source mdoc(7) à partir de laquelle elle a été générée.
tag[=term]
Si la page de manuel formatée est ouverte dans un pagineur, accède à la définition du term plutôt que d'afficher la page de manuel depuis le début. Si aucun term n'est spécifié, réutilise le premier argument de ligne de commande qui n'est pas un numéro de section. Si cet argument est au format apropos(1) key=val, seule la valeur de val est utilisée plutôt que l'argument dans son ensemble. Ceci est utile pour des commandes comme ‘man -akO tag Ic=ulimit’ pour rechercher un mot-clé et sauter directement à sa définition dans les pages de manuel correspondantes.
width=width
La largeur de sortie est définie sur width au lieu de la valeur par défaut de 78. Lorsque la sortie est dirigée vers un pagineur sur un terminal de moins de 79 colonnes de large, la valeur par défaut est réduite à une colonne de moins que la largeur du terminal. Dans tous les cas, les lignes qui sont produites en mode littéral ne sont jamais coupées et peuvent dépasser la largeur de sortie.

Sortie HTML

La sortie produite par -T html est conforme à HTML5 en utilisant des balises auto-fermantes optionnelles. Les styles par défaut utilisent uniquement CSS1. Les équations rendues à partir de blocs eqn(7) utilisent MathML.

Le fichier /usr/share/misc/mandoc.css documente les classes de feuilles de style disponibles pour personnaliser la sortie. Si aucune feuille de style n'est spécifiée avec -O style, -T html utilise par défaut une sortie simple (via une feuille de style intégrée) lisible dans n'importe quel navigateur graphique ou textuel.

Les caractères non-ASCII sont rendus sous forme de références de caractères Unicode hexadécimaux.

Les arguments -O suivants sont acceptés :

fragment
Omet la déclaration <!DOCTYPE> ainsi que les éléments <html>, <head> et <body> et n'émet que le sous-arbre sous l'élément <body>. L'argument style sera ignoré. Ceci est utile pour intégrer le contenu du manuel dans des documents existants.
includes=fmt
La chaîne fmt, par exemple, ../src/%I.html, est utilisée comme modèle pour les fichiers d'en-tête liés (généralement via la macro In). Les occurrences de ‘%I’ sont remplacées par le nom du fichier inclus. La valeur par défaut est de ne pas présenter d'hyperlien.
man=fmt[;fmt]
La chaîne fmt, par exemple, ../html%S/%N.%S.html, est utilisée comme modèle pour les manuels liés (généralement via la macro Xr). Les occurrences de ‘%N’ et ‘%S’ sont remplacées par le nom et la section du manuel lié, respectivement. Si aucune section n'est incluse, la section 1 est supposée. La valeur par défaut est de ne pas présenter d'hyperlien. Si deux formats sont donnés et qu'un fichier %N.%S existe dans le répertoire courant, le premier format est utilisé ; sinon, le second format est utilisé.
style=style.css
Le fichier style.css est utilisé comme feuille de style externe. Il doit s'agir d'une URI absolue ou relative valide.
tag[=term]
Même syntaxe et sémantique que pour la Sortie ASCII. Ceci est implémenté en passant une URI file:// se terminant par un identifiant de fragment au pagineur, plutôt qu'en passant simplement un nom de fichier. Lors de l'utilisation de cet argument, utilisez un pagineur prenant en charge de telles URIs, par exemple 
MANPAGER='lynx -force_html' man -T html -O tag=MANPAGER man
MANPAGER='w3m -T text/html' man -T html -O tag=toc mandoc

Par conséquent, pour la sortie HTML, cet argument ne fonctionne pas avec more(1) ou less(1). Par exemple, ‘MANPAGER=less man -T html -O tag=toc mandoc’ ne fonctionne pas car less(1) ne prend pas en charge les URIs file://.

toc
Si un fichier d'entrée contient au moins deux sections non standard, imprime un sommaire près du début de la sortie.

Sortie Locale

Par défaut, mandoc sélectionne automatiquement la sortie UTF-8 ou ASCII en fonction de la locale(1) actuelle. Si l'une des variables d'environnement LC_ALL, LC_CTYPE ou LANG est définie et que la première qui est définie sélectionne l'encodage de caractères UTF-8, il produit une Sortie UTF-8 ; sinon, il revient à la Sortie ASCII. Ce mode de sortie peut également être sélectionné explicitement avec -T locale.

Sortie Man

Utilisez -T man pour traduire l'entrée mdoc(7) au format de sortie man(7). Ceci est utile pour distribuer des sources de manuel à des systèmes hérités qui n'ont pas de formateurs mdoc(7). Le code eqn(7) et tbl(7) intégré n'est pas pris en charge.

Si le format d'entrée d'un fichier est man(7), l'entrée est copiée vers la sortie. L'analyseur est également exécuté, et comme d'habitude, le niveau -W contrôle quels DIAGNOSTICS sont affichés avant de copier l'entrée vers la sortie.

Sortie Markdown

Utilisez -T markdown pour traduire l'entrée mdoc(7) au format markdown conforme à la spécification de John Gruber de 2004. La sortie est également presque conforme à la spécification CommonMark.

Le jeu de caractères utilisé pour la sortie markdown est ASCII. Les caractères non-ASCII sont encodés en entités HTML. Comme cela n'est pas possible dans les contextes de polices littérales, car ceux-ci sont rendus comme des spans de code et des blocs de code dans la sortie markdown, les caractères non-ASCII sont translatés en approximations ASCII dans ces contextes.

Markdown est un langage de balisage très faible, donc tout le balisage sémantique est perdu, et même une partie du balisage présentationnel peut être perdue. N'utilisez pas cela comme étape intermédiaire pour la conversion en HTML ; utilisez plutôt -T html directement.

Les langages d'entrée man(7), tbl(7) et eqn(7) ne sont pas pris en charge par le mode de sortie -T markdown.

Sortie PDF

Une sortie PDF-1.1 peut être générée par -T pdf. Voir Sortie PostScript pour les arguments et les valeurs par défaut de -O.

Sortie PostScript

Les pages PostScript « Adobe-3.0 » Niveau-2 peuvent être générées par -T ps. Les pages de sortie sont par défaut au format lettre et sont rendues dans la famille de polices Times, 11 points. Les marges sont calculées comme 1/9 de la longueur et de la largeur de la page. La hauteur de ligne est de 1,4 m.

Les caractères spéciaux sont rendus comme dans la Sortie ASCII.

Les arguments -O suivants sont acceptés :

paper=name
La taille du papier name peut être l'une des suivantes : a3, a4, a5, legal, ou letter. Vous pouvez également manu
ally spécifiez les dimensions comme NNxNN, largeur par hauteur en millimètres. Si une valeur inconnue est rencontrée, lettre est utilisée.

Sortie UTF-8

Utilisez -T utf8 pour forcer la sortie texte en encodage de caractères multi-octets UTF-8, en ignorant les paramètres de locale(1) dans l'environnement. Voir Sortie ASCII concernant les styles de police et les arguments -O.

Sur les systèmes d'exploitation qui manquent de prise en charge des locales ou des caractères larges, et sur ceux où la représentation interne des caractères n'est pas UCS-4, mandoc revient toujours à la Sortie ASCII.

Sortie de l'arbre syntaxique

Utilisez -T tree pour afficher une représentation lisible par l'homme de l'arbre syntaxique. C'est utile pour déboguer le code source des pages de manuel. Le format exact est susceptible de changer, alors n'écrivez pas d'analyseurs pour celui-ci.

Le premier paragraphe montre les métadonnées trouvées dans le prologue mdoc(7), sur la ligne TH de man(7), ou les solutions de repli utilisées.

Dans le vidage de l'arbre, chaque ligne de sortie montre un nœud de l'arbre syntaxique. Les nœuds enfants sont indentés par rapport à leur nœud parent. Les colonnes sont :

  1. Pour les nœuds de macro, le nom de la macro ; pour les nœuds de texte et de tbl(7), le contenu. Il existe un format spécial pour les nœuds eqn(7).
  2. Type de nœud (texte, élément, bloc, en-tête, corps, fin-de-corps, pied, tbl, eqn).
  3. Indicateurs :
    • Une parenthèse ouvrante si le nœud est un délimiteur ouvrant.
    • Un astérisque si le nœud commence une nouvelle ligne d'entrée.
    • Le numéro de ligne d'entrée (commençant à un).
    • Deux-points.
    • Le numéro de colonne d'entrée (commençant à un).
    • Une parenthèse fermante si le nœud est un délimiteur fermant.
    • Un point si le nœud termine une phrase.
    • BROKEN si le nœud est un bloc interrompu par un autre bloc.
    • NOSRC si le nœud n'est pas dans le fichier d'entrée, mais généré automatiquement à partir des macros.
    • NOPRT si le nœud n'est pas censé générer de sortie pour un format de sortie donné.

L'argument -O suivant est accepté :

noval
Ignorer la validation et afficher l'arbre syntaxique non validé. Cela peut aider à déterminer si un comportement donné est causé par l'analyseur ou par le validateur. Les métadonnées ne sont pas disponibles dans ce cas.

ENVIRONNEMENT

LC_CTYPE
La locale(1) d'encodage des caractères. Lorsque la Sortie Locale est sélectionnée, elle décide s'il faut utiliser le format de sortie ASCII ou UTF-8. Elle n'affecte jamais l'interprétation des fichiers d'entrée.
MANPAGER
Toute valeur non vide de la variable d'environnement MANPAGER est utilisée à la place du programme de pagination standard, less(1) ; voir man(1) pour plus de détails. Utilisé uniquement si -a ou -l est spécifié.
PAGER
Spécifie le programme de pagination à utiliser lorsque MANPAGER n'est pas défini. Si PAGER ni MANPAGER ne sont définis, less(1) est utilisé. Utilisé uniquement si -a ou -l est spécifié.

STATUT DE SORTIE

L'utilitaire mandoc se termine avec l'une des valeurs suivantes, contrôlée par le niveau de message associé à l'option -W :

0
Aucune violation des conventions du système de base, aucune suggestion de style, aucun avertissement ou aucune erreur ne s'est produit, ou ceux qui se sont produits ont été ignorés car ils étaient inférieurs au niveau demandé.
1
Au moins une violation des conventions du système de base ou une suggestion de style s'est produite, mais aucun avertissement ou aucune erreur, et -W base ou -W style a été spécifié.
2
Au moins un avertissement s'est produit, mais aucune erreur, et -W warning ou un niveau inférieur a été demandé.
3
Au moins une erreur d'analyse s'est produite, mais aucune fonctionnalité non prise en charge n'a été rencontrée, et -W error ou un niveau inférieur a été demandé.
4
Au moins une fonctionnalité non prise en charge a été rencontrée, et -W unsupp ou un niveau inférieur a été demandé.
5
Des arguments de ligne de commande invalides ont été spécifiés. Aucun fichier d'entrée n'a été lu.
6
Une erreur du système d'exploitation s'est produite, par exemple une exhaustion de la mémoire, des descripteurs de fichiers ou des entrées de la table des processus. De telles erreurs peuvent amener mandoc à se terminer immédiatement, éventuellement au milieu de l'analyse ou du formatage d'un fichier.

Notez que la sélection du mode de sortie -T lint implique -W all.

EXEMPLES

Pour paginer les manuels vers le terminal :

$ mandoc -l mandoc.1 man.1 apropos.1 makewhatis.8

Pour produire des manuels HTML avec /usr/share/misc/mandoc.css comme feuille de style :

$ mandoc -T html -O style=/usr/share/misc/mandoc.css mdoc.7 > mdoc.7.html

Pour vérifier un grand ensemble de manuels :

$ mandoc -T lint `find /usr/src -name \*\.[1-9]`

Pour produire une série de manuels PostScript pour papier A4 :

$ mandoc -T ps -O paper=a4 mdoc.7 man.7 > manuals.ps

Convertir un manuel mdoc(7) moderne vers l'ancien format man(7), pour utilisation sur des systèmes ne disposant pas d'un analyseur mdoc(7) :

$ mandoc -T man foo.mdoc > foo.man

DIAGNOSTICS

Les messages affichés par mandoc suivent ce format :

mandoc: fichier:ligne:colonne: niveau: message: arguments de macro (os)

Les trois premiers champs identifient le nom du fichier fichier, le numéro de ligne et le numéro de colonne du fichier d'entrée où le message a été déclenché. Les numéros de ligne et de colonne commencent à 1. Les deux sont omis pour les messages faisant référence à un fichier d'entrée dans son ensemble. Toutes les chaînes de niveau et message sont expliquées ci-dessous. Le nom de la macro déclenchant le message et ses arguments sont omis lorsqu'ils sont dénués de sens. Le spécificateur de système d'exploitation os est omis pour les messages qui sont pertinents pour tous les systèmes d'exploitation. Les messages fatals concernant des arguments de ligne de commande invalides ou des erreurs du système d'exploitation, par exemple lors de l'épuisement de la mémoire, peuvent également omettre les champs fichier et niveau.

Les niveaux de message ont les significations suivantes :

syserr
Une erreur du système d'exploitation s'est produite. Il n'y a pas nécessairement de problème avec les fichiers d'entrée. La sortie peut néanmoins être manquante ou incomplète.
badarg
Des arguments de ligne de commande invalides ont été spécifiés. Aucun fichier d'entrée n'a été lu et aucune sortie n'est produite.
unsupp
Un fichier d'entrée utilise des fonctionnalités de bas niveau non prises en charge de roff(7). La sortie peut être incomplète et/ou mal formatée, il peut donc être préférable d'utiliser GNU troff au lieu de mandoc pour traiter le fichier.
error
Indique un risque de perte d'informations ou de mauvaise mise en forme grave, dans la plupart des cas causé par des erreurs de syntaxe graves.
warning
Indique un risque que les informations affichées ou leur mise en forme puissent différer de l'intention de l'auteur de manière mineure. De plus, les erreurs de syntaxe sont classées au moins comme des avertissements, même si elles ne provoquent généralement pas de mauvaise mise en forme.
style
Un fichier d'entrée utilise un style douteux ou déconseillé. Ce n'est pas une plainte concernant la syntaxe, et la mise en forme ou la portabilité ne sont probablement pas en danger. Bien que des précautions soient prises pour éviter les faux positifs aux niveaux de message les plus élevés, le niveau style essaie de réduire la probabilité que des problèmes passent inaperçus, il peut donc occasionnellement émettre des suggestions erronées. Veuillez utiliser votre bon jugement pour décider si une suggestion de style particulière justifie réellement une modification du fichier d'entrée.
base
Une convention utilisée dans le système de base d'un système d'exploitation spécifique n'est pas respectée. Il ne s'agit pas d'erreurs de balisage, et ni la qualité de la mise en forme ni la portabilité ne sont en danger. Les messages de niveau base sont imprimés avec le style plus intuitif level tag.

Les messages des niveaux base, style, warning, error et unsupp sont cachés à moins que leur niveau, ou un niveau inférieur, ne soit demandé à l'aide d'une option -W ou du mode de sortie -T lint.

Comme indiqué ci-dessous, toutes les vérifications base et certaines vérifications style ne sont effectuées que si un nom de système d'exploitation spécifique apparaît dans les arguments de l'option de ligne de commande -W, de la macro Os, de l'option de ligne de commande -Ios ou, si aucun des deux n'est présent, dans la valeur de retour de la fonction uname(3).

Conventions pour les manuels du système de base

Mdocdate trouvé
(mdoc, NetBSD) La macro Dd utilise la substitution de mots-clés Mdocdate de CVS, non prise en charge par le système de base NetBSD. Envisagez plutôt d'utiliser le format conventionnel « Mois jj, aaaa ».
Mdocdate manquant
(mdoc, OpenBSD) La macro Dd n'utilise pas la substitution de mots-clés Mdocdate de CVS, mais son utilisation est conventionnellement attendue dans le système de base OpenBSD.
architecture inconnue
(mdoc, OpenBSD, NetBSD) Le troisième argument de la macro Dt ne correspond à aucune des architectures sur lesquelles ce système d'exploitation est exécuté.
système d'exploitation spécifié explicitement
(mdoc, OpenBSD, NetBSD) La macro Os a un argument. Dans le système de base, elle est conventionnellement laissée vide.
identifiant RCS manquant
(OpenBSD, NetBSD) La page de manuel manque de la ligne de commentaire avec l'identifiant RCS généré par la substitution de mots-clés OpenBSD ou NetBSD de CVS, telle qu'utilisée conventionnellement dans ces systèmes d'exploitation.

Suggestions de style

format de date hérité de man(7)
(mdoc) La macro Dd utilise le format de date hérité de man(7) « aaaa-jj-mm ». Envisagez plutôt d'utiliser le format de date conventionnel de mdoc(7) « Mois jj, aaaa ».
normalisation du format de date à: ...
(mdoc, man) La macro Dd ou TH fournit un nom de mois abrégé ou un numéro de jour avec un zéro initial. Dans la sortie formatée, le nom du mois est écrit en toutes lettres et le zéro initial est omis.
caractère en minuscules dans le titre du document
(mdoc, man) Le titre est toujours utilisé tel qu'il est donné dans la macro Dt ou TH.
identifiant RCS en double
Une seule page de manuel contient deux copies de l'identifiant RCS pour le même système d'exploitation. Envisagez de supprimer l'instance ultérieure et de déplacer la première en haut de la page.
possible faute de frappe dans le nom de la section
(mdoc) La correspondance floue de chaînes de caractères a révélé que l'argument d'une macro Sh est similaire, mais pas identique, à un nom de section standard.
argument entre guillemets non terminé
(roff) Les arguments de macro peuvent être entourés de guillemets doubles de telle sorte que les espaces et les noms de macro contenus dans l'argument entre guillemets n'ont pas besoin d'être échappés. Le guillemet fermant du dernier argument d'une macro peut être omis. Cependant, son omission n'est pas recommandée car elle rend le code plus difficile à lire.
macro inutile
(mdoc) Une macro Bt, Tn ou Ud a été trouvée. Supprimez-la simplement : elle ne sert à rien.
envisagez d'utiliser la macro OS
(mdoc) Une chaîne de caractères a été trouvée en texte brut ou dans une macro Bx qui pourrait être représentée à l'aide de Ox, Nx, Fx ou Dx.
errnos pas dans l'ordre
(mdoc, NetBSD) Les éléments Er d'une liste Bl ne sont pas dans l'ordre alphabétique.
errno en double
(mdoc, NetBSD) Une liste Bl contient deux entrées consécutives It décrivant le même numéro Er.
manuel référencé non trouvé
(mdoc) Une macro Xr fait référence à une page de manuel qui n'a pas été trouvée. Lors de l'exécution avec -W base, la recherche est limitée au système de base, par défaut à /usr/share/man:/usr/X11R6/man. Ce chemin peut être configuré lors de la compilation à l'aide de la macro de préprocesseur MANPATH_BASE. Lors de l'exécution avec -W style, la recherche s'effectue le long du chemin de recherche complet tel que décrit dans la page de manuel man(1), en respectant les options de ligne de commande -m et -M, la variable d'environnement MANPATH, le fichier man.conf(5) et en revenant par défaut à /usr/share/man:/usr/X11R6/man:/usr/local/man, également configurable lors de la compilation à l'aide de la macro de préprocesseur MANPATH_DEFAULT.
délimiteur final
(mdoc) Le dernier argument d'une macro Ex, Fo, Nd, Nm, Os, Sh, Ss, St, ou Sx se termine par un délimiteur final. C'est généralement un mauvais style et cela indique souvent des fautes de frappe. Très probablement, le délimiteur peut être supprimé.
pas d'espace avant le délimiteur final
(mdoc) Le dernier argument d'une macro qui prend en charge les arguments de délimiteur final est plus long qu'un octet et se termine par un délimiteur final. Envisagez d'insérer un espace de sorte que le délimiteur devienne un argument séparé, le déplaçant ainsi hors de la portée de la macro.
mode de remplissage déjà activé, ignoré
(man) Une requête fi se produit alors que le document est toujours en mode de remplissage, ou est déjà revenu en mode de remplissage. Elle n'a aucun effet.
mode de remplissage déjà désactivé, ignoré
(man) Une requête nf se produit alors que le document est déjà passé en mode sans remplissage et n'est pas encore revenu en mode de remplissage. Elle n'a aucun effet.
ligne de texte d'entrée plus longue que 80 octets
Envisagez de casser la ligne de texte d'entrée à l'un des espaces avant la colonne 80.
texte verbatim « -- », envisagez peut-être d'utiliser \(em
(mdoc) Même si le périphérique de sortie ASCII affiche un tiret cadratin comme « -- », ce n'est pas une bonne façon de l'écrire dans un fichier d'entrée car il s'affiche mal sur tous les autres périphériques de sortie.
nom de fonction sans balisage
(mdoc) Un mot suivi d'une paire de parenthèses vides apparaît sur une ligne de texte. Envisagez d'utiliser une macro Fn ou Xr.
espace en fin de ligne d'entrée
(mdoc, man, roff) Les espaces en fin de ligne d'entrée sont presque jamais sémantiquement significatifs — mais dans le cas étrange où ils pourraient l'être, ils sont extrêmement déroutants lors de la révision et de la maintenance des documents.
mauvais style de commentaire
(roff) Les lignes de commentaire commencent par un point, une barre oblique inverse et un guillemet double. L'utilitaire mandoc traite la ligne comme une ligne de commentaire même sans la barre oblique inverse, mais l'omettre pourrait ne pas être portable.

Avertissements relatifs au prologue du document

titre du manuel manquant, utilisation de UNTITLED
(mdoc) Une macro Dt n'a pas d'arguments, ou il n'y a pas de macro Dt avant la première macro non-prologue.
titre du manuel manquant, utilisation de « »

section du manuel manquante, utilisation de « »

section manuelle inconnue

incompatibilité nom de fichier/section
(mdoc, man) Le nom du fichier d'entrée en cours de traitement est connu et son extension de nom de fichier commence par un chiffre non nul, mais la macro Dt ou TH contient un argument section qui commence par un chiffre non nul différent. L'argument section est utilisé tel quel. Envisagez de vérifier si le nom du fichier ou l'argument nécessitent une correction.
date manquante, utilisation de ""
(mdoc, man) Le document a été analysé comme mdoc(7) et il n'a pas de macro Dd, ou la macro Dd n'a pas d'arguments ou seulement des arguments vides ; ou le document a été analysé comme man(7) et il n'a pas de macro TH, ou la macro TH a moins de trois arguments ou son troisième argument est vide.
impossible d'analyser la date, utilisation telle quelle
(mdoc, man) La date fournie dans une macro Dd ou TH ne suit pas le format conventionnel.
date dans le futur, utilisation quand même

macro Os manquante, utilisation de ""

macro de prologue tardive
(mdoc) Une macro Dd ou Os se produit après une macro non-prologue, mais prend quand même effet.
macros de prologue dans le désordre
(mdoc) Les macros de prologue ne sont pas données dans l'ordre conventionnel Dd, Dt, Os. Les trois macros sont utilisées même lorsqu'elles sont données dans un autre ordre.

Avertissements concernant la structure du document

.so est fragile, préférer ln(1)
(roff) L'inclusion de fichiers ne fonctionne que lorsque le programme d'analyse s'exécute avec le répertoire de travail courant correct.
corps du document absent
(mdoc, man) Le corps du document ne contient ni texte ni macros. Un document vide est affiché, composé uniquement d'une ligne d'en-tête et d'une ligne de pied de page.
contenu avant le premier en-tête de section
(mdoc, man) Certaines macros ou du texte précèdent le premier en-tête de section Sh ou SH. Les macros et le texte incriminés sont analysés et ajoutés au niveau supérieur de l'arbre syntaxique, en dehors de tout bloc de section.
première section n'est pas NAME
(mdoc) L'argument de la première macro Sh n'est pas 'NAME'. Cela peut perturber makewhatis(8) et apropos(1).
section NAME sans Nm avant Nd
(mdoc) La section NAME ne contient aucune macro enfant Nm avant la première macro Nd.
section NAME sans description
(mdoc) La section NAME manque de la macro enfant obligatoire Nd.
description pas à la fin de NAME
(mdoc) La section NAME contient une macro enfant Nd, mais d'autres contenus la suivent.
contenu de section NAME incorrect
(mdoc) La section NAME contient du texte brut ou des macros autres que Nm et Nd.
virgule manquante avant le nom
(mdoc) La section NAME contient une macro Nm qui n'est ni la première, ni précédée d'une virgule.
ligne de description manquante, utilisation de ""
(mdoc) La macro Nd manque de l'argument requis. La ligne de titre du manuel se terminera après le tiret.
ligne de description hors de la section NAME
(mdoc) Une macro Nd apparaît en dehors de la section NAME. Les arguments sont imprimés de toute façon et le texte suivant est utilisé pour apropos(1), mais aucun de ces comportements n'est portable.
sections dans le désordre conventionnel
(mdoc) Une section standard apparaît après une autre section qu'elle précède habituellement. Tous les titres de section sont utilisés tels quels, et l'ordre des sections n'est pas modifié.
titre de section dupliqué
(mdoc) Le même titre de section standard apparaît plus d'une fois.
section inattendue
(mdoc) Un en-tête de section standard apparaît dans une section du manuel où il n'est normalement pas utile.
renvoi vers soi-même
(mdoc) Une macro Xr fait référence à un nom et une section correspondant à la section de la page de manuel actuelle et à un nom mentionné dans une macro Nm dans la section NAME ou SYNOPSIS, ou dans une macro Fn ou Fo dans la section SYNOPSIS. Envisagez d'utiliser Nm ou Fn à la place de Xr.
ordre Xr inhabituel
(mdoc) Dans la section SEE ALSO, une macro Xr avec un numéro de section inférieur suit une macro avec un numéro supérieur, ou deux macros Xr faisant référence à la même section sont dans le désordre alphabétique.
ponctuation Xr inhabituelle
(mdoc) Dans la section SEE ALSO, la ponctuation entre deux macros Xr diffère d'une virgule unique, ou il y a une ponctuation finale après la dernière macro Xr.
section AUTHORS sans macro An
(mdoc) Une section AUTHORS ne contient aucune macro An, ou seulement des macros vides. Probablement, des noms d'auteurs manquent de balisage.

Avertissements liés aux macros et à l'imbrication

macro obsolète
(mdoc) Voir le manuel mdoc(7) pour les remplacements.
macro ni appelable ni échappée
(mdoc) Le nom d'une macro qui n'est pas appelable apparaît sur une ligne de macro. Elle est imprimée telle quelle. Si l'intention est de l'appeler, déplacez-la sur sa propre ligne d'entrée ; sinon, échappez-la en la faisant précéder de '\&'.
saut de macro de paragraphe
Dans les documents mdoc(7), cela se produit
  • au début et à la fin des sections et sous-sections
  • juste avant les listes et les affichages non compacts
  • à la fin des éléments des listes non colonnes et non compactes
  • et pour plusieurs macros de paragraphe consécutives.
Dans les documents man(7), cela se produit
  • pour les macros P, PP, et LP vides
  • pour les macros IP n'ayant ni argument de tête ni argument de corps
  • pour br ou sp juste après SH ou SS
déplacement d'une macro de paragraphe hors d'une liste
(mdoc) Un élément de liste dans une liste Bl contient une macro de paragraphe finale. La macro de paragraphe est déplacée après la fin de la liste.
saut de macro sans espace
(mdoc) Une ligne d'entrée commence par une macro Ns, ou l'argument suivant une macro Ns est un délimiteur de fermeture isolé. La macro est ignorée.
blocs mal imbriqués
(mdoc) Si deux blocs s'intersectent, l'un doit contenir complètement l'autre. Sinon, la sortie rendue risque d'être étrange dans n'importe quel format de sortie, et le rendu dans les formats de sortie basés sur SGML sera probablement tout simplement incorrect car de tels langages ne supportent pas du tout les blocs mal imbriqués. Des exemples typiques de blocs mal imbriqués sont ""Ao Bo Ac Bc"" et ""Ao Bq Ac"". Dans ces exemples, Ac interrompt Bo et Bq, respectivement.
imbrications d'affichages non portables
(mdoc) Un affichage Bd, D1, ou Dl se produit imbriqué à l'intérieur d'un autre affichage Bd. Cela fonctionne avec mandoc, mais échoue avec la plupart des autres implémentations.

Avertissements liés au mauvais placement des macros

déplacement du contenu hors de la liste
(mdoc) Un bloc de liste Bl contient du texte ou des macros avant la première macro It. Les enfants fautifs sont déplacés avant le début de la liste.
première macro sur la ligne
Dans une liste Bl -column, une macro Ta apparaît comme première macro sur une ligne, ce qui n'est pas portable.
portée de ligne brisée
(man) Lors de l'analyse de la portée de la ligne suivante de la macro précédente, une autre macro est trouvée qui termine prématurément la précédente. La macro précédente, interrompue, est supprimée de l'arbre d'analyse.

Avertissements liés aux arguments manquants

saut de requête vide
(roff, eqn) Le nom de la macro est manquant dans une requête de définition de macro, ou une instruction de contrôle ou un mot-clé d'opération eqn(7) manque son argument requis.
la requête conditionnelle contrôle une portée vide
(roff) Une requête conditionnelle n'est utile que si l'un des éléments suivants la suit sur la même ligne logique d'entrée :
  • Le mot-clé ‘\{’ pour ouvrir une portée multiligne.
  • Une requête, une macro ou du texte, résultant en une portée d'une seule ligne .
  • La fin immédiate de la ligne logique sans espace blanc intervenant, résultant en une portée de ligne suivante.
Ici, une requête conditionnelle est suivie uniquement d'espaces blancs, et il n'y a pas d'autre contenu sur sa ligne logique d'entrée. Notez qu'il n'est pas important que la ligne logique d'entrée soit divisée sur plusieurs lignes physiques d'entrée à l'aide de caractères de continuation de ligne ‘\’. C'est l'un des rares cas où les espaces blancs de fin sont syntaxiquement significatifs. La requête conditionnelle contrôle une portée contenant uniquement des espaces blancs, elle n'aura donc probablement pas d'effet significatif, sauf qu'elle peut contrôler une clause el suivante.
saut de macro vide
(mdoc) La macro indiquée n'a pas d'arguments et donc aucun effet.
bloc vide
(mdoc, man) Un bloc Bd, Bk, Bl, D1, Dl, MT, RS, ou UR ne contient rien dans son corps et ne produira aucune sortie.
argument vide, utilisation de 0n
(mdoc) La largeur requise est manquante après Bd ou Bl -offset ou -width.
type d'affichage manquant, utilisation de -ragged
(mdoc) La macro Bd est invoquée sans le type d'affichage requis.
le type de liste n'est pas le premier argument
(mdoc) Dans une macro Bl, au moins un autre argument précède l'argument de type. L'utilitaire mandoc gère n'importe quel ordre d'arguments, mais certaines autres implémentations mdoc(7) ne le font pas.
manque -width dans la liste -tag, utilisation de 8n
(mdoc) Chaque macro Bl ayant l'argument -tag requiert -width également.
nom d'utilitaire manquant, utilisation de ""
(mdoc) La macro Ex -std est appelée sans argument avant que Nm n'ait d'abord été appelée avec un argument.
nom de fonction manquant, utilisation de ""
(mdoc) La macro Fo est appelée sans argument. Aucun nom de fonction n'est imprimé.
en-tête vide dans l'élément de liste
(mdoc) Dans une liste Bl -diag, -hang, -inset, -ohang, ou -tag, une macro It manque l'argument requis. L'en-tête de l'élément reste vide.
élément de liste vide
(mdoc) Dans une liste Bl -bullet, -dash, -enum, ou -hyphen, un bloc It est vide. Un élément de liste vide est affiché.
argument manquant, utilisation de la ligne suivante
(mdoc) Une macro It dans une liste Bd -column n'a pas d'arguments. Alors que mandoc utilise le texte ou les macros de la ligne suivante, le cas échéant, pour la cellule, d'autres formateurs peuvent mal formater la liste.
type de police manquant, utilisation de \fR
(mdoc) Une macro Bf n'a pas d'argument. Elle bascule vers la police par défaut.
type de police inconnu, utilisation de \fR
(mdoc) L'argument Bf est invalide. La police par défaut est utilisée à la place.
rien ne suit le préfixe
(mdoc) Une macro Pf n'a pas d'argument, ou un seul argument et aucune macro ne suit sur la même ligne d'entrée. Cela va à l'encontre de son objectif ; en particulier, l'espacement n'est pas supprimé avant le texte ou les macros qui suivent sur la ligne d'entrée suivante.
bloc de référence vide
(mdoc) Une macro Rs est immédiatement suivie d'une macro Re sur la ligne d'entrée suivante. Un tel bloc vide ne produit aucune sortie.
argument de section manquant
(mdoc) Une macro Xr manque son deuxième argument, le numéro de section. Le premier argument, c'est-à-dire le nom, est imprimé, mais sans parenthèses suivantes.
argument -std manquant, ajout
(mdoc) Une macro Ex ou Rv manque l'argument requis -std. L'utilitaire mandoc suppose -std même lorsqu'il n'est pas spécifié, mais d'autres implémentations peuvent ne pas le faire.
chaîne d'option manquante, utilisation de ""
(man) La macro OP est invoquée sans aucun argument. Une paire vide de crochets est affichée.
identificateur de ressource manquant, utilisation de ""
(man) Les macros MT ou UR sont invoquées sans aucun argument. Une paire vide d'angles crochets est affichée.
boîte eqn manquante, utilisation de ""
(eqn) Une marque diacritique ou un opérateur binaire est trouvé, mais il n'y a rien à sa gauche. Une boîte vide est insérée.

Avertissements liés aux mauvais arguments de macro

argument en double

saut d'argument en double

saut de type d'affichage en double

saut de type de liste en double
(mdoc) Une macro Bl a plus d'un argument de type ; le premier est utilisé.
saut de l'argument -width
(mdoc) Une liste Bl -column, -diag, -ohang, -inset, ou -item a un argument -width. Celui-ci n'a aucun effet.
nombre incorrect de cellules
Dans une ligne d'une liste Bl -column, le nombre de tabulations ou de macros Ta est inférieur au nombre attendu d'après la ligne d'en-tête de la liste ou dépasse le nombre attendu de plus d'une unité. Les cellules manquantes restent vides, et toutes les cellules dépassant le nombre de colonnes sont réunies en une seule cellule.
version inconnue d'AT&T UNIX
(mdoc) Une macro At a un argument invalide. Elle est utilisée telle quelle, avec "AT&T UNIX " préfixé.
virgule dans l'argument de fonction
(mdoc) Un argument d'une macro Fa ou Fn contient une virgule ; il devrait probablement être divisé en deux arguments.

Avertissements liés aux parenthèses

parenthèse dans le nom de la fonction
(mdoc) Le premier argument d'une macro Fc ou Fn contient une parenthèse ouvrante ou fermante ; c'est probablement une erreur, les parenthèses sont ajoutées automatiquement.

Avertissements liés aux bibliothèques

nom de bibliothèque inconnu
(mdoc, non disponible sur OpenBSD) Une macro Lb a un argument de nom inconnu et sera rendue comme « bibliothèque « nom » ».

Avertissements liés aux blocs

contenu invalide dans le bloc Rs
(mdoc) Un bloc Rs contient du texte brut ou des macros non-% . Le contenu erroné est laissé dans l'arbre syntaxique. Le formatage peut être médiocre.
argument booléen invalide
(mdoc) Une macro Sm a un argument autre que on ou off. L'argument invalide est déplacé hors de la macro, ce qui laisse la macro vide, provoquant ainsi le basculement du mode d'espacement.

Avertissements liés aux arguments

argument contenant deux échappements de police
(roff) Le deuxième argument d'une requête char contient plus d'une séquence d'échappement de police. Une mauvaise police peut rester active après l'utilisation du caractère.

police inconnue, requête ignorée
(man, tbl) Une requête ft de roff(7) ou un modificateur de mise en page f de tbl(7) a un argument de police inconnu.

Avertissements liés aux caractères

nombre impair de caractères dans la requête
(roff) Une requête tr contient un nombre impair de caractères. Le dernier caractère est mappé au caractère d'espacement.

Avertissements liés au texte brut

ligne vide en mode remplissage, utilisation de .sp
(mdoc) La signification des lignes d'entrée vides n'est bien définie qu'en mode non-remplissage : En mode remplissage, les sauts de ligne du texte d'entrée ne sont pas censés être significatifs. Cependant, pour la compatibilité avec groff, les lignes vides en mode remplissage sont formatées comme des requêtes sp. Pour demander une nouvelle ligne de paragraphe, utilisez Pp au lieu d'une ligne vide.
tabulation dans le texte rempli
(mdoc, man) La signification des caractères de tabulation n'est bien définie qu'en mode non-remplissage : En mode remplissage, les espaces ne sont pas censés être significatifs sur les lignes de texte d'entrée. Par choix dépendant de l'implémentation, les caractères de tabulation sur les lignes de texte sont transmis aux formateurs dans tous les cas. Étant donné que le texte avant la tabulation sera rempli, il est difficile de prédire à quelle position de tabulation la tabulation avancera.
nouvelle phrase, nouvelle ligne
(mdoc) Une nouvelle phrase commence au milieu d'une ligne de texte. Commencez-la sur une nouvelle ligne d'entrée pour aider les formateurs à produire un espacement correct.
séquence d'échappement invalide
(roff) Une séquence d'échappement a un délimiteur d'argument d'ouverture invalide, manque le délimiteur d'argument de fermeture, l'argument est de forme invalide, ou c'est une séquence d'échappement de caractère avec un nom invalide. Si l'argument est incomplet, \* et \n se développent en une chaîne vide, \B en le chiffre '0', et \w en la longueur de l'argument incomplet. Toutes les autres séquences d'échappement invalides sont ignorées.
échappement non défini, affichage littéral
(roff) Dans une séquence d'échappement, le premier caractère après la barre oblique inverse est invalide. Ce caractère est imprimé littéralement, ce qui équivaut à ignorer la barre oblique inverse.
chaîne non définie, utilisation de ""
(roff) Si une chaîne est utilisée sans avoir été définie auparavant, sa valeur est implicitement définie comme une chaîne vide. Cependant, définir explicitement les chaînes avant leur utilisation rend le code plus lisible.

Avertissements liés aux tableaux

ligne tbl commence par un span
(tbl) La première cellule dans une ligne de mise en page de tableau est un span horizontal ('s'). Les données fournies pour cette cellule sont ignorées, et rien n'est imprimé dans la cellule.
colonne tbl commence par un span
(tbl) La première ligne d'une spécification de mise en page de tableau demande un span vertical ('^'). Les données fournies pour cette cellule sont ignorées, et rien n'est imprimé dans la cellule.
ignoré la barre verticale dans la mise en page tbl
(tbl) Une spécification de mise en page de tableau contient plus de deux barres verticales consécutives. Une double barre est imprimée, toutes les barres supplémentaires sont rejetées.

Erreurs liées aux tableaux

caractère non alphabétique dans les options tbl
(tbl) La ligne d'options du tableau contient un caractère autre qu'une lettre, un espace ou une virgule, là où le début d'un nom d'option est attendu. Le caractère est ignoré.
ignoré l'option tbl inconnue
(tbl) La ligne d'options du tableau contient une chaîne de lettres qui ne correspond à aucun nom d'option connu. Le mot est ignoré.
argument d'option tbl manquant
(tbl) Une option de tableau qui nécessite un argument n'est pas suivie d'une parenthèse ouvrante, ou la parenthèse ouvrante est immédiatement suivie d'une parenthèse fermante. L'option est ignorée.
taille d'argument d'option tbl incorrecte
(tbl) Un argument d'option de tableau contient un nombre de caractères invalide. L'option et l'argument sont ignorés.
mise en page tbl vide
(tbl) Une spécification de mise en page de tableau est complètement vide, spécifiant zéro ligne et zéro colonne. Par défaut, une seule colonne alignée à gauche est utilisée.
caractère invalide dans la mise en page tbl
(tbl) Une spécification de mise en page de tableau contient un caractère qui ne peut être interprété comme un caractère clé de mise en page ni comme un modificateur de mise en page, ou un modificateur précède la première clé. Le caractère invalide est rejeté.
parenthèse non appariée dans la mise en page tbl
(tbl) Une spécification de mise en page de tableau contient une parenthèse ouvrante, mais pas de parenthèse fermante correspondante. Le reste de la ligne d'entrée, à partir de la parenthèse, n'a aucun effet.
ignoré l'espacement excessif dans la mise en page tbl
(tbl) Un modificateur d'espacement dans une mise en page de tableau est déraisonnablement grand. L'espacement par défaut de 3n est utilisé à la place.
tbl sans cellules de données
(tbl) Un tableau ne contient aucune cellule de données. Il ne produira probablement aucun résultat.
ignoré les données dans une cellule tbl fusionnée
(tbl) Une cellule de tableau est marquée comme un span horizontal ('s') ou un span vertical ('^') dans la mise en page du tableau, mais elle contient des données. Les données sont ignorées.
ignoré les cellules de données tbl supplémentaires
(tbl) Une ligne de données contient plus de cellules que la ligne de mise en page correspondante. Les données dans les cellules supplémentaires sont ignorées.
bloc de données ouvert à la fin de tbl
(tbl) Un bloc de données est ouvert avec T{, mais jamais fermé avec un T} correspondant. Les lignes de données restantes du tableau sont toutes mises dans une seule cellule, et toutes les cellules restantes restent vides.

Erreurs liées au code roff, mdoc et man

macro de prologue en double
(mdoc) L'une des macros de prologue apparaît plus d'une fois. La dernière occurrence remplace toutes les précédentes.
ignoré la macro de titre tardive
(mdoc) La macro Dt apparaît après la première macro non-prologue. Les formateurs traditionnels ne peuvent pas gérer cela car ils écrivent l'en-tête de page avant d'analyser le corps du document. Bien que cette restriction technique ne s'applique pas à mandoc, la sémantique traditionnelle est préservée. La macro tardive est rejetée, y compris ses arguments.
limite de la pile d'entrée dépassée, boucle infinie ?
(roff) Des limites de récursion explicites sont implémentées pour les fonctionnalités suivantes, afin d'éviter les boucles infinies :
  • l'expansion de séquences d'échappement imbriquées, y compris l'expansion de chaînes et de registres numériques,
  • l'expansion de macros définies par l'utilisateur imbriquées,
  • et l'inclusion de fichiers so.
Lorsqu'une limite est atteinte, la sortie est incorrecte, perdant généralement du contenu, mais l'analyseur peut continuer.
ignoré caractère invalide
(mdoc, man, roff) Le fichier d'entrée contient un octet qui n'est pas un caractère ascii(7) imprimable.
mentionne le numéro du caractère. L'octet fautif est remplacé par un point d'interrogation (‘?’). Envisagez de modifier le fichier d'entrée pour remplacer l'octet par une translittération ASCII du caractère souhaité.
saut macro inconnue
(mdoc, man, roff) Le premier identificateur sur une ligne de requête ou de macro n'est reconnu ni comme une requête roff(7), ni comme une macro définie par l'utilisateur, ni, respectivement, comme une macro mdoc(7) ou man(7). Il peut être mal orthographié ou non pris en charge. La requête ou la macro est ignorée, y compris ses arguments.
saut requête hors macro
(roff) Une requête shift ou return survient en dehors de toute définition de macro et n'a aucun effet.
saut requête non sécurisée
(roff) Un fichier d'entrée a tenté d'exécuter une commande shell ou de lire ou d'écrire un fichier externe. Ces tentatives sont refusées pour des raisons de sécurité.
saut élément hors liste
(mdoc, eqn) Une macro It survient en dehors de toute liste Bl, ou un délimiteur eqn(7) above survient en dehors de toute pile. Il est ignoré, y compris ses arguments.
saut colonne hors liste de colonnes
(mdoc) Une macro Ta survient en dehors de tout bloc Bl -column. Elle est ignorée, y compris ses arguments.
saut fin de bloc non ouvert
(mdoc, man, eqn, tbl, roff) Divers éléments de syntaxe ne peuvent être utilisés que pour fermer explicitement des blocs qui ont été précédemment ouverts. Une macro de fermeture de bloc mdoc(7), une macro man(7) ME, RE ou UE, un délimiteur droit ou une accolade fermante eqn(7), ou la fin d'une équation, d'un tableau ou d'une requête conditionnelle roff(7) est rencontrée, mais aucun bloc correspondant n'est ouvert. La requête ou la macro fautive est ignorée.
moins de blocs RS ouverts, saut
(man) La macro RE est appelée avec un argument, mais moins que le nombre spécifié de blocs RS est ouvert. La macro RE est ignorée.
insertion fin de bloc manquante
(mdoc, tbl) Diverses macros mdoc(7) ainsi que les tableaux nécessitent une fermeture explicite par des macros dédiées. Un bloc qui ne prend pas en charge l'imbrication incorrecte se termine avant que tous ses enfants ne soient correctement fermés. Les nœuds enfants ouverts sont fermés implicitement.
ajout fin de bloc manquante
(mdoc, man, eqn, tbl, roff) À la fin du document, un bloc mdoc(7) explicite, une portée de ligne suivante man(7) ou un bloc MT, RS ou UR, une équation, un tableau, ou une conditionnelle ou un bloc d'ignorance roff(7) est toujours ouvert. Le bloc ouvert est fermé implicitement.
caractère échappé non autorisé dans un nom
(roff) Les identificateurs de macros, de chaînes et de registres sont constitués de caractères ASCII imprimables et non blancs. Les séquences d'échappement et les caractères et chaînes exprimés en termes de celles-ci ne peuvent pas faire partie d'un nom. Le premier argument d'une requête am, as, de, ds, nr, ou rr, ou tout argument d'une requête rm, ou le nom d'une requête ou d'une macro définie par l'utilisateur appelée, est terminé par une séquence d'échappement. Dans les cas de as, ds, et nr, la requête n'a aucun effet. Dans les cas de am, de, rr, et rm, ce qui a été analysé jusqu'à ce point est utilisé comme arguments de la requête, et le reste de la ligne d'entrée est ignoré, y compris la séquence d'échappement. Lors de l'analyse d'une requête ou d'un nom de macro définie par l'utilisateur à appeler, seule la séquence d'échappement est ignorée. Les caractères qui la précèdent sont utilisés comme nom de requête ou de macro, les caractères qui la suivent sont utilisés comme arguments de la requête ou de la macro.
utilisation argument de macro hors macro
(roff) La séquence d'échappement \$ survient en dehors de toute définition de macro et se développe en une chaîne vide.
numéro d'argument non numérique
(roff) L'argument de la séquence d'échappement \$ n'est pas un chiffre ; la séquence d'échappement se développe en une chaîne vide.
NON IMPLÉMENTÉ : Bd -file
(mdoc) Pour des raisons de sécurité, la macro Bd ne prend pas en charge l'argument -file. En demandant l'inclusion d'un fichier sensible, un document malveillant pourrait autrement inciter un utilisateur privilégié à afficher involontairement le fichier à l'écran, révélant ainsi le contenu du fichier aux spectateurs. L'argument est ignoré, y compris le nom de fichier qui le suit.
saut affichage sans arguments
(mdoc) Une macro de bloc Bd n'a pas d'arguments. Le bloc est ignoré, et le contenu du bloc est affiché dans le mode qui était actif avant le bloc.
type de liste manquant, utilisation de -item
(mdoc) Une macro Bl ne spécifie pas le type de liste.
argument non numérique, utilisation de 1
(roff) L'argument d'une requête ce n'est pas un nombre.
argument n'est pas un caractère
(roff) Le premier argument d'une requête char n'est ni un caractère ASCII unique, ni une séquence d'échappement d'un seul caractère. La requête est ignorée, y compris tous ses arguments.
nom de manuel manquant, utilisation de ""
(mdoc) Le premier appel à Nm, ou tout appel dans la section NAME, manque l'argument requis.
appel système uname(3) échoué, utilisation de UNKNOWN
(mdoc) La macro Os est appelée sans arguments, et l'appel système uname(3) a échoué. Comme solution de contournement, mandoc peut être compilé avec -DOSNAME="\"chaîne\"".
spécificateur standard inconnu
(mdoc) Une macro St a un argument inconnu et est ignorée.
saut requête sans argument numérique
(roff, eqn) Une requête it ou une instruction size ou gsize eqn(7) a un argument non numérique ou négatif ou aucun argument du tout. La requête ou l'instruction invalide est ignorée.
shift excessif
(roff) L'argument d'une requête shift est supérieur au nombre d'arguments de la macro actuellement exécutée. Tous les arguments de macro sont supprimés et \n(.$ est mis à zéro.
NON IMPLÉMENTÉ : .so avec chemin absolu ou ".."
(roff) Pour des raisons de sécurité, mandoc n'autorise les requêtes d'inclusion de fichier so qu'avec des chemins relatifs et uniquement sans monter vers un répertoire parent. En demandant l'inclusion d'un fichier sensible, un document malveillant pourrait autrement inciter un utilisateur privilégié à afficher involontairement le fichier à l'écran, révélant ainsi le contenu du fichier aux spectateurs. mandoc affiche uniquement le chemin tel qu'il apparaît derrière so.
requête .so échouée
(roff) Le traitement d'une requête so nécessite la lecture d'un fichier externe, mais le fichier n'a pas pu être ouvert. mandoc affiche uniquement le chemin tel qu'il apparaît derrière so.
saut de tous les arguments
(mdoc, man, eqn, roff) Une macro mdoc(7) Bt, Ed, Ef, Ek, El, Lp, Pp, Re, Rs, ou Ud, une macro It dans une liste qui ne prend pas en charge les en-têtes d'éléments, une macro man(7) LP, P, ou PP, une macro eqn(7) EQ ou EN, ou une requête roff(7) br, fi, ou nf ou une requête de fermeture de bloc ‘..’ est appelée avec au moins un argument. Tous les arguments sont ignorés.
saut arguments excessifs
(mdoc, man, roff) Une macro ou une requête est
invoked with too many arguments:
  • Fo, MT, PD, RS, UR, ft, or sp avec plus d'un argument
  • An avec un autre argument après -split ou -nosplit
  • RE avec plus d'un argument ou avec un argument non entier
  • OP ou une requête de la famille de avec plus de deux arguments
  • Dt avec plus de trois arguments
  • TH avec plus de cinq arguments
  • Bd, Bk, ou Bl avec des arguments invalides
Les arguments excédentaires sont ignorés.

Fonctionnalités non prises en charge

input trop grand
(mdoc, man) Actuellement, mandoc ne peut pas traiter les fichiers d'entrée plus grands que sa limite de taille arbitraire de 2^31 octets (2 Gigaoctets). Comme les manuels utiles sont toujours petits, ce n'est pas un problème en pratique. L'analyse est abandonnée dès que la condition est détectée.
caractère de contrôle non pris en charge
(roff) Un caractère de contrôle ASCII pris en charge par d'autres implémentations roff(7) mais pas par mandoc a été trouvé dans un fichier d'entrée. Il est remplacé par un point d'interrogation.
séquence d'échappement non prise en charge
(roff) Un fichier d'entrée contient une séquence d'échappement prise en charge par GNU troff ou Heirloom troff mais pas par mandoc, et il est probable que cela cause une perte d'information ou un reformatage considérable.
requête roff non prise en charge
(roff) Un fichier d'entrée contient une requête roff(7) prise en charge par GNU troff ou Heirloom troff mais pas par mandoc, et il est probable que cela cause une perte d'information ou un reformatage considérable.
option eqn dans tbl
(eqn, tbl) La ligne d'options d'un tableau définit des délimiteurs d'équation. Tout code source d'équation contenu dans le tableau sera imprimé sans formatage.
modificateur de mise en page de tableau non pris en charge
(tbl) Une spécification de mise en page de tableau contient un modificateur ‘m’. Le modificateur est jeté.
ignorance d'une macro dans un tableau
(tbl, mdoc, man) Un tableau contient une invocation d'une macro mdoc(7) ou man(7) ou d'une macro non définie. La macro est ignorée et ses arguments sont traités comme s'ils étaient une ligne de texte.
saut de tbl en mode -Tman
(mdoc, tbl) Un fichier d'entrée contient la macro TS. Ce message n'est généré qu'en mode de sortie -T man, où l'entrée tbl(7) n'est pas prise en charge.
saut de eqn en mode -Tman
(mdoc, eqn) Un fichier d'entrée contient la macro EQ. Ce message n'est généré qu'en mode de sortie -T man, où l'entrée eqn(7) n'est pas prise en charge.

Arguments de ligne de commande incorrects

argument de ligne de commande incorrect
L'argument suivant l'une des options de ligne de commande -IKMmOTW est invalide, ou un fichier donné comme argument de ligne de commande ne peut pas être ouvert.
argument de ligne de commande dupliqué
L'option de ligne de commande -I a été spécifiée deux fois.
l'option a une valeur superflue
Un argument de l'option -O a une valeur mais n'en accepte pas.
valeur d'option manquante
Un argument de l'option -O n'a pas d'argument mais en requiert un.
valeur d'option incorrecte
Un argument de l'option -O indent ou width a une valeur invalide.
valeur d'option dupliquée
La même option -O est spécifiée plus d'une fois.
balise inexistante
L'option -O tag a été spécifiée mais la balise n'a été trouvée dans aucune des pages de manuel affichées.
-Tmarkdown non pris en charge pour les entrées man(7)
(man) L'option -T markdown a été spécifiée mais un fichier d'entrée utilise le langage man(7). Aucune sortie n'est produite pour ce fichier d'entrée.
