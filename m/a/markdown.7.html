MARKDOWN(7) Manuel d'informations diverses MARKDOWN(7)

NOM

Markdown — La syntaxe de formatage de texte Markdown

DESCRIPTION

Philosophie

Markdown est conçu pour être aussi lisible et aussi facile à écrire que possible.

Cependant, la lisibilité est la priorité absolue. Un document formaté en Markdown devrait pouvoir être publié tel quel, en texte brut, sans donner l'impression d'avoir été marqué avec des balises ou des instructions de formatage. Bien que la syntaxe de Markdown ait été influencée par plusieurs filtres existants de texte vers HTML -- y compris Setext, atx, Textile, reStructuredText, Grutatext, et EtText -- la source d'inspiration la plus importante pour la syntaxe de Markdown est le format des courriels en texte brut.

À cette fin, la syntaxe de Markdown est entièrement composée de caractères de ponctuation, et ces caractères ont été choisis avec soin pour ressembler à ce qu'ils signifient. Par exemple, les astérisques autour d'un mot ressemblent effectivement à de l'*emphase*. Les listes Markdown ressemblent à, eh bien, des listes. Même les citations ressemblent à des passages de texte cités, si vous avez déjà utilisé le courrier électronique.

HTML en ligne

La syntaxe de Markdown est destinée à un seul objectif : être utilisée comme format pour écrire pour le web.

Markdown n'est pas un remplacement pour HTML, ni même proche de cela. Sa syntaxe est très petite, correspondant seulement à un sous-ensemble très restreint de balises HTML. L'idée n'est pas de créer une syntaxe qui facilite l'insertion de balises HTML. À mon avis, les balises HTML sont déjà faciles à insérer. L'idée de Markdown est de rendre la prose facile à lire, écrire et éditer. HTML est un format de publication ; Markdown est un format d'écriture. Ainsi, la syntaxe de formatage de Markdown ne traite que les problèmes qui peuvent être transmis en texte brut.

Pour toute balise non couverte par la syntaxe de Markdown, vous utilisez simplement le HTML lui-même. Il n'est pas nécessaire de la préfixer ou de la délimiter pour indiquer que vous passez de Markdown à HTML ; vous utilisez simplement les balises.

Les seules restrictions sont que les éléments HTML de niveau bloc -- par exemple <div>, <table>, <pre>, <p>, etc. -- doivent être séparés du contenu environnant par des lignes vides, et les balises de début et de fin du bloc ne doivent pas être indentées avec des tabulations ou des espaces. Markdown est suffisamment intelligent pour ne pas ajouter de balises <p> supplémentaires (indésirables) autour des balises HTML de niveau bloc.

Par exemple, pour ajouter un tableau HTML à un article Markdown :

Ceci est un paragraphe normal.

<table>
    <tr>
        <td>Foo</td>
    </tr>
</table>

Ceci est un autre paragraphe normal.

Notez que la syntaxe de formatage Markdown n'est pas traitée à l'intérieur des balises HTML de niveau bloc. Par exemple, vous ne pouvez pas utiliser l'emphase de style Markdown *emphase* à l'intérieur d'un bloc HTML.

Les balises HTML de niveau span -- par exemple <span>, <cite>, ou <del> -- peuvent être utilisées n'importe où dans un paragraphe Markdown, un élément de liste ou un en-tête. Si vous le souhaitez, vous pouvez même utiliser des balises HTML à la place du formatage Markdown ; par exemple, si vous préférez utiliser les balises HTML <a> ou <img> à la place de la syntaxe de lien ou d'image Markdown, allez-y.

Contrairement aux balises HTML de niveau bloc, la syntaxe Markdown *est* traitée à l'intérieur des balises de niveau span.

Échappement automatique pour les caractères spéciaux

En HTML, deux caractères exigent un traitement spécial : `<` et `&`. Les crochets gauche sont utilisés pour démarrer les balises ; les ampersands sont utilisés pour désigner les entités HTML. Si vous voulez les utiliser comme caractères littéraux, vous devez les échapper en tant qu'entités, par exemple `&lt;`, et `&amp;`.

Les ampersands en particulier sont un casse-tête pour les auteurs web. Si vous voulez écrire à propos de 'AT&T', vous devez écrire '`AT&amp;T`'. Vous devez même échapper les ampersands dans les URL. Ainsi, si vous voulez créer un lien vers :

http://images.google.com/images?num=30&q=larry+bird

vous devez encoder l'URL comme :

http://images.google.com/images?num=30&amp;q=larry+bird

dans l'attribut `href` de votre balise d'ancrage. Il va sans dire qu'il est facile d'oublier cela, et c'est probablement la source la plus courante d'erreurs de validation HTML dans les sites web autrement bien marqués.

Markdown vous permet d'utiliser ces caractères naturellement, en prenant en charge tout l'échappement nécessaire pour vous. Si vous utilisez un ampersand dans le cadre d'une entité HTML, il reste inchangé ; sinon, il sera traduit en `&amp;`.

Donc, si vous voulez inclure un symbole de copyright dans votre article, vous pouvez écrire :

&copy;

et Markdown le laissera tel quel. Mais si vous écrivez :

AT&T

Markdown le traduira en :

AT&amp;T

De même, comme Markdown prend en charge le HTML en ligne, si vous utilisez des crochets comme délimiteurs pour les balises HTML, Markdown les traitera comme telles. Mais si vous écrivez :

4 < 5

Markdown traduira cela en :

4 &amp;lt; 5

Cependant, à l'intérieur des portées de code et des blocs de code Markdown, les crochets et les ampersands sont *toujours* encodés automatiquement. Cela rend facile l'utilisation de Markdown pour écrire sur du code HTML. (Contrairement au HTML brut, qui est un format terrible pour écrire sur la syntaxe HTML, car chaque `<` et `&` de votre code d'exemple doit être échappé.)

Éléments de bloc

Paragraphes et sauts de ligne

Un paragraphe est simplement une ou plusieurs lignes de texte consécutives, séparées par une ou plusieurs lignes vides. (Une ligne vide est toute ligne qui ressemble à une ligne vide -- une ligne ne contenant que des espaces ou des tabulations est considérée comme vide.) Les paragraphes normaux ne doivent pas être indentés avec des espaces ou des tabulations.

L'implication de la règle "une ou plusieurs lignes de texte consécutives" est que Markdown prend en charge les paragraphes Dtext "à retour à la ligne forcé". Cela diffère significativement de la plupart des autres formateurs de texte en HTML (y compris l'option "Convert Line Breaks" de Movable Type) qui traduisent chaque caractère de saut de ligne dans un paragraphe en une balise `
`.

Lorsque vous *voulez* insérer une balise de saut de ligne `
` en utilisant Markdown, terminez une ligne par deux espaces ou plus, puis appuyez sur retour.

Oui, cela demande un peu plus d'effort pour créer un `
`, mais une règle simpliste "chaque saut de ligne est un `
`" ne fonctionnerait pas pour Markdown. Les citations de bloc de style email de Markdown et les éléments de liste multi-paragraphes fonctionnent mieux -- et ont une meilleure apparence -- lorsque vous les formatez avec des retours à la ligne forcés.

En-têtes

Markdown prend en charge deux styles d'en-têtes, Setext et atx.

Les en-têtes de style Setext sont "soulignés" en utilisant des signes égaux (pour les en-têtes de premier niveau) et des tirets (pour les en-têtes de deuxième niveau). Par exemple :

Ceci est un H1
=============

Ceci est un H2
-------------

N'importe quel nombre de `=` ou de `-` en soulignement fonctionnera.

Les en-têtes de style Atx utilisent 1 à 6 caractères dièse au début de la ligne, correspondant aux niveaux d'en-tête 1 à 6. Par exemple :

# Ceci est un H1

## Ceci est un H2

###### Ceci est un H6

Optionnellement, vous pouvez

y "fermer" des en-têtes de style ATX. Ceci est purement cosmétique -- vous pouvez l'utiliser si vous pensez que cela rend mieux. Les crochets fermants n'ont même pas besoin de correspondre au nombre de crochets utilisés pour ouvrir l'en-tête. (Le nombre de crochets ouvrants détermine le niveau de l'en-tête.) :

# Ceci est un H1 #

## Ceci est un H2 ##

### Ceci est un H3 ######

Citations (Blockquotes)

Markdown utilise des caractères de style e-mail `>` pour les citations. Si vous êtes familier avec la citation de passages de texte dans un e-mail, alors vous savez comment créer une citation en Markdown. Ça rend mieux si vous retournez à la ligne manuellement et mettez un `>` avant chaque ligne :

> Ceci est une citation avec deux paragraphes. Lorem ipsum
> dolor sit amet, consectetuer adipiscing elit. Aliquam
> hendrerit mi posuere lectus. Vestibulum enim wisi,
> viverra nec, fringilla in, laoreet vitae, risus.
>
> Donec sit amet nisl. Aliquam semper ipsum sit amet
> velit. Suspendisse id sem consectetuer libero luctus
> adipiscing.

Markdown vous permet d'être paresseux et de ne mettre le `>` qu'avant la première ligne d'un paragraphe retourné manuellement :

> Ceci est une citation avec deux paragraphes. Lorem ipsum
dolor sit amet, consectetuer adipiscing elit. Aliquam
hendrerit mi posuere lectus. Vestibulum enim wisi,
viverra nec, fringilla in, laoreet vitae, risus.

> Donec sit amet nisl. Aliquam semper ipsum sit amet
 velit. Suspendisse id sem consectetuer libero luctus
  adipiscing.

Les citations peuvent être imbriquées (c'est-à-dire une citation dans une citation) en ajoutant des niveaux supplémentaires de `>` :

> Ceci est le premier niveau de citation.
>
> > Ceci est une citation imbriquée.
>
> Retour au premier niveau.

Les citations peuvent contenir d'autres éléments Markdown, y compris des en-têtes, des listes et des blocs de code :

> ## Ceci est un en-tête.
>
> 1.   Ceci est le premier élément de liste.
> 2.   Ceci est le deuxième élément de liste.
>
> Voici un exemple de code :
>
>     return shell_exec("echo $input | $markdown_script");

N'importe quel éditeur de texte décent devrait faciliter la citation style e-mail. Par exemple, avec BBEdit, vous pouvez sélectionner du texte et choisir "Augmenter le niveau de citation" dans le menu Texte.

Listes

Markdown prend en charge les listes ordonnées (numérotées) et non ordonnées (à puces).

Les listes non ordonnées utilisent des astérisques, des plus et des tirets — de manière interchangeable — comme marqueurs de liste :

*   Rouge
*   Vert
*   Bleu

est équivalent à :

+   Rouge
+   Vert
+   Bleu

et :

-   Rouge
-   Vert
-   Bleu

Les listes ordonnées utilisent des nombres suivis de points :

1.  Oiseau
2.  McHale
3.  Parish

Il est important de noter que les nombres réels que vous utilisez pour marquer la liste n'ont aucun effet sur la sortie HTML que Markdown produit. Le HTML que Markdown produit à partir de la liste ci-dessus est :

<ol>
<li>Bird</li>
<li>McHale</li>
<li>Parish</li>
</ol>

Si vous écriviez plutôt la liste en Markdown comme ceci :

1.  Oiseau
1.  McHale
1.  Parish

ou même :

3. Oiseau
1. McHale
8. Parish

vous obtiendriez exactement la même sortie HTML. L'idée est que, si vous le souhaitez, vous pouvez utiliser des nombres ordinaux dans vos listes Markdown ordonnées, de sorte que les nombres dans votre source correspondent aux nombres dans votre HTML publié. Mais si vous voulez être paresseux, vous n'êtes pas obligé.

Si vous utilisez une numérotation de liste paresseuse, vous devriez quand même commencer la liste avec le nombre 1. À l'avenir, Markdown pourrait prendre en charge le démarrage des listes ordonnées à un nombre arbitraire.

Les marqueurs de liste commencent généralement à la marge gauche, mais peuvent être indentés jusqu'à trois espaces. Les marqueurs de liste doivent être suivis d'un ou plusieurs espaces ou d'une tabulation.

Pour que les listes soient belles, vous pouvez envelopper les éléments avec des retraits suspendus :

    *   Lorem ipsum dolor sit amet, consectetuer adipiscing
	elit. Aliquam hendrerit mi posuere lectus. Vestibulum
	enim wisi, viverra nec, fringilla in, laoreet vitae,
	risus.
    *   Donec sit amet nisl. Aliquam semper ipsum sit amet
	velit. Suspendisse id sem consectetuer libero luctus
	adipiscing.

Mais si vous voulez être paresseux, vous n'êtes pas obligé :

*   Lorem ipsum dolor sit amet, consectetuer adipiscing
elit. Aliquam hendrerit mi posuere lectus. Vestibulum
enim wisi, viverra nec, fringilla in, laoreet vitae,
risus.
*   Donec sit amet nisl. Aliquam semper ipsum sit amet
velit. Suspendisse id sem consectetuer libero luctus
adipiscing.

Si les éléments de liste sont séparés par des lignes vides, Markdown enveloppera les éléments dans des balises `<p>` dans la sortie HTML. Par exemple, cette entrée :

*   Oiseau
*   Magie

deviendra :

<ul>
<li>Bird</li>
<li>Magic</li>
</ul>

Mais ceci :

*   Oiseau

*   Magie

deviendra :

<ul>
<li><p>Bird</p></li>
<li><p>Magic</p></li>
</ul>

Les éléments de liste peuvent être constitués de plusieurs paragraphes. Chaque paragraphe suivant dans un élément de liste doit être indenté de 4 espaces ou d'une tabulation :

    1.  Ceci est un élément de liste avec deux paragraphes. Lorem ipsum
	dolor sit amet, consectetuer adipiscing elit. Aliquam
	hendrerit mi posuere lectus.

        Vestibulum enim wisi, viverra nec, fringilla in,
	laoreet vitae, risus. Donec sit amet nisl. Aliquam
	semper ipsum sit amet velit.

    2.  Suspendisse id sem consectetuer libero luctus
	adipiscing.

Cela rend bien si vous indentez chaque ligne des paragraphes suivants, mais là encore, Markdown vous permettra d'être paresseux :

    *   Ceci est un élément de liste avec deux paragraphes.

        Ceci est le deuxième paragraphe de l'élément de liste.
	Vous n'êtes tenu d'indenter que la première ligne. Lorem
	ipsum dolor sit amet, consectetuer adipiscing elit.

    *   Un autre élément dans la même liste.

Pour placer une citation à l'intérieur d'un élément de liste, les délimiteurs `>` de la citation doivent être indentés :

*   Un élément de liste avec une citation :

    > Ceci est une citation
    > à l'intérieur d'un élément de liste.

Pour placer un bloc de code à l'intérieur d'un élément de liste, le bloc de code doit être indenté *deux fois* — 8 espaces ou deux tabulations :

*   Un élément de liste avec un bloc de code :

        <code goes here>

Il convient de noter qu'il est possible de déclencher accidentellement une liste ordonnée, en écrivant quelque chose comme ceci :

1986. Quelle excellente saison.

En d'autres termes, une séquence *chiffre-point-espace* au début d'une ligne. Pour éviter cela, vous pouvez échapper le point avec une barre oblique inverse :

1986\. Quelle excellente saison.

Blocs de Code

Les blocs de code préformatés sont utilisés pour écrire sur la programmation ou le code source de balisage. Plutôt que de former des paragraphes normaux, les lignes d'un bloc de code sont interprétées littéralement. Markdown enveloppe un bloc de code dans des balises `<pre>` et `<code>`.

Pour produire un bloc de code en Markdown, il suffit d'indenter chaque ligne du bloc d'au moins 4 espaces ou 1 tabulation. Par exemple, étant donné cette entrée :

Ceci est un paragraphe normal :

    Ceci est un bloc de code.

Markdown générera :

<p>Ceci est un paragraphe normal :</p>

<pre><code>Ceci est un bloc de code.
</code></pre>

Un niveau d'indentation — 4 espaces ou 1 tabulation — est retiré de chaque ligne du bloc de code. Par exemple, ceci :

Voici un exemple d'AppleScript :

    tell application "Foo"
        beep
    end tell

deviendra :

<p>Voici un exemple d'AppleScript :</p>

<pre><code>tell application "Foo"
    beep
end tell
</code></pre>

Un bloc de code continue jusqu'à ce qu'il atteigne une ligne qui n'est pas indentée (ou la fin de l'article).

À l'intérieur d'un bloc de code, les esperluettes (`&`) et les chevrons (`<` et `>`) sont automatiquement convertis en entités HTML. Ceci rend très facile l'inclusion de code source HTML d'exemple en utilisant Markdown — il suffit de le coller et de l'indenter, et Markdown s'occupera du casse-tête de l'encodage des esperluettes et des chevrons. Par exemple, ceci :

<div class="footer">
    &copy; 2004 Foo Corporation
</div>

deviendra :

<pre><code>&lt;div class="footer"&gt;
    &amp;copy; 2004 Foo Corporation
&lt;/div&gt;
</code></pre>

La syntaxe Markdown normale n'est pas traitée à l'intérieur des blocs de code. Par exemple, les astérisques sont juste des astérisques littéraux dans un bloc de code. Ceci signifie qu'il est également facile d'utiliser Markdown pour écrire sur la syntaxe de Markdown elle-même.

Règles Horizontales

Vous pouvez produire une balise de règle horizontale (`<hr />`) en plaçant trois ou plusieurs tirets, astérisques ou underscores sur une ligne seuls. Si vous le souhaitez, vous pouvez utiliser des espaces entre les tirets ou les astérisques. Chacune des lignes suivantes produira une règle horizontale :

* * *

***

*****

- - -

---------------------------------------

Éléments de Portée (Span Elements)

Liens

Markdown prend en charge deux styles de liens : inline et reference.

Dans les deux styles, le texte du lien est délimité par des [crochets].

Liens

Markdown permet de créer des liens en utilisant deux styles : inline et par référence.

Les liens inline ressemblent à ceci :

Ceci est un lien inline [d'exemple](http://example.com/ "Titre Facultatif").

[Ce lien](http://example.net/) n'a pas d'attribut titre.

Ce qui produira :

<p>Ceci est un lien inline <a href="http://example.com/" title="Titre Facultatif">d'exemple</a>.</p>

<p><a href="http://example.net/">Ce lien</a> n'a pas d'attribut titre.</p>

Si vous faites référence à une ressource locale sur le même serveur, vous pouvez utiliser des chemins relatifs :

Voir ma page [À propos](/about/) pour les détails.

Les liens par référence utilisent un second jeu de crochets, dans lequel vous placez une étiquette de votre choix pour identifier le lien :

Ceci est un lien par référence [d'exemple][id].

Vous pouvez utiliser un espace facultatif pour séparer les jeux de crochets :

Ceci est un lien par référence [d'exemple] [id].

Ensuite, n'importe où dans le document, définissez votre étiquette de lien comme ceci, sur une ligne séparée :

[id]: http://example.com/  "Titre Facultatif Ici"

C'est-à-dire :

  • Des crochets contenant l'identifiant du lien (facultativement indentés à partir de la marge gauche avec jusqu'à trois espaces) ;
  • suivis de deux-points ;
  • suivis d'un ou plusieurs espaces (ou tabulations) ;
  • suivis de l'URL du lien ;
  • facultativement suivis d'un attribut titre pour le lien, entouré de guillemets doubles ou simples, ou entouré de parenthèses.

Les trois définitions de lien suivantes sont équivalentes :

[foo]: http://example.com/  "Titre Facultatif Ici"
[foo]: http://example.com/  'Titre Facultatif Ici'
[foo]: http://example.com/  (Titre Facultatif Ici)

Note : Il existe un bug connu dans Markdown.pl 1.0.1 qui empêche l'utilisation d'apostrophes pour délimiter les titres de liens.

L'URL du lien peut, facultativement, être entourée d'accolades :

[id]: <http://example.com/>  "Titre Facultatif Ici"

Vous pouvez placer l'attribut titre sur la ligne suivante et utiliser des espaces ou tabulations supplémentaires pour le rembourrage, ce qui a tendance à mieux paraître avec des URL plus longues :

[id]: http://example.com/chemin/long/vers/la/ressource
    "Titre Facultatif Ici"

Les définitions de lien ne sont utilisées que pour créer des liens lors du traitement Markdown et sont supprimées de votre document dans la sortie HTML.

Les noms des définitions de lien peuvent contenir des lettres, des chiffres, des espaces et de la ponctuation — mais ils ne sont *pas* sensibles à la casse. Par exemple, ces deux liens :

[texte du lien][a]
[texte du lien][A]

sont équivalents.

Le raccourci de nom de lien implicite vous permet d'omettre le nom du lien, auquel cas le texte du lien lui-même est utilisé comme nom. Utilisez simplement un ensemble vide de crochets — par exemple, pour lier le mot « Google » au site Web google.com, vous pouvez simplement écrire :

[Google][]

Puis définissez le lien :

[Google]: http://google.com/

Étant donné que les noms de lien peuvent contenir des espaces, ce raccourci fonctionne même pour plusieurs mots dans le texte du lien :

Visitez [Daring Fireball][] pour plus d'informations.

Puis définissez le lien :

[Daring Fireball]: http://daringfireball.net/

Les définitions de lien peuvent être placées n'importe où dans votre document Markdown. J'ai tendance à les placer immédiatement après chaque paragraphe dans lequel elles sont utilisées, mais si vous le souhaitez, vous pouvez les placer toutes à la fin de votre document, un peu comme des notes de bas de page.

Voici un exemple de liens par référence en action :

J'obtiens 10 fois plus de trafic de [Google] [1] que de
[Yahoo] [2] ou [MSN] [3].

  [1]: http://google.com/        "Google"
  [2]: http://search.yahoo.com/  "Yahoo Search"
  [3]: http://search.msn.com/    "MSN Search"

En utilisant le raccourci de nom de lien implicite, vous pourriez plutôt écrire :

J'obtiens 10 fois plus de trafic de [Google][] que de
[Yahoo][] ou [MSN][].

  [google]: http://google.com/        "Google"
  [yahoo]:  http://search.yahoo.com/  "Yahoo Search"
  [msn]:    http://search.msn.com/    "MSN Search"

Les deux exemples ci-dessus produiront la sortie HTML suivante :

<p>J'obtiens 10 fois plus de trafic de <a href="http://google.com/"
title="Google">Google</a> que de
<a href="http://search.yahoo.com/" title="Yahoo Search">Yahoo</a>
ou
<a href="http://search.msn.com/" title="MSN Search">MSN</a>.</p>

Pour comparaison, voici le même paragraphe écrit en utilisant le style de lien inline de Markdown :

J'obtiens 10 fois plus de trafic de
[Google](http://google.com/ "Google") que de
[Yahoo](http://search.yahoo.com/ "Yahoo Search") ou
[MSN](http://search.msn.com/ "MSN Search").

L'intérêt des liens par référence n'est pas qu'ils sont plus faciles à écrire. L'intérêt est qu'avec les liens par référence, la source de votre document est beaucoup plus lisible. Comparez les exemples ci-dessus : en utilisant des liens par référence, le paragraphe lui-même ne fait que 81 caractères ; avec des liens de style inline, il fait 176 caractères ; et en HTML brut, il fait 234 caractères. Dans le HTML brut, il y a plus de balisage que de texte.

Avec les liens par référence de Markdown, un document source ressemble beaucoup plus au résultat final, tel qu'il est rendu dans un navigateur. En vous permettant de déplacer les métadonnées relatives au balisage hors du paragraphe, vous pouvez ajouter des liens sans interrompre le flux narratif de votre prose.

Emphase

Markdown traite les astérisques (`*`) et les tirets bas (`_`) comme des indicateurs d'emphase. Le texte entouré d'un seul `*` ou `_` sera entouré d'une balise HTML `<em>` ; les doubles `*` ou `_` seront entourés d'une balise HTML `<strong>`. Par exemple, cette entrée :

*astérisques simples*

_tirets bas simples_

**doubles astérisques**

__doubles tirets bas__

produira :

<em>astérisques simples</em>

<em>tirets bas simples</em>

<strong>doubles astérisques</strong>

<strong>doubles tirets bas</strong>

Vous pouvez utiliser le style que vous préférez ; la seule restriction est que le même caractère doit être utilisé pour ouvrir et fermer une plage d'emphase.

L'emphase peut être utilisée au milieu d'un mot :

incroyable

Mais si vous entourez un `*` ou un `_` d'espaces, il sera traité comme un astérisque ou un tiret bas littéral.

Pour produire un astérisque ou un tiret bas littéral à un endroit où il serait autrement utilisé comme délimiteur d'emphase, vous pouvez l'échapper avec une barre oblique inverse :

\*ce texte est entouré d'astérisques littéraux\*

Code

Pour indiquer une plage de code, entourez-la de guillemets accentués (`` ` ``). Contrairement à un bloc de code pré-formaté, une plage de code indique du code à l'intérieur d'un paragraphe normal. Par exemple :

Utilisez la fonction `printf()`.

produira :

<p>Utilisez la fonction <code>printf()</code>.</p>

Pour inclure un caractère accent grave littéral dans une plage de code, vous pouvez utiliser plusieurs accents graves comme délimiteurs d'ouverture et de fermeture :

``Il y a un accent grave littéral (`) ici.``

ce qui produira ceci :

<p><code>Il y a un accent grave littéral (`) ici.</code></p>

Les délimiteurs accentués entourant une plage de code peuvent inclure des espaces — un après l'ouverture, un avant la fermeture. Cela vous permet de placer des caractères accentués littéraux au début ou à la fin d'une plage de code :

Un seul accent grave dans une plage de code : `` ` ``

Une chaîne délimitée par des accents graves dans une plage de code : `` `foo` ``

produira :

<p>Un seul accent grave dans une plage de code : <code>`</code></p>

<p>Une chaîne délimitée par des accents graves dans une plage de code : <code>`foo`</code></p>

Avec une plage de code, les esperluettes et les crochets sont automatiquement encodés en entités HTML, ce qui facilite l'inclusion d'exemples de balises HTML. Markdown transformera ceci :

Merci de ne pas utiliser de balises `<blink>`.

en :

<p>Merci de ne pas utiliser de balises <code>&lt;blink&gt;</code>.</p>

Vous pouvez écrire ceci :

`&#8212;` est l'équivalent encodé en décimal de `&mdash;`.

pour produire :

<p><code>&amp;#8212;</code> est l'équivalent encodé en
décimal de <code>&amp;mdash;</code>.</p>

Images

Il est certes assez difficile de concevoir une syntaxe « naturelle » pour placer des images dans un format de texte brut.

Markdown utilise une syntaxe d'image qui est destinée à ressembler à la syntaxe des liens, permettant deux styles : inline et par référence.

La syntaxe d'image inline ressemble à ceci :

![Texte alternatif](/chemin/vers/img.jpg)

![Texte alternatif](/chemin/vers/img.jpg =TailleFacultative "TitreFacultatif")

C'est-à-dire :

  • Un point d'exclamation : `!` ;
  • suivi d'un ensemble de crochets, contenant le texte de l'attribut `alt` pour l'image ;
  • suivi d'un ensemble de parenthèses, contenant l'URL ou le chemin vers l'image, un attribut `taille` facultatif (au format largeur x hauteur) précédé d'un `=`, et un attribut `titre` facultatif entouré de guillemets doubles ou simples.
  • citations.

La syntaxe des références d'images ressemble à ceci :

![Texte alternatif][id]

Où « id » est le nom d'une référence d'image définie. Les références d'images sont définies en utilisant une syntaxe identique à celle des références de liens :

[id]: url/vers/image  =Taille facultative « Titre facultatif »

Divers

Liens automatiques

Markdown prend en charge un style de raccourci pour créer des liens « automatiques » pour les URL et les adresses e-mail : il suffit d'entourer l'URL ou l'adresse e-mail avec des crochets. Ce qui signifie que si vous voulez afficher le texte réel d'une URL ou d'une adresse e-mail, et en faire également un lien cliquable, vous pouvez le faire ainsi :

<http://example.com/>

Markdown transformera ceci en :

<a href="http://example.com/">http://example.com/</a>

Les liens automatiques pour les adresses e-mail fonctionnent de manière similaire, à la différence que Markdown effectuera également un peu d'encodage aléatoire d'entités décimales et hexadécimales pour aider à masquer votre adresse des robots de collecte d'adresses e-mail. Par exemple, Markdown transformera ceci :

<address@example.com>

en quelque chose comme ceci :

<a href="&#x6D;&#x61;i&#x6C;&#x74;&#x6F;:&#x61;&#x64;&#x64;&#x72;&#x65;
&#115;&#115;&#64;&#101;&#120;&#x61;&#109;&#x70;&#x6C;e&#x2E;&#99;&#111;
&#109;">&#x61;&#x64;&#x64;&#x72;&#x65;&#115;&#115;&#64;&#101;&#120;&#x61;
&#109;&#x70;&#x6C;e&#x2E;&#99;&#111;&#109;</a>

ce qui sera rendu dans un navigateur comme un lien cliquable vers « address@example.com ».

(Ce type de subterfuge d'encodage d'entités trompera en effet bon nombre, sinon la plupart, des robots de collecte d'adresses, mais cela ne les trompera certainement pas tous. C'est mieux que rien, mais une adresse publiée de cette manière commencera probablement à recevoir du spam.)

Échappements par barre oblique inverse

Markdown permet d'utiliser des échappements par barre oblique inverse pour générer des caractères littéraux qui auraient normalement une signification spéciale dans la syntaxe de mise en forme de Markdown. Par exemple, si vous vouliez entourer un mot d'astérisques littéraux (au lieu d'une balise HTML `<em>`), vous ajoutez des barres obliques inverses avant les astérisques, comme ceci :

\*astérisques littéraux\*
