MAILOCK(3) Manuel du programmeur Linux MAILOCK(3)

NOM

maillock, mailunlock, touchlock - gérer les fichiers de verrouillage de boîte aux lettres

SYNTAXE

#include <maillock.h>

cc [ indicateur ... ] fichier ... -llockfile [ bibliothèque ]

int maillock( const char *utilisateur, int retrycnt );
void mailunlock( void );
void touchlock( void );

DESCRIPTION

La fonction maillock tente de créer un fichier de verrouillage pour la boîte aux lettres de l'utilisateur d'une manière sûre (ou résistante) à NFS. L'algorithme est documenté dans lockfile_create(3).

La boîte aux lettres est généralement située dans /var/mail. Le nom du fichier de verrouillage devient alors /var/mail/NOM_UTILISATEUR.lock. Si la variable d'environnement $MAIL est définie et se termine par le même nom d'utilisateur que celui passé à maillock(), alors ce fichier est utilisé comme boîte aux lettres à verrouiller.

Il n'y a pas de bonne façon de savoir si un fichier de verrouillage est obsolète. Par conséquent, si le fichier de verrouillage a plus de 5 minutes, il sera supprimé. C'est pourquoi la fonction touchlock est fournie : tout en maintenant le verrou, il doit être rafraîchi régulièrement (toutes les minutes environ) en appelant touchlock () .

Enfin, la fonction mailunlock supprime le fichier de verrouillage.

VALEURS DE RETOUR

maillock renvoie l'un des codes de statut suivants :

   #define L_SUCCESS   0    /* Fichier de verrouillage créé                 */
   #define L_NAMELEN   1    /* Nom du destinataire trop long (> 13 caractères) */
   #define L_TMPLOCK   2    /* Erreur lors de la création du verrou temporaire   */
   #define L_TMPWRITE  3    /* Impossible d'écrire le PID dans le verrou temporaire */
   #define L_MAXTRYS   4    /* Échec après le nombre max. de tentatives       */
   #define L_ERROR     5    /* Erreur inconnue ; vérifier errno               */
   #define L_RMSTALE   8    /* Échec de la suppression du verrouillage obsolète    */

NOTES

Ces fonctions ne sont pas thread-safe. Si vous avez besoin de fonctions thread-safe, ou si vous devez verrouiller d'autres fichiers de boîte aux lettres (ou similaires) qui ne se trouvent pas à l'emplacement standard, utilisez plutôt lockfile_create(3).

Ces fonctions appellent lockfile_create(3) pour effectuer le travail. Cette fonction peut lancer un exécutable avec un groupe défini pour effectuer le verrouillage réel si le processus actuel n'a pas les privilèges suffisants.

Il y a quelques problèmes avec le vidage du cache d'attributs du noyau si vous utilisez NFS - voir la page de manuel de lockfile_create(3).
