MAIRIX(1) Manuel des commandes générales MAIRIX(1)

NOM

mairix - indexer et rechercher des dossiers de courrier

SYNTAXE

Indexation

mairix [ -v|--verbose ] [ -p|--purge ] [ -f|--rcfile mairixrc ] [ -F|--fast-index ] [ --force-hash-key-new-database hash ]

Recherche

mairix [ -v|--verbose ] [ -f|--rcfile mairixrc ] [ -r|--raw-output ] [ -x|--excerpt-output ] [ -H|--force-hardlinks ] [ -o|--mfolder mfolder ] [ -a|--augment ] [ -t|--threads ] motifs-recherche

Autre

mairix [ -h|--help ]

mairix [ -V|--version ]

mairix [ -d|--dump ]

DESCRIPTION

mairix indexe et recherche une collection de messages électroniques. Les dossiers contenant les messages à indexer sont définis dans le fichier de configuration. L'étape d'indexation produit un fichier de base de données. Ce fichier de base de données permet un accès rapide aux détails des messages indexés lors des opérations de recherche. Une recherche produit normalement un dossier (appelé mfolder) contenant les messages correspondants. Cependant, il existe un mode brut (-r) qui se contente de lister les messages correspondants.

Il peut fonctionner avec les types de dossiers suivants :

  • maildir
  • MH (compatible avec les formats de dossiers MH utilisés par xmh, sylpheed, claws-mail, nnml (Gnus) et evolution)
  • mbox (y compris les mboxes compressées avec gzip ou bzip2)
  • MMDF (y compris celles compressées avec gzip ou bzip2)
  • IMAP : dossiers distants sur un serveur IMAP

Si des dossiers source maildir ou MH sont utilisés, et qu'une recherche renvoie ses correspondances vers un mfolder au format maildir ou MH, des liens symboliques sont utilisés pour référencer les messages d'origine à l'intérieur du mfolder. Cependant, si des dossiers mbox ou MMDF sont impliqués, des copies des messages sont faites. Si des dossiers IMAP sont utilisés pour les deux, des copies des messages sont effectuées côté serveur IMAP. Avec des dossiers source IMAP et tout autre type de dossier de résultat, les messages sont téléchargés depuis le serveur IMAP pour être écrits dans le dossier de résultat. Avec un dossier de résultat IMAP et tout autre type de dossiers source, les messages sont téléchargés vers le serveur IMAP pour être ajoutés au dossier de résultat.

OPTIONS

mairix décide si une indexation ou une recherche est nécessaire en recherchant la présence de tout motif-recherche dans la ligne de commande.

Modes spéciaux

-h, --help

Afficher le résumé d'utilisation et quitter.
-V, --version
Afficher la version du programme et quitter.
-d

Afficher le contenu de la base de données sous forme lisible par l'homme sur la sortie standard.

Options générales

-f mairixrc

--rcfile mairixrc

Spécifier un fichier de configuration alternatif à utiliser. Le fichier de configuration par défaut est ~/.mairixrc.
-v, --verbose

Rendre la sortie plus verbeuse.
-Q, --no-integrity-checks

Normalement, mairix effectue des tests d'intégrité internes sur la base de données. L'option -Q supprime ces vérifications, ce qui permet à mairix de fonctionner plus rapidement, mais il sera moins susceptible de détecter des problèmes internes si des bugs surviennent.

La directive nochecks dans le fichier rc a le même effet.

--unlock

mairix verrouille son fichier de base de données lors de toute opération d'indexation ou de recherche pour éviter que plusieurs exécutions d'indexation ne s'interfèrent mutuellement, ou qu'une exécution d'indexation n'interfère avec les exécutions de recherche. L'option --unlock supprime le fichier de verrouillage avant d'effectuer l'opération d'indexation ou de recherche demandée. C'est un moyen pratique de nettoyer un fichier de verrouillage obsolète si une exécution précédente a planté pour une raison quelconque ou a été interrompue.

Options d'indexation

-p, --purge

Supprimer les messages obsolètes (morts) de la base de données lors d'une exécution d'indexation. (Normalement, les messages obsolètes sont laissés dans la base de données en raison du coût supplémentaire de la compaction de l'espace qu'ils occupent.)
-F, --fast-index

Lors du traitement des dossiers maildir et MH, mairix compare normalement le mtime et la taille de chaque message avec les valeurs stockées dans la base de données. S'ils ont changé, le message sera réanalysé. Cette vérification nécessite que chaque fichier de message soit stat'ed. Pour un grand nombre de messages dans ces types de dossiers, cela peut représenter une surcharge considérable.

Cette option indique à mairix de supposer que lorsqu'un message actuellement sur disque a un nom correspondant à un message déjà dans la base de données, le message est inchangé.

Une exécution d'indexation ultérieure sans utiliser cette option corrigerait toute réanalyse manquée en raison de son utilisation.

--force-hash-key-new-database hash

Cette option ne doit être utilisée que pour le débogage.
Si une nouvelle base de données est créée, hash est utilisé comme clé de hachage, au lieu d'un hachage aléatoire.

Options de recherche

-a, --augment

Ajouter les messages nouvellement trouvés au mfolder actuel au lieu de créer le mfolder à partir de zéro.
-t, --threads

En plus de retourner les messages correspondants, retourner également tous les messages du même fil de discussion que l'un des vrais correspondants.
-r, --raw-output

Au lieu de créer un mfolder contenant les messages correspondants, afficher simplement leurs chemins sur la sortie standard.
-x, --excerpt-output

Au lieu de créer un mfolder contenant les messages correspondants, afficher un extrait de leurs en-têtes sur la sortie standard. L'extrait montre À, Cc, De, Sujet et Date. Avec des dossiers source IMAP, cela nécessite de télécharger chaque message correspondant depuis le serveur IMAP.
-H, --force-hardlinks

Au lieu de créer des liens symboliques, forcer l'utilisation de liens physiques. Cela aide les gestionnaires de courrier comme alpine à détecter la présence de nouveaux messages dans le dossier de recherche.
-o mfolder

--mfolder mfolder

Spécifier un chemin alternatif temporaire pour le mfolder à utiliser, remplaçant la directive mfolder dans le fichier rc.

mairix refusera de sortir les résultats de recherche dans tout dossier qui semble être parmi ceux qui sont indexés. Ceci afin d'empêcher la suppression accidentelle d'e-mails.

Motifs de recherche

t:mot

Faire correspondre mot dans l'en-tête To:.
c:mot

Faire correspondre mot dans l'en-tête Cc:.

mairix search patterns

mairix may be invoked with a list of search patterns. If given, only messages which match all the patterns will be displayed. The patterns described below are matched against the message headers and body.

c:word

Match word in the Cc: header.
f:word

Match word in the From: header.
s:word

Match word in the Subject: header.
m:word

Match word in the Message-ID: header.
b:word

Match word in the message body.

Message body is taken to mean any body part of type text/plain or text/html. For text/html, text within meta tags is ignored. In particular, the URLs inside <A HREF="..."> tags are not currently indexed. Non-text attachments are ignored. If there's an attachment of type message/rfc822, this is parsed and the match is performed on this sub-message too. If a hit occurs, the enclosing message is treated as having a hit.

d:[start-datespec]-[end-datespec]

Match messages with Date: headers lying in the specific range.
z:[low-size]-[high-size]

Match messages whose size lies in the specified range. If the low-size argument is omitted it defaults to zero. If the high-size argument is omitted it defaults to infinite size.

For example, to match messages between 10kilobytes and 20kilobytes in size, the following search term can be used:

mairix z:10k-20k

The suffix 'k' on a number means multiply by 1024, and the suffix 'M' on a number means multiply by 1024*1024.

n:word

Match word occurring as the name of an attachment in the message. Since attachment names are usually long, this option would usually be used in the substring form. So
mairix n:mairix=

would match all messages which have attachments whose names contain the substring mairix.

The attachment name is determined from the name=xxx or filename=xxx qualifiers on the Content-Type: and Content-Disposition: headers respectively.

F:flags

Match messages with particular flag settings. The available flags are 's' meaning seen, 'r' meaning replied, and 'f' meaning flagged. The flags are case-insensitive. A flag letter may be prefixed by a '-' to negate its sense. Thus 
mairix F:-s d:1w-

would match any unread message less than a week old, and

mairix F:f-r d:-1m

would match any flagged message older than a month which you haven't replied to yet.

Note that the flag characters and their meanings agree with those used as the suffix letters on message filenames in maildir folders.

Recherche d'une correspondance dans plus d'une partie d'un message

Plusieurs parties du corps peuvent être regroupées si une correspondance y est recherchée. Exemples courants.

tc:mot

Correspondance du mot dans les en-têtes To: ou Cc: (ou les deux).
bs:mot

Correspondance du mot dans l'en-tête Subject: ou le corps du message (ou les deux).

Le modèle de recherche a: est une abréviation pour tcf:; c'est-à-dire, trouver le mot dans les en-têtes To:, Cc: ou From:. ("a" signifie "adresse" dans ce cas.)

Correspondance des mots

L'argument mot des chaînes de recherche peut prendre diverses formes.

~mot

Correspondance des messages ne contenant pas le mot.
mot1,mot2

Ceci correspond si les deux mots sont trouvés dans la partie spécifiée du message.
mot1/mot2

Ceci correspond si l'un des mots est trouvé dans la partie spécifiée du message.
sous-chaîne=

Correspondance de tout mot contenant sous-chaîne comme sous-chaîne
sous-chaîne=N

Correspondance de tout mot contenant sous-chaîne, autorisant jusqu'à N erreurs dans la correspondance. Par exemple, si N vaut 1, une seule erreur est autorisée, où une erreur peut être
  • une lettre manquante
  • une lettre supplémentaire
  • une lettre différente.
^sous-chaîne=

Correspondance de tout mot contenant sous-chaîne comme sous-chaîne, avec l'exigence que sous-chaîne se trouve au début du mot correspondant.

La précédence compte

L'ordre de liaison des constructions est le suivant :

1.
Les arguments individuels de la ligne de commande définissent des conditions distinctes qui sont combinées par un ET logique.
2.
Au sein d'un même argument, les lettres avant le deux-points définissent les parties du message auxquelles l'expression s'applique. S'il n'y a pas de deux-points, l'expression s'applique à tous les en-têtes listés précédemment et au corps.
3.
Après le deux-points, les barres obliques délimitent des disjonctions distinctes, qui sont combinées par un OU logique.
4.
Chaque disjonction peut contenir des conjonctions distinctes, séparées par des virgules. Ces conditions sont combinées par un ET logique.
5.
Chaque conjonction peut commencer par une tilde pour la nier, et peut être suivie d'une barre oblique pour indiquer une correspondance de sous-chaîne, éventuellement suivie d'un entier pour définir le nombre maximum d'erreurs autorisées.

Spécification de date

Cette section décrit la syntaxe utilisée pour spécifier les dates lors de la recherche avec l'option `d:'.

Les dates sont spécifiées comme une plage. Le début et la fin de la plage peuvent tous deux être spécifiés. Alternativement, si le début est omis, il est considéré comme étant le début des temps. Si la fin est omise, elle est considérée comme étant le moment présent.

Il existe 4 formats de base :

d:début-fin

Spécifier explicitement le début et la fin
d:début-
Spécifier le début, la fin est le moment présent
d:-fin
Spécifier la fin, le début est 'il y a longtemps' (c'est-à-dire assez tôt pour inclure n'importe quel message).
d:période
Spécifier le début et la fin implicitement, comme le début et la fin de la période donnée.

Le début et la fin peuvent être spécifiés de manière absolue ou relative. Un point final relatif est donné par un nombre suivi d'une seule lettre définissant l'échelle :

lettre abrégé pour exemple signification
d jours 3j 3 jours
s semaines 2s 2 semaines (14 jours)
m mois 5m 5 mois (150 jours)
a années 4a 4 années (4*365 jours)

Les mois sont toujours traités comme 30 jours, et les années comme 365 jours, à cette fin.

Les temps absolus peuvent être spécifiés sous de nombreuses formes. Certaines formes ont des significations différentes lorsqu'elles définissent une date de début par rapport à lorsqu'elles définissent une date de fin. Lorsqu'une seule expression spécifie à la fois le début et la fin (c'est-à-dire lorsque l'argument de d: ne contient pas de '-') elle aura généralement des interprétations différentes dans les deux cas.

Dans les exemples ci-dessous, supposons que la date actuelle soit le dimanche 18 mai 2003 (lorsque j'ai commencé à écrire ce matériel.)

Exemple Date de début Date de fin Notes
d:20030301-20030425 1er mars 2003 25 avril 2003
d:030301-030425 1er mars 2003 25 avril 2003 siècle supposé
d:mar1-apr25 1er mars 2003 25 avril 2003
d:Mar1-Apr25 1er mars 2003 25 avril 2003
td> insensible à la casse d:MAR1-APR25 1er mars 2003 25 avril 2003 insensible à la casse d:1mar-25apr 1er mars 2003 25 avril 2003 date et mois dans n'importe quel ordre d:2002 1er janvier 2002 31 décembre 2002 année entière d:mar 1er mars 2003 31 mars 2003 mars le plus récent d:oct 1er octobre 2002 31 octobre 2002 octobre le plus récent d:21oct-mar 21 octobre 2002 31 mars 2003 début avant fin d:21apr-mar 21 avril 2002 31 mars 2003 début avant fin d:21apr- 21 avril 2003 18 mai 2003 fin omise d:-21apr 1er janvier 1900 21 avril 2003 début omis d:6w-2w 6 avril 2003 4 mai 2003 les deux dates sont relatives d:21apr-1w 21 avril 2003 11 mai 2003 une date est relative d:21apr-2y 21 avril 2001 11 mai 2001 début avant fin d:99-11 1er janvier 1999 11 mai 2003 les 2 chiffres sont un jour du mois si possible, sinon une année d:99oct-1oct 1er octobre 1999 1er octobre 2002 fin avant maintenant, un seul chiffre est un jour du mois d:99oct-01oct 1er octobre 1999 31 octobre 2001 les 2 chiffres commençant par zéro sont traités comme une année d:oct99-oct1 1er octobre 1999 1er octobre 2002 jour et mois dans n'importe quel ordre d:oct99-oct01 1er octobre 1999 31 octobre 2001 année et mois dans n'importe quel ordre

Les principes du tableau fonctionnent comme suit.

  • Lorsque l'expression définit une période de plus d'un jour (c'est-à-dire si un mois ou une année est spécifié), le jour le plus ancien de la période est pris lorsque la date de début est définie, et le dernier jour de la période si la fin de la plage est définie.
  • La date de fin est toujours prise comme étant égale ou antérieure à la date actuelle.
  • La date de début est toujours prise comme étant égale ou antérieure à la date de fin.

CONFIGURATION DU DOSSIER DE RECHERCHE

Si le dossier de recherche n'existe pas lors de l'exécution en mode recherche, il est automatiquement créé. Pour 'mformat=maildir' (par défaut), cela devrait suffire. Si vous utilisez 'mformat=mh', vous devrez peut-être exécuter quelques commandes avant que votre client de messagerie ne reconnaisse le dossier. Par exemple, pour mutt, vous pourriez faire :

mkdir -p /home/richard/Mail/mfolder
touch /home/richard/Mail/mfolder/.mh_sequences

ce qui semble fonctionner. Alternativement, dans mutt, vous pourriez définir MBOX_TYPE sur 'mh' et enregistrer un message dans '+mfolder' pour que mutt configure la structure pour vous à l'avance.

Si vous utilisez Sylpheed, la meilleure approche semble être de créer le nouveau dossier à partir de Sylpheed avant de laisser mairix y écrire.

EXEMPLES

Supposons que mon adresse e-mail soit <richard@doesnt.exist>.

L'une ou l'autre des commandes suivantes trouvera tous les messages plus récents que 3 mois de ma part avec le mot 'chrony' dans la ligne d'objet :

mairix d:3m- f:richard+doesnt+exist s:chrony
mairix d:3m- f:richard@doesnt.exist s:chrony

Supposons que quelques correspondances erronées sur l'adresse ne me dérangent pas, que je veuille une plage de dates plus large et que je soupçonne que certains messages auxquels j'ai répondu auraient pu avoir le mot-clé d'objet mal orthographié (autorisons jusqu'à 2 erreurs) :

mairix d:6m- f:richard s:chrony=2

NOTES

mairix fonctionne exclusivement en termes de mots. L'index qui est construit en mode indexation contient une table des mots qui apparaissent dans quels messages. Par conséquent, la capacité de recherche est basée sur la recherche de messages contenant des mots particuliers. mairix définit un mot comme toute chaîne de caractères alphanumériques + underscore. Tout espace blanc, ponctuation, tiret, etc. est traité comme une limite de mot.

mairix a un traitement spécial pour les en-têtes To:, Cc: et From:. En plus de l'analyse normale des mots, ces en-têtes sont analysés une seconde fois, où les caractères '@', '-' et '.' sont également traités comme des caractères de mot. Cela permet à la plupart (sinon à toutes) des adresses e-mail d'apparaître dans la base de données sous forme de mots uniques. Ainsi, si vous avez un e-mail de wibble@foobar.zzz, il correspondra aux deux recherches suivantes :

mairix f:foobar
mairix f:wibble@foobar.zzz

Il devrait être clair à présent que la recherche ne peut pas être utilisée pour trouver des messages correspondant à des expressions régulières générales. Cela n'a jamais été une grande limitation. La plupart des recherches portent sur des mots-clés particuliers qui se trouvaient dans les messages, ou des détails sur les destinataires, ou la date approximative.

Il convient également de souligner qu'aucune information de 'localité' n'est stockée, vous ne pouvez donc pas rechercher des messages où un mot est 'proche' d'un autre mot. Pour chaque message et chaque mot, il existe une simple condition oui/non stockée : si le message contient le mot dans un en-tête particulier ou dans le corps. Jusqu'à présent, cela s'est avéré adéquat. mairix a une sensation similaire à l'utilisation d'un moteur de recherche Internet.
