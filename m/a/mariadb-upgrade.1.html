MARIADB-UPGRADE(1) Système de base de données MariaDB MARIADB-UPGRADE(1)

NOM

mariadb-upgrade - vérifie les tables pour la mise à niveau de MariaDB (mariadb-upgrade est maintenant un lien symbolique vers mariadb-upgrade)

SYNTAXE

mariadb-upgrade [options]

DESCRIPTION

mariadb-upgrade examine toutes les tables de toutes les bases de données à la recherche d'incompatibilités avec la version actuelle du serveur MariaDB. mariadb-upgrade met également à niveau les tables système afin que vous puissiez profiter des nouveaux privilèges ou capacités qui auraient pu être ajoutés.

mariadb-upgrade doit être exécuté chaque fois que vous mettez à niveau MariaDB.

Si une table présente une incompatibilité potentielle, mariadb-upgrade effectue une vérification de table. Si des problèmes sont détectés, une réparation de table est tentée.


Note

Sur Windows Server 2008 et Windows Vista, vous devez exécuter mariadb-upgrade avec des privilèges d'administrateur. Vous pouvez le faire en exécutant une invite de commande en tant qu'administrateur et en exécutant la commande. Ne pas le faire peut entraîner un échec de la mise à niveau.


Attention

Vous devriez toujours sauvegarder votre installation MariaDB actuelle avant d'effectuer une mise à niveau.

Pour utiliser mariadb-upgrade, assurez-vous que le serveur est en cours d'exécution, puis invoquez-le comme suit :

shell> mariadb-upgrade [options]

Après avoir exécuté mariadb-upgrade, arrêtez le serveur et redémarrez-le afin que les modifications apportées aux tables système prennent effet.

mariadb-upgrade exécute les commandes suivantes pour vérifier et réparer les tables, et pour mettre à niveau les tables système :

mariadb-check --all-databases --check-upgrade --auto-repair
mariadb < fix_priv_tables
mariadb-check --all-databases --check-upgrade --fix-db-names --fix-table-names

Notes sur les commandes précédentes :

•Comme mariadb-upgrade invoque mariadb-check avec l'option --all-databases, il traite toutes les tables de toutes les bases de données, ce qui peut prendre beaucoup de temps. Chaque table est verrouillée et donc indisponible pour les autres sessions pendant son traitement. Les opérations de vérification et de réparation peuvent prendre du temps, en particulier pour les grandes tables.
•Pour plus de détails sur les vérifications effectuées par l'option --check-upgrade, consultez la description de l'option FOR UPGRADE de l'instruction CHECK TABLE.
•fix_priv_tables représente un script généré en interne par mariadb-upgrade qui contient des instructions SQL pour mettre à niveau les tables de la base de données mysql.

Toutes les tables vérifiées et réparées sont marquées avec le numéro de version actuel de MariaDB. Cela garantit que la prochaine fois que vous exécuterez mariadb-upgrade avec la même version du serveur, il pourra déterminer s'il est nécessaire de vérifier ou de réparer la table à nouveau.

mariadb-upgrade enregistre également le numéro de version de MariaDB dans un fichier nommé mariadb-upgrade_info dans le répertoire de données. Ceci est utilisé pour vérifier rapidement si toutes les tables ont été vérifiées pour cette version, afin que la vérification des tables puisse être ignorée. Pour ignorer ce fichier et effectuer la vérification quoi qu'il en soit, utilisez l'option --force.

Pour cette raison, mariadb-upgrade doit être exécuté en tant qu'utilisateur ayant un accès en écriture au répertoire de données.

Si vous installez MariaDB à partir de paquets RPM sous Linux, vous devez installer les RPM serveur et client. mariadb-upgrade est inclus dans le RPM serveur mais nécessite le RPM client car ce dernier inclut mariadb-check.

mariadb-upgrade prend en charge les options suivantes, qui peuvent être spécifiées sur la ligne de commande ou dans les groupes d'options [mariadb-upgrade] et [client]. D'autres options sont transmises à mariadb-check. Par exemple, il peut être nécessaire de spécifier l'option --password[=motdepasse]. mariadb-upgrade prend également en charge les options de traitement des fichiers d'options.

•--help, -?

Affiche un court message d'aide et quitte.

•--basedir=chemin

Ancienne option acceptée pour la compatibilité descendante mais ignorée.

•--character-sets-dir=chemin

Ancienne option acceptée pour la compatibilité descendante mais ignorée.

•--check-if-upgrade-is-needed

Quitte avec un code d'état indiquant si une mise à niveau est nécessaire. Retourne 0 si une mise à niveau est nécessaire ou si la version actuelle n'a pas pu être déterminée, 1 lorsqu'aucune action n'est requise.

•--datadir=chemin

Ancienne option acceptée pour la compatibilité descendante mais ignorée.

•--debug=chemin, -# chemin

Pour les builds de débogage, affiche le journal de débogage.

•--debug-check

Affiche des informations de débogage à la sortie du programme.

•--debug-info, -T

Affiche des informations de débogage ainsi que des statistiques d'utilisation de la mémoire et du processeur à la sortie du programme.

•--default-character-set=nom

Ancienne option acceptée pour la compatibilité descendante mais ignorée.

•--force

Ignore le fichier mariadb-upgrade_info et force l'exécution de mariadb-check même si mariadb-upgrade a déjà été exécuté pour la version actuelle de MariaDB.

•--host

Se connecte à MariaDB sur l'hôte donné.

•--password[=motdepasse], -p[motdepasse]

Le mot de passe à utiliser lors de la connexion au serveur. Si vous utilisez la forme courte de l'option (-p), vous ne pouvez pas avoir d'espace entre l'option et le mot de passe. Si vous omettez la valeur du motdepasse suivant l'option --password ou -p sur la ligne de commande, mariadb-upgrade vous demandera de le saisir.

La spécification d'un mot de passe sur la ligne de commande doit être considérée comme non sécurisée. Vous pouvez utiliser un fichier d'options pour éviter de donner le mot de passe sur la ligne de commande.

•--port=num_port, -P num_port

Le numéro de port TCP/IP à utiliser pour la connexion.

•--protocol={TCP|SOCKET|PIPE|MEMORY}

Le protocole de connexion à utiliser pour se connecter au serveur. Il est utile lorsque les autres paramètres de connexion provoqueraient normalement l'utilisation d'un protocole autre que celui que vous souhaitez.

•--silent

Affiche moins d'informations.

•--socket=chemin, -S chemin

Pour les connexions à localhost, le fichier socket Unix à utiliser, ou, sous Windows, le nom du pipe nommé à utiliser.

•--ssl

Active le SSL pour la connexion (activé automatiquement avec d'autres indicateurs). Désactive avec --skip-ssl.

•--ssl-ca=nom

Fichier CA au format PEM (vérifiez la documentation OpenSSL, implique --ssl).

•--ssl-capath=nom

Répertoire CA (vérifiez la documentation OpenSSL, implique --ssl).

•--ssl-cert=nom

Certificat X509 au format PEM (vérifiez la documentation OpenSSL, implique --ssl).

•--ssl-cipher=nom

Chiffrement SSL à utiliser (vérifiez la documentation OpenSSL, implique --ssl).

•--ssl-key=nom

Clé X509 au format PEM (vérifiez la documentation OpenSSL, implique --ssl).

•--ssl-crl=nom

Liste de révocation de certificats (vérifiez la documentation OpenSSL, implique --ssl).

•--ssl-crlpath=nom

Chemin de la liste de révocation de certificats (vérifiez la documentation OpenSSL, implique --ssl).

•--ssl-verify-server-cert

Vérifie le "Common Name" (nom commun) du serveur dans son certificat par rapport au nom d'hôte utilisé lors de la connexion. Cette option est désactivée par défaut.

•--tmpdir=chemin, -t chemin

Le nom du chemin du répertoire à utiliser pour créer des fichiers temporaires.

•--upgrade-system-tables, -s

Met à niveau les tables système dans la base de données mysql. Cela inclut les tables de privilèges, les tables de fuseaux horaires et toutes les autres tables système qui nécessitent une mise à niveau.

D'autres options sont disponibles via la ligne de commande ou dans les fichiers d'options, telles que celles spécifiées dans la section Options du client.

mariadb-upgrade est un utilitaire qui fait partie de l'ensemble d'outils de gestion de MariaDB. Il est conçu pour simplifier le processus de mise à niveau des bases de données MariaDB.

•--user=nom_utilisateur, -u nom_utilisateur

Le nom d'utilisateur MariaDB à utiliser lors de la connexion au serveur et non lors de l'utilisation du nom de connexion actuel.

•--verbose

Affiche plus d'informations sur le processus. L'utiliser deux fois affichera les arguments de connexion ; l'utiliser 3 fois affichera toutes les commandes CHECK, RENAME et ALTER TABLE utilisées pendant la phase de vérification ; l'utiliser 4 fois (ajouté dans MariaDB 10.0.14) affichera également toutes les commandes mariadb-check utilisées ; l'utiliser 5 fois affichera toutes les commandes mariadb utilisées et leurs résultats lors de l'exécution du script mariadb-fix-privilege-tables.

•--version, -V

Affiche les informations de version et quitte.

•--version-check, -k

Exécute ce programme uniquement si sa 'version de serveur' correspond à la version du serveur auquel il se connecte. Note : la 'version de serveur' du programme est la version du serveur MariaDB avec lequel il a été compilé/distribué. Par défaut, activé ; utilisez --skip-version-check pour désactiver.

•--write-binlog

Active la journalisation binaire pendant l'exécution de mariadb-upgrade.
