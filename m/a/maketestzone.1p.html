NOM

generaterecords - génère une zone de test DNSSEC pouvant être utilisée pour DNSSEC

SYNTAXE

generaterecords -v -d mytestzone.example.com

DESCRIPTION

Le script generaterecords génère un fichier de zone, étant donné un nom de domaine, qui est ensuite signé et modifié pour invalider des portions des données de manière particulière. Chaque enregistrement généré est nommé de manière appropriée selon la manière dont les données de sécurité sont modifiées (l'enregistrement gooda contiendra un enregistrement A avec des données DNSSEC valides, mais l'enregistrement badseca contiendra un enregistrement A où la signature a été modifiée pour l'invalider).

Les résultats de ce processus peuvent ensuite être servis et des validateurs sécurisés, des applications et d'autres logiciels peuvent être testés pour voir s'ils échouent ou réussissent correctement selon les politiques de sécurité DNS déployées.

Après la génération des fichiers, envisagez d'exécuter donuts dessus pour voir comment les données ont été falsifiées pour être invalides.

PRÉREQUIS

zonesigner du projet dnssec-tools, logiciel bind 9.3.1 ou supérieur

DÉMARRAGE

Pour commencer à créer une nouvelle zone, vous devrez indiquer à zonesigner de créer de nouvelles clés pour toutes les nouvelles zones que maketestzone crée. Ainsi, la première exécution de maketestzone devrait ressembler à ceci :

Première fois :
maketestzone -k [AUTRES OPTIONS SOUHAITÉES]

Après cela, les fichiers de zone générés peuvent être chargés et servis sur un serveur de test.

Une fois tous les 30 jours (par défaut via zonesigner), le script devra être réexécuté pour recréer les enregistrements et resigner les données afin que les horodatages de signature restent valides (ou dans certains cas, invalides).

Tous les 30 jours :
maketestzone [AUTRES OPTIONS SOUHAITÉES]

NAME

maketestzone - Create DNSSEC test zones

SYNOPSIS

maketestzone [-h|--help] [--help-full] [--version] [file ...]

DESCRIPTION

The maketestzone tool is a helper script for creating DNSSEC test zones. It is designed to create test zone files that can be used for testing DNSSEC signing tools, such as zonesigner.

The tool takes one or more zone files as input and generates new zone files with additional records and configurations suitable for testing. These modifications can include adding RRSIG and NSEC records, rolling keys, and other specific test scenarios.

PRE-REQUISITES

This tool requires Perl and the Net::DNS module to be installed.

GETTING STARTED

To create a basic test zone, simply provide the path to your existing zone file as an argument:

    maketestzone your_zone.db

This will create a new file, typically named your_zone.db.test, with default test modifications.

For more advanced usage and specific test cases, refer to the options described below and the examples provided in the tool's documentation.

OPTIONS

-h
Afficher un résumé d'aide (indicateurs courts préférés)
--help
Afficher un résumé d'aide (indicateurs longs préférés)
--help-full
Afficher toutes les options d'aide (courtes et longues)
--version
Affiche le numéro de version du script.

AJOUT DE NOUVELLES SORTIES

La section suivante explique comment étendre l'outil maketestzone avec de nouvelles modifications de sortie.

AJOUT D'INFORMATIONS DE LÉGENDE

Pour la sortie HTML de la légende, le hachage %LegendInformation contient un nom de clé et une description pour chaque type de modification.

AJOUT DE NOUVELLES DIFFÉRENCES DE SOUS-ZONE

Le hachage %zonesigner_domain_opts énumère les arguments supplémentaires entre les appels de zonesigner pour divers sous-domaines. Ainsi, vous pouvez créer des sous-zones supplémentaires avec différentes options de zonesigner pour tester d'autres paramètres opérationnels entre le parent et l'enfant. Par exemple :

'rollzsk-ns.' . $opts{'d'} => '-rollzsk',

Force la sous-zone de test rollzsk-ns à dérouler sa clé zsk lorsque la zone est signée.

AJOUT DE NOUVELLES MODIFICATIONS D'ENREGISTREMENT

Maketestzone est à ses débuts de développement, mais possède déjà les bases d'un système extensible vous permettant de modifier les enregistrements à volonté sur la base de crochets de sous-programmes regexp => sous-programmes.

Pour ajouter une nouvelle modification, ajoutez un nouveau mot-clé aux indicateurs par défaut 'p' et éventuellement 'P' (ou ajoutez-le à l'exécution), puis ajoutez une nouvelle fonction à la liste des callbacks définis dans le hachage %destroyFunctions qui est basé sur votre nouveau mot-clé. Lorsque le fichier est analysé et qu'il rencontre un enregistrement correspondant à votre expression, votre fonction sera appelée. Des arguments peuvent être ajoutés à la fonction en passant une référence de tableau où le premier argument est la sous-routine à appeler et les restants sont des arguments supplémentaires. Les lignes de sortie doivent être imprimées vers le descripteur de fichier $fh.

Voici un exemple de fonction qui supprime la signature RRSIG de l'enregistrement suivant :

sub delete_signature {
    # les 2 premiers arguments sont toujours passés ; l'autre était dans la
    # référence de tableau avec laquelle la sous-routine a été enregistrée.
    my ($name, $type, $expr) = @_;
    Verbose("  deleting signatures of $_[0]");
    # imprime la ligne actuelle
    print $fh $_;
    my $inrec = 0;
    while (<I>) {
      # un nouvel enregistrement de nom signifie que nous avons terminé.
      last if /^\w/;
      # nous sommes dans un enregistrement rrsig multi-lignes
      $inrec = 1 if (/$expr\s+$type/);
      # imprime la ligne si nous ne sommes pas dans l'enregistrement rrsig
      print $fh $_ if (!$inrec);
      # quand nous avons terminé avec la dernière ligne de l'enregistrement rrsig, marquons cet endroit
      $inrec = 0 if (/\)/);
    }
}

Ceci est ensuite enregistré dans %destroyFunctions. Voici un exemple d'enregistrement de la fonction pour supprimer la signature sur un enregistrement DS :

'^(nosig[-\w]+).*IN\s+NS\s+' => [\&delete_signature, 'DS', 'RRSIG'],
