makecert(1)

Paquet: mono

Licences: GPL, LGPL2.1, MPL

Mono(MakeCert) Mono(MakeCert)

NOM

MakeCert - Crée des certificats X.509 à des fins de test

SYNTAXE

makecert [options] certificat

DESCRIPTION

Crée un certificat X.509 à l'aide des informations fournies. Ceci est utile pour tester les signatures Authenticode, les technologies SSL et S/MIME.

PARAMETRES

-# numéro
Spécifie le numéro de série du certificat.
-n dn
Spécifie le nom distinctif (DN) du sujet.
-in dn
Spécifie le nom distinctif (DN) de l'émetteur.
-r
Crée un certificat auto-signé, également appelé certificat racine.
-iv fichier_pvk
Spécifie le fichier de clé privée (.PVK) pour l'émetteur. La clé privée du fichier spécifié sera utilisée pour signer le nouveau certificat.
-ic fichier_cert
Extrait le nom de l'émetteur du fichier de certificat spécifié - c'est-à-dire que le nom du sujet du certificat spécifié devient le nom de l'émetteur du nouveau certificat.
-in nom
Utilise le nom de l'émetteur du paramètre spécifié.
-ik conteneur
Spécifie le nom du conteneur de clé à utiliser pour l'émetteur.
-iky [signature | exchange | #]
Spécifie le numéro de clé à utiliser dans le fournisseur (lorsqu'il est utilisé avec -ik).
-ip fournisseur
Spécifie le fournisseur cryptographique à utiliser pour l'émetteur.
-ir [localmachine | currentuser]
Spécifie que le fournisseur recherchera les conteneurs de clés de l'utilisateur ou de la machine pour l'émetteur.
-iy numéro
Spécifie le numéro de type de fournisseur à utiliser pour l'émetteur.
-sv fichier_pvk
Spécifie le fichier de clé privée (.PVK) pour le sujet. La partie publique de la clé sera insérée dans le certificat créé. S'il n'existe pas, le fichier spécifié sera créé avec une nouvelle paire de clés (par défaut une paire de clés RSA de 1024 bits).
-sk conteneur
Spécifie le nom du conteneur de clé à utiliser pour le sujet.
-sky [signature | exchange | #]
Spécifie le numéro de clé à utiliser dans le fournisseur (lorsqu'il est utilisé avec -sk).
-sp fournisseur
Spécifie le fournisseur cryptographique à utiliser pour le sujet.
-sr [localmachine | currentuser]
Spécifie que le fournisseur recherchera les conteneurs de clés de l'utilisateur ou de la machine pour le sujet.
-sy numéro
Spécifie le type de fournisseur à utiliser pour l'émetteur.
-a hachage
Sélectionne l'algorithme de hachage. Seuls les algorithmes MD5 et SHA1 sont pris en charge.
-b date
La date à partir de laquelle le certificat est valide (pasAvant).
-e date
La date jusqu'à laquelle le certificat est valide (pasAprès).
-m numéro
Spécifie la période de validité du certificat en mois. Ceci est ajouté à la date de validité pasAvant qui peut être définie avec -b ou sera par défaut à la date/heure actuelle.
-cy [authority|end]
Contraintes de base. Sélectionne un certificat d'autorité ou d'entité finale. Seuls les certificats d'autorité peuvent être utilisés pour signer d'autres certificats (-ic). Les certificats d'entité finale peuvent être utilisés par des clients (par exemple, Authenticode, S/MIME) ou des serveurs (par exemple, SSL).
-h numéro
Ajoute une restriction de longueur de chemin à la chaîne de certificats. Ceci n'est applicable qu'aux certificats dont la contrainte de base est définie sur Autorité (-cy authority). Ceci est utilisé pour limiter la chaîne de certificats qui peuvent être émis sous cette autorité.
-alt nom_fichier
Ajoute une extension subjectAltName au certificat. Chaque ligne de 'nom_fichier' sera ajoutée comme une entrée DNS de l'extension. Cette option est utile si vous souhaitez créer un certificat SSL unique pour fonctionner sur plusieurs hôtes qui ne partagent pas un nom de domaine commun (c'est-à-dire que CN=*.domaine.com ne fonctionnerait pas).
-eku oid[,oid]
Ajoute un ou plusieurs OID d'utilisation étendue de clé au certificat.
-p12 fichier_pkcs12 mot_de_passe
Crée un nouveau fichier PKCS#12 contenant à la fois les certificats (le sujet et éventuellement l'émetteur) et la clé privée. Le fichier PKCS#12 est protégé par le mot de passe spécifié. Cette option est exclusive à mono.
-?
Aide (affiche ce message d'aide)
-!
Aide étendue (pour les options avancées)

EXEMPLES

Pour créer un certificat de test SSL (c'est-à-dire non fiable), c'est facile une fois que vous connaissez le nom de votre hôte. La commande suivante créera un certificat de test pour un serveur SSL :

$ hostname 
pollux
$ makecert -r -eku 1.3.6.1.5.5.7.3.1 -n "CN=pollux" -sv pollux.pvk pollux.cer
Success

En particulier dans l'exemple ci-dessus, les paramètres utilisés pour construire ce certificat de test étaient :

-r
Crée un certificat auto-signé (c'est-à-dire sans hiérarchie).
-eku 1.3.6.1.5.5.7.3.1
Facultatif (car malheureusement la plupart des clients ne l'exigent pas). Ceci indique que votre certificat est destiné à l'authentification côté serveur.
-n
Nom commun (CN) = Nom de l'hôte. Ceci est vérifié par le client SSL et doit correspondre à l'hôte connecté (sinon vous obtiendrez un avertissement ou une erreur ou *la horreur* rien du tout).
-sv cle_privee.key
Le fichier de clé privée. La clé (paire de clés RSA de 1024 bits) sera générée automatiquement si le fichier spécifié n'est pas présent.
pollux.cer
Le certificat SSL à créer pour votre hôte.

RESTRICTIONS CONNUES

Comparé à la version Windows, certaines options ne sont pas prises en charge (-$, -d, -l, -nscp, -is, -sc, -ss). De plus, les fichiers PVK avec mots de passe ne sont pas pris en charge.
