MAKEMAP(8) Manuel du gestionnaire système MAKEMAP(8)

NOM

makemap — crée des cartes de base de données pour smtpd

SYNTAXE

makemap [-U] [-d type_base] [-o fichier_base] [-t type] fichier

DESCRIPTION

Les cartes fournissent une interface générique pour associer une clé textuelle à une valeur. Ces associations peuvent être accessibles via un fichier texte brut, une base de données ou DNS. Le format de ces types de fichiers est décrit ci-dessous. makemap lui-même crée les cartes de base de données utilisées par les recherches de cartes indexées spécifiées dans smtpd.conf(5).

makemap lit l'entrée depuis fichier et écrit les données dans un fichier nommé en ajoutant le suffixe “.db” à fichier. La ligne actuelle peut être étendue sur plusieurs lignes en utilisant une barre oblique inverse (‘\’). Les commentaires peuvent être placés n'importe où dans le fichier en utilisant une dièse (#), et s'étendent jusqu'à la fin de la ligne actuelle. Il faut être prudent lors de la mise en commentaire de textes multi-lignes : le commentaire est effectif jusqu'à la fin du bloc entier. Dans tous les cas, makemap lit des lignes composées de mots séparés par des espaces. Le premier mot d'une ligne est la clé de la base de données ; le reste représente la valeur associée. La clé et la valeur de la base de données peuvent être optionnellement séparées par le caractère deux-points.

Les options sont les suivantes :

-d type_base
Spécifie le format de la base de données. Les formats disponibles sont hash et btree. La valeur par défaut est hash.
-o fichier_base
Écrit la base de données générée dans fichier_base.
-t type
Spécifie le format du fichier de carte résultant. Le format de carte par défaut convient au stockage d'associations simples, non structurées, de clé à valeur. Cependant, si la valeur associée a une signification spéciale, comme dans le cas d'un fichier de domaines virtuels, un type approprié doit être fourni. Les types de sortie disponibles sont :
aliases
La valeur associée est une liste de destinations de courrier séparées par des virgules. Ce format peut être utilisé pour construire des alias d'utilisateurs et des mappages d'utilisateurs pour les fichiers de domaines virtuels.
set
Il n'y a pas de valeur associée – une carte de ce type ne permettra que la recherche de clés. Ce format peut être utilisé pour construire des cartes de domaines principaux.
-U
Au lieu de générer une carte de base de données à partir d'une entrée texte, déverse le contenu d'une carte de base de données sous forme de texte avec la clé et la valeur séparées par une tabulation.

DOMAINES PRINCIPAUX

Les domaines principaux peuvent être conservés dans des tables. Pour créer une table de domaines principaux, ajoutez chaque domaine principal sur une ligne séparée.

En plus d'ajouter une entrée à la carte des domaines principaux, il faut ajouter une règle de filtrage qui accepte le courrier pour la carte de domaine, par exemple :

table domains db:/etc/smtpd/domains.db

action "local" mbox

match for domain <domains> action "local"

DOMAINES VIRTUELS

Les domaines virtuels peuvent également être conservés dans des tables. Pour créer une table de domaines virtuels, ajoutez chaque domaine virtuel sur une ligne séparée.

Les domaines virtuels attendent un mappage d'utilisateurs virtuels vers des utilisateurs réels afin de déterminer si un destinataire est accepté ou non. Le format de mappage est une extension de aliases(5), qui permet l'utilisation de “user@domain.tld” pour accepter l'utilisateur uniquement sur le domaine spécifié, “user” pour accepter l'utilisateur pour n'importe lequel des domaines virtuels, “@domain.tld” pour fournir une redirection pour le domaine spécifié et “@” pour fournir une redirection globale pour tous les domaines. smtpd(8) effectuera les recherches dans cet ordre spécifique.

Pour créer une adresse virtuelle unique, ajoutez “user@example.com user” à la carte des utilisateurs. Pour gérer tout courrier destiné à n'importe quel utilisateur à example.com, ajoutez “@example.com user” à la carte virtuelle.

En plus d'ajouter une entrée à la carte virtuelle, il faut ajouter une règle de filtrage qui accepte le courrier pour les domaines virtuels, par exemple :

table vdomains db:/etc/smtpd/vdomains.db
table vusers db:/etc/smtpd/users.db

action "local" mbox virtual <vusers>

match for domain <vdomains> action "local"
match for domain "example.org" action "local"

FICHIERS

/etc/smtpd/aliases
Liste des alias de courrier des utilisateurs.
/etc/smtpd/secrets
Liste des identifiants des hôtes distants.

STATUT DE SORTIE

L'utilitaire makemap se termine avec le statut 0 en cas de succès, et avec un statut supérieur à 0 en cas d'erreur.

VOIR AUSSI

aliases(5), smtpd.conf(5), table(5), newaliases(8), smtpd(8)

HISTORIQUE

La commande makemap est apparue pour la première fois dans OpenBSD 4.6 en remplacement de la commande équivalente fournie avec sendmail.
