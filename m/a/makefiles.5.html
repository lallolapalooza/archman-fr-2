makefiles(4L) FORMATS DE FICHIERS GMD FOKUS makefiles(4L)

NOM

makefiles - guide utilisateur pour la compilation de projets sur différentes plateformes

SYNTAXE

make [cible]
gmake [cible]
smake [cible]

Cible peut être l'une des suivantes :

.help
pour obtenir une liste des cibles possibles et une courte description.
all
pour construire les cibles par défaut
install
pour construire et installer les cibles par défaut (voir INS_BASE et INS_KBASE pour savoir comment modifier le chemin d'installation).
ibins
pour construire et installer une cible dans SRCROOT/bins
depend
pour reconstruire les règles de dépendance pour toutes les cibles par défaut. Note : Tous les fichiers de dépendance seront automatiquement reconstruits lors de la prochaine exécution de make avant d'être inclus.
clean
pour supprimer les fichiers core et tous les fichiers objets intermédiaires.
clobber
pour supprimer les cibles de clean, tous les fichiers de dépendance et toutes les cibles finales
distclean
pour supprimer les cibles de clean et clobber ainsi que tous les fichiers construits pour toutes les architectures.
tags
pour construire des tags compatibles vi(1)
TAGS
pour construire des tags compatibles emacs(1)
config
réservé pour un usage futur.
rmtarget
pour supprimer la cible par défaut
relink
pour supprimer la cible par défaut et la reconstruire immédiatement. Ceci peut être utilisé pour changer par exemple LD_RUN_PATH dans l'exécutable.

DESCRIPTION

Makefiles est un ensemble de règles qui permet de compiler des projets structurés avec de petits makefiles de structure uniforme. Toutes les règles sont situées dans un répertoire central. La compilation des projets sur différentes plateformes peut être faite simultanément sans avoir besoin de modifier aucun des makefiles situés dans les répertoires des projets.

Makefiles est un ensemble d'outils de portabilité de haut niveau, supérieurs à autoconf et plus faciles à utiliser.

Trois programmes make sont supportés : Sunpro make, GNU make et smake.

BSDmake pourrait être supporté s'il supporte correctement les règles de correspondance de motifs.

L'objectif principal de conception était d'avoir un ensemble de makefiles petits et faciles à lire, chacun situé dans le répertoire feuille du projet et donc appelé leaf-makefile.

Chacun de ces leaf-makefiles ne contient en fait aucune règle. Il définit simplement quelques macros pour le programme make et inclut deux fichiers d'un dépôt central de règles make. Les fichiers inclus et les fichiers qui sont inclus récursivement définissent les règles nécessaires à la compilation du projet.

Chaque leaf-makefile est formé de manière très simple :

•
Il définit d'abord deux macros qui définissent l'emplacement relatif du répertoire racine du projet et le nom du répertoire contenant l'ensemble complet des règles, puis inclut le fichier de règles rules.top du répertoire qui forme le dépôt central de règles. Vous n'avez qu'à modifier la macro SRCROOT pour refléter l'emplacement relatif du répertoire racine du projet.
•
La partie suivante d'un leaf-makefile définit des macros qui décrivent la cible et la source. Vous ne pouvez avoir qu'une seule cible par leaf-makefile. Bien sûr, il peut y avoir de nombreux fichiers source nécessaires à la création de cette cible. Si vous voulez construire plus d'une cible dans un répertoire spécifique, vous devez mettre plus d'un makefile dans ce répertoire. C'est la partie d'un makefile qui décrit une cible unique. Modifiez cette partie pour y inclure tous les fichiers source, tous les fichiers d'inclusion locaux et tous les indicateurs de compilation non globaux nécessaires à votre cible. Pour une cible typique, cela se résume à remplir un formulaire.
•
Chaque leaf-makefile inclut finalement un fichier du répertoire des règles qui contient les règles pour le type de cible approprié à construire à partir de ce leaf-makefile.

Le makefile dans chaque répertoire doit s'appeler Makefile. Si vous souhaitez avoir plus d'un makefile dans un répertoire spécifique, vous devez choisir des noms différents pour les autres makefiles.

Il existe des règles pour les types de cibles suivants :

commandes
Les règles make pour les commandes utilisateur comme cat, ls, etc., sont situées dans le fichier rules.cmd
pilotes
Les règles make pour les pilotes de périphériques sont situées dans le fichier rules.drv
bibliothèques
Les règles make pour les bibliothèques non partagées sont situées dans le fichier rules.lib
bibliothèques partagées
Les règles make pour les bibliothèques partagées sont situées dans le fichier rules.shl
fichiers localisés
Les règles make pour les fichiers localisés sont situées dans le fichier rules.loc
fichiers non-localisés
Les règles make pour les fichiers non localisés sont situées dans le fichier rules.aux
scripts shell
Les règles make pour les scripts shell (une variante des fichiers localisés) sont situées dans le fichier rules.scr
pages de manuel
Les règles make pour les pages de manuel (une variante des fichiers localisés) sont situées dans le fichier rules.man
makefiles détournés
Les règles make pour les projets qui nécessitent plus d'un makefile dans un répertoire spécifique sont situées dans le fichier rules.mks Il contient une règle qui détourne vers les sous-makefiles listés. Chaque sous-makefile peut être de n'importe quel type.
répertoires
Les règles make pour les sous-répertoires sont situées dans le fichier rules.dir

Macros/Variables Utilisées Dans Les Règles

Voici une description des macros les plus importantes utilisées dans les règles make. NOTE : toutes ne peuvent pas être modifiées dans un makefile spécifique. Lisez attentivement la description et ne modifiez que les macros destinées à changer le comportement de la compilation.

ARCHDIR
contient l'emplacement où seront placés les fichiers objets et les cibles make. Un nom typique serait : OBJ/sparc-sunos5-cc
Ne modifiez pas cette macro.
ASFLAGS
Les indicateurs utilisés avec l'assembleur.
Ne modifiez pas cette macro.
ASMFILES
une liste de fichiers source assembleur, à spécifier dans un leaf makefile.
ASOPTS
La macro interne qui contient les indicateurs pour l'assembleur. Modifiez cette macro si vous souhaitez changer le comportement. Utilisez : ASOPTS= valeur Si vous voulez remplacer la valeur par défaut. Si vous voulez remplacer les indicateurs d'assembleur par défaut depuis la ligne de commande, appelez : make 'ASOPTS=valeur' Utilisez : ASOPTS += valeur Si vous voulez ajouter des indicateurs à la valeur par défaut depuis un makefile.
ASOPTX
peut être utilisé si vous souhaitez ajouter des indicateurs aux indicateurs de l'assembleur depuis la ligne de commande. Utilisez : make 'ASOPTX=valeur'
C_ARCH
cette macro contient le nom de l'architecture du compilateur c.
Ne modifiez pas cette macro.
CCOM
Cette macro peut être utilisée depuis la ligne de commande pour utiliser un compilateur c différent par défaut. Utilisez : make 'CCOM=gcc' pour utiliser gcc pour la prochaine exécution
n. Note : La valeur de CCOM n'est pas nécessairement identique au nom réel du compilateur c. Elle fait référence à un nom de fichier qui contient la définition de ce compilateur c. Cette remarque s'applique également à toutes les autres macros qui traitent du nom du compilateur c. La seule macro qui contient le nom d'invocation réel du compilateur c est CC. CC est défini dans le fichier de configuration dépendant de la machine dans le dépôt central des règles et ne doit pas être modifié ailleurs.
CFILES
une liste de fichiers sources C, à spécifier dans un makefile feuille.
CFLAGS
Les drapeaux utilisés avec le compilateur c. N'utilisez pas de drapeaux appartenant au préprocesseur c dans les macros COPTOPT, COPTS et COPTX.
Ne modifiez pas cette macro.
CLEAN_FILES
Une liste de fichiers (en dehors des fichiers objets) qui seront supprimés avec make clean.
Ne modifiez pas cette macro.
CLEAN_FILEX
cette macro peut être utilisée pour définir des fichiers supplémentaires qui doivent être supprimés avec make clean.
CLOBBER_FILEX
cette macro peut être utilisée pour définir des fichiers supplémentaires qui doivent être supprimés avec make clobber.
COPTOPT
Le drapeau d'optimisation du compilateur c. Ce drapeau est destiné à être remplacé soit par un makefile, soit par la ligne de commande.
COPTS
La macro interne qui contient les drapeaux pour le compilateur c. Modifiez cette macro si vous souhaitez changer le comportement. Utilisez : COPTS= valeur si vous souhaitez remplacer la valeur par défaut. Si vous souhaitez remplacer les drapeaux par défaut du compilateur c depuis la ligne de commande, appelez : make 'COPTS=valeur' Utilisez : COPTS += valeur si vous souhaitez ajouter des drapeaux à la valeur par défaut depuis un makefile.
COPTX
peut être utilisé si vous souhaitez ajouter des drapeaux aux drapeaux du compilateur c depuis la ligne de commande. Utilisez : make 'COPTX=valeur'
CPPFLAGS
Les drapeaux utilisés avec le préprocesseur c. Cette macro ainsi que : CPPOPTS et CPPOPTX sont également utilisées lors de la compilation de programmes c. Elles ne doivent contenir que les drapeaux suivants : -Dname=value , -Uname , -Idirectory et -Ydirectory.
Ne modifiez pas cette macro.
CPPOPTS
La macro interne qui contient les drapeaux pour le préprocesseur c. Modifiez cette macro si vous souhaitez changer le comportement. Utilisez : CPPOPTS= valeur si vous souhaitez remplacer la valeur par défaut. Si vous souhaitez remplacer les drapeaux par défaut du préprocesseur c depuis la ligne de commande, appelez : make 'CPPOPTS=valeur' Utilisez : CPPOPTS += valeur si vous souhaitez ajouter des drapeaux à la valeur par défaut depuis un makefile.
CPPOPTX
peut être utilisé si vous souhaitez ajouter des drapeaux aux drapeaux du préprocesseur c depuis la ligne de commande. Utilisez : make 'CPPOPTX=valeur'
CURDIR
Cette macro contient le nom du sous-répertoire actuellement traité.
Ne modifiez pas cette macro.
CWARNOPTS
Cette macro peut être définie dans $(DEFLTSROOT)/$(DEFLTSDIR)/Defaults ou $(DEFLTSROOT)/$(DEFLTSDIR)/Defaults.$(O_ARCH) pour remplacer les options d'avertissement par défaut du compilateur c.
CWOPTS
Cette macro est définie dans le fichier de configuration dépendant de la machine dans le dépôt central des règles et ne doit pas être modifiée ailleurs. Elle contient les drapeaux qui définissent le niveau d'avertissement par défaut pour le compilateur c.
DEFINSGRP
cette macro peut être définie dans le fichier des valeurs par défaut du projet pour configurer l'identifiant de groupe par défaut pour l'installation
DEFINSMODE
cette macro peut être définie dans le fichier des valeurs par défaut du projet pour configurer les permissions de fichier par défaut pour l'installation
DEFINSUSR
cette macro peut être définie dans le fichier des valeurs par défaut du projet pour configurer l'identifiant utilisateur par défaut pour l'installation
DEFUMASK
cette macro peut être définie dans le fichier des valeurs par défaut du projet pour configurer la valeur umask par défaut pour la création de sous-répertoires
DEFAULTSDIR
cette macro peut être définie depuis la ligne de commande ou depuis l'environnement shell si l'utilisateur souhaite utiliser un ensemble différent de fichiers Defaults qui ne se trouve pas dans le répertoire DEFAULTS dans le répertoire source racine. Elle peut être utilisée pour conserver deux ensembles ou plus de valeurs par défaut qui diffèrent, par exemple, dans le chemin d'installation ou le compilateur C.
DEFAULTSROOT
cette macro peut être définie dans un makefile feuille, si ce makefile souhaite utiliser un fichier Defaults qui ne se trouve pas dans $(DEFAULTSDIR) dans la source racine. Elle peut être utilisée si un sous-arbre dans un grand projet nécessite une configuration différente.
DEFLTSDIR
Ceci est une macro utilisée en interne qui est définie à partir de $(DEFAULTSDIR) ou des valeurs par défaut internes.
Ne modifiez pas cette macro.
DEFLTSROOT
Ceci est une macro utilisée en interne qui est définie à partir de $(DEFAULTSROOT) ou des valeurs par défaut internes.
Ne modifiez pas cette macro.
DEFCCOM
le nom par défaut du compilateur c. Il est généralement défini dans le fichier $(DEFLTSROOT)/$(DEFLTSDIR)/Defaults ou $(DEFLTSROOT)/$(DEFLTSDIR)/Defaults.$(O_ARCH).
DEFINCDIRS
une liste de répertoires recherchés par défaut en plus des répertoires d'inclusion système. Si cette macro n'est pas définie, $(SRCROOT)/include est utilisé.
DIRNAME
cette macro doit être définie dans le makefile situé dans le répertoire $(SRCROOT). La valeur doit être soit le nom du répertoire où se trouve le makefile, soit SRCROOT. La valeur de cette macro est automatiquement mise à jour pour suivre la hiérarchie des répertoires. Ne modifiez pas cette macro dans un makefile autre que le makefile dans la source racine.
DIRS
cette macro doit être définie dans un makefile situé dans un répertoire contenant des répertoires de dérivation. Elle doit contenir une liste de noms de répertoires vers lesquels les dérivations vont, par exemple : DIRS= libfoo libbar libgarbage.
HFILES
pour un fonctionnement normal, les makefiles trouveront automatiquement les fichiers d'inclusion nécessaires à la compilation. Cependant, si vous souhaitez créer un fichier de tags qui inclut des tags pour les définitions qui apparaissent dans les fichiers d'inclusion, vous devez définir HFILES pour qu'il contienne une liste de fichiers d'inclusion contenant de telles définitions.
INCDIRS
cette macro sera normalement une copie de DEFINCDIRS. Vous pouvez cependant spécifier une valeur différente dans un makefile feuille ou depuis la ligne de commande. Cela remplacera la valeur par défaut.
INS_BASE
cette macro doit être spécifiée dans le fichier $(DEFLTSROOT)/$(DEFLTSDIR)/Defaults ou $(DEFLTSROOT)/$(DEFLTSDIR)/Defaults.$(O_ARCH). Elle doit contenir le nom du chemin de la racine pour l'installation des cibles générales du projet. Voir INSDIR.
INS_KBASE
cette macro doit être spécifiée dans le fichier $(DEFLTSROOT)/$(DEFLTSDIR)/Defaults ou $(DEFLTSROOT)/$(DEFLTSDIR)/Defaults.$(O_ARCH). Elle doit contenir le nom du chemin de la racine pour l'installation des modules du noyau du projet. Voir INSDIR.
INSDIR
cette macro doit être spécifiée dans le makefile feuille. Elle doit contenir le nom du chemin d'un répertoire relatif à INS_BASE ou INS_KBASE. La cible sera installée dans $(INS_BASE)/$(INSDIR) .
INSGRP
cette macro peut être définie dans un makefile feuille pour configurer l'identifiant de groupe pour l'installation
INSMODE
cette macro peut être définie dans un makefile feuille pour configurer les permissions de fichier pour l'installation
INSUSR
cette macro peut être définie dans un makefile feuille pour configurer l'identifiant utilisateur pour l'installation
K_ARCH
cette macro contient l'architecture du noyau/machine pour la machine cible (par exemple, sun3 sun4c sun4m sun4u 9000-725 aviion). Elle est définie à la sortie de uname -m convertie en minuscules.
Ne modifiez pas cette macro.
KARCH
cette macro contient l'architecture du noyau/machine pour la machine cible (par exemple, sun3 sun4c sun4m sun4u 9000-725 aviion). Elle est définie à la sortie de uname -m convertie en minuscules.
Ne modifiez pas cette macro, sauf si vous souhaitez effectuer une compilation croisée.
LDFLAGS
Les drapeaux utilisés avec l'éditeur de liens.
Ne modifiez pas cette macro.
LDLIBS
La macro interne qui contient les bibliothèques utilisées lors de l'édition de liens de la cible.
Ne modifiez pas cette macro.
LDOPTS
La macro interne qui contient les drapeaux pour l'éditeur de liens. Modifiez cette macro si vous souhaitez changer le comportement. Utilisez : LDOPTS= valeur si vous souhaitez remplacer la valeur par défaut. Si vous souhaitez remplacer les drapeaux par défaut de l'éditeur de liens depuis la ligne de commande, appelez : make 'LDOPTS=valeur' Utilisez : LDOPTS += valeur si vous souhaitez ajouter des drapeaux à la valeur par défaut depuis un makefile.
LDOPTX
peut être utilisé si vous souhaitez ajouter des drapeaux aux drapeaux de l'éditeur de liens depuis la ligne de commande. Utilisez : make 'LDOPTX=valeur'
LDPATH
le chemin de recherche de bibliothèque par défaut pour l'éditeur de liens. Il est généralement défini dans le fichier $(DEFLTSROOT)/$(DEFLTSDIR)/Defaults ou
i>$(DEFLTSROOT)/$(DEFLTSDIR)/Defaults.$(O_ARCH).
LIB_KVM
une macro prédéfinie contenant le nom dépendant du système d'exploitation d'une bibliothèque nécessaire aux programmes qui lisent/écrivent la mémoire virtuelle du noyau. Ajoutez $(LIB_KVM) à votre liste de bibliothèques (par exemple, LIBS= -lintl $(LIB_KVM)), si votre cible utilise kvm.
LIB_MATH
une macro prédéfinie contenant le nom dépendant du système d'exploitation d'une bibliothèque nécessaire aux programmes qui utilisent les routines de la bibliothèque mathématique. Ajoutez $(LIB_MATH) à votre liste de bibliothèques (par exemple, LIBS= -lintl $(LIB_MATH)), si votre cible utilise des sous-routines mathématiques.
LIB_SOCKET
une macro prédéfinie contenant le nom dépendant du système d'exploitation d'une bibliothèque nécessaire aux programmes qui utilisent les appels socket. Ajoutez $(LIB_SOCKET) à votre liste de bibliothèques (par exemple, LIBS= -lintl $(LIB_SOCKET)), si votre cible utilise des sockets. Note : pour des raisons de portabilité, cela devrait même être fait sur les systèmes qui ne nécessitent pas de bibliothèque de sockets car ils ont l'interface de socket intégrée à libc.
LIBS_PATH
cette macro contient le chemin vers un répertoire où se trouvent les bibliothèques qui ont été construites lors d'une exécution de make dans le projet actuel.
Ne modifiez pas cette macro.
M_ARCH
cette macro contient l'architecture machine de la machine cible (par exemple, sun3 sun4 ip22 i86pc i586 9000-725 aviion). Elle est définie à la sortie de arch convertie en minuscules. Sur les systèmes où M_ARCH n'est pas disponible, elle est définie au contenu de K_ARCH.
Ne modifiez pas cette macro.
MK_FILES
les makefiles qui divergent dans des sous-makes dans le même répertoire doivent définir MK_FILES comme une liste de noms de makefiles pour les sous-makes. Les noms de makefiles pour les sous-makes doivent avoir un nom construit en ajoutant .mk au nom de base de la cible définie dans le makefile spécifique.
MAKEPROG
Définissez cette macro sur le nom de votre programme make s'il ne prend pas en charge la macro MAKE_NAME. Le programme make smake est capable de s'identifier. Si vous voulez utiliser un programme make qui n'est pas capable de s'identifier et dont le nom n'est pas make, définissez MAKEPROG sur le nom du programme make. Actuellement, seul gmake est pris en charge comme valeur alternative pour MAKEPROG. Si vous voulez utiliser un programme make non pris en charge, vous devrez vérifier s'il prend en charge les fonctionnalités nécessaires aux makefiles. Vous devrez écrire vos propres fichiers de règles pour ce programme make. Si vous voulez utiliser gmake, vous devriez exécuter setenv MAKEPROG gmake avant de lancer gmake ou utiliser un script shell qui s'en charge pour vous.
MAKE
Cette macro est configurée par le programme make. Elle contient un nom de chemin suffisant pour appeler récursivement le même programme make (soit le dernier composant du chemin, soit le chemin complet du programme make).
Ne modifiez pas cette macro.
MAKEFLAGS
Cette macro est configurée par le programme make. Elle contient les options de ligne de commande avec lesquelles make est appelé.
Ne modifiez pas cette macro.
MAKE_ARCH
Cette macro est actuellement configurée uniquement par smake. Elle contient l'architecture du processeur de la machine cible (par exemple, mc68020, sparc, pentium).
Ne modifiez pas cette macro.
MAKE_BRAND
Cette macro est actuellement configurée uniquement par smake. Elle contient la marque de la machine cible (par exemple, Sun_Microsystems(par exemple, ).
Ne modifiez pas cette macro.
MAKE_HOST
Cette macro est actuellement configurée uniquement par smake. Elle contient le nom d'hôte de la machine cible (par exemple, duffy, sherwood, ghost).
Ne modifiez pas cette macro.
MAKE_MACH
Cette macro est actuellement configurée uniquement par smake. Elle contient l'architecture du noyau de la machine cible (par exemple, sun3, sun4c, sun4m, sun4u).
Ne modifiez pas cette macro.
MAKE_MODEL
Cette macro est actuellement configurée uniquement par smake. Elle contient le nom du modèle de la machine cible (par exemple, SUNW,SPARCstation-20).
Ne modifiez pas cette macro.
MAKE_M_ARCH
Cette macro est actuellement configurée uniquement par smake. Elle contient l'architecture machine de la machine cible (par exemple, sun3, sun4).
Ne modifiez pas cette macro.
MAKE_NAME
Cette macro est actuellement configurée uniquement par smake. Elle contient le nom officiel du programme make (par exemple, make, smake, gmake).

MAKE_OS
Cette macro est actuellement configurée uniquement par smake. Elle contient le nom du système d'exploitation de la machine cible (par exemple, sunos, linux, dgux).

MAKE_OSDEFS
Cette macro est actuellement configurée uniquement par smake. Elle contient les définitions spécifiques du système d'exploitation pour le compilateur (par exemple, -D__SVR4).
Ne modifiez pas cette macro.
MAKE_OSREL
Cette macro est actuellement configurée uniquement par smake. Elle contient la version du système d'exploitation de la machine cible (par exemple, 5.5, 4.1.1).
Ne modifiez pas cette macro.
MAKE_OSVERSION

MAKE_SERIAL

Ne modifiez pas cette macro.
MANDIR
tous les makefiles pour les pages de manuel doivent définir cette macro sur le nom de chemin relatif à INS_BASE où le répertoire racine des pages de manuel pour le projet doit être. Les valeurs possibles pour les pages de manuel en anglais sont man ou share/man, les valeurs possibles pour les pages de manuel en allemand sont man/de ou share/man/de.

les makefiles pour les pages de manuel définissent cette macro sur le nom du fichier source troff pour la page de manuel

MARCH
Cette macro contient l'architecture de la machine cible (par exemple, sun3 sun4 ip22 i86pc i586 9000-725 aviion). Elle est définie à la sortie de arch convertie en minuscules. Sur les systèmes où M_ARCH n'est pas disponible, elle est définie au contenu de K_ARCH.
Ne modifiez pas cette macro sauf si vous souhaitez effectuer une compilation croisée.
O_ARCH
Cette macro contient le nom du système d'exploitation converti en minuscules. C'est généralement la sortie de : uname -s. Elle peut contenir un nom modifié si les règles de compilation pour différentes versions du système d'exploitation diffèrent (par exemple, sur SunOS et Solaris, le nom officiel du système d'exploitation est SunOS dans les deux cas).

Cette macro contient l'architecture du processeur pour la machine cible (par exemple, mc68020 mc88200 sparc pentium). Elle est définie à la sortie de uname -p convertie en minuscules. Sur les systèmes où P_ARCH n'est pas disponible, elle est définie au contenu de K_ARCH.
Ne modifiez pas cette macro.
PARCH
Cette macro contient l'architecture du processeur pour la machine cible (par exemple, mc68020 mc88200 sparc pentium). Elle est définie à la sortie de uname -p convertie en minuscules. Sur les systèmes où P_ARCH n'est pas disponible, elle est définie au contenu de K_ARCH.
Ne modifiez pas cette macro sauf si vous souhaitez effectuer une compilation croisée.
RULESDIR
La valeur de cette macro doit être définie avant l'inclusion du fichier de règles $(SRCROOT)/$(RULESDIR/rules.top. Si vous souhaitez tester le comportement d'une version modifiée des makefiles dans RULESDIR, placez une copie dans un répertoire alternatif, modifiez un ou plusieurs fichiers dedans, puis utilisez make avec une valeur différente de RULESDIR, qui pointe vers le répertoire alternatif.
RUNPATH
Est évaluée sur les systèmes où LD_RUN_PATH est supporté. Elle contient le chemin de recherche de bibliothèque par défaut pour les cibles liées dynamiquement à l'exécution. Ce chemin de recherche sera stocké à l'intérieur de la cible. Ceci est généralement défini dans le fichier $(DEFLTSROOT)/$(DEFLTSDIR)/Defaults ou $(DEFLTSROOT)/$(DEFLTSDIR)/Defaults.$(O_ARCH). Notez que les systèmes plus anciens utiliseront également LD_LIBRARY_PATH à cette fin.
SCRFILE
Cette macro doit être définie dans un makefile feuille pour que les scripts shell définissent la source de ce fichier script.
SRCFILE
Cette macro doit être définie dans un makefile feuille pour que les fichiers localisés définissent la source de ce fichier.
SRCROOT
Cette macro contient la position relative par rapport au répertoire racine source du projet. La valeur de cette macro doit être définie avant l'inclusion du fichier de règles $(SRCROOT)/$(RULESDIR/rules.top. SRCROOT doit être défini à ../.. si le makefile feuille approprié est situé deux niveaux de répertoire en dessous de la racine source.
SUBARCHDIR
Peut être défini pour placer les fichiers objet et la cible dans un répertoire différent de l'habituel. SUBARCHDIR modifiera la valeur de ARCHDIR. Si vous souhaitez créer une cible compilée pour dbx, vous pouvez utiliser : make COPTX=-g SUBARCHDIR=-dbx.
TARGET
Tous les makefiles, qui ne font pas référence à des cibles de bibliothèque ou à des sous-makes/sous-répertoires, doivent définir TARGET comme étant le nom du fichier de sortie de l'opération de liaison finale.
TARGETLIB
Tous les makefiles utilisés pour créer des bibliothèques doivent définir TARGETLIB comme étant la partie centrale de la bibliothèque cible. Si vous souhaitez créer par exemple libfoo, définissez TARGETLIB= foo. Ceci est nécessaire pour permettre aux systèmes d'exploitation d'avoir des conventions de nommage différentes pour les bibliothèques. Si vous créez une bibliothèque non partagée, l'exemple ci-dessus aboutirait à un nom de fichier : libfoo.a pour la cible réelle.
TARGETMAN
Cette macro doit être définie dans un makefile feuille pour les pages de manuel afin de définir le nom de base de cette page de manuel (sans le suffixe).
XMK_FILE
Les makefiles qui souhaitent installer des pages de manuel doivent définir XMK_FILE sur Makefile.man afin d'éviter d'avoir à installer un fichier make de diversion. Le fichier make trouvé dans XMK_FILE ne sera traité que si make est appelé avec la cible install.

DÉMARRAGE

Pour configurer un nouveau projet, copiez d'abord les répertoires RULES et TEMPLATES ainsi que tout leur contenu dans le répertoire racine du projet.

Copiez ensuite un makefile de niveau supérieur, un fichier Defaults et un fichier Targetdirs.archname dans le répertoire racine du projet.

Créez ensuite les répertoires suivants : cmd, lib, include.

Commencez maintenant à créer des répertoires cibles, par exemple sous cmd et lib. N'oubliez pas de créer un makefile et un fichier Targetdirs.archname approprié sur chaque répertoire nœud.

EXEMPLES

Si vous souhaitez configurer une copie privée de parties d'un projet, vous devez choisir un répertoire dans votre arborescence de répertoires qui deviendra la racine source du projet shadow. Créez ensuite des liens symboliques nommés RULES et TEMPLATES vers la racine source réelle. Si vous ne souhaitez pas modifier les fichiers d'inclusion globaux, créez également un lien symbolique vers le répertoire include, sinon copiez le répertoire include et son contenu. Copiez le makefile de niveau supérieur, le fichier Defaults et le fichier Targetdirs.archname.

Enfin, copiez l'arbre de sous-répertoires désiré avec tous les makefiles et les fichiers Targetdirs.archname qui se trouvent dans les répertoires au-dessus de votre partie du projet que vous souhaitez avoir séparément.

NOTES

La portée de ce manuel concerne uniquement l'utilisation des leaf makefiles. Si vous souhaitez apporter des modifications aux règles make, consultez le manuel makerules(4).

Les makefiles peuvent être utilisés avec Sunpro make, Gnu make et smake. Bien que Gnu make fonctionne sur de nombreuses plateformes, il ne dispose pas d'une sortie de débogage utile.

Utilisez Sunpro make ou smake si vous rencontrez des problèmes avec un makefile. Sunpro make et smake disposent tous deux d'une option -D, qui vous permet de visualiser les makefiles après la première expansion. Utilisez cette option si vous doutez que votre makefile soit correctement expansé et que les bonnes règles soient incluses. Il existe également une option -d qui fournit une sortie de débogage pendant l'exécution de make. Si vous souhaitez plus de sortie, utilisez -dd, -ddd, etc.

Smake dispose d'une option -xM qui vous montre la dépendance d'inclusion pour les règles make.
