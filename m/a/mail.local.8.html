MAIL.LOCAL(8) Manuel de l'administrateur système MAIL.LOCAL(8)

NOM

mail.local — stocker le courrier dans une boîte aux lettres

SYNTAXE

mail.local [-Ll] [-f expéditeur] utilisateur ...

DESCRIPTION

mail.local lit l'entrée standard jusqu'à la fin du fichier et l'ajoute au fichier mail de chaque utilisateur. L'utilisateur doit être un nom d'utilisateur valide.

Les options sont les suivantes :

-f expéditeur
Spécifier le nom de l'expéditeur.
-L
Ne pas créer de fichier nomutilisateur.lock lors du verrouillage du spool.
-l
Pour des raisons de compatibilité, demander que les fichiers nommés nomutilisateur.lock soient utilisés pour le verrouillage. (C'est le comportement par défaut.)

Les messages individuels dans la boîte aux lettres sont délimités par une ligne vide suivie d'une ligne commençant par la chaîne “From ”. Une ligne contenant la chaîne “From ”, le nom de l'expéditeur et un horodatage est ajoutée en préfixe à chaque message de courrier livré. Une ligne vide est ajoutée à chaque message. Un caractère supérieur à (‘>’) est ajouté en préfixe à toute ligne du message qui pourrait être confondue avec une ligne délimiteur “From ”.

Des efforts considérables ont été faits pour garantir que mail.local agisse aussi sûrement que possible si le répertoire de spool a les permissions 1777 ou 755. La valeur par défaut de 755 est plus sûre, mais elle empêche les clients de courrier d'utiliser le verrouillage de type nomutilisateur.lock. L'utilisation de 1777 est plus flexible dans un environnement de spool partagé NFS, donc de nombreux sites l'utilisent. Cependant, cela comporte certains risques, tels que des attaquants remplissant le disque de spool. Certains de ces problèmes peuvent être atténués en faisant du spool un système de fichiers séparé, et en y appliquant des quotas. L'utilisation de tout mode autre que 1777 et 755 pour le répertoire de spool est déconseillée mais peut fonctionner correctement.

La boîte aux lettres est toujours verrouillée en utilisant flock(2) pendant que le courrier est ajouté. À moins que le drapeau -L ne soit spécifié, un fichier nomutilisateur.lock est également utilisé.

Si le service biff(1) est retourné par getservbyname(3), le serveur biff est notifié du courrier livré.

ENVIRONNEMENT

TZ
Utilisé pour définir le fuseau horaire approprié sur l'horodatage.

FICHIERS

/tmp/local.XXXXXXXXXX
fichiers temporaires
/var/mail/utilisateur
répertoire de la boîte aux lettres de l'utilisateur

STATUT DE SORTIE

L'utilitaire mail.local se termine avec succès (0) en cas de succès, et (>0) en cas d'erreur.

VOIR AUSSI

biff(1), mail(1), flock(2), getservbyname(3), comsat(8), smtpd(8)

HISTORIQUE

Un sur-ensemble de mail.local (gérant la lecture des boîtes aux lettres ainsi que la livraison du courrier) est apparu dans Version 7 AT&T UNIX sous le nom de programme mail(1).

BOGUES

L'utilisation de quotas dans /var/mail peut poser problème si vous utilisez sendmail(8) comme MTA, car il demande à mail.local de livrer un message à plusieurs destinataires si possible. Cela pose des problèmes dans un environnement de quotas car un message peut être livré à certains utilisateurs mais pas à d'autres en raison des quotas de disque. Même si le message a été livré à certains des destinataires, mail.local se terminera avec un code de sortie > 0, ce qui amène sendmail(8) à tenter une nouvelle livraison plus tard. Cela signifie que certains utilisateurs continueront de recevoir le même message à chaque fois que sendmail(8) exécutera sa file d'attente. Ce problème n'existe pas pour les utilisateurs de smtpd(8).

Si vous exécutez sendmail(8) et avez des quotas de disque sur /var/mail, il est impératif de désactiver l'indicateur de mailer “m” pour le mailer ‘local’. Pour ce faire, localisez la ligne commençant par “Mlocal” dans /etc/mail/sendmail.cf et supprimez le “m” de la section des drapeaux, dénotée par “F=”. Alternativement, vous pouvez outrepasser les drapeaux de mailer par défaut en ajoutant la ligne :

define(`LOCAL_MAILER_FLAGS', `rn9S')dnl

à votre fichier “.mc” (c'est le fichier source qui est utilisé pour générer /etc/mail/sendmail.cf).
