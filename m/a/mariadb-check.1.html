MARIADB-CHECK(1) Système de base de données MariaDB MARIADB-CHECK(1)

NOM

mariadb-check - programme de maintenance de tables (mariadb-check est maintenant un lien symbolique vers mariadb-check)

SYNTAXE

mariadb-check [options] [nom_db [nom_tbl ...]]

DESCRIPTION

Le client mariadb-check effectue la maintenance des tables : il vérifie, répare, optimise ou analyse les tables.

Chaque table est verrouillée et donc indisponible pour les autres sessions pendant son traitement, bien que pour les opérations de vérification, la table ne soit verrouillée qu'en lecture. Les opérations de maintenance des tables peuvent prendre du temps, en particulier pour les grandes tables. Si vous utilisez l'option --databases ou --all-databases pour traiter toutes les tables d'une ou plusieurs bases de données, une invocation de mariadb-check peut prendre un temps considérable. (Ceci est également vrai pour mariadb-upgrade car ce programme invoque mariadb-check pour vérifier toutes les tables et les réparer si nécessaire.)

mariadb-check est fonctionnellement similaire à myisamchk, mais fonctionne différemment. La principale différence opérationnelle est que mariadb-check doit être utilisé lorsque le serveur mariadbd est en cours d'exécution, tandis que myisamchk doit être utilisé lorsqu'il ne l'est pas. L'avantage d'utiliser mariadb-check est que vous n'avez pas besoin d'arrêter le serveur pour effectuer la maintenance des tables.

mariadb-check utilise les instructions SQL CHECK TABLE, REPAIR TABLE, ANALYZE TABLE et OPTIMIZE TABLE de manière pratique pour l'utilisateur. Il détermine quelles instructions utiliser pour l'opération que vous souhaitez effectuer, puis envoie les instructions au serveur pour exécution.

Le moteur de stockage MyISAM prend en charge les quatre opérations de maintenance, de sorte que mariadb-check peut être utilisé pour effectuer l'une d'entre elles sur des tables MyISAM. D'autres moteurs de stockage ne prennent pas nécessairement en charge toutes les opérations. Dans ce cas, un message d'erreur est affiché. Par exemple, si test.t est une table MEMORY, une tentative de vérification produit ce résultat :

shell> mariadb-check test t
test.t
note     : Le moteur de stockage de la table ne prend pas en charge la vérification

Si mariadb-check ne parvient pas à réparer une table, consultez la base de connaissances MariaDB pour les stratégies de réparation manuelle des tables. Ce sera le cas, par exemple, pour les tables InnoDB, qui peuvent être vérifiées avec CHECK TABLE, mais pas réparées avec REPAIR TABLE.

L'utilisation de mariadb-check avec des tables partitionnées n'est pas prise en charge.


Attention

Il est préférable de sauvegarder une table avant d'effectuer une opération de réparation de table ; dans certaines circonstances, l'opération peut entraîner une perte de données. Les causes possibles incluent, sans s'y limiter, les erreurs du système de fichiers.

Il existe trois façons générales d'invoquer mariadb-check :

shell> mariadb-check [options] nom_db [nom_tbl ...]
shell> mariadb-check [options] --databases nom_db ...
shell> mariadb-check [options] --all-databases

Si vous ne nommez aucune table après nom_db ou si vous utilisez l'option --databases ou --all-databases, les bases de données entières sont vérifiées.

mariadb-check a une fonctionnalité spéciale par rapport aux autres programmes clients. Le comportement par défaut de vérification des tables (--check) peut être modifié en renommant le binaire. Si vous souhaitez avoir un outil qui répare les tables par défaut, il suffit de faire une copie de mariadb-check nommée mariadb-repair, ou de créer un lien symbolique vers mariadb-check nommé mariadb-repair. Si vous invoquez mariadb-repair, il répare les tables.

Les noms suivants peuvent être utilisés pour modifier le comportement par défaut de mariadb-check.

mariadb-repair L'option par défaut est --repair
mysqlanalyze L'option par défaut est --analyze
mysqloptimize L'option par défaut est --optimize

mariadb-check prend en charge les options suivantes, qui peuvent être spécifiées en ligne de commande ou dans les groupes de fichiers d'options [mariadb-check] et [client]. Les options -c, -r, -a et -o sont mutuellement exclusives.

•--help, -?

Affiche un message d'aide et quitte.

•--all-databases, -A

Vérifie toutes les tables de toutes les bases de données. Ceci est équivalent à utiliser l'option --databases et à nommer toutes les bases de données sur la ligne de commande.

•--all-in-1, -1

Au lieu d'émettre une instruction pour chaque table, exécute une seule instruction pour chaque base de données qui nomme toutes les tables de cette base de données à traiter.

•--analyze, -a

Analyse les tables.

•--auto-repair

Si une table vérifiée est corrompue, la corrige automatiquement. Toutes les réparations nécessaires sont effectuées après la vérification de toutes les tables.

•--character-sets-dir=chemin

Le répertoire où sont installés les jeux de caractères.

•--check, -c

Vérifie les tables pour les erreurs. C'est l'opération par défaut.

•--check-only-changed, -C

Vérifie uniquement les tables qui ont changé depuis la dernière vérification ou qui n'ont pas été correctement fermées.

•--check-upgrade, -g

Invoque CHECK TABLE avec l'option FOR UPGRADE pour vérifier les tables d'incompatibilités avec la version actuelle du serveur. Cette option active automatiquement les options --fix-db-names et --fix-table-names.

•--compress

Compresse toutes les informations envoyées entre le client et le serveur si les deux prennent en charge la compression.

•--databases, -B

Traite toutes les tables des bases de données nommées. Normalement, mariadb-check traite le premier argument de nom sur la ligne de commande comme un nom de base de données et les noms suivants comme des noms de tables. Avec cette option, il traite tous les arguments de nom comme des noms de bases de données.

•--debug[=options_debug], -# [options_debug]

Écrit un journal de débogage. Une chaîne typique options_debug est 'd:t:o,nom_fichier'. La valeur par défaut est 'd:t:o'.

•--debug-check

Affiche des informations de débogage lors de la sortie du programme.

•--debug-info

Affiche des informations de débogage et des statistiques d'utilisation de la mémoire et du processeur lors de la sortie du programme.

•--default-auth=nom

Plugin d'authentification client par défaut à utiliser.

•--default-character-set=nom_jeu_caract

Utilise nom_jeu_caract comme jeu de caractères par défaut.

•--defaults-extra-file=nom_fichier

Définit nom_fichier comme fichier à lire pour les options par défaut après la lecture des fichiers de configuration globaux. Doit être donné comme première option.

•--defaults-file=nom_fichier

Définit nom_fichier comme fichier à lire pour les options par défaut, remplaçant les fichiers de configuration globaux. Doit être donné comme première option.

•--extended, -e

Si vous utilisez cette option pour vérifier les tables, elle assure qu'elles sont cohérentes à 100 % mais prend beaucoup de temps.

Si vous utilisez cette option pour réparer les tables, elle forcera l'utilisation de l'ancienne méthode de réparation lente avec le cache des clés, au lieu de la réparation beaucoup plus rapide par tri.

•--fast, -F

Vérifie uniquement les tables qui n'ont pas été correctement fermées.

•--fix-db-names

Convertit les noms de bases de données au format utilisé depuis MySQL 5.1. Seuls les noms de bases de données contenant des caractères spéciaux sont affectés.

•--fix-table-names

Convertit les noms de tables (y compris les vues) au format utilisé depuis MySQL 5.1. Seuls les noms de tables contenant des caractères spéciaux sont affectés.

•--flush,

Vide chaque table après

OPTIONS

•--check, -c

Check the tables. This is useful if you don't want to have the checked tables take up space in the caches after the check.

•--force, -f

Continue even if an SQL error occurs.

•--host=nom_hote, -h nom_hote

Connect to the MariaDB server on the specified host.

•--medium-check, -m

Perform a check that is faster than an --extended operation. This finds only 99.99% of all errors, which should be good enough in most cases.

•--no-defaults

Do not read default options from any option file. This must be given as the first argument.

•--optimize, -o

Optimize the tables.

•--password[=mot_de_passe], -p[mot_de_passe]

The password to use when connecting to the server. If you use the short option form (-p), you cannot have a space between the option and the password. If you omit the mot_de_passe value following the --password or -p option on the command line, mariadb-check will prompt for one.

Specifying a password on the command line should be considered insecure. You can use an option file to avoid giving the password on the command line.

•--persistent, -Z

Used with ANALYZE TABLE to append the option PERSISTENT FOR ALL.

•--pipe, -W

On Windows, connect to the server via a named pipe. This option applies only if the server supports named-pipe connections.

•--plugin-dir=nom


Directory for client-side plugins.

•--port=num_port, -P num_port

The TCP/IP port number to use for the connection. Forces --protocol=tcp when specified on the command line without other connection properties.

•--print-defaults

Print the program argument list and exit. This must be given as the first argument.

•--process-tables

Perform the requested operation on tables. Defaults to on; use --skip-process-tables to disable.

•--process-views=valeur

Perform the requested operation (only CHECK VIEW or REPAIR VIEW). Possible values are NO, YES (correct the checksum, if necessary, add the mariadb-version field), UPGRADE_FROM_MYSQL (same as YES and toggle the algorithm MERGE<->TEMPTABLE.

•--protocol={TCP|SOCKET|PIPE|MEMORY}

The connection protocol to use for connecting to the server. It is useful when the other connection parameters normally would cause a protocol to be used other than the one you want.

•--quick, -q

If you are using this option to check tables, it prevents the check from scanning the rows to check for incorrect links. This is the fastest check method.

If you are using this option to repair tables, it tries to repair only the index tree. This is the fastest repair method.

•--repair, -r

Perform a repair that can fix almost anything except unique keys that are not unique.

•--silent, -s

Silent mode. Print only error messages.

•--skip-database=nom_db

Don't process the database (case-sensitive) specified as argument.

•--socket=chemin, -S chemin

For connections to localhost, the Unix socket file to use, or, on Windows, the name of the named pipe to use. Forces --protocol=socket when specified on the command line without other connection properties; on Windows, forces --protocol=pipe.

•--ssl

Enable SSL for connection (automatically enabled with other flags). Disable with --skip-ssl.

•--ssl-ca=nom

CA file in PEM format (check OpenSSL docs, implies --ssl).

•--ssl-capath=nom

CA directory (check OpenSSL docs, implies --ssl).

•--ssl-cert=nom

X509 cert in PEM format (check OpenSSL docs, implies --ssl).

•--ssl-cipher=nom

SSL cipher to use (check OpenSSL docs, implies --ssl).

•--ssl-key=nom

X509 key in PEM format (check OpenSSL docs, implies --ssl).

•--ssl-crl=nom

Certificate revocation list (check OpenSSL docs, implies --ssl).

•--ssl-crlpath=nom

Certificate revocation list path (check OpenSSL docs, implies --ssl).

•--ssl-verify-server-cert

Verify server's "Common Name" in its cert against hostname used when connecting. This option is disabled by default.

•--tables

Override the --databases or -B option. All name arguments following the option are regarded as table names.

•--use-frm

For repair operations on MyISAM tables, get the table structure from the .frm file so that the table can be repaired even if the .MYI header is corrupted.

•--user=nom_utilisateur, -u nom_utilisateur

The MariaDB user name to use when connecting to the server.

•--verbose, -v

Verbose mode. Print information about the various stages of program operation. Using one --verbose option will give you more information about what mariadb-check is doing.

Using two --verbose options will also give you connection information.

Using it 3 times will print out all CHECK, RENAME and ALTER TABLE during the check phase.

•--version, -V

Display version information and exit.

•--write-binlog

This option is enabled by default, so that ANALYZE TABLE, OPTIMIZE TABLE, and REPAIR TABLE statements generated by mariadb-check are written to the binary log. Use --skip-write-binlog to cause NO_WRITE_TO_BINLOG to be added to the statements so that they are not logged. Use the --skip-write-binlog when these statements should not be sent to replication slaves or run when using the binary logs for recovery from backup.
