MAILPOST(8) Documentation InterNetNews MAILPOST(8)

NOM

mailpost - Introduire un message électronique dans un newsgroup

SYNTAXE

mailpost [-hn] [-a addr] [-b base de données] [-c temps d'attente] [-d distribution] [-f addr] [-m liste de diffusion] [-o commande de sortie] [-p port] [-r addr] [-t répertoire temporaire] [-x en-tête[:en-tête...]] [-z en-tête[:en-tête...]] nouveaux groupes

DESCRIPTION

Le programme mailpost lit un message électronique correctement formaté depuis l'entrée standard et le transmet à inews pour publication sur un serveur de news. nouveaux groupes est une liste de noms de groupes séparés par des espaces blancs, dans lesquels l'article doit être publié (au moins un newsgroup doit être spécifié).

Avant de transmettre l'article à inews, il vérifie que l'article n'a pas déjà été vu, et il modifie certains champs d'en-tête (nettoyage de certains champs d'en-tête d'adresse, suppression de quelques-uns comme X-Complaints-To et X-Trace, et ajout de "X-" devant les champs d'en-tête inconnus). Les champs d'en-tête Received et *-To sont également modifiés pour éviter de spammer la passerelle (le nom du serveur de news ou le nom de domaine défini dans fromhost, pathhost et domain dans inn.conf sont supprimés).

Si l'article a déjà été vu (mailpost enregistre l'ID du message de chaque article qu'il traite), alors l'article sera rejeté avec un statut d'erreur non nul. D'autres erreurs provoqueront l'envoi de l'article par courrier électronique au newsmaster (sélectionné lors de la configuration et par défaut "usenet").

Normalement, mailpost est exécuté par sendmail(8) via une entrée d'alias :

local-mail-wreck-bikes: "|<chemin/vers/bin dans inn.conf>/mailpost
    -b /var/spool/mailpost -t /tmp -d local local.bicycles.racing"

Les indicateurs -b et -t sont utiles pour changer les répertoires utilisés par mailpost par défaut. En fait, bien qu'il soit recommandé d'exécuter mailpost en tant qu'utilisateur des news, il est souvent exécuté sous un autre utilisateur, notamment l'utilisateur de messagerie. Par conséquent, vous devez vous assurer de créer et de définir comme accessibles en écriture par l'utilisateur sous lequel mailpost s'exécute les répertoires où placer la base de données et les fichiers temporaires. De plus, mailpost doit être exécutable par cet utilisateur.

Au lieu de /var/spool/mailpost, le répertoire de la file d'attente de messagerie peut être spécifié, ou tout autre répertoire où le processus mailpost a un accès en écriture.

Une pratique courante pour faire passer un newsgroup vers une liste de diffusion est de créer un newsgroup modéré (en exécutant par exemple la commande "ctlinnd newgroup local.bicycles.racing m") et de définir l'adresse de modération pour ce newsgroup dans le fichier moderators de pathetc à l'adresse de la liste de diffusion. Si vous ajoutez un indicateur -a dans l'exemple ci-dessus, alors d'une part, lorsqu'un message est envoyé à la liste de diffusion, mailpost sera exécuté, le marquera comme approuvé, et le message atteindra directement le newsgroup. D'autre part, lorsqu'un message est publié dans le newsgroup, il n'a normalement pas de champ d'en-tête Approved, il sera donc envoyé (par nnrpd) à l'adresse de la liste de diffusion configurée dans le fichier moderators, ce qui signifie que le message atteint la liste de diffusion et, comme tout autre message posté à la liste de diffusion, il sera traité par mailpost, approuvé, et atteindra finalement le newsgroup.

OPTIONS

-a addr
Si l'indicateur -a est utilisé, addr (qui est généralement l'adresse e-mail de l'expéditeur) est ajoutée à l'article comme corps d'un champ d'en-tête Approved. C'est utile si l'un des newsgroups auxquels l'article doit être publié est modéré. (Bien sûr, cet indicateur ne doit être ajouté que si vous êtes censé auto-approuver vos publications.)

Assurez-vous que la connexion du lecteur établie par inews pour publier l'article est autorisée à publier des articles approuvés (voir la lettre "A" dans le paramètre access des blocs d'accès dans readers.conf).

-b base de données
Si l'indicateur -b est utilisé, il définit alors l'emplacement de la base de données persistante utilisée pour stocker les IDs de messages des articles envoyés. Ceci est destiné à empêcher les boucles d'articles si une passerelle news-vers-mail les renvoie ici. Cette option peut être requise si le processus mailpost n'a pas d'accès en écriture au répertoire de la base de données des news (notamment lorsqu'il est exécuté en tant qu'utilisateur de messagerie). La valeur par défaut est pathdb tel que défini dans inn.conf.

Assurez-vous que l'emplacement spécifié existe et est accessible en écriture par l'utilisateur sous lequel mailpost s'exécute.

-c temps d'attente
L'indicateur -c indique une durée de sommeil avant de publier. Si des messages en double sont reçus pendant cet intervalle (par toute instance de mailpost utilisant la même base de données), l'article n'est publié qu'une seule fois, mais avec le champ d'en-tête Newsgroups modifié pour faire une crosspost de l'article vers tous les groupes indiqués. Les unités pour temps d'attente sont les secondes ; une valeur raisonnable peut se situer entre des dizaines et des centaines de secondes, voire plus, en fonction de la durée de latence possible des e-mails vers votre système.
-d distribution
Si l'indicateur -d est utilisé, la valeur donnée est ajoutée à l'article comme corps du champ d'en-tête Distribution.
-f addr
L'indicateur -f est un synonyme de l'indicateur -r.
-h
Affiche les informations d'utilisation et quitte.
-m liste de diffusion
Si l'indicateur -m est utilisé, la valeur donnée est ajoutée à l'article dans un champ d'en-tête List-ID, si un tel champ d'en-tête n'existe pas déjà.
-n
Si l'indicateur -n est utilisé, aucun article n'est publié ni aucun courrier n'est envoyé en cas d'erreur. Tout est écrit sur la sortie standard.
-o commande de sortie
Spécifie le programme auquel l'article résultant traité par mailpost doit être envoyé. À des fins de débogage, "-o cat" peut être utilisé. La valeur par défaut est "inews -S -h".
-p port
Spécifie le port sur lequel nnrpd écoute, utilisé pour la publication d'articles. Si fourni, -p est passé à inews.
-r addr
Une heuristique est utilisée pour déterminer une valeur raisonnable pour le corps du champ d'en-tête Path. L'indicateur -r indique ce qui doit être utilisé si aucune autre valeur ne peut être déterminée.
-t répertoire temporaire
Si l'indicateur -t est utilisé, il définit alors l'emplacement du répertoire à utiliser pour stocker temporairement les messages d'erreur envoyés au newsmaster. Cette option peut être requise si la valeur par défaut fait référence à un chemin qui n'existe pas ou si le processus mailpost n'y a pas d'accès en écriture (notamment lorsqu'il est exécuté en tant qu'utilisateur de messagerie). Deux chemins sont essayés par défaut : pathtmp tel que défini dans inn.conf, puis /var/tmp si pathtmp n'est pas accessible en écriture.

Assurez-vous que l'emplacement spécifié existe et est accessible en écriture par l'utilisateur sous lequel mailpost s'exécute.

-x en-tête[:en-tête...]
Une liste d'en-têtes supplémentaires séparés par des deux-points qui doivent être traités comme des en-têtes connus ; ces en-têtes seront transmis à inews sans avoir de "X-" ajouté devant.

Par défaut, les en-têtes connus sont :

Archive
Archived-At
Comments
Content-*
Date
Distribution
From
Injection-Date
Keywords
List-ID
Message-ID
MIME-*
Organization
References
Return-Path
Sender
Subject
Summary
-z en-tête[:en-tête...]
Une liste d'en-têtes supplémentaires séparés par des deux-points qui doivent être supprimés.

Par défaut, les en-têtes supprimés sont :

X-Complaints-To
X-Trace

FICHIERS

pathbin/mailpost
Le script Perl lui-même utilisé pour alimenter un message électronique dans un newgroup.
pathdb/mailpost-msgid.dir et pathdb/mailpost-msgid.pag
Les fichiers de base de données par défaut qui enregistrent les message-IDs précédemment vus.
