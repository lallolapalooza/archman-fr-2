MAC-VENDOR(5) Manuel des formats de fichiers MAC-VENDOR(5)

NOM

mac-vendor - Fichier de vendeurs Ethernet pour arp-scan

SYNTAXE

mac-vendor.txt

DESCRIPTION

Le fichier mac-vendor.txt contient des correspondances entre les adresses MAC Ethernet et les chaînes de vendeurs pour arp-scan. Il est utilisé en plus des listes OUI de l'IEEE dans ieee-oui.txt. Il est destiné aux correspondances MAC-vendeur qui ne sont pas couvertes par les listes de fabricants de l'IEEE.

Chaque ligne du fichier mac-vendor.txt contient une correspondance MAC-vendeur sous la forme :

<PrefixeMAC><TABULATION><Vendeur>

Où <PrefixeMAC> est le préfixe de l'adresse MAC en hexadécimal, et <Vendeur> est le nom du vendeur. Le préfixe peut avoir n'importe quelle longueur, de deux chiffres hexadécimaux (un octet) à douze chiffres hexadécimaux (six octets, l'adresse matérielle Ethernet complète).

Les caractères hexadécimaux alphabétiques [A-F] peuvent être en majuscules ou en minuscules, et les symboles séparateurs tels que « : », « - » et « . » sont ignorés. Cela permet l'utilisation d'adresses MAC au format standard dans ce fichier.

Par exemple :

01:23:45 correspond à 01:23:45:xx:xx:xx, où xx représente n'importe quelle valeur ;
01:23:45:6 correspond à 01:23:45:6x:xx:xx ; et
01:23:45:67 correspond à 01:23:45:67:xx:xx.

N'incluez pas d'entrées des listes OUI de l'IEEE, car celles-ci sont déjà dans le fichier ieee-oui.txt, qui est automatiquement utilisé par arp-scan. Voir get-oui(1) pour plus de détails sur la façon de mettre à jour les listes OUI.

L'ordre des entrées dans le fichier n'a pas d'importance.

Les lignes vides et les lignes commençant par « # » sont ignorées. arp-scan tentera de faire correspondre les préfixes les plus longs avant d'essayer de faire correspondre les plus courts, et s'arrêtera à la première correspondance.

FICHIERS

/usr/local/share/arp-scan/mac-vendor.txt

EXEMPLE

# Rapport de bug Debian sur nmap #369681 daté du 31 mai 2006
52:54:00        QEMU
b0:c4:20        Bochs
# De la RFC 2338 : 00-00-5E-00-01-{VRID}
00:00:5e:00:01  VRRP (le dernier octet est le VRID)
# WLBS de Microsoft (Windows NT Load Balancing Service)
# http://www.microsoft.com/technet/prodtechnol/acs/reskit/acrkappb.mspx
02:bf   Microsoft WLBS (les quatre derniers octets sont l'adresse IP)
# HSRP de Cisco (Hot Standby Routing Protocol)
# 00-00-0c-07-ac-XX, où XX est le numéro de groupe HSRP (0 à 255)
00:00:0c:07:ac  HSRP (le dernier octet est le numéro de groupe)
