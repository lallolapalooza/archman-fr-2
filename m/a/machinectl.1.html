MACHINECTL(1) machinectl MACHINECTL(1)

NOM

machinectl - Contrôler le gestionnaire de machines systemd

SYNOPSIS

machinectl [OPTIONS...] {COMMANDE} [NOM...]

DESCRIPTION

machinectl peut être utilisé pour introspecter et contrôler l'état du gestionnaire d'enregistrement de conteneurs et de machines virtuelles systemd(1), systemd-machined.service(8).

machinectl peut être utilisé pour exécuter des opérations sur des machines et des images. Les machines dans ce sens sont considérées comme des instances en cours d'exécution de :

•Machines virtuelles (VM) qui virtualisent le matériel pour exécuter des instances complètes de système d'exploitation (OS) (y compris leurs noyaux) dans un environnement virtualisé au-dessus de l'OS hôte.
•Conteneurs qui partagent le matériel et le noyau de l'OS avec l'OS hôte, afin d'exécuter des instances utilisateur de l'OS au-dessus de l'OS hôte.
•Le système hôte lui-même.

Les machines sont identifiées par des noms qui suivent les mêmes règles que les noms d'hôte UNIX et DNS. Pour plus de détails, voir ci-dessous.

Les machines sont instanciées à partir d'images de disque ou de système de fichiers qui fréquemment — mais pas nécessairement — portent le même nom que les machines qui en sont exécutées. Les images dans ce sens peuvent être :

•Arbres de répertoires contenant un OS, y compris les répertoires de niveau supérieur /usr/, /etc/, etc.
•Sous-volumes btrfs contenant des arbres d'OS, similaires aux arbres de répertoires réguliers.
•Fichiers image disque binaires "bruts" contenant des tables de partitions MBR ou GPT et des systèmes de fichiers Linux.
•De même, des périphériques bloc contenant des tables de partitions MBR ou GPT et des systèmes de fichiers.
•L'arbre du système de fichiers de l'OS hôte lui-même.

Les images peuvent être téléchargées, importées et exportées via l'outil importctl(1).

COMMANDES

Les commandes suivantes sont comprises :

Commandes Machine

list

Liste les machines virtuelles et conteneurs en cours d'exécution (en ligne). Pour énumérer les images de machines qui peuvent être démarrées, utilisez list-images (voir ci-dessous). Notez que cette commande masque la machine spéciale ".host" par défaut. Utilisez l'option --all pour l'afficher.

Ajouté en version 206.

status NOM...

Affiche les informations d'état d'exécution d'une ou plusieurs machines virtuelles et conteneurs, suivies des données de journal les plus récentes du journal. Cette fonction est destinée à générer une sortie lisible par l'homme. Si vous recherchez une sortie analysable par ordinateur, utilisez plutôt show. Notez que les données de journal affichées sont rapportées par le gestionnaire de machine virtuelle ou de conteneur, et contiennent fréquemment la sortie console de la machine, mais pas nécessairement le contenu du journal de la machine elle-même.

Ajouté en version 206.

show [NOM...]

Affiche les propriétés d'une ou plusieurs machines virtuelles ou conteneurs enregistrés, ou du gestionnaire lui-même. Si aucun argument n'est spécifié, les propriétés du gestionnaire seront affichées. Si un NOM est spécifié, les propriétés de cette machine virtuelle ou de ce conteneur sont affichées. Par défaut, les propriétés vides sont supprimées. Utilisez --all pour les afficher également. Pour sélectionner des propriétés spécifiques à afficher, utilisez --property=. Cette commande est destinée à être utilisée chaque fois qu'une sortie analysable par ordinateur est requise, et n'affiche pas l'arbre des groupes de contrôle ni les entrées du journal. Utilisez status si vous recherchez une sortie formatée lisible par l'homme.

Ajouté en version 206.

start NOM...

Démarre un conteneur en tant que service système, en utilisant systemd-nspawn(1). Cela démarre systemd-nspawn@.service, instancié pour le nom de machine spécifié, similaire à l'effet de systemctl start sur le nom du service. systemd-nspawn recherche une image de conteneur par le nom spécifié dans /var/lib/machines/ (et d'autres chemins de recherche, voir ci-dessous) et l'exécute. Utilisez list-images (voir ci-dessous) pour lister les images de conteneurs disponibles à démarrer.

Notez que systemd-machined.service(8) interagit également avec une variété d'autres gestionnaires de conteneurs et de VM, systemd-nspawn n'est qu'une de ses implémentations. La plupart des commandes disponibles dans machinectl peuvent être utilisées sur des conteneurs ou des VM contrôlés par d'autres gestionnaires, pas seulement systemd-nspawn. Le démarrage d'images de VM et de conteneurs sur ces gestionnaires nécessite des outils spécifiques au gestionnaire.

Pour démarrer interactivement un conteneur en ligne de commande avec un accès complet à la console du conteneur, veuillez invoquer systemd-nspawn directement. Pour arrêter un conteneur en cours d'exécution, utilisez machinectl poweroff.

Ajouté en version 219.

login [NOM]

Ouvre une session de connexion interactive par terminal dans un conteneur ou sur l'hôte local. Si un argument est fourni, il fait référence à la machine conteneur à laquelle se connecter. S'il n'y en a pas de spécifié, ou si le nom du conteneur est spécifié comme une chaîne vide, ou si le nom de machine spécial ".host" (voir ci-dessous) est spécifié, la connexion est établie sur l'hôte local à la place. Cela créera une connexion TTY vers un conteneur spécifique ou l'hôte local et demandera l'exécution d'un getty dessus. Notez que ce n'est pris en charge que pour les conteneurs exécutant systemd(1) comme système d'init.

Cette commande ouvrira une invite de connexion complète sur le conteneur ou l'hôte local, qui demandera ensuite le nom d'utilisateur et le mot de passe. Utilisez shell (voir ci-dessous) ou systemd-run(1) avec l'option --machine= pour invoquer directement une commande unique, de manière interactive ou en arrière-plan.

Ajouté en version 209.

shell [[NOM@]NOM [CHEMIN [ARGUMENTS...]]]

Ouvre une session shell interactive dans un conteneur ou sur l'hôte local. Le premier argument fait référence à la machine conteneur à laquelle se connecter. S'il n'y en a pas de spécifié, ou si le nom de la machine est spécifié comme une chaîne vide, ou si le nom de machine spécial ".host" (voir ci-dessous) est spécifié, la connexion est établie sur l'hôte local à la place. Cela fonctionne de manière similaire à login, mais invoque immédiatement un processus utilisateur. Cette commande exécute l'exécutable spécifié avec les arguments spécifiés, ou le shell par défaut de l'utilisateur si aucun n'est spécifié, ou /bin/sh si aucun shell par défaut n'est trouvé. Par défaut, --uid=, ou en préfixant le nom de la machine avec un nom d'utilisateur et un caractère "@", un utilisateur différent peut être sélectionné. Utilisez --setenv= pour définir des variables d'environnement pour le processus exécuté.

Notez que machinectl shell ne propage pas le code de sortie/statut du processus shell invoqué. Utilisez plutôt systemd-run si ces informations sont requises (voir ci-dessous).

L'utilisation de la commande shell sans arguments (invoquant ainsi le shell ou la commande exécuté sur l'hôte local), est à bien des égards similaire à une session su(1), mais, contrairement à su, isole complètement la nouvelle session de la session d'origine, de sorte qu'elle ne partage aucune propriété de processus ou de session et se trouve dans un état propre et bien défini. Elle sera suivie dans de nouvelles sessions utmp, login, audit, security et keyring, et n'héritera d'aucune variable d'environnement ou limite de ressources, parmi d'autres propriétés.

Notez que systemd-run(1) avec son option --machine= peut être utilisé à la place de la commande machinectl shell, et permet une opération non interactive, une configuration plus détaillée et de bas niveau de l'unité invoquée, ainsi que l'accès aux informations d'exécution et de code de sortie/statut du processus invoqué. En particulier, utilisez l'option --wait de systemd-run pour propager les informations de statut de sortie du processus invoqué. Utilisez l'option --pty de systemd-run pour acquérir un shell interactif, de manière similaire à machinectl shell. En général, systemd-run est préférable à des fins de scripting. Cependant, notez que systemd-run peut nécessiter des privilèges plus élevés que machinectl shell.

Ajouté en version 225.

enable NOM..., disable NOM...

Active ou désactive un conteneur en tant que service système pour qu'il démarre au démarrage du système, en utilisant systemd-nspawn(1). Cela active ou désactive systemd-nspawn@.service, instancié pour le nom de machine spécifié, de manière similaire à l'effet de systemctl enable ou systemctl disable sur le nom du service.

Ajouté en version 219.

terminate NOM...

Termine un conteneur en cours d'exécution, en utilisant systemd-nspawn(1). Cela arrête systemd-nspawn@.service, instancié pour le nom de machine spécifié, de manière similaire à l'effet de systemctl stop sur le nom du service. Ceci est un arrêt immédiat, sans aucune possibilité de fermeture propre. Pour un arrêt propre, utilisez poweroff.

Ajouté en version 219.

kill NOM...

Envoie un signal au processus principal d'un conteneur en cours d'exécution, en utilisant systemd-nspawn(1). Cela envoie le signal spécifié à systemd-nspawn@.service, instancié pour le nom de machine spécifié, de manière similaire à l'effet de systemctl kill sur le nom du service. Par défaut, le signal SIGTERM est envoyé.

Ajouté en version 219.

poweroff NOM...

Arrête proprement un conteneur en cours d'exécution, en utilisant systemd-nspawn(1). Cela arrête systemd-nspawn@.service, instancié pour le nom de machine spécifié, de manière similaire à l'effet de systemctl poweroff sur le nom du service. Ceci est un arrêt propre, signalant au système d'exploitation invité de s'arrêter. Notez que l'arrêt peut prendre un certain temps. Si vous avez besoin d'un arrêt immédiat, utilisez terminate ou kill.

Ajouté en version 219.

reboot NOM...

Redémarre un conteneur en cours d'exécution, en utilisant systemd-nspawn(1). Cela déclenche un redémarrage de systemd-nspawn@.service, instancié pour le nom de machine spécifié, de manière similaire à l'effet de systemctl reboot sur le nom du service. Ceci est un arrêt propre suivi d'un redémarrage. Notez que le redémarrage peut prendre un certain temps.

Ajouté en version 219.

machine-id NOM...

Affiche le contenu du fichier machine-id d'une machine. Cela est utile pour vérifier que le machine-id est correctement configuré, ou pour récupérer le machine-id d'une machine donnée.

Ajouté en version 232.

Commandes Image

list-images [TYPE]

Liste les images de conteneurs disponibles pour le démarrage. La liste inclut les images trouvées dans les chemins de recherche configurés pour systemd-nspawn(1) (par exemple, /var/lib/machines/). Si TYPE est fourni, cela filtre la liste aux images de ce type uniquement. Les types d'image connus incluent "tar", "dir", "btrfs", "raw", "qcow2", "vmdk", "vhdx". Si TYPE est omis, toutes les images sont listées.

Notez que les machines virtuelles sont généralement gérées par des outils externes et ne sont pas énumérées ici. list-images est destiné aux conteneurs et autres types d'images gérés par systemd.

Ajouté en version 219.

image-status [TYPE]

Affiche des informations d'état sur les images de conteneurs disponibles pour le démarrage. Les informations incluent le chemin d'accès, la taille, les métadonnées et le type d'image. Les images sont recherchées dans les chemins de recherche configurés pour systemd-nspawn(1) (par exemple, /var/lib/machines/). Si TYPE est fourni, cela filtre la liste aux images de ce type uniquement. Les types d'image connus incluent "tar", "dir", "btrfs", "raw", "qcow2", "vmdk", "vhdx". Si TYPE est omis, toutes les images sont listées.

Ajouté en version 233.

pull IMAGE...

Télécharge une ou plusieurs images de conteneurs à partir d'un dépôt distant et les importe dans la collection locale d'images. Les images peuvent être spécifiées par leur nom et, éventuellement, une balise (par exemple, debian:11). Si aucune balise n'est spécifiée, la balise latest est utilisée par défaut. L'URL du dépôt peut être configurée via la directive OSImageServer= dans systemd.conf(5). Les images sont stockées dans les répertoires définis par DirMountPoint= dans nspawn.conf(5).

Ajouté en version 219.

clone SOURCE DEST

Crée une nouvelle image de conteneur nommée DEST en clonant l'image SOURCE. Le clonage utilise les instantanés de sous-volumes Btrfs si l'image source réside sur un système de fichiers Btrfs. Sinon, une copie complète est effectuée. La nouvelle image DEST peut ensuite être utilisée pour démarrer une nouvelle machine.

Ajouté en version 219.

add IMAGE

Ajoute une image de conteneur existante au gestionnaire de machines. L'image doit être un fichier binaire brut de disque ou un fichier image qcow2. L'image sera copiée dans le répertoire des images (par défaut /var/lib/machines/).

Ajouté en version 219.

remove IMAGE...

Supprime une ou plusieurs images de conteneurs de la collection locale. Les images en cours d'utilisation (c'est-à-dire démarrées comme machines) ne peuvent pas être supprimées.

Ajouté en version 219.

rename OLD NEW

Renomme une image de conteneur de OLD à NEW. Cela ne fonctionne que si aucune machine n'est actuellement démarrée à partir de l'image OLD.

Ajouté en version 219.

edit IMAGE

Ouvre l'image spécifiée dans l'éditeur de texte configuré (défini par la variable d'environnement EDITOR, ou vi par défaut). Cela permet de modifier le système de fichiers de l'image. Cette commande est particulièrement utile pour les images de type répertoire ou sous-volume. Pour les images de type fichier (par exemple, raw, qcow2), l'édition est généralement effectuée en montageant l'image.

Ajouté en version 219.

patch IMAGE

Applique un correctif à une image de conteneur. Le correctif est lu depuis l'entrée standard. Ceci est utile pour appliquer des modifications à des images existantes de manière reproductible.

Ajouté en version 219.

Commandes Système

link IMAGE [NOM]

Crée un lien symbolique à partir du répertoire /var/lib/machines/ vers l'image spécifiée. Si NOM est donné, le lien sera créé avec ce nom. Sinon, le nom de l'image elle-même est utilisé. Cela permet de référencer des images qui ne sont pas dans /var/lib/machines/ ou qui ont des noms différents de ceux des machines démarrées à partir d'elles.

Ajouté en version 219.

unbind NOM

Supprime un lien symbolique créé par link.

Ajouté en version 219.

mkdir NOM

Crée un nouveau répertoire d'image, prêt à être rempli avec un système d'exploitation. Ce répertoire sera créé dans le chemin de montage des répertoires d'images (par défaut /var/lib/machines/).

Ajouté en version 219.

mount NOM

Monte une image de système de fichiers (par exemple, un fichier image raw ou qcow2) sur un point de montage temporaire, et crée un lien symbolique à partir de /var/lib/machines/ vers ce point de montage. Les images montées sont accessibles via le NOM spécifié dans /var/lib/machines/.

Ajouté en version 219.

umount NOM

Démonte une image montée par mount et supprime le lien symbolique correspondant.

Ajouté en version 219.

identify [NOM]

Détermine le nom d'une machine s'exécutant sur l'hôte. Si NOM est donné, identifie cette machine. Si aucun NOM n'est donné, identifie la machine appelante (utile pour les processus s'exécutant à l'intérieur d'un conteneur). Ceci est utile pour obtenir des informations sur le type de machine (par exemple, conteneur, VM), le nom d'hôte, etc.

Ajouté en version 225.

set-password [NOM]

Définit le mot de passe d'un utilisateur dans une machine. Si NOM est spécifié, il fait référence à la machine cible. Si aucun NOM n'est spécifié, le mot de passe de l'utilisateur actuel sur l'hôte est défini. La commande demandera le nom d'utilisateur et le nouveau mot de passe. Ceci est utile pour définir le mot de passe root dans un nouveau conteneur, par exemple.

Ajouté en version 225.

set-hostname NOM [HOSTNAME]

Définit le nom d'hôte d'une machine. Si HOSTNAME n'est pas spécifié, une invite sera présentée pour entrer un nouveau nom d'hôte.

Ajouté en version 225.

set-uid-image IMAGE

Marque une image comme étant une image UID. Les images UID sont des images spéciales qui sont démarrées avec un UID différent pour l'utilisateur root, afin de fournir un isolement supplémentaire. Cela est utilisé par exemple pour exécuter des applications dans des conteneurs sans privilèges.

Ajouté en version 231.

unset-uid-image IMAGE

Annule le marquage d'une image comme étant une image UID.

Ajouté en version 231.

inspect-image IMAGE

Affiche les métadonnées d'une image de conteneur sous forme d'arbre JSON.

Ajouté en version 235.

Commandes Globales

stop-all

Ajouté en version 219.

shutdown

Arrête le gestionnaire de machines systemd-machined.service(8) et toutes les machines et conteneurs qu'il gère.

Ajouté en version 219.

daemon-reexec

Recharge la configuration du gestionnaire de machines systemd-machined.service(8).

Ajouté en version 219.

help

OPTIONS

Les options suivantes sont comprises :

――all, -a

N'importe quelle commande qui liste des éléments (par exemple, list, status) affichera également les éléments masqués par défaut, tels que la machine spéciale ".host". Par défaut, status affiche également les propriétés vides.

Ajouté en version 206.

――property=PROP

Utilisé avec la commande show pour sélectionner une propriété spécifique à afficher. Peut être spécifié plusieurs fois.

Ajouté en version 206.

――value=VAL

Utilisé avec la commande show pour afficher la valeur d'une propriété sous forme de chaîne brute, sans formatage supplémentaire.

Ajouté en version 206.

――uid=UID

Utilisé avec la commande shell pour spécifier l'UID sous lequel exécuter le shell dans la machine. Si non spécifié, l'UID de l'utilisateur courant est utilisé.

Ajouté en version 225.

――gid=GID

Utilisé avec la commande shell pour spécifier le GID sous lequel exécuter le shell dans la machine. Si non spécifié, le GID de l'utilisateur courant est utilisé.

Ajouté en version 225.

――setenv=VAR[=VALUE]

Utilisé avec la commande shell pour définir une variable d'environnement pour le processus shell. Si VALUE est omis, la valeur de la variable d'environnement correspondante sur l'hôte est utilisée.

Ajouté en version 225.

――user=USER

Utilisé avec la commande shell pour spécifier l'utilisateur sous lequel exécuter le shell dans la machine. Si non spécifié, l'utilisateur courant est utilisé.

Ajouté en version 225.

――machine=MACHINE

Utilisé avec la commande shell pour spécifier la machine dans laquelle exécuter le shell. C'est un alias pour le premier argument de la commande shell.

Ajouté en version 225.

――wait

Utilisé avec la commande shell pour attendre la fin du shell avant de retourner. Cela permet de récupérer le code de sortie du shell.

Ajouté en version 225.

――quiet, -q

N'affiche pas les messages de journal dans la sortie de status.

Ajouté en version 225.

――raw, -r

Utilisé avec la commande status pour afficher la sortie du journal de la machine au format brut, sans formatage supplémentaire.

Ajouté en version 225.

――json

Utilisé avec la commande status pour afficher la sortie du journal de la machine au format JSON.

Ajouté en version 225.

――output=MODE

Utilisé avec la commande status pour spécifier le mode de sortie du journal. Les modes possibles sont "short", "short-precise", "long", "callback", "json", "export". Le mode par défaut est "short".

Ajouté en version 225.

――throttle=SECONDS

Utilisé avec la commande status pour limiter la vitesse de sortie des messages du journal. SECONDS spécifie l'intervalle minimum entre deux messages.

Ajouté en version 225.

――since=CLOCK, until=CLOCK

Utilisé avec la commande status pour filtrer les messages du journal par date/heure. CLOCK peut être une date/heure absolue ou relative.

Ajouté en version 225.

――follow

Utilisé avec la commande status pour suivre les messages du journal en temps réel.

Ajouté en version 225.

――no-pager

N'utilise pas de pagineur pour afficher la sortie des commandes.

Ajouté en version 225.

――no-legend

N'affiche pas la légende (en-tête) lors de l'affichage de la sortie des commandes.

Ajouté en version 225.

――no-sync

N'effectue pas de synchronisation du système de fichiers avant de démarrer ou d'arrêter une machine. Cela peut accélérer les opérations, mais peut entraîner une perte de données si le système de fichiers n'est pas synchronisé.

Ajouté en version 233.

――read-only

Monte les images en lecture seule. Cela est utile pour inspecter des images sans risquer de les modifier.

Ajouté en version 233.

MACHINE NAME

Les noms de machine sont des chaînes de caractères qui peuvent contenir des lettres, des chiffres et des traits d'union. Ils doivent commencer et se terminer par une lettre ou un chiffre. La longueur maximale d'un nom de machine est de 63 caractères. Les noms de machine sont utilisés pour identifier de manière unique les machines virtuelles et les conteneurs. Le nom spécial .host fait référence à l'hôte du système.

EXEMPLES

Lister toutes les machines et leurs statuts :

$ machinectl list
$ machinectl status

Démarrer un conteneur nommé 'my-container' :

$ machinectl start my-container

Arrêter proprement le conteneur 'my-container' :

$ machinectl poweroff my-container

Obtenir un shell dans le conteneur 'my-container' en tant qu'utilisateur root :

$ machinectl shell my-container

Exécuter une commande dans le conteneur 'my-container' :

$ machinectl shell my-container /usr/bin/echo "Hello from container!"

Lister toutes les images de conteneurs disponibles :

$ machinectl list-images

Télécharger l'image Debian 11 :

$ machinectl pull debian:11

Créer une nouvelle machine à partir de l'image Debian 11 :

$ machinectl clone debian:11 my-debian-vm
$ machinectl start my-debian-vm

Cette commande recharge implicitement la configuration du gestionnaire système après avoir terminé l'opération. Notez que cette commande ne démarre ni n'arrête implicitement les conteneurs sur lesquels elle opère. Si cela est souhaité, combinez la commande avec l'option --now.

Ajouté dans la version 219.

poweroff NOM...

Éteint un ou plusieurs conteneurs. Cela déclenchera un arrêt en envoyant SIGRTMIN+4 au processus init du conteneur, ce qui amène les systèmes init compatibles avec systemd à s'arrêter proprement. Utilisez stop comme alias pour poweroff. Cette opération ne fonctionne pas sur les conteneurs qui n'exécutent pas un système init compatible avec systemd(1), tel que sysvinit. Utilisez terminate (voir ci-dessous) pour terminer immédiatement un conteneur ou une VM, sans l'arrêter proprement.

Ajouté dans la version 212.

reboot NOM...

Redémarre un ou plusieurs conteneurs. Cela déclenchera un redémarrage en envoyant SIGINT au processus init du conteneur, ce qui est à peu près équivalent à appuyer sur Ctrl+Alt+Suppr sur un système non conteneurisé, et est compatible avec les conteneurs exécutant n'importe quel gestionnaire système. Utilisez restart comme alias pour reboot.

Ajouté dans la version 209.

terminate NOM...

Termine immédiatement une machine virtuelle ou un conteneur, sans l'arrêter proprement. Cela tue tous les processus de la machine virtuelle ou du conteneur et désalloue toutes les ressources attachées à cette instance. Utilisez poweroff pour émettre une demande d'arrêt propre.

Ajouté dans la version 206.

kill NOM...

Envoie un signal à un ou plusieurs processus de la machine virtuelle ou du conteneur. Cela concerne les processus tels que vus par l'hôte, pas les processus à l'intérieur de la machine virtuelle ou du conteneur. Utilisez --kill-whom= pour sélectionner le processus à tuer. Utilisez --signal= pour sélectionner le signal à envoyer.

Ajouté dans la version 206.

bind NOM CHEMIN [CHEMIN]

Monte par liaison (bind mount) un fichier ou un répertoire de l'hôte dans le conteneur spécifié. Le premier argument de chemin est le fichier ou le répertoire source sur l'hôte, le second argument de chemin est le fichier ou le répertoire de destination dans le conteneur. Lorsque ce dernier est omis, le chemin de destination dans le conteneur est le même que le chemin source sur l'hôte. Combiné avec l'option --read-only, un montage par liaison en lecture seule est créé. Combiné avec l'option --mkdir, le chemin de destination est d'abord créé avant que le montage ne soit appliqué. Notez que cette option n'est actuellement prise en charge que pour les conteneurs systemd-nspawn(1), et uniquement si l'espace de noms utilisateur (--private-users) n'est pas utilisé. Cette commande prend en charge le montage par liaison de répertoires, de fichiers réguliers, de nœuds de périphériques, de nœuds de sockets AF_UNIX, ainsi que de FIFOs.

Ajouté dans la version 219.

NOMS DE MACHINES ET D'IMAGES

L'outil machinectl opère sur des machines et des images dont les noms doivent être choisis en suivant des règles strictes. Les noms de machines doivent être adaptés à une utilisation comme noms d'hôtes, en suivant un sous-ensemble conservateur des sémantiques DNS et UNIX/Linux. Spécifiquement, ils doivent être constitués d'une ou plusieurs chaînes d'étiquettes non vides, séparées par des points. Aucun point de début ou de fin n'est autorisé. Aucune séquence de plusieurs points n'est autorisée. Les chaînes d'étiquettes ne peuvent contenir que des caractères alphanumériques ainsi que le trait d'union. La longueur maximale d'un nom de machine est de 64 caractères.

Une machine spéciale avec le nom « .host » fait référence au système hôte en cours d'exécution lui-même. Ceci est utile pour les opérations d'exécution ou l'inspection du système hôte. Notez que machinectl list n'affichera pas cette machine spéciale à moins que le commutateur --all ne soit spécifié.

Les exigences relatives aux noms d'images sont moins strictes, cependant, elles doivent être valides en UTF-8, appropriées comme noms de fichiers (donc pas le point simple ou double, et n'incluant pas de barre oblique), et ne pas contenir de caractères de contrôle. Étant donné que de nombreuses opérations recherchent une image par le nom d'une machine demandée, il est recommandé de nommer les images de la même manière stricte que les machines.

Une image spéciale avec le nom « .host » fait référence à l'image du système hôte en cours d'exécution. Elle correspond donc conceptuellement au nom de machine spécial « .host » décrit ci-dessus. Notez que machinectl list-images n'affichera pas non plus cette image spéciale, à moins que --all ne soit spécifié.

FICHIERS ET RÉPERTOIRES

Les images de machines sont de préférence stockées dans /var/lib/machines/, mais sont également recherchées dans /usr/local/lib/machines/ et /usr/lib/machines/. Pour des raisons de compatibilité, le répertoire /var/lib/container/ est également recherché. Notez que les images stockées dans /usr/ sont toujours considérées comme étant en lecture seule. Il est possible de créer des liens symboliques vers des images de machines à partir d'autres répertoires dans /var/lib/machines/ pour les rendre disponibles pour le contrôle avec machinectl.

Notez que certaines opérations sur les images ne sont prises en charge, efficaces ou atomiques que sur les systèmes de fichiers btrfs.

Les images disque sont comprises par systemd-nspawn(1) et machinectl dans trois formats :

•Un simple arbre de répertoires, contenant les fichiers et répertoires du conteneur à démarrer.
•Des sous-volumes (sur les systèmes de fichiers btrfs), qui sont similaires aux simples répertoires décrits ci-dessus. Cependant, ils présentent des avantages supplémentaires, tels que le clonage efficace et le rapport de quotas.
•Des images disque « brutes », c'est-à-dire des images binaires de disques avec une table de partitions GPT ou MBR. Les images de ce type sont des fichiers réguliers avec le suffixe « .raw ».

Voir systemd-nspawn(1) pour plus d'informations sur les formats d'images, en particulier ses options --directory= et --image=.

EXEMPLES

Exemple 1. Télécharger une image RAW Ubuntu, définir un mot de passe root dedans, la démarrer en tant que service

# importctl pull-raw -mN \
      https://cloud-images.ubuntu.com/jammy/current/jammy-server-cloudimg-amd64-disk-kvm.img \
      jammy
# systemd-firstboot --image=/var/lib/machines/jammy.raw --prompt-root-password --force
# machinectl start jammy
# machinectl login jammy

Ceci télécharge l'image .raw spécifiée et la rend disponible sous le nom local « jammy ». Ensuite, un mot de passe root est défini avec systemd-firstboot(1). Ensuite, la machine est démarrée en tant que service système. Avec la dernière commande, une invite de connexion dans le conteneur est demandée.

STATUT DE SORTIE

En cas de succès, 0 est retourné, sinon un code d'échec non nul.

ENVIRONNEMENT

$SYSTEMD_LOG_LEVEL

Le niveau de journalisation maximum des messages émis (les messages d'un niveau de journalisation supérieur, c'est-à-dire moins importants, seront supprimés). Prend une liste de valeurs séparées par des virgules. Une valeur peut être soit l'une des valeurs suivantes (par ordre d'importance décroissante) : emerg, alert, crit, err, warning, notice, info, debug, soit un entier

VARIABLES

Des variables d'environnement spécifiques à systemd peuvent être utilisées pour modifier le comportement de nombreux outils systemd. Les variables d'environnement qui ne sont pas spécifiquement reconnues par un outil sont ignorées par défaut. Notez que les valeurs de ces variables d'environnement sont généralement passées en tant que chaînes de caractères et seront interprétées par l'outil en conséquence. Dans la plupart des cas, une valeur vide ou la chaîne « 0 » ou « no » désactivera une fonctionnalité, tandis qu'une valeur non vide ou la chaîne « 1 » ou « yes » l'activera. Certaines variables, comme $SYSTEMD_LOG_LEVEL, ont des formats de valeur plus complexes.

$SYSTEMD_LOG_LEVEL

Définit le niveau de journalisation maximal pour toutes les sorties de journalisation. La valeur est une chaîne représentant un niveau de journalisation. Les niveaux de journalisation disponibles sont, par ordre croissant : emerg, alert, crit, error, warning, notice, info, debug. Si la chaîne ne correspond à aucun niveau de journalisation connu, le niveau notice sera utilisé. Les valeurs peuvent aussi être des entiers dans la plage 0...7. Voir syslog(3) pour plus d'informations. Chaque valeur peut éventuellement être précédée de console, syslog, kmsg ou journal suivi de deux-points pour définir le niveau de journalisation maximal pour cette cible de journal spécifique (par exemple, SYSTEMD_LOG_LEVEL=debug,console:info spécifie de journaliser au niveau debug sauf lorsque la journalisation se fait vers la console, qui devrait être au niveau info). Notez que le niveau de journalisation maximal global prend la priorité sur tous les niveaux de journalisation maximaux par cible.

$SYSTEMD_LOG_COLOR

Une valeur booléenne. Si elle est vraie, les messages écrits sur le tty seront colorés selon leur priorité.

Ce paramètre est uniquement utile lorsque les messages sont écrits directement sur le terminal, car journalctl(1) et d'autres outils qui affichent les journaux coloreront les messages en fonction du niveau de journalisation par eux-mêmes.

$SYSTEMD_LOG_TIME

Une valeur booléenne. Si elle est vraie, les messages de journalisation console seront préfixés par un horodatage.

Ce paramètre est uniquement utile lorsque les messages sont écrits directement sur le terminal ou dans un fichier, car journalctl(1) et d'autres outils qui affichent les journaux ajouteront des horodatages basés sur les métadonnées de l'entrée par eux-mêmes.

$SYSTEMD_LOG_LOCATION

Une valeur booléenne. Si elle est vraie, les messages seront préfixés par un nom de fichier et un numéro de ligne dans le code source d'où provient le message.

Notez que l'emplacement du journal est souvent joint en tant que métadonnées aux entrées du journal de toute façon. L'inclure directement dans le texte du message peut néanmoins être pratique lors du débogage de programmes.

$SYSTEMD_LOG_TID

Une valeur booléenne. Si elle est vraie, les messages seront préfixés par l'identifiant numérique du thread (TID) actuel.

Notez que ces informations sont jointes en tant que métadonnées aux entrées du journal de toute façon. Les inclure directement dans le texte du message peut néanmoins être pratique lors du débogage de programmes.

$SYSTEMD_LOG_TARGET

La destination des messages de journalisation. L'une des valeurs suivantes : console (journaliser sur le tty connecté), console-prefixed (journaliser sur le tty connecté mais avec des préfixes codant le niveau de journalisation et la « facility », voir syslog(3), kmsg (journaliser dans le tampon de journal circulaire du noyau), journal (journaliser dans le journal), journal-or-kmsg (journaliser dans le journal si disponible, et dans kmsg sinon), auto (déterminer automatiquement la cible de journalisation appropriée, par défaut), null (désactiver la sortie du journal).

$SYSTEMD_LOG_RATELIMIT_KMSG

Indique s'il faut limiter le débit des messages kmsg ou non. Prend une valeur booléenne. La valeur par défaut est « true ». Si désactivé, systemd ne limitera pas le débit des messages écrits dans kmsg.

$SYSTEMD_PAGER, $PAGER

Le pagineur à utiliser lorsque --no-pager n'est pas utilisé. $SYSTEMD_PAGER est utilisé s'il est défini ; sinon, $PAGER est utilisé. Si ni $SYSTEMD_PAGER ni $PAGER ne sont définis, un ensemble d'implémentations de pagineurs bien connues sont essayées tour à tour, y compris less(1) et more(1), jusqu'à ce que l'une d'elles soit trouvée. Si aucune implémentation de pagineur n'est découverte, aucun pagineur n'est invoqué. Définir ces variables d'environnement sur une chaîne vide ou la valeur « cat » équivaut à passer --no-pager.

Note : si $SYSTEMD_PAGERSECURE n'est pas défini, $SYSTEMD_PAGER et $PAGER ne peuvent être utilisés que pour désactiver le pagineur (avec « cat » ou « » ), et sont sinon ignorés.

$SYSTEMD_LESS

Remplace les options passées à less (par défaut « FRSXMK »).

Les utilisateurs pourraient vouloir modifier deux options en particulier :

K

Cette option demande au pagineur de quitter immédiatement lorsque Ctrl+C est pressé. Pour permettre à less de gérer Ctrl+C lui-même pour revenir à l'invite de commande du pagineur, désactivez cette option.

Si la valeur de $SYSTEMD_LESS n'inclut pas « K », et que le pagineur invoqué est less, Ctrl+C sera ignoré par l'exécutable, et devra être géré par le pagineur.

X

Cette option demande au pagineur de ne pas envoyer de chaînes d'initialisation et de désinitialisation termcap au terminal. Elle est définie par défaut pour permettre à la sortie de la commande de rester visible dans le terminal même après la sortie du pagineur. Néanmoins, cela empêche certaines fonctionnalités du pagineur de fonctionner, en particulier la sortie paginée ne peut pas être parcourue avec la souris.

Notez que la définition de la variable d'environnement $LESS régulière n'a aucun effet pour les invocations de less par les outils systemd.

Voir less(1) pour plus de discussion.

$SYSTEMD_LESSCHARSET

Remplace le jeu de caractères passé à less (par défaut « utf-8 », si le terminal appelant est déterminé comme compatible UTF-8).

Notez que la définition de la variable d'environnement $LESSCHARSET régulière n'a aucun effet pour les invocations de less par les outils systemd.

$SYSTEMD_PAGERSECURE

Les commandes de pagineur courantes comme less(1), en plus de la « pagination », c'est-à-dire du défilement de la sortie, prennent en charge l'ouverture ou l'écriture d'autres fichiers et l'exécution de commandes shell arbitraires. Lorsque les commandes sont invoquées avec des privilèges élevés, par exemple sous sudo(8) ou pkexec(1), le pagineur devient une frontière de sécurité. Il faut veiller à ce que seuls les programmes dont les fonctionnalités sont strictement limitées soient utilisés comme pagineurs, et que les fonctionnalités interactives involontaires comme l'ouverture ou la création de nouveaux fichiers ou le lancement de sous-processus ne soient pas autorisées. Le « mode sécurisé » pour le pagineur peut être activé comme décrit ci-dessous, si le pagineur le prend en charge (la plupart des pagineurs ne sont pas écrits de manière à en tenir compte). Il est recommandé soit d'activer explicitement le « mode sécurisé », soit de désactiver complètement le pagineur à l'aide de --no-pager ou de PAGER=cat lorsque des utilisateurs non fiables sont autorisés à exécuter des commandes avec des privilèges élevés.

Cette option prend un argument booléen. Lorsqu'elle est définie sur vrai, le « mode sécurisé » du pagineur est activé. En « mode sécurisé », LESSSECURE=1 sera défini lors de l'invocation du pagineur, ce qui demande au pageur de désactiver les commandes qui ouvrent ou créent de nouveaux fichiers ou lancent de nouveaux sous-processus. Actuellement, seul less(1) est connu pour comprendre cette variable et implémenter le « mode sécurisé ».

Lorsqu'elle est définie sur faux, aucune limitation n'est imposée au pagineur. Définir SYSTEMD_PAGERSECURE=0 ou ne pas le supprimer de l'environnement hérité peut permettre à l'utilisateur d'invoquer des commandes arbitraires.

Lorsque $SYSTEMD_PAGERSECURE n'est pas défini, les outils systemd tentent de déterminer automatiquement si le « mode sécurisé » doit être activé et si le pagineur le prend en charge. Le « mode sécurisé » est activé si l'UID effectif n'est pas le même que le propriétaire de la session de connexion, voir geteuid(2) et sd_pid_get_owner_uid(3), ou lorsqu'il s'exécute sous sudo(8) ou des outils similaires ($SUDO_UID est défini [1]). Dans ces cas, SYSTEMD_PAGERSECURE=1 sera défini et les pagineurs qui ne sont pas connus pour implémenter le « mode sécurisé » ne seront pas utilisés du tout. Notez que cette autodétection ne couvre que les mécanismes les plus courants pour élever les privilèges et est destinée à des fins de commodité. Il est recommandé de définir explicitement $SYSTEMD_PAGERSECURE ou de désactiver le pagineur.

Notez que si les variables $SYSTEMD_PAGER ou $PAGER doivent être prises en compte, autres que pour désactiver le pagineur, $SYSTEMD_PAGERSECURE doit également être défini.

$SYSTEMD_COLORS

Prend un argument booléen. Lorsque vrai, systemd et les utilitaires associés utiliseront des couleurs dans leur sortie, sinon la sortie sera monochrome. De plus, la variable peut prendre l'une des valeurs spéciales suivantes : « 16 », « 256 » pour restreindre l'utilisation des couleurs aux couleurs ANSI de base 16 ou 256, respectivement. Cela peut être spécifié pour remplacer la décision automatique basée sur $TERM et la connexion de la console.

$SYSTEMD_URLIFY

La valeur doit être booléenne. Contrôle si des liens cliquables doivent être générés dans la sortie pour les émulateurs de terminal qui le prennent en charge. Cela peut être spécifié pour remplacer la décision prise par systemd en fonction de $TERM et d'autres conditions.

NAME

machinectl — contrôle les machines de type système et utilisateur sous systemd-nspawn

SYNOPSIS

machinectl [OPTIONS] COMMAND [MACHINE...]

DESCRIPTION

machinectl est une utilitaire pour contrôler les machines virtuelles gérées par systemd-nspawn. Il permet d'interagir avec les machines, de les démarrer, les arrêter, les suspendre, les reprendre et de les lister.

OPTIONS

-H, --machine=
Spécifie la machine sur laquelle exécuter la commande. Cela peut être un nom d'hôte ou une adresse IP.
-P, --property=
Définit une propriété pour la machine.
-p, --value=
Définit la valeur d'une propriété.
-q, --quiet
Réduit la sortie.
-y, --wait
Attend que la machine soit prête avant de continuer.
