MMV_STATS_REGISTRY(3) Manuel des fonctions de bibliothèque MMV_STATS_REGISTRY(3)

NOM

mmv_stats_registry, mmv_stats_start, mmv_stats_stop - Initialise le fichier de valeurs mappé en mémoire

SYNTAXE C

#include <pcp/pmapi.h>
#include <pcp/mmv_stats.h>

mmv_registry_t *mmv_stats_registry(const char *file,
int cluster, mmv_stats_flags_t flags);

void *mmv_stats_start(mmv_registry_t *registry);
void mmv_stats_stop(const char *fname,
void *addr);

cc ... -lpcp_mmv -lpcp

DESCRIPTION

mmv_stats_registry initialise une structure opaque qui définit divers aspects d'un fichier mappé en mémoire. Ce fichier est utilisé pour la communication inter-processus légère entre une application instrumentée et pmdammv(1).

L'interface mmv_stats_registry est utilisée pour allouer un registre, et permet de définir le nom du fichier MMV(5), l'identifiant de cluster et les flags (le cas échéant). Elle retourne un handle qui est utilisé dans les appels ultérieurs de l'API MMV lors de l'ajout de métriques, d'indoms, d'instances et de labels au registre - avant de créer effectivement le fichier.

mmv_stats_start est l'appel qui crée le fichier MMV(5) avec le handle retourné par mmv_stats_registry. Il retourne le handle de mémoire mappée utilisé dans les appels ultérieurs de l'API MMV, tels que mmv_inc_value(3).

mmv_stats_stop effectue un arrêt ordonné du handle de mapping retourné par un appel d'initialisation précédent et libère également la structure du registre.

La combinaison de mmv_stats_registry et mmv_stats_start fait la même chose que les appels dépréciés mmv_stats2_init. Cependant, maintenant, il faut d'abord appeler mmv_stats_registry puis les appels d'API qui ajoutent des instances, des indoms, des métriques et des labels. De cette façon, il n'est pas nécessaire de connaître à l'avance quelle version du mapping MMV(1|2|3) sera utilisée, car elle est calculée automatiquement.

Le fichier est créé dans le répertoire $PCP_TMP_DIR/mmv, l'argument name est censé être un nom de fichier de base, pas le chemin complet. Le contenu des métadonnées du fichier ne change pas une fois le fichier créé.

L'ancien fichier est supprimé sans condition, sauf en cas d'erreur.

cluster est l'identifiant de cluster PMDA MMV préféré à utiliser pour les métriques qui sont à l'origine de l'appel mmv_stats_start. Les flags fournissent un contrôle supplémentaire sur le comportement du PMDA MMV - par exemple, l'utilisation de MMV_FLAG_PROCESS garantira que les valeurs ne sont exportées que lorsque l'application instrumentée est en cours d'exécution - cela est vérifié à chaque demande de nouvelles valeurs.

Les sections suivantes expliquent comment ajouter des métriques, des indoms, des instances et des labels.

AJOUTER DES MÉTRIQUES

int mmv_stats_add_metric(mmv_registry_t *registry,
const char *name, int item, mmv_metric_type_t type, mmv_metric_sem_t sem, pmUnits units, int serial, const char *shorthelp, const char *longhelp);

Lors de l'ajout d'une métrique, elle est gérée en interne à l'aide de la structure suivante. sem dans la structure correspond à la sémantique. units dans la structure correspond à la dimension. serial dans la structure correspond à l'indom.

        typedef struct {
            char *name;                 /* Nom de la métrique */
            __uint32_t item;            /* Composant de l'élément du PMID */
            mmv_metric_type_t type;     /* Type de la métrique */
            mmv_metric_sem_t semantics; /* Sémantique de la métrique */
            pmUnits dimension;          /* Dimensions (TEMPS, ESPACE, etc.) */
            __uint32_t indom;           /* Identifiant du domaine d'instance */
            char *shorttext;            /* Optionnel, aide sur une ligne */
            char *helptext;             /* Optionnel, texte d'aide complet */
        } mmv_metric2_t;

AJOUTER DES INDOMS

int mmv_stats_add_indom(mmv_registry_t *registry,
int serial, const char *shorthelp, const char *longhelp);

Lors de l'ajout d'un indom, il est géré en interne à l'aide de la structure suivante.

        typedef struct {
            __uint32_t serial;           /* Numéro de série unique */
            __uint32_t count;            /* Nombre d'instances */
            mmv_instances2_t *instances; /* IDs internes/externes */
            char *shorttext;             /* Texte d'aide court */
            char *helptext;              /* Texte d'aide long */
        } mmv_indom2_t;

AJOUTER DES INSTANCES

int mmv_stats_add_instance(mmv_registry_t *registry,
int serial, int instid, const char *instname);

Lors de l'ajout d'une instance, elle est gérée en interne à l'aide de la structure suivante. instid dans la structure correspond à l'identifiant interne, tandis que instname correspond au nom externe.

        typedef struct {
            __int32_t internal;
            char *external;
        } mmv_instances2_t;

Il est utile de mentionner que si l'indom de l'instance n'est pas trouvé, cela retourne une erreur.

AJOUTER DES LABELS

int mmv_stats_add_registry_label(mmv_registry_t *registry,
const char *name, const char *value, mmv_value_type_t type, int optional);

int mmv_stats_add_indom_label(mmv_registry_t *registry,
int serial, const char *name, const char *value, mmv_value_type_t type, int optional);

int mmv_stats_add_metric_label(mmv_registry_t *registry,
int item, const char *name, const char *value, mmv_value_type_t type, int optional);

int mmv_stats_add_instance_label(mmv_registry_t *registry,
int serial, int instid, const char *name, const char *value, mmv_value_type_t type, int optional);

registry est le handle obtenu de mmv_stats_registry. name et value sont les chaînes qui formeront le label.

type spécifie le type de valeur qui peut être: MMV_STRING_TYPE, MMV_NUMBER_TYPE, MMV_BOOLEAN_TYPE, MMV_NULL_TYPE, MMV_ARRAY_TYPE et MMV_MAP_TYPE.

Pour le moment, il existe une simple vérification de la correction de la valeur. Après avoir ajouté un label, une fonction est appelée pour vérifier s'il est correct.

De plus, si optional est défini, le drapeau PM_LABEL_OPTIONAL est ajouté.

serial est le numéro de série de l'indom lors de l'ajout d'un label d'indom ou d'instance. item est l'identifiant de la métrique lors de l'ajout d'un label de métrique. Enfin, lors de l'ajout d'un label de registre, il n'est pas nécessaire de fournir l'ID du cluster car il sera extrait de la structure de registre interne déjà créée.

mmv_stats_add_registry_label ajoute un PM_LABEL_CLUSTER.

mmv_stats_add_indom_label ajoute un PM_LABEL_INDOM.

mmv_stats_add_metric_label ajoute un PM_LABEL_ITEM.

mmv_stats_add_instance_label ajoute un PM_LABEL_INSTANCES.

VALEURS DE RETOUR


Lors de l'ajout de métriques, d'indoms, d'instances et de labels, si c'est correct, retourne 0
et sinon, retourne un code errno. Les autres fonctions retournent l'adresse
de la région mémoire mappée en cas de succès. En cas d'échec, NULL est retourné et
errno est défini à une valeur appropriée pour être décodée avec strerror(3).
