mmcli(1) Commandes utilisateur mmcli(1)

NOM

mmcli - Contrôler et surveiller ModemManager

SYNOPIS

mmcli [OPTION...]

DESCRIPTION

ModemManager est un démon Linux basé sur DBus qui fournit une API de haut niveau unifiée pour communiquer avec les modems (haut débit mobile). Il agit comme une couche d'interface radio (RIL) standard et peut être utilisé par différents gestionnaires de connexion, comme NetworkManager. Grâce à son architecture de plugins intégrée, ModemManager communique avec des types de modems très différents utilisant des ports très différents. En plus des ports série AT standard, les ports Qualcomm QCDM et QMI sont également pris en charge.

OPTIONS DU GESTIONNAIRE

-B, --get-daemon-version
Récupérer la version du démon ModemManager en cours d'exécution.
-G, --set-logging=[ERR|WARN|INFO|DEBUG]
Définir le niveau de journalisation dans le démon ModemManager. Pour les informations de débogage, vous pouvez fournir DEBUG. Chaque valeur au-dessus de DEBUG fournit moins de détails. Dans la plupart des cas, ERR (pour afficher les erreurs) sont les messages importants.

Le mode par défaut est ERR.

-L, --list-modems
Lister les modems disponibles.
-M, --monitor-modems
Lister les modems disponibles et surveiller les modems ajoutés ou retirés.
-S, --scan-modems
Analyser les modems potentiels. Ceci n'est utile que lorsque l'on attend des modems RS232 purs, car ils ne sont pas notifiés automatiquement par le noyau.
-I, --inhibit-device=[UID]
Empêcher l'utilisation de l'appareil spécifié par ModemManager. L'UID à fournir est la valeur de la propriété Device exposée par un modem donné (c'est-à-dire égale à ID_MM_PHYSDEV_UID si elle est définie, ou sinon égale au chemin sysfs complet de l'appareil).

Cette commande ne se terminera pas immédiatement, car cela supprimerait implicitement l'inhibition. L'utilisateur doit s'assurer d'arrêter le processus mmcli en appuyant sur Ctrl+C pour désinhiber l'appareil.

Lorsqu'un appareil est inhibé par cette méthode, ModemManager désactivera le modem (arrêtant ainsi toute connexion en cours) et ne l'utilisera plus jusqu'à ce qu'il soit désinhibé.

--report-kernel-event=['KEY1=VALUE1,KEY2=VALUE2,...']
Signaler manuellement les événements du noyau, au lieu de s'appuyer sur udev (par exemple, si le démon est exécuté avec --no-auto-scan ou si le système a été compilé sans prise en charge udev).

Les KEYs pris en charge sont :

'action'
Action à signaler, soit 'add' soit 'remove'. Obligatoire.
'subsystem'
Sous-système du port spécifique signalé, par exemple 'tty' (pour les ports série), 'net' (pour les interfaces réseau) ou 'usbmisc' (pour les ports cdc-wdm).
'name'
Nom du port signalé, par exemple 'ttyACM0', 'wwan0' ou 'cdc-wdm0'.
'uid'
L'UID spécifique de l'appareil, équivalent à la balise udev ID_MM_PHYSDEV_UID. Tous les ports signalés avec la même valeur 'UID' seront considérés comme faisant partie du même appareil, ce qui peut être utile pour, par exemple, les modems avec plusieurs TTYs de plateforme.
--report-kernel-event-auto-scan
Lorsqu'il est compilé avec la prise en charge udev mais que le démon est exécuté avec --no-auto-scan, cette méthode peut être utilisée pour signaler automatiquement les événements du noyau basés sur udev.

Cette commande ne se terminera pas immédiatement. L'utilisateur doit s'assurer d'arrêter le processus mmcli en appuyant sur Ctrl+C pour arrêter la surveillance des nouveaux événements.

OPTIONS COMMUNES

Toutes les options ci-dessous prennent un argument CHEMIN ou INDEX. Si aucune action n'est fournie, les informations par défaut sur le modem, le bearer, etc. sont affichées à la place.

Le CHEMIN et l'INDEX sont créés automatiquement lorsque le modem est branché. Ils peuvent être trouvés en utilisant mmcli -L. Ceci produit quelque chose comme (pour les modems uniquement) :

Found 1 modems:
/org/freedesktop/ModemManager1/Modem/4

Dans ce cas, l'INDEX est 4 et le CHEMIN est l'ensemble de la chaîne ci-dessus.

Cependant, pour les cas bearers, SIM et SMS, le CHEMIN est légèrement différent. Le mot *Modem* est remplacé par le nom de l'objet en usage, comme *Bearer*. Par exemple :

/org/freedesktop/ModemManager1/Bearer/4
-m, --modem=[CHEMIN|INDEX]
Spécifier un modem.
-b, --bearer=[CHEMIN|INDEX]
Spécifier un bearer.
-i, --sim=[CHEMIN|INDEX]
Spécifier une carte SIM.
-s, --sms=[CHEMIN|INDEX]
Spécifier un SMS.

OPTIONS MODEM

Toutes les options modem ci-dessous utilisent le commutateur --modem ou -m pour spécifier le modem sur lequel agir.

Certaines opérations nécessitent un MODE. Le MODE peut être n'importe quelle combinaison des modes réellement pris en charge par le modem. Dans le cas idéal, les modes suivants sont possibles :


'2G' - Technologies 2G, par exemple EDGE, CDMA1x
'3G' - Technologies 3G, par exemple HSPA, EV-DO
'4G' - Technologies 4G, par exemple LTE
'ANY' - pour tous les modes pris en charge.

-w, --monitor-state
Surveiller l'état d'un modem donné.
-e, --enable
Activer un modem donné.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

Cela alimente l'antenne, démarre le processus d'enregistrement automatique et, en général, prépare le modem à être connecté.

-d, --disable
Désactive un modem donné.

Cela déconnecte les connexions existantes pour le modem et le place en mode basse consommation.

-r, --reset
Réinitialise le modem aux paramètres qu'il avait lors de sa mise sous tension.
--factory-reset=CODE
Réinitialise le modem à ses paramètres d'usine d'origine.

Le CODE fourni est spécifique au vendeur. Sans le code correct du vendeur, il est peu probable que cette opération réussisse. Ce n'est pas une action courante pour l'utilisateur.

--command=COMMAND
Envoie une COMMAND AT au modem donné. Par exemple, COMMAND pourrait être 'AT+GMM' pour interroger les informations du modèle de téléphone. Cette opération n'est disponible que lorsque ModemManager est exécuté en mode de débogage.
--create-bearer=['CLE1=VALEUR1,CLE2=VALEUR2,...']
Crée un nouveau bearer de données paquet pour un modem donné. Les CLEs et certaines VALEURs sont listées ci-dessous:
'apn'
Nom du point d'accès. Requis en 3GPP.
'ip-type'
Type d'adressage. Donné comme une valeur MMBearerIpFamily (par exemple, 'ipv4', 'ipv6', 'ipv4v6'). Optionnel en 3GPP et CDMA.
'allowed-auth'
Méthode d'authentification à utiliser. Donnée comme une valeur MMBearerAllowedAuth (par exemple, 'none|pap|chap|mschap|mschapv2|eap'). Optionnel en 3GPP.
'user'
Nom d'utilisateur (le cas échéant) requis par le réseau. Optionnel en 3GPP.
'password'
Mot de passe (le cas échéant) requis par le réseau. Optionnel en 3GPP.
'allow-roaming'
Indicateur pour indiquer si la connexion est autorisée pendant l'itinérance, donné comme une valeur booléenne (c'est-à-dire 'yes' ou 'no'). Optionnel en 3GPP.
'rm-protocol'
Protocole de l'interface Rm, donné comme une valeur MMModemCdmaRmProtocol (par exemple, 'async', 'packet-relay', 'packet-network-ppp', 'packet-network-slip', 'stu-iii'). Optionnel en CDMA.
'number'
Numéro de téléphone à composer. Requis en POTS.
--delete-bearer=[CHEMIN|INDEX]
Supprime un bearer d'un modem donné.
--set-allowed-modes=[MODE1|MODE2|...]
Définit les modes autorisés pour un modem donné. Pour les modes possibles, voir le début de cette section.
--set-preferred-mode=MODE
Définit le MODE préféré pour le modem donné. Le MODE DOIT être l'un des modes autorisés tels que définis avec l'option --set-allowed-modes. Les MODEs possibles sont détaillés au début de cette section.
--set-current-bands=[BAND1|BAND2|...]
Définit les bandes à utiliser pour un modem donné. Ce sont les plages de fréquence que le modem doit utiliser. Il existe un nombre considérable de bandes prises en charge et les énumérer toutes ici serait assez long. Pour plus de détails, voir la documentation MMModemBand.

Un exemple serait : 'egsm|dcs|pcs|g850' pour sélectionner toutes les bandes de fréquences GSM.

--set-primary-sim-slot=[SLOT]
Demande de basculer le slot SIM principal.

Le SLOT donné doit être un numéro de slot valide dans la plage [1,N], où N est le nombre de slots SIM disponibles dans le système.

--inhibit
Empêche le modem spécifique d'être utilisé par ModemManager. Cette méthode est complètement équivalente à --inhibit-device, la seule différence étant que, dans ce cas, le modem doit être géré par le démon au moment où l'inhibition est demandée.

Cette commande ne se terminera pas immédiatement, car cela impliquerait de supprimer l'inhibition. L'utilisateur doit s'assurer d'arrêter le processus mmcli en appuyant sur Ctrl+C afin de désinhiber l'appareil.

Lorsqu'un appareil est inhibé par cette méthode, ModemManager désactivera le modem (interrompant ainsi toute connexion en cours) et ne l'utilisera plus jusqu'à ce qu'il soit désinhibé.

OPTIONS 3GPP

Le 3rd Generation Partnership Project (3GPP) est une collaboration entre groupes d'associations de télécommunications. Ces options concernent les appareils qui prennent en charge la norme 3GPP.

Elles incluent des options pour contrôler les sessions USSD (Unstructured Supplementary Service Data).

Toutes les options 3GPP ci-dessous utilisent le commutateur --modem ou -m pour spécifier le modem sur lequel agir.

--3gpp-scan
Analyse les réseaux 3GPP disponibles.
--3gpp-register-home
Demande à un modem donné de s'enregistrer sur son réseau d'origine.

Cela enregistre le modem sur les réseaux par défaut spécifiés par le modem.

--3gpp-register-in-operator=MCCMNC
Demande à un modem donné de s'enregistrer sur le réseau de l'opérateur spécifié par le MCCMNC (Mobile Country Code, Mobile Network Code) donné. Ce code est utilisé pour les réseaux mobiles terrestres publics GSM/LTE, CDMA, iDEN, TETRA et UMTS, ainsi que pour certains réseaux mobiles satellitaires. La recommandation E.212 de l'UIT-T définit les codes de pays mobiles.
--3gpp-ussd-status
Demande le statut de toute session USSD en cours.
--3gpp-ussd-initiate=COMMAND
Demande au modem donné d'initier une session USSD avec la COMMAND.

Par exemple, COMMAND pourrait être '*101#' pour connaître votre solde prépayé actuel.

--3gpp-ussd-respond=RESPONSE
Lors de l'initiation d'une session USSD, une RESPONSE peut être nécessaire à la demande initiée par le réseau. Cette option le permet.
--3gpp-ussd-cancel
Annule une session USSD en cours pour un modem donné.
--3gpp-disable-facility-lock=FACILITY,CONTROL_KEY
Désactive le verrouillage de facilities sélectionnées à l'aide de la clé de contrôle fournie.
'FACILITY'
L'un des types de verrouillage suivants :
'net-pers' - personnalisation réseau
'net-sub-pers' - personnalisation sous-réseau
'provider-pers' - personnalisation fournisseur
'corp-pers' - personnalisation entreprise
'CONTROL_KEY'
Code alphanumérique pour déverrouiller la facility.

OPTIONS CDMA

Toutes les options CDMA (Code Division Multiple Access) nécessitent l'option --modem ou -m.

--cdma-activate=CARRIER
Active le modem donné en utilisant les paramètres OTA (Over the Air). Le CARRIER est un code fourni par le réseau pour les paramètres par défaut qu'ils proposent.

OPTIONS SIMPLES

Toutes les options simples doivent être utilisées avec --modem ou -m.

--simple-connect=['CLE1=VALEUR1,CLE2=VALEUR2,...']
Exécute une séquence de connexion complète en utilisant des paires CLE / VALEUR. Vous pouvez utiliser les options --create-bearer, ainsi que les suivantes :
'pin'
Code de déverrouillage PIN SIM.
'operator-id'
MCC-MNC ETSI d'un réseau pour forcer l'enregistrement.
--simple-disconnect
Déconnecte TOUS les bearers connectés pour un modem donné.

OPTIONS DE LOCALISATION

Ces options détaillent comment découvrir votre position à l'aide du Global Positioning System (GPS) ou directement à partir de votre infrastructure de réseau mobile (soit 3GPP, soit 3GPP2).

Toutes les options de localisation doivent être utilisées avec --modem ou -m.

--location-status
Affiche le statut actuel de la découverte de notre position.
--location-get
Affiche toutes les informations de localisation disponibles.
--location-enable-3gpp
Active la découverte de position en utilisant le réseau 3GPP.
--location-disable-3gpp
Désactive la découverte de position en utilisant le réseau 3GPP.
--location-enable-agps-msa
Active le support A-GPS (MSA). Cette commande ne démarre pas implicitement le moteur GPS, elle spécifie simplement que l'A-GPS doit être activé lorsque le moteur est démarré. Par conséquent, l'utilisateur doit demander l'activation de l'A-GPS avant que les sorties brutes ou NMEA soient activées avec --location-enable-gps-raw ou --location-enable-gps-nmea.
--location-disable-agps-msa
Désactive le support A-GPS (MSA).
--location-enable-agps-msb
Active le support A-GPS (MSB). Cette commande ne démarre pas implicitement le moteur GPS, elle spécifie simplement que l'A-GPS doit être activé lorsque le moteur est démarré. Par conséquent, l'utilisateur doit demander l'activation de l'A-GPS avant que les sorties brutes ou NMEA soient activées avec --location-enable-gps-raw ou --location-enable-gps-nmea.
--location-disable-agps-msb
Désactive le support A-GPS (MSB).
--location-enable-gps-nmea
Active la découverte de position en utilisant le GPS et rapportée avec des traces NMEA.

Cette commande démarrera le moteur GPS, s'il n'est pas déjà démarré.

--location-disable-gps-nmea
Désactive la découverte de position en utilisant le GPS et les traces NMEA.

Si la sortie brute n'est pas activée en même temps, le moteur GPS sera arrêté.

--location-enable-gps-raw
Active la découverte de position en utilisant le GPS et rapportée avec une valeur brute (c'est-à-dire longitude/latitude)
s.

Cette commande démarrera le moteur GPS s'il n'est pas déjà démarré.

--location-disable-gps-raw
Désactive la découverte de localisation à l'aide du GPS et des valeurs brutes.

Si la sortie NMEA n'est pas activée en même temps, le moteur GPS sera arrêté.

--location-enable-cdma-bs
Active la découverte de localisation en utilisant le réseau 3GPP2.
--location-disable-cdma-bs
Désactive la découverte de localisation en utilisant le réseau 3GPP2.
--location-enable-gps-unmanaged
Active la découverte de localisation en utilisant le GPS sans prendre le contrôle du port NMEA tty. Cela permet à d'autres programmes, par exemple gpsd, d'utiliser le port NMEA tty une fois que le moteur GPS a été activé.
--location-disable-gps-unmanaged
Désactive la découverte de localisation en utilisant le GPS et le port non géré.
--location-set-gps-refresh-rate=SEC
Définit le taux de rafraîchissement de la localisation sur l'interface DBus à SEC secondes. S'il est défini à 0, la nouvelle localisation est publiée sur l'interface DBus dès que ModemManager la détecte.
--location-set-supl-server=[IP:PORT] ou --location-set-supl-server=[FQDN:PORT]
Configure la localisation du serveur SUPL A-GPS, en spécifiant soit l'adresse IP (IP:PORT), soit un nom de domaine pleinement qualifié ([FQDN:PORT]).
--location-inject-assistance-data=[PATH]
Injecte des données d'assistance dans le module GNSS, chargées à partir d'un fichier local à l'emplacement PATH. Les données d'assistance doivent être dans un format attendu par l'appareil, par exemple, téléchargées à partir des URL exposées par la propriété 'AssistanceDataServers'.
--location-set-enable-signal
Active la notification des mises à jour de localisation via les signaux de propriété DBus. Ceci est requis si les applications s'appuient sur l'écoute des mises à jour de propriété 'Location', au lieu de requêtes explicites avec la méthode 'GetLocation' protégée par la politique.

Ces mises à jour de signal de propriété DBus sont désactivées par défaut.

--location-set-disable-signal
Désactive la notification des mises à jour de localisation via les signaux de propriété DBus.

OPTIONS DE MESSAGERIE

Toutes les options de messagerie doivent être utilisées avec --modem ou -m.

--messaging-status
Affiche l'état du support de messagerie.
--messaging-list-sms
Liste les SMS disponibles sur un modem donné.
--messaging-create-sms=['CLE1=VALEUR1,...']
Crée un nouveau SMS sur un modem donné. Les CLES peuvent être l'une des suivantes :
'number'

Numéro auquel le message est adressé.
'text'
Texte du message, en UTF-8. Lors de l'envoi, si le texte dépasse la limite de la technologie ou du modem, le message sera divisé en plusieurs parties ou messages. Notez que le texte et les données ne sont jamais fournis en même temps.
'smsc'
Indique le numéro du centre de service SMS.
'validity'
Spécifie la date d'expiration du SMS dans le SMSC.
'class'
Classe de message 3GPP (0..3).
'delivery-report-request'
Spécifie si un rapport de livraison est demandé lors de l'envoi du SMS ('yes' ou 'no')
'storage'
Spécifie le stockage où ce message est conservé. Les stockages peuvent être 'sm', 'me', 'mt', 'sr', 'bm', 'ta'.
--messaging-create-sms-with-data=PATH
Utilise PATH vers un nom de fichier comme données pour créer un nouveau SMS.
--messaging-create-sms-with-text=PATH
Utilise PATH vers un nom de fichier comme message pour créer un nouveau SMS.
--messaging-delete-sms=[PATH|INDEX]
Supprime un SMS d'un modem donné.

OPTIONS HORAIRES

Toutes les opérations horaires nécessitent l'option --modem ou -m.

--time
Affiche l'heure actuelle du réseau de l'opérateur. Cela inclut le fuseau horaire, ce qui est généralement important.

OPTIONS VOCALES

Toutes les opérations vocales nécessitent l'option --modem ou -m.

--voice-list-calls
Liste les appels gérés (initiés, reçus, en cours) sur un modem donné.
--voice-create-call=['CLE1=VALEUR1,...']
Crée un nouvel appel sortant sur un modem donné. Les CLES peuvent être l'une des suivantes :
'number'
Numéro à appeler.
--voice-delete-call=[PATH|INDEX]
Supprime un appel d'un modem donné.

OPTIONS DE FIRMWARE

Toutes les options de firmware nécessitent l'option --modem ou -m.

--firmware-status
Affiche les détails et propriétés spécifiques aux mises à jour de firmware.
--firmware-list
Liste toutes les images de firmware installées sur un modem donné.
--firmware-select=ID
Sélectionne une image de firmware parmi celles installées sur un modem donné. Une liste des images de firmware disponibles peut être vue en utilisant l'option --firmware-list.

L'ID fourni est un identifiant *UNIQUE* pour le firmware.

OPTIONS DE SIGNAL

Toutes les options de signal nécessitent l'option --modem ou -m.

--signal-setup=[Rate]
Configure la récupération d'informations étendues sur la qualité du signal au taux spécifié (en secondes).

Par défaut, ceci est désactivé (taux défini à 0).

--signal-get
Récupère les dernières informations étendues sur la qualité du signal chargées.

OPTIONS OMA

Toutes les options OMA nécessitent l'option --modem ou -m.

--oma-status
Affiche l'état du sous-système de gestion de périphériques OMA.
--oma-start-client-initiated-session=[SESSION TYPE]
Demande de démarrer une session initiée par le client.

Le type de session donné doit être l'un des suivants :
'client-initiated-device-configure'
'client-initiated-prl-update'
'client-initiated-hands-free-activation'

--oma-accept-network-initiated-session=[SESSION ID]
Demande d'accepter une session initiée par le réseau.
--oma-reject-network-initiated-session=[SESSION ID]
Demande de rejeter une session initiée par le réseau.
--oma-cancel-session
Demande d'annuler la session OMA en cours, le cas échéant.

OPTIONS SIM

--pin=PIN
Envoie le code PIN à une carte SIM donnée.
--puk=PUK
Envoie le code PUK à une carte SIM donnée. Ceci doit être utilisé *AVEC* --pin.
--enable-pin
Active la demande de PIN pour une carte SIM donnée. Ceci doit être utilisé *AVEC* --pin.
--disable-pin
Désactive la demande de PIN pour une carte SIM donnée. Ceci doit être utilisé *AVEC* --pin.
--change-pin=PIN
Change le PIN pour une carte SIM donnée. Il sera défini sur PIN. Ceci doit être utilisé *AVEC* --pin pour fournir l'ancien numéro PIN.

OPTIONS DE PORTEUSE

Toutes les options de porteuse nécessitent l'option --bearer ou -b.

-c, --connect
Se connecte à une porteuse donnée.
-x, --disconnect
Se déconnecte d'une porteuse donnée.

OPTIONS SMS

Toutes les options SMS nécessitent l'option --sms ou -s.

--send
Envoie un SMS.
--store
Cette option stockera le SMS dans le stockage par défaut défini par le modem, qui peut être soit la mémoire du modem, soit la mémoire SMS. Pour connaître le stockage par défaut existant, voir l'option --messaging-status.
--store-in-storage=STORAGE
Cette option spécifie le STOCKAGE à utiliser pour les messages SMS. Les valeurs possibles pour STOCKAGE incluent :
'sm'
Carte SIM
'rd'
Zone de stockage des données de la carte SIM.
'me'
Zone de stockage de l'équipement mobile.
'mt'
Somme des stockages de la carte SIM et de l'équipement mobile.
'sr'
Zone de stockage des messages de rapport d'état.
'bm'
Zone de stockage des messages de diffusion.
'ta'
Zone de stockage des messages de l'adaptateur terminal.
--create-file-with-data=CHEMIN
Cette option prend un SMS qui contient des DONNÉES (pas du TEXTE) et créera un fichier local décrit par CHEMIN et y stockera le contenu du SMS.

OPTIONS DE LIAISON

--start
Initier un appel sortant.
--accept
Accepter un appel entrant.
--hangup
Rejeter un appel entrant ou raccrocher un appel en cours.
--send-dtmf=[0-9A-D*#]
Envoyer une séquence DTMF lors d'un appel en cours.

OPTIONS D'APPLICATION

-J, --output-json
Exécuter l'action avec une sortie JSON lisible par machine, à utiliser par exemple par des scripts shell qui dépendent des opérations mmcli.
-K, --output-keyvalue
Exécuter l'action avec une sortie clé-valeur lisible par machine, à utiliser par exemple par des scripts shell qui dépendent des opérations mmcli.
-v, --verbose
Effectuer les actions avec plus de détails signalés et/ou enregistrés.
-V, --version
Retourne la version de ce programme.
-a, --async
Utiliser des méthodes asynchrones. Ceci est purement un outil de développement et n'a aucun bénéfice pratique pour la plupart des opérations utilisateur.
--timeout=SECONDES
Utiliser SECONDES pour le délai d'attente lors de l'exécution des opérations avec cette commande. Cette option est utile lors de l'exécution d'opérations longues, comme --3gpp-scan.

OPTIONS DE DIFFUSION CELLULAIRE

Toutes les options de diffusion cellulaire doivent être utilisées avec --modem ou -m.

--cell-broadcast-status
Afficher l'état du support de diffusion cellulaire.
--cell-broadcast-list-cbm
Lister les messages de diffusion cellulaire disponibles sur un modem donné.
--cell-broadcast-delete-cbm=[CHEMIN|INDEX]
Supprimer un message de diffusion cellulaire au chemin ou à l'index donné.
--cell-broadcast-set-channels=[CANAUX]
Définir la liste des canaux sur lesquels les diffusions cellulaires sont reçues (par exemple, 5370,5371-5372).

EXEMPLES

Envoyer le code PIN à la carte SIM

Vous devrez d'abord connaître le chemin/index approprié pour la carte SIM de votre modem :
$ mmcli -m 0 -K | grep "modem.generic.sim" | awk -F ": " '{ print $2 }'
/org/freedesktop/ModemManager1/SIM/0

Et après cela, vous pouvez simplement utiliser l'index de la carte SIM :
$ sudo mmcli -i 0 --pin=1234
code PIN envoyé avec succès à la carte SIM

Connexion et déconnexion simples

Vous pouvez lancer le processus de connexion simple comme suit :
$ sudo mmcli -m 0 --simple-connect="pin=1234,apn=internet"
modem connecté avec succès

Ensuite, vous pouvez le déconnecter comme suit :
$ sudo mmcli -m 0 --simple-disconnect
tous les bearers du modem ont été déconnectés avec succès

Scan du réseau 3GPP

Le scan des réseaux 3GPP peut prendre beaucoup de temps, un délai d'attente spécifique doit donc être donné :

Envoyer des messages SMS binaires depuis des fichiers

Lister les messages SMS

Statut de la localisation GPS

Vous devez d'abord vérifier si le modem possède des capacités de localisation spécifiques au GPS. Notez que nous supposerons que le modem est exposé sous l'index 0 ; si vous avez plus d'un modem, utilisez simplement --list-modems pour vérifier l'index de modem approprié :


$ mmcli -m 0 --location-status
----------------------------
Localisation | capacités : 3gpp-lac-ci, gps-raw, gps-nmea
| activé : aucun
| signaux : non

La sortie indique que le modem prend en charge les sources de localisation code de zone/ID de cellule 3GPP, GPS brut et GPS NMEA. Aucun n'est encore activé, car nous n'avons pas activé le modem, ce que nous pouvons faire en lançant :


$ sudo mmcli -m 0 --enable
modem activé avec succès


$ mmcli -m 0 --location-status
----------------------------
Localisation | capacités : 3gpp-lac-ci, gps-raw, gps-nmea
| activé : 3gpp-lac-ci
| signaux : non

Activation de la technologie de localisation GPS

Nous pouvons démarrer le moteur GPS en activant les sources de localisation GPS BRUT ou NMEA :


$ sudo mmcli -m 0 \
--location-enable-gps-raw \
--location-enable-gps-nmea
paramétrage de la collecte de localisation réussi

Si nous vérifions à nouveau le statut, nous verrons que les localisations spécifiques au GPS sont activées :


$ mmcli -m 0 --location-status
--------------------------------
Localisation | capacités : 3gpp-lac-ci, gps-raw, gps-nmea
| activé : 3gpp-lac-ci, gps-raw, gps-nmea
| signaux : non

NAME

SYNOPSIS

mmcli [options] [path] [command]

DESCRIPTION

The mmcli tool provides a command line interface to interact with ModemManager. It allows users to query modem information, control modem settings, and manage connections.

The command syntax is generally:

mmcli -M | --monitor

mmcli -L | --list

mmcli -S | --sim

Injecting assistance data

If the modem device does not have an ongoing connection (e.g. no mobile network coverage) but the system has other means to access the Internet (e.g. WiFi), the user may be able to download location assistance data and inject it in the module.

E.g. If the device supports XTRA assistance data, the user may download it from one of the servers listed by ModemManager and manually inject it afterwards. The XTRA assistance data is usually valid for several days.


$ mmcli -m 0 --location-status
--------------------------------
Location | capabilities: 3gpp-lac-ci, gps-raw, gps-nmea, agps-msa, agps-msb
| enabled: 3gpp-lac-ci
| signals: no
--------------------------------
GPS | refresh rate: 30 seconds
| a-gps supl server: supl.google.com:7276
| supported assistance: xtra
| assistance servers: https://xtrapath3.izatcloud.net/xtra3grcej.bin
| https://xtrapath1.izatcloud.net/xtra3grcej.bin
| https://xtrapath2.izatcloud.net/xtra3grcej.bin


$ wget -q https://xtrapath3.izatcloud.net/xtra3grcej.bin


$ sudo mmcli -m 0 --location-inject-assistance-data=./xtra3grcej.bin
successfully injected assistance data


$ sudo mmcli -m 0 --location-enable-gps-nmea
successfully setup location gathering


$ sudo mmcli -m 0 --location-enable-gps-raw
successfully setup location gathering

Setting the Cell Broadcast channel list

The channel list can be set as a comma separated list of channels or channel intervals:


$ sudo mmcli -m 0 \
--cell-broadcast-set-channels=5370,5371,5373-5000
successfully set channels in the modem

Key-Value output

Writing shell scripts that use mmcli to perform operations with the modem is easy when using the --output-keyvalue option. For example, you could gather all the main status information of the modem with a single call and then parse it to read single fields:


$ STATUS=$(mmcli -m 0 --output-keyvalue)
$ echo "${STATUS}" | grep "modem.generic.state " | awk -F ": " '{ print $2 }'
failed
$ echo "${STATUS}" | grep "modem.generic.state-failed-reason " | awk -F ": " '{ print $2 }'
sim-missing
