mmap2(2) Manuel des appels système mmap2(2)

NOM

mmap2 - mapper des fichiers ou des périphériques en mémoire

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/mman.h>    /* Définition des constantes MAP_* et PROT_* */
#include <sys/syscall.h> /* Définition des constantes SYS_* */
#include <unistd.h>
void *syscall(SYS_mmap2, unsigned long addr, unsigned long length,
              unsigned long prot, unsigned long flags,
              unsigned long fd, unsigned long pgoffset);

DESCRIPTION

Ceci n'est probablement pas l'appel système qui vous intéresse ; consultez plutôt mmap(2), qui décrit la fonction d'encapsulation glibc qui appelle cet appel système.

L'appel système mmap2() fournit la même interface que mmap(2), à l'exception du fait que le dernier argument spécifie le décalage dans le fichier en unités de 4096 octets (au lieu d'octets, comme le fait mmap(2)). Cela permet aux applications qui utilisent un off_t 32 bits de mapper de gros fichiers (jusqu'à 2^44 octets).

VALEUR DE RETOUR

En cas de succès, mmap2() renvoie un pointeur vers la zone mappée. En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

EFAULT
Problème lors de la récupération des données depuis l'espace utilisateur.
EINVAL
(Diverses plateformes où la taille de page n'est pas de 4096 octets.) offset * 4096 n'est pas un multiple de la taille de page du système .

mmap2() peut également renvoyer l'une des erreurs décrites dans mmap(2).

VERSIONS

Sur les architectures où cet appel système est présent, la fonction d'encapsulation glibc mmap() appelle cet appel système plutôt que l'appel système mmap(2).

Cet appel système n'existe pas sur x86-64.

Sur ia64, l'unité pour offset est en réalité la taille de page du système, plutôt que 4096 octets.

NORMES

Linux.

HISTORIQUE

Linux 2.3.31.

VOIR AUSSI

getpagesize(2), mmap(2), mremap(2), msync(2), shm_open(3)
