mtrace(3) Manuel des fonctions de bibliothèque mtrace(3)

NOM

mtrace, muntrace - suivi des allocations mémoire

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <mcheck.h>
void mtrace(void);
void muntrace(void);

DESCRIPTION

La fonction mtrace() installe des fonctions d'accroche pour les fonctions d'allocation mémoire (malloc(3), realloc(3) memalign(3), free(3)). Ces fonctions d'accroche enregistrent des informations de suivi sur l'allocation et la désallocation de mémoire. Ces informations de suivi peuvent être utilisées pour détecter les fuites de mémoire et les tentatives de libérer de la mémoire non allouée dans un programme.

La fonction muntrace() désactive les fonctions d'accroche installées par mtrace(), de sorte que les informations de suivi ne sont plus enregistrées pour les fonctions d'allocation mémoire. Si aucune fonction d'accroche n'a été installée avec succès par mtrace(), muntrace() ne fait rien.

Lorsque mtrace() est appelée, elle vérifie la valeur de la variable d'environnement MALLOC_TRACE, qui doit contenir le nom du chemin d'un fichier dans lequel les informations de suivi doivent être enregistrées. Si le nom du chemin est ouvert avec succès, il est tronqué à une longueur nulle.

Si MALLOC_TRACE n'est pas définie, ou si le nom du chemin qu'elle spécifie est invalide ou non inscriptible, alors aucune fonction d'accroche n'est installée, et mtrace() n'a aucun effet. Dans les programmes définis avec set-user-ID et set-group-ID, MALLOC_TRACE est ignorée, et mtrace() n'a aucun effet.

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
mtrace (), muntrace () Sécurité des threads MT-Non sécurisé

NORMES

GNU.

NOTES

En utilisation normale, mtrace() est appelée une fois au début de l'exécution d'un programme, et muntrace() n'est jamais appelée.

La sortie de suivi produite après un appel à mtrace() est textuelle, mais n'est pas conçue pour être lisible par l'homme. La bibliothèque C GNU fournit un script Perl, mtrace(1), qui interprète le journal de suivi et produit une sortie lisible par l'homme. Pour de meilleurs résultats, le programme suivi doit être compilé avec le débogage activé, afin que les informations de numéro de ligne soient enregistrées dans l'exécutable.

Le suivi effectué par mtrace() entraîne une pénalité de performance (si MALLOC_TRACE pointe vers un nom de chemin valide et inscriptible).

BOGUES

Les informations de numéro de ligne produites par mtrace(1) ne sont pas toujours précises : les références de numéro de ligne peuvent pointer vers la ligne de code source précédente ou suivante (non vide).

EXEMPLES

La session shell ci-dessous démontre l'utilisation de la fonction mtrace() et de la commande mtrace(1) dans un programme qui présente des fuites de mémoire à deux endroits différents. La démonstration utilise le programme suivant :


$ cat t_mtrace.c

#include <mcheck.h>
#include <stdio.h>
#include <stdlib.h>
int
main(void)
{
    mtrace();
    for (unsigned int j = 0; j < 2; j++)
        malloc(100);            /* Jamais libéré - une fuite mémoire */
    calloc(16, 16);             /* Jamais libéré - une fuite mémoire */
    exit(EXIT_SUCCESS);
}

Lorsque nous exécutons le programme comme suit, nous constatons que mtrace() a diagnostiqué des fuites de mémoire à deux endroits différents du programme :


$ cc -g t_mtrace.c -o t_mtrace
$ export MALLOC_TRACE=/tmp/t
$ ./t_mtrace
$ mtrace ./t_mtrace $MALLOC_TRACE
Mémoire non libérée :
-----------------
   Adresse     Taille     Appelant
0x084c9378     0x64  à /home/cecilia/t_mtrace.c:12
0x084c93e0     0x64  à /home/cecilia/t_mtrace.c:12
0x084c9448    0x100  à /home/cecilia/t_mtrace.c:16

Les deux premiers messages concernant la mémoire non libérée correspondent aux deux appels à malloc(3) dans la boucle for. Le dernier message correspond à l'appel à calloc(3) (qui appelle à son tour malloc(3)).

VOIR AUSSI

mtrace(1), malloc(3), malloc_hook(3), mcheck(3)
