mtx-context(1) Gestion des processus ConTeXt mtx-context(1)

NOM


mtx-context - Gestion des processus ConTeXt

SYNTAXE

mtxrun --script context [ OPTIONS ... ] [ FICHIERS ]

DESCRIPTION

Gestion des processus ConTeXt

OPTIONS : BASIQUES

--run
traite (un ou plusieurs) fichiers (action par défaut)
--make
crée les formats context
--ctx=name
utilise le fichier ctx (spécification de gestion de processus)
--noctx
ignore les directives et drapeaux ctx
--interface
utilise l'interface utilisateur spécifiée (par défaut : en)
--autopdf
ferme le fichier pdf dans le visualiseur et lance le visualiseur pdf ensuite
--purge
supprime les fichiers après une exécution (optionnel ou non) (--pattern=...)
--purgeall
supprime tous les fichiers après une exécution (optionnel ou non) (--pattern=...)
--usemodule=list
charge le module ou style donné, normalement partie de la distribution
--environment=list
charge le fichier d'environnement donné en premier (styles de document)
--mode=list
active les modes donnés (traitement conditionnel dans les styles)
--path=list
consulte également les chemins donnés lorsque les fichiers sont recherchés
--arguments=list
définit des variables consultables pendant une exécution (paires clé/valeur)
--randomseed=number
définit la graine aléatoire
--result=name
renomme la sortie résultante avec le nom donné
--trackers=list
définit des variables de suivi (affiche la liste avec --showtrackers)
--directives=list
définit des variables de directive (affiche la liste avec --showdirectives)
--silent=list
désactive les catégories de logs (affiche la liste avec --showlogcategories)
--strip
supprime le code Lua (destiné uniquement à la production où aucune erreur n'est attendue)
--errors=list
affiche les erreurs à la fin d'une exécution, quitte si dans la liste (aussi avec --silent)
--htmlerrorpage
génère une page d'erreur html à la place (optionnel : =scite)
--noconsole
désactive la journalisation sur la console (fichier journal uniquement)
--nodummy
ne crée pas de fichier factice (peut induire en erreur les visualiseurs pdf qui conservent le fichier en vue)
--purgeresult
supprime le fichier résultat avant l'exécution
--find=string
recherche le modèle donné dans les sources de documentation
--forcexml
force l'ébauche xml
--forcecld
force l'ébauche cld (document lua context)
--forcelua
force l'ébauche lua (comme texlua)
--forcemp
force l'ébauche mp
--arrange
exécute un passage d'imposition supplémentaire, étant donné que le style configure l'imposition
--noarrange
ignore les spécifications d'imposition dans le style
--pages
rapporte les numéros de page des pages nommées et liste les références (--page=... ou --page=...)
--jit
utilise luajittex avec jit désactivé (n'utilise que la machine virtuelle plus rapide)
--jiton
utilise luajittex avec jit activé (dans la plupart des cas pas plus rapide, voire plus lent)
--once
ne s'exécute qu'une fois (aucun fichier de données multipasse n'est produit)
--runs
traite au maximum ce nombre de fois
--forcedruns
traite ce nombre de fois (permet des exécutions d'essai d'optimisation)
--batchmode
s'exécute sans s'arrêter et n'affiche pas de messages sur la console
--nonstopmode
s'exécute sans s'arrêter
--nocompactfonts
revient à une mise à l'échelle de polices moins efficace (traditionnelle)
--nosynctex
n'initialise jamais synctex (pour les exécutions de production)
--synctex
s'exécute avec synctex activé (mieux vaut utiliser tupsynctex[state=start])
--nodates
omet les dates d'exécution dans le fichier pdf (valeur optionnelle : un nombre (décalage 1970) ou une chaîne "AAAA-MM-JJ HH:MM")
--nocompression
désactive de force la compression dans le backend
--trailerid
identifiant de remorque alternatif (ou constant)
--generate
génère la base de données de fichiers, etc. (comme le fait luatools)
--paranoid
ne descend pas vers .. et ../..
--version
rapporte la version installée de context
--global
suppose que le fichier donné est présent ailleurs
--nofile
utilise un fichier factice comme nom de tâche
--forceinput
utilise ce fichier comme fichier d'entrée au lieu de celui donné
--expert
affiche quelques options supplémentaires

OPTIONS : EXPERT

--touch
met à jour le numéro de version de context (fournit aussi --expert, optionnellement fournit --basepath)
--nostatistics
omet les statistiques d'exécution à la fin de la tâche
--profile
profilage de la tâche (utiliser : mtxrun --script profile --analyze)
--timing
génère un aperçu des temps et des statistiques
--keeptuc
conserve les fichiers tuc précédents (jobname-tuc-[run].tmp)
--keeppdf
conserve les fichiers pdf précédents (jobname-pdf-keep.tmp)
--keeplog
conserve les fichiers journaux précédents (jobname-log-[run].tmp)
--notuc
ne pas écrire de fichier tuc
--lmtx
force le mode lmtx (lorsqu'il est disponible)

mtx-context(1) — ConTeXt tools

NAME

mtxrun — ConTeXt MetaTool runner

SYNOPSIS

mtxrun [options...] [script] [arguments...]

DESCRIPTION

The ConTeXt MetaTool runner, also known as mtxrun, is a command-line tool that serves as an interface to the ConTeXt Mark IV system. It allows users to compile ConTeXt documents, manage ConTeXt modules, and perform various administrative tasks related to the ConTeXt environment.

The tool supports a wide range of options to control its behavior, including compilation modes, file processing, and debugging features.
