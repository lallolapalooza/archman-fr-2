NOM

mtree — format des fichiers de hiérarchie de répertoires mtree

DESCRIPTION

Le format mtree est un format textuel qui décrit une collection d'objets de système de fichiers. Ces fichiers sont typiquement utilisés pour créer ou vérifier des hiérarchies de répertoires.

Format général

Un fichier mtree se compose d'une série de lignes, chacune fournissant des informations sur un seul objet de système de fichiers. Les espaces blancs en début de ligne sont toujours ignorés.

Lors de l'encodage des noms de fichiers ou de chemins, tout caractère backslash ou tout caractère en dehors des 95 caractères ASCII imprimables doit être encodé comme un backslash suivi de trois chiffres octaux. Lors de la lecture des fichiers mtree, toute apparition d'un backslash suivi de trois chiffres octaux doit être convertie en caractère correspondant.

Chaque ligne est interprétée indépendamment comme l'un des types suivants :

Vide
Les lignes vides sont ignorées.
Commentaire
Les lignes commençant par # sont ignorées.
Spécial
Les lignes commençant par / sont des commandes spéciales qui influencent l'interprétation des lignes suivantes.
Relatif
Si le premier mot délimité par des espaces n'a pas de caractères /, c'est le nom d'un fichier dans le répertoire courant. Toute entrée relative décrivant un répertoire change le répertoire courant.
point-point
En tant que cas spécial, une entrée relative avec le nom de fichier .. change le répertoire courant pour le répertoire parent. Les options sur les entrées point-point sont toujours ignorées.
Complet
Si le premier mot délimité par des espaces a un caractère / après le premier caractère, c'est le chemin d'un fichier relatif au répertoire de départ. Il peut y avoir plusieurs entrées complètes décrivant le même fichier.

Certains outils qui traitent les fichiers mtree peuvent exiger que plusieurs lignes décrivant le même fichier apparaissent consécutivement. Il n'est pas permis que le même fichier soit mentionné à la fois par une spécification de fichier relative et une spécification complète.

Commandes spéciales

Deux commandes spéciales sont actuellement définies :

/set
Cette commande définit des valeurs par défaut pour une ou plusieurs clés. Elle est suivie sur la même ligne d'une ou plusieurs définitions de clés séparées par des espaces. Ces définitions s'appliquent à tous les fichiers suivants qui ne spécifient pas de valeur pour cette clé.
/unset
Cette commande supprime toute valeur par défaut définie par une commande /set précédente. Elle est suivie sur la même ligne d'une ou plusieurs clés séparées par des espaces.

Clés

Après le nom du fichier, une entrée complète ou relative se compose de zéro ou plusieurs définitions de clés séparées par des espaces. Chaque définition se compose d'une clé de la liste suivante immédiatement suivie d'un signe '=' et d'une valeur. Les programmes lisant les fichiers mtree devraient signaler les clés non reconnues.

Les clés actuellement supportées sont les suivantes :

cksum
La somme de contrôle du fichier en utilisant l'algorithme par défaut spécifié par l'utilitaire cksum(1).
device
Le numéro de périphérique pour les types de fichiers bloc ou char. La valeur doit être l'une des formes suivantes :
format,major,minor[,subunit]
Un périphérique avec les champs major, minor et optionnellement subunit. Leur signification est spécifiée par le format du système d'exploitation. Voir ci-dessous pour les formats valides.
number
Nombre opaque (tel que stocké sur le système de fichiers).

Les valeurs suivantes pour format sont reconnues : natif, 386bsd, 4bsd, bsdos, freebsd, hpux, isc, linux, netbsd, osf1, sco, solaris, sunos, svr3, svr4, et ultrix.

Voir mknod(8) pour plus de détails.

contents
Le chemin complet d'un fichier qui contient les données de ce fichier.
flags
Les drapeaux du fichier sous forme de nom symbolique. Voir chflags(1) pour des informations sur ces noms. Si aucun drapeau ne doit être défini, la chaîne “none” peut être utilisée pour remplacer la valeur par défaut actuelle.
gid
Le groupe du fichier sous forme de valeur numérique.
gname
Le groupe du fichier sous forme de nom symbolique.
ignore
Ignorer toute hiérarchie de fichiers sous ce fichier.
inode
Le numéro d'inode.
link
La cible du lien symbolique lorsque le type est 'link'.
md5
Le résumé de message MD5 du fichier.
md5digest
Un synonyme de md5.
mode
Les permissions du fichier actuel sous forme de valeur numérique (octale) ou symbolique.
nlink
Le nombre de liens physiques que le fichier est censé avoir.
nochange
S'assurer que ce fichier ou répertoire existe, mais ignorer tous les attributs par ailleurs.
optional
Le fichier est optionnel ; ne pas signaler d'erreur concernant le fichier s'il n'est pas présent dans la hiérarchie de fichiers.
resdevice
Le numéro de périphérique « resident » du fichier, c'est-à-dire l'ID du périphérique qui contient le fichier. Son format est le même que celui pour device.
ripemd160digest
Le résumé de message RIPEMD160 du fichier.
rmd160
Un synonyme de ripemd160digest.
rmd160digest
Un synonyme de ripemd160digest.
sha1
Le résumé de message FIPS 160-1 (« SHA-1 ») du fichier.
sha1digest
Un synonyme de sha1.
sha256
Le résumé de message SHA-256 du fichier.
sha256digest
Un synonyme de sha256.
sha512
Le résumé de message SHA-512 du fichier.
sha512digest
Un synonyme de sha512.
type
Le type du fichier. Les types reconnus sont : block, char, dir, fifo, file, link, et socket. Si cette clé est spécifiée, elle doit être la première dans la liste des clés.
uid
Le fichier propriétaire sous forme de valeur numérique.
uname
Le fichier propriétaire sous forme de nom symbolique.

Les programmes qui traitent les fichiers mtree sont censés enregistrer une erreur s'ils rencontrent des fichiers qui ne correspondent pas aux descriptions fournies, à moins que la clé optional n'ait été spécifiée.

Les programmes qui traitent les fichiers mtree ne devraient pas traiter de manière récursive les répertoires sauf si cela est spécifiquement indiqué par le programme.

Pour plus d'informations sur la génération de fichiers mtree, voir la page de manuel mtree(8).

HISTORIQUE

L'utilitaire mtree est apparu dans 4.3BSD-Reno. La capacité de somme de contrôle MD5 a été ajoutée dans FreeBSD 2.1, en réponse à l'utilisation répandue de programmes pouvant usurper cksum(1). Les sommes de contrôle SHA-1 et RIPEMD160 ont été ajoutées dans FreeBSD 4.0, car de nouvelles attaques ont démontré les faiblesses de MD5. La somme de contrôle SHA-256 a été ajoutée dans FreeBSD 6.0. La prise en charge des indicateurs de fichier a été ajoutée dans FreeBSD 4.0, et provient en grande partie de NetBSD. Le format d'entrée « complet » a été ajouté par NetBSD.
