Nom

mtools.conf - fichiers de configuration de mtools

Description

Cette page de manuel décrit les fichiers de configuration de mtools. Ils s'appellent `/etc/mtools.conf' et `~/.mtoolsrc'. Si la variable d'environnement MTOOLSRC est définie, son contenu est utilisé comme nom de fichier pour un troisième fichier de configuration. Ces fichiers de configuration décrivent les éléments suivants :

*  
Indicateurs et variables de configuration globaux
*  
Indicateurs et variables par lecteur

Emplacement des fichiers de configuration

`/etc/mtools.conf' est le fichier de configuration global du système, et `~/.mtoolsrc' est le fichier de configuration privé de l'utilisateur.

Sur certains systèmes, le fichier de configuration global s'appelle `/etc/default/mtools.conf'.

  Syntaxe générale du fichier de configuration

Les fichiers de configuration sont composés de sections. Chaque section commence par un mot-clé identifiant la section, suivi de deux-points. Viennent ensuite des affectations de variables et des indicateurs. Les affectations de variables prennent la forme suivante :

nom=valeur

Les indicateurs sont des mots-clés isolés sans signe égal ni valeur qui les suit. Une section se termine soit à la fin du fichier, soit là où la section suivante commence.

Les lignes commençant par un dièse (#) sont des commentaires. Les caractères de nouvelle ligne sont équivalents aux espaces blancs (sauf là où ils terminent un commentaire). Le fichier de configuration ne respecte pas la casse, sauf pour les éléments entre guillemets (tels que les noms de fichiers).

Valeurs par défaut

Pour la plupart des plateformes, mtools contient des valeurs par défaut raisonnables compilées en dur pour les lecteurs de disquettes physiques. Ainsi, vous n'avez généralement pas besoin de vous soucier du fichier de configuration si tout ce que vous voulez faire avec mtools est d'accéder à vos lecteurs de disquettes. En revanche, le fichier de configuration est nécessaire si vous souhaitez également utiliser mtools pour accéder à vos partitions de disque dur et aux fichiers d'image DOSEMU.

Variables globales

Les indicateurs globaux peuvent être définis sur 1 ou 0.

Les indicateurs globaux suivants sont reconnus :

MTOOLS_SKIP_CHECK 
S'il est défini sur 1, mtools ignore la plupart de ses vérifications de cohérence. Ceci est nécessaire pour lire certains disques Atari qui ont été créés avec des ROMs plus anciennes et qui ne seraient pas reconnus autrement.
MTOOLS_FAT_COMPATIBILITY 
S'il est défini sur 1, mtools ignore les vérifications de taille FAT. Certains disques ont une FAT plus grande que nécessaire. Ceux-ci sont rejetés si cette option n'est pas activée.
MTOOLS_LOWER_CASE 
S'il est défini sur 1, mtools affiche les noms de fichiers courts entièrement en majuscules en minuscules. Ceci a été fait pour permettre un comportement cohérent avec les anciennes versions de mtools qui ne connaissaient pas les bits de casse.
MTOOLS_NO_VFAT 
S'il est défini sur 1, mtools ne générera pas d'entrées VFAT pour les noms de fichiers mixtes, mais sinon des noms de fichiers DOS valides. Ceci est utile lorsque l'on travaille avec des versions DOS qui ne comprennent pas les noms longs VFAT, comme FreeDOS.
MTOOLS_DOTTED_DIR 
Dans un répertoire large, affiche le nom court avec un point au lieu d'espaces séparant le nom de base et l'extension.
MTOOLS_NAME_NUMERIC_TAIL 
S'il est défini sur un (par défaut), génère des suffixes numériques pour tous les noms longs (~1). S'il est défini sur zéro, ne génère des suffixes numériques que si un conflit serait autrement survenu.
MTOOLS_TWENTY_FOUR_HOUR_CLOCK 
Si 1, utilise la notation européenne pour les heures (horloge de vingt-quatre heures), sinon utilise la notation UK/US (am/pm).
MTOOLS_LOCK_TIMEOUT 
Combien de secondes attendre qu'un appareil verrouillé se libère. La valeur par défaut est 30.

Exemple : Insérer la ligne suivante dans votre fichier de configuration demande à mtools d'ignorer les vérifications de cohérence :

  MTOOLS_SKIP_CHECK=1

Les variables globales peuvent également être définies via l'environnement :

  export MTOOLS_SKIP_CHECK=1

Les variables globales de type chaîne peuvent être définies sur n'importe quelle valeur :

MTOOLS_DATE_STRING 
Le format utilisé pour afficher les dates des fichiers. Par défaut, c'est jj-mm-aaaa.

Indicateurs et variables par lecteur

  Informations&#x00A0;générales

Les indicateurs et valeurs par lecteur peuvent être décrits dans une section de lecteur. Une section de lecteur commence par drive "lettre_du_lecteur" :

Viennent ensuite des paires variable-valeur et des indicateurs.

Voici un exemple de description de lecteur :

  drive a:
    file="/dev/fd0" use_xdf=1

  Informations&#x00A0;de&#x00A0;localisation

Pour chaque lecteur, vous devez décrire où ses données sont stockées physiquement (fichier image, périphérique physique, partition, décalage).

file 
Le nom du fichier ou du périphérique contenant l'image disque. Ceci est obligatoire. Le nom du fichier doit être entouré de guillemets.
partition 
Indique à mtools de traiter le lecteur comme un périphérique partitionné et d'utiliser la partition donnée. Seules les partitions primaires sont accessibles par cette méthode, et elles sont numérotées de 1 à 4. Pour les partitions logiques, utilisez la variable plus générale offset. La variable partition est destinée aux supports amovibles tels que les disques Syquest, les lecteurs ZIP et les disques magnéto-optiques. Bien que les systèmes DOS traditionnels considèrent les disques Syquest et les disques magnéto-optiques comme des `disquettes géantes' non partitionnées, OS/2 et Windows NT les traitent comme des disques durs, c'est-à-dire des périphériques partitionnés. L'indicateur partition est également utile pour les images disque DOSEMU. Il n'est pas recommandé pour les disques durs pour lesquels un accès direct aux partitions est disponible par montage.
offset 
Décrit où commence le système de fichiers MS-DOS dans le fichier. Ceci est utile pour les partitions logiques dans les images disque DOSEMU et pour les disques RAM ATARI. Par défaut, il est égal à zéro, ce qui signifie que le système de fichiers commence juste au début du périphérique ou du fichier.

  Configuration de la géométrie du disque

Les informations de géométrie décrivent les caractéristiques physiques du disque. Elles ont trois objectifs :

formatage 
Les informations de géométrie sont écrites dans le secteur d'amorçage du nouveau disque créé. Cependant, vous pouvez également décrire les informations de géométrie sur la ligne de commande. Voir la section mformat pour plus de détails.
filtrage 
Sur certains systèmes Unix, il existe des nœuds de périphérique qui ne s'appliquant
port one physical géométrie. Par exemple, vous pourriez avoir besoin d'un nœud différent pour accéder à un disque comme étant de haute densité ou de basse densité. La géométrie est comparée à la géométrie réelle stockée sur le secteur de démarrage pour s'assurer que ce nœud de périphérique est capable de lire correctement le disque. Si la géométrie ne correspond pas, cette entrée de lecteur échoue et la prochaine entrée de lecteur portant la même lettre de lecteur est tentée. Voir la section descriptions multiples, pour plus de détails sur la fourniture de plusieurs descriptions pour une seule lettre de lecteur.
Si aucune information de géométrie n'est fournie dans le fichier de configuration, tous les disques sont acceptés. Sur Linux (et sur SPARC), il existe des nœuds de périphériques avec une géométrie configurable (`/dev/fd0', `/dev/fd1' etc.), et le filtrage n'est donc pas nécessaire (et ignoré) pour les lecteurs de disques. (Mtools effectue toujours un filtrage sur les fichiers plats (images disque) sous Linux : ceci est principalement destiné à des fins de test, car je n'ai pas accès à un Unix qui aurait réellement besoin de filtrage).
Si vous n'avez pas besoin de filtrage, mais souhaitez tout de même une géométrie par défaut pour le formatage, vous pouvez désactiver le filtrage à l'aide de l'indicateur mformat_only.
Si vous souhaitez un filtrage, vous devez fournir l'indicateur filter. Si vous fournissez une géométrie, vous devez fournir l'un des deux indicateurs.
géométrie initiale 
Sur les périphériques qui le prennent en charge (généralement les périphériques de disquette), les informations de géométrie sont également utilisées pour définir la géométrie initiale. Cette géométrie initiale est appliquée lors de la lecture du secteur de démarrage, qui contient la géométrie réelle. Si aucune information de géométrie n'est fournie dans le fichier de configuration, ou si l'indicateur mformat_only est fourni, aucune configuration initiale n'est effectuée.
Sous Linux, la géométrie initiale n'est pas vraiment nécessaire, car les périphériques configurables sont capables de détecter automatiquement le type de disque avec suffisamment de précision (pour la plupart des formats courants) pour lire le secteur de démarrage.

Des informations de géométrie incorrectes peuvent entraîner des erreurs très étranges. C'est pourquoi je vous recommande vivement d'ajouter l'indicateur mformat_only à la description de votre lecteur, sauf si vous avez réellement besoin du filtrage ou de la géométrie initiale.

Les variables liées à la géométrie suivantes sont disponibles :

cylinders 

tracks
Le nombre de cylindres. (cylinders est la forme préférée, tracks est considéré comme obsolète)
heads 
Le nombre de têtes (côtés).
sectors 
Le nombre de secteurs par piste.

Exemple : la section de lecteur suivante décrit un lecteur de 1,44 Mo :

  drive a:
      file="/dev/fd0H1440"
      fat_bits=12
      cylinders=80 heads=2 sectors=18
      mformat_only

Les descriptions de géométrie abrégées suivantes sont disponibles :

1.44m 
disque 3 1/2 haute densité. Équivalent à : fat_bits=12 cylinders=80 heads=2 sectors=18
1.2m 
disque 5 1/4 haute densité. Équivalent à : fat_bits=12 cylinders=80 heads=2 sectors=15
720k 
disque 3 1/2 double densité. Équivalent à : fat_bits=12 cylinders=80 heads=2 sectors=9
360k 
disque 5 1/4 double densité. Équivalent à : fat_bits=12 cylinders=40 heads=2 sectors=9

Les descriptions de format abrégées peuvent être modifiées. Par exemple, 360k sectors=8 décrit un disque de 320 Ko et est équivalent à : fat_bits=12 cylinders=40 heads=2 sectors=8

  Flags d'ouverture

De plus, les indicateurs suivants sont disponibles :

sync 
Toutes les opérations d'E/S sont effectuées de manière synchrone
nodelay 
Le périphérique ou le fichier est ouvert avec l'indicateur O_NDELAY. Ceci est nécessaire sur certaines architectures non-Linux.
exclusive 
Le périphérique ou le fichier est ouvert avec l'indicateur O_EXCL. Sous Linux, cela garantit un accès exclusif au lecteur de disquette. Sur la plupart des autres architectures, et pour les fichiers plats, cela n'a aucun effet.

  Variables de lecteur à usage général

Les variables de lecteur à usage général suivantes sont disponibles. Selon leur type, ces variables peuvent être définies sur une chaîne (precmd, postcmd) ou un entier (tous les autres)

fat_bits 
Le nombre de bits FAT. Cela peut être 12 ou 16. Ceci est très rarement nécessaire, car cela peut presque toujours être déduit des informations du secteur de démarrage. Au contraire, décrire le nombre de bits FAT peut en fait être préjudiciable si vous vous trompez. Vous ne devriez l'utiliser que si mtools se trompe sur le nombre de bits FAT auto-détecté, ou si vous souhaitez formater un disque avec un nombre étrange de bits FAT.
codepage 
Décrit la page de codes DOS utilisée pour les noms de fichiers courts. C'est un nombre compris entre 1 et 999. Par défaut, la page de codes 850 est utilisée. La raison en est que cette page de codes contient la plupart des caractères qui sont également disponibles en ISO-Latin-1. Vous pouvez également spécifier une page de codes globale pour tous les lecteurs en utilisant le paramètre global default_codepage (en dehors de toute description de lecteur). Ce paramètre existe à partir de la version 4.0.0
data_map 
Remappe les données à partir du fichier image. Ceci est utile pour les fichiers image qui pourraient nécessiter l'insertion de secteurs remplis de zéros supplémentaires. C'est le cas par exemple pour les images de disquettes IBM 3174. Ces images représentent des disquettes avec moins de secteurs sur leur premier cylindre. Ces secteurs manquants ne sont pas stockés dans l'image, mais sont toujours comptés dans la disposition du système de fichiers. Le data_map permet de simuler ces secteurs manquants pour les couches supérieures de mtools. Un data_map est une séquence séparée par des virgules de type de source et de taille. Le type de source peut être zero pour les secteurs remplis de zéros créés par map, skip pour les données dans l'image brute à ignorer (sautées), et rien pour les données à utiliser telles quelles (copiées) à partir de l'image brute. Le datamap est automatiquement complété par un dernier élément implicite de données à utiliser telles quelles à partir du décalage actuel jusqu'à la fin du fichier. Chaque taille est un nombre suivi d'une unité : s pour un secteur de 512 octets, K pour des Kilo-octets, M pour des Méga-octets, G pour des Giga-octets, et rien pour des octets seuls.
Exemple :
data_map=1s,zero31s,28s,skip1s serait une carte à utiliser avec les images de disquettes IBM 3174. Le premier secteur (1s, secteur de démarrage) est utilisé tel quel. Suivent 31 secteurs factices remplis de zéros (zero31s), puis les 28 secteurs suivants de l'image (28s) sont utilisés tels quels (ils contiennent la FAT et le répertoire racine), puis un secteur de l'image est sauté (skip1s), et enfin le reste de l'image est utilisé tel quel (implicite)
precmd 
Exécute la commande donnée avant d'ouvrir le périphérique. Sur certaines variantes de Solaris, il est nécessaire d'appeler 'volcheck -v' avant d'ouvrir un périphérique de disquette, afin que le système remarque qu'il y a bien un disque dans le lecteur. precmd="volcheck -v" dans la clause drive établit le comportement souhaité.
postcmd 
Exécute la commande donnée après la fermeture du périphérique. Peut être utile si mtools partage le fichier image avec une autre application, afin de libérer le fichier image pour cette application.
blocksize 
Ce paramètre représente une taille de bloc par défaut qui sera toujours utilisée sur ce périphérique. Toutes les E/S sont effectuées avec des multiples de cette taille de bloc, indépendamment de la taille de secteur enregistrée dans le secteur de démarrage du système de fichiers. Ceci est utile pour les périphériques caractères dont la taille de secteur n'est pas de 512, comme par exemple les lecteurs de CD-ROM sous Solaris.

Seule la variable file est obligatoire. Les autres paramètres peuvent être omis. Dans ce cas, une valeur par défaut ou une valeur auto-détectée est utilisée.

  Flags de lecteur à usage général

Un indicateur peut être défini sur 1 (activé) ou 0 (désactivé). Si la valeur est omise, il est activé. Par exemple, scsi est équivalent à scsi=1

nolock 
Indique à mtools de ne pas utiliser de verrouillage sur ce lecteur. Ceci est nécessaire sur les systèmes avec des sémantiques de verrouillage boguées. Cependant, l'activation de cette option rend l'opération moins sûre dans les cas où plusieurs utilisateurs peuvent accéder au même lecteur en même temps.
scsi 
Lorsqu'il est défini sur 1, cette option indique à mtools d'utiliser les E/S SCSI brutes au lieu des appels standard de lecture/écriture pour accéder au périphérique. Actuellement, cela est pris en charge sur HP-UX, Solaris et SunOS. C'est nécessaire car sur certaines architectures, comme SunOS ou Solaris, les médias PC ne peuvent pas être accessibles en utilisant les appels système read et write, car le système d'exploitation s'attend à ce qu'ils contiennent une "étiquette de disque" spécifique à Sun.
Comme l'accès SCSI brut utilise toujours l'intégralité du périphérique, vous devez spécifier l'indicateur "partition" en plus

Nom

syntaxe du fichier de configuration Mtools

Description

Chaque section de configuration commence par un mot-clé suivi d'un signe égal. Les sections peuvent être imbriquées. Les mots-clés sont insensible à la casse.

scsi 
Indique à mtools d'utiliser des commandes SCSI pour l'accès au périphérique. Cette option est uniquement valide pour les lecteurs décrits dans les fichiers de configuration système (par exemple, `/etc/mtools.conf', et non dans `~/.mtoolsrc' ou `$MTOOLSRC'). Bien sûr, cette option est également un no op si mtools n'est pas installé setuid root. Il est nécessaire d'installer mtools setuid root sur Solaris si vous voulez accéder aux lecteurs Zip/Jaz. Ainsi, si le drapeau scsi est donné, privileged est automatiquement implicite, sauf si explicitement désactivé par privileged=0.
Mtools utilise ses privilèges root pour ouvrir le périphérique, et pour émettre les appels d'E/S SCSI réels. De plus, les privilèges root ne sont utilisés que pour les lecteurs décrits dans un fichier de configuration système tel que `/etc/mtools.conf', et non pour ceux décrits dans `~/.mtoolsrc' ou `$MTOOLSRC'.
privileged 
Lorsqu'il est défini sur 1, cela demande à mtools d'utiliser ses privilèges setuid et setgid pour ouvrir le lecteur donné. Cette option n'est valide que pour les lecteurs décrits dans les fichiers de configuration système (tels que `/etc/mtools.conf', pas `~/.mtoolsrc' ou `$MTOOLSRC'). Évidemment, cette option est également un no op si mtools n'est pas installé setuid ou setgid. Cette option est implicite par 'scsi=1', mais à nouveau uniquement pour les lecteurs définis dans les fichiers de configuration système. Privileged peut également être défini explicitement sur 0, afin d'indiquer à mtools de ne pas utiliser ses privilèges pour un lecteur donné même si scsi=1 est défini.
Mtools n'a besoin d'être installé setuid que si vous utilisez les variables de lecteur privileged ou scsi. Si vous n'utilisez pas ces options, mtools fonctionne parfaitement bien même lorsqu'il n'est pas installé setuid root.
vold 
Demande à mtools d'interpréter le nom de périphérique comme un identifiant vold plutôt que comme un nom de fichier. L'identifiant vold est traduit en un vrai nom de fichier à l'aide des fonctions media_findname() et media_oldaliases() de la bibliothèque volmgt. Ce drapeau n'est disponible que si vous avez configuré mtools avec l'option --enable-new-vold avant la compilation.
swap 
Considère le média comme un disque Atari dont les mots sont échangés.
use_xdf 
Si ceci est défini sur une valeur non nulle, mtools essaie également d'accéder à ce disque comme un disque XDF. XDF est un format de haute capacité utilisé par OS/2. C'est désactivé par défaut. Voir la section XDF, pour plus de détails.
mformat_only 
Indique à mtools d'utiliser la géométrie de ce lecteur uniquement pour le mformattage et non pour le filtrage.
filter 
Indique à mtools d'utiliser la géométrie de ce lecteur à la fois pour le mformattage et le filtrage.
remote 
Indique à mtools de se connecter à floppyd (voir la section floppyd).

  Fournir plusieurs descriptions pour un lecteur

Il est possible de fournir plusieurs descriptions pour un lecteur. Dans ce cas, les descriptions sont essayées dans l'ordre jusqu'à ce qu'une convienne. Les descriptions peuvent échouer pour plusieurs raisons :

1. 
parce que la géométrie n'est pas appropriée,
2. 
parce qu'il n'y a pas de disque dans le lecteur,
3. 
ou à cause d'autres problèmes.

Les définitions multiples sont utiles lors de l'utilisation de périphériques physiques qui ne peuvent supporter qu'une seule géométrie de disque. Exemple :

  drive a: file="/dev/fd0H1440" 1.44m
  drive a: file="/dev/fd0H720" 720k

Cela indique à mtools d'utiliser /dev/fd0H1440 pour les disques de 1.44m (haute densité) et /dev/fd0H720 pour les disques de 720k (double densité). Sous Linux, cette fonctionnalité n'est pas vraiment nécessaire, car le périphérique /dev/fd0 est capable de gérer n'importe quelle géométrie.

Vous pouvez également utiliser plusieurs descriptions de lecteur pour accéder à vos deux lecteurs physiques via une seule lettre de lecteur :

  drive z: file="/dev/fd0"
  drive z: file="/dev/fd1"

Avec cette description, mdir z: accède à votre premier lecteur physique s'il contient un disque. Si le premier lecteur ne contient pas de disque, mtools vérifie le deuxième lecteur.

Lors de l'utilisation de plusieurs fichiers de configuration, les descriptions de lecteur dans les fichiers analysés en dernier remplacent les descriptions pour le même lecteur dans les fichiers précédents. Afin d'éviter cela, utilisez les mots-clés drive+ ou +drive au lieu de drive. Le premier ajoute une description à la fin de la liste (c'est-à-dire qu'elle sera essayée en dernier), et le second l'ajoute au début de la liste.

Emplacement des fichiers de configuration et ordre d'analyse

Les fichiers de configuration sont analysés dans l'ordre suivant :

1. 
valeurs par défaut compilées
2. 
`/etc/mtools.conf'
3. 
`~/.mtoolsrc'.
4. 
`$MTOOLSRC' (fichier pointé par la variable d'environnement MTOOLSRC)

Les options décrites dans les fichiers ultérieurs remplacent celles décrites dans les fichiers précédents. Les lecteurs définis dans les fichiers précédents persistent s'ils ne sont pas remplacés dans les fichiers ultérieurs. Par exemple, les lecteurs A et B peuvent être définis dans `/etc/mtools.conf' et les lecteurs C et D peuvent être définis dans `~/.mtoolsrc'. Cependant, si `~/.mtoolsrc' définit également le lecteur A, cette nouvelle description remplacerait la description du lecteur A dans `/etc/mtools.conf' au lieu de s'y ajouter. Si vous souhaitez ajouter une nouvelle description à un lecteur déjà décrit dans un fichier précédent, vous devez utiliser le mot-clé +drive ou drive+.

Compatibilité descendante avec la syntaxe ancienne du fichier de configuration

La syntaxe décrite ici est nouvelle pour la version mtools-3.0. L'ancienne syntaxe orientée ligne est toujours prise en charge. Chaque ligne commençant par une seule lettre est considérée comme une description de lecteur utilisant l'ancienne syntaxe. Les sections de lecteur de style ancien et nouveau peuvent être mélangées dans le même fichier de configuration, afin de faciliter la mise à niveau. La prise en charge de l'ancienne syntaxe sera progressivement supprimée, et afin de décourager son utilisation, j'omets délibérément sa description ici.
