mremap(2) Manuel des appels système mremap(2)

NOM

mremap - réaffecter une adresse de mémoire virtuelle

BIBLIOTHÉQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#define _GNU_SOURCE         /* Voir feature_test_macros(7) */
#include <sys/mman.h>
void *mremap(size_t old_size;
             void old_address[old_size], size_t old_size,
             size_t new_size, int flags, ...  /* void *new_address */);

DESCRIPTION

mremap() étend (ou réduit) un mappage mémoire existant, le déplaçant potentiellement en même temps (contrôlé par l'argument flags et l'espace d'adressage virtuel disponible).

Les mappages peuvent également être simplement déplacés (sans aucun redimensionnement) en spécifiant old_size et new_size égaux et en utilisant le drapeau MREMAP_FIXED (voir ci-dessous). Depuis Linux 6.17, alors que old_address doit être mappé, old_size peut s'étendre sur plusieurs mappages, y compris des zones non mappées entre eux lors d'un déplacement simple. Le drapeau MREMAP_DONTUNMAP peut également être spécifié.

De même, si l'opération effectue une réduction, c'est-à-dire si old_size est supérieur à new_size, alors old_size peut également s'étendre sur plusieurs mappages, qui ne doivent pas être adjacents les uns aux autres. Si cette réduction est effectuée sur place, c'est-à-dire si ni MREMAP_FIXED, ni MREMAP_DONTUNMAP ne sont spécifiés, new_size peut également s'étendre sur plusieurs VMA. Cependant, si la plage est déplacée, alors new_size doit s'étendre sur un seul mappage.

Si l'opération n'est ni un déplacement MREMAP_FIXED ni une réduction, alors old_size doit s'étendre sur un seul mappage.

old_address est l'ancienne adresse du premier bloc de mémoire virtuelle que vous souhaitez étendre, réduire et/ou déplacer. Notez que old_address doit être aligné sur une page. old_size est la taille de la plage contenant les blocs de mémoire virtuelle à manipuler. new_size est la taille demandée des blocs de mémoire virtuelle après le redimensionnement. Un cinquième argument optionnel, new_address, peut être fourni ; voir la description de MREMAP_FIXED ci-dessous.

Si la valeur de old_size est zéro, et old_address fait référence à un mappage partageable (voir la description de MAP_SHARED dans mmap(2)), alors mremap() créera un nouveau mappage des mêmes pages. new_size sera la taille du nouveau mappage et l'emplacement du nouveau mappage peut être spécifié avec new_address ; voir la description de MREMAP_FIXED ci-dessous. Si un nouveau mappage est demandé par cette méthode, alors le drapeau MREMAP_MAYMOVE doit également être spécifié.

L'argument flags, un masque de bits, peut être 0, ou inclure les drapeaux suivants :

MREMAP_MAYMOVE
Par défaut, s'il n'y a pas assez d'espace pour étendre un mappage à son emplacement actuel, alors mremap() échoue. Si ce drapeau est spécifié, alors le noyau est autorisé à relocaliser le mappage vers une nouvelle adresse virtuelle, si nécessaire. Si le mappage est relocalisé, alors les pointeurs absolus vers l'ancien emplacement du mappage deviennent invalides (les décalages par rapport à l'adresse de départ du mappage devraient être employés).
MREMAP_FIXED (depuis Linux 2.3.31)
Ce drapeau remplit un rôle similaire à celui du drapeau MAP_FIXED de mmap(2). Si ce drapeau est spécifié, alors mremap() accepte un cinquième argument, void *new_address, qui spécifie une adresse alignée sur page vers laquelle le mappage doit être déplacé. Tout mappage précédent à l'adresse spécifiée par new_address et new_size est démappé.
Si MREMAP_FIXED est spécifié, alors MREMAP_MAYMOVE doit également être spécifié.
Depuis Linux 6.17, si old_size est égal à new_size et que MREMAP_FIXED est spécifié, alors old_size peut s'étendre au-delà du mappage dans lequel réside old_address. Dans ce cas, les espaces entre les mappages dans la plage d'origine sont maintenus dans la nouvelle plage. L'opération entière est effectuée atomiquement sauf en cas d'erreur, auquel cas l'opération peut être partiellement complétée, c'est-à-dire que certains mappages peuvent être déplacés et d'autres non.
Le déplacement de plusieurs mappages n'est pas autorisé si l'un de ces mappages a été enregistré avec userfaultfd(2), ou s'il mappe des pilotes qui spécifient leur propre logique de mappage d'adresses.
MREMAP_DONTUNMAP (depuis Linux 5.7)
Ce drapeau, qui doit être utilisé conjointement avec MREMAP_MAYMOVE, réaffecte des mappages à une nouvelle adresse mais ne les démappe pas de leur adresse d'origine.
Le drapeau MREMAP_DONTUNMAP ne peut être utilisé qu'avec des mappages qui ne sont ni VM_DONTEXPAND ni VM_MIXEDMAP. Avant Linux 5.13, le drapeau MREMAP_DONTUNMAP ne pouvait être utilisé qu'avec des mappages anonymes privés (voir la description de MAP_PRIVATE et MAP_ANONYMOUS dans mmap(2)).
Après achèvement, tout accès à la plage spécifiée par old_address et old_size entraînera une faute de page. La faute de page sera gérée par un gestionnaire userfaultfd(2) si l'adresse se trouve dans une plage précédemment enregistrée avec userfaultfd(2). Sinon, le noyau allouera une page remplie de zéros pour gérer la faute.
Le drapeau MREMAP_DONTUNMAP peut être utilisé pour déplacer atomiquement un mappage tout en laissant la source mappée. Voir NOTES pour quelques applications possibles de MREMAP_DONTUNMAP.

Si les segments de mémoire spécifiés par old_address et old_size sont verrouillés (en utilisant mlock(2) ou similaire), alors ce verrouillage est maintenu lorsque les segments sont redimensionnés et/ou relocalisés. Par conséquent, la quantité de mémoire verrouillée par le processus peut changer.

VALEUR DE RETOUR

En cas de succès, mremap() renvoie un pointeur vers la nouvelle zone de mémoire virtuelle. En cas d'erreur, la valeur MAP_FAILED (c'est-à-dire (void *) -1) est renvoyée, et errno est définie pour indiquer l'erreur.

ERREURS

EAGAIN
L'appelant a essayé d'étendre un segment mémoire qui est verrouillé, mais cela n'a pas été possible sans dépasser la limite de ressources RLIMIT_MEMLOCK.
EFAULT
Une adresse dans la plage old_address à old_address+old_size est une adresse mémoire virtuelle invalide pour ce processus. Vous pouvez également obtenir EFAULT même s'il existe des mappages qui couvrent tout l'espace d'adressage demandé, mais ces mappages sont de types différents, et l'opération mremap() effectuée ne prend pas en charge cela.
EINVAL
Un argument invalide a été donné. Les causes possibles sont :
•
old_address n'était pas aligné sur une page ;
•
une valeur autre que MREMAP_MAYMOVE ou MREMAP_FIXED ou MREMAP_DONTUNMAP a été spécifiée dans flags ;
•
new_size était zéro ;
•
new_size ou new_address était invalide ;
•
la nouvelle plage d'adresses spécifiée par new_address et new_size se chevauchait avec l'ancienne plage d'adresses spécifiée par old_address et old_size ;
•
MREMAP_FIXED ou MREMAP_DONTUNMAP a été spécifié sans également spécifier MREMAP_MAYMOVE ;
•
MREMAP_DONTUNMAP a été spécifié, mais une ou plusieurs pages dans la plage spécifiée par old_address et old_size n'étaient pas privées anonymes ;
•
MREMAP_DONTUNMAP a été spécifié et old_size n'était pas égal à new_size ;
•
old_size était zéro et old_address

•
old_size était zéro et l'indicateur MREMAP_MAYMOVE n'a pas été spécifié.
ENOMEM

•

NORMES

Linux.

HISTORIQUE

Avant glibc 2.4, glibc n'exposait pas la définition de MREMAP_FIXED, et le prototype de mremap() ne permettait pas l'argument new_address.

NOTES

mremap() modifie le mappage entre les adresses virtuelles et les pages mémoire. Cela peut être utilisé pour implémenter un realloc(3) très efficace.

Sous Linux, la mémoire est divisée en pages. Un processus a (un ou) plusieurs segments de mémoire virtuelle linéaires. Chaque segment de mémoire virtuelle a un ou plusieurs mappages vers des pages mémoire réelles (dans la table des pages). Chaque segment de mémoire virtuelle a sa propre protection (droits d'accès), qui peut provoquer une violation de segmentation (SIGSEGV) si la mémoire est accédée incorrectement (par exemple, écriture dans un segment en lecture seule). L'accès à la mémoire virtuelle en dehors des segments provoquera également une violation de segmentation.

Si mremap() est utilisé pour déplacer ou étendre une zone verrouillée avec mlock(2) ou un équivalent, l'appel mremap() fera de son mieux pour peupler la nouvelle zone mais n'échouera pas avec ENOMEM si la zone ne peut pas être peuplée.

Cas d'utilisation de MREMAP_DONTUNMAP

Les applications possibles pour MREMAP_DONTUNMAP incluent :

•
userfaultfd(2) non coopératif : une application peut retirer une plage d'adresses virtuelles à l'aide de MREMAP_DONTUNMAP, puis utiliser un gestionnaire userfaultfd(2) pour gérer les fautes de page qui surviennent ensuite lorsque d'autres threads du processus accèdent aux pages de la plage retirée.
•
Ramasse-miettes (Garbage collection) : MREMAP_DONTUNMAP peut être utilisé en conjonction avec userfaultfd(2) pour implémenter des algorithmes de ramasse-miettes (par exemple, dans une machine virtuelle Java). Une telle implémentation peut être moins coûteuse (et plus simple) que les techniques de ramasse-miettes conventionnelles qui impliquent de marquer les pages avec la protection PROT_NONE en conjonction avec l'utilisation d'un gestionnaire SIGSEGV pour intercepter les accès à ces pages.

BOGUES

Avant Linux 4.14, si old_size était zéro et que le mappage référencé par old_address était un mappage privé (voir la description de MAP_PRIVATE dans mmap(2)), mremap() créait un nouveau mappage privé sans rapport avec le mappage d'origine. Ce comportement était involontaire et probablement inattendu dans les applications utilisateur (puisque l'intention de mremap() est de créer un nouveau mappage basé sur le mappage d'origine). Depuis Linux 4.14, mremap() échoue avec l'erreur EINVAL dans ce scénario.
