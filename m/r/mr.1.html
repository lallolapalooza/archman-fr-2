NOM

mr - un outil pour gérer tous vos dépôts de contrôle de version

SYNTAXE

mr [options] checkout

mr [options] update

mr [options] status

mr [options] clean [-f]

mr [options] commit [-m "message"]

mr [options] record [-m "message"]

mr [options] fetch

mr [options] push

mr [options] diff

mr [options] log

mr [options] grep motif

mr [options] run commande [param ...]

mr [options] bootstrap src [répertoire]

mr [options] register [dépôt]

mr [options] config section ["paramètre=[valeur]" ...]

mr [options] action [param ...]

mr [options] [online|offline]

mr [options] remember action [param ...]

DESCRIPTION

mr est un outil pour gérer tous vos dépôts de contrôle de version. Il peut cloner, mettre à jour ou effectuer d'autres actions sur un ensemble de dépôts comme s'ils n'en formaient qu'un seul. Il supporte toute combinaison de dépôts Subversion, git, cvs, mercurial, bzr, darcs, fossil et veracity, et le support pour d'autres systèmes de contrôle de version peut être facilement ajouté.

mr se déplace et opère sur tous les dépôts enregistrés à partir de votre répertoire de travail ou en dessous. Ou, si vous êtes dans un sous-répertoire d'un dépôt qui ne contient aucun autre dépôt enregistré, il restera dans ce répertoire et n'opérera que sur ce dépôt.

mr est configuré par des fichiers .mrconfig, qui listent les dépôts. Il commence par lire le fichier .mrconfig dans votre répertoire personnel, et celui-ci peut à son tour charger des fichiers .mrconfig à partir des dépôts. Il recherche également automatiquement un fichier .mrconfig dans le répertoire courant ou dans l'un de ses répertoires parents.

Ces commandes prédéfinies devraient être assez familières aux utilisateurs de tout système de contrôle de version :

checkout (ou co)
Clone tous les dépôts qui ne sont pas déjà clonés.
update
Met à jour chaque dépôt à partir de son dépôt distant configuré.

Si un dépôt n'est pas encore cloné, il le clonera d'abord.

status
Affiche un rapport d'état pour chaque dépôt, indiquant les modifications non commitées présentes dans le dépôt. Pour les systèmes de contrôle de version distribués, affiche également les branches locales non poussées.
clean
Affiche les fichiers ignorés, les fichiers non suivis et autres éléments inutiles dans le répertoire de travail.

Le paramètre optionnel -f permet de supprimer les fichiers en plus de les afficher.

commit (ou ci)
Commite les modifications dans chaque dépôt. (Par défaut, les modifications sont également poussées vers le dépôt distant, lors de l'utilisation de systèmes distribués comme git. Si ce comportement par défaut ne vous plaît pas, vous pouvez le modifier dans votre .mrconfig, ou utiliser record à la place.)

Le paramètre optionnel -m permet de spécifier un message de commit.

record
Enregistre les modifications dans le dépôt local, mais ne les pousse pas vers le dépôt distant. Uniquement supporté pour les systèmes de contrôle de version distribués.

Le paramètre optionnel -m permet de spécifier un message de commit.

fetch
Récupère les informations de chaque dépôt distant, mais ne met pas à jour la copie de travail. Uniquement supporté pour certains systèmes de contrôle de version distribués.
push
Pousse les modifications locales committées vers le dépôt distant. Ne fait rien pour les systèmes de contrôle de version centralisés.
diff
Affiche un diff des modifications non committées.
log
Affiche l'historique des commits.
grep motif
Recherche un motif dans chaque dépôt en utilisant la sous-commande grep. Utilise ack ou ack-grep pour les VCS qui n'en ont pas. Ignore la valeur de retour des sous-commandes grep afin que vous puissiez utiliser "mr -m grep foo" sans obtenir de sortie dans les dépôts ne correspondant pas.
run commande [param ...]
Exécute la commande spécifiée dans chaque dépôt.

Ces commandes sont également disponibles :

bootstrap src [répertoire]
Demande à mr de récupérer la source "src" et de l'utiliser comme fichier .mrconfig pour cloner les dépôts qui y sont listés, dans le répertoire spécifié.

mr comprend plusieurs types de sources :

URL pour curl
"src" peut être une URL comprise par curl.
copie via ssh
Pour utiliser scp afin de télécharger, "src" peut avoir la forme "ssh://[utilisateur@]hôte:fichier".
fichier local
Vous pouvez récupérer le fichier de configuration par d'autres moyens et passer son **chemin** comme "src".
entrée standard
Si la source "src" est constituée d'un seul tiret "-", le fichier de configuration est lu depuis l'entrée standard.

Le répertoire sera créé s'il n'existe pas. Si aucun répertoire n'est spécifié, le répertoire courant sera utilisé.

Cas spécial : si la source "src" inclut un dépôt nommé ".", celui-ci est cloné en haut du répertoire spécifié.

list (ou ls)
Liste les dépôts sur lesquels mr agira.
register
Enregistre un dépôt existant dans un fichier mrconfig. Par défaut, le dépôt du répertoire courant est enregistré, ou vous pouvez spécifier un répertoire à enregistrer.

Le fichier mrconfig qui est modifié est choisi soit par l'option -c, soit en recherchant le plus proche connu, dans ou au-dessus du répertoire courant.

config
Ajoute, modifie, supprime ou affiche une valeur d'un fichier mrconfig. Le paramètre suivant est le nom de la section dans laquelle se trouve la valeur. Pour ajouter ou modifier des valeurs, utilisez une ou plusieurs occurrences de "paramètre=valeur". Utilisez "paramètre=" pour supprimer un paramètre. Utilisez simplement "paramètre" pour obtenir la valeur d'un paramètre.

Par exemple, pour ajouter (ou modifier) un dépôt dans src/foo :

mr config src/foo checkout="svn co svn://example.com/foo/trunk foo"

Pour afficher la commande que mr utilise pour mettre à jour le dépôt dans src/foo :

mr config src/foo update

Pour voir la bibliothèque intégrée de fonctions shell contenues dans mr :

mr config DEFAULT lib

Le fichier mrconfig utilisé est choisi soit par l'option -c, soit en recherchant le plus proche connu, dans ou au-dessus du répertoire courant.

offline
Indique à mr qu'il est en mode hors ligne. Toute commande qui échoue en mode hors ligne sera mémorisée et retentée lorsque mr sera de nouveau en ligne.
online
Indique à mr qu'il est de nouveau en mode en ligne. Les commandes qui ont échoué en mode hors ligne seront ré-exécutées.
remember
Mémorise une commande, à exécuter plus tard lorsque mr repassera en mode en ligne. Cela met implicitement mr en mode hors ligne. La commande peut être n'importe quelle commande mr régulière. Ceci est utile lorsque vous savez qu'une commande échouera parce que vous êtes hors ligne, et que vous ne voulez donc pas l'exécuter immédiatement, mais simplement vous souvenir de l'exécuter lorsque vous retournerez en ligne.
help
Affiche cette aide.

Les actions peuvent être abrégées à

ny sous-chaîne non ambiguë, donc "mr st" équivaut à "mr status", et "mr up" équivaut à "mr update"

Des paramètres supplémentaires peuvent être passés à la plupart des commandes et sont transmis sans modification au système de contrôle de version sous-jacent. Ceci est surtout utile si les dépôts sur lesquels mr agira utilisent tous le même système de contrôle de version.

OPTIONS

-d répertoire
--directory répertoire
Spécifie le répertoire de plus haut niveau dans lequel mr doit opérer. La valeur par défaut est le répertoire de travail courant.
-c mrconfig
--config mrconfig
Utilise le fichier mrconfig spécifié. La valeur par défaut est d'utiliser à la fois ~/.mrconfig et de rechercher un fichier .mrconfig dans le répertoire courant, ou dans l'un de ses répertoires parents.
-f
--force
Force mr à agir sur des dépôts qui seraient normalement ignorés en raison de leur configuration.
--force-env
Force mr à s'exécuter même si des variables d'environnement potentiellement dangereuses sont définies.
-v
--verbose
Être verbeux.
-m
--minimal
Minimiser la sortie. Si une commande échoue ou s'il y a une quelconque sortie, la sortie normale sera affichée.
-q
--quiet
Être silencieux. Ceci supprime la sortie habituelle de mr, ainsi que toute sortie des commandes exécutées (y compris la sortie d'erreur standard). Si une commande échoue, la sortie sera affichée.
-k
--insecure
Accepter les certificats SSL non fiables lors de l'amorçage.
-s
--stats
Développe la ligne de statistiques affichée à la fin pour inclure des informations sur exactement quels dépôts ont échoué et ont été ignorés, le cas échéant.
-i
--interactive
Mode interactif. Si un dépôt ne peut pas être traité, un sous-shell sera démarré que vous pourrez utiliser pour résoudre ou investiguer le problème. Quittez le sous-shell pour continuer l'exécution de mr.
-n [nombre]
--no-recurse [nombre]
Si aucun nombre n'est spécifié, opère uniquement sur le dépôt du répertoire courant, ne récurse pas dans les dépôts plus profonds.

Si un nombre est spécifié, récurse dans les dépôts à une profondeur maximale de ce nombre de sous-répertoires. Par exemple, avec -n 2, il récurse dans ./src/foo, mais pas dans ./src/packages/bar.

-j [nombre]
--jobs [nombre]
Exécute le nombre spécifié de jobs en parallèle, ou un nombre illimité de jobs sans nombre spécifié. Ceci peut considérablement accélérer les opérations telles que les mises à jour. Ce n'est pas recommandé pour les opérations interactives.

Notez que l'exécution de plus de 10 jobs à la fois risque de dépasser les limites de connexion ssh. L'exécution de 3 à 5 jobs à la fois fournira une bonne accélération des mises à jour sans trop charger la machine.

--cache
Sauvegarde la sortie de la commande et les valeurs de retour dans des fichiers dans l'arborescence des répertoires ~/.mrcache/ après l'exécution de chaque commande.

Ignoré lors de l'exécution depuis des sous-répertoires d'un dépôt, sauf si --top est activé.

Ceci est utilisé par l'extension de shell "cache-mr-status.sh".

--cached
Pour les dépôts où le cache est peuplé, imprime la sortie mise en cache au lieu d'exécuter les commandes. Pour les dépôts avec un cache non peuplé, exécute les commandes et stocke la sortie dans le cache.

Ignoré lors de l'exécution depuis des sous-répertoires d'un dépôt, sauf si --top est activé.

Ceci est le plus utile lorsque l'extension de shell "cache-mr-status.sh" est activée.

--uncache
Pour les dépôts où le cache est peuplé, supprime la sortie mise en cache avant d'exécuter les commandes.

Ceci peut être utile aux utilisateurs de l'extension de shell "cache-mr-status.sh".

--top
Lors de l'exécution depuis des sous-répertoires d'un dépôt, change le répertoire pour aller au sommet du dépôt avant d'exécuter les commandes.

Ceci est utilisé par l'extension de shell "cache-mr-status.sh".

-t
--trust-all
Fait confiance à tous les fichiers mrconfig même s'ils ne sont pas listés dans ~/.mrtrust. À utiliser avec prudence.
-p
--path
Ce drapeau obsolète est ignoré.

FICHIERS MRCONFIG

Voici un exemple de fichier .mrconfig :

[src]
checkout = svn checkout svn://svn.example.com/src/trunk src
chain = true
[src/linux-2.6]
checkout = git clone git://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux-2.6.git &&
      cd linux-2.6 &&
      git checkout -b mybranch origin/master

Le fichier .mrconfig utilise une variante du format de fichier INI. Les lignes commençant par "#" sont des commentaires. Les valeurs peuvent être prolongées sur la ligne suivante en indentant la ligne avec des espaces.

La section "DEFAULT" permet de définir des valeurs par défaut pour les sections qui la suivent.

La section "ALIAS" permet d'ajouter des alias pour les actions. Chaque paramètre est un alias et sa valeur est l'action à utiliser.

Toutes les autres sections ajoutent des dépôts. L'en-tête de section spécifie le répertoire où se trouve le dépôt. Ceci est relatif au répertoire qui contient le fichier mrconfig, mais vous pouvez également choisir d'utiliser des chemins absolus. (Notez que vous pouvez utiliser des variables d'environnement dans les noms de section ; elles seront transmises au shell pour expansion. Par exemple, "[$HOSTNAME]", ou "[${HOSTNAME}foo]").

Au sein d'une section, chaque paramètre définit une commande shell à exécuter pour gérer une action donnée. mr contient des gestionnaires par défaut pour "update", "status", "commit", et d'autres actions standard.

Normalement, vous n'avez besoin de spécifier que quoi faire pour "checkout". Ici, vous spécifiez la commande à exécuter pour créer un checkout du dépôt. La commande sera exécutée dans le répertoire parent et doit créer le répertoire du dépôt. Utilisez donc "git clone", "svn checkout", "bzr branch" ou "bzr checkout" (pour une branche liée), etc.

Notez que ces commandes shell sont exécutées dans un environnement shell "set -e", où tout paramètre supplémentaire que vous passez est disponible dans $@. Toutes les commandes autres que "checkout" sont exécutées à l'intérieur du dépôt, bien que pas nécessairement à son sommet.

La variable d'environnement "MR_REPO" est définie sur le chemin vers le sommet du dépôt. (Pour l'action "register", "MR_REPO" est défini sur le nom de base du répertoire qui devrait être créé lors du checkout du dépôt.)

La variable d'environnement "MR_CONFIG" est définie sur le fichier .mrconfig qui définit le dépôt concerné, ou, si le dépôt n'est pas encore dans un fichier de configuration, sur le fichier .mrconfig qui devrait être modifié pour enregistrer le dépôt.

La variable d'environnement "MR_ACTION" est définie sur la commande exécutée (update, checkout, etc).

Quelques paramètres ont des significations spéciales :

skip
Si "skip" est défini et que sa commande renvoie vrai, alors mr ignorera ce dépôt. La commande reçoit le nom de l'action dans $1.

Voici deux exemples. Le premier ignore le dépôt sauf si mr est exécuté par joey. Le second utilise la fonction hours_since (incluse dans la bibliothèque intégrée de mr) pour ignorer la mise à jour du dépôt sauf si au moins 12 heures se sont écoulées depuis la dernière mise à jour.

[mystuff]
checkout = ...
skip = test `whoami` != joey
[linux]
checkout = ...
skip = [ "$1" = update ] && ! hours_since "$1" 12

Une autre façon d'utiliser skip est pour un checkout paresseux. Ceci fait que mr ignore l'action sur un dépôt sauf s'il existe déjà. Pour activer le dépôt, vous devez explicitement le vérifier (en utilisant "mr --force -d foo checkout").

[foo]
checkout = ...
skip = lazy
order
Le paramètre "order" peut être utilisé pour outrepasser l'ordre par défaut des dépôts. La valeur par défaut de l'ordre est 10. Utilisez des valeurs plus petites pour que les dépôts soient traités plus tôt, et des valeurs plus grandes pour que les dépôts soient traités plus tard.

Notez que si un dépôt est situé dans un sous-répertoire d'un autre dépôt, il n'est pas recommandé de le traiter plus tôt.

chain
Si "chain" est défini et que sa commande renvoie vrai, alors mr essaiera de charger un fichier .mrconfig depuis la racine du dépôt.
include
Si "include" est défini, sa commande est exécutée et devrait produire un contenu de fichier mrconfig supplémentaire. Le contenu est inclus comme s'il faisait partie du fichier incluant.

Contrairement à tout le reste, "include" n'a pas besoin d'être placé dans une section.

mr expédie plusieurs bibliothèques qui peuvent être incluses pour ajouter la prise en charge de versions supplémentaires

n choses de type de contrôle (unison, git-svn, git-fake-bare, git-subtree). Pour les inclure toutes, vous pouvez utiliser :

include = cat /usr/share/mr/*

Voir les fichiers individuels pour plus de détails.

deleted
Si "deleted" est défini et que sa commande renvoie vrai, alors mr traitera le dépôt comme supprimé. Il ne supprimera jamais réellement le dépôt, mais il avertira s'il voit le répertoire du dépôt. Ceci est utile lorsqu'un fichier mrconfig est partagé entre plusieurs machines, pour garder une trace et se souvenir de supprimer les anciens dépôts.
lib
Le réglage "lib" peut contenir du code shell qui sera exécuté avant chaque commande. Cela peut être un moyen utile de définir des fonctions shell que d'autres commandes pourront utiliser.

Contrairement à la plupart des autres réglages, celui-ci peut être spécifié plusieurs fois, auquel cas les morceaux de code shell sont concaténés cumulativement.

fixups
Si "fixups" est défini, sa commande est exécutée chaque fois qu'un dépôt est extrait ou mis à jour. Cela offre un moyen facile de faire des choses comme des corrections de permissions, ou d'autres ajustements au contenu du dépôt, chaque fois que le dépôt est modifié.
jobs
Si "jobs" est défini, exécute le nombre spécifié de tâches en parallèle. Cela peut considérablement accélérer les opérations telles que les mises à jour.

Notez que l'exécution de plus de 10 tâches à la fois risque de rencontrer des limites de connexion ssh. Exécuter entre 3 et 5 tâches à la fois fournira une bonne accélération des mises à jour sans surcharger excessivement la machine.

VCS_action
Lors de la recherche d'une commande à exécuter pour une action donnée, mr recherche d'abord un réglage portant le même nom que l'action. S'il ne le trouve pas, il recherche un réglage nommé "VCS_action" (en substituant le nom du système de contrôle de version et l'action). S'il ne le trouve pas, il recherche un réglage nommé "action_default" (en substituant le nom de l'action).

En interne, mr a des réglages pour "git_update", "svn_update", etc. Pour changer l'action effectuée pour un système de contrôle de version donné, vous pouvez redéfinir ces actions spécifiques au VCS. Pour ajouter un nouveau système de contrôle de version, vous pouvez simplement y ajouter des actions spécifiques au VCS.

pre_ et post_
Si "pre_action" est défini, sa commande est exécutée avant que mr n'effectue l'action spécifiée. De même, les commandes "post_action" sont exécutées après que mr ait effectué avec succès l'action spécifiée. Par exemple, "pre_commit" est exécuté avant de commiter ; "post_update" est exécuté après la mise à jour.
_prepend
Tout réglage peut être suffixé par "_prepend", pour ajouter une valeur supplémentaire au début de la valeur existante du réglage. Une fin de ligne est ajoutée entre la valeur supplémentaire et la valeur existante. De cette manière, les actions peuvent être construites cumulativement.

Ceci est utile pour appliquer des commandes modificateurs comme nice, ionice ou nocache. Pour appliquer des commandes modificateurs, assurez-vous de terminer ce suffixe par un caractère de continuation de ligne shell (le backslash "\" dans la plupart des shells) afin que la fin de ligne ajoutée par ce suffixe soit ignorée.

_append
Tout réglage peut être suffixé par "_append", pour ajouter une valeur supplémentaire à la fin de la valeur existante du réglage. Des fins de ligne sont ajoutées à la fin de la valeur existante et après la valeur supplémentaire. De cette manière, les actions peuvent être construites cumulativement.
_default
Tout réglage peut être suffixé par "_default", pour définir la valeur du réglage lorsqu'un réglage spécifique au VCS ne peut pas être trouvé. Ceci est principalement utilisé pour faire en sorte que les actions ne fassent rien pour la plupart des actions VCS en définissant action_default à "true" et en définissant ensuite l'action pour chaque VCS qui possède l'action.

Ceci est utilisé par l'extension mr "upgrade".

VCS_test
Le nom du système de contrôle de version est lui-même déterminé en exécutant chaque action "VCS_test" définie, jusqu'à ce qu'une réussisse.

FICHIERS MRCONFIG NON FIABLES

Étant donné que les fichiers mrconfig peuvent contenir des commandes shell arbitraires, ils peuvent tout faire. Cette flexibilité est une bonne chose, mais elle permet également à un fichier mrconfig malveillant de supprimer tout votre répertoire personnel. Un tel fichier pourrait être contenu dans un dépôt que votre ~/.mrconfig principal extrait. Pour éviter les soucis concernant les commandes malveillantes dans un fichier mrconfig, mr lit par défaut tous les fichiers mrconfig autres que le principal ~/.mrconfig en mode non fiable. En mode non fiable, les fichiers mrconfig sont limités à l'exécution uniquement de commandes sûres connues (comme "git clone") d'une manière soigneusement vérifiée.

Pour configurer mr afin qu'il fasse confiance à d'autres fichiers mrconfig, listez-les dans ~/.mrtrust. Un fichier mrconfig doit être listé par ligne. Soit le chemin complet doit être listé, soit le chemin peut commencer par ~/ pour spécifier un fichier relatif à votre répertoire personnel.

FICHIER JOURNAL HORS LIGNE

Le fichier ~/.mrlog contient les commandes que mr s'est souvenu d'exécuter plus tard, car il était hors ligne. Vous pouvez supprimer ou modifier ce fichier pour supprimer des commandes, ou même pour ajouter d'autres commandes que 'mr online' exécutera. Si le fichier est présent, mr suppose qu'il est en mode hors ligne.

EXTENSIONS

mr peut être étendu pour prendre en charge des choses comme unison et git-svn. Certains fichiers fournissant de telles extensions sont disponibles dans /usr/share/mr/. Certains fichiers fournissant des extensions shell pour mr sont dans /usr/share/mr.sh/. Voir la documentation dans les fichiers pour plus de détails sur leur utilisation.

STATUT DE SORTIE

mr renvoie une valeur non nulle si une commande a échoué dans l'un des dépôts.
