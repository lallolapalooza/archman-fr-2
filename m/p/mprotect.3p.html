MPROTECT(3P) Manuel du programmeur POSIX MPROTECT(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation de cette interface sous Linux peut différer (consulter la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

mprotect — définir la protection d'un mappage mémoire

SYNTAXE

#include <sys/mman.h>
int mprotect(void *addr, size_t len, int prot);

DESCRIPTION

La fonction mprotect() modifie les protections d'accès à celles spécifiées par prot pour toutes les pages entières contenant une partie de l'espace d'adressage du processus, commençant à l'adresse addr et s'étendant sur len octets. Le paramètre prot détermine si les lectures, écritures, exécutions ou une combinaison de ces accès sont autorisés pour les données mappées. L'argument prot doit être soit PROT_NONE, soit le OU bit à bit inclus de PROT_READ, PROT_WRITE, et PROT_EXEC, ou une combinaison de ceux-ci.

Si une implémentation ne peut pas supporter la combinaison des types d'accès spécifiés par prot, l'appel à mprotect() échouera.

Une implémentation peut autoriser des accès autres que ceux spécifiés par prot ; cependant, aucune implémentation ne doit permettre une écriture réussie si PROT_WRITE n'a pas été défini, ni autoriser un quelconque accès si seul PROT_NONE a été défini. Les implémentations doivent supporter au moins les valeurs suivantes de prot : PROT_NONE, PROT_READ, PROT_WRITE, et le OU bit à bit inclus de PROT_READ et PROT_WRITE. Si PROT_WRITE est spécifié, l'application doit s'assurer qu'elle a ouvert les objets mappés dans la plage d'adresses spécifiée avec la permission d'écriture, sauf si MAP_PRIVATE a été spécifié dans le mappage original, même si les descripteurs de fichiers utilisés pour mapper les objets ont depuis été fermés.

L'implémentation peut exiger que addr soit un multiple de la taille de page renvoyée par sysconf().

Le comportement de cette fonction n'est pas spécifié si le mappage n'a pas été établi par un appel à mmap().

Lorsque mprotect() échoue pour des raisons autres que [EINVAL], les protections de certaines pages dans la plage [addr,addr+len) peuvent avoir été modifiées.

VALEUR DE RETOUR

En cas de succès, mprotect() renvoie 0 ; sinon, elle renvoie -1 et définit errno pour indiquer l'erreur.

ERREURS

La fonction mprotect() échouera si :

EACCES
L'argument prot spécifie une protection qui viole la permission d'accès du processus sur l'objet mémoire sous-jacent.
EAGAIN
L'argument prot spécifie PROT_WRITE sur un mappage MAP_PRIVATE et les ressources mémoire disponibles sont insuffisantes pour réserver le verrouillage de la page privée.
ENOMEM
Les adresses dans la plage [addr,addr+len) sont invalides pour l'espace d'adressage d'un processus, ou spécifient une ou plusieurs pages qui ne sont pas mappées.
ENOMEM
L'argument prot spécifie PROT_WRITE sur un mappage MAP_PRIVATE, et cela nécessiterait plus d'espace que le système ne peut en fournir pour le verrouillage des pages privées, si nécessaire.
ENOTSUP
L'implémentation ne supporte pas la combinaison d'accès demandée dans l'argument prot.

La fonction mprotect() peut échouer si :

EINVAL
L'argument addr n'est pas un multiple de la taille de page renvoyée par sysconf().
