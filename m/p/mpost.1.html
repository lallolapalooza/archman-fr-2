MPOST(1) Manuel des commandes générales MPOST(1)

NOM

mpost, pmpost, upmpost - MetaPost, un système de création graphique
r-mpost, r-pmpost, r-upmpost - MetaPost restreint

SYNTAXE

mpost [options] [commandes]

mpost --dvitomp fichier dvi[.dvi] [fichier mpx[.mpx]]

DESCRIPTION

MetaPost interprète le langage MetaPost et produit des images PostScript (EPS) ou Scalable Vector Graphics (SVG). Le langage MetaPost est similaire à Metafont de Knuth, avec des fonctionnalités supplémentaires pour inclure des commandes tex(1) ou troff(1) et accéder aux fonctionnalités de PostScript non présentes dans Metafont.

MetaPost est normalement utilisé avec un ensemble de macros de base, et il utilisera son nom d'exécutable comme nom du fichier de préchargement à utiliser. Par exemple, lorsqu'il est appelé sous le nom mpost, le fichier mpost.mp est utilisé, qui lit simplement plain.mp. Lorsque l'option --ini est donnée, le préchargement n'a pas lieu.

Les commandes données sur la ligne de commande au programme MetaPost lui sont passées comme première ligne d'entrée. (Mais il est souvent plus facile de taper des arguments étendus comme première ligne d'entrée, car les shells UNIX ont tendance à ignorer ou mal interpréter les symboles préférés de MetaPost, comme les points-virgules, sauf si vous les mettez entre guillemets.) L'utilisation normale est de dire mpost figs pour traiter le fichier figs.mp. Le nom de base de figs devient le ``nom de travail'' (``jobname''), et est utilisé pour former les noms de fichiers de sortie. Si aucun fichier n'est nommé, le nom de travail devient mpout. L'extension par défaut, .mp, peut être remplacée en spécifiant explicitement une extension.

Lorsque l'option --dvitomp est donnée, MetaPost agit uniquement comme convertisseur DVI vers MPX. Voir dvitomp (1) pour plus de détails.

Le programme pmpost est une variante avec prise en charge du japonais, et upmpost a une prise en charge du japonais activée pour Unicode, analogue à ptex et uptex.

Ces trois variantes sont également installées avec un préfixe `r-', c'est-à-dire r-mpost, r-pmpost, r-upmpost, qui spécifie implicitement l'option --restricted pour rendre MetaPost sûr à exécuter sur des entrées inconnues ; les commandes tex, makempx et editor sont désactivées.

Cette page de manuel n'est qu'un squelette. Pour une liste de toutes les options de ligne de commande, exécutez --help.

La documentation principale de cette version de MetaPost se trouve dans le Manuel de l'utilisateur qui aurait dû être installé avec le programme et est également disponible sur https://tug.org/metapost.

Le langage MetaPost est similaire à Metafont, mais le manuel suppose aucune connaissance de Metafont. MetaPost n'a pas de commandes de sortie bitmap ni le mécanisme d'affichage en ligne de Metafont.

AUTEURS

MetaPost a été créé par John D. Hobby, intégrant des algorithmes de Metafont de Donald E. Knuth. Il a été initialement implémenté sur Unix, intégrant des routines dépendantes du système de web2c, tout en ne s'appuyant pas sur celui-ci sauf pour le traducteur Web vers C réel.

Ulrik Vieth a adapté MetaPost pour tirer parti des fonctionnalités avancées de recherche de chemins dans les versions plus récentes de web2c et a travaillé à intégrer pleinement MetaPost dans la distribution TeX canonique d'Unix.

L'auteur principal de MetaPost actuel est Taco Hoekwater, avec l'aide de Hans Hagen et de nombreux autres. Il est actuellement maintenu par Luigi Scarso.
