NOM

mpd.conf - Documentation de mpd.conf

DESCRIPTION

mpd.conf est le fichier de configuration de mpd(1). S'il n'est pas spécifié sur la ligne de commande, MPD le recherche d'abord à l'emplacement $XDG_CONFIG_HOME/mpd/mpd.conf, puis à ~/.mpdconf, ensuite à ~/.mpd/mpd.conf, et enfin dans /etc/mpd.conf.

Chaque ligne du fichier de configuration contient un nom de paramètre et sa valeur, par exemple :

connection_timeout "5"

Les lignes commençant par # sont traitées comme des commentaires et ignorées.

Pour les paramètres qui spécifient un chemin dans le système de fichiers, le tilde ('~') est développé en $HOME. De plus, les expansions de chemins suivantes sont prises en charge :

  • $HOME
  • $XDG_CONFIG_HOME
  • $XDG_MUSIC_DIR
  • $XDG_CACHE_HOME
  • $XDG_RUNTIME_DIR

music_directory "~/Music"

db_file "$XDG_CONFIG_HOME/mpd/database"

Certains paramètres sont groupés dans des blocs avec des accolades, par exemple les paramètres par plugin :

audio_output {
    type "alsa"
    name "Ma sortie ALSA"
    device "iec958:CARD=Intel,DEV=0"
    mixer_control "PCM"
}

La directive include peut être utilisée pour inclure des paramètres d'un autre fichier ; le nom de fichier donné est relatif au fichier actuel :

include "other.conf"

Vous pouvez utiliser include_optional à la place si vous souhaitez que le fichier inclus soit optionnel ; la directive sera ignorée si le fichier n'existe pas :

include_optional "may_not_exist.conf"

Voir docs/mpdconf.example dans l'archive source pour un exemple de fichier de configuration.

Ce manuel n'est pas complet, il ne liste que les options les plus importantes. Veuillez lire le manuel utilisateur de MPD pour un guide de configuration complet : http://www.musicpd.org/doc/user/

PARAMÈTRES OPTIONNELS

db_file <fichier>
Spécifie où le fichier de base de données sera stocké.
log_file <fichier>
Spécifie où le fichier journal doit être situé. La valeur spéciale "syslog" fait que MPD utilise le démon syslog local.
sticker_file <fichier>
L'emplacement de la base de données des stickers. Il s'agit d'une base de données qui gère les informations dynamiques attachées aux chansons.
pid_file <fichier>
Spécifie le fichier dans lequel enregistrer l'ID du processus de mpd.
music_directory <répertoire>
Spécifie le répertoire où se trouve la musique. Si vous ne configurez pas ceci, vous ne pourrez lire que des flux.
playlist_directory <répertoire>
Spécifie le répertoire où les listes de lecture enregistrées sont stockées. Si vous ne configurez pas ceci, vous ne pourrez pas enregistrer de listes de lecture.
state_file <fichier>
Spécifie si un fichier d'état est utilisé et où il est situé. L'état de mpd sera sauvegardé dans ce fichier lorsque mpd sera terminé par un signal TERM ou par la commande kill. Lorsque mpd sera redémarré, il lira le fichier d'état et restaurera l'état de mpd (y compris la liste de lecture).
restore_paused <oui ou non>
Mettez MPD en mode pause au lieu de démarrer la lecture après le démarrage.
user <nom_utilisateur>
Spécifie l'utilisateur sous lequel MPD s'exécutera, s'il est défini. MPD ne doit jamais s'exécuter en tant que root, et vous pouvez utiliser cette option pour que MPD change son ID utilisateur après initialisation. N'utilisez pas cette option si vous démarrez MPD en tant qu'utilisateur non privilégié.
port <port>
Spécifie le port sur lequel mpd écoute. La valeur par défaut est 6600.
log_level <niveau>
Supprime tous les messages inférieurs au seuil donné. Les niveaux de journalisation suivants sont disponibles :
  • error : erreurs
  • warning : avertissements
  • notice : messages informatifs intéressants
  • info : messages informatifs sans importance
  • verbose : messages de débogage (pour les développeurs et le dépannage)

La valeur par défaut est notice.

follow_outside_symlinks <oui ou non>
Contrôle si MPD suivra les liens symboliques pointant à l'extérieur du répertoire de musique. Vous devez recréer la base de données après avoir modifié cette option. La valeur par défaut est "yes".
follow_inside_symlinks <oui ou non>
Contrôle si MPD suivra les liens symboliques pointant à l'intérieur du répertoire de musique, ajoutant potentiellement des doublons à la base de données. Vous devez recréer la base de données après avoir modifié cette option. La valeur par défaut est "yes".
zeroconf_enabled <oui ou non>
Si oui, et que MPD a été compilé avec le support d'Avahi ou Bonjour, les informations de service seront publiées avec Zeroconf. La valeur par défaut est oui.
zeroconf_name <nom>
Si Zeroconf est activé, c'est le nom du service à publier. Ce nom doit être unique sur votre réseau local, mais les collisions de noms seront correctement gérées. La valeur par défaut est "Music Player @ %h", où %h sera remplacé par le nom d'hôte de la machine exécutant MPD.
audio_output
Voir DESCRIPTION et les différentes sections PARAMÈTRES DE SORTIE AUDIO pour le format de ce paramètre. Plusieurs sections audio_output peuvent être spécifiées. Si aucune section audio_output n'est spécifiée, MPD recherchera une sortie audio utilisable.
filesystem_charset <jeu_de_caractères>
Spécifie le jeu de caractères utilisé pour le système de fichiers. Une liste des jeux de caractères pris en charge peut être obtenue en exécutant "iconv -l". La valeur par défaut est déterminée à partir de la locale lors de la création initiale de la base de données.
save_absolute_paths_in_playlists <oui ou non>
Spécifie si des chemins relatifs ou absolus pour les noms de fichiers de chansons sont utilisés lors de l'enregistrement des listes de lecture. La valeur par défaut est "no".
auto_update <oui ou non>
Spécifie si la mise à jour automatique de la base de données musicale doit être prise en charge lorsque des fichiers sont modifiés dans music_directory. Par défaut, la mise à jour automatique de la base de données est désactivée. (Uniquement implémenté sous Linux.)
auto_update_depth <N>
Limite la profondeur des répertoires surveillés, 0 signifie surveiller uniquement le répertoire musical lui-même. Il n'y a pas de limite par défaut.

PARAMÈTRES REQUIS DE SORTIE AUDIO

type <type>
Spécifie le type de sortie audio. Voir la liste des sorties prises en charge dans mpd --version pour les valeurs possibles.
name <nom>
Spécifie un nom unique pour la sortie audio.

PARAMÈTRES OPTIONNELS DE SORTIE AUDIO

format <sample_rate:bits:channels>
Spécifie

finit le taux d'échantillonnage, les bits par échantillon et le nombre de canaux audio envoyés à l'appareil de sortie audio. Voir la documentation du paramètre audio_output_format pour plus de détails. Par défaut, il utilise le format audio qui est passé à la sortie audio. replay_gain_handler <logiciel, mixeur ou aucun>
Spécifie comment le gain de relecture est appliqué. Par défaut, c'est "logiciel", ce qui utilise un contrôle de volume logiciel interne. "mixeur" utilise le contrôle du mixeur (matériel) configuré. "aucun" désactive le gain de relecture sur cette sortie audio.
mixer_type <matériel, logiciel ou aucun>
Spécifie quel mixeur doit être utilisé pour cette sortie audio: le mixeur matériel (disponible pour ALSA, OSS et PulseAudio), le mixeur logiciel ou aucun mixeur ("aucun"). Par défaut, le mixeur matériel est utilisé pour les périphériques qui le prennent en charge, et aucun pour les autres.
