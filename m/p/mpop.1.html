MPOP(1) Manuel des commandes générales MPOP(1)

NOM

mpop - Un client POP3

SYNTAXE

Mode de récupération des courriels (par défaut) :
mpop [option...] [--] [compte...]
mpop --host=hôte [option...]
Mode de configuration :
mpop --configure <adresse électronique>
Mode d'information du serveur :
mpop [option...] --serverinfo [compte...]
mpop --host=hôte [option...] --serverinfo

DESCRIPTION

En mode de récupération des courriels, mpop récupère les courriels d'une ou plusieurs boîtes aux lettres POP3, effectue éventuellement un filtrage, et les livre via un agent de livraison de courriels (MDA), vers un dossier maildir, ou vers un fichier mbox. Les courriels qui ont été livrés avec succès auparavant ne seront pas récupérés une seconde fois, même si des erreurs surviennent ou si mpop est arrêté en milieu de session.
En mode d'information du serveur, mpop affiche des informations sur un ou plusieurs serveurs POP3.
Si aucun nom de compte n'est donné sur la ligne de commande, un compte nommé default sera utilisé.
La meilleure façon de commencer est probablement de jeter un coup d'œil à la section EXEMPLES.

STATUT DE SORTIE

Les codes de sortie standard de sendmail sont utilisés, tels que définis dans sysexits.h.

OPTIONS

Les options remplacent les paramètres du fichier de configuration, pour chaque compte utilisé.

Options Générales
--version
Affiche les informations de version, y compris des informations sur les bibliothèques utilisées.
--help
Affiche l'aide.
-P, --pretend
Affiche les paramètres de configuration qui seraient utilisés, mais n'effectue aucune action supplémentaire. Un astérisque (`*') sera imprimé à la place de votre mot de passe.
-d, --debug
Affiche beaucoup d'informations de débogage, y compris la conversation entière avec le serveur. Soyez prudent avec cette option : la sortie (potentiellement dangereuse) ne sera pas assainie, et votre mot de passe pourra être affiché dans un format facilement décodable !
Cette option implique --half-quiet, car la sortie de progression interférerait avec la sortie de débogage.
Changement du mode de fonctionnement
--configure=adresse électronique
Génère une configuration pour l'adresse électronique donnée et l'affiche. Elle peut être modifiée ou copiée telle quelle dans le fichier de configuration. Notez que cela ne fonctionne que pour les domaines de messagerie qui publient des enregistrements SRV appropriés ; voir la RFC 8314.
-S, --serverinfo
Affiche des informations sur le(s) serveur(s) POP3 et quitte. Cela inclut des informations sur les fonctionnalités prises en charge (pipelining, méthodes d'authentification, commande TOP, ...), sur les paramètres (temps pendant lequel les courriels ne seront pas supprimés, temps minimum entre les connexions, ...), et sur le certificat TLS (si TLS est actif).

-C, --file=fichier de configuration
Utilise le fichier donné au lieu de ~/.mpoprc ou $XDG_CONFIG_HOME/mpop/config comme fichier de configuration utilisateur.
--host=nom d'hôte
Utilise ce serveur avec les paramètres de la ligne de commande ; n'utilise aucune donnée du fichier de configuration. Cette option désactive le chargement du fichier de configuration. Vous ne pouvez pas utiliser cette option et des noms de compte sur la ligne de commande.
--port=nombre
Définit le numéro de port de connexion. Voir la commande port.
--source-ip=[IP]
Définit ou annule une adresse IP pour lier la socket. Voir la commande source_ip.
--proxy-host=[IP|nom d'hôte]
Définit ou annule un proxy SOCKS à utiliser. Voir la commande proxy_host.
--proxy-port=[nombre]
Définit ou annule un numéro de port pour l'hôte proxy. Voir la commande proxy_port.
--socket=[nom de socket]
Définit ou annule un nom de socket de domaine Unix local pour la connexion. Voir la commande socket.
--timeout=(off|secondes)
Définit un délai réseau. Voir la commande timeout.
--pipelining=(auto|on|off)
Active ou désactive le pipelining POP3. Voir la commande pipelining.
--received-header[=(on|off)]
Active ou désactive l'en-tête Received. Voir la commande received_header.
--auth[=(on|méthode)]
Définit la méthode d'authentification sur automatique (avec « on ») ou choisit manuellement une méthode d'authentification. Voir la commande auth.
--user=[nom d'utilisateur]
Définit ou annule le nom d'utilisateur pour l'authentification. Voir la commande user.
--passwordeval=[cmd]
Évalue le mot de passe pour l'authentification. Voir la commande passwordeval.
--tls[=(on|off)]
Active ou désactive TLS/SSL. Voir la commande tls.
--tls-starttls[=(on|off)]
Active ou désactive STARTTLS pour TLS. Voir la commande tls_starttls.
--tls-trust-file=[fichier]
Définit ou annule un fichier de confiance pour TLS. Voir la commande tls_trust_file.
--tls-crl-file=[fichier]
Obsolète. Définit ou annule un fichier de liste de révocation de certificats (CRL) pour TLS. Voir la commande tls_crl_file.
--tls-fingerprint=[empreinte]
Définit ou annule l'empreinte d'un certificat TLS de confiance. Voir la commande tls_fingerprint.
--tls-key-file=[fichier]
Définit ou annule un fichier de clé pour TLS. Voir la commande tls_key_file.
--tls-cert-file=[fichier]
Définit ou annule un fichier de certificat pour TLS. Voir la commande tls_cert_file.
--tls-certcheck[=(on|off)]
Active ou désactive la vérification du certificat serveur pour TLS. Voir la commande tls_certcheck.
--tls-priorities=[priorités]
Définit ou annule les priorités TLS. Voir la commande tls_priorities.
--tls-host-override=[hôte]
Définit ou annule la substitution pour la vérification de l'hôte TLS. Voir la commande tls_host_override.
--tls-min-dh-prime-bits=[bits]
Obsolète, utiliser --tls-priorities à la place. Définit ou annule la taille minimale en bits de la prime Diffie-Hellmann (DH). Voir la commande tls_min_dh_prime_bits.
Options spécifiques au mode de récupération des courriels
-q, --quiet

-Q, --half-quiet

-a, --all-accounts
Interroge tous les comptes du fichier de configuration.

UTILISATION

Une suggestion pour un fichier de configuration approprié peut être générée en utilisant l'option --configure. Le fichier de configuration par défaut est ~/.mpoprc ou $XDG_CONFIG_HOME/mpop/config. Les paramètres de ce fichier peuvent être modifiés par des options de ligne de commande.
Un fichier de configuration est un simple fichier texte. Les lignes vides et les lignes de commentaire (le premier caractère non blanc est '#') sont ignorées. Toutes les autres lignes doivent contenir une commande et peuvent contenir un argument pour cette commande. L'argument peut être entouré de guillemets doubles ("").
Si un nom de fichier commence par une tilde (~), cette tilde sera remplacée par $HOME.
Si une commande accepte l'argument on, elle accepte également un argument vide et le traite comme s'il s'agissait de on.
Les commandes sont organisées en comptes. Chaque compte commence par la commande account et définit les paramètres d'un compte POP3.

Les commandes sont les suivantes :

defaults
Définir les valeurs par défaut. Les commandes de configuration suivantes définiront des valeurs par défaut pour toutes les définitions de compte suivantes.
account name [:account[,...]]
Démarrer une nouvelle définition de compte avec le nom donné. Les valeurs par défaut actuelles sont remplies.
Si deux-points et une liste de comptes précédemment définis sont donnés après le nom du compte, le nouveau compte, avec les valeurs par défaut remplies, héritera de tous les paramètres des comptes de la liste.
eval cmd
Remplacer la ligne actuelle du fichier de configuration par la première ligne de la sortie (stdout) de la commande cmd. Ceci peut être utilisé pour décrypter des paramètres ou pour les créer via des scripts. Par exemple, eval echo host localhost remplace la ligne actuelle par host localhost.
Notez que chaque ligne eval sera évaluée lors de la lecture du fichier de configuration.
Notez que pour les mots de passe, vous pouvez également utiliser la commande passwordeval au lieu de eval password cmd. Cela présente l'avantage que la commande n'est évaluée que si nécessaire.
host hostname
Le serveur POP3 à partir duquel récupérer les courriers. L'argument peut être un nom d'hôte ou une adresse réseau. Chaque définition de compte doit contenir cette commande.
port number
Le port sur lequel le serveur POP3 écoute. La valeur par défaut est 110 ("pop3"), sauf si TLS sans STARTTLS est utilisé, auquel cas c'est 995 ("pop3s").
source_ip [IP]
Définir une adresse IP source pour lier la connexion sortante. Utile uniquement dans des cas spéciaux sur des systèmes multi-hommes. Un argument vide désactive cette fonction.
proxy_host [IP|hostname]
Utiliser un proxy SOCKS. Tout le trafic réseau passera par ce proxy, y compris les requêtes DNS, à l'exception d'une requête DNS qui pourrait être nécessaire pour résoudre le nom du proxy lui-même (cela peut être évité en utilisant une adresse IP comme nom d'hôte du proxy). Un argument hostname vide désactive l'utilisation du proxy. Le protocole SOCKS pris en charge est la version 5. Si vous souhaitez utiliser ceci avec Tor, voir également "Utilisation de mpop avec Tor" ci-dessous.
proxy_port [number]
Définir le numéro de port pour l'hôte proxy. Un argument number vide le réinitialise au port par défaut, qui est 1080 ("socks").
socket socketname
Définir le nom du fichier d'un socket de domaine Unix auquel se connecter. Ceci remplace à la fois host/port et proxy_host/proxy_port.
timeout (off|seconds)
Définir ou annuler un délai d'attente réseau, en secondes. La valeur par défaut est de 180 secondes. L'argument off signifie qu'aucun délai d'attente ne sera défini, ce qui signifie que la valeur par défaut du système d'exploitation sera utilisée.
pipelining (auto|on|off)
Activer ou désactiver le pipelining POP3. Vous ne devriez jamais avoir besoin de modifier le paramètre par défaut, qui est auto : mpop active le pipelining pour les serveurs POP3 qui annoncent cette capacité, et le désactive pour tous les autres serveurs. Le pipelining peut accélérer considérablement une session POP3.
auth [(on|method)]
Choisir une méthode d'authentification. L'argument par défaut on choisit une méthode automatiquement.
Généralement, un nom d'utilisateur et un mot de passe sont utilisés pour l'authentification. Le nom d'utilisateur est spécifié dans le fichier de configuration avec la commande user. Il existe cinq méthodes différentes pour spécifier le mot de passe :
1. Ajouter le mot de passe au trousseau système. Les trousseaux actuellement pris en charge sont le trousseau Gnome et le trousseau Mac OS X. Pour le trousseau Gnome, utilisez la commande secret-tool (qui fait partie de libsecret de Gnome) pour stocker les mots de passe : secret-tool store --label=mpop host pop.freemail.example service pop3 user joe.smith. Sur Mac OS X, utilisez la commande suivante : security add-internet-password -s pop.freemail.example -r pop3 -a joe.smith -w. Dans les deux exemples, remplacez pop.freemail.example par le nom du serveur POP3 et joe.smith par votre nom d'utilisateur.
2. Stocker le mot de passe dans des fichiers cryptés, et utiliser passwordeval pour spécifier une commande qui décrypte ce fichier, par exemple en utilisant GnuPG. Voir EXEMPLES.
3. Stocker le mot de passe dans le fichier de configuration en utilisant la commande password. (Généralement, il n'est pas considéré comme une bonne idée de stocker des mots de passe dans des fichiers en clair. Si vous le faites quand même, vous devez vous assurer que le fichier ne peut être lu que par vous-même.)
4. Stocker le mot de passe dans ~/.netrc. Cette méthode est probablement obsolète.
5. Taper le mot de passe dans le terminal lorsqu'il est requis.
Il est recommandé d'utiliser la méthode 1 ou 2.
Plusieurs méthodes d'authentification existent. La plupart des serveurs n'en supportent que certaines.
Les méthodes utilisateur / mot de passe suivantes sont prises en charge : user (une méthode simple en texte brut prise en charge par tous les serveurs), plain (une autre méthode simple en texte brut, prise en charge par presque tous les serveurs), scram-sha-1 et scram-sha-1-plus (une méthode qui évite les mots de passe en clair et exige que le serveur prouve qu'il est en possession du mot de passe (haché et salé), ce qui empêche certaines attaques man-in-the-middle. La variante -plus utilise en outre des informations de liaison de canal TLS pour des garanties de sécurité encore meilleures), scram-sha-256 et scram-sha-256-plus (identique mais avec une fonction de hachage plus forte), apop (une méthode obsolète qui évite les mots de passe en clair, mais n'est plus considérée comme sécurisée), cram-md5 (une méthode obsolète qui évite les mots de passe en clair, mais n'est plus considérée comme sécurisée), digest-md5 (une méthode obsolète trop compliquée qui évite les mots de passe en clair, mais n'est plus considérée comme sécurisée), login (une méthode non standard en texte brut similaire mais pire que la méthode plain), ntlm (une méthode obscure et non standard qui est maintenant considérée comme défectueuse ; elle nécessite parfois un paramètre de domaine spécial passé via ntlmdomain).
Si aucune méthode n'est spécifiée, mpop en sélectionnera une automatiquement en fonction des avantages de sécurité. Avec TLS, l'ordre est scram-sha-256-plus, scram-sha-1-plus, scram-sha-256, scram-sha-1, plain, suivi de certaines méthodes obsolètes si rien d'autre n'est disponible. Sans TLS, seuls scram-sha-256 et scram-sha-1 sont pris en compte.
Il existe actuellement trois méthodes d'authentification qui ne sont pas basées sur des informations utilisateur/mot de passe et qui doivent être choisies manuellement : oauthbearer ou son prédécesseur xoauth2 (un jeton OAuth2 du fournisseur de messagerie est utilisé comme mot de passe. Voir la documentation de votre fournisseur de messagerie pour savoir comment obtenir ce jeton. La commande passwordeval peut être utilisée pour passer les jetons régulièrement changeants à mpop depuis un script ou une variable d'environnement), external (l'authentification se fait en dehors du protocole, généralement en envoyant un certificat client TLS, et la méthode se contente de confirmer que cette authentification a réussi), et gssapi (le framework Kerberos s'occupe de l'authentification sécurisée, seul un nom d'utilisateur est requis).
La prise en charge d'une méthode particulière dépend de la bibliothèque d'authentification sous-jacente et de sa version. Utilisez --version pour savoir quelles méthodes sont prises en charge.
user login
Définir le nom d'utilisateur pour l'authentification. Un argument vide désactive le nom d'utilisateur.
password secret
Définir le mot de passe pour l'authentification. Un argument vide désactive le mot de passe. Envisagez d'utiliser la commande passwordeval ou un trousseau au lieu de cette commande, afin d'éviter de stocker des mots de passe en clair dans le fichier de configuration.
passwordeval [cmd]
Définir le mot de passe pour l'authentification sur la sortie (stdout) de la comma
nd cmd. Ceci peut être utilisé par exemple pour déchiffrer des fichiers de mots de passe à la volée ou pour interroger des trousseaux de clés, et ainsi éviter de stocker des mots de passe en clair.
ntlmdomain [domaine]
Définit un domaine pour la méthode d'authentification ntlm. Ceci est obsolète.
tls [(on|off)]
Active ou désactive TLS (également connu sous le nom de SSL) pour les connexions sécurisées.
Transport Layer Security (TLS) « ... fournit la confidentialité des communications sur Internet. Le protocole permet aux applications client/serveur de communiquer d'une manière conçue pour empêcher l'écoute clandestine, la falsification ou la falsification de messages » (citation de la RFC2246).
Un serveur peut utiliser TLS dans l'un des deux modes : via une commande STARTTLS (la session commence par l'initialisation normale du protocole, et TLS est ensuite démarré en utilisant la commande STARTTLS du protocole), ou immédiatement (TLS est initialisé avant l'initialisation normale du protocole ; cela nécessite un port distinct). Le premier mode est celui par défaut, mais vous pouvez passer au second mode en désactivant tls_starttls.
Lorsque TLS est démarré, le serveur envoie un certificat pour s'identifier. Pour vérifier l'identité du serveur, un programme client est censé vérifier que le certificat est formellement correct et qu'il a été délivré par une autorité de certification (CA) à laquelle l'utilisateur fait confiance. (Il peut également y avoir des chaînes de certificats avec des CA intermédiaires.)
La liste des CA de confiance est spécifiée à l'aide de la commande tls_trust_file. La valeur par défaut est "system" et sélectionne le défaut du système, mais vous pouvez également choisir vous-même les CA de confiance.
Un problème fondamental avec cela est qu'il faut faire confiance aux CA. Comme toute autre organisation, une CA peut être incompétente, malveillante, compromise par de mauvaises personnes ou contrainte par des agences gouvernementales à compromettre les utilisateurs finaux sans les en informer. Toutes ces choses se sont produites et continuent de se produire dans le monde entier. L'idée d'avoir des organisations centrales auxquelles il faut faire confiance pour que votre communication soit sécurisée est fondamentalement erronée.
Au lieu de faire confiance à une CA, vous pouvez choisir de faire confiance à un seul certificat pour le serveur auquel vous souhaitez vous connecter. À cette fin, spécifiez l'empreinte du certificat avec tls_fingerprint. Cela garantit qu'aucun homme du milieu ne peut usurper l'identité du serveur en vous présentant un certificat frauduleux délivré par une CA qui se trouve dans votre liste de confiance. Cependant, vous devrez mettre à jour l'empreinte chaque fois que le certificat du serveur change, et vous devrez vous assurer que le changement est légitime à chaque fois, par exemple lorsque l'ancien certificat a expiré. C'est gênant, mais c'est le prix à payer.
Les informations sur un certificat serveur peuvent être obtenues avec --serverinfo --tls --tls-certcheck=off. Cela inclut la CA émettrice du certificat (pour que vous puissiez faire confiance à cette CA via tls_trust_file), et l'empreinte du certificat (pour que vous puissiez faire confiance à ce certificat particulier via tls_fingerprint).
TLS permet également au serveur de vérifier l'identité du client. À cette fin, le client doit présenter un certificat délivré par une CA à laquelle le serveur fait confiance. Pour présenter ce certificat, le client a également besoin du fichier de clé correspondant. Vous pouvez définir les fichiers de certificat et de clé à l'aide de tls_cert_file et tls_key_file. Ce mécanisme peut également être utilisé pour authentifier les utilisateurs, de sorte que l'authentification utilisateur/mot de passe traditionnelle ne soit plus nécessaire. Voir le mécanisme external dans auth.
Vous pouvez également utiliser des certificats clients stockés sur un périphérique d'authentification externe en spécifiant des URI de périphérique GnuTLS dans tls_cert_file et tls_key_file. Vous pouvez trouver les URI correctes à l'aide de p11tool --list-privkeys --login (p11tool est fourni avec GnuTLS). Si votre périphérique nécessite un code PIN pour accéder aux données, vous pouvez le spécifier à l'aide de l'un des mécanismes de mot de passe (par exemple, passwordeval, password).
tls_starttls [(on|off)]
Choisit la variante TLS : démarrer TLS à partir de la session (on, par défaut), ou tunneliser la session via TLS (off).
tls_trust_file fichier
Active la vérification du certificat serveur à l'aide d'une liste d'autorités de certification (CA) de confiance. La valeur par défaut est la valeur spéciale "system", qui sélectionne la valeur par défaut du système. Un argument vide désactive la confiance dans les CA. Si vous sélectionnez un fichier, il doit être au format PEM, et vous devriez également utiliser tls_crl_file.
tls_crl_file [fichier]
Définit un fichier de liste de révocation de certificats (CRL) pour TLS, pour vérifier les certificats révoqués (un argument vide, qui est la valeur par défaut, désactive cela).
OCSP est une alternative aux fichiers CRL. Lorsque GnuTLS est utilisé, les informations OCSP encapsulées seront automatiquement vérifiées, et l'extension TLS MustStaple est prise en charge, mais aucune requête OCSP manuelle ne sera envoyée lorsque des informations OCSP encapsulées sont manquantes. Avec d'autres bibliothèques TLS, le comportement peut être différent.
tls_fingerprint [empreinte]
Définit l'empreinte d'un seul certificat à accepter pour TLS. Ce certificat sera approuvé indépendamment de son contenu (cela remplace tls_trust_file). L'empreinte doit être de type SHA256, mais peut, pour des raisons de compatibilité ascendante, être aussi de type SHA1 ou MD5 (veuillez éviter cela). Le format doit être 01:23:45:67:.... Utilisez --serverinfo --tls --tls-certcheck=off --tls-fingerprint= pour obtenir l'empreinte du certificat serveur.
tls_key_file fichier
Envoie un certificat client au serveur (utilisez ceci avec tls_cert_file). Le fichier doit contenir la clé privée d'un certificat au format PEM. Un argument vide désactive cette fonctionnalité.
tls_cert_file fichier
Envoie un certificat client au serveur (utilisez ceci avec tls_key_file). Le fichier doit contenir un certificat au format PEM. Un argument vide désactive cette fonctionnalité.
tls_certcheck [(on|off)]
Active ou désactive les vérifications du certificat serveur. Elles sont activées par défaut. Leur désactivation remplacera tls_trust_file et tls_fingerprint. ATTENTION : Lorsque les vérifications sont désactivées, les sessions TLS ne seront pas sécurisées !
tls_priorities [priorités]
Définit les priorités pour les paramètres de session TLS. La valeur par défaut est définie par la bibliothèque TLS et peut être sélectionnée en utilisant un argument vide à cette commande. L'interprétation de la chaîne priorités dépend de la bibliothèque TLS. Utilisez --version pour savoir quelle bibliothèque TLS vous utilisez.
Pour GnuTLS, consultez la section sur les chaînes de priorités dans le manuel.
Pour libtls, la chaîne priorités est une liste de chaînes de paramètres séparées par des espaces, préfixées par PROTOCOLS=, CIPHERS=, ou ECDHECURVES=. Ces chaînes de paramètres seront passées aux fonctions tls_config_parse_protocols, tls_config_set_ciphers, et tls_config_set_ecdhecurves. Les parties non reconnues de la chaîne priorités seront ignorées. Exemple : "PROTOCOLS=TLSv1.3 CIPHERS=ECDHE-RSA-AES128-SHA256 ECDHECURVES=P-384".
tls_host_override [hôte]
Par défaut, la vérification de l'hôte TLS utilise le nom d'hôte donné par la commande host. Cette commande permet d'utiliser un nom d'hôte différent pour la vérification. Ceci n'est utile que dans des cas particuliers.
tls_min_dh_prime_bits [bits]
Obsolète, utilisez tls_priorities à la place. Définit ou annule le nombre minimum de bits de nombres premiers de Diffie-Hellman (DH) acceptés pour les sessions TLS. La valeur par défaut est définie par la bibliothèque TLS et peut être sélectionnée en utilisant un argument vide à cette commande. N'abaissez la valeur par défaut (par exemple à 512 bits) que s'il n'y a pas d'autre moyen de faire fonctionner TLS avec le serveur distant.
delivery méthode arguments_méthode...
Comment livrer les messages reçus de ce compte.
delivery mda commande
Livrer les courriels via un agent de livraison de courrier (MDA).
Toutes les occurrences de %F dans la commande seront remplacées par l'adresse de l'expéditeur de l'enveloppe du message actuel (ou MAILER-DAEMON s'il n'y en a pas). Notez que cette adresse est garantie de contenir uniquement des lettres a-z et A-Z, des chiffres 0-9 et l'un des caractères ".@_-+/", même si ce n'est qu'un sous-ensemble de ce qui est théoriquement autorisé dans une adresse e-mail. Les autres caractères, y compris ceux interprétés par le shell, sont remplacés par "_". Néanmoins, vous devriez placer %F entre guillemets simples : '%F'.
Utilisez "delivery mda /usr/bin/procmail -f '%F' -d $USER" pour le MDA procmail.
Utilisez "delivery mda /usr/sbin/sendmail -oi -oem -f '%F' -- $USER" pour laisser votre MTA gérer le courrier.
Utilisez "delivery mda /usr/local/bin/msmtp --host=localhost --from='%F' -- $USER@`hostname`.`dnsdomainname`" pour passer le courrier à votre MTA via SMTP. (C'est ce que fait fetchmail par défaut.)
delivery maildir répertoire
Livrer les courriels dans le répertoire maildir donné. Le répertoire doit exister et il doit avoir les sous-répertoires maildir cur, new et tmp ; mpop ne créera pas les répertoires. Ce type de livraison ne fonctionne que sur les systèmes de fichiers qui prennent en charge les liens physiques.
delivery mbox fichier_mbox
Livrer les courriels dans le fichier donné au format mbox. Le fichier sera verrouillé avec fcntl(2). mpop utilise la variante de format mbox MBOXRD ; voir la documentation du format mbox.
delivery exchange répertoire
Livrer les courriels dans le répertoire de prise en charge d'Exchange donné. Le répertoire doit exister.

Si la méthode de livraison doit analyser les en-têtes du courrier pour une adresse d'expéditeur d'enveloppe (la méthode mda si la commande contient %F, et la méthode mbox), elle doit créer un fichier temporaire pour y stocker les en-têtes du courrier (mais pas le corps).

uidls_file nom_fichier
Le fichier dans lequel stocker les UIDL. Ce sont des...
ded pour identifier les nouveaux messages. %U dans le nom de fichier sera remplacé par le nom d'utilisateur du compte actuel. %H dans le nom de fichier sera remplacé par le nom d'hôte du compte actuel. Si le nom de fichier contient des répertoires qui n'existent pas, mpop les créera. mpop verrouille ce fichier pour un accès exclusif lors de l'accès au compte POP3 associé.
La valeur par défaut est "~/.mpop_uidls/%U_at_%H". Vous pouvez également utiliser un fichier UIDLS unique pour plusieurs comptes, mais vous ne pourrez alors pas interroger plus d'un de ces comptes en même temps.
only_new [(on|off)]
Par défaut, mpop traite uniquement les nouveaux messages (les nouveaux messages sont ceux qui n'ont pas été récupérés avec succès lors d'une session précédente). Si cette option est désactivée, mpop traitera tous les messages.
keep [(on|off)]
Conserver tous les courriels sur le serveur POP3, ne jamais les supprimer. Le comportement par défaut est de supprimer les courriels qui ont été récupérés avec succès ou filtrés par les filtres kill.
killsize (off|size)
Les courriels plus volumineux que la taille donnée seront supprimés (sauf si la commande keep est utilisée, auquel cas ils seront simplement ignorés). L'argument de taille doit être zéro ou supérieur. S'il est suivi d'un `k' ou d'un `m', la taille est mesurée en kibioctets/mébioctets au lieu d'octets. Notez que certains serveurs POP3 signalent des tailles légèrement incorrectes pour les courriels ; voir NOTES ci-dessous.
Lorsque killsize est défini sur 0 et keep sur on, tous les courriels sont marqués comme récupérés, mais aucun courriel n'est supprimé du serveur. Cela peut être utilisé pour synchroniser la liste UID du client avec la liste UID du serveur.
skipsize (off|size)
Les courriels plus volumineux que la taille donnée seront ignorés (non téléchargés). L'argument de taille doit être zéro ou supérieur. S'il est suivi d'un `k' ou d'un `m', la taille est mesurée en kibioctets/mébioctets au lieu d'octets. Notez que certains serveurs POP3 signalent des tailles légèrement incorrectes pour les courriels ; voir NOTES ci-dessous.
filter [command]
Définir un filtre qui décidera s'il faut récupérer, ignorer ou supprimer chaque courriel en examinant les en-têtes du courriel. Le serveur POP3 doit prendre en charge la commande POP3 TOP pour que cela fonctionne ; voir l'option --serverinfo ci-dessus. Un argument vide désactive le filtrage.
Toutes les occurrences de %F dans la commande seront remplacées par l'adresse d'expéditeur de l'enveloppe du message actuel (ou MAILER-DAEMON s'il n'y en a pas). Notez que cette adresse est garantie de ne contenir que des lettres a-z et A-Z, des chiffres 0-9, et l'un des caractères ".@_-+/", même si ce n'est qu'un sous-ensemble de ce qui est théoriquement autorisé dans une adresse de courriel. D'autres caractères, y compris ceux interprétés par le shell, sont remplacés par "_". Néanmoins, vous devriez placer %F entre guillemets simples : '%F'.
Toutes les occurrences de %S dans la commande seront remplacées par la taille du courriel actuel telle que signalée par le serveur POP3.
Les en-têtes du courriel (plus la ligne vide séparant les en-têtes du corps) seront redirigés vers la commande. En fonction du code de retour, mpop décide quoi faire du courriel :
0 : procéder normalement ; aucune action spéciale
1 : supprimer le courriel ; ne pas le récupérer
2 : ignorer le courriel ; ne pas le récupérer
Les codes de retour supérieurs ou égaux à 3 indiquent qu'une erreur s'est produite. Les codes d'erreur sysexits.h peuvent être utilisés pour fournir des informations sur le type d'erreur, mais ce n'est pas nécessaire.

received_header [(on|off)]
Activer ou désactiver l'ajout d'un en-tête Received. Par défaut, mpop préfixe un en-tête Received au courriel lors de la livraison. Ceci est requis par les RFC si le courriel est ensuite acheminé, par exemple via SMTP.

FILTRAGE

Trois commandes de filtrage sont disponibles. Elles seront exécutées dans l'ordre suivant :
killsize
skipsize
filter
Si une commande de filtrage s'applique à un courriel, les filtres restants ne seront pas exécutés.

EXEMPLES

Fichier de configuration

# Exemple de fichier de configuration utilisateur ~/.mpoprc
#
# Ce fichier se concentre sur TLS, l'authentification et la méthode de livraison des courriels.
# Les fonctionnalités non utilisées ici comprennent le filtrage des courriels, les délais d'attente, les proxys SOCKS,
# les paramètres TLS, et plus encore.

# Définir les valeurs par défaut pour tous les comptes suivants.
defaults

# Utiliser toujours TLS.
tls on

# Définir une liste de CAs de confiance pour TLS. La valeur par défaut est d'utiliser les paramètres système, mais
# vous pouvez sélectionner votre propre fichier.
#tls_trust_file /etc/ssl/certs/ca-certificates.crt

# Livrer le courrier à un fichier de courrier MBOX :
delivery mbox ~/Mail/inbox
# Livrer le courrier à un dossier maildir :
#delivery maildir ~/Mail/incoming
# Livrer le courrier via procmail :
#delivery mda "/usr/bin/procmail -f '%F' -d $USER"
# Livrer le courrier via le serveur SMTP local :
#delivery mda "/usr/bin/msmtp --host=localhost --from='%F' -- $USER"
# Livrer le courrier à un répertoire de récupération Exchange :
#delivery exchange c:\exchange\pickup

# Utiliser un fichier UIDLS dans ~/.local/share au lieu de ~/.mpop_uidls
uidls_file ~/.local/share/%U_at_%H

# Un service de freemail
account freemail

# Nom d'hôte du serveur POP3
host pop.freemail.example

# Comme alternative à tls_trust_file, vous pouvez utiliser tls_fingerprint
# pour épingler un seul certificat. Vous devrez mettre à jour l'empreinte lorsque le
# certificat du serveur changera, mais un attaquant ne pourra pas vous tromper pour que vous acceptiez
# un certificat frauduleux. Obtenez l'empreinte avec
# $ mpop --serverinfo --tls --tls-certcheck=off --host=pop.freemail.example
#tls_fingerprint 00:11:22:33:44:55:66:77:88:99:AA:BB:CC:DD:EE:FF:00:11:22:33

# Authentification. Le mot de passe est donné en utilisant l'une des cinq méthodes, voir ci-dessous.
user joe.smith

# Méthode de mot de passe 1 : Ajouter le mot de passe au trousseau système, et laisser mpop le récupérer
# automatiquement. Pour définir le mot de passe du trousseau à l'aide de libsecret de Gnome :
# $ secret-tool store --label=mpop \
# host pop.freemail.example \
# service pop3 \
# user joe.smith

# Méthode de mot de passe 2 : Stocker le mot de passe dans un fichier crypté, et dire à mpop
# quelle commande utiliser pour le déchiffrer. Ceci est généralement utilisé avec GnuPG, comme dans
# cet exemple. Normalement, gpg-agent vous demandera une fois le mot de passe de déchiffrement.
passwordeval gpg2 --no-tty -q -d ~/.mpop-password.gpg

# Méthode de mot de passe 3 : Stocker le mot de passe directement dans ce fichier. Généralement, il n'est pas
# bon d'idée de stocker les mots de passe dans des fichiers en texte clair. Si vous le faites quand même, au
# moins assurez-vous que ce fichier ne peut être lu que par vous-même.
#password secret123

# Méthode de mot de passe 4 : Stocker le mot de passe dans ~/.netrc. Cette méthode n'est probablement plus
# pertinente.

# Méthode de mot de passe 5 : Ne pas spécifier de mot de passe. Mpop vous demandera alors de le saisir.
# Cela signifie que vous devez pouvoir taper dans un terminal lorsque mpop s'exécute.

# Une deuxième boîte aux lettres au même service freemail
account freemail2 : freemail
user joey

# Le serveur POP3 de votre FAI
account isp
host mail.isp.example
auth on
user 12345
# Votre FAI utilise SpamAssassin, donc testez chaque courriel pour l'en-tête "X-Spam-Status: Yes"
# et supprimez tous les courriels avec cet en-tête avant de les télécharger.
filter if [ "`grep "^X-Spam-Status: Yes"`" ]; then exit 1; else exit 0; fi

# Définir un compte par défaut
account default : freemail

Filtrage avec SpamAssassin

La commande filter "/chemin/vers/spamc -c > /dev/null" supprimera tous les courriels que SpamAssassin considère comme du spam. Puisqu'aucun corps de message n'est passé à SpamAssassin, vous devriez désactiver tous les tests spécifiques au corps dans le fichier de configuration SpamAssassin ; par exemple, définissez use_bayes 0.

Si votre fournisseur de messagerie utilise SpamAssassin pour vous, il vous suffit de vérifier le résultat. Le script suivant peut le faire lorsqu'il est utilisé comme filtre mpop :
#!/bin/sh
if [ "`grep "^X-Spam-Status: Yes"`" ]; then
exit 1 # supprimer ce message
else
exit 0 # procéder normalement
fi
Comme la commande filter est passée à un shell, vous pouvez également l'utiliser directement :
filter if [ "`grep "^X-Spam-Status: Yes"`" ]; then exit 1; else exit 0; fi

Utilisation de mpop avec Tor

Utilisez les paramètres suivants :
proxy_host 127.0.0.1
proxy_port 9050
tls on
Utilisez une adresse IP comme nom d'hôte du proxy, afin que mpop ne divulgue pas de requête DNS lors de sa résolution.
TLS est requis pour empêcher les hôtes de sortie de lire votre session POP3.

FICHIERS

~/.mpoprc ou $XDG_CONFIG_HOME/mpop/config
Fichier de configuration par défaut.
~/.mpop_uidls
Répertoire par défaut pour stocker les fichiers UIDLS.
~/.netrc et SYSCONFDIR/netrc
Le fichier netrc contient les informations de connexion. Avant de demander un mot de passe, msmtp le recherchera dans ~/.netrc et SYSCONFDIR/netrc.

ENVIRONNEMENT

$USER, $LOGNAME
Ces variables remplacent le nom d'utilisateur. $LOGNAME n'est utilisé que si $USER n'est pas défini. Le nom d'utilisateur est utilisé pour les en-têtes Received.
