NOM

MP4Box - multiplexeur multimédia en ligne de commande de GPAC

SYNTAXE

MP4Box [options] [fichier] [options]

OPTIONS GENERALES

MP4Box est un multiplexeur multimédia, doté d'un vaste éventail de fonctionnalités : conversion, découpage, encodage, vidage, DASH, chiffrement, transcodage et autres.
MP4Box propose un large ensemble d'options, classées par catégories (voir .I -h). Ces options ne suivent aucun ordre particulier.

Par défaut, MP4Box réécrit le fichier d'entrée. Vous pouvez modifier ce comportement en utilisant l'option .I out.
MP4Box enregistre par défaut le fichier avec un entrelacement de 0,5 seconde et les métadonnées (moov...) au début, le rendant adapté au téléchargement et à la lecture sur HTTP. Cela peut cependant prendre plus de temps pour enregistrer le fichier, utilisez .I flat pour changer ce comportement.

MP4Box génère généralement un fichier temporaire lors de la création d'un nouveau fichier IsoMedia. L'emplacement de ce fichier temporaire dépend de l'OS, et il se peut que le lecteur/la partition sur lequel le fichier temporaire est créé ne dispose pas de suffisamment d'espace ou n'ait pas de droits d'accès en écriture. Dans un tel cas, vous pouvez spécifier un emplacement de fichier temporaire avec .I tmp.

L'identifiant de piste pour les opérations basées sur les pistes (généralement appelé tkID dans l'aide) utilise la syntaxe suivante :
* INT : la cible est la piste avec l'ID INT
* n`INT` : la cible est la piste numéro INT
* `audio`, `video`, `text` : la cible est la première piste audio, vidéo ou texte
* `audioN`, `videoN`, `textN` : la cible est la N-ième piste audio, vidéo ou texte, avec N=1 étant la première piste du type désiré

Valeurs des options :
Sauf indication contraire, une option d'opération sur piste de type entier attend un identifiant de piste comme valeur.
Une option de type booléen n'attend aucune valeur suivante.

-mem-track-stack

utilise le profil indiqué pour la configuration globale GPAC. Si non trouvé, le fichier de configuration est créé. Si un chemin de fichier est indiqué, cela chargera le profil depuis ce fichier. Sinon, cela créera un répertoire du nom spécifié et y stockera la nouvelle configuration. Le nom réservé 0 signifie un nouveau profil, non enregistré sur disque. Fonctionne avec -p=NOM ou -p NOM

définit les informations de chapitre à partir du fichier indiqué, en utilisant le signalement QT pour les pistes texte

définit l'échelle de temps du film à la valeur indiquée (tiques par seconde)

définit la langue. LAN est le code BCP-47 (eng, en-UK, ...). Si aucun ID de piste n'est donné, définit la langue pour toutes les pistes

définit le délai de démarrage de la piste (>0) ou le saut initial (<0) en ms ou en secondes fractionnaires (N/D)

* none : supprime les informations PAR de la piste, sans modifier le flux binaire

* criteria=string : liste de 4CC séparés par des espaces
* trackID=ID : piste à ajouter à ce groupe

Attention : Les options modifient l'état au fur et à mesure de leur analyse, trackID=1:criteria=lang:trackID=2 est différent de criteria=lang:trackID=1:trackID=2

conserve le chronométrage UTC dans le fichier après modification

définit udta pour la piste donnée ou pour le film si tkID est 0. OPTS est une liste séparée par des deux-points :
* type=CODE : code 4CC de l'UDTA (pas nécessaire pour l'option box=)
* box=FILE : emplacement des données udta, formaté comme des boîtes sérialisées
* box=base64,DATA : données udta encodées en base64, formatées comme des boîtes sérialisées
* src=FILE : emplacement des données udta (sera stocké dans une seule boîte de type CODE)
* src=base64,DATA : données udta encodées en base64 (sera stocké dans une seule boîte de type CODE)
* str=STRING : utilise la chaîne donnée comme charge utile pour la boîte udta

applique le patch de boîte décrit dans FILE, pour la pisteID donnée si définie
-bo

gèle l'ordre des boîtes dans le fichier d'entrée
-init-seg (string)

utilise le fichier donné comme segment d'initialisation pour le déchargement ou le chiffrement

-xmov

identique à zmov et encapsule ftyp dans otyp

définit la liste d'éditions. La syntaxe suivante est utilisée (sans séparateurs entre les entrées) :
* `r` : supprime toutes les éditions
* `eSTART` : ajoute une édition vide avec un temps de début donné. START peut être
- VAL : temps de début en secondes (entier, double, fraction), durée du média utilisée comme durée de l'édition
- VAL-DUR : temps de début et durée en secondes (entier, double, fraction)
* `eSTART,MEDIA[,RATE]` : ajoute une édition régulière avec le temps de début donné, le temps de début du média en secondes (entier, double, fraction) et le taux (fraction ou INT)
* Exemples :
- re0-5e5-3,4 : supprime les éditions, ajoute une édition vide à 0s pendant 5s, puis ajoute une édition régulière à 5s pendant 3s en commençant à 4s dans la piste média
- re0-4,0,0.5 : supprime les éditions, ajoute une seule édition à 0s pendant 4s en commençant à 0s dans la piste média et jouant à une vitesse de 0.5
-moovpad (int)

spécifie la quantité de remplissage à conserver après la boîte moov pour des modifications ultérieures sur place - si 0, le remplissage de moov est désactivé
-no-inplace

désactive la réécriture sur place
-hdr (string)

met à jour les informations HDR en fonction du XML donné, 'none' supprime les informations HDR

Options d'extraction

MP4Box peut être utilisé pour extraire des pistes médias de fichiers MP4. Si vous avez besoin de convertir ces pistes, veuillez consulter la documentation des filtres.

Options :

-raw (string)

extrait la piste donnée au format brut lorsque cela est pris en charge. Utilisez tkID:output=FileName pour définir le nom du fichier de sortie
-raws (string)

extrait chaque échantillon de la piste donnée dans un fichier. Utilisez tkID:N pour extraire le N-ième échantillon
-nhnt (int)

extrait la piste donnée au format NHNT
-nhml (string)

extrait la piste donnée au format NHML. Utilisez tkID:full pour un vidage NHML complet avec toutes les propriétés des paquets
-webvtt-raw (string)

extrait la piste donnée en tant que média brut dans WebVTT en tant que métadonnées. Utilisez tkID:embedded pour inclure les données médias dans le fichier WebVTT
-single (int)

extrait la piste donnée dans un nouveau fichier mp4
-six (int)

extrait la piste donnée en tant que média brut dans des instructions de streaming XML expérimentales
-mux (string)

multiplexe le fichier d'entrée vers la destination donnée
-qcp (int)

identique à .I raw mais par défaut un fichier QCP pour EVRC/SMV
-saf

multiplexe le fichier d'entrée vers un multiplex SAF
-dvbhdemux

démultiplexe le fichier DVB-H en paquets IP envoyés sur le réseau
-raw-layer (int)

identique à .I raw mais ignore les extracteurs SVC/MVC/LHVC lors de l'extraction
-diod

extrait l'IOD du fichier au format brut
-mpd (string)

convertit un manifest HLS ou Smooth (local ou distant http) en MPD - les options -url-template et -segment-timelinepeuvent être utilisées dans ce mode.
Note : Ceci ne fournit qu'une conversion de base, pour des conversions plus avancées, voir gpac -h dasher

Attention : Ceci n'est pas compatible avec les autres options DASH et ne convertit pas les segments associés

Spécification des fichiers d'entrée

Les fichiers médias d'entrée pour dash peuvent utiliser les modificateurs suivants
* #trackID=N : utilise uniquement la piste ID N du fichier source
* #N : utilise uniquement la piste ID N du fichier source (mappé à .I -tkid)
* #video : utilise uniquement la première piste vidéo du fichier source
* #audio : utilise uniquement la première piste audio du fichier source
* :id=NAME : définit l'ID de la représentation à NAME. La valeur réservée NULL désactive l'ID de représentation pour les entrées multiplexées. Si non défini, une valeur par défaut est calculée et toutes les pistes sélectionnées de la source seront dans le même multiplex de sortie.
* :dur=VALUE : traite VALUE secondes (fraction) du média. Si VALUE est plus long que la durée du média, la durée du dernier échantillon est étendue.
* :period=NAME : définit la période de la représentation à NAME. Plusieurs périodes peuvent être utilisées. Les périodes apparaissent dans le M PD dans le même ordre que spécifié avec cette option
* :BaseURL=NOM: définit l'URL de base. Définit plusieurs fois pour plusieurs URL de base
Attention : Cela ne modifie pas l'emplacement des fichiers générés (voir le modèle de segment).
* :bandwidth=VALEUR: définit la bande passante de la représentation à une valeur donnée
* :pdur=VALEUR: définit la durée de la période associée à VALEUR secondes (fraction) (alias pour period_duration:VALEUR). Ceci n'est utilisé que lorsqu'aucun média d'entrée n'est spécifié (insertion de période à distance), par exemple :period=X:xlink=Z:pdur=Y
* :ddur=VALEUR: remplace la durée du segment DASH cible par VALEUR secondes (fraction) pour cette entrée (alias pour duration:VALEUR)
* :xlink=VALEUR: définit la valeur xlink pour la période contenant cet élément. Seul le xlink déclaré sur la première rep d'une période sera utilisé
* :asID=VALEUR: définit l'ID AdaptationSet à VALEUR (entier non signé)
* :role=VALEUR: définit le rôle de cette représentation (voir spécification DASH). Les médias avec des rôles différents appartiennent à différents ensembles d'adaptation.
* :desc_p=VALEUR: ajoute un descripteur au niveau de la période.
* :desc_as=VALEUR: ajoute un descripteur au niveau de l'ensemble d'adaptation. Deux entrées avec des valeurs différentes seront dans des éléments AdaptationSet différents.
* :desc_as_c=VALEUR: ajoute un descripteur au niveau de l'ensemble d'adaptation. La valeur est ignorée lors de la création des éléments AdaptationSet.
* :desc_rep=VALEUR: ajoute un descripteur au niveau de la représentation. La valeur est ignorée lors de la création des éléments AdaptationSet.
* :sscale: force l'échelle du film à correspondre à l'échelle du média du premier piste dans le segment.
* :trackID=N: utilise uniquement l'ID de piste N du fichier source
* @f1[:args][@fN:args][@@fK:args]: définit une chaîne de filtres à insérer entre la source et le dasher. Chaque filtre de la chaîne est formaté comme un filtre régulier, voir la documentation des filtres `gpac -h doc`. Si plusieurs filtres sont définis :
- ils seront enchaînés dans l'ordre donné s'ils sont séparés par un seul @
- une nouvelle chaîne de filtres sera créée s'ils sont séparés par un double @@. Dans ce cas, aucun ID de représentation n'est attribué à la source.
Exemple
source.mp4:@c=avc:b=1M@@c=avc:b=500k

Ceci chargera une chaîne de filtres avec deux encodeurs connectés à la source et au dasher.
Exemple
source.mp4:@c=avc:b=1M@c=avc:b=500k

Ceci chargera une chaîne de filtres avec le second encodeur connecté à la sortie du premier (!!).
Note : @f doit être placé après toutes les autres options.
Note : La valeur des descripteurs doit être un élément XML correctement formaté (ou des éléments), la valeur n'est pas vérifiée. La syntaxe peut utiliser file@FILENAME pour charger le contenu à partir d'un fichier.

Options

-dash (nombre)

crée DASH à partir des fichiers d'entrée avec une durée de segment (sous-segment pour le profil onDemand) donnée en ms
-dash-live (nombre)

génère une session DASH en direct en utilisant la durée de segment donnée en ms ; l'utilisation de -dash-live=F écrira également le contexte en direct vers F. MP4Box exécutera la session en direct jusqu'à ce que q soit pressé ou qu'une erreur fatale se produise
-ddbg-live (nombre)

identique à .I dash-live sans régulation temporelle à des fins de débogage
-frag (nombre)

spécifie la durée du fragment en ms. Si non définie, c'est la durée DASH (un fragment par segment)
-out (chaîne)

spécifie le nom du fichier MPD de sortie
-profile,-dash-profile (chaîne)

spécifie le profil DASH cible et définit les options par défaut pour assurer la conformité au profil souhaité. Le profil par défaut est full en mode statique, live en mode dynamique (ancienne syntaxe utilisant :live au lieu de .live comme séparateur toujours possible). Les valeurs définies sont onDemand, live, main, simple, full, hbbtv1.5.live, dashavc264.live, dashavc264.onDemand, dashif.ll
-profile-ext (chaîne)

spécifie une liste d'extensions de profil, telles qu'utilisées par DASH-IF et DVB. La chaîne sera concaténée par deux-points avec le profil utilisé
-rap

assure que les segments commencent par des points d'accès aléatoires, les durées des segments peuvent varier en fonction de l'encodage source
-frag-rap

assure que tous les fragments commencent par des points d'accès aléatoires (la durée peut varier en fonction de l'encodage source)
-segment-name (chaîne)

définit le nom du segment pour les segments générés. S'il n'est pas défini (par défaut), les segments sont concaténés dans le fichier de sortie, sauf dans le profil live où dash_%%s. Les chaînes de remplacement prises en charge sont :
- $Number[%%0Nd]$ est remplacé par le numéro de segment, potentiellement préfixé par 0
- $RepresentationID$ est remplacé par le nom de la représentation
- $Time$ est remplacé par le temps de début du segment
- $Bandwidth$ est remplacé par la bande passante de la représentation
- $Init=NAME$ est remplacé par NAME pour le segment d'initialisation, ignoré sinon
- $Index=NAME$ est remplacé par NAME pour les segments d'index, ignoré sinon
- $Path=PATH$ est remplacé par PATH lors de la création de segments, ignoré sinon
- $Segment=NAME$ est remplacé par NAME pour les segments médias, ignoré pour les segments d'initialisation
-segment-ext (chaîne, défaut : m4s)

définit l'extension du segment, null signifie aucune extension
-init-segment-ext (chaîne, défaut : mp4)

définit l'extension du segment pour les segments d'initialisation, d'index et de commutation de flux binaire, null signifie aucune extension
-segment-timeline

utilise SegmentTimeline lors de la génération de segments
-segment-marker (chaîne)

ajoute une boîte du type donné (4CC) à la fin de chaque segment DASH
-insert-utc

insère une horloge UTC au début de chaque segment ISOBMF
-base-url (chaîne)

définit l'URL de base au niveau du MPD. Peut être utilisé plusieurs fois.
Attention : ceci ne modifie pas l'emplacement des fichiers générés
-mpd-title (chaîne)

définit le titre MPD
-mpd-source (chaîne)

définit la source MPD
-mpd-info-url (chaîne)

définit l'URL d'information MPD
-cprt (chaîne)

ajoute une chaîne de droits d'auteur au MPD
-dash-ctx (chaîne)

stocke/restaure le timing DASH à partir du fichier indiqué
-dynamic

utilise le type MPD dynamique au lieu de statique
-last-dynamic

identique à .I dynamic mais ferme la période (insère la marque lmsg si nécessaire et met à jour la durée)
-mpd-duration (nombre)

définit la durée en secondes d'une session live (si 0, vous devez utiliser .I mpd-refresh)
-mpd-refresh (nombre)

spécifie le temps de mise à jour du MPD en secondes
-time-shift (int)

spécifie la profondeur du tampon de décalage temporel du MPD en secondes, -1 pour garder tous les fichiers)
-subdur (nombre)

spécifie la durée maximale en ms du fichier d'entrée à "dasher" en mode LIVE ou contexte. S'il n'y a pas assez d'échantillons pour terminer un segment, les données sont bouclées sauf si .I no-loop est utilisé, ce qui déclenche la fin de la période.

exécute pendant les ms données la session dash-live puis sort
-min-buffer (int)

spécifie le temps tampon minimum du MPD en ms
-ast-offset (int)

spécifie le décalage AvailabilityStartTime du MPD en ms s'il est positif, ou l'offset de temps de disponibilité de chaque représentation s'il est négatif
-dash-scale (int)

spécifie que le timing pour .I dash, .I dash-live, .I subdur et .I do_frag est exprimé dans l'échelle de temps donnée (unités par seconde) plutôt qu'en ms
-mem-frags

la fragmentation se fait en mémoire plutôt que sur disque avant le déchargement sur disque
-pssh (int)

définit le mode de stockage pssh
* v: film initial
* f: fragments de film
* m: MPD
* mv, vm : dans le film initial et le MPD
* mf, fm : dans les fragments de film et le MPD
* n : supprime PSSH du MPD, du film initial et des fragments de film
-sample-groups-traf

stocke les descriptions de groupes d'échantillons dans traf (dupliquées pour chaque traf). Si non défini, les descriptions de groupes d'échantillons sont stockées dans le film initial
-mvex-after-traks

stocker la boîte mvex après les boîtes trak dans la boîte moov. Si non définie, mvex est avant
-sdtp-traf (int)

Fractionnement de fichier

MP4Box peut fractionner les fichiers d'entrée par taille, durée ou extraire une partie donnée du fichier en de nouveaux fichiers IsoMedia.
Cela nécessite qu'au plus une piste dans le fichier d'entrée ait des points d'accès non aléatoires (typiquement une piste vidéo au maximum).
Le fractionnement ignorera toutes les pistes MPEG-4 Systems et les pistes d'indices (hint tracks), mais tentera de fractionner les pistes multimédias privées.
Le fichier d'entrée doit avoir suffisamment de points d'accès aléatoires pour être fractionné. Si ce n'est pas le cas, vous devrez réencoder le contenu.
Vous pouvez ajouter des médias à un fichier et le fractionner en une seule passe. Dans ce cas, le fichier de destination (celui qui serait obtenu sans fractionnement) ne sera pas stocké.

Les plages de temps sont spécifiées comme suit :
* `S-E` : Heure de début S et heure de fin E, formatées comme HH:MM:SS.ms, MM:SS.ms ou durée en secondes (int, double, fraction)
* `S:E` : Heure de début S et heure de fin E en secondes (int, double, fraction). Si E est précédé de D, cela définit E = S + durée
* `S:end` ou `S:end-N` : Heure de début S en secondes (int, double), N secondes (int, double) avant la fin

Le fractionnement MP4Box exécute une session de filtrage en utilisant le filtre reframer comme suit :
- l'option splitrange du reframer est toujours définie
- la source est démultiplexée avec l'option alltk définie
- les plages de début et de fin sont transmises aux options xs et xe du reframer
- pour -splitz, les options xadjust et xround=after sont appliquées
- pour -splitg, les options xadjust et xround=before sont appliquées
- pour -splitf, l'option xround=seek est appliquée et propbe_refset si non spécifiée à l'invite
- pour -splitx, l'option xround=closest et propbe_ref sont appliquées si non spécifiées à l'invite

Le mode de stockage de sortie par défaut est l'entrelacement complet et nécessitera un fichier temporaire pour chaque sortie. Ce comportement peut être modifié en utilisant -flat, -newfs, -inter et -frag.
Les noms des fichiers de sortie peuvent être spécifiés en utilisant -out et des modèles (par exemple, -out split$num%04d$.mp4 produit split0001.mp4, split0002.mp4, ...).
Plusieurs plages de temps peuvent être spécifiées sous forme de liste séparée par des virgules pour -splitx, -splitz et -splitg.

-split (string)

fractionner en fichiers d'une durée maximale donnée (nombre flottant) en secondes. Une unité suffixe peut être spécifiée :
* `M`, `m` : la durée est en minutes

Options d'importation

Importation de fichiers

La syntaxe est .I add / .I cat URL[#FRAGMENT][:opt1...:optN=val]
Ce processus créera le fichier de destination s'il n'existe pas, et y ajoutera la ou les pistes. Si vous souhaitez toujours créer un nouveau fichier de destination, ajoutez .I -new.
Les types de médias d'entrée pris en charge dépendent de votre installation, consultez la documentation des filtres pour plus d'informations.

Pour sélectionner une piste média désirée à partir d'une source, un identifiant de fragment '#' peut être spécifié, avant toute autre option. La syntaxe suivante est utilisée :
* `#video` : ajoute la première piste vidéo trouvée dans la source
* `#audio` : ajoute la première piste audio trouvée dans la source
* `#auxv` : ajoute la première piste vidéo auxiliaire trouvée dans la source
* `#pict` : ajoute la première piste image trouvée dans la source
* `#trackID=ID` ou `#ID` : ajoute la piste spécifiée. Pour les fichiers IsoMedia, ID est l'ID de piste. Pour les autres fichiers médias, ID est la valeur indiquée par MP4Box -info inputFile
* `#pid=ID` : numéro du PID désiré pour les sources MPEG-2 TS
* `#prog_id=ID` : numéro du programme désiré pour les sources MPEG-2 TS
* `#program=NAME` : nom du programme désiré pour les sources MPEG-2 TS

Par défaut, toutes les importations sont effectuées séquentiellement, et le multiplexage final est effectué à la fin ; cela nécessite cependant un fichier temporaire contenant le fichier ISOBMF d'origine (le cas échéant) et les fichiers ajoutés avant la création de la sortie finale. Comme cela peut devenir assez volumineux, il est possible d'ajouter des médias à un nouveau fichier sans stockage temporaire, en utilisant l'option .I -flat, mais cela désactive le multiplexage des médias.

Si vous souhaitez créer un nouveau fichier multiplexé sans stockage temporaire, utilisez l'option .I -newfs. Le multiplexage pourrait ne pas être aussi précis qu'avec l'utilisation de.

Je suis nouveau car il dépend de la planification des entrées du multiplexeur (chaque exécution peut entraîner un résultat légèrement différent). De plus, dans ce mode :
- Certaines options de multiplexage (marquées avec X ci-dessous) seront activées pour toutes les entrées (par exemple, il n'est pas possible d'importer une piste AVC avec xps_inband et une autre sans).
- Certaines options de multiplexage (marquées comme D ci-dessous) ne peuvent pas être utilisées car elles nécessitent un stockage temporaire pour l'édition de fichiers.
- L'utilisation de .I cat est possible, mais les sources concaténées ne seront pas entrelacées dans la sortie. Si vous souhaitez effectuer des opérations cat/add plus complexes sans fichier temporaire, utilisez une playlist.

L'URL de la source peut être n'importe quelle URL prise en charge par GPAC, pas seulement les fichiers locaux.

Remarque : Lors de l'importation de fichiers SRT ou SUB, MP4Box choisira des options de mise en page par défaut pour que les sous-titres apparaissent en bas de la vidéo. Vous NE DEVRIEZ PAS importer de tels fichiers avant qu'une piste vidéo ne soit ajoutée au fichier de destination, sinon les résultats ne seront probablement pas utiles (l'importation SRT/SUB par défaut utilise la police serif par défaut, la taille de police 18 et la taille d'affichage 400x60). Pour plus de détails, consultez la documentation TTXT.

Lors de l'importation de plusieurs pistes/sources en une seule passe, toutes les options seront appliquées si elles sont pertinentes pour chaque source. Ces options sont définies pour tous les flux importés. Si vous avez besoin de spécifier ces options par flux, définissez les options par fichier en utilisant la syntaxe -add stream[:opt1:...:optN].

Le nom du fichier d'importation peut être défini sur vide ou sur self, indiquant que les options d'importation doivent être appliquées aux pistes du fichier de destination.
Exemple
-add self:moovts=-1:noedit src.mp4

Cela appliquera les options moovts et noedit à toutes les pistes de src.mp4.
Exemple
-add self#2:moovts=-1:noedit src.mp4

Cela appliquera les options moovts et noedit à la piste avec l'ID=2 dans src.mp4.
Seules les options par fichier marquées d'un S sont possibles dans ce mode.

Lors de l'importation d'un fichier ISOBMFF/QT, seules les options marquées C ou S peuvent être utilisées.

Options de guidage

Le guidage IsoMedia consiste à créer des pistes spéciales dans le fichier qui contiennent des informations spécifiques au protocole de transport et éventuellement des informations de multiplexage. Ces pistes sont ensuite utilisées par le serveur pour créer les paquets réels envoyés sur le réseau, en d'autres termes, elles fournissent au serveur des indications sur la manière de construire les paquets, d'où leur nom de pistes de guidage.
MP4Box prend en charge la création de pistes de guidage pour les serveurs RTSP qui les prennent en charge, tels que QuickTime Streaming Server, DarwinStreaming Server ou les serveurs RTSP conformes à la norme 3GPP.
Note : Les outils de streaming GPAC comme la sortie rtp et le serveur rtsp n'utilisent pas de pistes de guidage, ils utilisent une paquetisation à la volée à partir de n'importe quelles sources média, pas seulement MP4.

Accès aléatoire à la scène

>Scène Accès Aléatoire

MP4Box peut encoder des flux BIFS ou LASeR et insérer des points d'accès aléatoires à une fréquence donnée. Ceci est utile lors de l'empaquetage de contenu pour la diffusion, où les utilisateurs n'entreront pas dans la scène en même temps. Dans la terminologie MPEG-4, cela s'appelle le carrousel de scène.## Traitement par blocs BIFS
Le mode d'encodage par blocs BIFS permet d'encoder des unités d'accès BIFS uniques à partir d'un contexte initial et d'un ensemble de commandes.
Les AU générées sont des BIFS bruts (non packetisés SL), dans des fichiers nommés FILE-ESID-AUIDX.bifs, où FILE est le nom de base du fichier d'entrée.
Les commandes avec une temporisation de 0 dans l'entrée modifieront uniquement la version du carrousel (c'est-à-dire le contexte de sortie).
Les commandes avec une temporisation différente de 0 dans l'entrée généreront de nouvelles AU.

force la génération d'échantillons d'ombre de synchronisation BIFS toutes les `int` millisecondes (ne peut pas être utilisé avec .I sync ou .I carousel)
-carousel (int)

utilise le carrousel BIFS (ne peut pas être utilisé avec .I sync ou .I shadow)

-ms (string)

Prise en charge des balises

Les balises sont spécifiées sous forme de liste séparée par des deux-points nom_balise=valeur_balise[:balise2=val2]
Définir une balise sans valeur ou avec la valeur NULL supprime la balise.
La valeur spéciale de balise clear (ou reset) supprime toutes les balises.
Les balises non prises en charge peuvent être ajoutées en utilisant leur code à quatre caractères comme nom de balise, et une valeur de chaîne sera supposée.
Si le nom de la balise a une longueur de 3, le préfixe 0xA9 est utilisé pour créer le code à quatre caractères.

Les balises peuvent également être chargées à partir d'un fichier texte en utilisant -itags nom_fichier. Le fichier doit être en UTF8 avec :
- les lignes commençant par nom_balise=valeur spécifient le début d'une balise
- les autres lignes spécifient le reste de la dernière balise déclarée

Si le nom de la balise commence par WM/, la balise est ajoutée à la boîte Xtra (balise WMA, chaîne uniquement).

Clé de métadonnées QT

La balise est ajoutée comme une clé de métadonnées QT si :
- nom_balise commence par QT/
- ou nom_balise n'est pas reconnu et est plus long que 4 caractères

nom_balise peut éventuellement être préfixé par HDLR@, indiquant le 4CC de l'espace de noms de la balise, l'espace de noms par défaut étant mdta.
valeur_balise peut être préfixé par :
* S : forcer l'encodage en chaîne (doit être placé en premier) au lieu d'analyser la valeur de la balise
* b : utiliser un encodage 8 bits pour les entiers signés ou non signés
* s : utiliser un encodage 16 bits pour les entiers signés ou non signés
* l : utiliser un encodage 32 bits pour les entiers signés ou non signés
* L : utiliser un encodage 64 bits pour les entiers signés ou non signés
* f : forcer l'encodage flottant pour les nombres
Les nombres sont convertis par défaut et stockés en mode de taille variable.
Pour forcer un entier positif à utiliser un stockage signé, ajoutez + devant le nombre.
Exemple
-tags io.gpac.some_tag=s+32

Cela forcera le stockage de la valeur 32 en format signé 16 bits.
valeur_balise peut également être formaté comme suit :
* XxY@WxH : un type rectangle
* XxY : un type point
* W@H : un type taille
* A,B,C,D,E,F,G,H,I : une matrice 3x3
* FNAME : les données sont chargées depuis FNAME, le type est défini sur jpeg ou png si nécessaire
