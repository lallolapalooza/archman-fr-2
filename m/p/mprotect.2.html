mprotect(2) Manuel des appels système mprotect(2)

NOM

mprotect, pkey_mprotect - définir la protection sur une région de mémoire

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/mman.h>
int mprotect(size_t size;
             void addr[size], size_t size, int prot);
#define _GNU_SOURCE             /* Voir feature_test_macros(7) */
#include <sys/mman.h>
int pkey_mprotect(size_t size;
             void addr[size], size_t size, int prot, int pkey);

DESCRIPTION

mprotect() modifie les protections d'accès pour les pages mémoire du processus appelant contenant toute partie de la plage d'adresses dans l'intervalle [addr, addr+size-1]. addr doit être aligné sur une frontière de page.

Si le processus appelant tente d'accéder à la mémoire d'une manière qui viole les protections, le noyau génère un signal SIGSEGV pour le processus.

prot est une combinaison des indicateurs d'accès suivants : PROT_NONE ou un OR bit à bit des autres valeurs de la liste suivante :

PROT_NONE
La mémoire ne peut pas être du tout accédée.
PROT_READ
La mémoire peut être lue.
PROT_WRITE
La mémoire peut être modifiée.
PROT_EXEC
La mémoire peut être exécutée.
PROT_SEM (depuis Linux 2.5.7)
La mémoire peut être utilisée pour des opérations atomiques. Cet indicateur a été introduit dans le cadre de l'implémentation de futex(2) (afin de garantir la capacité d'effectuer les opérations atomiques requises par des commandes telles que FUTEX_WAIT), mais n'est actuellement utilisé sur aucune architecture.
PROT_SAO (depuis Linux 2.6.26)
La mémoire doit avoir un ordonnancement d'accès fort. Cette fonctionnalité est spécifique à l'architecture PowerPC (la version 2.06 de la spécification d'architecture ajoute la fonctionnalité matérielle SAO, et elle est disponible sur POWER 7 ou PowerPC A2, par exemple).

De plus (depuis Linux 2.6.0), prot peut avoir l'un des indicateurs suivants défini :

PROT_GROWSUP
Appliquer le mode de protection jusqu'à la fin d'un mappage qui grandit vers le haut. (De tels mappages sont créés pour la zone de pile sur les architectures — par exemple, HP-PARISC — qui ont une pile grandissant vers le haut.)
PROT_GROWSDOWN
Appliquer le mode de protection vers le bas jusqu'au début d'un mappage qui grandit vers le bas (ce qui devrait être un segment de pile ou un segment mappé avec l'indicateur MAP_GROWSDOWN défini).

Comme mprotect(), pkey_mprotect() change la protection des pages spécifiées par addr et size. L'argument pkey spécifie la clé de protection (voir pkeys(7)) à attribuer à la mémoire. La clé de protection doit être allouée avec pkey_alloc(2) avant d'être passée à pkey_mprotect(). Pour un exemple d'utilisation de cet appel système, voir pkeys(7).

VALEUR DE RETOUR

En cas de succès, mprotect() et pkey_mprotect() retournent zéro. En cas d'erreur, ces appels système retournent -1 et errno est défini pour indiquer l'erreur.

ERREURS

EACCES
La mémoire ne peut pas se voir attribuer l'accès spécifié. Cela peut se produire, par exemple, si vous mmap(2) un fichier auquel vous avez uniquement un accès en lecture, puis que vous demandez à mprotect() de le marquer comme PROT_WRITE.
EINVAL
addr n'est pas un pointeur valide, ou n'est pas un multiple de la taille de page du système.
EINVAL
(pkey_mprotect()) pkey n'a pas été alloué avec pkey_alloc(2).
EINVAL
Les deux indicateurs PROT_GROWSUP et PROT_GROWSDOWN ont été spécifiés dans prot.
EINVAL
Des indicateurs invalides ont été spécifiés dans prot.
EINVAL
(Architecture PowerPC) PROT_SAO a été spécifié dans prot, mais la fonctionnalité matérielle SAO n'est pas disponible.
ENOMEM
Des structures internes du noyau n'ont pas pu être allouées.
ENOMEM
Les adresses dans la plage [addr, addr+size-1] sont invalides pour l'espace d'adressage du processus, ou spécifient une ou plusieurs pages qui ne sont pas mappées. (Avant Linux 2.4.19, l'erreur EFAULT était incorrectement produite dans ces cas.)
ENOMEM
La modification de la protection d'une région mémoire entraînerait le dépassement du nombre maximum autorisé de mappages avec des attributs distincts (par exemple, protection en lecture par rapport à lecture/écriture). (Par exemple, rendre la protection d'une plage PROT_READ au milieu d'une région actuellement protégée comme PROT_READ|PROT_WRITE résulterait en trois mappages : deux mappages lecture/écriture aux extrémités et un mappage en lecture seule au milieu.)

VERSIONS

POSIX stipule que le comportement de mprotect() n'est pas spécifié s'il est appliqué à une région de mémoire qui n'a pas été obtenue via mmap(2).

Sous Linux, il est toujours permissible d'appeler mprotect() sur n'importe quelle adresse dans l'espace d'adressage d'un processus (à l'exception de la zone des vsyscalls du noyau). En particulier, il peut être utilisé pour modifier les mappages de code existants afin qu'ils soient inscriptibles.

Le fait que PROT_EXEC ait un effet différent de PROT_READ dépend de l'architecture du processeur, de la version du noyau et de l'état du processus. Si READ_IMPLIES_EXEC est défini dans les indicateurs de personnalité du processus (voir personality(2)), la spécification de PROT_READ ajoutera implicitement PROT_EXEC.

Sur certaines architectures matérielles (par exemple, i386), PROT_WRITE implique PROT_READ.

POSIX.1 stipule qu'une implémentation peut autoriser des accès autres que ceux spécifiés dans prot, mais au minimum peut autoriser l'accès en écriture uniquement si PROT_WRITE a été défini, et ne doit pas autoriser d'accès si PROT_NONE a été défini.

Les applications doivent être prudentes lors du mélange d'utilisations de mprotect() et pkey_mprotect(). Sur x86, lorsque mprotect() est utilisé avec prot défini sur PROT_EXEC, une clé pkey peut être allouée et définie implicitement sur la mémoire par le noyau, mais uniquement lorsque la pkey était précédemment 0.

Sur les systèmes qui ne prennent pas en charge les clés de protection en matériel, pkey_mprotect() peut toujours être utilisé, mais pkey doit être défini sur -1. Lorsqu'il est appelé ainsi, le fonctionnement de pkey_mprotect() est équivalent à celui de mprotect().

NOTES

EXEMPLES

Le programme ci-dessous montre l'utilisation de mprotect(). Le programme alloue quatre pages de mémoire, rend la troisième de ces pages en lecture seule, puis exécute une boucle qui parcourt la région allouée vers le haut en modifiant des octets.

Voici un exemple de ce que nous pourrions voir lors de l'exécution du programme :


$ ./a.out
Début de la région :        0x804c000
SIGSEGV obtenu à l'adresse : 0x804e000

Source du programme

#include <err.h>
#include <malloc.h>
#include <signal.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/mman.h>
#include <unistd.h>
static char *buffer;
static void
handler(int sig, siginfo_t *si, void *unused)
{
    /* Note : appeler printf() depuis un gestionnaire de signal n'est pas sûr
       (et ne doit pas être fait dans les programmes de production), car
       printf() n'est pas asynchrone-signal-safe ; voir signal-safety(7).
       Néanmoins, nous utilisons printf() ici comme moyen simple de
       montrer que le gestionnaire a été appelé.  */
    printf("SIGSEGV obtenu à l'adresse : %p\n", si->si_addr);
    exit(EXIT_FAILURE);
}
int
main(void)
{
    int               pagesize;
    struct sigaction  sa;
    sa.sa_flags = SA_SIGINFO;
    sigemptyset(&sa.sa_mask);
    sa.sa_sigaction = handler;
    if (sigaction(SIGSEGV, &sa, NULL) == -1)
        err(EXIT_FAILURE, "sigaction");
    pagesize = sysconf(_SC_PAGE_SIZE);
    if (pagesize == -1)
        err(EXIT_FAILURE, "sysconf");
    /* Allouer un tampon aligné sur une frontière de page ;
       la protection initiale est PROT_READ | PROT_WRITE.  */
    buffer = memalign(pagesize, 4 * pagesize);
    if (buffer == NULL)
        err(EXIT_FAILURE, "memalign");
    printf("Début de la région :        %p\n", buffer);
    if (mprotect(buffer + pagesize * 2, pagesize,
                 PROT_READ) == -1)
        err(EXIT_FAILURE, "mprotect");
    for (char *p = buffer ; ; )
        *(p++) = 'a';
    printf("La boucle est terminée\n");     /* Ne devrait jamais arriver */
    exit(EXIT_SUCCESS);
}
